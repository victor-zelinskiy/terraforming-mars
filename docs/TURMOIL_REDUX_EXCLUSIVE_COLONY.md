# TR25 · Exclusive Colony («Эксклюзивная колония») — КОЛОНИЯ СВЕРХ ЛИМИТА

**Статус: см. §10.** Карта проектов набора Turmoil Redux. Печатный текст: «Requires Unity to be ruling or that you have 2
delegates there. Place a colony on any colony tile, EVEN IF YOU ALREADY HAVE A COLONY THERE, OR IT HAS 3 COLONIES. THIS
IGNORES THE 3-COLONY LIMIT. (You gain the colony tile's placement bonus.)» Цена 10, метка Космос, AUTOMATED, плашка Союза
(`{party: UNITY}`), ▲ Колонии (`compatibility: 'colonies'`). Лора на скане нет — запись придумана
(`docs/claude/turmoil-redux-invented-lore.md`): «Fully booked? Not for members.» → «Мест нет? Для членов клуба —
найдутся.»

Карта мала (одна постройка), её вес — в шести контрактах, которые наследует следующая карта, снимающая правило
постройки (§9):

1. **лимит — правило ДВЕРИ**, а не свойство массива кубов, §1;
2. **ОДИН писатель кубов** и его инвариант, §2;
3. **ОДНО чтение бонуса постройки** — `buildBenefitAt`, §3;
4. **общий шаг** `BuildColony` с близнецом и **маркер** `buildSites`, §4;
5. **МЕСТА КАК МОДЕЛЬ** — причал сверх лимита в трёх хостах, §5;
6. **дверь и СЦЕНА «ЛИМИТ ОТКРЫВАЕТСЯ»**, §6–§7.

Промт: `docs/claude/prompts/project-tr25-exclusive-colony.md`. Файл карты:
`src/server/cards/turmoilRedux/ExclusiveColony.ts` (шапка — чтение скана, что печатает настольная плитка и четырнадцать
правил чтения, каждое закреплено `tests/cards/turmoilRedux/ExclusiveColony.spec.ts`).

**Физическая правда, из которой всё выводится.** Настольная плитка (`…/Colonies/Vesta.png`) печатает бонус постройки В
ПЕРВЫХ ТРЁХ клетках трека, и кубы колоний стоят НА этих клетках — маркер не может встать ниже них. Четвёртый куб встаёт на
четвёртую клетку, которая ничего не печатает (поэтому карта и оговаривает бонус в скобках). В интерфейсе он стоит там же:
причал 4 под клеткой 4, защёлка и планка — те же объекты, стоп — на пятой клетке.

## 1. Лимит — правило двери

`MAX_COLONIES_PER_TILE = 3` и смысл `Colony.isFull()` не менялись. Изменилось, ГДЕ число кубов сравнивается с тройкой:
**только в двери постройки и в `common/colonies/colonyBerths.ts`.**

```ts
// src/server/player/Colonies.ts
type BuildDoorOptions = {allowDuplicate?, ignoreLimit?, canAffordOptions?, active?};
buildBlockedReason(colony, options: BuildDoorOptions = {}): string | undefined
getPlayableColonies(allowDuplicate: boolean | BuildDoorOptions = false, canAffordOptions = 0)   // девять позиционных вызовов апстрима не тронуты
NO_FREE_TRACK_CELL_REASON = 'No free cell on the colony track'
```

Порядок причин — ОДНА на плитку: неактивна → **(без `ignoreLimit`) заполнена** → **(всегда) нет свободной клетки трека** →
уже ваша (без `allowDuplicate`) → РТ не по карману (океан Европы; Leavitt + Pharmacy Union). Два флага независимы — это
две печатные оговорки карты: `ignoreLimit` без `allowDuplicate` на полной плитке со своим кубом отвечает «уже ваша».
Флаг снимает лимит ДЛЯ ЭТОЙ ПОСТРОЙКИ: после неё `isFull()` истинно (4 ≥ 3), и плитка закрыта для всех обычных дверей —
владельца, «Научной колонии», стандартного проекта, Colony Contest и MarsBot.

**Физический предел не снимает никто:** кубу нужна клетка трека, и маркеру должна остаться своя
(`colonyBerths.hasFreeTrackCell` = `built < trackTop`). Одной картой недостижим (4 ≤ 6) — правило написано и названо
причиной, а не предположено; `Colony.placeCube` / `addColony` бросают при его нарушении (пол движка, двери называют его
раньше).

`Behavior.colonies.buildColony`, `Executor` и двенадцать декларативных карт-строителей не тронуты.

## 2. ОДИН писатель кубов

```ts
// src/server/colonies/IColony.ts
placeCube(owner: PlayerId): number      // push → «маркер не ниже числа колоний» → занятый причал; throw без клетки трека
hasFreeTrackCell(): boolean
```

Зовут `Colony.addColony` (постройка игрока) и `AutomaColonies.botBuildColony` (у бота были собственный push и своя копия
правила маркера — их нет). Source-level гард `tests/colonies/ColonyBerths.spec.ts`: в `src/server` + `src/common` никто,
кроме писателя и десериализации, не пишет в массив кубов плитки (состав `game.colonies` — другой массив, у него свой гард).

`addColony` читает причал ОДИН раз до push — строка журнала, бонус и повтор Vital Colony говорят об одном и том же
причале. Постройка в причал сверх напечатанных пишет свою строку —
`'${0} built a colony on ${1} beyond the 3-colony limit'` — ВМЕСТО обычной.

Карта не добавляет ни одного сериализуемого поля: «сверх лимита» — это счёт. `SerializedColony` побайтно прежний
(массив из четырёх кубов десериализуется без предела); старые сохранения не затронуты.

## 3. ОДНО чтение бонуса постройки

```ts
// src/common/colonies/ColonyMetadata.ts
buildBenefitAt(metadata, slot): {type, quantity, resource}     // слот ЗАЖАТ в напечатанные клетки
// src/common/colonies/colonyBerths.ts — одна арифметика для сервера и клиента
printedBerths(): number                                         // = MAX_COLONIES_PER_TILE
berthIsOverLimit(slot): boolean
berthCount(built, projectedSlot?): number                       // max(printed, built, projectedSlot + 1)
hasFreeTrackCell(metadata, built): boolean
```

До карты движок читал бонус ИНДЕКСОМ числа кубов (`build.quantity[colonies.length]`): четвёртая постройка читала
`undefined` и прибавляла его к производству / запасу / карте — состояние портилось молча. Четвёртая колония получает
ПОСЛЕДНЮЮ НАПЕЧАТАННУЮ клетку: то же число у однородных плиток, 2 ПО у Titania (5 / 3 / 2). Читают все: `addColony`,
`colonyTradePreview.buildBonusFollowUps` и клиент (`colonyBuildModel`, `colonyTradePlan`, стейдж, досье, сетка, легаси-плитка
поповера). Гард-сканер `tests/colonies/colonyBuildBenefitReader.spec.ts`: сырое `build.quantity[` вне читателя и
замороженного десктопа — провал с файлом и строкой; гард данных — каждая плитка манифеста печатает ровно
`MAX_COLONIES_PER_TILE` клеток постройки и `trackTop > MAX_COLONIES_PER_TILE`.

`colonyTradePreview.buildBonusFollowUps` потерял гейт «`slot >= MAX` → пусто»: КТО может строить, решает дверь, а не
превью. Полная плитка отвечает, что спросит СЛЕДУЮЩИЙ куб (стейдж двери пре-собирает цель-карту отсюда); пусто только
там, где нет клетки трека.

## 4. Общий шаг и маркер

```ts
// src/server/deferredActions/BuildColony.ts
new BuildColony(player, {allowDuplicate?, ignoreLimit?, title?, colonies?, giveBonusTwice?,
                         cause?: ChoiceContextSource, canAffordOptions?, placementContext?, onCancel?, commit?})
hasCandidate(): boolean                                   // read-only: вопрос играбельности
previewSelectColony(): SelectColonyModel | undefined      // read-only близнец живого промпта, поле в поле
previewSkip(): {reason, skipped}                          // 'No colony available to build on' · 'Build a colony'
// src/common/colonies/ColonyBuildSite.ts — маркер SelectColonyModel.buildSites, строка на КАЖДОГО кандидата
type ColonyBuildSite = {colony, slot, overLimit, own};
```

- Тело разложено по форме `MaximizeColonyTrack`: `offer()` → `prompt()` → близнец / `execute()`.
- `cause` (карта-даритель) → `markChoiceContext({source: cause, mode: 'effect-choice'})` — адрес staged-хвоста
  (`deferredInputBatch`: `choiceContext.source.card`), и «нет плитки» становится НАЗВАННЫМ пропуском
  (`recordSkippedEffect`). Без `cause` промпт — прежний (плюс маркер).
- В ответе дверь перечитывается теми же опциями: мир мог сдвинуться, пока хвост был припаркован; отказ → `InputError` →
  хвост сброшен, вопрос встаёт живым. (Собственный поднабор вызывающего — `colonies` — правило той карты, не
  перепроверяется.)
- `canAffordOptions` — ПРЕВЬЮ: до розыгрыша цена карты не уплачена, и «по карману ли РТ бонуса» обязано её учесть
  (приём TR10); живой шаг строится без неё.
- **`buildSites` публикуется на КАЖДОМ промпте постройки** (стандартный проект, follow-up карты, Colony Contest, бонус
  клетки Terra Cimmeria, staged-дверь) — подпись `'Build'` строится в одном месте. Клиент узнаёт акт по маркеру
  (`colonyPickIntent`: `trackMoves` → `roster` → `tileSite` → `buildSites` → `pick`); сравнение
  `buttonLabel === 'Build'` удалено.
- **Ответ — существующая третья форма** `{type: 'colony', colonyName, stagedFor}`. Новой формы и пятой staged-цели нет:
  режим решает маркер промпта.

**Прогноз «колония построена».** Грант `{kind: 'colony', count}` (`EffectForecastGrant`): его источники — шаг
`boardPlacement / colony` (декларативный `buildColony`) и `colonyPick` с `buildSites`
(`effectForecast.colonyBuildsOfBranch`); он предлагается реакторам `onColonyAddedByAnyPlayer` каждого места в порядке
живого цикла через `grantForecast`. Близнец — у Poseidon (единственный реактор класса в премиум-скоупе); пара
`FORECAST_HOOK_PAIRS` и гарды покрытия / паритета — на месте. Вне скоупа и честно `unknown`: Colony Trade Hub
(`prelude2`), Naomi (`ceos`), корпорация бота C33.

## 5. МЕСТА КАК МОДЕЛЬ — три хоста

```ts
// src/client/console/colonyBuild/colonyBerths.ts
colonyBerthsOf(colony, projection?): Array<{index, owner?, state: 'empty' | 'taken' | 'projected', overLimit}>
nextBuildSlot(colony, site?): number      // слот маркера, иначе число кубов — никогда зажим
freeBerths(colony): number                // max(0, printed − built)
buildSiteOf(sites, colony): ColonyBuildSite | undefined
berthBuildBenefit(metadata, slot)         // бонус ОДНОГО причала для BenefitGlyph: список из одного, idx 0
```

Литерал `[0, 1, 2]` и зажим `Math.min(…, 2)` в поверхностях колоний — провал гарда `tests/console/colonyBerths.spec.ts`
(с файлом и строкой).

**Подача — формой, не цветом** (янтарь — планка и стоп, циан — занятое место, мята — проекция):

- **ОТМЕТКА ЛИМИТА** — торцевой упор напечатанного ряда в зазоре перед четвёртым причалом: нейтральная светлая вертикаль с
  пяткой, высотой в ряд причалов. При допуске вертикаль уходит в пятку ОДНИМ transform и остаётся так навсегда.
- **ПЛАСТИНА причала** — двойной волосной контур со срезанным углом вместо скруглённого дока (SVG, штрих в экранных
  единицах). Пока дверь только проецирует куб — один пунктирный контур мятного тона и призрак куба в цвете игрока над
  бонусом, который причал заплатит; после допуска контур замкнут и удвоен (кроссфейд прозрачности).
- **ОДНО слово** «Сверх лимита» — бирка в полосе механизма, читается ВПРАВО от отметки (полоса над бонусом владельца
  пуста), собственная защёлка причала проходит за ней. На причале и на клетке текста нет. Без свечения и пульса.

Всё это существует только там, где у модели ЕСТЬ такой причал (стоит четвёртый куб, или дверь его проецирует). Обычная
плитка не рендерит ни одного из этих узлов, классов и токенов (`ConsoleColonyBerths.spec`).

| Хост | Что сделано |
| --- | --- |
| **Инструмент трека** (`ConsoleColonyTrackInstrument` — стейдж и досье) | причалы — `v-for` по модели; якоря `data-colony-build-slot="<Имя>#3"` + `data-colony-build-seat` + `data-colony-bonus-source`; `data-colony-berth-overlimit` = `standing` / `passed`; пропсы `buildSlot`, `admitCell`, `projectedColor`. Блок «Бонус владельца» отдаёт ОДНУ колонку: `grid-column: calc(var(--berths, 3) + 1) / -1` (у обычной плитки — прежние `4 / -1`) |
| **Плитка сетки** (`ConsoleColonyTile`) | четвёртый слот в том же ряду под компактной метрикой ТОЛЬКО такой плитки (слот 2.5 → 2.2 rem, зазор .4 → .3; Deck 1.85 → 1.65, .4 → .25); место куба — прежние 32 px; бокс плитки не меняется, уступают пипсы трека; отметка лимита — волосной упор в зазоре, нулевой лейаут |
| **Досье** (`ConsoleColonyInspect`) | тот же инструмент; факт словами — ОДНОЙ строкой в колонке акта («Сверх лимита: 4-я колония · <игрок>»), не в панели правил |
| Легаси-поповер чипа (`components/colonies/ColonyTile.vue`) | четвёртый слот виден (модель); премиум-подачи нет |

**Порядок уступок «Бонуса владельца» в трёх колонках** (арифметика «ставка × кубы = итог» обязана стоять в ОДНОЙ строке на
fhd / 4K / Deck с четырьмя кубами): ① примечание «За каждую торговлю здесь» (уходит целиком, когда арифметика нарисована;
иначе режется только эллипсисом в своём боксе) → ② кубы смыкают ряды (≥ 3) → ③ член ставки «N [бонус] ×»
(container query по ширине самого блока: 12.6 rem для двух кубов, 14.3 rem для сомкнутых) → ④ кубы и итог не уступают
никогда. Замерено пробником: fhd 23.1 rem и 4K 18.4 rem — вся фраза; Deck 10.6 rem — «[кубы] = итог».

## 6. Дверь — staged, целиком TR07

```
КАРТЫ В РУКЕ › ЭКСКЛЮЗИВНАЯ КОЛОНИЯ › РОЗЫГРЫШ          «Колония — плитка выбирается в «Колониях»»
        │ A «Выбрать колонию»  (НИЧЕГО не отправлено)
… › ВЫБОР КОЛОНИИ      призрак куба на КАЖДОМ кандидате в причале маркера; у плитки на лимите — четвёртый, за отметкой
        │ A выбрать · X осмотреть · L3 источник                     B «Назад» → композер, оплата цела
… › ЛУНА · СТРОИТЕЛЬСТВО   причал 4 в проекции, призрачный стоп на клетку правее, «Место 4 · сверх лимита»
        │ A «Разыграть карту» → ЕДИНСТВЕННЫЙ POST [projectCard + оплата, {colony, colonyName, stagedFor}, …ответы цели]
        ▼                                                            B «Назад» → сетка (плитка в фокусе та же)
   СЦЕНА (§7) → продолжение награды в зоне стейджа → стейдж складывается домой → квитанция сетки → поле
```

- **Проекция на сетке — только у двери КАРТЫ** (`ConsoleColonyPick.buildProjected`: staged, или живой промпт называет
  карту дарителем). Стандартный проект, follow-up декларативной карты и колония резолюции получают прежнюю сетку.
  Статус кандидата — спокойный, не отказ: «Сверх лимита — по карте» / «Вторая колония — по карте»; отключённые — причиной
  сервера. Рейл называет причал («Место 4 · сверх лимита») вместо «Свободно мест: 0».
- **Стейдж `build`** — существующая композиция, три правки: причал — из маркера (закреплён в снимке границы коммита,
  `HeldView.buildSlot`); `buildPreview` — «дверь предлагает эту плитку и нацеленный причал пуст» (число кубов с лимитом
  не сравнивается); строка «Новая колония» — «Место 4 · сверх лимита». A «Разыграть карту», X — досье (у постройки с
  решениями X остаётся её коммитом), L3 «Источник».
- **Коммит — ОДНО тело на обе двери** (`ConsoleShell.armColonyBuildCommit`): закрепить стейдж → причал сервера →
  армировать героя куба (`armColonyBuild(…, door)`) → ответы пред-собранных шагов. Живая дверь шлёт как раньше; staged —
  `commitStagedTail(адресованный ответ, following, claim)`: ОДИН батч, за плиткой — ответы шагов бонуса, по порядку
  (сервер паркует весь неотвеченный остаток). Гард проводки: `tests/console/colonyBuildDoorWiring.spec.ts`.
- **Продолжение награды рождается В СТЕЙДЖЕ и на staged-двери**: заявка исхода — КОЛОНИИ (`claimColonyBuildOutcome`),
  сделанная ПОСЛЕ оптимистичной заявки розыгрыша (руки), поэтому добор (Плутон) и поздняя цель встают в зоне стейджа, а
  не руки. Плитка, чей бонус ничего не спрашивает, не заявляет ничего — заявка розыгрыша стоит. Четыре формы продолжения:
  цель-карта (Титан) — пре-собрана на стейдже и едет в ТОМ ЖЕ POST; добор (Плутон) — в зоне стейджа, «домой» после
  последней взятой карты; делегаты (Венера Redux) — шаг Парламента в зоне секции ПОСЛЕ «домой» (§7); океан (Европа) —
  на поле, когда рука ушла.
- **Три исхода** (зеркало §9-quater): LANDED → §7 и «домой»; RE-ASKED → стоящая сетка / стейдж становится живой дверью на
  месте (армирование куба снято на detect); PARKED → уход без сцены, куб приходит обычным обновлением.

## 7. Сцена «ЛИМИТ ОТКРЫВАЕТСЯ»

Существующая подпись постройки (`colony-focus-stage.md` §4b), сдвинутая на клетку, плюс ОДИН новый такт перед кубом.
Числа директора куба не менялись.

| Такт | Что происходит | Чем ведётся |
| --- | --- | --- |
| **ДОПУСК** | отметка лимита отпускает (один transform), пунктир смыкается в пластину, призрак уступает | ОДИН класс от состояния транзакции постройки (`admitCell` ← `colonyBuildState.active` — армирована на нажатии, до POST); CSS 220 ms × `--motion-scale` |
| **КУБ** | полёт в место `#3`, рождён в размере покоя | `colonyBuildDirector` |
| **ЗАЩЁЛКА** | `--latching` на клетке 4 и причале 4 | фаза `landed` |
| **СТОП** | уезжает на клетку правее; маркер, стоявший на 3, поднимается с коммитом | `--stop-col` |
| **НАГРАДА** | бонус постройки из глифа причала | существующий путь |
| **ДОМОЙ** | продолжение награды в зоне стейджа → стейдж складывается в плитку → сетка одно чтение стоит квитанцией | `ConsoleShell.landColonyBuild` |

- **Домой** ждёт СОСТОЯНИЯ, не времени (`colonyBuildContinuationOwed`): заявка колонии (добор берут сколько угодно),
  принимающая карта (`cardSceneLive`), вложенный шаг, с которым стейдж живёт (`workspaceFrameHasNested('colonies')` —
  сброс руки), промпт с источником-колонией, который обслуживает сам стейдж (`choiceContext.source = {kind: 'colony',
  name}`). Размещение на поле (океан Европы) НЕ ждётся — оно уходит на поле, когда рука ушла со своим шагом. Один `dwell`
  — чтение квитанции.
- **Делегаты плитки (Венера Redux) — шаг Парламента ПОСЛЕ «домой», не под стейджем.** Шаг голосования занимает всю
  центральную зону секции (`colonies-parliament`), поэтому в «должен внутри стейджа» он НЕ входит: его дверь ПРИДЕРЖАНА,
  пока стоит стейдж постройки картой (`openShellTaskSurface`: `partyStep && colonyBuildAnswered() && colonyFocus.open`),
  посадка складывает стейдж домой, ждёт, пока его узел уйдёт из секции (состояние, `probeTick`, с границей), сама открывает
  дверь и ждёт шаг (`colonyBuildSectionStepOwed`: кадр Парламента в колониях ∨ стоящий грант — `votePrompt.source ===
  'grant'` + источник-колония) — и только потом сетка читается квитанцией. Первая редакция держала стейдж под шагом:
  Парламент рисовался поверх зажжённого трека, а строка команд показывала глаголы стейджа.
- **Строка команд после нажатия — СТАТУС, одна грамматика на все акты колонии** (2026-10-05, после сдачи — решение
  владельца): на стейдже «Выполняется…» (`ConsoleShell.colonyActAnswered` по интенту: постройка картой —
  `colonyBuildAnswered`, замена состава — `colonyRosterAnswered`, город — `colonyCityAnswered`, трек —
  `colonyTrackMoveAnswered`), на сетке-квитанции «Выполнено» (`consoleColoniesUi.receipt` — зеркало ОДНОГО чтения секции
  `receiptOn`). Промпт staged-двери переживает ответ, и по нему строка предлагала «Выбрать · Осмотреть · Назад» над сеткой,
  которая ничего из этого не принимает (TR10, TR25), а у TR22 строка была пустой. Ввод по-прежнему у сцены (A «дожимает»
  церемонию состава и посадку города). Живая постройка — прежняя строка.
- **Квитанция постройки принадлежит ХОСТИРУЕМОМУ экземпляру** (сетка staged-двери — всегда шаг своего хоста): чтение
  секции спрашивает `embedded`. Шаг делегатов можно свернуть («Свернуть»), и свежие «Колонии», открытые с колеса рядом с
  припаркованным потоком, — обычная сетка со своими глаголами, не квитанция.
- **Квитанция** — общее чтение `receiptOn` (ростер ∨ город ∨ постройка картой: третий пользователь, не третья копия).
  Запись — у транзакции постройки (`colonyBuildState.door / receipt / homing`), латч через растворение хоста — у секции.
- **Деградация называет себя:** `colonyBuildState.degraded` → `data-colony-build-degraded` на СВИДЕТЕЛЕ транзакции
  (`colonyBuild/ConsoleColonyBuildWitness.vue` — узел shell-слоя куба; он же несёт `data-colony-build-phase`); e2e
  требует отсутствия. Раньше ветка «unmeasurable» молчала. ⚠ Свидетель — отдельный компонент намеренно: фаза,
  опубликованная на корне секции, заставляла всю секцию перерисовываться на нажатии и на каждом такте ОБЫЧНОЙ постройки
  (A/B: прокси куба рождался на 10–25 мс позже базы). Шаблон секции не читает транзакцию постройки, а обычный причал
  ничего не «допускает» (`admitCell` = −1 — пропсы инструмента стоят) — оба закреплены `colonyBuildDoorWiring.spec`.
- **Зритель:** полёта постройки у зрителя нет (класс — нет ни у одной). Причал раскрывается ОДНИМ переходом раньше, чем
  проявится куб (одноразовые классы `--revealing`, снимаются на `animationend`); стоп и планки — своими переходами;
  холдов нет.
