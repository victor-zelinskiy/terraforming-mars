## 1. Граница «игровой экран / справка»

Обзор Парламента показывает **объекты и состояния**: печати партий, числа делегатов, кубы игроков, графические формулы,
чипы прогноза, состояния доступности/выбора/использования. Из постоянного обзора удалены все абзацы правил:

| Было (v1) | Стало (v2) |
| --- | --- |
| «Побеждает больше делегатов; при равенстве — ближайшая к правительству» под заголовком области | нет; правило ничьей — в осмотре резолюции (X) |
| «Эффект есть у всех игроков, пока партия правит» под формулой правящей | нет; печать правящей носит золотое кольцо «правит» |
| «0 из 2 до эффекта» в талли | две точки порога на талли (заполненная = ваш делегат) |
| зона «деталь партии» с причинами доступа и текстами эффекта/действия | нет; формула — на самой печати, причины — в осмотре (X) |
| легенда Повестки в одну строку | нет; уровни/РТ/карта — глифы шагов; следующий шаг — глиф в шапке |
| «Кресло председателя и один шаг Повестки → вам: уровень влияния 2» | глифы: `КРЕСЛО + ②` (или РТ/карта) |
| «Эффекта пока нет · (Тестовая резолюция)» на грани dummy | одна спокойная строка «Собственного эффекта нет» |

Единственная контекстная строка обзора — **строка партии** под рядом печатей: короткая причина, почему действие
сфокусированной партии нельзя выполнить сейчас (использовано · причина сервера · не ваше окно). Когда действие доступно,
строка пуста — об этом говорят глиф ◈ на печати и глагол в командной строке.

## 2. Композиция

```
┌ ПРАВИТЕЛЬСТВО ──────────────┐ ┌ ОБЛАСТЬ ГОЛОСОВАНИЯ ─────────────────────────────────────────┐
│ [принятая карта] [печать    │ │ V1 · ★ ПОБЕЖДАЕТ      V2                      V3            │
│  правящей: кольцо, формула] │ │ [карта] │талли│       [карта] │талли│          [карта] │талли│ │
│ ┌ ЗАДАНИЕ ПРЕДСЕДАТЕЛЯ ─────┐│ │ лента делегатов (порядок = правило ничьей)                    │
│ │ [графика условия] слова  ││ │ РЕЙКА ФОКУСА: откуда делегат · N→N+1 · чипы прогноза          │
│ │ гонка: кубы N/M          ││ └───────────────────────────────────────────────────────────────┘
│ │ НАГРАДА КРЕСЛО + ② · ПРЕДС.││ ┌ ПАРТИИ — ОДИН РЯД ПЕЧАТЕЙ ×6 ──────────────────────────────┐
│ └───────────────────────────┘│ │ [печать: кольцо состояния · имя · формула · поддержка · ◈]  │
└──────────────────────────────┘ │ СТРОКА ПАРТИИ: причина недоступности действия (или пусто)    │
                                 ┌ ПОВЕСТКА: влияние N · следующий шаг ② · СТАРТ ① [РТ] ② …   ┐
```

- **Печать партии** (`ConsolePartyPlaque.vue`, `.con-pseal`) — единое визуальное семейство в трёх размерах: `tile` (ряд
  партий), `hero` (правящая партия в правительстве, источник в композере действия), `full` (предмет fullscreen-осмотра,
  px-размер 360×430, масштабируется зумом вьюера как грань карты). Тёмный сплав, акцент партии — шов плиты; кольцо
  состояния на печати: **золото** — правит, **мята** — ваш эффект, **циан пунктир** — на голосовании (точки на кольце —
  ваши делегаты из двух), без кольца — отсутствует. Цвет игрока — только куб `PlayerCube`; цвета состояний — консольные;
  акцент партии — материал. Три языка не смешиваются.
- **Steam Deck** — собственная группировка: печати 3×2 без модуля механики (X открывает), слоты голосования в стек.
- **TV** — та же композиция, шрифты ≥ .8rem.

## 3. Одна точка исполнения, два входа (обязательное требование)

Оба входа приводят в **один** workspace «ДЕЙСТВИЯ КАРТ» с **одним** композером `ConsolePartyActionComposer` над **одним**
серверным промптом. Различаются только происхождение и возврат.

| Вход | Стек | Крошка | Возврат по B (до коммита) | Завершение |
| --- | --- | --- | --- | --- |
| Меню действий | `[card-actions]` | `⚡ ДЕЙСТВИЯ КАРТ › ИНДУСТРИАЛИСТЫ › НАСТРОЙКА` | сворачивание композера в сетку | flow уходит на поле |
| Парламент → печать → A | `[parliament ⊃ card-actions]` (сцена) | `⚖ ПАРЛАМЕНТ › ИНДУСТРИАЛИСТЫ › НАСТРОЙКА` | кадр снимается, Парламент возвращает сцену с прежним фокусом | flow уходит **в Парламент** (печать пульсирует «использовано») |

Контракты:
- `WORKSPACE_KINDS.parliament.frameSteps['card-actions'] = 'scene'` — хост уступает сцену (`.con-parl--handed-over`:
  кроссфейд, `visibility` после фейда; секция остаётся смонтированной — фокус, зона и стадия переживают вложение).
- Дверь: `ConsoleShell.openParliamentPartyAction(party)` → `consoleCardActionsUi.openWith = {party}` (ОДНОРАЗОВО) +
  `pushWorkspaceFrame({kind:'card-actions', …})`; `ConsoleCardActions.mounted()` потребляет `openWith` и открывает
  композер напрямую (`preselected`), минуя browse-слой. Печать Парламента вооружает `armDescendRect('action-slot')` /
  `armActionFocusOrigin` — композер раскрывается из ректа печати, печать-герой переезжает как переносимый объект.
- Корень крошки вложенного `card-actions` — хост (`hostCrumb`: `workspaceFrameRoot(host)` + эмблема хоста), когда хост
  уступает сцену (`workspaceHostYieldsScene`); латеральный `card-actions` над phase-корнем остаётся сам себе корнем.
- `preselected` cancel = `leaveWorkspace()` (не `closeComposer()`): сетки, к которой можно «вернуться», не было.
- **Передача сцены не прячет гостя.** `ConsoleShell.sceneHandedOver` (слагаемое `pickBridgeActive`, по которому
  `ConsoleCardActions` скрывается `v-show`) НЕ считает Парламент: он прячет себя классом (кроссфейд), а его гость —
  сам workspace действий. Учёт Парламента гасил композер в момент открытия («ПАРЛАМЕНТ › УЧЁНЫЕ › НАСТРОЙКА» над
  пустой полосой; ввод при этом доходил — сценарий проходил «вслепую»). Свидетель `crumbText` в драйвере читает
  самую глубокую ВИДИМУЮ шапку (`visibility: hidden` у переданного хоста).
- Контекст командной строки для sheet, стоящего внутри секции, уступившей сцену (и для шага руки внутри него), — корень
  крошки (`ConsoleShell.commandContext`: `workspaceFrameRoot(host)` при `workspaceHostYieldsScene(host)`), а не «ДЕЙСТВИЯ
  КАРТ»: одна и та же надпись сверху и снизу экрана.
- Локальная стадия действия Парламента (`stage: 'action'`) и дверь торговли Союза внутри Парламента УДАЛЕНЫ:
  `ConsolePartyActionComposer` монтируется только в `ConsoleCardActions`.
- Отправка партийного действия идёт через ту же `beginAwaitingHandoff('action-composer')`, что и пакет карточного
  действия: чипы награды (производство Индустриалистов, ресурсы Учёных) рождаются в иконках печатной формулы
  (`armActionCommit` + `runActionCommitMotion` в композере, `resolveActionCommitAnchors` по `.pcard__mech` печати).

## 4. Красные — цельный сценарий в одном workspace

`запуск → добор 2 → выбор 2 на сброс → сброс → награда → результат`, всё внутри `card-actions`:

1. **Коммит** (`onPartyConfirm`): `claimWorkspaceOutcome('card-actions', 'PARTY_Reds', ['draw'], 0, 2)` синхронно;
   `consoleCardActionsUi.partyFlow.stage = 'committed'`; `partyMcBefore` фиксируется.
2. **Клейм по источнику**: `workspaceClaimsDrawReveal` сопоставляет `{type:'party', party}` с ключом `partyTileKey`
   (`partyActionKey.ts` — общий модуль клейма и модели действий). Сцена добора HUD уступает
   (`workspaceClaimOwnsArrival`), композер летит свой beat: `runBatchArrival` из `.con-deckstack__pile` в подготовленные
   слоты (`.con-pact__beatstage`, тот же `wsStageLayout`), встроенный `ConsoleRevealOverlay` телепортируется в
   `[data-embed-slot="workspace-reveal"]` композера (RELEASE → UNFOLD → REVEAL той же фразой).
3. **Сброс — шаг руки** (`card-actions ⊃ hand`): промпт `handSelect` с маркером `partyActionPrompt.stage === 'discard'`
   — ALWAYS_INTERRUPTIVE для ворот обязательных действий, но здесь это следующий шаг СОБСТВЕННОГО действия игрока, а не
   прерывание: **взятие карт и есть подтверждение** (закон `openDiscardPick` у reveal'а). На `result-detached` /
   `drawn-complete` при `ConsoleShell.partyDiscardStepOwed` (запись flow'а `committed` + маркер сброса той же партии +
   живой кадр `card-actions` + задача `handSelect`) клейм отпускается, бит подтверждается (`acknowledgeMandatoryBeat`), и
   шаг открывается, когда приём карт закончился (`consoleForegroundBusy` ↓ → `openShellTaskSurface` → ранняя ветка
   `openPartyDiscardStep`, БЕЗ `closeConsoleLayers()` — иначе снялся бы сам хост). `openHandWorkspace()` →
   `workspaceHostForStep()` = `card-actions`; композер публикует зону `[data-embed-slot="action-hand"]`
   (`handStepHosted`, `flush:'post'`); рука — ОДНА и та же инстанция (`embedded`), крошка `… › КРАСНЫЕ › СБРОС КАРТ`
   (`setWorkspaceFrameStage('hand','Card discard')`). Выбор — из всей руки, включая только что полученные карты.
   Наложения анимаций нет: альбом поднимает карты из дока, в который они уже долетели.
   Ловушка, оплаченная этой итерацией: `drawSignal` карточного composer'а усыновлял партийный пакет в `outcomeFlow`,
   и его «клейм упал → concludeFlow» обнулял `partyFlow` за тик до передачи сброса — workspace уходил, сброс
   объявлялся над полем. Партийный пакет — сцена партийного композера, `drawSignal` его не трогает.
4. **Удержание завершения**: `ConsoleShell.partyFlowOwed` — маркер сброса для партии flow-record'а ИЛИ стадия
   `result` — входит в `ownsPrompt` `concludeWorkspaceFlow` и в `owedConclusionSignal`; страж принудительного закрытия
   sheet при смене промпта также читает его. Отменить после добора нельзя: сервер списал использование в момент добора,
   B на сброшенных стадиях = «свернуть».
5. **Награда/результат**: уход кадра руки (`handStepHosted` ↓) → `beginPartyResult()` → бит `[data-pact-result]`
   («Сброшено 2 · +N М€ за меток: M» или честное «меток нет — 0 М€»), затем `concludeFlow()` → одно охраняемое завершение.
6. **Сворачивание/восстановление**: B на шаге сброса = «свернуть» весь workspace (карточка на поле — путь назад);
   `actionWorkspaceRestorePlan` получил `hostedHand` — шаг руки пересаживает партийный композер из драфта
   (`consoleCardActionsUi.draft` = ключ партии); `seat-outcome` для ключа партии не трогает `outcomeFlow` карточного
   композера. **Перезагрузка посреди сброса**: сервер перестраивает промпт сброса; на клиенте кадров нет, плашка
   объявляет решение, A → `openShellTaskSurface` → `resumePartyActionWorkspace(party)` поднимает workspace действий
   заново вокруг шага (`openWith = {party, resume: true}`: тайл партии берётся из ИСТОЧНИКОВ — сетка меню уже
   отфильтровала использованное действие; стадия `committed`, `partyMcBefore` и числа сброса пересаживаются в
   `mounted()`), рука встаёт его шагом — flow заканчивается там же, где начался, битом награды.

## 5. Осмотр (X) и тексты

`parliamentAnnotations.ts` переписан: партия — `ЭФФЕКТ` (одно предложение) · `ДЕЙСТВИЕ` (предложение + нюанс правил +
живое состояние «раз за поколение · доступно/использовано/причина») · `ДЛЯ ВАС` (фактические основания доступа) ·
`ДОСТУП` (одна строка справки). Резолюция — `ЭФФЕКТ РЕЗОЛЮЦИИ` (dummy: «Собственного эффекта нет») · `ЭФФЕКТ ПАРТИИ`
(что даёт принятие) · `ЗАДАНИЕ ПРЕДСЕДАТЕЛЯ` (условие + награда) · `СТАТУС` (слот · делегаты · лидер; побеждает/нет; ваши
делегаты). Имена партий и тексты действий переводятся ДО подстановки в параметры (`translateText`) — смешение языков
устранено. Предмет осмотра партии — `ConsolePartyPlaque size="full"` (`CardZoomCard`), фит вьюера знает `.con-pseal--full`.
Высота панели правил ограничена полосой карты (TV ≈ 1760 px, Deck ≈ 575 px), а шрифты — полом чтения, поэтому длинное
четырёхблочное чтение получило четвёртую ступень длины панели — `--packed` (`ConsoleCardRulesPanel.lengthTier`,
> 300 символов локализованного текста): тип остаётся плотным, уступает ХРОМ (зазоры групп/строк, чипы, паддинг). Плюс
редактура: строка «Требование партии на картах: выполнено» опущена (сюрприз только «не выполнено»), ссылка на правило —
одна строка, у резолюции — эффект партии сказан один раз (пассивный, иначе действие), задание с наградой в одной строке,
статус в двух.

## 6. Индустриалисты — однозначный выбор

Строки решения носят маркер состояния (номер → ✓), чип под курсором — циановое кольцо, выбранный — мятная плита,
оба — плита в кольце. Кнопка выполнения показывает готовность кольцом точек (по одной на решение) и оживает только при
полном выборе; строка «ИТОГ» сводит операцию по пулам: снижение и повышение ОДНОГО производства — один чип
`M€ 4 → 5`, разных — два чипа. Подсказки «Сначала выберите…» удалены.

## 8. Честные ограничения

1. Перезагрузка посреди сброса Красных проходит через плашку обязательного решения на поле (кадров на клиенте
   после перезагрузки нет — их поднимает A); сам композер после подъёма стоит в стадии `committed` без анимации входа.
2. R3-слой «Эффекты» в композере партийного действия по-прежнему отсутствует.
3. Оплаченный голос (делегат из резерва) поднимает промпт оплаты в зоне стадии голоса (`[data-embed-slot="parliament"]`) —
   штатный `ConsoleTaskHost`; отдельного сценария приёмки в этой итерации нет.
4. Резолюции — dummy без арта; печать партии в окне арта — намеренная замена плейсхолдера.
