# Turmoil Redux — Biodome Contest (RX03): награда всем по влиянию + тайл победителю

Дата: 2026-09-17. Продолжение `TURMOIL_REDUX_AQUIFER_CONTEST.md` (шаблон семейства `RX##`) и
`TURMOIL_REDUX_ARCHITECTURE_AWARD.md` (счётный член).

Biodome Contest — третья настоящая резолюция и первая, где **обычный ресурс всем по влиянию** соседствует с
**размещением тайла победителем**, которое само двигает глобальный параметр и тянет за собой всю цепочку
последствий (РТ за тайл, РТ за шаг кислорода, порог 8 % с температурой и океаном, бонусы клетки, реакции партии).
Документ фиксирует трактовки, общий слой (данные о части победителя, её чтение и блок в интерфейсе), исправленный
досье-движок, живые сценарии «Полигона», проверки и рецепт для следующих резолюций этого вида.

## 2. Правило и трактовки

Печатный текст: *When enacted: Gain 2 plants per point of Influence you have. The player that won this resolution
places a greenery tile and raises Oxygen 1 step.* Задание председателя: разместить 2 озеленения.

**Формула общей части:** `растения = 2 × влияние` для **каждого** участника (голосовал или нет, есть ли доступ к
эффекту партии — неважно): 0 → 0, 1 → +2, 2 → +4, 3 → +6, 5 → +10. **Максимума нет** — «макс. 5» принадлежит
Architecture Award, а не семейству.

| Вопрос | Трактовка | Где закреплено |
| --- | --- | --- |
| Что именно выдаётся | Обычные растения в запас (`stock.add`): не производство, не ресурс на карте, не метка растения, не общий пул | спек «two plants per influence for EVERY participant» |
| Влияние | Канонический `parliament.influence(player)` **после** шага победителя по Повестке (драйвер сеет `ctx.influence` после шага 1); учитываются все надбавки, которые знает реестр | спек «the winner's Agenda step is counted BEFORE the plants» |
| Победитель | Получает свои растения **один раз**, как все, и **отдельно** — озеленение | спек «the winner is paid once and places on top» |
| Часть победителя | Одно стандартное размещение (`PlaceGreeneryTile`): клетки даёт общий валидатор (`getAvailableSpacesForType('greenery')` + правило Красного города), тайл принадлежит игроку, бонусы клетки работают | спек «the general validator decides the cells» |
| «Поднимает кислород на 1 шаг» | Это **собственный** подъём озеленения (`Game.addGreenery`), второго подъёма нет | спек «one greenery, one oxygen step» |
| РТ | +1 РТ за тайл (ревизия озеленений Redux, `ParliamentHandler.onGreeneryPlaced`) **и** +1 РТ за фактический шаг кислорода; при максимуме кислорода — только РТ за тайл | спек «the tile's own TR stands at maximum oxygen» |
| Порог 8 % | Обычный: температура +1 шаг (и её РТ), при 0 °C — бесплатный океан по общим правилам; всё это идёт через штатные системы | e2e `console-parliament-biodome` (каскад 7 % → 8 % → 0 °C → океан) |
| Бесплатность | Растения не тратятся и не требуются, стоимость стандартного проекта не платится, действие не расходуется, это **не** конверсия растений | спек «free: no plants, no cost, no action» |
| Фаза | `Phase.PARLIAMENT`: не режим Мирового правительства (без РТ) и не финальный режим озеленений (без кислорода) — даже в последнем поколении | спек «never the World Government or final-greenery mode» |
| Эффект Зелёных | Партия уже правит в момент принятия, поэтому её обычный хук платит 2 M€ за каждый фактически полученный шаг РТ | спек «the Greens pay for the TR that actually lands» |
| Плоская выдача растений | Не запускает реакцию Зелёных на **производство** растений — это не производство | спек «a plain plant gain is not production» |
| Влияние 0 | Названный ноль: строка журнала + `outcome skipped` («Нет влияния»), без фиктивной выдачи и без пустого обязательного выбора | спек «influence 0 is a named zero» |
| Нулевая общая выплата | Часть победителя не отменяет — это независимые шаги | спек «a zero payout does not cancel the winner's tile» |
| Кислород на максимуме | Тайл всё равно размещается | спек «the tile lands with oxygen maxed» |
| **Нет доступной клетки** | Часть победителя **названа и пропущена** (журнал + `outcome skipped`): пустого выбора нет, фаза не виснет, ничего не подменяется (ни деньги, ни растения, ни «просто кислород» — подъём принадлежит размещению, которого не было). **Авторского FAQ на эту грань нет — это трактовка проекта** | спек «no legal cell — the part is named and skipped» |
| Нейтральная победа | Озеленение не размещает никто (`winnerSteps` для нейтрального не выполняются — FAQ правил, с. 18, Colony Contest); общая выплата сохраняется | спек «a neutral winner keeps the shared payout» |
| Задание председателя | «Разместить 2 озеленения» — тип задания «тайл», не выдача растений, не метки, не накопление ресурсов. Засчитываются только **свои** размещения в фазу действий, пока задание активно; это озеленение **не** засчитывается (корень цепочки — политическая фаза, `QuestTracker.eligible` требует `Phase.ACTION`), как бы поздно ни ответили на выбор клетки. Своё озеленение при максимуме кислорода засчитывается (заданию нужен тайл, а не рост параметра) | спек «the resolution's own greenery gives no quest progress» |
| MarsBot | Политика `none` не меняется: бот не считается получателем, обязательных выборов ему не выдаётся, общие правила Redux для озеленений бота остаются | спек «MarsBot (mode none)…» |

## 3. Жизненный цикл и однократность

- Шаг `plants` **мутирует** (ничего не спрашивает): `stock.add(PLANTS, amount, {log: false, from: {resolution}})` —
  штатное изменение со всеми событиями и записью в EventRecorder; одна строка журнала несёт весь расчёт
  (`влияние → растения`), `ctx.report({kind: 'stock', …})` кладёт в запись `before/after/influence`.
- Шаг `greenery` **спрашивает**: `new PlaceGreeneryTile(player, 'greenery', {placementContext: committedPlacement(…,
  {kind: 'resolution', resolution: BIODOME_CONTEST_ID})})`, ответ мутирует и репортит
  `{kind: 'greenery', space, parameter: {id: 'oxygen', before, after}}` — кислород читается **до** и **после**
  реального размещения, а не предсказывается.
- Ключи идемпотентности драйвера `effect:<gen>:<instance>:<seat>:<step>`. ⚠️ **Исправлено в этой итерации:**
  ключи содержали `PlayerId`, а `Cloner.replacePlayerIds` (клон партии, загрузка фикстуры, dev-дверь) выдаёт новые
  id — после ремапа ключ переставал совпадать, и растения выплачивались **второй раз**. Теперь запись ведётся
  по **месту за столом** (`appliedBySeat: Record<PlayerId, Array<string>>`, ключ шага без id) с обратной
  совместимостью со старым плоским списком строк: старые сохранения читаются как есть, новые не ломаются ремапом.
- Возобновление: перезагрузка внутри размещения повторно строит тот же вопрос и читает тот же кислород (пока фаза
  ждёт ответ, на столе ничего не меняется). Повторный запрос/реконнект не повторяет ни растения, ни тайл, ни РТ,
  ни деньги Зелёных, ни бонусы клетки. Постоянного флага «эта карта уже срабатывала» нет — законное повторное
  принятие в другом поколении даёт эффект снова.
- Обязательные последствия (в т.ч. вложенные выборы — бонус-карта клетки, океан от температуры) завершаются до
  продолжения политического цикла: цикл ждёт `phase.pending`.

## 4. Общий слой (переиспользуемо следующими резолюциями)

### Сервер и `src/common`

- **`src/common/parliament/winnerReward.ts`** — часть победителя как **данные**: `WinnerRewardDeclaration`
  (`{kind: 'tile', tile: 'greenery' | 'ocean'}`), `REDUX_GREENERY_TILE_TR`, `winnerParameterRoom(reward, table)`
  (что сделает собственное размещение с параметром прямо сейчас: `current/max/rises/resulting/tileAvailable/
  temperatureBonus`), `winnerRewardTr(reward, room)` и `winnerRewardTrTotal`. Одно место, где записано «сколько это
  стоит РТ» — клиент ничего не выводит сам. Про клетку здесь не говорится **ничего**: её бонусы — дело досье.
- **Запись исхода** (`SerializedParliament` / `ParliamentModel`): виды `stock` и `greenery`, поле
  `parameter: {id, before, after}`, `part: 'effect' | 'winner'` (кто именно это получил — общий эффект или
  победитель), `stock` (какой ресурс). Старые записи без `part` читаются по виду исхода.
- **`BoardInformationEngine`**: `greeneryRevisionFacts` (+1 РТ за тайл — раньше досье молчало об этом и при
  максимуме кислорода показывало пустоту), `partyReactionFacts` (выплаты правящей партии за фактические шаги РТ),
  `terraformRatingFact(..., reason)` — у факта появилась **причина**, которую клиент показывает вместо
  собственной догадки (`BoardFact.reason` → `placementDossier.reasonLabel`).
- **Dev-дверь «живых сценариев»** (`ApiDevPlaygroundScenario` + общий `devFixtureBoot` + `PlaygroundScenarioModel`):
  POST `api/dev/playground-scenario?scenario=<имя>` поднимает сгенерированную движком фикстуру как **настоящую
  партию** и отвечает `{gameId, playerId, seats}`. Имя допускается **по форме** (`parliament-…`, ничего
  путеподобного), доступ — как у остальных dev-дверей (loopback/ADMIN), сборка без фикстур отвечает 404 с
  причиной. `ApiDevLoadGame` переведён на тот же общий хелпер.

### Клиент

- **`winnerRewardModel.ts`** — одно чтение части победителя на все поверхности, по моменту:
  `reference` (без стола — каталог/инспектор), `conditional` («при победе», карта на голосовании — что сделает
  размещение со столом **сейчас**), `pending` (карта принята, получатель зафиксирован, тайл ещё впереди),
  `applied` (сервер записал: параметр до/после или названный пропуск, с поколением). Нейтральная победа — своё
  конечное чтение. Плюс `winnerRewardSentenceOf` (та же мысль словами для инспектора) и `winnerRewardRuleKey`
  (одно уточняющее предложение про РТ).
- **`ConsoleWinnerReward.vue`** — один графический блок части победителя (`block` / `chip` / `inline`): звезда и
  подпись момента, тайл, параметр `7 → 8 %` или «Макс.», суммарный РТ и разбивка. Стоит **отдельно** от
  чисел влияния, чтобы никто не прочитал бесплатное озеленение как общее или как оплаченное своими растениями.
  Хосты: блок эффекта в голосовании, подвал полноэкранного осмотра, стенд «Полигона», итоги.
- Разбор досье размещения при этом остаётся единственным местом, где обещают **конкретную клетку**: до выбора
  клетки бонусы не обещаются нигде.

### «Полигон» («Витрина резолюций Redux»)

- Семейство сценариев **`winner-tile`**: влияние 0 / 1 / 3 / сверх трека (7 → +14, без максимума), разные места с
  разным влиянием, взгляд победителя и другого игрока на одно и то же размещение, нейтральная победа, шаг Повестки
  перед выплатой, кислород ниже максимума / на максимуме / на пороге 8 % (РТ 1 / 2 / 3), отсутствие доступной
  клетки, записанный результат, задание 0/2 → 1/2 → выполнено. Все числа считает та же модель, что и игра.
- **Живые сценарии** (отмечены в кольце): A поднимает фикстуру как настоящую партию и уводит игрока туда —
  голосование, реальный выбор клетки с каскадом (7 % → 8 % → 0 °C → океан), максимум кислорода, отсутствие клетки,
  нейтральная победа, итоги поколения. Требование §13 («набор статических карточек недостаточен») выполняется
  именно здесь.

## 6. Рецепт: резолюция «награда всем по влиянию + тайл победителю»

1. **Каталог**: id `RDX_<партия>_<имя>`, следующий свободный `RX##` по алфавиту, заглушку той же партии — в
   `copies: 0` (совместимость сохранений), арт через `scripts/import-card-art.mjs`.
2. **Эффект всем**: `InfluenceScaledEffect` с `unit: {kind: 'stock', resource}` и `recipient: 'each'` — модель
   влияния, журнал, записи исходов и чтения на всех поверхностях появляются сами.
3. **Часть победителя**: `winnerReward: {kind: 'tile', tile: …}` в каталоге + шаг в `winnerSteps`, который
   спрашивает **штатное** размещение с `placementContext` (источник — резолюция) и репортит `parameter` до/после.
   Ничего не считать самому: `winnerReward.ts` уже знает про РТ и про максимум параметра.
4. **Грани**: нет клетки → названный пропуск; нейтральная победа → шаг не выполняется; нулевая общая выплата не
   отменяет часть победителя.
5. **Показ**: `ConsoleWinnerReward` (block/chip/inline) рядом с `ConsoleInfluenceYield` — своих чисел не считать.
6. **Проверки**: серверный спек на правило и грани, превью↔факт для досье (если тайл двигает параметр),
   e2e на живую цепочку и сценарии стенда, включая живой запуск.
