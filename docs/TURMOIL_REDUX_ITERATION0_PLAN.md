## 2. Архитектура сервера

### 2.1 Выбор движка, операции для контента, готовность карт — три разных вещи

1. **Выбор движка.** `GameOptions.turmoilReduxExpansion` (+ `expansions.turmoilRedux`) и
   классический `turmoilExtension` взаимоисключающи (валидация в `Game.newInstance`, рядом с
   существующими отказами — `Game.ts:320-328`; классика в консольном создателе по-прежнему не
   предлагается). При Redux создаётся `game.parliament: Parliament`; классический `game.turmoil`
   не создаётся. Redux требует `coloniesExtension` (проверка там же и в создателе).
2. **Операции для контента — `game.politics: PoliticalOps | undefined`** (новый fork-owned файл
   `src/server/politics/PoliticalOps.ts`), реализации: `ReduxPoliticalOps` (над `Parliament`) и
   `ClassicPoliticalOps` (тонкий адаптер над `Turmoil`, чтобы у контента была одна точка вызова;
   классический движок из UI недоступен, адаптер существует ради единообразия и тестов). Семантика
   Redux по таблице:

   | Операция | Redux |
   | --- | --- |
   | `sendDelegates(player, party?, count, opts)` | размещение на резолюции указанной партии в области голосования; без партии — выбор игрока (`SelectParty` по партиям области); нейтральный — по тем же правилам |
   | `dominantParty()` | партия текущей побеждающей резолюции (ничья — ближе к ENACTED) |
   | `partyLeader(party)` | лидер голосования на её резолюции по правилам Redux; `undefined`, если партии нет в области |
   | `normalizeParty(party)` | `KELVINISTS → GREENS` |
   | `influence(player)`, `addInfluenceBonus(player, n)` | Agenda + бонусы карт |
   | `chairman()`, `isChairman(player)` | владелец кресла |
   | `satisfiesPartyRequirement(player, party)` | правит **или** ≥N собственных делегатов на резолюции партии (N = 2, параметр) |
   | `hasPartyEffect(player, party)` | правит ∨ ≥2 делегатов ∨ грант картой (`grantPartyEffect(player, party, source)` / `revokePartyEffect`) |
   | `eventDeckOps()` | в Standard — операции над колодой резолюций (`peek/draw/discard`); Chaotic позже подменит на колоду событий |
   | `neutralDelegatesOnResolutions()`, `replaceNeutralDelegate(...)` | Collusion: только на резолюциях, Popular Support исключён |
   | `delegatesInReserve(player)`, `delegatesOf(player, party)` | по леджеру |

   Контент вызывает только `game.politics`; `Turmoil.getTurmoil` в новом коде не используется.
   `PartyRequirement`/`ChairmanRequirement` переводятся на фасад (классика через адаптер).
3. **Готовность карты и включение в пул.** `compatibility: 'turmoil'` в манифестах трактуется как
   «требует политического движка». Новый признак записи манифеста `politics?: 'classic' | 'redux' |
   'both'` (для карт, вех/наград, тайлов колоний): при Redux в пул попадают только записи с
   `'redux'`/`'both'`; при отсутствии признака запись считается `'classic'` (не готова). В нулевой
   итерации ни одна политическая карта не помечена → пул Redux совпадает с сегодняшним, но путь
   адаптации карты = «реализовать через `game.politics` + пометить `'redux'`», без включения
   классического флага. Классические вехи/награды Lobbyist/Politician/T. Politician — `'classic'`;
   Pallas — `'classic'`; `SpaceBonus.DELEGATE` (доска VBN) — через `politics.sendDelegates`.

### 2.2 Состояние (`SerializedParliament`, `version: 1`)

```ts
type ResolutionId = string;              // 'RDX_UNITY_1' … устойчив, из каталога
type ResolutionInstanceId = string;       // `${ResolutionId}#${copy}` — экземпляр в колоде
type Delegate = PlayerId | 'NEUTRAL';
type Vote = {owner: Delegate; seq: number};            // seq — глобальный монотонный счётчик
type Slot = {instance: ResolutionInstanceId; votes: Array<Vote>};   // index 0 = ближайший к ENACTED
type Enacted = {instance: ResolutionInstanceId; quest: QuestState} | undefined;
type QuestState = {definition: QuestDefinition; generation: number;
  progress: Record<PlayerId, number>; completedBy?: PlayerId};
type DelegateLedger = {lobby: 0 | 1; reserve: number; chairman: 0 | 1;
  onResolutions: Record<ResolutionInstanceId, number>};   // сумма всегда 7 (инвариант, ассерт)
type PhaseProgress = {generation: number; step: PhaseStep; cursor?: number;
  pending?: {player: PlayerId; key: string}; applied: Array<string>};
```

Поля `Parliament`: `slots: [Slot, Slot, Slot]`, `enacted`, `chairman?: PlayerId`, `ledgers:
Record<PlayerId, DelegateLedger>`, `neutralSupply: number`, `popularSupport: Record<PartyName,
0|1|2|3>`, `agenda: Record<PlayerId, 0..12>`, `influenceBonus: Record<PlayerId, number>`,
`grantedEffects: Record<PlayerId, Array<{party, source}>>`, `partyActionUses:
Record<PlayerId, Partial<Record<PartyName, number>>>`, `resolutionActionUses: Record<PlayerId,
number>`, `deck: Array<ResolutionInstanceId>`, `discard: Array<ResolutionInstanceId>`, `voteSeq`,
`phase?: PhaseProgress`, `botMode: 'bystander'`.

Загрузка: неизвестный `ResolutionId` или `version` старше поддерживаемой → `IncompatibleSaveError`
с именем игры и идентификатором (явная несовместимость, не пустой слот). Каталог резолюций
неизменяем по идентификаторам: добавление новых карт не меняет dummy в сохранённых партиях.

### 2.3 Правила разрешения

- **Победившая резолюция**: максимум голосов; ничья → меньший индекс слота.
- **Победивший игрок**: среди не-нейтральных владельцев — максимум голосов; ничья → минимальный
  `seq` первого голоса; только нейтральные или нет голосов → нейтральный (Agenda не двигается,
  ★-эффекты не выполняются).
- **Лидер партии** (для `PoliticalOps.partyLeader`) — то же правило на карте партии.
- **Доступ**: `hasPartyEffect` / `satisfiesPartyRequirement` — §2.1; оба живые; использования
  действий хранятся отдельно (`partyActionUses`, `resolutionActionUses`) и **не сбрасываются** при
  потере/повторном получении доступа в поколении.
- **Голосование**: доступно в фазу действий, если `lobby === 1` (бесплатно) или `reserve > 0 &&
  canAfford(5)`; полное действие; только область голосования. Порядок: оплата → размещение →
  лог/событие → прогресс задания «делегаты».

### 2.4 Партийные эффекты (`src/server/parliament/parties/*.ts`)

Единый интерфейс `PartyEffect {party; passive?: {onTilePlaced?, onTerraformRatingGained?,
onProductionChanged?, wildTags?}; action?: {id, canAct(player): Availability, execute(player):
PlayerInput | undefined, preview(player): ActionPreview}}`. Доступ проверяется в момент хука через
`hasPartyEffect`; пассивы работают в любой фазе, где выполняется их условие (решение Q7), WGT
сохраняет свои исключения (фаза SOLAR не даёт РТ — хук Зелёных не вызывается).

| Партия | Реализация | Точки входа |
| --- | --- | --- |
| Unity | `TradeWithUnity implements IColonyTrader` (бесплатно; нужен свободный флот; занятость колонии соблюдается), опция трека `bonusTradeOffset = 1` через существующий `IncreaseColonyTrack` (спрашивает); использование учитывается в `partyActionUses[UNITY]` при фактической торговле | `Colonies.tradeHandlers()`, `Colony.trade`, зеркало `colonyTradePreview.ts` |
| Greens | `onTerraformRatingGained(steps)` → +2 M€ × steps (источник `party`); `onProductionChanged(plants\|heat, +delta)` → +delta пр. M€ (по фактической дельте) | `Player.increaseTerraformRating.raiseRating`, `Production.add` |
| Scientists | `wildTags(player) = 1` в режимах `default`/`milestone` `Tags.count`; действие: выбор data/микробы (только типы, для которых есть допустимая карта) → `AddResourcesToCard(count 2)`; нет получателей → недоступно с причиной | `Tags.count`, `AddResourcesToCard` (с `autoSelect:false`) |
| Mars First | `onTilePlaced(space)` для Марса (не колонии): +1 сталь; город → +1 карта | `Game.grantPlacementBonuses` (рядом с `resolveTilePlacementBonuses`) |
| Industrialists | действие: выбор уменьшаемого производства (только допустимые: M€ > −5, прочие > 0) → выбор M€/энергии +2; допустимость считается до операции, уменьшение того же ресурса разрешено при возможности уменьшить | `SelectProductionToLose`-подобный ввод или `OrOptions` по ресурсам + `Production.canAdjust` |
| Reds | действие: `DrawCards.keepAll(2)` → `DiscardCards(2,2)` с `exchange`-маркером → +2 M€ за метку растения/микробы/животные сброшенных (печатные метки, с учётом событий) | `DrawCards`, `DiscardCards`, `Tags` |

Опции меню действий несут маркер `partyAction: {party, usesLeft}`; действие принятой резолюции —
`resolutionAction: {id, usesLeft}`; голосование — `votePrompt: {source: 'lobby'|'reserve', cost,
slots: [{instance, party, projection}]}`. Все маркеры — в `promptMarkerGuard`.

### 2.5 Резолюции (`src/server/parliament/resolutions/**`)

```ts
interface ResolutionDefinition {
  id: ResolutionId; party: PartyName; copies: number; compatibility?: Array<Expansion>;
  renderData: ICardRenderRoot; text: {effect: string; quest: string};   // EN-ключи
  quest: QuestDefinition;                       // обязательна
  immediate?(ctx: EnactContext): void;          // ctx.forEachPlayer + ctx.ask(player, input, key)
  winner?(ctx: EnactContext, winner: IPlayer): void;
  passive?: PartyEffect['passive'] & {cardDiscount?, resourceValue?, onCardPlayed?};
  action?: {maxUses(player): number; canAct; execute; preview};
}
```

Dummy: `RDX_<PARTY>_1/2` × 6 партий, `copies: 1`, `immediate/winner/passive/action` отсутствуют,
`quest` — реальные виды из каталога (по одному на карту: 2 метки Земли, 2 озеленения, 2 метки
науки, 2 метки стройки, +1 пр. стали, 4 делегата, …). Грань говорит «Эффект резолюции: нет
(тестовая резолюция)». Тестовая резолюция `RDX_TEST_CHOICE` (вне пула, `copies: 0`) — немедленный
эффект с выбором каждого игрока (`ctx.ask`) для проверки возобновления.

Каталог → `genfiles/resolutions.json` (генератор рядом с `GlobalEventProcessor` в
`export_card_rendering.ts`), клиентский `ClientResolutionManifest`.

### 2.6 Задания председателя (`src/server/parliament/quests/**`)

`QuestKind` (каталог): `productionSteps(resource)`, `tags(tag)`, `tiles(kind: greenery | cityOnMars |
cityOrSpecial | spaceCity)`, `colonies`, `tr`, `cardResources(kind)`, `delegates`, `cardsPlayed(type)`,
`trades` (резерв). Стартовое задание поколения 1: `productionSteps(heat) × 3` — только при пустом
ENACTED в первом поколении; далее задание берётся из определения принятой резолюции.

Трекер получает `QuestProgressEvent {kind, player, amount /* фактическая дельта */, origin}` из точек
мутации: `simpleAddTile` (тайлы), `Production.add` (усечённая дельта), `Player.playCard` (метки,
тип), `increaseTerraformRating.raiseRating` (фактические шаги), `addResourceTo` (ресурсы карт),
`Colony.addColony`, `Parliament.vote`. Допустимость — по корню текущего scope рекордера
(`EventRecorder`: добавить `currentRoot(): {player, category, phase, sources[]}`):
`phase === ACTION`, `root.player === игрок`, `category ∈ OWN_ACTION_CATEGORIES`, и в цепочке
источников **нет** `{kind:'resolution'}` (эффект принятой резолюции, включая её действие, не
зачитывается — решение Q5). Прогресс — игровая логика; журнал/уведомления отражают его, но не
определяют. Выполнение: при `progress ≥ count` и `completedBy === undefined` → Agenda +1, делегат в
кресло по правилу: предыдущий председатель — владельцу в резерв; действующий председатель
сохраняет своего; при отсутствии свободного делегата — из резерва, затем из лобби, затем с
выбранной игроком своей резолюции (`SelectParty` по своим картам); восьмой делегат не создаётся.

### 2.7 Политическая фаза — драйвер и фаза игры

- Новое значение `Phase.PARLIAMENT = 'parliament'`: тайлы получают владельца и бонусы, параметры
  дают РТ (`addTile`/`increase*` проверяют `!== Phase.SOLAR`), карточные хуки на `Phase.ACTION` не
  срабатывают; WGT остаётся под `Phase.SOLAR`.
- Порядок нефинального цикла: производство → возврат флотов и рост колоний
  (`returnTradeFleets`, `endGenerationForColonies`) → **`ParliamentPhase.run`** (шаги 1–5) → WGT
  (если включён) → `startGeneration`. Финальный цикл: производство → шаги 1–3 (Agenda, Popular
  Support, принятие с эффектом) → возврат `Phase.PRODUCTION` → финальные озеленения → подсчёт.
  Область голосования не обновляется, лобби не пополняется.
- Драйвер персистентен (`PhaseProgress`): шаги `winner → agenda → agenda-bonus → support → enact
  → enact-effects(cursor по игрокам, pending-выбор) → refresh → lobby → done`; каждая операция
  имеет ключ идемпотентности (`agenda:<gen>:<player>`, `bonus:<gen>:<player>:<step>`,
  `enact:<gen>:<instance>`, `effect:<gen>:<instance>:<player>`) в `applied`. `Game.deserialize`
  получает ветку `Phase.PARLIAMENT → parliament.resume(game)`, которая пересоздаёт ожидающий
  промпт по `pending.key` из определения резолюции (чистая функция состояния) и выставляет
  `activePlayer` спрашиваемому. Повторный запрос/перезагрузка не выдаёт награды дважды.
- Порядок изменения состояния при принятии: Agenda победителя (и бонус шага) **до** принятия;
  при принятии обновляются ENACTED/правящая партия/доступ; затем эффект резолюции; делегаты
  проигравших карт остаются до шага обновления.
- События рекордера: категория `political-phase`, типы `parliament-vote`, `parliament-winner`,
  `parliament-agenda`, `parliament-support`, `parliament-enacted`, `parliament-refresh`,
  `parliament-chairman`, `parliament-access` (получен/потерян эффект), источники
  `{kind:'resolution', id}` и `{kind:'party'}`. Клиентская сцена и уведомления строятся из них
  (атомарная доставка по идентификаторам событий — без переигрывания после перезагрузки).

### 2.8 Пересмотр озеленений и финал

`Game.addGreenery`: после `addTile` — `+1 РТ` игроку (источник «правило Redux: озеленение»),
кислород как сейчас; финальные озеленения — +1 РТ за тайл, без дополнительного кислорода (решение
Q3), в том числе для бота (`AutomaGameEnd.placeFinalGreeneries` идёт через тот же путь).
`calculateVictoryPoints`: категория `greenery` не начисляется при Redux; ПО городов — как обычно;
классические ПО председателя/лидеров не начисляются (решение Q2). Терраформер — 35 (решение Q12).

### 2.9 Модель для клиента (`ParliamentModel` в `GameModel.parliament`)

`slots[{instance, resolutionId, party, votes[{color|neutral, seq}], leader?, isWinning,
tiePriority}]`, `enacted{instance, resolutionId, party, quest{definition, progress by color,
completedBy?}}` или `undefined` (+ `rulingParty` всегда), `chairman?: color`, `popularSupport`,
`agenda[{color, step, influence}]`, `delegates[{color, lobby, reserve, onResolutions, chairman}]`,
`access[{color, ruling, byDelegates[], granted[]}]`, `deckSize`, `discardSize`, `phase?`
(прогресс для сцены), и для зрителя: `vote{available, reason?, source, cost, projections[по
слоту: {votesAfter, leaderAfter, becomesWinning, unlocksEffect, unlocksRequirement}]}`,
`partyActions[{party, available, reason?, usesLeft, preview}]`, `resolutionAction?`. Все проекции
— чистые серверные функции (guard на чистоту).

## 3. Концепция workspace «Парламент»

Образцы самостоятельных систем: workspace колоний и гидросети. Kind `parliament` в
`WORKSPACE_KINDS` (`hosts: 'inFlow'`, зона `parliament-step`, `serves`: промпты с маркерами
`votePrompt`/`partyAction`/`resolutionAction`). Вход — RT ↓ («Голосование» → «Парламент»);
вход работает всегда для осмотра, ограничения — внутри.

### 3.1 Информационная иерархия (band, TV 4K и Deck)

```
┌ ПАРЛАМЕНТ ──────────────────────────────────────────────────────────────────┐
│ [ПРИНЯТА: грань]  правит ЗЕЛЁНЫЕ · эффект  │ [V1 ★приоритет] [V2]    [V3]   │
│  задание: 2/3 ●●○  кресло: [куб]           │  голоса ●●●○ · лидер: вы       │
│─────────────────────────────────────────────┴───────────────────────────────│
│ ПАРТИИ  [U 1][G ●][S 2][M –][I –][R 3]   эффекты у вас: G, S                │
│ AGENDA  ①②③④⑤⑥⑦⑧⑨⑩⑪⑫  кубы · влияние 2   │ ЛОББИ ● · РЕЗЕРВ 4 · ДЕЙСТВИЯ ▸ │
└─────────────────────────────────────────────────────────────────────────────┘
```

- **Первичный фокус — область голосования** (V1–V3): решение «за что голосовать» читается сразу:
  голоса лентой в порядке размещения (кубы игроков, серые нейтральные), лидер, побеждающая карта и
  подпись приоритета ничьей у V1. Стартовый фокус — V1.
- **Вторичный — принятая резолюция и правящая партия**: грань, формула эффекта партии, состояние
  действия резолюции, задание с кубами прогресса всех игроков, кресло.
- **Третичный — партии/Popular Support/мои эффекты, Agenda/влияние, лобби/резерв, действия**:
  компактный нижний ярус; подробности — X (досье партии, осмотр карты).
- На Deck: тот же порядок ярусов, грани уменьшены, текст эффекта — 2 строки, полный текст — X.

### 3.2 Навигация

| Зона | Перемещение | A | X | B |
| --- | --- | --- | --- | --- |
| Голосование (V1–V3) | ←/→ | стадия «ГОЛОС» (если доступно; иначе причина в статус-строке) | осмотр грани | закрыть |
| Принятая | ↑ из V | действие резолюции (если есть) | осмотр | закрыть |
| Партии | ↓ из V | действие партии (если у партии есть действие и доступ) | досье партии | назад в V |
| Agenda | ↓ из партий | — | пояснение шагов | назад |
| Действия (ряд тайлов) | → из партий / ↓ | стадия действия | превью | назад |

Командная строка меняется по зоне; глифы — `GamepadGlyph`; ничего не кликается мышью иначе, чем
пад. Фокус стабилен при обновлении модели (ключи по `instance`, не по индексу).

### 3.3 Стадии (ONE FLOW, crumb `ПАРЛАМЕНТ › <субъект> › <ЭТАП>`)

- **ГОЛОС** (`ПАРЛАМЕНТ › <РЕЗОЛЮЦИЯ> › ГОЛОС`): соседние карты отпускаются на месте, выбранная
  разворачивается из своего rect; справа — транзакция `ActionEffectChip`: источник («из лобби ·
  бесплатно» / `🪙 42 → 37`), «резерв 4 → 3», проекция: голоса 3 → 4, лидер (с причиной «первый
  делегат»), станет ли побеждающей, откроется ли эффект/требование партии. A — отправить (submit
  `party`); B — назад без последствий. Результат: куб летит из лобби/резерва (реальные элементы
  нижнего яруса) в ленту карты; счётчик тикает; лидер обновляется; flow уходит через guarded-
  конклюзию. Отмена возможна до A.
- **ДЕЙСТВИЕ партии** (`ПАРЛАМЕНТ › ИНДУСТРИАЛИСТЫ › ДЕЙСТВИЕ`): превью чипами; вложенные шаги
  в зоне стадии: Индустриалисты — две линейки выбора (что уменьшить → что повысить) с
  `current → resulting` и недопустимыми пунктами с причиной; Учёные — выбор типа (только
  допустимые) → карточный пикер целей; Красные — добор (intake в док) → выбор 2 карт на сброс в
  hand album (сумма M€ за метки считается по выделению) → выплата с причиной. A подтверждает на
  последнем шаге; B — уровень назад; после ответа сервера — collapse/уход.
- **Unity**: тайл «Бесплатная торговля» открывает **существующий торговый flow как встроенный
  шаг** (`ПАРЛАМЕНТ › СОЮЗ › ТОРГОВЛЯ`, секция колоний в embedded-режиме по контракту
  `consoleWorkspaceEmbed`) с предвыбранной строкой оплаты «Бесплатно (Союз)» и вопросом «+1 шаг
  трека?»; правила торговли не дублируются; возврат — в парламент.
- **Осмотр** (X): общий зум-инспектор, правая колонка — три блока: «Эффект резолюции»,
  «Эффект партии», «Задание председателя» + проекция «для вас».
- **Досье партии** (X на партии): эффект, действие, кто имеет доступ и почему, Popular Support.

### 3.4 Грань резолюции (новое семейство)

`CardType.RESOLUTION`, тема `resolution` (фиолетовый корпус, серебряная панель механики), геометрия
фиксирована: шапка (эмблема партии слева, заголовок), окно арта (стабильное место под будущий арт,
процедурный фолбэк), панель механики (иконки из ассетов/SVG: влияние, ★ победитель, ресурсы,
производство, тайлы), угол задания (счётчик + иконка), медальон дополнения. Текст правил — в
fullscreen-осмотре справа. Иконки: эмблемы партий (5 существующих `assets/parties/*.png` + новая
Индустриалистов), звезда победителя, значок задания — SVG в общем стиле; недостающие арты не
блокируют.

### 3.5 Политическая фаза — последовательность событий

Сцена «ПАРЛАМЕНТ · ИТОГИ ПОКОЛЕНИЯ» использует **ту же раскладку workspace** (те же DOM-позиции
карт, слотов, лент, трека), чтобы анимации имели точные конечные позиции. Beats из событий
рекордера, каждый завершается своим сигналом (hold анимации или ответ игрока), не общим таймером:

1. Итоги голосования — подсветка, счёт, победившая карта, подпись ничьей.
2. Agenda — куб победителя движется; бонус шага (РТ/карта) летит с причиной «Повестка».
3. Народная поддержка — серые кубы в слоты партий с подписями причин.
4. Принятие — делегаты победившей карты разлетаются владельцам (лобби/резерв), прежняя ENACTED
   уходит в сброс, карта въезжает в слот; «правит: <партия>»; эффект — по игрокам с причинами
   (для dummy — «эффект отсутствует», строка не рисуется); **слот встроенного выбора** (тестовая
   резолюция, будущие реальные): спрашиваемому — вложенный шаг в зоне сцены, остальным —
   «Ожидание: <игрок> выбирает…».
5. Обновление — две карты в сброс (делегаты домой), три новые въезжают из колоды, нейтральные из
   Popular Support прыгают голосами, лобби загорается.
Затем WGT (существующая поверхность), флип поколения, мандатное объявление. После перезагрузки
сцена открывается на шаге по `phase.progress`, уже отыгранные beats не повторяются (ключи событий).

### 3.6 Объяснимость вне workspace

Пассивы партий — в превью розыгрыша/действий (`effectForecast`: факты с источником `rule/party`
вместо `unknown`), в уведомлениях («Вы получили 2 M€ · Зелёные · за +1 РТ») и журнале (источник
`party`/`resolution`); доступ получен/потерян — уведомление с причиной; задание — тосты прогресса.
Новых постоянных плашек в верхней полосе и ресурсной панели нет.

## 4. Временная интеграция MarsBot — режим «наблюдатель»

Явный режим `botMode: 'bystander'` (`BotParliamentPolicy` — интерфейс с точками расширения:
`participates`, `delegatesForBot`, `partyEffectsApply`, `questEligibility`, `onPhaseStep`).
Реализация нулевой итерации:

- Партия Redux с ботом создаётся (конфликт `expansion:turmoilRedux` в `automaCompatibility`
  не добавляется); обычные ходы, колоды, ресурсы, Government Intervention — без изменений;
  дополнительный WGT не запускается.
- У бота нет делегатов, лобби, Agenda, кресла; он не голосует, не выполняет задания; на него не
  применяются партийные эффекты и действия (в т.ч. эффект правящей партии) — политика
  возвращает «не участвует».
- Эффекты «каждый игрок…» будущих резолюций обходят бота через политику (не через ядро).
- Ядро **не** содержит правила «бот никогда не даёт прогресса»: трекер заданий получает события и
  бота, а решение принимает политика (сейчас — «нет»).
- Пересмотр озеленений действует на бота (РТ за тайл, без ПО озеленений) — общий путь `addGreenery`.
- Политическая фаза не блокирует ход бота, смену поколения и сохранение (промптов боту нет).

## 6. Критерии готовности

1. Партия Redux с MarsBot: создание, ≥5 поколений, бот ходит без зависаний и промптов.
2. Workspace через колесо: осмотр без доступного голосования; голосование из лобби и из резерва;
   отмена до A; результат с полётом куба в точную позицию.
3. Шесть эффектов и четыре действия — сценарии от входа до возврата; Unity — через торговый flow.
4. Dummy-резолюции принимаются, уходят в сброс, заменяются; Popular Support, Agenda, влияние,
   председатель (стартовое задание) работают.
5. Сохранение/загрузка на любом шаге фазы и посреди тестового выбора — без повторных наград.
6. Финал: шаги 1–3 в последнем поколении, +1 РТ за озеленение, без ПО озеленений, ПО городов
   сохранены, без классических политических ПО, Терраформер 35.
7. TV и Deck: читаемость, навигация, переходы, нулевой overflow, отсутствие скачков при передаче
   анимации статике.
8. Новая резолюция подключается через `ResolutionDefinition` без правок ядра и workspace
   (доказательство — `RDX_TEST_CHOICE`).
9. Серверные спеки: порядок голосов, ничьи, леджер, доступ, использования, задания,
   восстановление фазы; клиентские unit/e2e по этапам.
