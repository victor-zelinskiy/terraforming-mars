# RX23 · Mohole Contest (Зелёные) — награда победителю ШАГОМ ПАРАМЕТРА

**Статус: СДАНА 2026-09-25.** Четвёртая карта Зелёных и **первая, у которой часть победителя — прямой
шаг глобального параметра без тайла**: «победитель голосования повышает температуру на 2 шага». Это
третий вид `winnerReward` (после тайла RX01/RX03 и колонии RX09), и главное, что он вводит, — **шаг
параметра, за который платят**: в отличие от мирового хода RX12/RX14 (никому не приписан, `unrewarded`),
здесь шаг делает ПОБЕДИТЕЛЬ и получает всё, что положено поднимающему.

Печатный текст: «При принятии: получите по 3 тепла за каждое влияние. Победитель голосования повышает
температуру на 2 шага.» Задание председателя: разыграйте карту с меткой бактерий (зелёный КРУГ с
бактериями = метка, §4.1.1 спека). Дополнений не требует.

Промт: `docs/claude/prompts/resolution-rx23-mohole-contest.md`. Файл карты:
`src/server/parliament/resolutions/greens/MoholeContest.ts`.

## 1. Объявление — и общий исполнитель

```ts
scaled: [{id: 'heat', unit: {kind: 'stock', resource: HEAT}, perInfluence: 3, recipient: 'each'}],
winnerReward: {kind: 'parameter', parameter: 'temperature', steps: 2},          // common/parliament/winnerReward.ts
immediateSteps: [HEAT_STEP],
winnerSteps: [winnerParameterStep(MOHOLE_CONTEST_ID, MOHOLE_CONTEST_TEMPERATURE)],  // resolutions/WinnerParameterStep.ts
quest: {goal: {kind: 'tag', tag: Tag.MICROBE}, count: 1},
```

`WinnerParameterReward = {kind: 'parameter', parameter: 'temperature' | 'oxygen' | 'venus', steps}` — океанов
в этом виде нет нарочно: океан — тайл, и тайл — `WinnerTileReward`. Из объявления выводятся:

| Что | Откуда |
| --- | --- |
| исполнение | `winnerParameterStep(id, reward)` — ОДИН общий шаг семейства (как `levyStep` у бюджетов); карта его лишь перечисляет под ключом `winnerParameterStepKey(reward)` = id параметра |
| комната (сколько шагов реально, потолок) | общая `parameterRoom` — та же арифметика, что у тайла победителя и у мирового хода; `winnerParameterRoom` принимает теперь `WinnerTileReward \| WinnerParameterReward` и несёт `steps` / `applied` |
| бонусы трека по пути | `ParameterRoom.heatProductionBonus` (порогов −24/−20 пересечено) и `oceanBonus` (достигнут 0 °C и тайл океана остался) — считаются в `parameterRoom`, читаются через комнату победителя |
| РТ | `winnerRewardTr` → `parameter: room.applied` |
| ключ шага, запись, чтения, семейство стенда | `winnerParameterStepKey`, `kind: 'globalParameter'` + `part: 'winner'`, `winnerRewardModel`, `familyOf → 'winner-tile'` |

Гард контракта: `winnerReward {kind: 'parameter'}` без шага под выведенным ключом (или шаг без объявления)
не проходит; `steps` — положительное целое; `text.winner` обязателен; запись победителя называет объявленный
параметр, несёт фактические шаги (`after − before` в шаге параметра), **никогда не помечена `unrewarded`**
и несёт `tr` не меньше сделанных шагов.

## 2. ЛОВУШКА: победитель НАГРАЖДАЕТСЯ

`Game.increaseTemperature`: `rewarded = phase !== SOLAR && !options?.unrewarded`. Политическая фаза —
`PARLIAMENT`, значит по умолчанию награда идёт тому `IPlayer`, которого дали движку. RX12 и RX14 передают
`{unrewarded: true}` ЯВНО, потому что там шаг делает закон для всех и никому не приписан. Здесь шаг делает
победитель — и общий исполнитель **не знает слова `unrewarded`** вовсе. Победитель получает:

* **+1 РТ за каждый реально сделанный шаг** (`increaseTerraformRating(steps, {global: true})`);
* **бонусы трека** −24 °C / −20 °C — по +1 производства тепла (и реакцию правящих Зелёных на него: +1 пр. M€);
* **свои хуки** `onGlobalParameterIncrease` и хук Turmoil;
* **реакцию правящей партии на РТ** — Зелёные правят с момента принятия: 2 M€ за шаг РТ, записывается
  движком как `reaction` под шагом `temperature` (карта об этом не знает);
* **океан на 0 °C** — вне гейта награды, как у всех (§3).

Запись несёт **`tr`** — рейтинг, ИЗМЕРЕННЫЙ вокруг вызова движка (`terraformRating` до/после), а не
выведенный из объявления: если карта-хук победителя добавит РТ, запись скажет честно.

## 3. Каскад — океан на 0 °C как встроенный шаг заседания

Движок сам деферит `PlaceOceanTile` для поднимающего (источник промпта — `{kind: 'system', name:
'Temperature bonus step'}`, не резолюция: это честный непосредственный источник, и он не переписан).
Три вещи сделаны, чтобы этот промпт не «повис» вне сцены:

1. **Драйвер дренирует хвост мутирующего шага СРАЗУ** (`ParliamentPhase.stepEffects`): раньше отложенная
   работа мутирующего шага шла после обхода ВСЕХ мест (у спрашивающих шагов — RX01/RX03 — хвост дренировался
   в `continue()` ответа, потому и «фаза ждёт океан» работала только для них). Теперь океан победителя
   размещается, пока остальные места ждут, — как у любого встроенного шага.
2. **Модель называет хвост как ask того же шага** (`ParliamentModel`): когда `effects.pending` пуст, а окно
   реакций (`effects.scan`) называет место, у которого стоит промпт (и это не гейт фазы), сервер публикует
   `pending = {player, key: <шаг>, input}`. Другие места читают честное ожидание («синий размещает»), а само
   место — шаг заседания.
3. **Клиент: хвост-размещение** (`consoleSittingFlow.sittingTailPlacementOf`): промпт `space` без
   источника-резолюции + `pending` сервера на этого зрителя с `input: 'space'` → `rewardStep = 'placement'`,
   `position.tail = true`. Хвост держит страницу НАГРАДА (`sittingRewardSettled` = false → `owed-step`),
   крошка называет «РАЗМЕЩЕНИЕ», и он стоит **за той же дверью, что тайл RX01** (`parliamentPlacementDoorClosed`
   учитывает хвост): допущенный сразу, он забирал экран ДО волны тепла — секция размонтировалась и волна
   сбрасывалась неигранной (первый прогон e2e). Разница в том, КТО открывает дверь: **обход заседания, когда
   его страница тиха** (волна села, ничего не хостится, ничего не дочитывается), никогда не нажатие — глагола
   «К полю» у хвоста нет.

**Один рейс к полю.** Планетарный такт (`parliamentWorldBeat`, обобщён с RX12 — см. §5) уводит рамку к
доске для глайда маркера; размещение океана начинается там же, и `runWorldMoveBeat(…, {boardBusy})` **не
возвращает стек, пока у зрителя стоит `space`-промпт** — рамку возвращает конец размещения
(`resumeYieldedStackOverQuietBoard`), а квитанция читается тогда. `mayYieldForWorld` допускает уход при
`rewardStep === 'placement' && tail` (у резолюционного тайла — двери RX01 — по-прежнему ждёт нажатия).

Потолок: один шаг до максимума — один шаг и запись с фактическим числом; на максимуме — **названный
пропуск** («Температура на максимуме: не повышается»), тепло всем всё равно выдано. Часть победителя от
влияния не зависит (влияние 0 пропускает только тепло). Нейтральный победитель — шага нет, тепло всем.

## 4. Чтения

* **Осмотр / панель голосования** (`winnerRewardModel`): контексты те же четыре; для шага комната читает
  «температура −4 → 0 °C; РТ +2; на 0 °C следует океан» / «производство тепла +1» / «температура на
  максимуме — без шага» (`winnerStepFollowUps`, `winnerParameterRangeKey`, `winnerParameterMaxKey`). РТ
  за океан в сумму НЕ входит (как и клетка тайла — это дело досье размещения); океан назван как следствие.
  Глаголы — «повышает» (`You raise it` / `Raised by ${0}` / `You raised it` / `Raised · ${0}`); правило под
  блоком победителя — одна фраза про «как обычный игрок: 1 РТ за шаг, бонусы шкалы, океан на 0 °C».
* **Блок победителя** (`ConsoleWinnerReward`): глиф — иконка параметра (`con-wreward__tile--temperature`,
  тот же спрайт HUD), единицы `°C`, «Макс.» на потолке, в заметке — бонусы трека.
* **Лента заседания**: чип `tile` с глифом параметра (тип `WinnerRewardGlyph`), чтение — блок победителя.
* **Итоги**: запись победителя — часть его СТРОКИ (`ResultsPayoutPart.parameter` + `tr`: иконка,
  «−4 → 0 °C», «РТ +2»); **строка ПЛАНЕТА только для мировых записей** — награждённый шаг победителя на неё
  не попадает (её смысл — «ход, которого никто не делал»).
* **Стенд «Полигон»**: семейство `winner-tile`; сценарии с `parameter: 'temperature'` показываются только
  закону, чья часть победителя двигает температуру (`scenarioList` учитывает `winnerRewardParameter`), и
  сценарии кислорода RX03 получили `parameter: 'oxygen'`; запись стенда считает `winnerParameterRoom`.

## 5. Показ — планетарный такт для двух тонов

`parliamentWorldBeat` теперь детектирует **записи планеты** (`isPlanetRecord`: `globalParameter` мировая
без места ИЛИ с местом и `part: 'winner'`), ключ — `<место|world>:<шаг>`. Такт тот же: OWE → YIELD → парк
полевых бетов рассказывает историю (маркер едет; для награждённого шага стандартный дельта-чип РТ рельсы
тикает у победителя — ничего своего не анимируется) → RETURN и квитанция. Отличие ровно одно и
структурное: `boardBusy` (§3). Волна тепла на рельсу — путь RX03.

**Попутная починка общего слоя (RX12).** Свидетель волны тепла в e2e вскрыл, что `enterServerStep` сажал обход
на страницу НАГРАДА при входе в шаг, когда «мировой ход должен» — ПРИНЯТИЕ пропускалось, карта не доезжала до
сцены, и волна места сбрасывалась как «не с чего лететь». У RX12/RX14 это не ловили (их e2e проверяли запись,
не чип). Теперь ход, который ещё предстоит, сажает на награду только после сыгранного принятия.

температуры и Венеры, «на 0 °C следует океан», «за Венеру», подписи пяти сценариев стенда.
