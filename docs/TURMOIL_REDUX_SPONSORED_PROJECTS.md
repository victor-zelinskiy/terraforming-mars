## 2. Третья форма единицы — `onto: 'each-counted'` + `resources: 'own-kind'`

Рядом с двумя прежними («одна карта на выбор» и `spread` RX06): по `per` единиц СВОЕГО вида на каждую карту, которую
насчитал счёт. `'own-kind'` — честное «любой» (`CardResourceUnitKinds`), никогда список всех видов игры. Читатели
спрашивают `declaredCardResourceKinds(unit)` / `paysEachCountedCard(effect)`.

Читатели формы, получившие ветку (исчерпывающе): иконка величины (`own-kind-resource` — «?»-куб лица), представление
счёта (глиф `resource-card`, `PremiumCountGlyph` / `premiumCardIcons`), поиск пикера (`scaledEffectForCardResource`), две
заметки «некому» (`noRecipientNoteOf` / `noRecipientCompactNoteOf` — у единицы без объявленного вида ноль — это ноль
счёта, не «сгорело»), семейство «Полигона» (`each-card`), стенд (`countAt`, синтетические записи), модель итогов
(`unitOf` → `OWN_KIND_UNIT`, `eachCard`), аннотации осмотра (ветка `holders`), чтение панели голосования
(`holdersReadingOf`), строка адреса (`rewardAddressRowOf`), класс итога в заседании (`partUnitClass`). Двенадцать.

## 3. Седьмой вид счёта — `holders` (`cardsWithResources`)

Сервер спрашивает ДВИЖОК: `Player.getCardsWithResources()` — то же чтение, что у классического глобального события
Sponsored Projects. Корпорация — карта табло (Р2); держатель с 0 — нет; чужая карта — никогда. Модель
(`ResolutionCountModel.byCard`) держит каждую карту с её видом, числом и тем, что ОДНА единица сделает с её ПО (`vp
{from, to}` — `targetVictoryPoints`, та же функция, что у пикеров). Стенд пересказывает предикат для своих синтетических
держателей (`countHoldersToward` / `holderCountVerdict`), прибитый к движку корпусом. Своя копия «карт с ресурсом» —
дефект (§12 промта).

## 4. Общий шаг — `eachCountedCardStep` (`resolutions/ResolutionEachCard.ts`)

- Список карт фиксируется в `ctx.state` при первом запуске: «уже есть ресурс» читается ДО посадки — реактор (Meat
  Industry, Martian Fiber) не расширит его.
- По `per` единиц вида КАРТЫ через `addResourceTo` (`log: true`, источник — резолюция): журнал называет каждую карту,
  ПО карты двигаются по её правилам, стол отвечает.
- Запись: `cardResource` + `onto: 'each-counted'` + `count` / `counted` / `countedByCard` + `cards[] {card, amount,
  resource, before, vp?}`; единый `resource` — только при посадке одного вида.
- Место без держателя — названный пропуск «No card of yours has a resource yet» (рядом с «No influence» добора).
- Шаг отказывает любой другой единице (гард спека).

## 5. Адрес

Вид и поверхность прежние (`cardResource` / `tableau-card`), но у выплаты без вопроса нет стадии `choice` —
`CARD_RESOURCE_EACH_ADDRESS` (стадия `reward`), строка выбирается по `onto` записи (`rewardAddressRowOf`), полезная
нагрузка несёт `onto`, `before`, `vp`.

## 6. Чтение правила (каждый пункт — `tests/parliament/SponsoredProjects.spec.ts`, 18 спеков)

Объявление и отказ шага от чужой единицы · лицо · счёт = `getCardsWithResources` + ПО + паритет стенда · порядок место за
местом · корпорация · держатель с 0 · чужая карта получает только от СВОЕЙ выплаты · единый вид назван · два названных
нуля · пустая колода · журнал + Meat Industry + Martian Fiber · перезагрузка внутри взятия · список зафиксирован в
`ctx.state` · адрес · задание · бот · модель. `ResolutionContract` — новая проверка `checkEachCounted` (счёт `holders`,
шаг под id части, `onto` на каждой записи, посаженные карты = насчитанные в их порядке, `per` единиц названного вида с
`before`); насыщенное табло держит ресурсы на двух картах, так что платящая ветка пройдена.

## 8. Чтения

- **Лицо**: «[карта с ресурсом] : + [?]» · «[карта] / [влияние]».
- **Панель голосования** — две строки, не складываются: «[влияние] 1 → +1 · +1 если победите» (добор) и «[карта с
  ресурсом] 4 → +4 [?]» (карты); под ними строка держателей (`voteInfoModel.holdersReadingOf` →
  `[data-parl-vote-holders]`): «[вид] Arklight 4 → 5 · Рыба 2 → 3 · Аэростаты 1 → 2 · Суперкомпьютер 3 → 4 · ПО +1» —
  число и вид каждой карты из `countedByCard` сервера, ПО — сумма его `vp`. Место без держателя — строки нет, ноль
  счёта называет себя сам. Чужие исходы (леджер) — колонка каждого места считает СВОИ карты.
- **Осмотр (X)**: «Учтены сейчас: …» со списком изменений и «Эти ресурсы принесут N ПО»; после принятия — «…при
  принятии» и «принесли».
- **Итоги заседания**: «+4 [?] на 4 карты [виды]» — число карт не уступает места никогда, за ним виды по одному разу
  (имена — в квитанции и в осмотре); с 6 карт — число одно (`EACH_CARD_LIST_MAX`), список — X.
- **«Полигон»**: семейство `each-card`, девять сценариев — три вида, голосование, влияние 0, ни одного держателя,
  держатель с 0, корпорация, восемь карт, пустая колода, запись.

## 9. КВИТАНЦИЯ СТОЛА — показ выплаты, которая никого не спросила

Все прежние выплаты закона на карту спрашивали «куда», и их показ стоял на пикере (жетоны садились на капсулы кандидатов
`consoleResolutionPayout`). Здесь пикера нет, и у заседания нет поверхности, где эти карты видны — без новой работы игрок
увидел бы «N ресурсов» в итогах и ничего прилетающим.

**Поверхность** — `ConsoleTableReceipt.vue`: ОДИН ряд лиц принимающих карт (лицо, имя, капсула) с чтением под каждой
(«[вид] 2 → 3», «ПО 2 → 3» где очки движутся). Слой зоны стадии НАГРАДА (`.con-sit__receiptpane`, `data-sit-receipt`;
вход — фраза слоя зоны, уход — свёртка тела; никогда `v-if`-подмена). Ряд решается из панели (`planReceiptRow`: одна
строка, лицо не больше натурального × масштаб × 1.1, промежуток — доля лица, восемь карт ближе и меньше). Лицо монтируется,
когда ряд решён, в тире арта по своей решённой ширине (`artTierForWidth`) — прогретом при посеве (`receiptArtTiers`).
Ничего не называет сама (полоса читает выплату), ввода не держит, не скроллит.

**DETECT → SEED → OWE → PLAY** (`console/parliament/tableReceiptBeat.ts`, образец `careerGrantBeat`):
1. **DETECT** — по ЗАПИСЯМ ФАЗЫ: новые записи зрителя `cardResource` с `onto: 'each-counted'` (не первое знакомство, не
   новое поколение, не чужое место). Никогда по стоящему промпту и никогда по тексту.
2. **SEED** — в блоке применения вида (`parliamentRewardBeat.seed` → `seedTableReceipts`, свой ответ и опрос одинаково),
   только пока заседание на экране: капсулы и сателлит держатся (`beginPanelRewardHold`), ПО карт заявлены
   `claimVpShares(..., {releaseOnLanding: true})` — ячейка ПО тикает на касании жетона своей карты; арт прогрет.
3. **OWE** — стадия НАГРАДА держит поле и страницу (`sittingFieldOf(..., receipt)`, `mayLeave` / ход повтора), пока
   квитанция должна; держатель анимации `parliament-table-receipt` (истечение отпускает всё — названо).
4. **PLAY** — `sittingDirector.beatReceipt` (такт `receipt` стадии НАГРАДА, после волны места и такта КАРЬЕРА):
   - **сначала взятие**: поверхность добора ушла из зоны, интейк не занят, карты долетели в руку (`receiptStageClear`) —
     и ни мгновением позже: размонтированная с вопросом поверхность добора больше не держит `committing` до таймера
     отказа (PL-798 — было 1,58 с пустой стадии, теперь квитанция встаёт в кадре посадки последней карты);
   - квитанция встаёт в зоне; **импульс закона** (`runActionCommitMotion`) садится на печатный «?» — причина до следствия;
   - **пятый хост директора приёма TR53** (`runCardReceive`, host `resolution`): PRESENT (лица приподнимаются) → PAY
     (`runResourceTransfers`: жетон на карту, рождён на «?» закона, садится на капсулу СВОЕГО лица по очереди —
     `destinationOf` → `.pcard__res`; капсула тикает на касании, `cardResourceLanded`) → READ → RETURN; любой выход
     (`degraded` / `aborted` / `reduced`) отпускает недоставленное — ничего не теряется;
   - уход: панель сворачивается, поле возвращается, когда квитанция больше не должна.

**PL-426** (жетон выплаты резолюции садится без подъёма и возврата карты, К-R8) — квитанция построена на директоре с
PRESENT · RETURN, но пикеры RX01 / RX18 / RX34 / RX35 по-прежнему на `consoleResolutionPayout` без директора: класс не
закрыт, строка остаётся открытой.
