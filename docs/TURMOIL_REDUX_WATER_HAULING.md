## 1. Чтение правила — три источника и один выведенный пункт

- **FAQ, с. 19:** «…can other players send their trade fleets to it? — No. Only the player that played those cards
  is allowed to **trade with them**.»
- **Союз, с. 3:** «…to trade for free. **If you use this to trade with a colony track**, you may advance it 1 step
  before the trade.» — оговорка осмысленна, только если торговать можно и не с колонией.
- **Текст карты:** «send **the** trade fleet» — флот ЭТОЙ торговли (Aurora Station печатает ту же фразу и флота не даёт).
- **Выведено, не напечатано:** плата вносится как за любую торговлю («when you trade» = торговое действие);
  бесплатно — только бесплатным путём (действие Союза, мех Беспилотных конвоев).

Правила чтения 1–10 — в шапке файла карты, каждое закреплено спеком карты.

## 2. `ITradeDestination` — пути оплаты не знают слова «причал»

```ts
// src/server/colonies/ITradeDestination.ts
type TradeDestinationSource = {kind: 'colony'; name: ColonyName} | {kind: 'card'; card: CardName};   // = формы EventSource
interface ITradeDestination {
  readonly tradeSource: TradeDestinationSource;                              // чем путь называет назначение и чему пишет скидку
  tradeBlockedReason(player, terms?: number | TradeTerms): string | undefined; // СВОЙ гейт назначения (до оплаты)
  trade(player, tradeOptions?: TradeOptions, bonusTradeOffset?: number): void;
}
```

- `IColony extends ITradeDestination` (поведение побайтно прежнее), `FleetDockDestination(card)` — второе.
- `IColonyTrader.trade(destination)`: во всех девяти путях поменялись ТИП и токен лога
  (`MessageBuilder.tradeDestination` — колония как COLONY, причал как CARD) и аргумент скидки
  (`recordTradeDiscount(…, destination.tradeSource, …)` → `tradeDiscountSaved: [{colony | dock, resource, amount}]`).
  `Colony.trade` не тронут. Спек-таблица «путь × причал» (12 строк) — `FleetDock.spec.ts`.
- **«Торговля состоялась»** — модуль `tradePerformed.ts`: `reportTrade` (задание председателя) и
  `payTradeFlatBonuses` (Venus Trade Hub; список `tradeFlatBonuses` читают и превью). Это ДВА вызова, а не один:
  колония держит их в прежних точках (порядок её событий не изменился), причал зовёт в том же порядке вокруг посадки.

## 3. `FleetDock` — co-located контракт класса

```ts
// ICard.fleetDock?: FleetDock   (в файле карты — инвариант 8)
type FleetDock = {
  rewardBlockedReason?(player): string | undefined;        // блокер НАГРАДЫ (океаны кончились); занятость считает модуль
  previewEffects(player): ReadonlyArray<ActionEffect>;      // чипы current → resulting, без мутаций
  previewFollowUps?(player): ReadonlyArray<ColonyTradeFollowUpModel>; // что награда СПРОСИТ (TR27: cardTarget)
  receive(player): void;                                    // сама награда — зовётся ПОСЛЕ посадки флота
};
```

Модуль владеет общим: состояние `card.data = {dockedGeneration}` (занято ⇔ `=== game.generation`, сбрасывать не
нужно; старый сейв без `data` = свободный причал), `fleetDockOffers(player)` (карты табло ВЛАДЕЛЬЦА; одна причина в
порядке «флот уже на карте» → `rewardBlockedReason`), `dockFleet` (штамп, `usedTradeFleets++`, событие
`fleet-docked`, затем `receive` — под источником карты). ⚠ `FleetDock.ts` импортирует ТОЛЬКО типы: его читает
`ModelUtils` до появления классов карт; посадка и назначение живут в `FleetDockDestination.ts` (иначе цикл импортов
через `ParliamentHandler`). По той же причине пик и обёртка двери — в `tradeDoor.ts`, не в `ColoniesHandler`.

## 4. Пик назначения и вторая форма ответа

- `tradeDestinationPick(player, title, label, terms, onDestination)` = `ColoniesHandler.tradeColonyPick` + маркер
  **`SelectColonyModel.fleetDocks: [{card, available, reason?, effects}]`**. Пик с НУЛЁМ колоний и свободным причалом
  — законный промпт.
- Ответ: `{type: 'colony', colonyName}` **или** `{type: 'colony', fleetDock: CardName}` — ровно одно поле
  (`isSelectColonyResponse`). Причал обязан быть `available` в маркере ЭТОГО промпта (иначе `InputError` с его
  причиной) и повторно судится ЖИВЬЁМ перед обработчиком двери — всё ДО оплаты.
- `tradeThrough(player, trader, destination, {headline})` — одна обёртка всех дверей: корень
  `beginAction(destination.tradeSource, {category: 'colony'})`; заголовок пишет только торговое действие
  («traded with …» / «sent a trade fleet to …»), у двери карты заголовок — строка её пути, как и раньше.
- Двери на пике назначения: торговое действие (`Colonies.tradeWithColony`), TR66, TFLP, Союз (запертый путь главной
  двери). **Гэп (вне скоупа, не расширять):** Darkside Smugglers' Union, Collegium Copernicus, Huygens Observatory
  остаются на `tradeColonyPick`; первые две спрашивают `canTrade({colonyOnly: true})`, чтобы свободный причал не
  открыл им пустой пик.

## 5. Гейт торговли

`tradeBlockedReason()`: эмбарго → нет свободного флота → **нет открытой колонии И нет доступного причала** (тогда
причина колоний, как раньше). `potentialTradeCount()` = `min(колонии + доступные причалы, свободные флоты)`.

## 6. Событие, модель, превью

- `GameEvent 'fleet-docked'` (`player`, `target.card`, источник — карта, journal). Журнал: строка под картой
  «[флот] −1» (`journalEventChild`), корень группы — заголовок «${0} sent a trade fleet to ${1}».
- `CardModel.fleetDocked?: Color` — ЦВЕТ владельца флота (лицо рисует знак в его ливрее), публично, для любого
  зрителя, пока поколение не сменилось.
- `GET api/game/colony-trade-preview?id&dock=<card>` → `FleetDockPreviewModel {card, available, reason?,
  megacreditsPayment?, energyMix?, effects, followUps, flatBonuses?, reactions?}`; `colony` и `dock` взаимоисключающи; чужая /
  не-причал карта → 204. Платёжная часть — один строитель `tradePaymentPreview` на оба превью. **`reactions`** (TR26) —
  ОТВЕТ СТОЛА на награду: факты движка прогноза для грантов `effects` (`effectForecast.rewardReactionFacts` — реакторы
  карт и их каскад, эффекты партий игрока, пассив принятой резолюции; те же близнецы, что читает «Сработает»
  композеров). Это часть КЛАССА, не карты: правящие Зелёные отвечают «+2 M€» и на РТ «Лайнера», и на РТ океана
  «Перевозки воды» — до TR26 этот ответ был сюрпризом после нажатия у обеих.

## 7. Два классовых исправления, найденных картой

1. **«Получите торговый флот» на пределе 4** (`behavior.colonies.addTradeFleet`; в скоупе Sky Docks, Space Port,
   Space Port Colony): чип превью «флотов N → N+1» / «4 → 4 · предел» + предупреждение, после розыгрыша —
   `effect-skipped` теми же словами (`colonies/tradeFleetGain.ts`).
2. **Отложенный шаг внутри `withSource` терял корень действия**: `captureContext` берёт только верхнюю область,
   `currentRoot()` отвечал «ничьё действие», и РТ отложенного океана (причала, бонуса колонии) не шёл в задание
   председателя, хотя тот же прирост «сразу» — шёл. Не-корневая область теперь помнит корень (`EventContext.root`).

Сдвиг сид-сдачи Redux (новая карта в колоде): два спека `ParliamentPhase.spec.ts` починены классом — нейтральное
лидерство СЧИТАЕТСЯ, колода бота пуста и на его открывающем ходу.

RU: семь строк платы пути потеряли «с колонией на» (их токен назначения теперь колония ИЛИ карта) — осознанная правка
чужих переводов, все использования — только эти логи.

## 8. Клиент — ОДИН flow от обзора колоний до океана

**Колонка «ПРИЧАЛЫ»** (`ConsoleColoniesSection` → `.con-colonies__docks`, плитка `ConsoleFleetDockTile`). Не слот сетки
планет: раскладки сетки спроектированы по числу тайлов, а колонка — узкий столбец справа (`--con-colonies-docks-w`
8rem, на Deck 7rem). Ширина — токен, поэтому фит сетки (`fit()`) просто измеряет то, что осталось; карточки
колонки делят её высоту (`fitDocks` → `--con-dock-zoom`). Источник — `fleetDockModel.fleetDockViews`: карты табло
ЗРИТЕЛЯ с `ClientCard.fleetDock` (экспорт `make:cards`) + вердикт живого пика (`SelectColonyModel.fleetDocks` →
`TradeColonyContext.docks`); вне окна торговли — публичная модель (`CardModel.fleetDocked`). Колонки нет в
пиках, где действие — не торговля (постройка, сетап, каталог). Плитка = премиум-лицо карты + одна строка статуса
(свободен · флот на карте · причина) — через ТУ ЖЕ лестницу, что тайл колонии
(`fleetDockReason` → `colonyTradeReason`: причал = всегда активное назначение без визитёра, его собственный отказ —
`colonyBlock`). Ход на плитке не читается (как у колонии). **Строка статуса — плитки, и режет её только она сама**
(PL-016, 2026-10-05): слот причала ограничен колонкой (`.con-colonies__dockslot { max-width: 100% }` — слот по
содержимому, и длинная строка расширяла его, после чего колонка срезала фразу с обеих сторон без многоточия), а статус
может нести КОРОТКУЮ форму для плитки (`FleetDockTileStatus.short`, печатает `fleetDockTileLabel`): занятый причал
читается «Флот на карте», а полная фраза «Флот на карте · вернётся в следующем поколении» остаётся `text` — её печатают
рельс под сеткой (курсор на причале) и плашка обозревателя эффектов. Отказ награды — фраза сервера, короткой формы у
неё нет: не поместилась — многоточие в собственном боксе, полная причина в рельсе. Проба читает ПЛАШКУ против колонки
и текст против своего бокса: текст «помещался» (306 / 306) всё время, пока колонка резала плашку.

**Курсор** — второй зоной кольца обзора (`colonyCursorStep`, чистая функция): ▶ с последней плитки ряда входит в
колонку на высоте ряда, ◀ возвращает на ту же плитку, ↑/↓ ходят по колонке с ощутимым краем. Индекс сетки не
трогается, пока курсор в колонке. X на причале — штатный осмотр карты (живая модель, знак флота на ▲). Торговля
без открытых колоний: вход «Торговля» жив, обзор открывается с курсором на свободном причале
(`landColonyCursorOnTradeable`).

**Стейдж причала** (`ConsoleFleetDockStage`, `colonyFocusState.dock`). Сосед фокус-стейджа колонии в том же
регионе на тех же хуках спуска: плитка — источник раскрытия, карта — несомый объект (`data-colony-focus-planet` на
НЕзумленной обёртке: FLIP-транслейт внутри CSS `zoom` масштабируется). Герой — полное премиум-лицо. Пути оплаты —
ТЕ ЖЕ ряды и ТА ЖЕ модель, что у колонии (`ConsoleTradePayRows` + `tradePayModel`; фокус-стейдж колонии переведён на
них же), шаг оплаты M€ и микс Delta Works — общие `paymentPlan` + `ConsolePaymentPanel`. РЕЗУЛЬТАТ — только чипы
сервера (превью `?dock=`, на проводе — маркер пика) + флот «2 → 1» + нота `'After confirming: place an ocean
tile'`. Крошка «КОЛОНИИ › ПЕРЕВОЗКА ВОДЫ › ТОРГОВЛЯ», стейдж себя не титулует. Грамматика: ОДИН глагол A, метка
следует за курсором и публикуется в `fleetDockUi` (на другом пути — «Выбрать», на строке оплаты — «Выбрать», на
выбранном пути — «Торговать» или «Продолжить к оплате» при нескольких миксах; курсор сам ничего не выбирает) ·
X «Осмотреть» карту · B «Назад». Отказ — ОДНА причина на стейдже (`[data-fleet-dock-verdict]`), A мёртв.
Голый пик двери карты (`pickMode`) отвечает `{type: 'colony', fleetDock}` один.

**Подтверждение** — шелл `onFleetDockConfirm`: стражи двойного нажатия, ОДИН строитель батча
(`buildTradeBatch({fleetDock})` → `tradeDestinationResponse`), квитанция (`holdPresentation`: путь оплаты и чипы
прибиты на границе коммита), `armTradeFleet({kind: 'card', card})`, `submitBatch`. `armColonyTrade` не армится,
исход не клеймится. Отказ сервера: флот возвращается (батарея abort), стейдж отдаётся как был (`fleet.active`
падает без посева сцены).

**Полёт** — тот же директор и тот же слой, цель — карта (`TradeFleetTarget`; `colonyName` остаётся колониальной
половиной цели, поэтому ни один читатель колонии не изменился). Лестница ИЗМЕРЕННЫХ якорей: ▲ на лице-герое стейджа
(`.con-fleetdock [data-fleet-berth="card:…"]`) → ▲ на плитке колонки → нет rect: полёта нет, фазы идут, гейт
разрешается. ⚠ **Найдено картой и закрыто классом**: быстрый сервер отвечал (~200 мс), пока слой ещё мерил якоря
rAF-пробником (на медленном кадре 4K), и `runTradeFleet` без директора отпускал гейт через 120 мс — вид
применялся, корабль так и не взлетал. Теперь слой объявляет окно измерения (`setTradeFleetLaunchPending`), гейт в
нём ждёт директора (сеть `LAUNCH_WAIT_MS` 1.5 с), а пробник тикает на `probeTick`. Колониальная торговля
получает ту же починку (её кадры и тайминги не менялись — исправлена только гонка, в которой полёт пропадал).

**Знак флота на лице** (B5): `CardModel.fleetDocked` = цвет ВЛАДЕЛЬЦА (не `true`) → `PremiumCard` отдаёт
состояние причала инъекцией (`premiumFleetDock.ts`), `PremiumFleetMark` монтируется ТОЛЬКО на узле ▲ печатного
`trade` и только у карты-причала: слот `[data-fleet-berth="card:<имя>"]` — absolute, ноль лейаута, всегда разложен
(посадочный якорь), флот в нём — `ColonyFleetIcon` в ливрее владельца (тот же корабль, что прокси полёта: кроссфейд
прокси → знак без подмены картинки; PNG `trade-fleet.png` не принял бы ливрею без `filter`, который консоль
вырезает). Виден везде, где видна карта; карта не тускнеет. Обозреватель эффектов — плашка состояния
«Флот на карте · вернётся в следующем поколении». Отдельный компонент — потому что computed/inject в КАЖДОМ узле
механики дорожали монтирование лица (замер A/B — см. отчёт).

**Сцена после посадки** (`fleetDockScene.ts`) — ОДНА фраза для каждого причала, слот награды по КАТЕГОРИИ (§9).
Ниже — фраза категории `placement` (TR06). Blocking-холд `'trade-fleet-dock'`
(`diagnose` + `expire`) сеется в `gameTransport.seedRewardHolds` — тем же блоком, что apply, и только пока стоит
стейдж этой карты; admission `placement` ждёт его. Фазы: `seeded` → **answer** (импульс коммита по печатному
«▲ : [океан]», значок океана отвечает один раз — `runActionCommitMotion`; куда садится импульс, следует из плана
сцены, не из литерала) → **read** (680 мс — ритм
CARDLAND колонии) → **leave** (карта уходит ТАКТОМ, знак флота — с ней) → **conclude**: `flow-complete` →
шелл `onFleetDockFlowComplete` → ОДНА охраняемая концовка корня стека (`concludeWorkspaceFlowOrOwe`), стейдж не
сворачивается отдельно — уходит ВМЕСТЕ с workspace; холд отпускается, когда корень workspace покинул документ
(MutationObserver — конец ухода, не таймер). Отказ концовки → стейдж сворачивается, холд падает, размещение встаёт
где стоит. `colonyFollowUpLive` держит фрейм, пока сцена идёт (иначе `settleColonyFollowUp` дорисовал бы свой

## 9. Класс после TR26 — категория награды, фраза со слотом, «награда на рельс»

TR26 UNMI Liner («Лайнер UNMI», 6 · Земля + Космос · плашка Союза · «▲* : [РТ]» · +1 флот) — вторая сестра. В файле

нет), ни `previewFollowUps`. Сервер класса не получил ни одного механизма; получил два наблюдателя:

- **`reactions` в превью причала** (§6) — ответ стола на награду виден ДО нажатия, для обеих сестёр;
- **гард по манифесту** `tests/colonies/FleetDockManifest.spec.ts` — перечисляет карты с `fleetDock` (пол ≥ 2) и на
  каждой держит инварианты класса: объявлен `data.dockedGeneration`, превью чисто (снимок до / после), `receive`
  пишет под источником карты, ворота Колоний, клиентский экспорт `ClientCard.fleetDock`, печатный ряд «▲ : [награда]»
  находится `fleetDockEffectNode` и несёт значок награды, обещание Зелёных = выплате. TR27 он возьмёт сам.

### 9.1 Категория награды — чистая функция данных сервера

`fleetDockModel.fleetDockRewardCategory(followUps)` / `fleetDockScenePlan(preview)` — по превью `?dock=`, прибитому
стейджем на ГРАНИЦЕ КОММИТА (`holdPresentation` → `armFleetDockScene`). Клиент не знает имён карт-причалов (grep
`WATER_HAULING` / `UNMI_LINER` / `AURORA_STATION` по `src/client` — только комментарии и КЛЕТКА поля `SpaceName`, §10.7).

| Категория | Признак в данных | Слот REWARD | Уход карты |
| --- | --- | --- | --- |
| `placement` (TR06) | есть follow-up «после подтверждения» | ПУСТ — награда впереди, на поле | своим тактом (LEAVE), затем workspace; поле встаёт чистым |
| `rail` (TR26) | follow-up нет | rail-выигрыши чипов (`railRewardSpecs`: РТ → `stock:rating`, сток / производство стандартного ресурса) летят из печатных значков на рельс; ответ стола — следом | ВМЕСТЕ с workspace (LEAVE нет) |
| `card` (TR27) | `cardTarget` (цель награды — `cardTargetFollowUpOf`, §10.1) | жетон из КАЖДОГО печатного значка ресурса садится на карту-получатель (она стоит на стейдже; держатель — сам причал → счётчик героя), счётчик карты, «ДОП. РЕСУРСЫ» и ячейка ПО — на касаниях; остальное (производство M€) — готовым `rail`-путём | ВМЕСТЕ с workspace |

Старшинство: карта > поверхность впереди > плоский выигрыш («Перевозка воды» несёт И размещение, И чип РТ — этот РТ
принадлежит океану и приходит с тайлом, не с карты). Превью не успело к нажатию → фраза по умолчанию (как до
категорий): по чипам маркера категорию не угадывают — они не отличают плоский выигрыш от РТ тайла, который впереди.

### 9.2 Фраза сцены: ANSWER → REWARD → READ → LEAVE → CONCLUDE

Холд сцены `'trade-fleet-dock'` стоит для ЛЮБОЙ категории (следующий промпт, обзор хода бота и нотификации ждут
фразу) и падает, когда корень workspace покинул документ. Куда садится импульс ANSWER — из плана (`answer`:
`global` для параметра / РТ, `resources` + ресурс для стандартного, `generic`), не литерал. Для `placement` фраза
та же, что до обобщения: A/B кадров стейджа — попиксельно, тайминги тактов — в шуме прогона (журнал § TR26).

### 9.3 «Награда на рельс» — `console/resourceTransfer/railReward.ts` (функция КЛАССА, не сцены)

«Выигрыш — это награда, где бы в потоке он ни пришёл»: уже применённый сервером выигрыш (РТ, сток, производство)
показывается ПРИХОДЯЩИМ. Владелец говорит КОГДА (своя сцена) и ОТКУДА (свой измеренный узел); модуль владеет холдами,
их порядком и отпуском — цепочка переживает уход поверхности владельца.

- **SEED** (`seedRailReward(key, {cause, reactions, known}, before, after)` — из `seedFleetDockHold`, тот же
  синхронный блок, что применение вида, и ТОЛЬКО пока стоит стейдж этой карты): обещание сверяется с ДИФФОМ двух
  видов (`verifyRailReward`) — по каждому ряду рельса «применённое изменение = награда + известные движения
  торговли» (`fleetDockModel.tradeKnownRailMoves`: плата выбранного пути, плоские бонусы). Ряд, который не сошёлся,
  НЕ удерживается и назван (`mismatch`); не сошёлся ряд ПРИЧИНЫ — не удерживается ничего.
- **FLY** (`flyRailReward(key, originOf)` — на handoff импульса, когда он СЕЛ на печатный значок): жетон рождается
  в центре значка награды лица-героя (якоря ACTION COMMIT: `resolveGainIconOrigins`; игла `rating → tr.png`),
  общий директор перелётов, адрес — строка рейтинга (`RATING_RAIL_KEY` живёт в `resourceTransferModel`), холд
  отпускается КАСАНИЕМ, дельта-чип рождается там же.
- **ANSWER** — реакции стола (`reactionRailSpecs`: только `exact`-факты «вам») отпускаются одним тактом часов
  анимации ПОСЛЕ последнего касания: реакция не тикает раньше причины.
- **Деградация НАЗВАНА**: `railRewardState.degraded` (+ `data-fleet-dock-degraded` на стейдже, dev-warn):
  `no-origin` · `no-source` · `no-destination` · `no-stage` · `stalled` · `mismatch` (`ResourceTransferRun.onDegrade`).
- **Холды ограничены**: blocking-поставщик `'rail-reward'` (`diagnose` + `expire`), `releaseRailReward` на любом
  конце сцены (`endFleetDockScene`), reduced motion не сеет ничего. Юниты — `railReward.spec`.
- **Производная ячейка ПО** рельса удерживается вместе с рейтингом (PL-014) — иначе «+1 ПО» объявлялось на секунду
  раньше касания жетона, в дюйме от удержанного числа.
- **Дуга жетона не покидает экран** (PL-012, `transferArcPlan(…, ceilingY)`): бросок в верхние ряды рельса уходил
  за верхний край и ~250 мс награды не было нигде.

Парламентские потребители РТ (бонус Карьеры, задание председателя) остались на своей очереди
`parliamentRewardBeat` — ключ рельса у них тот же; перевод остальных источников РТ вне Парламента — PL-001.

**Второй владелец модуля — ДЕЙСТВИЕ карты (TR28, 2026-10-06).** Коммит действия (`consoleActionCommitRail.ts`) держит
через `railReward` всё, что ветка платит на рейтинг (прямой РТ — `consoleActionCommit.actionRailTrSpecs`), и движения
по капсуле собственной карты, когда печатный ряд — таймлайн (`capsuleTimeline`): один `RailReward` с причиной в
печатном порядке, известными движениями ветки (`actionKnownRailMoves`) и ответом стола из прогноза ветки. Модуль
получил одну возможность — `flyRailRewardLink`: владелец летит ЧАСТЬ удержанной причины (звено таймлайна), каждый
жетон отпускается на своём касании (потеря — на отлёте), запись держится до последнего звена; ответ стола —
по-прежнему тактом после последнего касания (`flyRailReward`). Сид, сверка, деградация, потолок — те же, что у
причала; `heldCardCapsule` — капсула ОДНОЙ карты (выигрыши минус потери, со знаком) для поверхности, которая рисует
эту карту, пока её жетоны летят.

### 9.4 Два причала в одном табло

Колонка «ПРИЧАЛЫ» — токен ширины: второй причал не отнимает у сетки планет НИЧЕГО (`--coltile-scale` при двух
причалах == при одном — утверждено числом в e2e на fhd и 4K), карточки колонки делят её высоту (`fitDocks`).
Курсор: ▶ с последней плитки ряда входит в колонку на высоте ряда, ↑ / ↓ ходят между причалами с ощутимым краем, ◀
возвращает на ту самую плитку, с какого бы причала ни ушёл. Статусы и знаки флота независимы (штамп поколения — на
карте). После торговли с одним причалом обзор открывается с курсором НЕ на занятом. Знак флота стоит на своей
карте в колонке, на стейдже, в просмотрщике — и в «Разыграно» (PL-013: стол рисует лица без живой модели;
`premiumFleetDock.publicFaceModel` отдаёт докованной карте имя + флот).

### 9.6 Дверь R3 «Эффекты» на стейдже причала (PL-060, 2026-10-06)

Строка «⚡ сработает» на стейдже — та же группа, что у композеров розыгрыша и действия, и у них она ДВЕРЬ: R3 (или
клик) разворачивает слой обозревателя эффектов в режиме прогноза. Стейдж причала сдал её как результат — владелец
увидел дыру на кадре лайнера. Теперь:

- **Превью несёт прогноз, не список.** `FleetDockPreviewModel.forecast?: EffectForecast` (бывшее `reactions`) —
  `effectForecast.rewardReactionForecast`: те же проходы, что у грантов розыгрыша (реакторы карт, каскад, эффекты
  партии, пассив резолюции), покрытие движка (`coverageOf` — ОДНО чтение для всех строителей), без скидок и ценностей
  оплаты (плата торговли — ряды самого стейджа, не цена карты); отсутствует, когда ничего не отвечает. Чипы строки —
  `forecast.facts`, реакции рельса — они же.
- **Третий хост слоя** — `EffectForecastHost 'dock'` (`consoleEffectForecast.ts`): свои курсоры обозревателя, своё
  «открыт ли». Хуки descend-фразы находят хост по `[data-forecast-host]` раньше `.con-composer` — композеры как были.
- **Стейдж**: группа несёт ключ R3 (`.con-fleetdock__vfxrow`, `data-forecast-row`), рабочая колонка — `data-forecast-browse`
  (паркуется, не размонтируется), слой `.con-fleetdock__fxlayer` / `__fxpanel` в боксе `__main` (значения композера);
  `forecastCanOpen` = есть факты · нет под-шага · ничего не удержано; под-шаг и граница коммита складывают слой мгновенно
  (`armForecastInstantFold`), размонтирование закрывает. Вспышка строки — на часах анимации (гард PL-003).
- **Бар и крошка**: `fleetDockUi.forecastAvailable` → «R3 Эффекты» в обычном ряду; `fleetDockUi.forecastOpen` → бар =
  `forecastExplorerUi('dock').barCommands` (ниже ветки `answered`); `crumbStage` колоний → `forecastStageText('dock', …)`:
  «КОЛОНИИ › ЛАЙНЕР UNMI › ТОРГОВЛЯ · ЭФФЕКТЫ».
- **Гарды**: `ConsoleFleetDockStage.spec` § the R3 «Эффекты» layer; `FleetDockManifest.spec` (прогноз ровно когда есть
  ответ, покрытие движка); e2e `console-unmi-liner` § 2b. Кадры: `screenshots/unmi-liner/<профиль>-02b-liner-effects-layer.png`.

## 10. TR27 Aurora Station — награда с ЦЕЛЬЮ: одна конструкция, пре-сбор, три исхода

«Станция Аврора» · 14 · ACTIVE · Венера + Город + Космос · плашка Союза · «▲* : [аэростат·V][аэростат·V][произв. M€ 1]»
· «[город]*» · 1 ПО за 2 аэростата · `compatibility: ['colonies', 'venus']`. Третья сестра и ПЕРВАЯ, чья награда
СПРАШИВАЕТ («на какую карту Венеры положить два аэростата»); флота не даёт. Файл карты —
`src/server/cards/turmoilRedux/AuroraStation.ts` (шапка — чтение скана и правила 1–16), спек — 32 случая.

### 10.1 Сервер: обещание и выплата читают ОДИН объект

- **`FleetDock.rewardTarget?(player): AddResourcesToCard`** — карта СТРОИТ шаг цели (ресурс, число, ограничение метки) и
  НИКОГДА не ставит его в очередь сама. Модуль `fleetDockRewardTarget(player, card)` штампует источник (`choiceContext`
  карты-причала) и отдаёт ЭТОТ ЖЕ объект двум читателям:
  - **превью** `?dock=` — `colonyTradePreview.cardTargetFollowUpOf(action, role, {vpSteps})`, то же чтение, что у цели
    награды КОЛОНИИ (колонийная ветка теперь делегирует ему байт в байт): `lost` (держателя нет — потеря названа) ·
    `auto` (один — назван, вопроса нет) · `pick` (несколько — кандидаты, у каждого ПО за каждую посаженную единицу,
    `vpSteps` из `distributionVictoryPoints`);
  - **выплата** — `dockFleet` ставит в очередь этот шаг, а за ним `receive` с ТЕМ ЖЕ приоритетом (FIFO = печатный
    порядок: аэростаты, затем производство).
- **Три исхода ответа** — те же, что у пре-сбора колонии: пре-собранная цель едет ХВОСТОМ ОДНОГО POST
  (`{type: 'card', cards: [...]}`) и принимается репликой батча; устаревшая (кандидат исчез) отброшена — вопрос задан
  вживую; стоит другой вопрос впереди — хвост паркуется. Вопрос ПОСЛЕ посадки флота невозможен по построению.
- Сохранение посреди вопроса → загрузка → тот же вопрос (спек карты). Мэр считает город станции, «Марсианская
  перепись» (TR15) — нет: это город НЕ на Марсе.
- Гард манифеста: награда, которая спрашивает, спрашивает через `rewardTarget` — `cardTarget` в `previewFollowUps`
  файла карты означал бы ДВЕ конструкции цели.

### 10.2 Стейдж причала: цель названа ДО «Торговать»

- Ряд «ЦЕЛЬ ТОРГОВОЙ НАГРАДЫ» (`[data-fleet-dock-target]`, чтение — `ConsoleTradeTargetValue`, общее с колонией): ОДИН
  держатель → УТВЕРЖДЕНИЕ (карта и её «0 → 2», курсор не останавливается); НЕСКОЛЬКО → РЕШЕНИЕ (ничего не выбрано,
  `--missing`, «Торговать» отказан, пока карта не названа; A спускается в шаг цели).
- **Шаг цели — `ConsoleTradeTargetStep`, ТОТ ЖЕ компонент, что у стейджа колонии** (вынесен в 2/5 без единого
  изменённого пикселя: A/B кадров стейджа колонии — 0 px на устоявшихся кадрах). Грамматика общего селектора: A —
  выбрать, X — осмотреть, LB/RB — ось владельца, B — уровень назад с прежним выбором. Сам причал стоит в нём как
  «ЭТА КАРТА» (не вторым лицом), у каждого кандидата — «n → n + 2» и ПО. Хвост «… › ЦЕЛЬ НАГРАДЫ».
- Выбор едет хвостом ОДНОГО POST; у карточной двери — голый пик тем же батчем.
- Чип результата переприцеливается на выбор; ни один блок стейджа не двигается от выбора (e2e мерит).

### 10.3 Сцена: категория `card`

`fleetDockScenePlan` по превью, прибитому на коммите: жетон ресурса — на КАЖДЫЙ печатный значок (`printedRewardUnits`;
k-й жетон рождается на k-м значке — `resolveGainIconOrigins`), адрес — карта-получатель (`cardTargetTokens` →
`card-resource:<icon>@<card>`); остальное (производство M€) — готовые rail-спеки.

- **Получатель стоит на стейдже до первого жетона** (`ConsoleTradeReceivingCards`, общий с колонией) со счётчиком,
  замороженным на значении до торговли; держатель — сам причал → заморожен счётчик героя. Тик — на касании.
- **Производные числа не раньше причины**: счётчик карты (ряд `railReward` по ресурсам табло), спутник «ДОП. РЕСУРСЫ»
  и ячейка ПО рельса (`panelRewardHold.vp` / `heldVictoryPoints` — очки, которые жетон приносит карте «1 / 2»).
- `railReward` различает награду ДОЛЖНУЮ (вопрос задан вживую или запаркован — холдов нет, засевает ответ, который
  платит, его дифф называет получателя: `railRewardOwed`, `fleetDockOwedCard`) и СЛОМАННУЮ (`mismatch`).
- **Сцена кончается сама.** Секция колоний больше не сворачивает стейдж причала на отпуске заявки (сцену резало
  посреди импульса, до первого жетона); вопрос, заданный вживую, стоит в зоне стейджа (заявка `pick`).
- Под голодающим компоновщиком (4K программного рендера, кадр 70–170 мс) три жетона (шаг ≈ 90 мс) рождаются и садятся в
  ОДНОМ кадре — порядок схлопывается, «никогда не раньше своего жетона» держится (e2e утверждает порядок там, где
  рождения различимы).

### 10.4 Три причала в одном табло

Колонка «ПРИЧАЛЫ» держит три карты в порядке табло, сетка планет при трёх такая же, как при одном
(`--coltile-scale` равен — e2e), статусы целы и внутри колонки, курсор ↑ / ↓ обходит три с ощутимым краем, ◀
возвращает на плитку. Юнит — `fleetDockModel.spec` § three docks. Подгонка колонки (`ConsoleColoniesSection.fitDocks`) мерит ВСЕ члены: padding колонки, заголовок
(он не уступает — с `overflow: hidden` его flex-минимум 0, и переполненная колонка сжимала его до нуля, а подгонка мерила
0 px), на каждый причал — статус и зазор «лицо ↔ статус», натуральный бокс лица — отрисованный бокс над отрисованным
зумом (PL-019: на 4K статус третьего причала резался клипом колонки). Все три заняты — статусы в короткой форме «Флот на
карте», зум лиц тот же, что у свободных (e2e на fhd, 4K, Deck).

### 10.5 Клетка поля — пятая клетка венерианского фланга

`SpaceName.AURORA_STATION` ('80'), строка таблицы `expansionSpaceColonies` с ДВУМЯ модулями (`['turmoilRedux',
'venus']` — клетка есть, только где карту можно сыграть; старое сохранение её получает). НЕ hosted (на печатном поле
города Венеры стоят у шкалы), рисуется `Board.vue` по имени, как четыре соседки. Место — ПОСТРОЕНИЕ, не на глаз:
следующий РАВНЫЙ шаг дуги за Стратополисом (окружность правой тройки ≈(301.9, 273.1) r 295.8, шаг 11.62° → −15.99°,
left 586 / top 192) лёг НА маркер океана 0 °C шкалы температуры — отвергнут; клетка закрывает фланг так же, как
Доун-Сити: ЗЕРКАЛО МАКСВЕЛЛА относительно столбца Доун-Сити (top 86, left 615 = 573 + 42, равное плечо 59 px).
Только консоль ставит её (`console.less`, keep-px). Гард — `tests/console/offMarsCellPlacement.spec.ts`.

### 10.6 После нажатия строка команд — СТАТУС

От границы коммита до ухода workspace стейдж причала — такт в полёте: строка читает «Выполняется…» (грамматика актов
колонии), а не «Торговать · Осмотреть · Назад», которые ничто не принимает (PL-018, все три сестры). Зеркало
`fleetDockUi.answered` ставит `holdPresentation`, снимают отказ, уход стейджа и сброс; вопрос, заданный вживую в зоне
стейджа, держит строку своей задачи. Чип флота в РЕЗУЛЬТАТЕ называет единицу («торговый флот», PL-008).

### 10.7 Клиент не знает карт-причалов

grep `AURORA_STATION` по `src/client` — только `SpaceName` клетки поля (`Board.vue`, `specialCellInfo.ts`, как у
каждого города Венеры) и комментарии. Категория, шаг цели, получатель, порядок жетонов — из данных сервера.
