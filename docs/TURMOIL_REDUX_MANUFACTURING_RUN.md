# RX37 · Manufacturing Run («Серийный выпуск», Индустриалисты) — ДЕЙСТВИЕ НЕСКОЛЬКО РАЗ ЗА ПОКОЛЕНИЕ

**Статус: СДАНА 2026-10-20** (A `c370826bf3` · B `df964fad00` · полировка `9c12f2205e` · C — доки; не запушено). Закон из одного действия — без принятия, без части победителя, без пассива:
*«Action: Add 2 floaters OR 1 fighter OR 1 mech to any card. You can use this action twice this generation.
Players with at least 2 Influence can use it 3 times.»* Задание председателя — **2 зелёные карты** (объект и ключ
RX24). Аэростаты, истребители и мехи есть без Венеры — `compatibility` не объявляется.

Промт: `docs/claude/prompts/resolution-rx37-manufacturing-run.md`. Файл карты:
`src/server/parliament/resolutions/industrialists/ManufacturingRun.ts`. Спеки: `tests/parliament/ManufacturingRun.spec.ts`,
`tests/console/actionUsesReading.spec.ts`; e2e `tests/e2e/console-parliament-manufacturing.spec.ts`.

Карта лежала в очереди `Resolutions\skip\`, пока не было держателей мехов; сегодня их девять, истребителей шесть,
аэростатов двадцать два.

## 1. Объявление — почти чистая сборка

```ts
quest: {goal: {kind: 'cardsPlayed', cardType: 'automated'}, count: 2},   // RX24
action: MANUFACTURING_RUN_ACTION,                                         // usesPerGeneration · canAct · execute · preview
actionUses: {base: 2, atInfluence: {influence: 2, uses: 3}},              // НОВОЕ: сколько раз — данные
```

Своя механика одна — **«сколько раз за поколение» зависит от влияния**. Всё остальное — уже существующая форма
партийного действия Учёных.

## 2. `actionUses` — число использований как ДАННЫЕ, ОДНА функция

`src/common/parliament/actionUses.ts` (образец — `actionBill.ts`):

| что | роль |
| --- | --- |
| `ResolutionActionUses {base, atInfluence?: {influence, uses}}` | объявление рядом с `action`, никогда вместо |
| `actionUsesFor(uses, influence)` | ОДНО чтение: без объявления — `1` (правило семейства, R p.6) |
| `actionUsesStanding(uses, influence)` | где стоит место: `{uses, raised, short}` — «на линии / ниже линии» RX20 |
| `actionUsesDeclared(uses)` | гард: целая положительная база, порог ПОДНИМАЕТ число |

Кто читает: `usesPerGeneration(player)` закона (= `actionUsesFor(MANUFACTURING_RUN_USES, parliament.influence(player))`),
манифест (`IClientResolution.actionUses`, экспорт рядом с `actionBill`), клиентское чтение
`console/parliament/actionUsesReading.ts` (панель голосования, инспектор, «Полигон»).

**Решение Р3 — влияние ЖИВОЕ.** `Parliament.resolutionActionUsesLeft` и раньше звал `usesPerGeneration(player)` в момент
вопроса: место с влиянием 1 потратило оба использования, стало председателем (Повестка +1 → влияние 2) — третье
появляется в том же поколении (спек «the THIRD use appears in the same generation»). Влияние внутри поколения только
растёт, поэтому обратный случай не возникает; если бы возник — «осталось» честно упирается в 0.

**Гард `ResolutionContract` § SEAM (две новые проверки):** `actionUses` без `action` — отказ; и для КАЖДОГО закона с
действием `usesPerGeneration(seat)` === `actionUsesFor(definition.actionUses, I)` при влиянии 0 / 1 / 2 — для закона без
объявления это `1`, так что константа «2» в файле карты без объявления ловится тут же.

**Причина исчерпания называет числа:** `ParliamentModel` для закона с `usesPerGeneration > 1` пишет
«This resolution action was already used ${0} of ${1} times this generation» («2 из 2» / «3 из 3»); для прежних
законов — прежняя строка.

## 3. Форма — ветка Учёных, ОДИН построитель (решение Р2)

`src/server/parliament/resourceToOwnCard.ts` — `resourceToOwnCardChoice(player, yields, {title, buttonLabel, mark,
source, trigger, noHolder, give})`: `OrOptions` по видам С ДЕРЖАТЕЛЯМИ (печатный порядок), ветка — `SelectCard` над
держателями вида, `markResourceGainPrompt({amount, cardResource, vpBox})`, маркер семейства (`mark`), ответ — функция
вызывающего (`give` внутри `runPartyAction` / `runResolutionAction`). Плюс `yieldsWithHolders` (гейт) и
`resourceToOwnCardPreview(yields, player?)` (чипы плитки: с местом — только виды с держателями).

- **Учёные переведены на построитель байт-в-байт**: тот же заголовок, кнопка, маркеры в том же порядке; спек
  `PartyEffects` зелёный без правок, и `ManufacturingRun.spec` закрепляет промпт Учёных отдельным кейсом.
- **Вид — ветка, не карта**: печатное «OR» — вариантный выбор, величины у видов разные (2 / 1 / 1), поэтому чтение RX18
  «вид следует из карты» отвергнуто.
- **Одна ветка** остаётся веткой из одного варианта: `OrOptions.reduce()` для `SelectCard`-веток не годится (зовёт `cb()`
  без ответа), поэтому «свёрнута» она на клиенте — единственный вариант засевается (правило «A CHOICE IS A PRESS»:
  выбора нет — нечего нажимать), а КАРТА спрашивается всегда, даже при одном держателе (без `autoSelect`).
- Нет держателя ни одного вида — названная причина «No card of yours can hold floaters, fighters or mechs».

## 4. Консоль

### 4.1 Дыра B1: «раз за поколение», вшитый закону

> **ЗАМЕНЕНО (ОДИН ФРЕЙМВОРК, 2026-10-24):** ресурсная форма закона — строка-цель общего композера (единственная цель посеяна, T14); `.con-pact__card-face` → `[data-composer-card]` композера — см. `docs/claude/console/parliament-one-framework.md`. Ниже — история.

Потребители `usesLeft` / `usesPerGeneration` пройдены все: плитка «Действий карт» (`sourceUsesText` — сервер), плашка
Парламента и состояние `used` (`usesLeft <= 0` — сервер), композер (`usesText` — маркер / модель), стенд — читали
сервер. **Подставлял `1` ровно один**: `parliamentEffectsStepModel.ts` («Ваши эффекты»). Теперь — живой вердикт места
(`resolutionActionState.usesPerGeneration`), иначе база объявления; рядом — `usesLeft`, и шаг читает
«2 раза за поколение · осталось 1» словами (`cadenceOf`). Юнит — `parliamentEffectsStep.spec`.

### 4.2 Чтения порога (B2)

`actionUsesReading.ts`: ПРАВИЛО «2 раза за поколение · 3 при влиянии 2+»; МЕСТО «Для вас: 3 раза за поколение» /
«Для вас: 2 раза · ещё 1 влияния — и будет 3»; ПОБЕДА «Если победите: 3 раза за поколение» — только где шаг Повестки
победителя переводит место через линию (тот же расчёт `influenceAtAgenda(step + 1)`, что и у прогнозов величин).
Панель голосования — под кикером «Действие, пока принята» (`VoteReadingVm.uses`, `data-parl-vote-uses`); чужое место —
только правило (третье лицо для строки места не заводилось). Инспектор — строка правила под фразой действия
(`resolutionAnnotations`). «Полигон» — строка «Сколько раз». Плитка «Действий карт» читает живое «N из M».

### 4.3 Форма решения (B3) — ветка Учёных, обобщённая по ФОРМЕ промпта

`ConsolePartyActionComposer` читает `resourceForm`: партия Учёных ИЛИ закон, чей промпт — `or` из `SelectCard` с
`resourceGainPrompt`. Те же два ряда («РЕСУРС» → «КАРТА-ЦЕЛЬ»), тот же ответ (`resourceToCardResponse(entry, branch,
card)` — бывший `scientistsResponse`, по записи меню, а не по партии). Второго композера и копии разметки нет.

### 4.4 Показ — жетон садится на НАСТОЯЩУЮ карту (PL-427 классом)

**Дыра (PL-427, К-R9).** Партийное действие Учёных (и закон пошёл бы тем же путём) отдавало ресурс ВОЛНЕ оболочки
(`ActionCommitPlan.specs` → `runCommitRewardWave`), а её лестница мест посадки не знает рядов композера партии: жетон
летел в спутник «ДОП. РЕСУРСЫ» под непрозрачным стеклом стадии. Вторая половина той же дыры — вывод потока: на ответ
сервера `ConsoleCardActions` звал `concludeFlow` в следующем тике, и рабочая область уходила под жетоном.

**Закрыто классом, для Учёных и закона сразу:**
- миниатюра ряда «КАРТА-ЦЕЛЬ» — конец полёта: `data-composer-card` на обёртке лица (`.con-pact__card-face`);
- коммит формы строит РЕЛЬСОВУЮ половину (`ActionCommitRail`: одно звено `card-resource` на выбранную карту, её ПО по
  `vpBox`, `holdsSurface`, `capsules`) вместо волны; она засевается в блоке применения ответа против ДВУХ видов
  (`seedActionCommitRail` → `seedRailReward`, капсула карты держится до касания) и летит директором приёма TR53
  (`runCardReceive` хост `composer`: миниатюра поднимается атрибутом `data-receiving`, жетон садится, капсула тикает на
  касании, миниатюра опускается) — пятый хост не понадобился, селекторы рельса просто читают и `.con-pact`
  (`composerCardSelector`);
- ряды стоят на СНИМКЕ нажатого (`resourceSnapshot`): меню после ответа меняется (у Учёных действие уходит, у закона
  второе использование — новый промпт), а жетону нужен ряд; бар — статус «Выполняется…», второго коммита нет;
- вывод потока ждёт конца половины (`concludeAfterRail` по `actionCommitRailState.ended` — любой исход половины
  его поднимает: касание, «не полетела», несовпадение видов).

PL-426 (жетон выплаты РЕЗОЛЮЦИИ на заседании садится без подъёма карты, К-R8) — другой хост (страница награды
заседания, `parliamentRewardBeat`), этой правкой не закрыт — строка реестра остаётся открытой.

## 7. Слабые места (честно)

- **«Для вас» на чужом месте** не печатается (только правило): строка места в третьем лице не заводилась — правило
  и так говорит, сколько раз для любого места.
- **Инспектор** печатает правило, но не строку «для вас»: у `resolutionAnnotations` нет места читателя без новой
  нитки параметров через оболочку (файл в работе соседней сессии); строка места стоит на панели голосования.
- **Хвост крошки после нажатия** — «НАСТРОЙКА» янтарём вместо «ВЫПОЛНЕНИЕ» (PL-738, открыта).
- **Длинный ряд целей** (4+ держателей одного вида) проверен расчётом, не кадром: на ТВ лица 0,42 × UI, ряд переносится
  на вторую строку раньше, чем выходит за полосу; отдельной фикстуры на девять мехов нет.
- **«Ваши эффекты» в e2e** не проверяются: юнит закрепляет живое число и «осталось N», кадра шага в спеке нет.
