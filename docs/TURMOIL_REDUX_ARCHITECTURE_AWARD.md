# Turmoil Redux — Architecture Award (RX02): счётный член + влияние, с ограничением

Дата: 2026-09-17. Продолжение `TURMOIL_REDUX_AQUIFER_CONTEST.md` (шаблон семейства RX##).

Architecture Award — вторая настоящая резолюция и первая, у которой результат зависит одновременно от **состояния
tableau** и от **влияния**, а затем упирается в **максимум**. Документ фиксирует трактовки правил (включая открытый
раньше `Q-8`), общие расширения («значок ПО», «счётный член», запись результата), показ в игре и «Полигоне», проверки
и рецепт для следующих резолюций вида «+N за X + влияние (макс. M)».

## 2. Правило и трактовки

Печатный текст: *When enacted: Increase your M€ production 1 step for every Building card with a NON-NEGATIVE VP icon
you have in play + Influence. (Max. 5)*. Задание: разыграть 2 метки строительства.

**Формула:** `прирост = min(5, B + I)` для **каждого** участника (голосовал или нет, есть ли доступ к эффекту партии —
неважно). Ограничение действует на **сумму прироста**, не на итоговое производство (10 → 15 законно). Отрицательное
производство растёт обычным образом. Это **производство**, не деньги. Части победителя нет.

| Вопрос | Трактовка | Где закреплено |
| --- | --- | --- |
| Значок ПО обязателен (`Q-8`) | Да — буквальное чтение: строительная карта без значка ПО даёт 0 ПО, но **не считается** | `victoryPointsIcon.ts`, спек «a positive fixed icon counts…» |
| Фиксированный значок | Считается при значении ≥ 0 (напечатанный 0 — тоже) | то же |
| Переменный значок (`CountableVictoryPoints`) | Считается по **знаку** формулы (`each ≥ 0`), а не по текущему счёту: «2 ПО за научный ресурс» без ресурсов считается; штраф «−1 за …» при текущих 0 — нет | спек «a variable non-negative icon counts even while it scores 0» |
| Особый значок (`'special'`, свой `getVictoryPoints`) | Карта **сама объявляет знак** в своём файле: `victoryPointsSign: 'nonNegative' \| 'negative' \| 'either'`; `either` (Agricola Inc, Duncan) не «неотрицательный»; необъявленный никогда не угадывается | 12 карт корпуса, guard `victoryPointsIcon.spec.ts` |
| Строительная карта | Карта, **печатающая** метку строительства; wild-метки и чужие бонусы её таковой не делают | `resolutionCounts.ts` |
| Несколько меток / большой значок | Одна карта = одна единица B | спек «one card is one unit» |
| «В игре» | tableau игрока (корпорации, прологи, CEO, проекты); рука, сброс, чужие карты — нет; выключенный Pharmacy Union — вне игры; сыгранные события лежат рубашкой вверх — их метки не в игре, кроме Odyssey (`Tags.eventTagsInPlay` — одно правило активности меток) | `ResolutionCounts.ts`, спек «only the player's own cards IN PLAY» |
| Влияние | Канонический `parliament.influence(player)` **после** шага победителя по Повестке (драйвер сеет `ctx.influence` после шага 1); делегаты влияния не дают | спек «influence comes from the Redux ledger AFTER…» |
| Нейтральный победитель | Общий эффект сохраняется | спек «a neutral winner cancels nothing» |
| Два делегата | Дают эффект партии «Марс вперёд», но **не** запускают эффект резолюции | спек «two delegates grant the Mars First EFFECT…» |
| Нулевой результат | Названный пропуск: строка журнала + `outcome skipped` с причиной «Нет подходящих карт и влияния», производство не меняется, анимации нет | спек «the cap bounds the INCREASE…» (второе место) |
| MarsBot | Политика `none` не меняется: бот не считается, не получает, фаза не зависает | спек «MarsBot (mode none)…» |

**Единое правило «значок ПО».** Предикат «неотрицательный значок ПО» уже жил в `AutomaScoring.hasNonNegativeVpIcon`
(Hard/Brutal-подсчёт MarsBot и корпорация Vitor) с допущением «все особые значки неотрицательны». Он вынесен в
`src/common/cards/victoryPointsIcon.ts`, и `AutomaScoring` теперь делегирует туда — у бота и у резолюции одно
правило. Следствие (осознанное): Vermin в стопке сыгранных карт бота больше не даёт +1 ПО на Hard/Brutal — его значок
«−1 за город» является штрафом, как и требует формулировка правила бота.

## 3. Жизненный цикл и однократность

- Шаг `production` **мутирует** (ничего не спрашивает): `player.production.add(M€, amount, {log: false, from:
  {resolution}})` — штатное изменение со всеми событиями, реакциями и записью в EventRecorder
  (`production-changed`, источник `resolution`, снимок до/после); одна строка журнала несёт весь расчёт.
- Ключ идемпотентности драйвера `effect:<gen>:<instance>:<player>:production`: повторный вызов/возобновление
  не платит дважды; прерывание между игроками (краш на втором игроке) после перезагрузки платит только второму
  (спек «an enactment interrupted between two players…»); повторное законное принятие в новом поколении — новое
  начисление по состоянию того момента.
- `outcome` замораживает всё, из чего посчитан результат: `production`, `amount`, `influence`, `count` (B),
  `counted` (названия карт), `uncapped` (сумма до ограничения), `before`/`after`. Поздние карты, влияние и смена
  правительства ничего не пересчитывают.
- Итог фазы хранит `winner.slot` — слот, из которого карта была принята (для физического перехода в сцене итогов;
  старые сохранения без поля деградируют без перехода).

## 4. Общие расширения (для следующих резолюций)

### Сервер + общий слой
- **`victoryPointsIcon.ts`** — классификатор печатного значка ПО (`none` / `fixed` / `variable` со знаком) +
  `victoryPointsSign` в `StaticCardProperties`/`ICard`/`ClientCard` (экспорт в `cards.json`; `Card` отказывает знаку
  на не-`special` карте).
- **`resolutionCounts.ts`** — «счётный член» динамического эффекта: `ResolutionCountId`
  (`buildingCardsWithNonNegativeVp`), `cardCountVerdict` (считается / почему нет — EN-ключ причины),
  `countCardsToward` → `{id, count, cards}`. Один предикат для сервера и «Полигона»; паритет клиентского манифеста и
  серверных классов проверяется по всему корпусу.
- **`influenceScaling.ts`** — `InfluenceScaledEffect.count?: {id, per}`; `scaledAmount(effect, influence, counted)` и
  `uncappedAmount`; чтение `InfluenceYield` получило `count`, `counted`, `uncapped`; `yieldCapped` (ограничение
  сработало) и `yieldAtCap` (результат на максимуме).
- **Модель:** `ParliamentPlayerModel.counts` — счёт каждого места для всех счётных членов каталога (число + карты);
  `ParliamentEnactOutcomeModel` — поля производства и счёта; `ParliamentPhaseSummaryModel.winner.slot`.
- **DSL:** `b.vpCard(tag)` → `CardRenderItemType.VP_CARD` — «карта с меткой и значком ПО».

### Клиент
- **`PremiumVpCardGlyph.vue`** — общий графический элемент: силуэт карты (обложка в светлом ободке), медальон
  печатной метки, золотая плашка ПО с гравировкой «ПО» (локализовано). Один рисунок для грани карты
  (`PremiumMechNode` → `{kind: 'vpCard'}`), блока расчёта и «Полигона». Размер — `--pvpcard-size`.
- **`influenceYieldModel.ts`** — `voteYieldsOf`/`enactedYieldsOf` читают счёт места (без счёта — только формула,
  никакого выдуманного нуля); подпись оценки со счётным членом — «Если принять сейчас»; `yieldCountPresentation`
  (глиф + ключи); `productionResourceLabelKey`.
- **`ConsoleInfluenceYield.vue`** — формула «1 [прод. M€] / [карта-глиф] + [влияние] · макс. 5 · каждому игроку»;
  чтение «[глиф] 2 + [влияние] 2 → +4 [прод. M€]» и метка «МАКС.» на максимуме; производство — спрайт в коричневой
  печатной плашке (язык чипа переноса производства). Data-атрибуты `data-yield-count/-uncapped/-max`.
- **Инспектор (fullscreen)** — в колонке правил: предложение эффекта + одна фраза квалификации («Переменный значок ПО
  считается и при 0 ПО; карта без значка ПО не считается») и блок «Для вас»: «Учтены сейчас: …» (оценка) или
  «Учтены при принятии: …» (записанный результат). Так игрок проверяет, откуда взялось B, без постоянной панели.
- **Голосование на Deck** — блок собственного эффекта с чтениями: графика формулы уступает место (та же графика
  печатается на выбранной карте над ним), текст идёт на всю ширину, оценка и прогноз стоят рядом. Раньше второй
  плашке не хватало высоты и её подпись обрезалась (так было и у Aquifer Contest).
- **Итоги фазы (общая сцена, для всех резолюций):**
  - принятая карта **физически переходит** из слота голосования в правительство: грань правительства ждёт
    (`recapPending.govAwaits`), лицевой прокси стоит над прежним слотом и на бите «принята» летит в правительство
    (`runCardDealFlight`); в любой момент видна одна карта (e2e-проба по местам на экране);
  - бит результата производства зрителя: **один** чип «+N» производства вылетает из блока механики принятой карты и
    садится в ячейку производства M€ рейла (`runResourceTransfers`, канал `production`); ноль и чужие результаты не
    летят; строка итога: «player2: производство M€ +5, максимум (3 → 8) — 3 карты строительства со значком ПО +
    влияние 3»;
  - делегаты принятой карты уходят домой **кубами своего размера** из центра карты. Раньше источником полёта был
    прямоугольник самой карты, а полёт масштабирует прокси по отношению двух прямоугольников — из карты вылетал
    красный блок размером с карту и сжимался по пути (найдено по кадрам записи, дефект был и до RX02). e2e-проба
    мерит самый большой куб в воздухе против куба в резерве (негативный контроль на старой сборке: 230 px против 15).
  - на момент сцены итогов число производства в рейле уже итоговое: сцена — повтор решения, принятого в конце
    поколения. В момент самой фазы изменение производства показывает общий механизм рейла (`AnimatedMetricValue`,
    чип ±N; эпоха — `runId` партии). Удерживать в сцене старое значение значило бы показать ложное «−5». На записи
    проверена сцена итогов; момент фазы отдельно не записывался.
- **Журнал:** одна строка на игрока «player2 повышает производство [M€] на 5 — [Архитектурная премия]: 3 карты
  строительства с неотрицательным значком ПО + влияние 3 = 6, ограничено максимумом 5 (3 → 8)»; X на строке с чипом
  резолюции теперь открывает её инспектор (`journalInspectTargets.resolutions`).
- **Правительство / InfoPanel:** однократный эффект не выглядит постоянным — строки «Эффект резолюции» у
  правительства и в полосе партий нет (они только для `passive`/`action`).

### «Полигон» («Витрина резолюций Redux»)
Резолюция со счётным членом получает своё семейство сценариев (RT листает внутри семейства): нет карт и влияния ·
только влияние · только карты · ниже максимума · ровно +5 · сверх максимума · у каждого игрока свой результат ·
победитель сначала шагает по Повестке · записанный результат · задание 0/2 · 1/2 · выполнено. Каждое место держит
синтетический tableau из **настоящих** карт (Artificial Lake, Domed Crater, Space Elevator, Physics Complex, Capital —
учитываются; Mine — нет значка ПО; Biomass Combustors, Corporate Stronghold — отрицательный значок; Tundra Farming —
нет метки строительства), счёт идёт через общий предикат, у каждой карты виден вердикт с причиной. View / A / Y / L3 и
X (настоящий fullscreen) работают как у Aquifer Contest.

## 6. Рецепт: резолюция «+N за X + влияние (макс. M)»

1. Если X — новый счётный объект: добавить id в `RESOLUTION_COUNT_IDS`, ветку в `cardCountVerdict` (или новый
   не-карточный подсчёт в том же модуле — например, города, колонии, шаги производства), презентацию в
   `yieldCountPresentation` (глиф + ключи), при новом объекте — DSL-примитив и общий глиф.
2. Объявить `scaled: [{id, unit, perInfluence, count: {id, per}, cap, recipient}]`; шаг считает через
   `resolutionCount` + `scaledAmount`/`uncappedAmount`, мутирует штатным API с `from: {resolution}`, пишет одну
   строку журнала и `ctx.report` с `count`/`counted`/`uncapped` (и `before`/`after` для производства/запасов).
3. Клиентские поверхности (голосование, fullscreen, «Для вас», итоги с полётом, «Полигон») подхватывают декларацию
   сами; для нового вида выплаты (`stock`) — ветка в `outcomeText` и `playOutcomeFlight`.
