# Turmoil Redux — «Парламент» v4: режим голосования из трёх карт, физика делегатов, единый каркас эффектов

Дата: 2026-09-16. Продолжение `TURMOIL_REDUX_PARLIAMENT_V3.md` (шаг голосования как фазовый спуск, физика карты,
кубы + гнёзда, счёт оплаченного голоса внутри шага, маркер Повестки) — всё это осталось и переработано там, где v3
не читалось цельно. Правила игры не менялись; каталог реальных резолюций, новые колонии, Chaotic, обучение и политика
MarsBot — вне итерации. Документ фиксирует **найденные причины**, **архитектуру режима голосования**, **контракты**,
**проверку** и **честные ограничения**.

## 1. Причины, найденные по скриншотам и покадровым записям

| Симптом (v3) | Причина | Что сделано (v4) |
| --- | --- | --- |
| Голос = карта-герой слева + форма справа; две другие резолюции пропадали | шаг был построен вокруг ОДНОЙ карты; сравнить три резолюции можно было только через вьюер | **режим голосования из трёх карт**: те же три слота обзора едут в ряд, выбор ◀ ▶, нижняя зона объясняет выбранную |
| Карта в шаге — вторая копия (слот `--carried` прятал первую) | копия + скрытый оригинал = два DOM-объекта, «прыжок» при возврате | **`<Teleport defer>`** переносит САМ элемент слота в ряд (одна копия по построению), вход/выход — измеренные FLIP'ы |
| Вход читался как «пустой растягивающийся контейнер» | поверхность раскрывалась `clip-path`'ом из ректа слота без содержимого | поверхность **проявляется в итоговой геометрии вместе с содержимым** (`SURFACE_AT` 180 мс, `expo.out`), содержимое — двумя волнами (структура → мелкий текст); карты — событие |
| Из вьюера: обзор мигал под гаснущей вуалью | receders отступали анимацией 200 мс, вуаль вьюера снималась быстрее | при `fromViewer` receders **паркуются до первого кадра** — вуаль снимается на сцену голосования, карта летит в свой слот |
| B: поверхность исчезала за кадр, обзор «выстреливал» | поверхность, карты и обзор стартовали в одном тике; expo.out возврата | порядок **поверхность → карты → сцена**: поверхность тонет с 0 мс (170), карты домой с 40 мс, обзор дышит обратно со 130 мс |
| Счётчики тикали на ~80 мс позже визуальной остановки куба | `power2.inOut` доезжал последние 1,5 % пути 50–80 мс; `onLanded` только в `onComplete` | **посадка при `p ≥ 0.985`** (`TOUCHDOWN_AT`, хвост снэпается) — тик счётчиков, бейдж, CTA и класс `--landed` в одном кадре с остановкой куба |
| Прокси садился на 26 px, реальный куб 15 px — хлопок на передаче | цель полёта — обёртка `.con-parl__vote-cube`, а не `.player-cube` внутри | цель = **внутренний куб**; кейфреймы `con-parl-land` — приземление (scale 1 → .86 → 1.08 → 1), без translate/opacity |
| «ПОБЕЖДАЕТ» переезжал на карту и лидер менялся, пока куб ещё в лобби | бейджи читали живую модель сразу после ответа | **`voteInFlight`**: до посадки все следствия голоса (счёт, лидер, бейдж на каждой карте, CTA) читают снимок `VoteSnapshot {…, winner}` |
| Лобби: «использован в этом поколении» при кубе, стоящем в гнезде | текст читал модель, куб — `sourceHold` | **`sourceLeaving`** + `onDeparted` (p ≥ 0.1): слова гнезда/счётчик резерва меняются, когда куб ВИДИМО ушёл |
| Крошка мигала ГОЛОС → ОТПРАВКА → ГОЛОС за 80 мс | стадия `submitting` имела свой ярлык | `crumbStageOf(stageBeforeSubmit)`: переходный бит не переименовывает хвост (фаза `committed` красит его янтарём) |
| «Эффект партии для вас: 1 из 2 → 1 из 2» после посадки | `voteAccessOf` брал «до» из живой модели | `voteAccessOf(slot, party, after, **beforeMine**)` — «до» из снимка |
| Нажатие A замирало на ~165 мс до первого кадра | тело инфо-зоны монтировалось на нажатии (механики, формулы, факты) | инфо-тело **всегда смонтировано** под скрытым слоем: нажатие только переносит карты и поднимает поверхность (JS-блок 85 → 60 мс, первый кадр 165 → 128 мс в headless) |
| «Уйдёт свободный делегат из лобби» справа + «ВАШ ГОЛОС: свободный делегат из лобби» + кольцо на группе | три утверждения об одном источнике | подсказка скамьи осталась **только для «нечего отправить»** (янтарь); источник отмечен кольцом группы и блоком «Ваш голос» |
| dummy: «ЭФФЕКТ РЕЗОЛЮЦИИ / СОБСТВЕННОГО ЭФФЕКТА НЕТ» в две строки, задание упиралось в низ | блок «свой эффект» всегда колонка | `--none`: кикер и нота в одну строку; заданию есть воздух |
| Пассивный эффект Учёных — одинокое двоеточие перед меткой; Союз/Учёные не узнавались | `effectParts` считал spacer-узел причиной; эмблемы — два «кольца» | стоячий модификатор без стрелки/двоеточия (`pcard-effect--standing`, общий каркас); **Союз = сцепленные кольца, Учёные = атом** (синий vs серебро) |
| «Марс вперёд»: сталь читалась дважды | одна строка «тайл → сталь, город → сталь + карта» | две строки: тайл на Марсе → 1 сталь; город → дополнительно карта (правила не менялись) |
| Итоги: маркер Повестки доезжал, но реальный куб оставался скрытым под прокси; `agendaSettling` висел до 5-секундной страховки холда (награда-карта со ступени ждала бы вечно) | хэндл директора лежал в `data()` — при чтении это reactive-proxy, `this.agendaGlide === handle` всегда false → колбэк lock выходил молча | хэндлы хранятся через **`markRaw`** (`agendaGlide`, `flightHandles`); снятие прокси полёта — через `probeTick` (rAF или 50 мс), не голый rAF |
| Счётчик TV/Deck: «Ваши ○○ 0» вылезал за слот; факты не влезали (5 строк + заметки в значении); на Deck переносились чип источника и CTA | `flex-wrap: nowrap` у счётчика; заметка стояла в колонке значения и сжимала ключ в многоточие | счётчик переносится; **четыре** строки фактов (счёт несёт хвост «из них ваших 0 → 1»), заметка строки — под её ключом, ключ может занять две строки (TV: «2 из 2 → эффект ваш»); Deck: без «полное действие», без пустых мест поддержки на печатях, `--con-parl-info-h: 14.4rem` |
| Deck: панель правил вьюера у dummy-резолюции прокручивалась (572 > 504 px) | четыре блока чтения; блок «Эффект резолюции — собственного нет» повторял надпись лица рядом | у dummy инспектор не тратит блок на «нет эффекта» (лицо говорит это в зоне механики); на Deck тир `dense` отдаёт хром, как `packed` |

## 2. Архитектура режима голосования

```
ПАРЛАМЕНТ › <резолюция> › ГОЛОС                  (descendWorkspaceFrame('parliament', name, 'Vote'))
┌ СКАМЬЯ ── ваши делегаты: [ЛОББИ ● свободный делегат] [РЕЗЕРВ ▤ ×4 · 5 M€ за делегата] ──────────┐
│ ┌ слот 1 (выбран) ──┐ ┌ слот 2 ─────────────┐ ┌ слот 3 ─────────────┐                          │
│ │ эмблема · партия   │ │ … · ПОБЕЖДАЕТ        │ │ …                    │   ← те же элементы обзора │
│ │ [карта]            │ │ [карта]              │ │ [карта]              │      (Teleport в [data-parl-vrow]) │
│ │ лента ● [место]    │ │ лента ● ●            │ │ Делегатов пока нет   │                          │
│ │ 1 делегат · лидер · ваши ○○ 0 │ …          │ │ …                    │                          │
│ └────────────────────┘ └──────────────────────┘ └──────────────────────┘                          │
│ ┌ ИНФО-ПОВЕРХНОСТЬ (фиксированная геометрия) ─────────────────┐ ┌ ВАШ ГОЛОС ───────────────────┐ │
│ │ имя · партия · [ПОБЕЖДАЕТ]                                  │ │ ● Свободный делегат из лобби  │ │
│ │ ЭФФЕКТ РЕЗОЛЮЦИИ — графика + текст | «собственного нет»     │ │ ПОСЛЕ ВАШЕГО ГОЛОСА           │ │
│ │ ЕСЛИ РЕЗОЛЮЦИЯ БУДЕТ ПРИНЯТА — правит партия, её эффект     │ │ делегатов 1→2 · ваши 0→1      │ │
│ │   всем: формула партии + текст                              │ │ лидер ● → ● player2           │ │
│ │ ЗАДАНИЕ ПРЕДСЕДАТЕЛЯ — графика + условие · награда          │ │ побеждает нет → да (ничья…)   │ │
│ │                                                             │ │ эффект партии для вас 0→1 из 2│ │
│ │                                                             │ │ (A) Отправить делегата        │ │
│ └─────────────────────────────────────────────────────────────┘ └───────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘
```

- **Одна копия каждой карты по построению.** Слот обзора `<Teleport defer to="[data-parl-vrow]" :disabled="!slotsCarried">`
  переезжает в ряд режима и обратно — тот же DOM-элемент, та же `premium-card-face`. Перед сменой раскладки секция
  измеряет ВСЁ несомое (`measureVoteRects`: лица, подписи, счётчики, каждый куб ленты по `instance#seq`, гнездо лобби и
  резерв зрителя), после `$nextTick` + `fitCards()` играет FLIP'ы из старых ректов (`playParliamentVoteEnter`) — первый
  кадр каждого объекта закреплён `gsap.set` на ректе отправления, статичное конечное состояние = анимированное.
- **Фраза входа** (`consoleParliamentVoteMotion.ts`): COMMIT плиты (120) → RECEDE остального обзора в точку нажатия
  (200) ∥ CARRY карт/кубов/подписей (40 → 380, `power3.inOut`) ∥ скамья: гнездо лобби и стек резерва FLIP'ом с реестра
  мест ∥ SURFACE: инфо-поверхность проявляется в итоговой геометрии с содержимым (180 → 260) → REVEAL структуры (240) →
  LATE мелкий текст (360). **Из вьюера** — та же фраза минус FLIP выбранной карты (её везёт `playZoomHandoff` в
  `[data-zoom-handoff="parliament-vote"]`), receders запаркованы до первого кадра.
- **Фраза выхода (B)**: поверхность тонет с содержимым (0 → 170) → скамья и карты домой (40 → 320/280, снова FLIP по
  измеренным ректам ряда) → обзор дышит обратно из той же точки (130 → 220) → слой отпускает. В `done` — только сброс
  флага `voteLeaving`; ничего не «допоказывается».
- **Стадии**: `browse → vote → submitting → (paying) → landed → уход`. Крошка = `crumbStageOf(stage | stageBeforeSubmit)`.
  `voteInFlight` = снимок есть ∧ (`submitting` | `paying` | `landed` до `landedSeq`). Пока голос в воздухе: `tallyOf`,
  `winningShownOf` (для КАЖДОЙ карты — снимок хранит `winner`), класс `--mine`, `voteInfo.winning`, CTA
  («Выполняется…» → «Делегат поставлен») и бар команд читают снимок.
- **Полёт делегата** (`runDelegateCubeFlight`): прокси рождается на измеренном ректе куба-источника
  (`[data-parl-lobby-cube] .player-cube` | верх стека `[data-parl-reserve-cube]`), `onLifted` (первый тик) убирает
  куб источника из-под прокси, `onDeparted` (p ≥ 0.1) отпускает слова источника (`sourceLeaving`), `onLanded` при
  p ≥ 0.985 снэпает прокси на цель = **внутренний куб** места на ленте, секция ставит `landedSeq` (реальный куб
  появляется под прокси, `con-parl-land` — приземление), прокси снимается следующим кадром. Оплаченный голос,
  свёртка/восстановление и перезагрузка вокруг счёта — как в v3.

## 5. Честные ограничения

1. Итоги поколения физичны частично: возвраты делегатов в реестр, народная поддержка и лобби едут кубами, маркер
   Повестки — директором Гидросети; переезд принятой карты и раздача новых резолюций — текстовые биты с подсветкой.
   В headless-Chromium (e2e) rAF голодает на тихом экране, и полёт GSAP замирает на последних процентах пути — тест
   итогов прокачивает кадры (`page.screenshot({clip: 8×8})` внутри `expect.poll`); на реальном компоситоре кадры идут сами.
1a. На TV и Deck счётчик слота занимает две строки («2 делегата · лидер» / «ваши ○○ 2») — ширина слота там не вмещает
   три группы в одну; на 1080 — одна строка.
2. Записи движения сняты Playwright'ом из headless-окна: рекордер под нагрузкой теряет кадры (в одном прогоне полёт куба
   «выпал» из видео при полном DOM-таймлайне) — ориентир для ритма даёт связка кадры + таймлайн, не одно видео.
3. Порог карт в ряду — по высоте инфо-поверхности (`--con-parl-info-h`): при трёх блоках с графикой карты 1080 — 245 px;
   шире их не сделать, не отняв у объяснения.
4. R3-слой «Эффекты» в композере партийного действия отсутствует (как в v2/v3).
5. Арты резолюций — печати партий в окне арта; dev-резолюции только для осмотра (`copies: 0`).
