# Turmoil Redux · TR21 Arboretum («Дендрарий»)

Карта проектов набора (2026-10-04). Впервые в проекте: **НАГРАДА КАРТЫ, КОТОРУЮ РЕШАЕТ КЛЕТКА, И ОНА ЛЕЖИТ НА КАРТЕ** —
«+1 data на ЛЮБУЮ карту за каждый город рядом с этим тайлом». Число зависит от клетки, причина — соседи, адресат — карта,
которую игрок выбрал. Оценивается одно: **выбор клетки читается как выбор ВЫГОДЫ, а выгода приходит физически.** Игрок
водит курсор и на каждой клетке видит, какие города заплатят (подсвечены), сколько data, на какую карту и «было → станет»,
что ещё сработает; после подтверждения каждый соседний город отдаёт свою data, и она ложится на выбранную карту.

Промпт: `docs/claude/prompts/project-tr21-arboretum.md`. Соседи: `docs/TILE_PLAY_STAGED_COMMIT.md` §8-bis (первая выдача
карты, рождённая у соседей), `docs/claude/console/board-placement-flow.md` (старшинство тонов), `docs/TURMOIL_REDUX_MARTIAN_CENSUS.md`
(требование партии), `docs/TURMOIL_REDUX_FORESTRY_SUPPORT.md` (ближайший образец — выплата «за каждый соседний тайл» у резолюции).

## 0. Решения владельца

Приняты по умолчанию промпта и ждут подтверждения:

1. RU-имя «Дендрарий».
2. Стопка городов считается ПО ЯРУСАМ.
3. Все data — на ОДНУ карту.
4. Цель — ДО клетки, в композере (весь розыгрыш обратим до подтверждения клетки; досье знает, куда лягут data).
5. Тон подсветки: клетка, которая ПЛАТИТ СЕЙЧАС (`reward`), старше клетки, которая ДАСТ ПО В КОНЦЕ (`score`).
6. Сцена — карта-получатель выходит к полю и принимает data.

## 1. Карта и правила

TR21, 12 M€, AUTOMATED, метки Растение + Строительство, `requirements: {party: PartyName.MARS}`, 1 ПО, `tr: {oxygen: 1}`
(только для расчёта цены при Красных — шаг кислорода даёт движок), `compatibility` нет. Ряд лица:
«[озеленение O₂]  X [data]*». Лор — печатный: «It's like an aquarium, but for trees and loiterers.» / «Это как аквариум,
только для деревьев и зевак.»

**Кислород — часть озеленения, не второй эффект**: красный кружок на значке — печатная пометка любого `b.greenery()`;
шаг даёт `Game.addGreenery` (на максимуме — шага и его РТ нет, тайл всё равно ставится); правило Redux отдельно платит
+1 РТ за сам тайл озеленения.

## 2. Контракт «награду решает клетка» (сервер)

### 2.1 Счёт — `boards/cityStack.ts`
`adjacentCitySpaces(board, space)` — клетки-города вокруг; `adjacentCityTiers(board, space)` — их ярусы. ОДНА функция для
досье, выплаты, сцены и двух починок «по ярусам» в `BoardInformationEngine` (факт ПО Торгового района считал КЛЕТКИ;
«соседний город получит ПО в конце игры» у озеленения писал `0 → 1` на стопку из двух).

### 2.2 Цель без числа — `deferredActions/SelectResourceTarget.ts`
`new SelectResourceTarget(player, resource, cause, basis, title?)` — «выбери карту, на которую ЛЯГУТ ресурсы, число — потом»:
`Priority.PLAY_CARD_RESOURCE_CHOICE`, без авто-выбора, кандидаты — `AddResourcesToCard` (одна функция кандидатов), ответ
хранится в шаге (`chosen`) и читается `andThen` размещения; `previewSelectCard()` — read-only близнец. Маркер —
`resourceGainPrompt` БЕЗ `amount`, с `amountBasis: {per: 'adjacent-city'}` (`AdjacencyAmountBasis`) + `choiceContext`
`reward`. Шаг превью — `actionPreviews.resourceTargetStep(step)`.

### 2.3 Общий модуль — `cards/adjacentCityPayout.ts`
- `adjacentCityTarget(player, card, resource, legalCells, title)` → шаг или `undefined` (ни одна законная клетка не платит —
  правило 6; держателя нет — `undefined`, предупреждение отдельно).
- `adjacentCityPreviewSteps(step, warning)` — шаг цели или НАЗВАННОЕ предупреждение без числа (число решит клетка).
- `payPerAdjacentCity(player, card, space, resource, target)` — в `andThen` размещения: N = 0 → строка «соседних городов
  нет»; держатель выбран → `land()`; держателя нет → `recordSkippedEffect(noHolder, skippedAddToCard(resource, N))`.
- `land()`: `addResourceTo(target, {qty: N, log: false, from: {card}, basis: {count: N, unitKey}})` + одна строка журнала
  с причиной + запись подачи (`game.recordCardAdjacencyPayout`) с ИЗМЕРЕННЫМИ реакциями (`stock.asUnits()` до / после —
  что заплатил стол, мерит сервер, клиент не выводит).
- `adjacentCityPayoutFacts(player, card, space, resource)` — хук досье: факт «За N соседних городов» с `delta {data, N}`,
  `spaces` = клетки городов (relation-слой зажигает их сам), `landsOnChosenCard`, реакции стола
  (`grantReactionFacts` — живые `grantForecast` табло, тот же проход, что у композера) как факты `reaction: true`;
  N = 0 → правило «Соседних городов нет — data не будет»; нет держателя → предупреждение «data некуда положить» с величиной.

### 2.4 Хук досье карты подсвечивает клетки
`placementPreviews.FactOptions.spaces` — первый хук КАРТЫ, который называет клетки поля (до этого умели только резолюции
через `ctx.gain(…, {spaces})`). `forecastReaction(fact)` превращает факт прогноза в факт досье (одна строка, имя карты,
голая дельта, `reaction: true`).

### 2.5 Журнал — `EventImpact.cardResources[].basis`
`CardResourceBasis = {count, unitKey}` (`unitKey` — английский ключ с группой множественного числа). Строка журнала
печатает чип + «за 3 соседних города»; общий для любой будущей выплаты «за каждый X».

### 2.6 Запись подачи — `GameModel.cardAdjacencyPayouts`
`CardAdjacencyPayoutModel = {seq, color, card, spaceId, basis, neighbours: [{spaceId, units}], target, resource, amount,
before, reactions?}` — кольцо (cap 8), `seq = gameAge * 100 + n`, читается клиентом ОДИН раз по `seq` (герой или
remote-стейдж). Сцена играет запись сервера, а не геометрию.

### 2.7 Что получает следующая карта «за каждый X рядом с тайлом» даром
Шаг цели без числа, staged-коммит с целью до клетки, строка досье с целью и реакциями, подсветка платящих клеток тоном
`reward`, названный пропуск, строка журнала с причиной, запись подачи и сцена. Требует руки: другой X → новый
`AdjacencyAmountBasis.per` + ключ единицы + функция счёта в `boards/` (с `spaces`) + источник жетона в геометрии сцены
(`cityDataPayoutBeat.stageGeometry` знает только города). Строка в чеклисте набора §4.

## 3. Клиент — ВЫБОР

- **Композер**: шаг цели (`ConsolePlayedTargetStep`) печатает у кандидата его живой счёт и СТАВКУ «· +1 за каждый соседний
  город» — никакого «→ N» (`PlayedTargetImpact.per`, `consolePlayedTargetPreview` по `amountBasis`); то же в сводке
  (`ConsolePlayCardConfirm`, `ConsoleActionComposer`). Выбранная цель едет в staged-арм (`StagedPlayArm.cardTarget`).
  «⚡ Сработает» TR18 — в слое R3 как отложенный факт без числа (компактная строка печатает только посчитанные дельты).
- **Досье** (`placementDossier.ts`): строка «За N соседних городов [data] +N», под ней «→ [мини-лицо] Векторные вычисления
  [data] 2 → 6» (два серверных числа: счёт карты из табло + `amount` факта — `ConsoleShell.placementChosenTarget`) и
  «⚡ Марсианское оптоволокно [M€] +4» — ответ стола читается С причиной, в той же строке (`DossierRow.reactions`); секция
  «Сработает» — только для реакции без строки-причины. Строка с этими линиями отдаёт резерв колонки значений
  (`con-dossier-row--landing`: колонка выровнена вправо, числа не сдвигаются) — имена карт читаются целиком. Высота линий
  — высота их текста (лицо `zoom .04`, иконки `1.05em`, эмодзи-молния зажата): на 4K богатая клетка фикстуры встала без
  скролла ровно в край (было +138 px).
- **Поле**: `placementRelations.TONE_RANK` — `penalty > ocean > reward > score > event`: свой город рядом с озеленением и
  платит data сейчас, и даст ПО в конце — светится золотом (`reward`).

## 4. Клиент — СЦЕНА «ГОРОДА ПЛАТЯТ»

Чистая половина — `tilePlacement/cityDataPayoutModel.ts` (запись, порядок жетонов, тайминги, где стоит карта);
директор — `cityDataPayoutBeat.ts`; слой — `ConsoleCityPayoutLayer.vue` (смонтирован оболочкой рядом со слоем посадки
тайла, никогда внутри телепортируемой поверхности).

СВОЯ сцена — ПОСЛЕ обычных тактов посадки (тайл → бонус клетки → вода → Ares → волна закона) и после истории шкал
(кислород тикает РАНЬШЕ первого импульса города — `waitForTheScales`, ограничено 6 с):
1. **RISE** (320 мс) — карта-получатель (премиум-лицо, живая модель с замороженным `before`, капсула видна) выходит ИЗ
   ячейки data спутника «ДОП. РЕСУРСЫ» (первый кадр — во всю непрозрачность на месте ячейки) и встаёт у поля рядом с
   озеленением, не закрывая ни его, ни платящие города (`cityPayoutPlate` — шесть направлений, внутри видимой доски);
2. **PAY** — каждый город просыпается по разу на каждый свой жетон (волна берега океана в регистре города; стопка —
   дважды), жетон data конденсируется у его кромки и летит Resource Transfer Framework в капсулу карты; счётчик капсулы
   тикает на КАСАНИИ; два касания в одном кадре тикают по очереди (`CITY_PAYOUT_TICK_GAP_MS` 90 мс — никогда «4 → 6»
   одним рендером, никогда раньше касания);
3. **READ** (680 мс) — «2 → 6» стоит (плашка под картой);
4. **RETURN** (260 мс) — карта уходит в свою ячейку, её счётчик тикает там (холд спутника, посеянный в коммите, снимается
   на посадке);
5. через вдох (200 мс) ответ стола (M€ TR18, измеренный сервером) летит из ячейки в рельсу, тикая на касании.

ЧУЖАЯ сцена (remote-стейдж): те же волны и жетоны летят к чипу игрока в статус-полосе; его карта у другого не поднимается.

Холды: `city-data-payout` (блокирующий, реактивный, `expire` + `diagnose`, снимается концом сцены — не таймером) и
`city-data-payout-pending` (только лента нотификаций, пока сцена ждёт шкалы). Reduced motion — ничего не летит, счётчики
тикают с коммитом. Нечего мерить — `data-city-payout-degraded`, все холды отпущены, числа тикают.
