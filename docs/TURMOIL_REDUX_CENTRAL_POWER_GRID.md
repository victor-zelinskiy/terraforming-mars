# Turmoil Redux — Central Power Grid (RX04): счётный член становится МЕХАНИЗМОМ

Дата: 2026-09-17. Продолжение `TURMOIL_REDUX_ARCHITECTURE_AWARD.md` (шаблон «+N за X + влияние, макс. M»).

Central Power Grid — четвёртая настоящая резолюция и **вторая карта семейства «счётчик + влияние → ограничение →
изменение производства»**. Её задача — доказать, что семейство подключается через общий механизм, а не копированием:
декларация (`InfluenceScaledEffect` со счётным членом и ограничением), одна арифметика (`scaledAmount` /
`uncappedAmount`), штатное `production.add`, запись результата, идемпотентность драйвера, клиентские поверхности и
«Полигон» — всё общее. Отличается ровно одно: **что именно считается**.

| | Architecture Award (RX02) | Central Power Grid (RX04) |
| --- | --- | --- |
| Счётчик | **КАРТЫ** — одна подходящая карта = 1 | **МЕТКИ** — карта даёт каждую свою энергетическую метку |
| Условие карты | метка строительства **и** неотрицательный значок ПО | печатная энергетическая метка, и больше ничего |
| Карта с двумя метками | 1 | **2** |
| Значок ПО | обязателен | не участвует вовсе |

## 2. Правило и трактовки

Печатный текст: *When enacted: Increase your M€ production 1 step for each Power tag you have + Influence. (Max. 5)*.
Задание председателя: разыграть 2 энергетические метки.

**Формула:** `прирост = min(5, P + I)` для **каждого** участника (голосовал или нет, есть ли доступ к эффекту партии —
неважно; нейтральная победа ничего не отменяет). Ограничение действует на **сумму прироста**, не на итоговое
производство (8 → 13 законно). Отрицательное производство растёт обычным образом (−3 при +4 → 1). Это
**производство M€**, не деньги. **Части победителя нет** — ни океана Aquifer Contest, ни озеленения Biodome Contest.

| Вопрос | Трактовка | Где закреплено |
| --- | --- | --- |
| Что считается | **метки**, а не карты: `HE3 Fusion Plant` (две энергетические метки) даёт 2 | `resolutionCounts.ts` (`resolutionCountKind('powerTags') = {kind:'tags', tag: power}`), спек «counts TAGS, not cards» |
| Значок ПО | не участвует: карта без значка и карта с −1 ПО считаются обе | спек «the VP icon plays no part» |
| Запас и производство энергии | не участвуют: «Искусственный фотосинтез» (+2 производства энергии, метка науки) даёт 0 | спек «the energy RESOURCE and energy PRODUCTION are not tags» |
| Источники меток | канонический счётчик проекта `Tags.count(POWER, 'raw')` — разыгранные проекты, корпорация(и) в игре, прологи, CEO, постоянные модификаторы | `ResolutionCounts.ts`, спек «every source in play counts» + «two corporations after a merger» |
| Исключённые зоны | рука, сброс, чужой tableau; сыгранное событие лежит рубашкой вверх (кроме Odyssey); отключённый Pharmacy Union вне игры | спек «only the player's own cards IN PLAY» |
| **Универсальные метки** | wild-метка (печатная и выданная Учёными) **не** энергетическая: принятие — не собственное действие игрока, поэтому подстановка режима `'default'` не применяется. Контекст назван явно: `RESOLUTION_TAG_COUNTING_MODE = 'raw'` | спек «a WILD tag is not a power tag», сценарии «Полигона» `grid-wild` / `grid-own-turn` |
| Влияние | канонический `parliament.influence(player)` **после** шага победителя по Повестке (драйвер сеет `ctx.influence` после шага 1); делегаты влияния не дают | спек «influence comes from the Redux ledger AFTER…» |
| Два делегата | дают эффект партии «Индустриалисты», но **не** запускают эффект резолюции | спек «two delegates grant the Industrialists' EFFECT…» |
| Нулевой результат | названный пропуск: строка журнала + `outcome skipped` с причиной «Нет энергетических меток и влияния», производство не меняется, перелёта нет | спек «the cap bounds the INCREASE…» |
| Финальное поколение | производство всё равно растёт (финальные системы видят настоящее значение), денежной компенсации нет: доход того поколения уже выплачен по старому производству | спек «the FINAL generation still raises the production…» |
| MarsBot | политика `none` не меняется: бот не считается, не получает, фаза не зависает | спек «MarsBot (mode none)…» |

**Явный контекст подсчёта.** Общему механизму не хватало одного: словом названного момента, в который читается
счётчик меток. `RESOLUTION_TAG_COUNTING_MODE` (`'raw'` из `Tags.CountingMode`) — это минимальное переиспользуемое
расширение: сервер (`resolutionCount`), модель места и клиентский обход синтетического tableau стоят на одном слове,
и «во время своего хода соседний счётчик показывает универсальную метку» больше не может просочиться в прогноз.

## 3. Жизненный цикл и однократность

- Шаг `production` **мутирует** (ничего не спрашивает): `player.production.add(M€, amount, {log: false, from:
  {resolution}})` — штатное изменение со всеми событиями, реакциями и записью в EventRecorder
  (`production-changed`, источник `resolution`, снимок до/после); одна строка журнала несёт весь расчёт. Под
  источником карты в событиях нет ни одного `resource-changed` — денег она не выдаёт.
- Ключ идемпотентности драйвера `effect:<gen>:<instance>:<player>:production`: повторный вызов/возобновление
  не платит дважды; прерывание между игроками после перезагрузки платит только второму; повторное законное
  принятие в новом поколении — новое начисление по состоянию того момента.
- `outcome` замораживает всё: `production`, `amount`, `influence`, `count` (P), `counted` (названия карт),
  **`countedUnits` (вклад каждой карты)**, `uncapped`, `before`/`after`. Поздние метки, влияние и смена
  правительства ничего не пересчитывают.

## 4. Общие расширения (что переиспользовано и что выросло)

### Общий слой
- **`resolutionCounts.ts`** — счётный член получил **ВИД**: `ResolutionCountKind` (`{kind:'cards'}` |
  `{kind:'tags', tag}`), `cardCountUnits(id, card, ctx)` (сколько единиц даёт карта), `ResolutionCountModel.units`
  (вклад каждой перечисленной карты — только у tag-счёта; у card-счёта колонка единиц не появляется),
  `RESOLUTION_TAG_COUNTING_MODE`. `cardCountVerdict` получил ветку `powerTags` с причиной «No power tag».
- **`ResolutionCounts.ts` (сервер)** — для tag-счёта ЧИСЛО берётся у канонического счётчика проекта
  (`player.tags.count(tag, RESOLUTION_TAG_COUNTING_MODE)` — он же видит постоянные модификаторы, которых не печатает
  ни одна карта), а общий предикат даёт РАЗБИВКУ по картам. Паритет двух источников закреплён спеком по корпусу.
- **`influenceScaling.ts`** — `InfluenceYield.countedUnits` + `YieldCount.units`; `fixedYield` принимает
  `countedUnits`. Арифметика не изменилась ни на строку.
- **Модель / сохранение** — `SerializedEnactOutcome.countedUnits` и `ParliamentEnactOutcomeModel.countedUnits`
  (необязательные: старые сохранения читаются как «каждая карта = 1»).

### Клиент
- **`PremiumCountGlyph.vue`** — общий глиф счётного объекта: `vp-card` (карта со значком ПО — Architecture Award)
  или `tag` (печатный медальон метки — Central Power Grid), в ОДНОЙ коробке `--pvpcard-size`, так что строка формулы
  и чтение сохраняют общий ритм независимо от того, что считается. `ConsoleInfluenceYield.vue` и «Полигон» перешли
  на него.
- **`influenceYieldModel.ts`** — `YieldCountGlyph` (союз), запись `powerTags` (глиф + `'${0} power tag(s)'` +
  фраза квалификации), `countedContributions(y, nameOf)` — список учтённых карт с вкладом («… ×2» только там, где
  вклад больше единицы).
- **Инспектор (fullscreen)** — блок «Для вас» печатает вклад каждой карты; строка «не учтено ни одной карты»
  появляется только при счёте 0 (счёт, стоящий не на картах, не называется «нет карт»).
- **Голосование, итоги фазы, журнал, физический переход карты, полёт производственного чипа** — без изменений:
  всё это уже читало декларацию и запись, а не имя карты.

### «Полигон» («Витрина резолюций Redux»)
Новое семейство сценариев `counted-tags` (RT листает внутри семейства), на НАСТОЯЩИХ карточных определениях и общем
предикате: 0 меток и 0 влияния · только влияние · только метки · ниже максимума · ровно +5 · сверх максимума ·
**одна карта с двумя метками** · метки на корпорации, прологе и проекте · энергетическая карта без значка ПО ·
энергетическая карта с отрицательным значком · **универсальная метка не считается** · **просмотр в свой ход — при
принятии счёт тот же** · у каждого игрока свой результат · победитель сначала шагает по Повестке · отрицательное
производство · производство 8 → 13 · записанный результат · задание 0/2, 1/2, выполнено. У каждой карты виден
вердикт с причиной и вклад («✓ Учтена ×2»), у места — сумма вкладов.

## 6. Рецепт (уточнение к RX02): новый счётный объект

1. Добавить id в `RESOLUTION_COUNT_IDS`, вид в `resolutionCountKind`, ветку в `cardCountVerdict`; если объект — не
   карта, а её печатная деталь (метка), вид `tags` уже даёт правильный вклад через `cardCountUnits`.
2. Если у счёта есть КАНОНИЧЕСКИЙ счётчик проекта — брать число у него (`ResolutionCounts.ts`), а общий предикат
   оставить разбивкой, и закрепить паритет спеком.
3. Назвать презентацию в `yieldCountPresentation` (глиф + множественная форма + фраза квалификации); глиф — через
   `PremiumCountGlyph`, новый рисунок заводить только для действительно нового объекта.
4. Дальше ничего: декларация `scaled`, шаг через `resolutionCount` + `scaledAmount`, `ctx.report` — и голосование,
   fullscreen, «Для вас», итоги с полётом и «Полигон» подхватывают карту сами.
