## 3. Что значит «адаптирована»

### 3.1 Карта «на месте» (53 карты)
Маршрут — `docs/claude/expansion-adaptation-checklist.md` целиком (таблица подсистем — что нужно карте каждой
формы, и какой гард это требует). Коротко, по форме карты (пометки в списке):
1. **Декларативная** (`behavior` без bespoke) — превью / информация / причины / лицо автоматически; работа —
   лор (`assets/text/lore_texts.json` по `cardNumber`, EN + RU; RU-тексты — по планке
   `docs/claude/ru-translation-standard.md`), RU `card_info.json` по аудиту `make:cards`, арт
   (`assets/card-images/<P##>.webp`, при отсутствии — процедурный фолбэк, не гэп), спек карты. Карта с ПОИСКОМ ПО
   МЕТКЕ («draw N X cards» — P76): блок поиска засевается из одного дескриптора, описание со словом «draw» берёт строку
   `ACCEPTED` гарда `cardInformation` (прецедент Aqueduct Systems), а стенд ставится фикстурой с ПОСЕЯННОЙ лентой
   (`stackDeckTop`) — иначе лента и стопка «СБРОШЕННЫЕ» не видны. Счётный термин меток считает собственную метку
   разыгрываемой карты (`Counter.cardIsUnplayed`) — превью ≡ исполнение, а базис называет эту долю («в т.ч. эта карта N» —
   `ActionEffectBasis.self`, P81). Журнал серии: `docs/claude/prelude2-cards-progress.md`.
   ИМЕНОВАННЫЕ ПОИСКИ ПО СВОЙСТВУ КАРТЫ — пять правил одного маршрута (`card-draw-motion.md` § Правило поиска): значок
   аэростата (P44), требование партии (P51), любое требование (P54), без меток (PC03 — `noTags`: ни одной ПЕЧАТНОЙ метки и
   не событие; джокер здесь метка; отброшенная карта называет метки, которые её отбросили — `failedTags`), плюс метка / тип /
   «без меток X». Новое правило — поле `DrawCard` + ОДИН предикат + поле дескриптора + `drawSearchReading` (switch без default
   не скомпилируется без ветки); у корпорации строка старта генератора тоже читает дескриптор (PC03 — corp-local «Draw a
   card.» теряла правило).
2. **bespokePlay / `play()`** — ко-локированный `cardPlayPreview` (результат показан даже без выбора; каждая цель
   ПОКАЗАНА — Special Permit «украсть 4 растения», Recession «каждый соперник»), `metadata.infoText` по блоку на бонус,
   `skipped`-запись при пустой цели. Атака bespoke-карты передаёт `cause` (`cardSource(this)` — промпт называет карту) и
   имеет превью по форме Air Raid (шаг цели `orOptionsStep(previewOptions())` + чип выигрыша); причина руки «нет цели» —
   именованный `unplayableReason` (P82, реестр DB). Розыгрыш, который ЗАКАНЧИВАЕТ ход (P80 — «это считается пасом»): карта объявляет
   `playCountsAsPass`, превью несёт `passes`, композер читает пас тем же чтением, что кнопка «Пас» (реестр CT), а закон
   общий: любое действие, после которого сервер отдаёт ход, уводит экран только через `screenHandoff`.
   Bespoke-половина требования («никто не спасовал») — именованный `unplayableReason` + `requirementFootnote` на лице.
   Bespoke с ПОРОГОМ АВТО-ПРИМЕНЕНИЯ (P78: «≤ 3 кандидатов — кладём молча») — всегда промпт, превью по форме Astra
   (`mergeCardSteps`), а в композере кандидатов не больше мест и каждый — выигрыш → ПОСЕЯНЫ ВСЕ (реестр CU).
   Умноженный печатный бонус клетки (P74 «ещё 2 раза») — ТОЛЬКО через `printedBonusMultiplier` (`PlaceCityTile` / `addTile`; staged
   несёт его в `StagedPlacementModel`), никогда ручными `grantSpaceBonuses` после тайла: досье, пометка «×N» на поле, волна посадки и
   повтор закона RX10 читают одно число (реестр DD).
   Bespoke-СЧЁТ без вопроса (P69): ОДНА приватная функция счёта карты читается `bespokePlay`, `countedPlayForecast` и
   `cardPlayPreview` (форма Interplanetary Trade); счёт НАБОРАМИ меток («за каждую пару Земли и Венеры») — термин `set`
   базиса (`actionPreviews.tagSetBasis`): стороны со своими числами, джокер на стороне, своя метка карты (`self`) — реестр CV.
3. **Действие** (`ActivePreludeCard` — Floating Trade Hub, World Government Advisor; активные проекты; Board of Directors —
   BESPOKE с ко-локированными хуками: решение ПОСЛЕ вскрытия и цена декларативным `action` не выражаются) — `actionPreview` + `actionUnavailableReason`; у Venus Orbital Survey снять строку
   `SAFE_WITHOUT_INFORMATION` в `tests/cards/actionCaption.spec.ts`; правило длиннее бюджета подписи браузера действий —
   курированный `action-short` (P68). Bespoke-действие со СБРОСОМ (P68): `discardOptions()` один на живой промпт и
   шаг превью, `min` — одно число; выплата склада — волной семейства сброса, сцена ухода — даром (реестр CS). Bespoke-действие-ВЫБОР (P73): превью в
   порядке ЖИВОГО `OrOptions` (ветка называет свою печатную строку `renderKey`), источник — общий шаг с `cause`
   (`RemoveResourcesFromCard` `source: 'self'`), недоступный вариант показан с причиной, роль держателя объявлена рядом с
   действием (`holderActionGood`) — реестр DC.
4. **Живой хук** (`onCardPlayed` — Soil Bacteria, Ecotec, Spire, Palladin Shipping, Sagitta; `onColonyAddedByAnyPlayer` — Colony
   Trade Hub; `onProductionGain` — Suitable Infrastructure; `onResourceAdded` — Main Belt Asteroids;
   `onIncreaseTerraformRating` — Terraforming Deal; `onGlobalParameterIncrease` — Venus Contract) — ДВОЙНИК ПРОГНОЗА
   обязателен (`effectForecastCoverage` / `effectForecastParity` падают с именем карты).
5. **ПОЛИТИЧЕСКАЯ** — чтения через фасад `game.politics` (никакого `Turmoil.getTurmoil`), делегаты через
   `placeDelegates` (Redux — `PlaceDelegatesOnResolution`), требование партии = «правит ИЛИ ≥2 своих делегатов»,
   Кельвинисты = Зелёные (`normalizeParty`), требование председательства — `ChairmanRequirement`; маркер
   `politics: 'redux'` в манифесте; спек карты — таблица Redux через `tests/parliament/parliamentArrange.ts`.
   Классическая партия в требовании (P75 — Кельвинисты): сервер держит `KELVINISTS`, как апстрим (апстримный спек на
   классике — байт в байт), а премиум-читатели — плашка лица, генератор «Информации», описание — идут через
   `normalizeReduxParty` (реестр CW). ⚠ Свежий стол Redux открывается с Зелёными у власти — «запертый» стол
   Зелёных в спеке / фикстуре сажает закон другой партии.
   Грант делегатов розыгрыша без двери поля (P83 — «2 делегата на одну резолюцию») — шаг того же флоу: голосование
   встаёт внутри руки («КАРТЫ В РУКЕ › <карта> › ГОЛОСОВАНИЕ»), флоу должен шаг до ответа — даром, общей веткой шелла
   (`workspaceHostForStep`; реестр CX), стенд пинит порядок «РТ-жетон → ответ партии → дверь».
   Карта ВЛИЯНИЯ (P71 — «+1 влияния», класс T05: даритель по имени через фасад) проверяется в ИТОГАХ ЗАСЕДАНИЯ — единственном
   месте, где её +1 видно в деле: разбор «ПОДРОБНОСТИ ВЫПЛАТ» читает влияние места из СНИМКА сервера с составом по
   именам (`summary.influenceRead`) и что оно значило для закона (реестр CY).
   Печать «разместите N делегатов в 1 партии» под Redux — «добавьте N делегатов на ОДНУ резолюцию области голосования»
   (принятая резолюция в предложении не стоит — `PlaceDelegatesOnResolution`); сноска классики на лице («*») снимается,
   если скан её не печатает (P72). Грант розыгрыша N > 1 — ОДНА фраза: композер прогревает Парламент, шаг встаёт из
   рассказанной посадки, кубики со сдвигом (реестр CZ).
   `manyParties` под Redux («можно на разные партии») — СЕРИЯ грантов по одному с маркером `votePrompt.series {index, of}`;

   каждый подсчёт меток играбельной карты Учёных (P85 — на 1 M€ больше видимых меток; база называет долю `wild`).
6. **Корпорация** — MarsBot уже играет собственных двойников (Spire — `tests/automa/MarsBotSpire.spec.ts`); человеческая

   Briber — по апстриму, вторая корпорация, стол без механики, бот не берёт двойника); ② правило получает ИМЕНОВАННУЮ
