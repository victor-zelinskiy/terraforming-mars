# RX20 · Skyscrapers (Марс вперёд) — СТОПКА городов: высота на клетке, ярус как третий случай посадки, тайл ПО ПОРОГУ

**Статус: СДАНА 2026-09-25.** Первая карта, которая меняет МОДЕЛЬ ДОСКИ: «победитель голосования и
каждый игрок с влиянием не менее 2 получают тайл города и обязаны разместить его поверх одного из
своих городов на Марсе; каждый город в стопке приносит ПО за соседние озеленения отдельно; без города
на Марсе — ничего». Печатное задание председателя — 2 тайла города на Марсе.

Четыре новых вещи в одной карте, каждая — член семейства, а не параллельный путь:

| Что ново | Как сделано | Где |
| --- | --- | --- |
| СТОПКА городов | ОДНО поле клетки `Space.stackHeight` (отсутствует = 1, пишется от 2), тайл на клетке один; ОДНА функция величины `MarsBoard.countCities` (сумма ярусов) и все потребители-величины на ней; предикаты читают клетку | блок A |
| Ярус как размещение | `Game.addTile(player, space, tile, {stacking: true})` — клетка не платит второй раз (ни печатный бонус, ни соседство с океаном, ни Ares), триггеры «город размещён» и партийные пассивы срабатывают, повтор бонусов (RX10) не повторяет | блок A |
| Ярус на экране | нижние ярусы под верхним тайлом внутри гекса (шаг 3,5 px, вся стопка в масштабе 0,86 — гекс не растёт), счётчик «×N», кубик владельца на верхнем ярусе; осмотр клетки «Стопка городов ×N» + ряд ПО на ярус; разбор счёта — строка на ярус | блок B |
| Посадка яруса | ТРЕТИЙ законный случай арма посадки (`stacking`), хореография крана: заход → загрузка основания (счётчик «×1») → вертикальный спуск → контакт (счётчик тикает «×2» в тот же синхронный ход, что красится ярус) → осадка | блок C |
| Тайл ПО ПОРОГУ | объявление `tileGrant` (тайл · куда · получатели), новое семейство `tile-grant`, вид исхода `city`, счёт назначений `marsCities`, ОДНА модель чтения `tileGrantModel` для голосования, осмотра, ленты, итогов и стенда | блоки A, D |

## 1. Стопка — высота на клетке, величина в одном месте

`Space.stackHeight?: number` — единственное новое состояние. Отсутствие поля = один город (старые
сохранения читаются без миграции), сериализуется только от 2 (`Board.serialize`), читается только
вместе с тайлом (`deserializeSpace`). Никакого массива тайлов, никакой второй структуры: стопка — это
ОДИН тайл города с высотой.

**Две категории потребителей, разведённые намеренно:**

- **ВЕЛИЧИНА** («сколько городов») — `MarsBoard.countCities(player?, 'everywhere' | 'onmars' | 'offmars')`
  = сумма ярусов. На неё переведены все места, где число городов было смыслом: Mayor, Metropolist,
  Constructor, Landlord, Urbanist (озеленения × ярусы), `Counter` (`countCityTiers` по соседям),
  `CitiesRequirement`, Vermin, Hospitals, StarVegas, NewHolland (`onmars`), StrongSociety, Election,
  `citiesCount` модели игрока. Общая арифметика — `src/server/boards/cityStack.ts` (`tiersOf`,
  `cityTiersOf`, `countCityTiers`) — файл без зависимостей, потому что `Counter → MarsBoard → Board`
  давал цикл импорта.
- **ПРЕДИКАТЫ** («есть ли город рядом», «эта клетка — город») читают клетку и не умножаются на высоту:
  соседство озеленения с городом, кандидаты стандартного города, Ares-соседство — одна клетка = один
  сосед.

**ПО за каждый ярус отдельно** — `calculateVictoryPoints` идёт по ярусам: строка `CityVpDetail`
`{spaceId, points, tier, tiers}` на ярус (карта-источник только у первого), разбор счёта печатает
«Город · ярус k из N» (`scoreExplorerModel.buildCityFacts`), «Городов: N» считает ярусы.

## 2. Ярус — размещение, которое не платит второй раз

`Game.addTile(player, space, tile, {stacking})`: ветка `stacking` проверяет `MarsBoard.canStackCity`
(тайл города, не колония, владелец — игрок) и тип CITY, минует стоимость Ares, заявку на землю и
`canCover`, кладёт ярус через `simpleAddCityTier` (тот же объект тайла, `stackHeight = tiersOf + 1`,
журнал «строит тайл города поверх своего города — стопка из N», `events.recordTilePlaced`), вызывает
`ParliamentHandler.onTileAdded` и `onTilePlaced(…, {coveringExistingTile: true, stacked: true})` ВМЕСТО
`grantPlacementBonuses`, рассылает карточные `onTilePlaced` и корпорации автоматы, пропускает бонус
Ares за опасную зону. `IGame.addCityTier(player, space)` — короткая форма. Development Craze
(`repeatPlacementBonuses`) возвращает `undefined` при `placement.stacked` — повторять нечего.

Что ОТВЕЧАЕТ на «город размещён» — отвечает и на ярус: Rover Construction платит 2 M€, правящая «Марс
вперёд» даёт сталь и карту (в e2e это видно: сталь +1, карта партии на экране). Предпосылка честна —
ярус ЕСТЬ размещение тайла города, только без клеточных бонусов.

**Тип размещения `city-tier`** (`PlacementType`, `BoardPlacementKind`): кандидаты =
`getAvailableSpacesForCityTier(player)` (свои города на Марсе), причина отказа `not-your-city`
(«Не один из ваших городов на Марсе»), досье клетки: нет фактов стоимости, правило «Без бонуса
размещения» (`tier-no-bonus`), превью `place-city-tier` «Стопка городов: 1 → 2 яруса» с ПО от
`g × tiers` до `g × (tiers + 1)`, партийный факт «Марс вперёд» только там, где триггеры тайла
срабатывают, `withHypotheticalTile` наращивает стопку в гипотезе.

## 3. Тайл ПО ПОРОГУ — объявление, счёт назначений, одна модель чтения

```ts
tileGrant: {tile: 'city', placement: 'own-city', recipients: {winner: true, influenceAtLeast: 2}}
```

- `tileGrantEligibility(grant, {winner, influence})` → `'winner' | 'influence' | 'none'` — ОДИН предикат,
  которым платит шаг и который читает клиент; звезда безусловна (победитель ниже линии получает).
- `tileGrantStepKey(grant)` = `city-tier` — ключ шага и записи выводится из объявления, клиент ищет запись
  игрока по нему (`tileGrantOutcomeOf`), а не по позиции; реакция партии под тем же ключом — не запись.
- `tileGrantCountId(grant)` = `marsCities` — СЧЁТ НАЗНАЧЕНИЙ: седьмой вид счёта (`BoardCountedTile
  'marsCity'`), клетка считается ОДИН раз какой бы высоты ни была стопка; сервер отдаёт в модель места
  ровно список кандидатов шага (`getAvailableSpacesForCityTier`), стенд считает свои клетки тем же
  предикатом `spaceCountVerdict` (паритет пришпилен корпусом досок в `Skyscrapers.spec`).
- Причины пропусков — данные рядом с объявлением: `TILE_GRANT_NOT_ELIGIBLE_REASON`,
  `TILE_GRANT_NO_DESTINATION_REASON`; ЗАПИСЬ `{kind: 'city', influence, space, stackHeight}` или пропуск с
  причиной; адрес `city` (поверхность доска, стадия `board`, чтение `tile-grant`).

**`tileGrantModel.ts`** — двойник `winnerRewardModel`, четыре момента: `reference` (правило одно),
`conditional` (на голосовании: «Ваш при влиянии N — и без победы» / «Только если победите: влияние N
меньше 2», назначения «ваших городов на Марсе: N» или честное «Городов на Марсе нет — ярус некуда
поставить»), `pending` (фаза решает: «Размещаете вы — победитель голосования» / «— влияние N» /
«Не ваш: …»), `applied` (запись: «Размещено вами — …» + «стопка из N», или пропуск с причиной сервера,
с поколением из завершённой фазы). Одна графика — `ConsoleTileGrant.vue` (`.con-tgrant`: тайл города →
город-основание, назначения либо «×N»), варианты `block` / `chip` / `inline`.

Кто читает модель: панель голосования (`voteReadingOf().grant` — чтение «для вас» без числа,
`voteInfoBudget` считает его одним чтением), полноэкранный осмотр (чип бара + строка «Для вас» +
правило «Каждый город в стопке отдельно приносит ПО…» под эффектом), лента заседания (чип `grant` в
строке НАГРАДА, только для яруса, который должен или лёг, — пропущенное место читает свой чип
пропуска), панель итогов (часть `city`: глиф города + «×2»), стенд (семейство `tile-grant`: ячейки
через общий предикат, записи `grantOutcomes`, контроль «Города на Марсе»). Квитанция: ярус —
такой же тайл доски, как тайл победителя: `detectNewViewerTile` видит `city`, заседание по возврату
читает страницу награды до итогов.

## 4. Сцена посадки — см. `docs/claude/console/tile-replacement.md`

Арм с `stacking` (`ConsoleBoardInput.saveData` по `placementType === 'city-tier'`), `verifyPlacement`
принимает рост стопки ровно на 1 на той же клетке (недекларированный рост отвергается),
`cityStackScene` — два реактивных флага, которые клетка рисует классами (`--stack-loading`,
`--stack-contact`), контакт — один синхронный ход (`stackContact` + `applySpacePreview`). Замер
e2e: заход по x, спуск с x зафиксированным и y монотонным, «×2» в том же сэмпле, что высота 2, пыль
на контакте.

## 6. Что это оставляет следующим картам

- **Migration Funding** (2 M€ за город на Марсе): величина = `countCities(player, 'onmars')`, стопка
  считается отдельно по построению; счётный член — `marsCities` уже есть, но он считает КЛЕТКИ (назначения);
  для «ярусов на Марсе» нужен вид счёта по ярусам — одна строка в `resolutionCountKind`.
- **Mars First Budget** («каждый размещает город»): `tileGrant` с `placement: 'any-legal'` — второй
  вариант объявления, тот же предикат получателей (`influenceAtLeast: 0`), та же модель чтения.
- Второй тайл по порогу (озеленение, океан) — `tile` в объявлении и `tileGrantLabelKey`; сцена — обычная.
