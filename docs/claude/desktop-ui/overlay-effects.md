## Effects overlay (the "ЭФФЕКТЫ" overlay — passive/ongoing effects)

The bottom-bar **ЭФФЕКТЫ** counter button (`activeOverlay === 'effects'`, between Played and Victory Points) opens `src/client/components/effects/EffectsOverlay.vue` — a premium MASTER-DETAIL panel of the displayed player's PASSIVE/ongoing effects (blue cards + corporations): a grid of effect blocks on the left, a per-effect "what it did this game" summary on the right. Active blue-card ACTIONS are a SEPARATE overlay (ДЕЙСТВИЯ) and are deliberately excluded here. Badge = effect-block count with the shared `AnimatedMetricValue` delta-chip (`metricKey="bar.effects"`, `variant="misc"`). Icon: `BarButtonIcon name="effects"` (a 4-point sparkle, distinct from the VP 5-point star).

**100% client-derived, NO server change** (mirrors the colony-manifest precedent). The printed passive-effect GRAPHIC already lives in each card's `renderData`, which the client has via the static manifest (`getCard(name).metadata.renderData`) even though the live `CardModel` tableau doesn't carry it. So `src/client/components/effects/effectExtraction.ts` walks the displayed player's `tableau` (CardModel names + `isDisabled`), looks each card up, and filters its renderData to the passive-effect nodes:
- **What's an effect node:** `is:'effect'` at root level, OR the `is:'effect'` node(s) NESTED inside a `corp-box-effect` / `corp-box-effect-action` container (`is:'corp-box-action'` is skipped wholesale). Type guards from `@/common/cards/render/Types`.
- **effect vs action** (both render as `is:'effect'`!): excluded via `isPassiveEffectNode` — the DSL bakes an `'Effect: '` / `'Action: '` prefix into the node's description (last string of `rows[2]`), and the delimiter symbol is `:` (`CardRenderSymbolType.COLON`) for effects vs `->` (`ARROW`) for actions. Verified against all 995 cards: **77 in-scope cards → 83 effect blocks, 0 action leaks** (the desc-prefix check runs FIRST, so an `effect()` node that happens to contain an arrow SYMBOL in its content row — e.g. Supercapacitors' crossed energy→heat — is still classified as a passive effect).
- **Edge cases** (`EFFECT_OVERRIDES` map, `Partial<Record<CardName, {exclude?, renderWhole?, text?}>>`): a few cards encode the passive rule outside a clean `effect()` box. `renderWhole: true` renders the card's ENTIRE renderData root (the raw symbol rows ARE the effect graphic, via `CardRenderData`) + its description — used for `OLYMPUS_CONFERENCE` (drawn as raw root rows: science tag : science / OR / −science +card, no `effect()` node). `text:` shows a text-only block. `descFromMeta: true` appends `metadata.description` under a `renderWhole` graphic (for cards whose effect text isn't in the render — Olympus). `exclude:` drops a card. The other bespoke-render cards are now covered: `PROTECTED_HABITATS` + `NEPTUNIAN_POWER_CONSULTANTS` via `renderWhole` (the whole renderData IS the effect; Neptunian's effect text is already in its render so no `descFromMeta`). `SUPERCAPACITORS` needs NO override anymore — instead of a `text:` descriptor, its card was given a real `effect()` node (`eb.startEffect.energy(1).arrow(Size.MEDIUM, true).heat(1)` → energy → heat with a **crossed-out arrow** meaning "conversion is optional"; the immediate M€-production box stays a separate root row), so the generic scan extracts it like any normal effect card and the SAME graphic renders on the card AND in the overlay. The crossed arrow is a reusable render primitive: `ICardRenderSymbol.cancelled?: true` + `CardRenderSymbol.arrow(size, cancelled)` + the `b.arrow(size, cancelled)` builder overload; client-side `CardRenderSymbolComponent` adds `.card-symbol-cancelled`, and `cards_v2.less` draws a red diagonal line via `::after` (scoped under `.card-container`, so it works in the effect block too). Any future card can draw a struck-through arrow the same way. Per the brief, per-card `if`/override entries here are the SANCTIONED way to dab edge cases; the generic scan covers everything else. (One generic extraction fix beyond overrides: an effect drawn with its TRIGGER on a ROOT row + an empty effect cause — `eb.empty().startEffect`, e.g. Viral Vectors' plant/microbe/animal trigger — has that root row SPLICED in as the effect's cause by `collectEffectNodes`/`withSplicedCause`, so the overlay shows the FULL trigger : result, not a truncated fragment.) `playerEffects(tableau)` orders **corporation effects first**, then cards in tableau order; one card with several `effect()` calls → several blocks. Each `EffectEntry`/group effect carries `effectNode` (→ `CardRenderEffectBoxComponent`) OR `renderRoot` (→ `CardRenderData` + a `.effect-item__desc` description) OR `text` (text-only); `EffectBlock` picks the first present.

**Grouped by SOURCE, but ONE EFFECT = ONE BLOCK** (`playerEffectGroups` → `EffectGroup`, rendered by `EffectBlock.vue`): each source is a `.effect-group` — a LIGHT wrapper, never one merged block. The source name appears ONCE in a slim `.effect-group__label` (accent + name via `v-i18n` + corp/card type chip), and the source's effects sit under a thin left accent bracket (`.effect-group__items`); The group is ONE CARD FRAME (mirrors the Actions overlay's `.action-group`): a slim `.effect-group__label` header (accent + name + live resource badge `.effect-group__res` + type) over `.effect-group__items` — a column of separately-selectable ROW BUTTONS, one per effect (`.effect-item`, the row twin of `.compact-action`). Each effect: `EffectEntry.key` = `<cardName>#<i>`; hover previews it, click PINS it (selection is **per EFFECT, not per card**), the chosen row gets the bright ring (`.effect-item--selected`). A multi-effect card (the 6 in-scope: Carbon Nanosystems, Pharmacy Union, Splice, Advanced Alloys, PolderTech Dutch, Solar Logistics) reads as one cohesive card whose effects are distinct buttons — NO `i/N` clutter on the grid (the frame conveys the grouping; the `i/N` ordinal survives only in the DETAILS header). The grid card is **ICONS-ONLY** (the prose is hidden — see the render fix); the fit engine lays out GROUPS, selection is per EFFECT; the badge/header count is the FLAT effect total (`playerEffects.length`).

**THE RENDER FIX (icons + text colour + localization)** — the card render icons (`.card-resource`, tags, tiles) are CSS-scoped under `.card-container` (the `<Card>` root; the card FRAME is on the SIBLING class `.filterDiv`, not `.card-container` itself). Rendering an effect node OUTSIDE that scope shows the text but NOT the sprite icons. So each effect's `CardRenderEffectBoxComponent :effectData` is wrapped in a bare `<div class="card-container" v-i18n>` (no `.filterDiv`): the `.card-container` makes the descendant icon CSS match (sprites render exactly as on the card), and the `v-i18n` localizes plate text (e.g. "СТАНДАРТНЫЕ ПРОЕКТЫ") — mirroring how `Card.vue` wraps `.card-content-wrapper` in `v-i18n` (the description has its OWN `v-i18n` in `CardDescription`, so it localizes either way; plates rely on the ancestor). `.effect-item__render.card-container` then strips the legacy card margin/width, `zoom: 1.2`s for legibility, and forces non-plate `.card-text-*` to LIGHT for the dark overlay (gold PLATES keep their own dark text). **The baked-in prose description is HIDDEN (`.effect-item__render .card-description { display:none }`) so the graphic is ICONS-ONLY** — on the grid card AND on the details rule graphic; the prose lives ONLY in the details panel's dedicated «Описание» block (a multi-effect card never duplicates text). Text-override entries render `.effect-item__text` instead. Hover/click are EMITTED up as the EFFECT KEY — the overlay is a **MASTER-DETAIL** surface (see below): hovering an effect PREVIEWS it (`@namehover` → a transient `hoverKey`), clicking PINS it (`@open` → `setEffectSelection`); the source-card preview + the `CardZoomModal` fullscreen live INSIDE the details panel (the old shared `CardPreviewPopover` over the grid was REMOVED — it could cover the blocks, mirroring the Actions-overlay decision). The selected EFFECT (not the whole card) gets a ring (`.effect-item--selected`).

**MASTER-DETAIL "what this effect did THIS GAME" (the upgrade — `EffectDetailsPanel.vue`).** `EffectsOverlay.vue` is a centred dark-glass panel (`.effects-board-overlay`, L-corner ticks) that MIRRORS the Actions overlay's master-detail layout: LEFT = the effect-block grid (`.effects-board__master`, CSS multi-column `--effects-master-cols` + `break-inside: avoid` so variable-height blocks pack without gaps), RIGHT = a static `EffectDetailsPanel` (`.effects-board__detail-cell` relative + `.effects-board__detail` absolute inset:0, so its variable content never resizes the overlay — the split height is pre-computed by the hidden `.effects-board__measure` probe → `--effects-detail-min-h`, exactly like Actions). The **adaptive fit engine** (`fit()` + ResizeObserver) reserves the fixed `DETAIL_W` (380) detail column and sets `--effects-overlay-width` + `--effects-master-cols` (1–`MAX_COLS`=3) + `--detail-width` from the GROUP count + viewport (`MIN_W` 640, `FIT_MAX_W` 1680); under `max-width:1080px` the split stacks. The header's READ-ONLY player chip + seat-switch-by-clicking-a-panel + Esc-closes + `handleOutsideOverlayClick` exemption + journal mutual-exclusion are unchanged.

The details panel is **per EFFECT** (`:entry` = the selected `EffectEntry`, NOT the group) and turns "I read the rule" into "I see how the effect actually PERFORMED this game". For the hovered/pinned effect it shows: a mini-context header (type chip + name + an `i/N` ordinal on a multi-effect card + ⤢ fullscreen + a live card-resource chip `card.resources`), the effect's icons-only graphic, a dedicated **«Описание»** block with THAT effect's own full text (the prose stripped from the graphic), and a **per-game summary** — trigger count, impact lines (M€ saved / resources / card-resources / production / TR / cards drawn, each `iconClassFor`-iconed), the live **Current** value, and **Last triggered: Gen N** — or, when nothing measurable happened, a **thematic NOTE** (never a dead empty state). **On-play gains are EXCLUDED — only PASSIVE effects count.** `EventRecorder.record` now tags every impact produced under a passive-effect scope (`ctx.kind === 'effect'`) with `'passive-effect'`, and `recordDiscount` carries it too; `effectOverlayStats` filters to ONLY `'passive-effect'`-tagged events. So a card's immediate on-play `behavior` bonus (recorded under the play's `'action'` scope — e.g. Solar Logistics' `b.titanium(2)` on play) NO LONGER leaks onto its passive effects (the bug where every Solar Logistics effect showed a stray "+2 titanium"). **Resource-as-payment is recorded** (`EventRecorder.recordResourceAsPayment`, called from `Player.pay` per spent card resource via `CARD_FOR_SPENDABLE_RESOURCE` + `DEFAULT_PAYMENT_VALUES`): spending Psychrophiles microbes / Carbon Nanosystems graphene / Kuiper asteroids as M€ emits a `'passive-effect'`+`'resource-payment'` event with `megacreditsSaved` (value) + `cardResourcesSpentAsPayment` (count) — aggregated into `SourceStats.paymentResources` (kept SEPARATE from `cardResources` accumulation). A **`'payment'` category** (`signature.valueAsPayment` — a "card-resource = N M€" result) shows what the effect DID: «Эквивалент M€» (value) + «Использовано» (spent) + «Текущее» (available), NEVER the accumulation «Добавлено» (which belongs to the accumulator effect / the card's action) — fixing Psychrophiles + Carbon Nanosystems' payment effect reading as "accumulation".

**Per-effect stats (signature filtering).** The event stream attributes to the source CARD (not a single effect), but the details are STILL scoped to the SELECTED effect: `effectExtraction.effectSignature(node)` extracts each effect's impact signature (`{icons, discount, valueModifier, valueAsPayment}` from its render RESULT row — the `EffectSignature` type lives in the pure `effectSummary` so the server test runner stays manifest-free) onto `EffectEntry.signature`; the overlay passes the selected effect's `signature` + the union of its SIBLINGS' result icons (`siblingIcons`, via `siblingIconsFor`) to the panel, and `effectSummary.defaultViewModel` — when the card has >1 effect — HIDES any stat line / current-value whose icon belongs ONLY to a sibling (in `siblingIcons` but not this effect's `signature.icons`; a metric in BOTH or in NEITHER is kept, so it never wrongly hides this effect's own / an ambiguous line) and derives the per-effect headline via `classifyEffectSignature` (reading the effect, not the card aggregate). So a DISJOINT multi-effect card is genuinely per-effect — PolderTech Dutch shows energy on its ocean→energy effect and plants on its greenery→plant effect; Solar Logistics shows «Сэкономлено» on its discount effect and «Взято карт» on its draw effect. The card-level firing COUNT + last-trigger (which the stream can't attribute) are shown ONLY for a single-effect card; a multi-effect card hides them and captions «Часть статистики считается на уровне всей карты» (`vm.cardScoped`). `EffectSummaryContext` carries `effectIndex`/`effectCount`/`signature`/`siblingIcons`.

**Data feed = a bounded route + the existing aggregator (no model bloat).** `GET /api/game/effect-stats?id=&color=` (`src/server/routes/ApiGameEffectStats.ts`, registered in `requestProcessor.ts` + `paths.API_GAME_EFFECT_STATS`) returns `effectOverlayStats(game.events.events, color)` — the WHOLE-GAME per-source aggregate from `src/common/events/aggregate.ts` (REUSED, not rebuilt). `id` = the viewer's own participant id (auth, like journal-events); `color` picks WHOSE effects (open economy info, so opponents' stats are fetchable). The overlay fetches **stale-while-revalidate**: it caches by colour in `effectsOverlayState.ts` (module-reactive → survives the playerkey remount) but ALWAYS refetches on open / seat change — events accumulate WITHIN a generation, so a generation-keyed cache would show a stale "not used yet" right after the player spends a resource / triggers an effect; cached data shows instantly, the skeleton appears ONLY on a cold cache, and the fresh stats update in place. Passing `:viewerId="playerView.id"` + `:statsCacheKey="String(game.generation)"`. `viewerId===''` (the playground) / no `fetch` (JSDOM) → the panel still shows the base rule + thematic notes (no per-game numbers). **The `resource-payment` events are EXCLUDED from the JOURNAL route** (`ApiGameJournalEvents` filters them out) — they're overlay-analytics only; the journal's "Оплата" row already shows the actual spend, so without the filter a card resource paid (Carbon Nanosystems graphene) would duplicate as a misleading "Углеродные наносистемы → −12 M€" row. The overlay's own route (`/api/game/effect-stats`) still includes them. **Known graceful gap:** `EventRecorder` has no `vp-granted` / `global-parameter-changed` path, so `stat.vp` / `stat.globalParameterSteps` are effectively always empty and those lines simply don't appear — do NOT instrument them as part of effect work.

**Each effect is summarised INDIVIDUALLY — the PURE view-model `effectSummary.ts` (extended, unit-tested), NOT one generic template.** `getEffectSummary(stat, ctx)` resolves: (1) a bespoke PROVIDER for the few cards needing custom LINE construction (`PHARMACY_UNION_PROVIDER` → diseases + TR led, headline "Corporation ability"); else (2) the category-aware default — `classifyEffect(ctx, stat)` buckets the effect (`discount` / `resourceAccumulation` / `passiveTr` / `passiveProduction` / `trigger` / `ruleChange` / `corporation`) → a `CATEGORY_HEADLINE` + line reordering (a discount leads with Saved, a resource card with Added, …) + a per-card `CARD_HEADLINE` override ("Microbes farmed", "Animals raised", …); and (3) a NOTE that is ALWAYS available when empty — `EFFECT_SUMMARY_NOTES[card]` (curated thematic notes for the rule-changers: Protected Habitats / Adaptation Technology / Standard Technology / Media Group / Olympus Conference / Supercapacitors / Neptunian Power Consultants) else `CATEGORY_FALLBACK_NOTE[category]`. So EVERY effect resolves to a bespoke provider → a category summary → a thematic note — never a bare card hover or dead state. To add a bespoke summary for a new card: add a `CARD_HEADLINE` / `EFFECT_SUMMARY_NOTES` entry or a provider — never special-case in the UI. The `EffectSummaryContext` carries `cardResourceType` + `currentCardResource` (threaded from the live `CardModel`) for the Current line + classification. **Coverage is regression-guarded** like the other subsystems: `tests/client/components/effects/effectSummaryCoverage.spec.ts` enumerates `allScopeEffectCardNames()` and FAILS (with the card list) if any in-scope effect resolves to a dead summary — the machine-checkable audit.

**Economic special-handlers + the "framed by capability, not data" empty-note fix (event/stat foundation — see `docs/EVENT_STAT_FOUNDATION.md`).** Two effect families that read as `ruleChange` ("Пассивное правило") are now genuinely tracked, and the over-shown generic fallback is fixed at its root. (1) **steel/titanium VALUE modifiers** (Advanced Alloys / Rego Plastics / Mercurian Alloys / PhoboLog): `Player.pay()` → `recordPaymentValueBonus()` scans the tableau for declarative `behavior.steelValue`/`titanumValue` cards and records the EXACT extra M€ value each contributed (`spent × +N`), attributed to the owning card — `EventImpact.paymentValueBonus` (tag `payment-bonus`), aggregated into `SourceStats.paymentValueBonus` → a `paymentValueBonus` summary category (headline "Payment value bonus" → extra value + spent-under-effect, **confidence `exact`**). (2) **Trading Colony / Trade Envoys track bump** (`behavior.colonies.tradeOffset`): `Colony.recordTradeTrackBonus()` (called from BOTH `Colony.trade` auto-path AND `IncreaseColonyTrack` choice-path) records the track steps + the EXACT extra trade reward (`quantity[after]−quantity[before]`) — `EventImpact.colonyTrackAdvanced` (tag `colony-track`) → a `colonyTrade` category (steps + extra reward + **per-colony `breakdown`**, **confidence `partial`** — the reward's M€ value is deliberately NOT estimated). Both tags are analytics-only (excluded from `ApiGameJournalEvents`, like `resource-payment`). **ROOT-CAUSE FIX:** the empty-state note is now framed by `emptyCategory(ctx)` — the effect's render SIGNATURE / special-card kind (`PAYMENT_VALUE_MODIFIER_CARDS` / `COLONY_TRADE_OFFSET_CARDS`), NOT the (empty) accumulated data — so an unfired trigger reads "hasn't triggered yet" and a discount "applies when you play a matching card"; the bare "passive rule" note + `ruleOnly` confidence is now reserved for effects with NO measurable output. The `EffectSummaryViewModel` gained `confidence` (`exact`/`partial`/`ruleOnly`, a chip in `EffectDetailsPanel`) + `breakdown`. The client special-card SETS drive only the pre-contribution note (the server records every such card generically); widen them when an expansion's value-modifier / trade-offset cards enter scope. **Iteration 2 closed the documented gaps:** (a) **trade DISCOUNT** (Cryo-Sleep / Rim Freighters `behavior.colonies.tradeDiscount`) is now recorded — the 3 `Colonies.ts` traders call `recordTradeDiscountSaving()` → `EventImpact.tradeDiscountSaved` (tag `trade-discount`) → `SourceStats.tradeDiscount` → a `tradeDiscount` summary category (Saved-on-trades per resource + per-colony breakdown, confidence `partial`); `TRADE_DISCOUNT_CARDS` frames the empty note. (b) **`global-parameter-changed`** is now emitted at all 4 `Game.ts` raise sites (`recordGlobalParameterChange`) attributed to the active scope source — the `EventImpact.globalParameter` field + `globalParameterSteps` aggregation already existed; tag `global-parameter` (analytics-only). (c) **`vp-granted` is intentionally NOT a stream event** — there is no mid-game VP mutation in the engine (VP is endgame-computed; `VictoryPointsOverlay` has the breakdown), so emitting it would invent data.
