## BoardInformation — premium board explainability + unified placement

The fork has a single **explainability layer for the Mars board**: the board "explains itself" so the player always knows what's on a cell, why it's (un)available, what placing there will do, **who** receives each bonus, what's immediate vs endgame, and whether a pending placement can still be cancelled. It is NOT a separate "analysis mode" — it lives on the three surfaces where decisions happen: **hover**, **active placement**, and the **confirm modal** (+ the journal already confirms it via the existing event stream). Built to accept future **Ares** facts (adjacency bonuses, hazard penalties, owner income, ocean upgrades) WITHOUT a new UX — Ares rules are NOT implemented, only the model + extension point.

**The fact vocabulary (shared) — `src/common/boards/BoardInformationFacts.ts`.** A `BoardFact` is ONE explainable statement: `category` / `timing` (`immediate`/`endgame`/`cost`/`rule`/`warning`/…) / `severity` / **`recipient`** (`current-player` / `player` / `tile-owner` / `neutral` / `nobody` — the load-bearing field) / `title`+`description` (English i18n keys) / `delta` (a chip — shape-compatible with `ActionEffect`, so `ActionEffectChip` renders it) / `vp:{from,to}`. `BoardCellInfo` = hover (status + facts); `BoardPlacementPreview` = the consequences of placing `kind` on a cell, pre-grouped into `costFacts`/`immediateFacts`/`recipientFacts`/`futureScoringFacts`/`warningFacts`/`ruleFacts`. The pure `groupFactsByRecipient(facts, viewerColor)` is the ONE place the "who gets what" ordering lives (current player first, then others, then neutral; collapses the viewer's own colour into `current-player`). Category union already names the Ares kinds (`ares-adjacency-bonus`/`tile-owner-benefit`/`hazard-penalty`/`hazard-cleanup`/`ocean-upgrade`) — declared, not produced.

**The engine (server, read-only) — `src/server/boards/BoardInformationEngine.ts`.** `boardCellInfo(player, space)` (hover) + `boardCellPreview(player, space, kind)` (placement). It NEVER mutates state and NEVER re-implements rules — it reuses the REAL sources: `MarsBoard.oceanAdjacencyBonus` (the +N M€ rule, now the single source of truth — `Game.grantPlacementBonuses` calls the SAME method), the printed `space.bonus` + the covering-tile rule, the `calculateVictoryPoints` adjacency predicates for city/greenery endgame VP (recipient = the CITY OWNER, possibly an opponent), `MarsBoard.placementCostInfo` (wraps `computeAdditionalCosts`/`spaceCosts`/`canAfford`/`placementMegacreditDeficit`), and `MarsBoard.illegalReasonFor`. PURITY is test-guarded (`tests/boards/BoardInformationEngine.spec.ts` snapshots game state before/after). **NEVER call `grantPlacementBonuses`/`addTile`/`game.events.*`/`game.defer` from it.** `aresAdjacencyFacts()` is the documented Ares extension point (returns `[]` today; reads neighbour `space.adjacency` GENERICALLY when Ares lands — never hardcode "special tile = source").

**Delivery — bounded read-only endpoint `GET /api/game/board-cell-preview?id=&space=&[color]&[kind]`** (`src/server/routes/ApiGameBoardCellPreview.ts`, mirrors `ApiGameEffectStats`/`ApiGameDeltaPreview`; path constant + requestProcessor registration). No `kind` → `BoardCellInfo`; with `kind` → `BoardPlacementPreview`. `color` = whose perspective (board is open info; spectators allowed). NOT attached to `SelectSpaceModel` (which is in every poll) — facts are fetched lazily per cell.

**Client surfaces:**
- **Hover inspector** — `src/client/components/board/boardInfoState.ts` (module-reactive fetch+cache, configured from `PlayerHome.syncBoardInfo` with the viewer id + displayed player's colour + players) drives `BoardCellInfoPopover.vue` (mounted in `Board.vue`, teleported, positioned at the cell). `Board.vue`'s existing hex-wide hover delegation PARTITIONS: a cell with a curated `getSpecialCellInfo` entry keeps its lore overlay (`SpecialCellInfoOverlay`); EVERY other cell gets the general inspector. Deflection Zone / reserved / restricted / volcanic facts come from the engine (honest, code-based — the Deflection Zone is just land-equivalent + fixed position on Hollandia, NOT invented lore).
- **Active placement preview** — `SelectSpace.vue`'s board hover now branches: an illegal cell → the existing `PlacementReasonPopover` (one unavailability system); a LEGAL cell → `BoardPlacementPreviewPopover.vue` (fetches `boardCellPreview(kind)`, where `kind` rides the new `SelectSpaceModel.placementType` set by `createMarsSelectSpace`). The greenery-next-to-opponent-city case shows the opponent's endgame VP in a separate "Получат другие игроки" block.
- **Confirm modal reuse** — `ConfirmDialog.vue` gained a default `<slot/>`; `SelectSpace.vue`'s confirm renders the SELECTED cell's preview via the shared `BoardPlacementPreviewContent.vue` (Cost / You receive / Other players receive / At game end / Risk / Field rules) — no duplicate text assembly.
- Shared renderers: `BoardFactRow.vue` (one fact → chip/VP-badge/timing-tag) + `BoardFactGroups.vue` (recipient grouping) — reused by hover, preview, and confirm so they can't diverge.

**Cancellability marker — `placementContext` (mirrors the `markChoiceContext` idiom).** `BaseInputModel.placementContext?:{cancellable, reason?, source?}` (server: `BasePlayerInput.markPlacementContext`, serialized centrally in `ServerModel.getWaitingFor`; builders `cancellablePlacement`/`committedPlacement` in `src/server/inputs/placementContext.ts`). `createMarsSelectSpace` DEFAULTS every placement to a COMMITTED marker (honest "can't cancel — action already underway") — overridden to cancellable by the pay-on-commit projects. `PlacementBanner` reads `cancellable`/`reason` from the marker (no client hardcoding); it shows "Отменить размещение" only when cancellable, else the honest reason.

**Pay-on-commit placement (City / Greenery / Aquifer standard projects + convert-plants).** The placement-bearing standard projects OVERRIDE `payAndExecute` to present the cancellable space selection FIRST and apply the M€ cost + effects ONLY in the commit callback (`StandardProjectCard.commitCost` + `commitInScope`, via the new `src/server/deferredActions/StandardProjectPlacement.ts`). So at the `SelectSpace` prompt NOTHING is committed — resources intact, no tile, no triggers, no journal/notification root (the analytics scope opens inside the commit, so a cancel emits nothing). **Cancel** (a new `CancelResponse {type:'cancel'}`) → `SelectSpace.process` calls `onCancel` (sets the transient `player.pendingPlacementCancelled`) → the action loop's `runWhenEmpty` cb (`Player.getActions`) re-presents the menu WITHOUT counting the action. Convert-plants was already this shape (plants spent in its `andThen`); it now also carries the cancellable marker + inherits the preview/confirm. **Aquifer at max oceans** falls back to the committed legacy path (a degenerate stall / Whales — no placement to cancel). `addCity`/`addGreenery`/`addOcean` are unchanged; the shared `PlaceCityTile`/`PlaceGreeneryTile`/`PlaceOceanTile` gained optional `placementContext`/`onCancel` pass-through but cards leave them at the committed default. The whole server suite (7408) stays green — the refactor is transparent to existing tests because they pick a space (which triggers commit).

**Cancel surfaced in the mandatory notification + colony pay-on-commit (cancel iteration).** The cancel of a not-yet-committed action is exposed in THREE places, all driven by the server `placementContext.cancellable` marker (no client guessing): `PlacementBanner` (board placements), `ColoniesOverlay` build mode ("Отменить строительство"), and — the prominent anchor — the **mandatory-action notification** (`NotificationCard` gains an optional calm `cancelCta`; `notificationModel.buildTurnNotification` sets it from `waitingFor.placementContext?.cancellable`, contextual label `Cancel placement`/`Cancel construction`; `NotificationLayer` `@cancel` → `tm-notification-cancel` window event → `PlayerHome.onNotificationCancel` → the `WaitingFor` ref's `onPlacementCancel()` → a `CancelResponse`). **Build-Colony standard project is now pay-on-commit** (mirrors the standard-project refactor): `BuildColonyStandardProject.payAndExecute` defers `BuildColony` with a `commit` closure (`commitInScope`→`commitCost`+`addColony`) + `onCancel`; `SelectColony` gained `onCancel` + `CancelResponse` handling (mirrors `SelectSpace`). Card-driven colony builds (VitalColony etc.) leave the options unset → committed (the card is already played). **NOT made cancellable (would be unsafe — classified Category D in `docs/PENDING_ACTION_CANCEL_AUDIT.md`):** blue-card/CEO ACTIONS that place/move (Mars Nomads action) and card-play-with-placement — `Player.playActionCard` marks the card used + logs + opens the journal scope at SELECTION time, before the action's `SelectSpace`, so a cancel would leave the card stuck "used"; they need a transactional reveal/pay/play-on-commit refactor first. Client-only nested picks (sell-patents / played-pick / actions-pick / convert-plants) already expose cancel in their own overlays and don't raise an action-required notification, so they needed no change. Full classification: `docs/PENDING_ACTION_CANCEL_AUDIT.md`.

**Journal (M8) — consistency, not a rewrite.** The journal already groups a placement's IMMEDIATE effects (ocean M€ `oceanBonus`, printed `spaceBonus`, the tile) under the action's `correlationId` via the existing event stream, and the preview mirrors the SAME grant logic (shared `oceanAdjacencyBonus` etc.), so preview ↔ commit cannot diverge (guarded by `tests/boards/placementPreviewConsistency.spec.ts`). Future/endgame VP is intentionally PREVIEW-ONLY (the journal is a commit log of what HAPPENED, never a speculation of scoring). When Ares adds cross-player adjacency income, it flows through the existing event system as a normal journal child.

**Off-Mars / external tiles — location ≠ `countsAs` (iteration; full list in `docs/SPECIAL_TILE_AUDIT.md`).** `countsAs: city/ocean` does NOT mean the tile participates in Mars city-greenery / ocean-adjacency scoring — an off-Mars reserved city slot (Maxwell Base, Ganymede Colony, the Venus city slots) is an ordinary `CITY` tile on a `COLONY` space that `countsAs` a city but has NO Mars adjacency. The engine now derives `BoardCellStatus.external` from the REAL adjacency graph — **`onMarsGrid(board, space) = board.getAdjacentSpaces(space).length > 0`** (mirrors `calculateVictoryPoints`, which scores cities via `getAdjacentSpaces`; a `COLONY` slot returns `[]`). City-greenery scoring + ocean facts are GATED on `onMarsGrid` (both `boardCellInfo` and `boardCellPreview`); an occupied off-grid tile gets a neutral **`external-area`** fact ("Внешняя область — обычное соседство на Марсе не применяется") instead of false 0-VP scoring. An off-grid tile is marked `special` even if its `TileType` is a plain `CITY` (reads as a special city, not "ГОРОД"), named from `space.tile.card` (set by `behavior.city`). The reserved-cell checks (`COLONY`/`RESTRICTED`/Noctis) now fire only when EMPTY, so an OCCUPIED reserved slot flows to the tile branch (real identity) and the stale empty-cell "only X can be placed here" lore no longer shows over a placed tile (the popover also suppresses lore when `status.external`). **`countsAs` stays shown (separately) — it is NOT scoring.** **New Holland is verified on-grid** (it covers an ocean on the Mars surface) so its city scoring + ocean adjacency are CORRECT and unchanged — the fix is purely the off-grid gate, not a per-tile rule. **Header redesign:** the popover header is now two rows for a named special/composite tile — a compact TYPE badge + owner chip on top, the NAME on its own line below (`.board-cell-popover__head--named` / `__head-top` / `__name`) — killing the ugly "ОСОБЫЙ ГОРОД : НОВАЯ ГОЛЛАНДИЯ" colon-orphan wrap; ordinary cells keep the single-row look. Ares-ready: the `external`/location split is exactly what a future Ares adjacency-source layer reads (location ≠ identity ≠ countsAs ≠ scoring). New i18n keys in `board_info.json` (`External area`, the external note). Tests: off-Mars city no-false-scoring + New Holland on-grid regression in `BoardInformationEngine.spec.ts` (23 passing).

**Special-tile identity + Deflection Zone (iteration — full list in `docs/SPECIAL_TILE_AUDIT.md`).** A SPECIAL / composite tile NEVER degrades to a bare "ОСОБЫЙ ТАЙЛ" or an ordinary "ГОРОД". `BoardInformationEngine.baseCellStatus` derives identity from `Board.isSpecialTile` + the tile sets: `special` (true for any special tile), `countsAs` (`countsAsFor` → `['city'|'ocean'|'greenery']` from `CITY_TILES`/`OCEAN_TILES`/`GREENERY_TILES`, so a composite like New Holland / Ocean City reads as **city + ocean**), and a **guaranteed name** `tileLabel = tileTypeToString[tileType] ?? space.tile.card` (`tileTypeToString` covers EVERY `TileType`, and for in-scope card-placed tiles it IS the source card — so the header names it without a redundant "Источник" line). `headerFor` returns `Special city` (composite that counts as a city — Capital / New Holland / Ocean City) vs `Special tile` (everything else); an ORDINARY city/ocean/greenery is untouched (`special !== true`), so the good city tooltip is preserved. `existingTileScoringFacts` shows a special tile's OWN board scoring SEPARATELY from the generic city-greenery rule via `adjacencyVpFact` (category `future-scoring`, no `+0` badge): **Capital** → +1 VP / adjacent ocean (`score-capital`), **Commercial District** → +1 VP / adjacent city (`score-commercial`). Client `BoardCellInfoPopover` renders the name beside the header, a "Считается как: …" line (`countsAsLabels`), and includes `future-scoring` in `scoringFacts`. **Asteroid Deflection Zone (Hollandia)** was corrected from the WRONG "fixed position on a random map" text to the REAL rule (mirrors `Game.ts` `withinDeflectionZone = inside>0 && outside===0`, consumed by `Player.plantsAreProtected`): *protected from plant destruction while ALL your tiles are inside the zone*. Hover a deflection cell → the rule + a per-player **`zoneProtection`** status block (`buildZoneProtection`, viewer first: `active`/`inactive-no-zone-tiles`/`inactive-has-tiles-outside`); placement preview → a `deflection-impact` fact (in-zone activates/keeps/won't-restore; off-zone-while-protected warns it disables). New model: `ZoneProtection`/`ZonePlayerProtection` + `BoardCellInfo.zoneProtection`. The dead/wrong deflection i18n keys were deleted. Plant-destruction target gating is ALREADY enforced server-side (`Player.plantsAreProtected`); surfacing it in the attack-target picker is a documented frontier (see the audit). Ares-ready: `countsAs` + the special-tile identity are exactly what a future Ares adjacency-source layer reads.

## Iteration — the placement preview learns WHAT THE CARD DOES (2026-07-29)

Until now `boardCellPreview` knew the CELL and the TILE, never the CARD. So Solar Farm — a card whose entire decision is *which* area, because its energy production equals the plant bonuses printed there — showed only "Cell bonus +2 plants" and revealed its actual payload after the tile was down. Same class of blindness: Mining Area / Mining Rights (which production you get depends on the area), Flooding (who you can hit for 4 M€ depends on the neighbours), and every opponent trigger (`Arctic Algae`, `Tharsis Republic`, `Pets`, `Philares`, …), which quietly enriched somebody else.

**The key that unlocks it: `SelectSpace.sourceCard`.** A new `CardName` field on `SelectSpace` → `SelectSpaceModel.sourceCard` (in `toModel`, so it survives nesting, unlike the centrally-decorated `placementContext`) → the client forwards it as `?card=` to `/api/game/board-cell-preview` → the engine resolves the instance (`player.tableau.get` → `newCard` → `game.getStandardProjects()`) and asks it. `PlaceTile` derives it from `tile.card` (so every card that already records itself on the tile is covered with zero per-card work); `Executor` passes `card.name` for `behavior.city/greenery/ocean`; `PlaceCityTile`/`PlaceGreeneryTile`/`PlaceOceanTile`/`createMarsSelectSpace` take a `sourceCard` option for the bespoke placers. It also fills `placementContext.source.card`, which `consoleTaskSummary.sourceCardOf` had been reading as `undefined` for every card placement.

**Two co-located READ-ONLY hooks** (`ICard`, builders in `src/server/cards/placementPreviews.ts`, context in `boards/PlacementPreviewContext.ts`):
- `placementPreview?(player, space, ctx)` — the PLACING card's own space-dependent consequence. Solar Farm, Mining Area/Rights, Flooding, Immigrant City / Urbanized Area / Noctis City (their `.andThen` production costs), City standard project (its +1 M€ production is granted inside `commit(space)`).
- `tilePlacedPreview?(cardOwner, activePlayer, space, ctx)` — the mirror of `onTilePlaced`, walked over EVERY player's tableau in generation order (the same `triggerForAllCards` shape). Arctic Algae, Herbivores, Immigrant City, Pets, Rover Construction, Mining Guild, Tharsis Republic, Hospitals, Vermin, Neptunian Power Consultants, Philares, PolderTech Dutch, Ecological/Geological Survey. Fact ids are namespaced by owner colour so two players holding the same card can't collide.

**The context flag that prevents the classic bug:** at preview time the tile is NOT on the board, so `Board.isCitySpace(space)` answers about the cell's CURRENT content and every mirrored trigger would silently report "nothing happens". `PlacementPreviewContext` therefore precomputes `countsAsCity` / `countsAsOcean` / `countsAsGreenery` (from the same `*_TILES` sets) plus `covering` / `cleared` / the resolved `tileType`, and the hook doc-comments forbid the predicate form.

**Generic engine additions (no per-card work):**
- **Your tile's own adjacency contract (Ares)** — `placedTileAdjacencyFacts` reads `behavior.tile.adjacencyBonus ?? Card.adjacencyBonus`, so "your tile will grant an adjacency bonus" / "…will impose an adjacency cost" (Nuclear Zone's 2 M€ tax on every future neighbour, including your own) needs no table. Solar Farm's bonus moved onto the card property so the live placement and the preview read one constant.
- **The global-parameter CHAIN** — a greenery crossing 8% oxygen also raises the temperature (`Game.increaseOxygenLevel`), which can cross a heat-production step (−24/−20 °C) or the free-ocean step (0 °C). All of it previewed, with `current → resulting` on every parameter. TR is suppressed in `Phase.SOLAR` exactly as the commit path suppresses it (the WGT placement no longer promises rating it won't grant).
- **Special-tile adjacency VP at the moment of choosing** — `specialTileAdjacencyVpFacts` is now SHARED by the hover ("Capital scores for adjacent oceans") and the placement preview ("Capital *will* score…"), which previously said nothing.
- **Arcadian Communities' +3 M€** for building on an area you reserved — granted by `Game.addTile` itself (keyed on `space.player === player`), purely space-dependent.
- **Milestone / award progress** → the new `progressFacts` group. Scores come from the REAL `IMilestone.getScore` / `IAward.getScore`; to ask them about a board that doesn't exist yet, `withHypotheticalTile` installs the prospective tile, reads, and restores the exact three fields `simpleAddTile` writes (mirroring its ocean/Martian-Nature-Wonders/Rey-Skywalker "unowned" rule) in a `finally`. Purity stays test-guarded. A milestone that the placement COMPLETES is called out. Rendered as a `from → to / target` badge, not a fake resource chip — there is no `milestone` sprite and inventing one renders a missing image.

**Client:** `BoardPlacementPreviewContent` gained the "Milestones and awards" section; `BoardFactRow` now renders `fact.source.label` as a quiet card-attribution tag (a gain must never read as anonymous) and finally forwards `delta.production` as the chip's `production` note (which also fixes the pre-existing `ENERGY_PRODUCTION` cell bonus rendering as a one-off gain). `progressFacts` is optional so a cached older payload still renders.

**Not every "pick a cell" places a tile — `SelectSpace.placementEffect`.** Three shapes: `'tile'` (default), `'bonus-only'` (Mars Nomads MOVES its camp — the destination's placement bonuses are collected, no tile lands), `'marker'` (Land Claim / an Arcadian Communities marker / seating the nomad camp — nothing is granted). `previewContext` turns it into `ctx.placesTile` + `ctx.grantsPlacementBonus`, and the engine gates on them: no printed bonus / ocean M€ for a marker, no Ares adjacency / endgame VP / milestone count / Arcadian M€ without a tile.

This is what fixed the one real preview↔commit divergence. Mining Guild's live guard keys off `game.nomadSpace`, which at PREVIEW time still points at the camp's current cell — so the panel promised +1 steel production that the commit suppresses. Teaching the preview about Mars Nomads would have hard-coded one card into a corporation; instead the corporation now states the rule it actually has (*"each time you place a TILE"* → `if (!ctx.placesTile) return []`) and the prompt declares whether a tile lands. The tabletop ruling is recorded in the card itself (BGG 3154812): *"Mining Guild and Philares cannot take advantage of it"*, *"adjacency bonuses are not placement bonuses"*.

**Density is part of the contract.** The panel is the entire right rail on a TV, so every line must earn its height: `stripRedundantSource` removes the card tag from the card the prompt title already names (Solar Farm was printed three times on one screen); a milestone row carries a `from → to / target` badge instead of a "Milestone progress" line under a "Milestones and awards" heading; the confirm CTA is no longer repeated at the bottom of the panel, and the permanent "cancelling is not available" note is gone (it stated a non-event on every placement — B answers it when actually asked). Risk moved directly under Cost so a danger can never fall below the fold. When content still overflows, it ANNOUNCES itself: a fade at each cut edge plus a sticky `stickR` glyph line, both driven by a three-property measurement on scroll / resize / new preview.
