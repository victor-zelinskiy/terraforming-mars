**When the user says "adapt / cover expansion X" (Turmoil, Ares, Moon, Pathfinders, CEOs, Star Wars, Underworld, Prelude2, Community, Delta, …), THIS is the master to-do.** Every premium subsystem this fork built is **scoped** — it deliberately covers only a set of modules today, guarded by tests that ENUMERATE exactly which cards need attention. Adapting an expansion = widening that scope module-by-module and clearing what the guard tests print. Do them in this order; **the guard tests are your worklist — run them right after step 1 and they tell you every card to touch.**

**Current scope (everything below already covers these):** `base`, `corpera` (Corporate Era), `promo`, `venus` (VenusNext), `colonies`, `prelude` (Prelude1).
**Not yet in scope (the frontier) — EXACT `GameModule` keys:** `prelude2`, `turmoil`, `community`, `ares`, `moon`, `pathfinders`, `ceo`, `starwars`, `underworld`, `deltaProject`. ⚠️ The module KEY ≠ the source DIR for two: key `ceo` ↔ dir `src/server/cards/ceos`; key `deltaProject` ↔ dir `src/server/cards/delta`. Use the KEY in the SCOPE sets, the DIR for file paths. (Full list: `src/common/cards/GameModule.ts`.)

### Step 0 — the load-bearing rule for ALL of the below
**Every per-card hook is CO-LOCATED in the card file** (next to `canPlay`/`canAct`/`bespokePlay`), pulling wording from a thin stable builder module. This is deliberate: a fork that merges upstream — when upstream changes a card, the hook is in the SAME diff/conflict, so it can't silently drift. **Never** centralize these into a fork-only table upstream never touches (it would merge clean and rot). Builders: `src/server/cards/actionPreviews.ts` (previews), `src/server/cards/actionReasons.ts` (action reasons), `src/server/inputs/optionMetadata.ts` (modal metadata). All hooks/previews are READ-ONLY (never mutate game state).

### Step 1 — widen every SCOPE constant (do this FIRST, then run the guards)

- `tests/models/cardPlayPreviewCoverage.spec.ts` → `SCOPE` (play-from-hand previews)

### The expansion-specific gotchas to expect
- **Turmoil**: send-delegate has no dedicated action button yet (rides `wf-action`) — add its selector to BOTH `PLACEMENT_LOCKED_SELECTORS` (PlayerHome) and `placement_banner.less` when you build it. Party-action payments are `SelectPaymentDeferred` (already modal-routed).
- **Moon**: `ICard.reserveUnits` / moon-rate requirements — the requirement explainer + placement deficit already map moon rates; verify new moon spaces in `unplayableReasons` board checks.
- **Pathfinders / Underworld / Star Wars**: new `CardResource` types — `iconClassFor` (`optionIcons.ts`) derives `card-resource-<key>` by lowercasing+hyphenating, correct for every in-scope resource; verify a genuinely new resource icon class exists, else add it. New underground-token / corruption requirements already have requirement-reason branches.
- **CEOs**: one-per-game CEO action has no dedicated button yet (migration list item). Asimov-style free-award funding is OUT of the AwardsOverlay free-mode scope (awards not in `game.awards`) — stays on the generic modal until addressed.
- **AndOptions-nested SelectCard** (FocusedOrganization [prelude2], AeronGenomics [underworld]) still renders via legacy `AndOptions.vue` — a known narrow gap; a premium `ModernAndOptions` was deliberately deferred.
- **NO-AUTO-SELECT / hidden-target — there is NO auto-guard for BESPOKE single-candidate auto-apply** (it lives in hand-written `action()`/`bespokePlay`/deferred code, not a declarative key the coverage spec can enumerate). This class KEEPS resurfacing per expansion (Cloud Seeding's `decreaseAnyProduction` auto-attacked the lone opponent; CometAiming/AsteroidRights/DirectedImpactors/Astrodrill/ExtremeColdFungus auto-added to a single card) because each is bespoke. **Per module: `grep` the card dir for `length === 1` / `length > 1` adjacent to `addResourceTo`/`removeResourceFrom`/`.attack(`/`.cb(`/`production.add`/`SelectCard`/`SelectPlayer`** and triage each: a single-candidate that APPLIES DIRECTLY (auto-add-to-self, auto-attack-the-only-opponent) is the bug → replace with the `SelectCard`/`SelectPlayer` (always shown — neither auto-resolves) + pre-collect it in the preview. EXEMPT: a FIXED self-target (filter to `this`) and `OrOptions.reduce()` (auto-picks the only OR BRANCH, no hidden target). The DECLARATIVE keys (`removeAnyPlants`/`decreaseAnyProduction`/`addResourcesToAnyCard`) are guarded by `cardPlayPreviewCoverage.spec.ts` — run it; it FAILS with the new module's offending cards. Record the triage in `docs/DELAYED_TARGET_AUDIT.md`.
- **Card-text ORDER is the only carrier of sequence (no crutch words).** A new expansion's cards get their `information` blocks auto-ordered to render position (behavior-derived) — BUT if a card's RENDER itself draws effects out of execution order, the fix is the RENDER (a card-authoring bug), not a re-order in the info model. Authored `infoText` must be hand-ordered to render reading order; the guard (`cardInformation.spec.ts` render-order-monotone + no-sequencing-words) FAILS with the offending card. NEVER paper over order with «then»/«затем». `hasBespokePlay` now catches an INHERITED bespoke override (an Ares/promo subclass extending a bespoke base with a partial `behavior`) — such a card silently lost its bespoke tile + adjacency before; it now lands in `needsCuration` → give it `infoText`.
- **Premium-face tiles: the VARIANT is a render-node FLAG, not the `TileType`.** A shared special tile (Deimos Down base/promo/ares → all `TileType.DEIMOS_DOWN`) resolves its art from the node's `isAres` via `TILE_VARIANT_PRIORITY` (Ares wins). A new expansion tile → add the asset + a `TILE_VISUAL` entry; a new node-flag variant → add a `TILE_VARIANT_PRIORITY` entry (keep Ares first). Missing card ART is NOT a gap — the procedural theme fallback is intentional.
- **Contextual choice modals — there is NO auto-enumerating guard** (OrOptions are built dynamically inside methods, so a static coverage spec like `cardPlayPreviewCoverage` can't list them). A new expansion's TRIGGERED effects (`onCardPlayed`/`onTag*`/`onTilePlaced`/`onColony*`) and standalone deferred actions that build an `OrOptions` of text `SelectOption`s render context-less UNLESS marked. **Per module: `grep` the card dir for `new OrOptions(` together with `new SelectOption(`** and triage each — if it's hosted by the play modal (`bespokePlay`/`cardPlayPreview`) or the action-confirm modal (`action()`/`actionPreview`) it's already premium (skip); a `behavior`/declarative-generated OrOptions is auto-covered (skip); EVERYTHING ELSE (a triggered/on-play/deferred bespoke OrOptions) needs `.markChoiceContext(...)` + per-option metadata. Record the triage (done / already-premium / phase-2) in `docs/CHOICE_CONTEXT_AUDIT.md` so the next expansion starts from a known baseline. The shared deferred-attack prompts (`StealResources`/`RemoveAnyPlants`/…) are the standing phase-2 item: rich per-target metadata already, but no source-card preview (needs threading the source `ICard` through the Executor) — DON'T re-discover this per card, it's one shared fix.
