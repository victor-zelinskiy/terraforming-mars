## TR09 · EVA Mechs — 2026-09-29

**Что нового.** Три вещи сразу, потому что карта первая:
1. **Инфраструктура набора** — манифест `turmoilRedux` (пространство `TR##`, шесть карт-замен зарезервированы
   гардом), регистрация в `AllManifests` + `GameCards` (`turmoilReduxExpansion`), `CardName` секция
   `// Turmoil Redux`, RU-файл `src/locales/ru/turmoil_redux_cards.json`, вход модуля в премиум-скоуп (22 точки),
   строки скоупа в `CLAUDE.md` и `expansion-adaptation-checklist.md`, чеклист автора и этот журнал.
2. **Ресурс карт `CardResource.MECH = 'Mech'`** — литерал несущий (спрайт `assets/resources/mech.png`, id
   `res-mech`, класс `.card-resource-mech`); глобальный класс через `@card_resource_types`, семейство
   `resource_icon--mech`, таблицы клиента, множественное в спутнике, иконка-игла для импульса коммита.
3. **Платёжная единица `mechs`** — тропа `floodgateSteel` целиком (компилятор + «молчащие» точки), но без её
   лишнего: никаких unit-гейтов, наград, атак, Last Resort, стандартных проектов, отложенных счетов.

**Решения.**
- Мех — ОБЫЧНЫЙ жадный альтернативный источник (`initialCounts` не трогали): защита `floodgateSteel` нужна
  той стали как блокаде; у меха второго применения нет. Следствие — «Переплата +4» при 2 мехах на 6 M€
  без M€ на руках: честно, понижается инлайн-пилюлями/LT. Если следующая карта TR введёт трату мехов на
  эффект — пересмотреть (записано в документе карты §4).
- Дорожка называет РЕСУРС («Мехи»), не карту: имя карты носит только `floodgateSteel`, где сталь на карте
  иначе неотличима от стали планшета.
- Значение плоское (5): `rateFor` и `payingAmount` без веток — модификаторы титана и Metal Research не
  достают (закреплено спеком с реально принятым RX19).
- Фикстура `eva-mechs` (2 игрока, blue: EVA Mechs с 2 мехами, 1 энергия, 3 M€, 0 титана, в руке
  Trans-Neptune Probe) — plain base+corpera, карта положена в tableau напрямую; ворота колоды — дело
  манифест-гарда, не e2e.

**Что напечатали гарды.** До расширения скоупа модуль был вне всех 22 точек; после расширения и карты —
все 121 серверных и 259 клиентских проверок зелёные, ворклист TR09 пуст; `make:cards`: 510 карт,
0 `missingTranslations`, 0 `needsCuration`. Строка действия из `behavior` — 49 символов, `action-short`
не понадобился; эффект — курируемый `effect-short` «Space tag: mechs here pay 5 M€ each» (образец Dirigibles).

**Гэпы / наблюдения.**
- `npm run e2e:fixtures` падал ДО парламентских фикстур на `parliament-powergrid-recap` (ожидание «red P=4» не
  сходилось: сид-0 сдача корпораций едет вместе с составом колоды — красному выпал ThorGate с меткой энергии,
  count 5). Предсуществующая поломка (проверено на неизменённом HEAD-файле), **починена в тот же день классом,
  а не экземпляром**: `reduxTable` прикалывает корпорации к местам — `customCorporationsList` ровно по одному
  имени на место (`REDUX_TABLE_CORPORATIONS` = то, что несут все сданные фикстуры: Teractor, Aridor, ThorGate,
  Arklight, Tharsis Republic, Poseidon; венерианские столы — UNMI, PhoboLog, …) и затем сам раздаёт: каждому месту
  сданную карту с именем его позиции (свап между руками — `Deck.shuffle(cardsOnTop)` перемешивает верх между
  собой, так что список гарантирует множество, а не порядок). Полный генератор снова проходит все 98 builder'ов
  (dry-run `FIXTURES=__none__`, exit 0); перегенерировано только семейство `parliament-powergrid-*` — расстановка,
  деньги, TR и исходы идентичны сданным, соседние слоты области взяты из выросшего пула резолюций (спеки сдачу
  не предполагают). Подтверждение: `console-parliament-powergrid` 6/6, `console-parliament-vote-fit` (powergrid)
  6/6, `console-parliament-sitting-reward` (RX04) 3/3. Каждая таблица сеет свой rng (`Game.newInstance(seed = 0)`),
  позиция блока `eva-mechs` чужие сдачи не меняет.
- e2e: `tests/e2e/console-eva-mechs.spec.ts` — путь действия (композер «1→0 энергия» / «2→3 на этой карте»,
  капсула «2», коммит → борт, сервер: 3 меха, 0 энергии, спутник «3» с монетой «5») + путь оплаты (дорожка
  «Мехи ×5» с иконкой меха, авто 1 мех + 1 M€ = точно, RB → «переплата +4», LB назад, розыгрыш → сервер:
  зонд в tableau, 2 меха, 2 M€) — 1 + `--repeat-each=4` = **5/5 зелёных** (~30 с прогон); ratchet 0
  `waitForTimeout`. Кадры: `screenshots/eva-mechs/01…05`.
- Вкладки «Flagged» бывших `?effectsPlayground` / `?actionsPlayground` живут только как диагностика
  (`flaggedEffectCandidates` / `flaggedActionCandidates`): список действий обязан быть пустым (гард), в списке
  эффектов TR09 закреплён отдельной строкой `effectExtraction.spec` — оба зелёные.
- `tests/e2e/console-effect-forecast.spec.ts` читал `thisPlayer.megaCredits` (поле модели — `megacredits`),
  поэтому его проверка «бесплатный розыгрыш не тронул M€» сравнивала −1 с −1 — вакуумно зелёная. **Починено:**
  хелпер читает `megacredits` + `megacreditProduction` и БРОСАЕТ, если полей нет (вакуум невозможен по построению);
  сама проверка стала честной — «бесплатно» значит цена 0, а не «M€ стоят на месте»: Insulation переводит
  производство тепла в M€, а синий — Manutech, который выплачивает шаг производства сразу, так что запас обязан
  сдвинуться РОВНО на прирост производства (цена 2 читалась бы как «прирост − 2»; 0 шагов → 0 = 0). Прогон
  1080-journey зелёный. Попутно поправлено то же имя поля в неиспользуемом типе `console-parliament-aquifer.spec.ts`.

## TR08 · Formula Zero — 2026-09-29

Близнец Security Fleet: действие «1 M€ → истребитель на эту карту», 1 ПО за истребитель, требование 2 метки
Науки, стоимость 5. Полностью декларативная (`spend.megacredits` + `addResources` + `victoryPoints.resourcesHere`),
хуков и прогноз-близнеца нет. Карта: `src/server/cards/turmoilRedux/FormulaZero.ts`, спек
`tests/cards/turmoilRedux/FormulaZero.spec.ts` (11 проверок).

**Что нового для набора** (у каждого пункта уже был зелёный образец в скоупе, кода не понадобилось):
1. **Цена действия в M€.** У обычного игрока — плоский чип «1 → 0 M€», без промпта. У Helion шаг оплаты
   ПЕРВЫМ в ветке и плоский чип убран — это дало общее правило `actionPreview.ts` (`spend.megacredits`), в нём
   ничего не правили; исполнение оставляет `SelectPayment`, ответ `{heat: 1}` кладёт истребитель (спек).
   Авто-причина при 0 M€ — `{type: 'megacredits', message: 'Need ${0} more M€', params: ['1']}` (не «Not enough
   M€»: у M€ своя ветка в `actionUnavailableReasons`, с дефицитом).
2. **ПО за ресурс карты** — общий путь `resourcesHere`: 0 / 1 / 3 истребителя → 0 / 1 / 3, переживает
   сохранение. На лице бейдж «1/[истребитель]», в списке действий после коммита — «1 ПО».
3. **Метка Марса в скоупе.** Обычная метка: `tags.count(MARS)` = 1, наукой не считается. Столбец Марса в
   матрице МЕТКИ появляется только на столе с Кризисом Redux: матрица читает `game.tags` (метки всех колод
   партии), а TR08 пока единственная карта скоупа с этой меткой. На столе base+corpera с картой, положенной
   прямо в tableau, столбца нет, и это правильно.

**Решения.**
- **Метки — `[MARS]`, а не `[SCIENCE, SCIENCE, MARS]`, как было в промте.** Два атома на скане стоят в
  оранжевой плашке «MIN» рядом с ценой, то есть это ТРЕБОВАНИЕ (текст: «Requires 2 Science tags»). Метка в
  углу одна — Марс. Конвенция сканов уточнена в чеклисте §0.
- Имя «Формула-0» (решение владельца); ключи ПО и капшена — Security Fleet (`1 VP for each fighter resource on
  this card.` уже переведён). Строка действия из `behavior` уложилась в 52 символа, поэтому `action-short` не
  понадобился. Новых i18n-ключей ровно три: имя, «Action: Pay 1 M€ to add a fighter resource to this card.»,
  лор «Now this is pod-racing!».
- `consoleActionCommitMotion.ts` `ICON_NEEDLES`: добавлены `fighter` (TR08 + Security Fleet) и драйв-бай
  `graphene` (Carbon Nanosystems). Без них импульс коммита не находил иконку результата и молча деградировал.
  На кадре коммита иконка истребителя в ряду действия подсвечена.

**Что напечатали гарды.** Все гарды чеклиста §3 зелёные с первого прогона после карты, ворклист TR08 пуст:
серверные 141 проверка, клиентские 148. `make:cards`: 511 карт, 0 `missingTranslations` / 0 `needsCuration` /
0 `seededRunOn`, TR08 — `ok`. Полные наборы: server 13 299 passing, client 6 145 passing.

**Визуальная приёмка** (временный проб, fhd; кадры `screenshots/formula-zero/`, не в git):
витрина `?premiumCardsPlayground` (Марс в углу, чип «наука ≥ 2», ряд 1 M€ → истребитель, бейдж «1/[истр.]»);
композер «ДЕЙСТВИЯ КАРТ › ФОРМУЛА-0 › НАСТРОЙКА» с чипами «1 → 0» M€ и «0 → 1 на этой карте»; кадр коммита
(капсула «1», M€ 0, ПО 20 → 21); список «Активированы» после коммита («Формула-0 [истр.] 1 · 1 ПО», ресурсы на
карте 1); сервер: 1 истребитель, 0 M€. Ошибок страницы нет.

**Гэпы / наблюдения.**
- **TR09 несла лишнюю метку Науки — ИСПРАВЛЕНО 2026-09-29** (решение владельца: баг). На скане TR09 атом стоит в
  плашке требования («Requires 1 Science tag»), в углу только Космос; `EvaMechs.ts` объявлял `[SCIENCE, SPACE]`.
  Теперь `[SPACE]` — карта, её спек и `docs/TURMOIL_REDUX_EVA_MECHS.md`; фикстура `eva-mechs` хранит только имя и
  счётчик, от метки не зависит.
- **MarsBot × Redux-колонии: латентный сбой, вскрыт колодой.** С TR08 в колоде сидированная партия
  `ParliamentPhase › with MarsBot` пошла иначе: бот поторговал с Redux-Плутоном и упал на «Pluto Redux has no
  MarsBot storage area» (без TR08 в манифесте спек зелёный, проверено). Сломала бы и любая следующая карта набора.
  **Починено структурно** в `shippingAreaFor` (`common/automa/ShippingBoardData.ts`): плитка-замена
  (`TURMOIL_REDUX_REPLACEMENTS`) хранит в области базового двойника, ключ счётчика — плитка в игре. Спеки: данные
  (`VenusAndShippingData`) и паритет обмена с базовым Плутоном (`AutomaColoniesFlow`).
  **Отложено (решение владельца 2026-09-29):** у ДОБАВЛЕНИЯ Venus Redux области на Shipping Board нет, так что
  постройка / торговля / бонус бота там бросит то же исключение (стол MarsBot + Redux + Venus Next). Будет решено
  вместе с поддержкой MarsBot для Кризиса Redux — не отдельной правкой.
- e2e и фикстуры не добавлялись (политика §5). Любая новая карта меняет сдачу Redux-столов генератора, а спеки
  сдачу не предполагают.

## TR66 · Automated Convoys — 2026-09-29

«Беспилотные конвои»: ОДНО действие, два варианта — A «2 энергии → 2 меха на эту карту», B «1 мех с этой карты →
бесплатная торговля». Стоимость 9, метка Космоса, требования нет (плашка MIN на скане пуста), ▲ у арта = нужны
Колонии → в манифесте `compatibility: 'colonies'` (прецедент Delta Works). Карта:
`src/server/cards/turmoilRedux/AutomatedConvoys.ts` (+ трейдер `TradeWithAutomatedConvoys` в том же файле), спек
`tests/cards/turmoilRedux/AutomatedConvoys.spec.ts` (26 проверок).

**Что нового для набора** (у каждого пункта был зелёный образец вне набора — клиентского кода НОЛЬ):
1. **Первое двухвариантное действие.** Форма DP11 Modular Floodgates: `orBranches` A, B = печатные ряды = порядок
   `action()`; один живой вариант — это всё действие (коллапс без промпта), два — `OrOptions` с
   `markChoiceContext(effectChoice(this))`. `canAct` ⇔ хоть одна ветка (гард `actionBranchAvailability`).
2. **Первый РАСХОДНИК меха, и он — вторая дверь торговли.** Форма TFLP: вариант B не торгует сам, а входит в ОДНУ
   торговлю через собственный `IColonyTrader`, зарегистрированный в `Colonies.tradeHandlers()` сразу после
   TFLP. `optionMetadata.card = AUTOMATED_CONVOYS` — структурная идентичность пути, по ней консоль запирает оплату
   во второй двери. Мех снимается `removeResourceFrom` (рекордер видит; `resourceCount--` у TFLP не копировали),
   флот тратится (`Colony.trade`), действие помечается использованным — одна попытка на обе двери.
3. **Второй держатель мехов.** Мехи конвоев — НЕ деньги: платёжная единица читает только EVA
   (`CARD_FOR_SPENDABLE_RESOURCE.mechs`), `getSpendable('mechs')` = мехи EVA; спутник ДОП. РЕСУРСЫ даёт одну монету
   «5» по запасу EVA (`railValueModel.spec` — EVA 2 + конвои 3 → бейдж «5», `spendableAmount` 2; конвои без EVA →
   монеты нет).

**Решения.**
- **Причины — по одной на ветку, в порядке проверки.** A: «Not enough energy». B: сначала «No mechs on this card»
  (единственное условие самой карты), затем причина движка `tradeBlockedReason()` — эмбарго / «No trade fleet
  available» / колония. Действие целиком мертво: без мехов → энергия (торговля и не была на столе); мех есть, но
  торговля закрыта → то, что её закрыло (у игрока есть средство, ему важно, что перекрыло путь).
- **Сев мехов EVA не меняется** — §4 `docs/TURMOIL_REDUX_EVA_MECHS.md` дополнен: TR66 тратит СВОИ мехи, пул оплаты
  второго применения не получил; триггер пересмотра — карта, тратящая мехи С EVA / «с любой карты».
- Лор на скане с опечаткой «someting» → в файл «Amazon was onto something.» (RU «Amazon был на верном пути.»).
- Новые ключи i18n (9): имя, два `Action: …`, заголовки опций «Pay 2 energy to add 2 mechs to this card» /
  «Spend 1 mech from this card to trade for free», кнопка «Add mechs», «Pay 1 mech (use ${0} action)»,
  «No mechs on this card» (в `ui.json` рядом с аэростатами), лог «${0} spent 1 mech to trade with ${1}», лор.
  Кнопка варианта B — существующий «Trade».

**Что напечатали гарды.** Гарды чеклиста §3: серверные 179, клиентские 181 — зелёные с первого прогона, ворклист
TR66 пуст; `make:cards`: 512 карт, 0/0/0, TR66 `ok` (два блока — по описанию на ряд, `action-short` не нужен).
Полные наборы: client 6146 passing; server — см. следующий пункт.

**Сдвиг сдачи вскрыл отложенный гэп (как предсказывал TR08).** С TR66 в колоде два спека стола MarsBot + Redux +
Venus Next покраснели: `CloudDevelopment › MarsBot (mode none) is never asked…` и `GasExport › MarsBot is never
paid…` — бот строит колонию на Venus Redux и падает «Venus Redux has no MarsBot storage area». Без TR66 в манифесте
оба зелёные (проверено: 54/54 → 52/2). Структурная правка отложена владельцем до поддержки MarsBot для Кризиса
Redux, поэтому в этих двух спеках (их предмет — парламент и бот, не колонии) неподдержанная плитка снимается со
стола сразу после создания игры, с комментарием-ссылкой сюда. Гэп остаётся открытым: реальный стол MarsBot + Redux +
Venus по-прежнему падает на первой постройке / торговле бота на Venus Redux.

**e2e.** Новых нет (политика §5). Существующие `console-card-trade-entry` + `console-card-trade-resume` с двумя
трейдерами-картами в `tradeHandlers` — **5/5 зелёных**.

**Визуальная приёмка** (временный проб на движковой фикстуре — 2p, колонии, конвои с 1 мехом, 4 энергии; fhd;
кадры `screenshots/tr66/`, не в git):
1. витрина `?premiumCardsPlayground` (фильтр `turmoilRedux`): Космос в углу, два ряда действия через «ИЛИ», чипа
   требования нет;
2. композер «ДЕЙСТВИЯ КАРТ › БЕСПИЛОТНЫЕ КОНВОИ › НАСТРОЙКА» (вариант 1/2): «БУДЕТ СПИСАНО [энергия] 4 → 2» /
   «ВЫ ПОЛУЧИТЕ [мех] 1 → 3 на этой карте»; коммит — капсула «3», мехи ряда подсвечены, чип «−2» у энергии;
   сервер: 3 меха, 2 энергии;
3. вторая дверь «БЕСПИЛОТНЫЕ КОНВОИ › КАЛЛИСТО · ТОРГОВЛЯ»: ОДНА строка оплаты «Потратьте 1 мех (действие
   Беспилотные конвои) 1 → 0», запертая и выбранная; X → торговля: чип «+2» энергии, флот на Каллисто, трек сброшен,
