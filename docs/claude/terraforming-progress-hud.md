## Terraforming progress HUD + "Terraforming complete" event (both modes)

**One shared math, one shared trigger, two mode-native presentations.** The total terraforming percent counts ONLY Temperature + Oxygen + Oceans — **Venus is NEVER an input** (it is not a base game-end parameter; the game-end VARIANTS that require Venus/Moon are the server's `game.isTerraformed` concern, not display progress). The math lives ONCE in `src/client/components/gameProgress/terraformingProgress.ts` (`terraformingProgress({temperature, oxygenLevel, oceans})` → per-axis 0..1 + `total` + integer `percent` **capped at 99 until `complete`** + `complete`; a GameModel can be passed directly) — consumed by BOTH the desktop `Sidebar.vue` gauge (spine + `planet-overall` % readout; per-axis underlines incl. Venus's own stay local) and the console `ConsoleStatusStrip.vue`. **Console top HUD:** the game-end trio (Temp·O₂·Oceans) is one instrument group `.con-status__terra` — a compact label-less percent + a THIN 3px rail underline (`__terra-rail`/`__terra-fill`, width-transition through `--motion-scale`); Venus sits OUTSIDE the group behind a divider (`__param--venus`), then the generation block. **EVERY global readout plays the premium FLIP-SWAP — `ConsoleFlipValue.vue`** (`.con-flipval` in `console.less`): a one-shot split-flap tick (the old value folds up, the new unrolls in + a thin scanline flash), used by the game-end trio, Venus, the total percent AND the generation. `value` is the numeric truth (drives detection), `text` the formatted readout (`-6°C` / `7/9` / `78%`) so it works for any unit, `accent` (`cyan`/`mint`/`gold`) tints ONLY the one-shot beat. Mounts silently (a reload never replays); a DECREASE (undo / game switch) snaps with no flip. **⚠️ LAYERING (load-bearing): the component sits INSIDE the `.con-status__value` cell, never IS it** — the delta-chip `:has(.metric-feedback-host--…)` hooks put an `animation` shorthand on that cell, so a flip on the SAME element would be clobbered by that higher-specificity rule; nested, the two compose (the cell plays the chip's colour/scale pop, the cards fold inside it). The shine keyframe declares ONLY its 35% peak on purpose — the implicit start/end are the element's own computed `text-shadow`, so a persistent glow (the gold `--final` generation) is restored, never overwritten. **The delta chips stay on temperature/oxygen/oceans/venus/percent** (the sidebar's `globals.*` metric keys + scope `global`; the percent is `globals.terraforming-percent`; the `:has` hooks replay the shared `global-num-transition-*` keyframes) — so those announce twice over. **The GENERATION carries NO chip** (the flip alone is its announcement) **and console mode suppresses the desktop's "new generation" toast entirely** (`NotificationLayer.handleGenerationAndPass` gates `buildGenerationNotification` on `!consoleEnabled` — the HUD tick IS the announcement; desktop keeps the toast). The «ПКЛ.» generation label is VISIBLE in ALL profiles (the handheld profile shows it compact at 11px — an earlier pass hid it and a bare number read as ambiguous). Handheld/large profiles tune sizes in `console.less`.

**The generation readout's FLIP is the FIRST BEAT of the generation scene (TR61, 2026-10-17).** `ConsoleFlipValue` emits `flip-end` when its swap settles; the status strip forwards the generation cell's end to `noteGenerationFlipEnd(generation)`, and the scene (`console/generationScene/generationScene.ts`) sets the DISPLAYED view's generation ahead of the commit (`transportHolds.generationScene`) and waits for exactly that signal — never a timer — before the conversion and the income beats (`.claude/rules/console-ui.md` § THE GENERATION CHANGE IS ONE SCENE). An older readout's end is not this flip (the generation is compared).

**The completion event** — `src/client/components/gameProgress/terraformingCelebration.ts` (module reactive; the shared brain): `observeTerraformingProgress(view)` is called from `NotificationLayer.update()` (both modes) with the seed-silently-then-diff pattern (mirrors generation/pass/scale-claims) — reload/reconnect into an already-terraformed game shows ONLY the persistent states, never the cinematic; a live not-complete→complete transition bumps `celebrationNonce` exactly once. **Two separate truths:** `complete` (three params — what the rails show at 100%) vs `finalGeneration` (authoritative last-gen: multiplayer → server `isTerraformed` [variant-aware]; solo → `generation >= lastSoloGeneration`, since solo runs to a fixed generation regardless). The subtitle «Это последнее поколение» is shown only when honest (`celebrationFinal`); otherwise the neutral «Температура, кислород и океаны достигли максимума» (solo mid-run / Venus-required variant — the event still fires on the three params, per the "never wait for Venus" rule). Surfaces: desktop → a prestige `terraforming-complete` notification variant (mint, one-shot glow, TTL 14s, NOT suppressed by an open journal) + `planet-sidebar--terraformed/--celebrating` gold states;
