## P76 · Ishtar Expedition («Экспедиция Иштар») — ПЕРВАЯ КАРТА PRELUDE 2 · РОЗЫГРЫШ ИЗ РУКИ С ПОИСКОМ ПО МЕТКЕ — СДАНА 2026-10-29

**Задача.** Событие, 6 M€, метка Венеры, требование Венера ≥ 10 %; «получите 3 титана и доберите 2 карты Венеры» —
`stock.titanium: 3` + `drawCard: {count: 2, tag: VENUS}` (поиск по метке). Правила не менялись; работа — премиум-скоуп
и проход всей цепочки глазами на боксе. Промт: `docs/claude/prompts/prelude2-p76-ishtar-expedition.md`.

  Венеры.» (канон требования — `venus_next_cards.json`); имя «Экспедиция Иштар» оставлено.
- `infoText` не нужен: генератор сам засеял три блока (требование · титан · поиск из ОДНОГО дескриптора); RU блока поиска

- Спек `tests/cards/prelude2/IshtarExpedition.spec.ts`: апстримный блок байт в байт + `premium` (17 `it`).
- Фикстуры `ishtar-expedition` / `ishtar-expedition-locked` (соло, Венера + Prelude 2, Teractor, 20 M€; верх колоды
  Ants ✗ → Venusian Insects ✓ → Birds ✗ → Aerial Mappers ✓; сухой прогон в генераторе) и стенд
  `tests/e2e/console-ishtar-expedition.spec.ts` (A — заперта; B — путь целиком; C — перезагрузка посреди стадии).

**Проверено на боксе** (tv4k, `--exclusive --workers=1`, раскадровка `screenshots/p76/tv4k/story-play/`):
плита заперта с причиной «Венера 8/10%», A не шлёт ничего; композер — `0 → 3` титана и «+2 взять · с меткой V», ряд
«Далее» называет поиск, 0 POST до A; розыгрыш — ОДИН POST; крошка «КАРТЫ В РУКЕ › ЭКСПЕДИЦИЯ ИШТАР › РОЗЫГРЫШ →
РАЗЫГРАНО → ДОБОР КАРТ» (корень и карта — те же на каждом сэмпле, хвост только растёт); «+3» титана долетает в ряд
титана с ударом посадки; встроенная стадия «ДОБОР КАРТ» в руке, итог «ВСКРЫТО 4 · ПОЛУЧЕНО 2 · СБРОШЕНО 2 — С МЕТКОЙ V»,
стопка «СБРОШЕННЫЕ 2» под колодой; X открывает осмотр поверх стадии, B — та же стадия; B забирает обе в док, workspace
уходит на доску; сервер 14 M€ / 3 титана / обе карты в руке; журнал — одна запись с дочерней строкой поиска.

**Найдено (не чинилось — решения класса / владельца):**
1. **Награда события рождается на РУБАШКЕ.** Событие сначала ложится рубашкой вверх на стопку «СОБЫТИЯ», и лишь потом
   из неё вылетает «+3» титана (`recv:front`); печатные значки к моменту рождения скрыты. Это задокументированное
   решение класса (`consolePlayedHero` § `heroRewardSourceSelectors`: «An EVENT lands face-down … its rewards emerge
   from the pile — the card's honest on-table location»), не случайность — вынесено владельцу.
2. **Складская награда розыгрыша рождается из центра карты, не из печатного значка** — и у открытой карты: из
   печатного значка рождаются только ресурсы карт (`heroGainOrigin`, TR56 / PL-190); волна рельса
   (`railWaveWithPrintedVp`) берёт общую точку карты. У ACTION COMMIT действий карт складская награда рождается из
   значков — расхождение двух дверей одного закона. На P76 (событие) не видно из-за п. 1.
3. **После перезагрузки** посреди стадии добора пачка показывается отдельной сценой в центральном проёме (с названным
   источником «Экспедиция Иштар» и итогом поиска), а не во встроенной стадии руки — заявка workspace перезагрузку не
   переживает; честная деградация, взятие работает, второй POST розыгрыша не возникает.

**Что даром следующим картам Prelude 2.** Декларативная карта с поиском по метке проходит весь путь без кода: генератор
засевает блок поиска (нужен только RU в `card_info.json` и строка `ACCEPTED` в `cardInformation`, если описание говорит
«draw N X cards»); стенд такой карты — фикстура с ПОСЕЯННОЙ лентой (`stackDeckTop`), иначе лента и стопка не видны.
MarsBot-стол Prelude 2 сегодня отвергает (`automaCompatibility` — §5 дока): серверный спек кладёт карту в руку на
Венера-стол с ботом без опции Prelude 2.
