## Console native mode — the pending-decision COPY contract (`consoleTaskSummary`)

**No pending prompt is ever announced as a bare «Ожидает решения».** The console had THREE parallel labellings of the same pending state — the deferred amber chip (`ConsoleShell` banner band), the command bar's `commandContext`, and `ConsoleTaskHost`'s kicker — and all three hardcoded the SAME context-less string, telling the player THAT a decision is pending but never WHAT it is. `src/client/console/consoleTaskSummary.ts` is now the ONE source of that copy: `consoleTaskSummary(task, view, override?) → {kickerKey, ask, sourceCard?, returnKey}` — the decision TYPE (the chip), the CONCRETE ask, WHO asks, and the context-aware B verb (it absorbed `deferReturnLabel`).

- **PURE + key-based** (mirrors `notificationModel` / `victoryPointsModel` / `effectSummary`): no Vue/DOM/i18n — it emits English i18n KEYS and passes the server's own `string | Message` title through untouched as `ask`; the VIEW translates (`translateText` for a key, `translateMessage` for a Message). That is what lets the guard run under the SERVER test runner.
- **The server title WINS.** It is the most specific already-localized sentence in the system. A per-kind key is used ONLY when the title is boilerplate (`GENERIC_TITLES`: 'Select player' / 'Select colony' / …) or absent — the same carve-out `ConsoleTaskHost.titleText` already made for the card browser, now centralized so chip / bar / host cannot diverge.
- **It reads the markers NOBODY read for copy.** `choiceContext.mode` outranks `.source.kind` (an attack reads «АТАКА» even when a corporation asks; `reward` → «Бонус», never confused with an Award); `venusBonusPrompt` / `spendHeatPrompt` name the two marked `composite` (`and`) shapes — precisely the prompts NO console surface serves, i.e. the ones that read generic hardest; `placementContext.source` / `choiceContext.source.card` supply the source-card chip; `startGamePrompt.kind` splits corp/prelude/pay.
- **`activeTaskSummary` (ConsoleShell) is deliberately built from the RAW `taskFor(view)`**, NOT `hostTask ?? shellTask ?? startTask` — an unserved prompt still deserves a name. The CLIENT-built payment (std-project alt-resource) passes its real prompt via the `override` param, because `view.waitingFor` there still holds the ACTION MENU and would label the payment "Take your next action".
- **Exhaustive over the closed `ConsoleTask` union with a `never` guard — a new `TaskKind` FAILS THE COMPILE until it gets copy.** Only the honest `unknown` guard may return `GENERIC_KICKER`.
- Styles: the two-level chip is `.con-banner__kicker` / `__ask` (ellipsizes; sentence-case, since the band is uppercase) / `__src` under `.con-banner--deferred` in `console.less` (rem + escaped `~"min(58rem, 78vw)"` — LESS owns `min()`). i18n: new keys in `ru/console.json`. Guard: `tests/client/components/console/consoleTaskSummary.spec.ts` re-walks the ROUTER's own fixture table and asserts no row falls back to the generic kicker.

**To add a new console prompt kind:** add the `TaskKind` to `consoleTaskRouter`, then give it a kicker + ask in `consoleTaskSummary` (the compile forces you) and a fixture row in the spec. Never hardcode a label at a call site.
