## Console native mode — the MANDATORY ANNOUNCEMENT GATE (announce → A → open, never auto-pop)

**A mandatory ACTION is ANNOUNCED, not auto-opened.** Console used to mount a mandatory surface the instant `taskFor` classified the prompt — the corp first-action modal popped over the still-running prelude/intake animations, a colony bonus (Pluto: draw then discard) flung the hand discard open, and the between-generations draft workspace stood itself up over whatever the player was reading the moment the phase flipped. The gate (`src/client/console/consoleMandatoryGate.ts`, PURE + a tiny reactive store; unit-tested) turns that into a calm sequence: the surface stays CLOSED (only the player's chip status shows), and once the ordinary-notification feed has completely finished a premium top card **`ConsoleMandatoryAnnounce.vue`** (`.con-mandatory`) names the pending action; **A opens it** (the CTA moved from B to A in the 2026-07-20 unification). NO server change was needed.

- **⚠️ A DRAWN-CARDS REVEAL IS NEVER GATED — it is a cinematic ENDPOINT, not a decision.** The reveal overlay is the continuous end of a draw CINEMATIC: the deck-draw scene (`consoleDeckDraw`) literally *assembles into* it (cards peel off the deck at the `'assemble'` phase and fly into the reveal's own slots; the board-card-bonus scene does the same off a tile/colony). Gating the reveal would SPLIT that one cinematic — the animation plays, then stops mid-flight and demands a B to "review the cards" — the exact abrupt break the gate exists to remove. So the gate covers only genuine DECISION prompts; a reveal always flows straight through. **The load-bearing rule: logically-consecutive steps where the second is the CONTINUATION of the first (an animation flowing into its own surface) are ONE unit — never split with an announcement.** (The Pluto discard IS still gated, because it is a distinct SURFACE — the hand — reached only after the reveal cinematic has fully settled + the card physically landed: a real decision boundary, not a mid-animation split.)
- **The BEAT model — two sources, one deterministic order (2026-08-12).** At any moment there is at most ONE current mandatory action *beat* (`MandatoryBeat` = `{key, taskKind, flow?}`), drawn from: (1) an interruptive TASK beat (`task:<promptIdentityKey>` — one server prompt), else (2) the first pending **FLOW beat** (`MandatoryFlowBeat` — a whole workspace flow the player must OPEN; today the between-generations draft, derived by `draftMandatoryFlowBeat` with the key `draft:gen<N>` — stable across every pick round, the wait and the research buy, so one announce + one open per generation). The shell feeds flows via its `mandatoryFlowBeats` computed; a task beat (the server's immediate demand) always outranks them; among flows the array order decides — one plate at a time, never a visual stack; the next pending action presents only after the current one completes, re-honouring the notification boundary. The gate HOLDS a beat until the player ACKNOWLEDGES it (A); a NEW decision is a new key → held again. A FLOW beat's acknowledge runs its open route in `openMandatoryAnnounce` (`enterWorkspace('draft')`, guarded by `workspaceFrameKnown` — idempotent under a double press); the `draftFrameLive` watcher only CLOSES the frame on its falling edge (the auto-enter is GONE). Pluto flow: [draw → deck-draw → reveal cinematic] flows through untouched → take (the hand counter ticks on the PHYSICAL landing — the hand-intake director's contract) → THEN the discard beat is announced → A → the hand opens in select mode. The reveal and discard arrive in the SAME server response (`DiscardCards` is a separate deferred action, but `cardDrawReveals` + the discard `SelectCard` land together); the discard waits for the reveal client-side (`rawDrawnRevealPending` suppresses the task surface), then is announced.
- **The LIFECYCLE is ASYMMETRIC (pending → presented → acknowledged → gone).** Ordinary notifications and mandatory actions NEVER share a queue: the feed keeps flowing while a pending action waits beside it (no `mandatory-choice` lease is held while a beat is merely held). The FIRST presentation (`mandatoryPresentationReady` → the shell watcher latches `markMandatoryBeatPresented`) waits for the ordinary-notification feed to finish COMPLETELY — `notificationsSettled()` = nothing visible + empty queue + exit animations done (the layer's TransitionGroup leave hooks maintain `notificationState.leaving`; the `turn` singleton is deliberately excluded — it mirrors `waitingFor` itself and would deadlock) — plus `!presentationHeld`, `!isAnimationHoldActive()`, no reveal/heroes. Deliberately NOT gated on location: the moment is one; WHERE the player stands picks the FORM (plate on the board home via `mandatoryAnnounceVisible`, chip beacon elsewhere via `mandatoryChipAttention` — both read the shared `mandatoryActionPresented`). ONCE PRESENTED the action is a STANDING state: later notifications show beside it and can no longer hide the plate, re-queue it or replay its entrance — post-presentation the plate yields only to the player's own location (`boardHomeIdle`) and the viewer's own full-bleed cinematics (reveal / played hero / tile hero). A DEFERRED task counts as presented (the player opened it themselves). Input stays disjoint by construction: the plate claims only A (checked before the toast branch), a toast claims only B + hold-X — a new toast can neither trigger A nor lose the plate. Latches die with their beat (`noteMandatoryBeatIdentity`, driven by the shell's `mandatoryBeatKey` watcher): an answered/invalidated action leaves nothing stale (no empty transition), and the SAME key re-arising later (an admin rollback replaying the same generation's draft) runs a FRESH pending → presented → open cycle instead of silently inheriting an old acknowledgment (which would leave a prompt nobody can open — the workspace no longer auto-enters).
- **SCOPE (Option A — "all interruptive / triggered").** `isInterruptiveMandatoryTask(task, forcedReaction)`: `corpFirstAction` + `handSelect` (forced hand pick) are ALWAYS gated; the host sub-prompts (`choice`/`player`/`amount`/`resource`/`distribute`/`payment`/`projectCard`/`colony`/`composite`) are gated ONLY when the viewer's status is an OFF-TURN forced reaction (`actionLabelForPlayer(...) === 'forcedaction'` — the canonical player-status classifier, so the gate and the chip can't disagree). The viewer's OWN turn is NEVER gated — the action menu, a tile placement after their own play (`space`), a composer they opened, `cardSelect`/draft/start-scene flows — those open immediately. **A task announcement can NEVER appear mid-animation** — `mandatoryAnnounceVisible` requires `!isAnimationHoldActive()` — so a decision never interrupts a scene either.
- **Surface suppression (while held).** The gate makes the task surfaces think the prompt isn't shown yet: `shellTask` / `activeConsoleTask` (host) return `undefined` while `taskGateHeld` (so `corpFirstActionOpen`, the hand-select section, the task host all stay closed and `openShellTaskSurface` isn't auto-called). `consoleRevealMode` is NOT gated (the reveal always flows). `rawDrawnRevealPending` (currentRevealEvent minus the tile/deck holds) still suppresses `shellTask`/`activeConsoleTask`/`startTask` so the Pluto discard waits for the WHOLE reveal to be taken. The desktop `<waiting-for>` fallback stays suppressed throughout (host prompts via `hostServesPrompt` = raw `taskServedByHost`; shell/corp via WaitingFor's own routing).
- **Visibility + open.** `mandatoryAnnounceVisible` = held AND the player is on the MAIN board home (`section === 'board'`, no sheet/quick/confirm/journal/zoom/fallback/inspection/placement, no animation hold / hero / theater / gov-scale) — matching "closed the screen / finished the animations". While held but not-yet-visible (mid-animation, in another section) the player sees only their chip status. `handleIntent`'s announcement branch (placed BEFORE the toast-dismiss, so the mandatory decision wins B over a transient toast) calls `openMandatoryAnnounce()` on B → `acknowledgeMandatoryBeat` + (for a shell-section task) `openShellTaskSurface`; a host/corp beat auto-mounts once its suppression clears. The board-home command run gains a `{control:'back', label: Open}` while announced.
- **Leak detector.** `isMandatoryGateHeld()` (a shell-mirrored flag, since the detector runs on a timer and can't recompute the shell signals) → the held prompt is legitimately served (the announcement / chip is its surface), never stranded; `.con-mandatory` is also in `SERVING_SURFACES`.
- **«СВЕРНУТЬ» IS A ROUND TRIP — the same card serves both halves, and its predicate must cover every family that offers the verb (2026-08-13).** A surface that advertises minimize carries `!consoleState.task.deferred` in its own `v-if`, so B unmounts it and the board-home `.con-mandatory` card is the ONLY door back (A restores; B on the board home reads the SAME `mandatoryDeferredActive`, deliberately last among the "go somewhere" branches). A family missing from that predicate is therefore a SOFT-LOCK, and a SILENT one — a deferred task is deliberately invisible to the leak detector (`setConsoleTaskDeferred` → `clearStranded`), so nothing shouts and only a reload recovers. That shipped for the whole DEDICATED COMPOSITE family (`NATIVE_COMPOSITE_KINDS` — the Venus alt-track bonus, Stormcraft's spend-heat, the planetary thresholds, «оставь K из N»): the predicate enumerated the task host, the shell sections and the start scene, and these belong to none of the three, so «Разместите бонус шкалы Венеры» → B was unrecoverable for the rest of the session. Now `mandatoryDeferredActive` reads `minimizableTaskLive` (host ?? shell ?? start ?? composite, each with its own admission gate) gated by **`taskMinimizable(kind)`** in `consoleTaskRouter.ts` — exhaustive over `TaskKind`, so a new kind does not compile until it declares whether it can be folded away, and `consoleTaskRouter.spec.ts` asserts «minimizable ⇔ some family claims it» over the full fixture table. e2e: `console-composite-surfaces.spec.ts` (minimize → the card names the bonus → A → the same stage returns).
- **A VISIBLE SURFACE MUST HOLD THE LEASE — the converse of "a lease is a claim that something renders".** The same composite family took no `mandatory-choice` lease while it was on screen, and `mandatoryPromptsHeld` lets a flow-holding bot-turn card hold prompts only while `mandatoryLeases === 0` (its documented fixed point: "with a surface up the hold is off and the surface stays"). Since these surfaces are gated on the very `admits('host')` that hold feeds, a bot card arriving over them UNMOUNTED them for its whole TTL. `consoleMandatoryPresenting` now includes `compositeSurfaceActive` (the four surfaces' own `v-if`s, collected once and reused by `journalHardBlocked` too — all four already register roots in `SERVING_SURFACES`, so the foreground watchdog still sees them).
- **To extend:** a new interruptive prompt kind → add it to `ALWAYS_INTERRUPTIVE` or `FORCED_REACTION_INTERRUPTIVE` in `consoleMandatoryGate.ts` (+ a fixture row in `tests/client/components/console/consoleMandatoryGate.spec.ts`). A new MUST-OPEN workspace flow → a `MandatoryFlowKind` value + a pure derivation in its own flow module (the pattern: `draftMandatoryFlowBeat`) + the shell's `mandatoryFlowBeats` array + an open-route branch in `openMandatoryAnnounce` — never an auto-`enterWorkspace` watcher. NEVER add a cinematic endpoint (a reveal-like surface an animation flows into) to the gate — that would re-introduce the split. The kicker/ask REUSE `consoleTaskSummary` (the draft plate names its live stage — pick / wait / buy — for free). Reset the gate on game switch (`resetMandatoryGate()` in ConsoleShell mount/unmount). Tests: `consoleMandatoryGate.spec.ts` (scope + beat derivation incl. flow order + held/ack + presented latch + identity invalidation), `notificationState.spec.ts` (the settled signal + leave tracking), `consoleDraftFlow.spec.ts` (the draft's pending-action derivation), e2e `console-draft-workspace.spec.ts` (plate → A → workspace, incl. the reload restore).
