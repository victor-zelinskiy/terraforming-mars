## Console native mode — the MANDATORY ANNOUNCEMENT GATE (announce → B → open, never auto-pop)

**An INTERRUPTIVE mandatory DECISION is ANNOUNCED, not auto-opened.** Console used to mount a mandatory surface the instant `taskFor` classified the prompt — the corp first-action modal popped over the still-running prelude/intake animations, and a colony bonus (Pluto: draw then discard) flung the hand discard open. The gate (`src/client/console/consoleMandatoryGate.ts`, PURE + a tiny reactive store; unit-tested) turns that into a calm sequence: the surface stays CLOSED (only the player's chip status shows), and once the foreground is idle (screens closed, animations done) a premium top card **`ConsoleMandatoryAnnounce.vue`** (`.con-mandatory`) names the decision; **B opens it**. NO server change was needed.

- **⚠️ A DRAWN-CARDS REVEAL IS NEVER GATED — it is a cinematic ENDPOINT, not a decision.** The reveal overlay is the continuous end of a draw CINEMATIC: the deck-draw scene (`consoleDeckDraw`) literally *assembles into* it (cards peel off the deck at the `'assemble'` phase and fly into the reveal's own slots; the board-card-bonus scene does the same off a tile/colony). Gating the reveal would SPLIT that one cinematic — the animation plays, then stops mid-flight and demands a B to "review the cards" — the exact abrupt break the gate exists to remove. So the gate covers only genuine DECISION prompts; a reveal always flows straight through. **The load-bearing rule: logically-consecutive steps where the second is the CONTINUATION of the first (an animation flowing into its own surface) are ONE unit — never split with an announcement.** (The Pluto discard IS still gated, because it is a distinct SURFACE — the hand — reached only after the reveal cinematic has fully settled + the card physically landed: a real decision boundary, not a mid-animation split.)
- **The BEAT model.** At any moment there is at most ONE current interruptive mandatory DECISION *beat* (`MandatoryBeat` = `{key, taskKind}`). The gate HOLDS a beat until the player ACKNOWLEDGES it (B), keyed by a stable `beat.key` (`task:<type|title>`); a NEW decision is a new key → held again. Pluto flow: [draw → deck-draw → reveal cinematic] flows through untouched → take (the hand counter ticks on the PHYSICAL landing — the hand-intake director's contract) → THEN the discard beat is announced → B → the hand opens in select mode. The reveal and discard arrive in the SAME server response (`DiscardCards` is a separate deferred action, but `cardDrawReveals` + the discard `SelectCard` land together); the discard waits for the reveal client-side (`rawDrawnRevealPending` suppresses the task surface), then is announced.
- **SCOPE (Option A — "all interruptive / triggered").** `isInterruptiveMandatoryTask(task, forcedReaction)`: `corpFirstAction` + `handSelect` (forced hand pick) are ALWAYS gated; the host sub-prompts (`choice`/`player`/`amount`/`resource`/`distribute`/`payment`/`projectCard`/`colony`/`composite`) are gated ONLY when the viewer's status is an OFF-TURN forced reaction (`actionLabelForPlayer(...) === 'forcedaction'` — the canonical player-status classifier, so the gate and the chip can't disagree). The viewer's OWN turn is NEVER gated — the action menu, a tile placement after their own play (`space`), a composer they opened, `cardSelect`/draft/start-scene flows — those open immediately. **A task announcement can NEVER appear mid-animation** — `mandatoryAnnounceVisible` requires `!isAnimationHoldActive()` — so a decision never interrupts a scene either.
- **Surface suppression (while held).** The gate makes the task surfaces think the prompt isn't shown yet: `shellTask` / `activeConsoleTask` (host) return `undefined` while `taskGateHeld` (so `corpFirstActionOpen`, the hand-select section, the task host all stay closed and `openShellTaskSurface` isn't auto-called). `consoleRevealMode` is NOT gated (the reveal always flows). `rawDrawnRevealPending` (currentRevealEvent minus the tile/deck holds) still suppresses `shellTask`/`activeConsoleTask`/`startTask` so the Pluto discard waits for the WHOLE reveal to be taken. The desktop `<waiting-for>` fallback stays suppressed throughout (host prompts via `hostServesPrompt` = raw `taskServedByHost`; shell/corp via WaitingFor's own routing).
- **Visibility + open.** `mandatoryAnnounceVisible` = held AND the player is on the MAIN board home (`section === 'board'`, no sheet/quick/confirm/journal/zoom/fallback/inspection/placement, no animation hold / hero / theater / gov-scale) — matching "closed the screen / finished the animations". While held but not-yet-visible (mid-animation, in another section) the player sees only their chip status. `handleIntent`'s announcement branch (placed BEFORE the toast-dismiss, so the mandatory decision wins B over a transient toast) calls `openMandatoryAnnounce()` on B → `acknowledgeMandatoryBeat` + (for a shell-section task) `openShellTaskSurface`; a host/corp beat auto-mounts once its suppression clears. The board-home command run gains a `{control:'back', label: Open}` while announced.
- **Leak detector.** `isMandatoryGateHeld()` (a shell-mirrored flag, since the detector runs on a timer and can't recompute the shell signals) → the held prompt is legitimately served (the announcement / chip is its surface), never stranded; `.con-mandatory` is also in `SERVING_SURFACES`.
- **To extend:** a new interruptive prompt kind → add it to `ALWAYS_INTERRUPTIVE` or `FORCED_REACTION_INTERRUPTIVE` in `consoleMandatoryGate.ts` (+ a fixture row in `tests/client/components/console/consoleMandatoryGate.spec.ts`). NEVER add a cinematic endpoint (a reveal-like surface an animation flows into) to the gate — that would re-introduce the split. The kicker/ask REUSE `consoleTaskSummary` (the same copy the deferred amber chip uses). Reset the gate on game switch (`resetMandatoryGate()` in ConsoleShell mount/unmount). Tests: `consoleMandatoryGate.spec.ts` (scope + decision-beat derivation + held/ack lifecycle) + the gate-held stranded-guard case in `consoleCorpFirstAction.spec.ts`.
