## Console SURFACE MOTION — band-surface transition orchestration (read docs/CONSOLE_SURFACE_MOTION.md before touching a console modal's mount/unmount)

The console band surfaces transition through ONE orchestration layer — `src/client/console/surfaceMotion/` (`surfaceMotionModel.ts` PURE vocabulary+awaiting contract, unit-tested; `surfaceMotionState.ts` reactive store + DOM captures; `surfaceMotionDirector.ts` GSAP runtime behind Vue `<transition :css="false">` hooks). MIGRATED (waves 1–2): quick wheels, card-actions (+action composer), std-projects, task host, reveal, play-composer, corp-first, the Пас/convert `confirm`, trade-composer, ma-confirm, both inspects, gov-support, production-loss — full dim on the shade; `ma-screen`/`sheet`/`info-mode`/`section` (colonies+hydro) animate through the director but keep their OWN dim policy (`NON_SHADE_OWNERS`). NOT migrated by design: start scene, draft tray, mandatory announce, played overlay, stranded/alert, the journal, the hydro section's INNER layers (`.con-hydroconfirm`/`.con-hydro__help` — child mounts outside the hooks, own local dim+entry). Load-bearing invariants:
- **ONE shared shade** (`.con-shade`, z 11460, CSS-opacity-only) dims behind every MIGRATED band surface; owners register in the director's enter/leave hooks, so a swap keeps continuous darkness (never stacked dims / a blink through zero). Migrated surfaces render NO own `__backdrop` div and their dead CSS rules are DELETED — **⚠ before deleting such a rule always grep the `.vue`s: chassis classes are SHARED** (`.con-task-host__backdrop` was also rendered by trade/maconfirm/colinspect; `.con-composer__backdrop` by play/corpfirst — both regressed to dim-less once before being caught). `NON_SHADE_OWNERS` = child layers whose parent already owns + own-dim-by-design surfaces — a child's leave hook never fires on a parent unmount, so child ownership would LEAK. Dynamic shade suppressors (the `pickSuppressed` symmetry): `revealVeilSuppressed` (a scene-VEILED reveal — board-bonus/deck-draw/colony-trade fly their cards over an undimmed field; the overlay reports `bonusVeiled`) and the trade-fleet flight holds the THIN `--veil` tier (`surfaceShadeVisible/Veil |= isTradeFleetActive()` — replaces the retired `--launching` backdrop rule).
- **Markup contract:** `data-motion-surface="<id>"` on the root (no attribute → hooks pass through untouched — the gradual-migration path; MA screen + generic sheet are deliberately unmigrated, their light dims are design), `data-motion-panel` on the animated panel (leave animates ALL panels under the root — a departing center carries its open composer), `data-motion-anchor="card:<name>"` on phase-FLIP anchors, `data-motion-variant` gates the reveal (headless = no shade/motion; drawn = shade only, its draw cinematic owns the choreography).
- **PHASE pairs** (`PHASE_PAIRS`: composer→reveal, composer/card-actions/play-composer→task-host [the Helion follow-up-payment case], reveal↔task-host) continue ONE operation: panel enters as a recompose, anchors FLIP from the captured departing rects (**zoom-compensated**: `effZoom = rect.width/offsetWidth` — transform px inside a CSS `zoom:` context are rescaled by the browser; uncompensated FLIPs undershoot on TV). The awaiting-resolve captures the departure UNCONDITIONALLY (`departureUsable` filters by the pair table). The departing side blanks its own anchors while a FLIP is live (`isAnchorHandoffLive`) — the travelling card never doubles.
- **AWAITING handoff (semantic commit):** the action composer's confirm NO LONGER closes it — `beginAwaitingHandoff` holds the stage (CTA «Выполняется…»), `handleIntent` absorbs ALL input (below the system-alert branch), and the `playerView` PRE-FLUSH watcher resolves via the pure `resolveAwaiting`: reveal → capture the old DOM + `closeConsoleLayers()` in the same patch (phase FLIP, no blank frame); a game step without a reveal → dismiss; same view (poll) → hold; safety = `AWAITING_SAFETY_MS` + a shell timer. NEVER re-close the composer at submit time — that re-opens the "confirm → bare board → reveal" gap this kills.
- **Wheel handoff:** `activateQuickSlot` marks the chosen slot (`markWheelHandoff`) before closing — the leave flashes it, the target surface enters FROM its direction (`wheelOrigin`, fresh ≤700ms). Wheel timings are mechanical (120/95ms); input routing is untouched.
- **The pick bridge is never animated:** v-show hides (hand/tableau pick) set `data-motion-pick-hidden`; the flip back is recognized as a re-show → instant. Every hook is episode-guarded + safety-timed (`done()` guaranteed); reduced motion = short functional fade, no travel/FLIP, unchanged semantics/order.
- **To migrate the next surface / add a phase pair:** the 6-step checklist at the end of `docs/CONSOLE_SURFACE_MOTION.md`. Guards: `tests/client/components/console/surfaceMotionModel.spec.ts` (23) + the e2e drive `tests/e2e/console-surface-motion.spec.ts` (fhd + tv4k, live anti-blink shade probes through both handoffs).


## The COLONY WORKSPACE ENTRY — one phrase, two doors (2026-08-12)

The colonies GRID (the overview) arrives through two doors and both speak ONE phrase — `colonyEntryCascade` (`consoleColonyFocusMotion.ts`): the colony ISLANDS surface in reading order (a short no-travel rise, `expo.out`, whole-wave spread capped so a 12-tile catalog is no slower than 6 tiles), each island's PLANET arrives into its berth a beat later (SCALE-only — the tiles live inside a CSS `zoom:` context where translate-px would be rescaled), the fleet dock settles from above, the one-line status rail seats LAST (words after objects). Perf-lite safe (transform/opacity only), reduced motion = the callers' own short fades.

- **Standalone door** (wheel «Торговля» / std-project pick / self-heal): the workspace-family materialize in `surfaceMotionDirector.enterSurface` + the shared cascade from `contentCascade('section')`. ⚠ **The root-selector trap that kept this branch dead for its whole life:** the section root ITSELF is `.con-colonies` (it carries `data-motion-surface`), and `el.querySelector('.con-colonies')` matches DESCENDANTS only — so the guard never matched, the whole cascade silently no-op'd, and the workspace arrived as a bare 210 ms panel fade («колонии просто появляются» from the wheel). When a cascade branch keys on the surface's own class, test `el.classList.contains(...)` first and fall back to `querySelector` for wrapped roots. (Found by the entry probe, not by eye — a dead cascade still "animates" via the panel fade.)
- **Embedded door** (a SelectColony hosted as a step — the solo setup removal and Poseidon's build inside «Старт партии», a played card's build inside the hand): `playColonyStepEntry` — the step's room opens by clip (the frame is never scaled, so the host's chrome cannot drift), then the same cascade. The hooks-era note in `ConsoleShell.vue` stands: the `data-motion-surface` attribute is STRIPPED while embedded, the director passes through, and the section's own `mounted()` owns the arrival.
- **The DOUBLE-PLAYED ENTRY (the «колонии мигают» at game start), fixed at the cause:** the start's queue plays arm the played hero with `host: 'workspace'`, and the hero's `'closing'` beat used to guard its `goBoardHome()` with `workspaceFrameHasNested('hand')` ONLY. A SelectColony that rode the play's own response had already pushed `start ⊃ colonies` (prompt-anchored); the closing beat truncated it, the stranded-colony self-heal re-pushed it a tick later, and the section REMOUNTED — the entry played twice, ~0.5 s apart. The guard now asks the one sanctioned question for BOTH scenery hosts: `workspaceFrameHasNested('hand') || workspaceFrameHasNested('start')`. General law: **a play's completion beat may never unwind frames a LATER prompt already stood up** — if the workspace it ran in is hosting anything, the beat keeps its hands off the stack.

Guard: `tests/e2e/console-colony-entry-probe.spec.ts` — drives both doors, samples the arrival per-frame from inside the page, and fails on: no visible ramp (a dead cascade / bare pop), any dip after the grid fully showed (the replayed-entry blink), a remount during the arrival, or a fit-scale change mid-entrance.
