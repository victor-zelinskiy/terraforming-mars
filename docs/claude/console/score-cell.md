# ЯЧЕЙКА ПО — КАЖДОЕ ОЧКО ИЗ СВОЕЙ ПРИЧИНЫ

Контракт ячейки «ПО» рельса (TR55 «Утилизация ядерных боеголовок», 2026-10-15). Его наследует любая будущая
карта и любой новый источник очков. Код: `src/common/game/vpAttribution.ts` (атрибуция),
`src/client/console/scoreCell/` (реестр долей, слова причины, хост вех и наград), хосты в сценах.

## Закон

Ячейка ПО — такой же счётчик, как любой другой, и подчиняется закону **физической причинности**: она
меняется **на касании жетона «±N ПО»**, рождённого в источнике (печатный значок ПО севшей карты, тайл, «+5»
вехи, гнездо эмблемы награды, капсула карты), или — когда у источника нет тела на этом экране — **с названной
причиной на том же экране** (ярлык под шапкой счёта). Никогда в кадре применения вида.

## Как это устроено

1. **Атрибуция — одна чистая функция над разбором сервера.** `vpAttribution(before, after)` вычитает два
   `VictoryPointsBreakdown` по компонентам: строка карты (`detailsCards`, по имени; псевдо-строки «Colony VP»,
   «Turmoil Points», «Underworld Corruption Bribe» — `other`), клетка города (`detailsCities`, ярусы стопки
   суммируются), озеленения, веха и награда по имени (с местами «до → после»), РТ (`rating`), скалярные
   компоненты (`other:<ключ>`). **Сумма долей = разность итога** — остаток одна честная доля
   `other:unattributed`. Клиент ничего не пересчитывает. Неоднозначность названа в шапке модуля: ход «вверх и
   обратно» внутри одного ответа даёт ноль и доли не даёт (экран промежуточного значения не видел). Спек на
   реальных играх: `tests/common/game/vpAttribution.spec.ts`.
2. **Жетон ПО — один вид в общем механизме переноса.** `{channel: 'stock', resource: VP_RAIL_KEY}`
   (`vpTransferSpec(points)` — потеря идёт тем же жетоном назад, уход боком — PL-104). Удержание —
   **единственное** удержание ПО панели (`panelRewardHold.vp` / `vpLoss`, через `beginPanelRewardHold` /
   `releasePanelRewardHold`), адрес — чернила ячейки (`.con-score__cell--vp .con-score__value`, PL-094),
   лицо — золотой щит `ConsoleVpBadge` с «±N» на золотой посадке (`.con-transfer__chip--vp`, без `filter` и
   `text-shadow`), удар контакта — золото ячейки (`.con-transfer__beat--vp`).
3. **Реестр долей** (`scoreCell/vpShareLedger.ts`):
   - **Претензии хостов.** Хост при арме заявляет, какие доли он покажет (`claimVpShares(owner, match, rank)`).
     Ранг решает спор: розыгрыш карты (10) выше тайла (1). Заявка «на касании» (`releaseOnLanding`) отпускает
     долю карты на касании первого жетона карточного ресурса на эту карту (такт контакта
     `noteCardResourceLanding` — и при деградации).
   - **Засев** (`seedVpShares(before, after)`) — **последним** в apply-блоке (`gameTransport.seedRewardHolds`
     для своего сабмита, `App.update` для опроса / WS): атрибуция; РТ исключён (это дело ячейки РТ и её
     жетонов); то, что держат другие писатели в этом ответе, **вычитается** (`noteVpHeldElsewhere` — `railReward`
     с ПО ресурса карты, городские выплаты; расхождение их клиентского счёта с атрибуцией названо в трассе —
     К-V3); доля под претензией удерживается, **любая другая тикает сейчас и называет причину**.
   - **Отпуск.** Хост летит (`flyVpShares` — жетон из измеренного источника; нет источника — отпуск с названной
     причиной), или отпускает в своей концовке (с названием; `named: false` — только когда причиной был сам
     жетон ресурса). Потолок удержания — `VP_SHARE_CEILING_MS` (20 с, с названием). Холд `vp-shares` —
     уведомительный, не блокирующий. Общий сброс сцены (`clearPanelRewardHold`) удержания реестра **не трогает**
     (хранитель `registerPanelVpKeeper`).
4. **Маски.** Приватный счёт (`shouldMaskOwnPassiveVp`) — реестр не сеет ничего: ни удержания, ни жетона, ни
   причины. Счёт соперника — не дело реестра (только своё место). Reduced motion — ничего не держится, каждая
   доля названа.
5. **Слова причины** (`scoreCell/vpReasonText.ts`, единый рендерер чтений PL-160): «+1 ПО · Капитолий»,
   «−3 · Награда «Собственник»: место 1 → 2», «Ваш город: соседние озеленения», «Веха «Мэр»». Не больше двух
   строк + «ещё N»; один раз на 2,8 с; ярлык под шапкой счёта вне потока.

## Хосты и источники

| Источник | Хост | Жетон / причина |
| --- | --- | --- |
| Печатные ПО розыгрыша | `consolePlayedHero` (`PLAYED_HERO_VP_OWNER`, ранг 10) | жетон с `.pcard__vp` севшей карты (событие — из рубашки стопки), значок «нажимается» (`data-vp-emit`); порядок: свои выигрыши → печатные ПО → реакции стола → РТ последним |
| Ресурс розыгрыша на свою другую карту / реакция | `consolePlayedHero` | доля карты отпускается на касании её последнего жетона ресурса |
| Staged-розыгрыш (карта + тайл) | `stagedPlay` (`STAGED_PLAY_VP_OWNER`, ранг 10) | жетон из поставленного тайла после выигрышей карты (класс «печати» — карта уже не на экране) |
| Действие с ресурсом на карту | `consoleActionCommitRail` (`ACTION_COMMIT_VP_OWNER`, ранг 5, «на касании») | ПО — на касании жетона ресурса в капсулу (К-V2: превью не несёт `vpBox` своей карты) |
| Свой тайл | `consoleTilePlacement` (`TILE_VP_OWNER`, ранг 1, `isBoardVpShare`) | жетон из поставленного тайла после всех выплат клетки |
| Чужой тайл (соперник, бот) | `consoleRemotePlacement` (`REMOTE_TILE_VP_OWNER`, ранг 1) | доли ждут касания чужого тайла; жетон из ближайшей севшей клетки; окно 8 с для бота, чей вид применяется последним ходом |
| Веха / финансирование награды | `scoreCell/maVp.ts` (`MA_VP_OWNER`, ранг 5) | жетон с «+5» церемонии / гнезда эмблемы; поверхность уходит после «попа» |
| Перераспределение награды, ПО за метки чужой карты и всё без тела | — | тик с названной причиной |
| Старт партии | `ConsoleResourcePanel.vp()` | ячейка ПО ставится вместе со ставкой РТ раскрытия (К-V6) |

«Доска» для тайловых хостов — `isBoardVpShare`: клетка города, озеленения и карта, чья строка **читает поле**
(`vpCardReadsBoard` — механика сервера: города, океаны, соседство, Луна, особое правило, штраф без формулы).
Карта, считающая свои ресурсы или метки, тайлу не принадлежит.

## Не сделано (записано)

- **Информация (Y)** читает сырой разбор по категориям: во время полёта рельс и панель Информации расходятся
  на сумму в воздухе (К-V7). Категорийная модель (`buildLiveScoreModel`) не умеет «удержать» долю без
  пересчёта сумм категорий — строка реестра.
- **Потери от атак** человека по животным: у жертвы нет полёта ресурса вовсе — её доля карты тикает с
  названной причиной (отдельная итерация).
- **Staged-розыгрыш с голосованием / колонией** (TR03, TR07): ПО карты не заявлены — тик с причиной.
- **Ресурсы на карты с ПО от Парламента / колоний / Гидросети** вне живого пика — тик с причиной. (Живой пик TR53 и
  выплата резолюции держат сам коммит до касания — там ячейка уже тикает после причины.)
- **Дуга жетона к верхней ячейке** проходит над крошкой полосы на 4K (PL-442) — общая дуга `toss`.
