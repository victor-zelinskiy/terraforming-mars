## Console TV display profile (`con-profile-tv` — the living-room 4K recomposition, TV-3)

**The 4th layout profile `tv`** (flagship: LG OLED42C34LA — 42" 3840×2160 16:9 OLED, couch ~1.5–2 m; architecturally any ~40–48" 16:9 TV / 4K monitor). Selection priority: user pick (main menu → «Настройки» → «Дисплей» — `ConsoleOptionsPanel`, cycles Auto→Handheld→Standard→Large→TV 4K, persists to `tm_console_profile`) → `?consoleProfile=tv|auto` → the PHYSICAL-panel heuristic in `consoleLayoutProfile.ts` (`explainProfile`: ~16:9 aspect + physical height ≥2000 [screen×dpr] + window covers the screen — **the physical gate runs BEFORE the small-viewport handheld rule**, so a 4K panel resolves `tv` at ANY OS scale: 3840×2160@100%, 2560×1440@150%, 1920×1080@200%, 1280×720@300% (the ROG XG32UQ case), while a real Deck [physical 800 rows] stays handheld; desktop 1440p stays `large`, 16:10 panels never match; a bare 1080p output is NOT auto-promoted — use the picker). The scale follows the viewport HONESTLY below 1 too (`clamp(min(vw/1920, vh/1080), 0.4, 2.5)` — a 300%-scaled viewport is SMALLER than the logical space; a floor above it physically cannot fit and overflows). Diagnostics: the Options panel shows profile/viewport/panel/DPR/scale/reason live; every decision logs one `[console-display]` line; Electron adds authoritative panel data via `desktopBridge.getDisplayInfo()` (`desktop:getDisplayInfo` IPC).

**The scale model (three layers — never a root transform / browser zoom):**
1. **Logical space.** ALL console-native stylesheets (`console*.less`) are authored in **rem** (1rem = 20px logical — spectre's rem base, pinned by `html.console-native { font-size: 20px }`), i.e. a 1920×1080 logical layout. `html.console-native.con-profile-tv { font-size: calc(20px * var(--con-ui-scale)) }` maps it onto the viewport; `--con-ui-scale` = clamp(min(vw/1920, vh/1080), 0.4, 2.5), owned by `consoleLayoutProfile.syncDisplayCssVars` with the JS mirror `conUiScale()` / `consoleLayoutState.uiScale` — the two can never diverge. JS geometry (GSAP FLIP directors, fit engines, ensureVisible) keeps working untouched: computed values stay plain px. **NEW console styles must be written in rem** (`scripts/console-px-to-rem.mjs` re-converts px that arrive via merges; a `keep-px` line marker exempts genuinely physical sizes). **Two rem-model traps (both shipped as bugs once — don't repeat):** (a) a JS reader of a length-valued custom property MUST resolve through `cssUnits.cssLengthPx()` — `getComputedStyle().getPropertyValue('--x')` returns the UNRESOLVED `"18.3rem"` string and a bare `parseFloat` reads it as 18.3px (this collapsed the colonies grid); (b) anything positioned INSIDE the planet's `transform: scale(var(--board-scale))` px-space (off-Mars `.board-space-XX` margins, the cell spotlight inset, the arc-marker ring) stays **px + `keep-px`** — rem there drifts against the px-authored hexes and breaks the board's union-bbox self-calibration (tiles crept onto the planet, the board de-centred).
2. **Embedded px content** (premium card faces, benefit glyphs, TagCount clusters, BoardFactGroups, card graphics) integrates through `zoom:` — every FIXED zoom on such content multiplies by `var(--con-ui-scale, 1)` (see `scripts/console-tv-zoom-scale.mjs` for the audited list; counter-zooms inside already-zoomed slots and rem-text nudges are deliberately NOT multiplied). JS fit engines' px knobs (hand-grid gaps/zoom ceilings, colonies gaps, task-host/start-scene strip ceilings+floors+CHROME, deal DECK_SCALE, scroll steps, director offsets, boardCardBonus presentation clamps, trade-fleet arc lifts) multiply by `conUiScale()` — a new px constant in console JS must do the same or cards stop growing on 4K.
3. **The design pass** — `src/styles/console_tv.less`: central tokens (`--con-t-hero/…/-floor` couch type scale 44/36/29/23/20/17/16 logical px; `--con-safe-x/y` ≈3.2% clamped safe area consumed by `.con-root` + every floating layer — ONE source, never a second nested inset; `--con-focus-ring`, `--con-hit-min` 64, `--con-cta-h`), per-screen recompositions (wider inspector/journal-with-capped-line-length/modal caps, hit-min rows, stronger focus rings on the browse surfaces), and the legacy fallback surfaces riding `zoom: var(--con-ui-scale)` (mandatory modal / endgame / rematch — the same integration the handheld profile uses). A new console screen gets its TV block here.

Regression contract: rem@20px is byte-identical on handheld/standard/large (verified by denormalizing the compiled CSS); `GamepadLayer` strips all four `con-profile-*` classes when switching. Tests: `tests/client/components/console/consoleLayoutProfile.spec.ts` (heuristic + scale). Screenshot matrix: `tests/e2e/tv-profile-screens.spec.ts` (server on 8080 + built client) → `screenshots/tv-profile/<preset>/` for tv-4k / tv-os200 / tv-1080 / deck-handheld / standard-1080.
