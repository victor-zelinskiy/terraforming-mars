## Console Native Foundation (VueUse layer) — read docs/CONSOLE_FOUNDATION.md before console work

The console flow has a FOUNDATION layer on **@vueuse/core@14.3.0** (`src/client/console/composables/` + `src/client/components/console/foundation/` + `src/styles/console_foundation.less`; full rules in `docs/CONSOLE_FOUNDATION.md`). The non-negotiables:

- **Semantic input, never raw events.** Physical input → `GamepadIntent` (gamepadPollModel) → `ConsoleAction` (`consoleActionModel.ts` — `primary`/`back`/`inspect`/`fullscreen`/`prevSection`/…; per-screen `overrides` re-label controls contextually). The ONE keyboard map lives there too; the GLOBAL `consoleKeyBridge` (installed by GamepadLayer while console mode is on) synthesizes keyboard into the same `dispatchConsoleIntent` slot for the WHOLE flow — pre-game AND in-game. NEVER add a component-local `keydown` listener or a new physical binding at a call site; new screens use `useConsoleInput({onAction, onNav, overrides})`, existing ones migrate to `consoleActionOf(intent)` matching (pilot: ConsoleMainMenu). `useGamepad`/`useMagicKeys` from VueUse are deliberately NOT used (own poll model is stronger; see the doc) — don't introduce them.
- **Overflow policy: a browser-native scrollbar in console-native is a BUG.** Every console-native SCREEN root (owns the viewport) calls `useConsoleNativeSurface()` in `setup()` → refcounted `html.console-native` (html/body/#app locked to `overflow:hidden`) + VueUse body scroll-lock (wired: ConsoleShell, ConsoleMainMenu, ConsoleCreateGame). The class is deliberately NARROWER than `console-mode` — legacy join/lobby pages still window-scroll until migrated. Content that doesn't fit lives ONLY inside `ConsoleScrollArea.vue` (hidden native chrome + custom cyan rail; `ensureVisible(el)` keeps the pad cursor in view, `scrollByPx` for right-stick, `contentClass`/`fill` for markup-only migration of legacy `overflow-y:auto` containers) — never a hand-rolled `overflow-y: auto`. Animations follow the `.con-motion-clip` (outer clip) + `.con-motion-layer` (inner transform/opacity) pattern; `transition: all` and width/height/top/left animation are banned in console-native code. The dev-only `consoleOverflowGuard` (auto in dev, `?conOverflow=1` in prod) warns with top offenders when the page overflows — treat every `[console-overflow]` warn as a bug.
- **Viewport / reduced motion:** read `useConsoleViewport()` (width/height/profile/isHandheld/isLarge/isTv/uiScale/isPortrait) — no manual `matchMedia`/`innerWidth`/resize listeners; JS-side reduced-motion comes from `useConsoleReducedMotion()` / `consoleReducedMotionActive()` / `consoleMotionMs(base)` (CSS media queries unchanged). `useConsoleFocusFrame` is the reserved measured-rect provider for the future moving selection frame.
