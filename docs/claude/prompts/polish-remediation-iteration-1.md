Следствия: (1) полировка, породившая новый шов / ложь / регрессию, — хуже исходной слабости: доделать до концепции или откатить, половины не
бывает; (2) у каждого полёта ОБА конца ВИДИМЫ в свой момент (источник — при рождении и до отрыва, адресат — при посадке); накрытый, гаснущий
или размонтированный конец = полёта от / к нему НЕТ — такт переселяется на видимого дублёра того же объекта или честно деградирует до тика со
своим дельта-чипом; **«измерим» ≠ «видим»**; (3) сданная полировка перепроверяется следующей задачей на её маршруте (раскадровка 4K, вердикт
«оставить / доделать / откатить»); строка «сделана» — только со своим гардом и кадрами ДО / ПОСЛЕ на 4K; (4) сырой `${n}` на экране — класс
дефекта, не опечатка: один путь рендера для чтений с параметрами + гард «на экране нет `${`» в каждом e2e.

## 2. P0-B · Полёт цены / награды между рельсом, спутником, капсулой и картой — закон видимости
**Что есть** (таблица фактов выше): происхождения — чернила строки рельса (PL-094 / PL-099), капсула героя (`.pcard` капсула — PL-100 / PL-140),
ячейка спутника ДОП. РЕСУРСЫ (`.con-res-aux` — оплата карточным ресурсом с ДРУГОЙ карты: мехи EVA, аэростаты, data TR29), печатный значок карты;
адресаты — чернила рельса, капсула героя, ячейка спутника, карта-адресат в табло (невидима в workspace — её дублёр: строка «КАРТА-ПОЛУЧАТЕЛЬ» в
композере). Поверхности: композер действий / розыгрыша (уходит по `markFoldable` → POP), сцена «Разыграно» (`committing` → `closing`), непрозрачное
стекло полосы (PL-137) над спутником.
**Закон (предложение — в батч владельцу первым, с кадрами):**
- **Видимость конца** — `effectiveVisibility(el)`: ненулевой бокс, эффективная непрозрачность по цепи предков ≥ 0,5, центр не накрыт другим слоем
  (`elementsFromPoint(center)` возвращает элемент из поддерева конца или его собственный прокси — а не стекло полосы), элемент смонтирован. Рантайм —
  `consoleResourceTransfer.resolveSourceRect` → `resolveVisibleSource(spec)`: первый ВИДИМЫЙ селектор; ни одного → `point` дублёра (см. ниже); ни
  того ни другого → честный деград (`noteCardResourceLanding` — уже есть: «amount HAS arrived», тик с чипом).
- **Дублёры** — объекты композера, которые ОЗНАЧАЮТ тот же факт и видимы, пока композер стоит: чип цены «БУДЕТ СПИСАНО [N → M на этой карте]» (= капсула
  героя), строка «КАРТА-ПОЛУЧАТЕЛЬ … [Ресурсы на этой карте 0 → 1]» (= капсула карты-адресата), чип «ВЫ ПОЛУЧИТЕ» (= ячейка спутника / рельса); у каждого —
  `data-transfer-anchor="<канал>:<ресурс>[@карта]"` (ключи — те же, что у `verifyRailReward` / `knownCardRows`), и ladder'ы `resolveVisibleSource` /
  `targetPointFor` ищут их ПЕРВЫМИ, пока поверхность стоит.
- **Последовательность** — (а) поверхность-источник живёт до ОТРЫВА каждого жетона (`markFoldable` после `TRANSFER_POP_MS` — для ВСЕХ цепей, не только
  loss-only; PL-142 обобщается); (б) адресат за стеклом / в табло — жетон рождается у дублёра, отделяется в слой приложения (`ConsoleResourceTransferLayer`
  — уже app-level), поверхность уходит (POP), и только тогда полёт к измеренному адресату на открывшейся доске (CLAUDE.md «Physical causality»: «it
  detaches into an app-level layer, the workspace collapses, and only then does it fly to the measured destination»); (в) если и после ухода адресат не
  видим (например, скрыт стеком) — тик с чипом, не полёт.
- **Отказ от концепции** (альтернатива владельца): если кадры покажут, что честная последовательность удлиняет каждое действие на ≥ 0,5 с без выигрыша
  в читаемости — вернуть цены с рельса к «тик на касании результата + дельта-чип» (поведение до PL-099), оставив полёты только там, где оба конца на одной
  поверхности (капсула ↔ печатный значок, рельс ↔ рельс). Рекомендация — закон видимости + дублёры: он сохраняет причинность и убирает «из пустоты».
**Шаги**: (1) раскадровки 4K ДО на четырёх сценах: оплата аэростатами с другой карты (Aerial Mappers / Dirigibles), оплата мехами EVA за Космос из руки,
действие «+1 ресурс на ЛЮБУЮ карту» (Aerial Mappers A, TR29 B), цена с рельса (Space Mirrors 7 M€, Caretaker 8 тепла); по каждому кадру — где родился
жетон, был ли источник видим, стоял ли адресат при посадке; (2) батч владельцу: закон + дублёры ИЛИ откат (кадры); (3) реализация классом в
`consoleResourceTransfer.ts` / `consoleActionCommitRail.ts` / `consolePlayedHero.ts` (одна ветка свёртки, одна функция видимости); (4) гарды: e2e-пробник
«каждый прокси полёта рождён внутри видимого элемента и сел на видимый» — общий `tests/e2e/consoleStart.ts` помощник `effectiveVisibility(page, sel)`
(вытащить из `console-parliament-chairman-quest.spec.ts` / `console-habitat-science` / `console-martian-census` — там он написан трижды), пробник
`transferEndsVisible(page)` на `MutationObserver` слоя `.con-transfer` (рождение → `elementsFromPoint` центра = источник / дублёр / сам прокси;
посадка → адресат); юнит `resolveVisibleSource` (jsdom: накрытый / непрозрачный / размонтированный); рантайм-диагностика

**Порядок**: P0-A (§1) → раскадровки ДО семьи A (§2 шаг 1) → **батч владельцу** (закон видимости + дублёры ИЛИ откат; кадры) → реализация §2 → ревизия

`npm run make:cards`, `npm run make:json`; перед визуальной проверкой — `npm run make:css` + `npm run build:server`. **Не пушить.**
Гочи: 4K e2e — один воркер; e2e и тяжёлые процессы не совмещать; имена кадров скринкаста = время получения; `TM_E2E_STORYBOARD` даёт кадры только когда
