## Диагноз (подтверждён файл:строка на `56fa5188f6`; перепроверить A1–A5 на своём HEAD)

**A1 · DSL не умеет два добора.** `drawCard` — одно значение; апстрим держит P56 bespoke без `source` и без превью → `cardPlayPreviewCoverage:203` красный, `drawExpected` 0 (герой мимо источника — PL-1685), ворот `canDraw` нет (PL-1692), provisions `cardInHand`/`playableCard` не даются (P55 «Сначала карты» не назовёт P56 помощником).

**A2 · Батч несёт одно правило.** Сервер уже шлёт ДВА сегмента с правилами, но батч-`search` — первый; сводка (`ConsoleDrawSearchTally :21`) и каждый вердикт (`ConsoleRevealOverlay :2944`) читают батч → «с меткой Юпитер» на всё вскрытие, вердикт на карте Юпитера, отброшенной поиском Венеры, — ложь (инвариант 16 «правда прежде истории»).

**A3 · Исчерпанный поиск без совпадений теряет ленту.** `Player.ts:2123` ранний выход → сегмент с отбросами не попадает в батч: если Юпитер не найден, его отбросы и «колода вскрыта до конца» на вскрытии не видны (PL-1642). Для P56 батч при этом всё равно есть (второй поиск) — потеря молчаливая (инвариант 4).

**A4 · Театр.** R4 — два поиска = одна лента (закон); при отбросах только в одном сегменте — `intakeSearchRun` играет его, второй — «хвост» с полки. Оба случая легальны; стенд называет, какой покрыт. Перетасовка посреди поиска — счётчики колоды/сброса не знают (гэп, вне скоупа).

**A5 · RU, лор, арт.** Описание — не по стандарту; лора/арта нет; 1-карточные предложения информации — новые ключи.
