### Правила чтения
1. **Требование** — `game.generation >= 4`; причина с «сейчас» («Требуется поколение 4 или позже · Сейчас: 2»), вид
   `GENERATION` (§1 A5). До 4-го поколения карта в руке неиграбельна.
2. **Кто может уйти** — плитка В ИГРЕ, на которой нет ни одной колонии (ничьей, включая куб MarsBot) и нет торгового флота
   (`visitor === undefined`). **«TILES»**: в форке нет ничего, что кладётся НА плитку колонии (поля `Colony`: `colonies`,
   `visitor`, `trackPosition`, `isActive` — `Colony.ts:51–54`); предикат — ОДНА функция `colonyTileIsVacant(colony)`,
   будущая механика «на плитке» расширяет её. Активность и позиция трека не важны (неактивный Титан — законный кандидат).
   Запас MarsBot на Shipping Board (`shippingStorage`) — НЕ «на плитке» (он на планшете бота).
3. **Кто не может** — стоит ОТКЛЮЧЁННЫМ с ОДНОЙ причиной, по порядку: есть колонии → «На плитке есть колонии»; есть флот →
   «На плитке стоит торговый флот». Никогда не скрыт. Единственный кандидат — всё равно ВЫБИРАЕТСЯ нажатием (инвариант 3).
4. **Что приходит** — любая плитка РЕЗЕРВА (`game.discardedColonies` — плитки стола, не сданные в эту партию), кроме только
   что снятой. Вход в игру — правило движка: активна, если она активна по классу или у кого-то в табло есть карта её
   ресурса (`colonyTileWillEnterActive`, `ColoniesHandler.ts:131–143`); трек — начальная позиция.
5. **«Replace it»** — новая плитка встаёт НА МЕСТО снятой: тот же индекс `game.colonies`, без пересортировки (решение
   владельца №3). Снятая возвращается в резерв В ИСХОДНОМ СОСТОЯНИИ (трек 1, активность по классу) — как после
   save/load, где резерв пересобирается из пула (`ColonyDealer.restore`, `:147–152`): «вживую == после загрузки» — спек.
6. **«Place a colony on it, if possible»** — колония ИГРОКА, сыгравшего карту, на новую плитку, слот 1, с наградой за
   постройку и всеми триггерами (`Colony.addColony`, `Colony.ts:116–147` — он же зовёт `onColonyAddedByAnyPlayer`,
   парламентский квест, Aridor). Цель фиксированная (исключение «fixed self-target» из запрета авто-выбора) — но
   ПОКАЗАНА до нажатия на каждом кандидате. **Невозможно** — та же ОДНА функция причин, что у постройки
   (`BuildColony.disabledReason`, `:65–89` / `getPlayableColonies`, `player/Colonies.ts:279–304`): плитка войдёт неактивной;
   не по карману РТ океана (Европа при Красных). Тогда замена происходит, колония — НАЗВАННЫЙ ПРОПУСК
   (`recordSkippedEffect`), а кандидат остаётся выбираемым и говорит это ДО нажатия.
7. **Нет ни одной пустой плитки** — карта играбельна (метки, 1 ПО), эффект целиком — названный пропуск, композер говорит
   это до розыгрыша, двери нет (решение №4, прецедент TR07 №2). Пустой резерв на законном столе невозможен (пул Redux 13,
   в игре ≤ 7) — всё равно названный пропуск, не падение.
8. **Не торговля и не «дополнительная плитка»**: число плиток в игре не меняется; флоты, треки прочих плиток, запас
   MarsBot не тронуты. История парламента, ключёванная именем снятой плитки, остаётся.
9. **Журнал**: одна строка `'${0} replaced the ${1} colony tile with ${2}'` + типизированное событие (A1) под источником
   карты; затем обычные строки постройки и награды.
10. **MarsBot карту не играет.** За столом с ботом человек её играет: куб бота = колония (правило 2); порядок `game.colonies`
    сохраняется (бот считает `flipToPick` по порядку списка — `AutomaColonies.ts:113–126`). См. решение №9.

### Решения владельца (по умолчанию — как написано; подтвердить в отчёте, не блокер)
1. RU-имя **«Окраинная колония»**.
2. **Снятая плитка возвращается в РЕЗЕРВ** (физически — в коробку к несданным), её может вернуть следующий эффект; в
   кандидаты ЭТОГО розыгрыша не входит. Альтернатива «из игры навсегда» требует нового сериализуемого поля — не делать без
   решения.
3. **Замена наследует слот** (тот же индекс, сетка не сдвигается ни на пиксель); чистое ДОБАВЛЕНИЕ (Aridor) сохраняет
   сортировку движка по имени — клиент читает итоговый индекс из массива сервера и нигде не сортирует сам.
4. Нет кандидата на снятие → карта играбельна, эффект — названный пропуск.
5. Кандидат, на который колония НЕ встанет, остаётся выбираемым (причина на нём до нажатия).
6. «TILES» = сегодня пустое множество (правило 2).
7. **Хореография — ритуал TR03/TR07** (staged: до последнего A ничего не отправлено, один POST) в ТРИ уровня: СНЯТИЕ →
   ЗАМЕНА → стейдж-подтверждение; церемония играется на стейдже и ЗАКАНЧИВАЕТСЯ ПОСАДКОЙ плитки в её слот сетки (§2 B1 LANDING, B4).
8. **Зритель**: нотификация + журнал всегда; церемония на сетке — только если у зрителя в этот момент открыта сетка
   колоний; авто-открытия «Колоний» под чужой розыгрыш НЕТ.
9. **Плитка, входящая за стол с MarsBot**: сетап бота делает все плитки активными с треком на 2-й клетке
   (`AutomaColonies.setupColonies`, `:28–33`), но к плитке, севшей позже (в т. ч. C30 бота-Aridor), правило сегодня не
   применяется. Сверить с Rule Book (`docs/AUTOMA_DATA_AUDIT.md`); свод молчит → по умолчанию «входящая плитка садится по
   правилу стола» ОДНОЙ веткой в `seat` (чинит и C30); если правка тянет больше одной функции — записать гэпом, не чинить.
10. Плашка требования на лице — текстом, как на скане: **«ПОК. 4+»**.
11. Maria (CEO) и Prospecting (Underworld) получают серверный путь даром (общая функция), визуально НЕ принимаются (вне скоупа).

### A2 · Маркер `rosterChange` — проекция, которую клиент не выводит сам
`SelectColonyModel.rosterChange?: ColonyRosterPrompt` (`PlayerInputModel.ts:959–994`; сериализация — в `SelectColony.toModel`,
`:66–97`, вложение-безопасно — память `select-colony-placement-context`):
```ts
type ColonyRosterPrompt = {
  kind: 'add' | 'remove' | 'replace';
  /** replace / remove: КАЖДАЯ плитка в игре, порядок стола; не может уйти → ОДНА причина. */
  outgoing?: ReadonlyArray<{colony: ColonyName, reason?: string}>;
  /** add / replace: по записи на каждого кандидата `coloniesModel`. */
  incoming?: ReadonlyArray<{
    colony: ColonyName,
    entersActive: boolean,            // colonyTileWillEnterActive — НЕ `isActive` каталожной модели
    build?: {slot: number} | {skipped: string},   // только когда эффект строит колонию (TR10); причина — правило 6
  }>;
};
```
Клиент не решает, кто кандидат, войдёт ли плитка активной и встанет ли куб (инвариант 2). Присутствие маркера делает акт
пика `roster` (B2). `purpose: 'addNewColonyToGame'` остаётся (каталог); кандидаты `coloniesModel` у `replace` — плитки
РЕЗЕРВА, уходящие живут в `outgoing` (их модели у клиента есть — они в `game.colonies`).

### A3 · ОДИН вопрос, ОДИН ответ — четвёртая форма `SelectColonyResponse`
`{type: 'colony', colonyName: <входящая>, replaces: <уходящая>, stagedFor?: CardName}`. `isSelectColonyResponse` принимает
ровно наборы `[type, colonyName]`, `[…, stagedFor]`, `[type, fleetDock]`, `[type, colonyName, replaces]`, `[…, replaces,
stagedFor]`; `replaces` + `fleetDock` — не ответ. `SelectColony.process` (`:112–134`): у промпта `kind: 'replace'` ответ БЕЗ
`replaces` — ошибка, `replaces` вне кандидатов `outgoing` (или с причиной) — ошибка; у прочих промптов `replaces` — ошибка.
**Атомарность — закон**: между снятием и посадкой нет состояния сервера, в которое может вклиниться промпт (стол с дырой

### B0 · Законы фреймворка (каждый — проверяемое утверждение приёмки)
1. **Плитка — МЕСТО, планета — ОБЪЕКТ.** Двигается только диск планеты (`ConsolePlanetDisc` — тот же компонент у плитки,
   стейджа, досье и прокси: «та же планета» по построению). Плитка не летает, не масштабируется, не пульсирует: её
   содержимое живёт внутри CSS `zoom:` (дробный scale перерастеризует цифры — память `console-colony-entry-phrase`, три
   вкусовых правила). Плитка СОБИРАЕТСЯ вокруг севшей планеты и РАЗБИРАЕТСЯ вокруг уходящей.
2. **Грамматика одна, порядок зеркальный.** Приход — «пространство → объекты → СЛОВА» (как вход стейджа, `colony-focus-stage.md`
   §5); уход — «слова → объекты → пространство». Stagger — шёпот (≤ 14 мс/клетка), вся волна капнута.
3. **Слот существует раньше объекта.** Пустой слот — «свободная орбита»: точный бокс плитки (18.3×10.7rem × `--coltile-scale`),
   тонкое пунктирное кольцо на месте диска, приглушённая пластина без слов. Объект летит в ИЗМЕРЕННОЕ место
   (`restingRectOf`), источник меряется СЫРЫМ (`.claude/rules/animations.md` § Landing rects).
4. **Откуда — куда — почему** у каждого движения: уходящая планета отрывается от СВОЕГО диска и уходит «в глубину» (уменьшение
   + дрейф ключевого света, растворение в точку); приходящая — из того экранного объекта, который игрок выбрал (каталожная
   плитка / герой стейджа), а у зрителя — «из глубины» над своим слотом. Синтетического дилера нет.
5. **Реагирует только тронутое, один раз**: слот отвечает ОДНИМ one-shot на касание планеты (`animationend` его снимает);
   соседние плитки не подсвечиваются, не пульсируют, не «уступают» (закон 11 парламента).
6. **Сетка не пересчитывается на глазах.** На время церемонии `fit()` заморожен; ровно ОДИН пересчёт — в названный момент
   (под припаркованным слоем либо в такте RESEAT). Замена не меняет ни одного бокса сетки (гард e2e: rect'ы прочих плиток
   до == после).
7. **Курсор — ИМЯ, не индекс.** Чтение фокуса сетки привязано к `ColonyName`; изменение состава переякоривает его по имени
   (ушла плитка в фокусе → её преемник по слоту). Найденный дефект чинится классом, не только для церемонии.
8. **Один владелец темпа.** Свой поток — клиент-армированный гейт транспорта (образец — постройка: `armColonyBuild` →
   `detectColonyBuild` → `runColonyBuild` при УДЕРЖАННОМ коммите → коммит под севшим прокси → `endColonyBuild`,
   `consoleColonyBuild.ts:140–322`, `transportHolds`, `gameTransport.ts:248–263`). Зритель — посев из диффа двух видов в блоке
   apply. Двух гейтов, гоняющихся за один ответ, нет.
9. **Каждый холд назван, реактивен и ограничен**: поставщик `'colony-roster'` (`registerAnimationHoldSupplier` с `expire` +
   `diagnose`), отпуск — посадкой (`onComplete` И `onInterrupt`), никогда `setTimeout`; ввод на время церемонии — `none`
   (вступает в `isColonyTradeInputLocked`-семейство); **A во время церемонии = «дожать»** (конечные позы немедленно —
   как в заседании), не пропуск такта и не второй submit.
10. **Нечем мерить — признаться**: `data-colony-roster-degraded` на корне секции (e2e требует отсутствия), конечные позы,
    холды отпущены. Reduced motion / fx-lite: конечные позы + короткий фейд (`REDUCED_MOTION_CAP_MS`).
11. **Presented-состав один**: `presentedColonyRoster(view)` — единственный читатель списка плиток для сетки и курсора
    (`coloniesForRail`, `ConsoleShell.vue:5575`); пока церемония должна/идёт, он отдаёт состав «до». Второго списка нет.

### B1 · Четыре фразы директора (длительности — базовые, через `motionMs()`; easing — `MOTION_EASE`)
**DEPART — планета уходит** (≈ 560 мс; масштабы `tile` | `stage`):
`0` слова гаснут (имя, цифры, статус — LATE-слой) → `60–220` трек темнеет справа налево, маркер снимается, глифы бонусов
гаснут → `160–560` диск отрывается: короткая дуга наружу, scale 1 → 0.55, свет дрейфует, кромка-rim гаснет, прозрачность
→ 0 (`power2.in`) → `560` на месте диска — пунктир свободной орбиты, кромка плитки отпускает последней.

**ARRIVE — планета приходит** (≈ 900 мс):
`0–140` орбита слота отвечает (пунктир наливается) → `80–540` прокси-диск идёт из источника в измеренный диск слота
(`power3.inOut` — планета самый тяжёлый объект и садится медленнее всех; параллакс света и нарастание rim — язык
PLANET DEPTH стейджа) → `540` СТЫКОВКА: кольцо замыкается, one-shot слота, хэндофф «показать настоящий диск → убрать
прокси СЛЕДУЮЩИМ кадром» (не кроссфейд) → `520–760` СТРУКТУРА: кромка, причалы, клетки трека зажигаются слева направо
одним проходом, маркер садится с lock-пульсом → `760–900` СЛОВА. Плитка, входящая НЕАКТИВНОЙ: трек не зажигается, статус
говорит правду («Ещё не активна — нужна карта с [ресурс]») — без «праздника».

**RESEAT — сетка меняет население** (≈ 360 мс; нужен, когда меняется ЧИСЛО плиток или вся рейка):
размер плитки тот же → ОДИН связный translate-FLIP уцелевших (без stagger, без scale); размер меняется (`--coltile-scale`
пересчитан) → «пересадка»: содержимое отпускает (opacity) → пустые пластины едут и меняют размер → содержимое
возвращается каскадом входа (`colonyEntryCascade`). Текст под масштабом не едет никогда.

**LANDING — плитка занимает итоговую позицию** (свой поток): стейдж складывается ДОМОЙ в слот сетки существующей фразой
(`colony-focus-stage.md` §5: кромка и мелкий текст первыми, затем структура, затем панель — в rect плитки; планета · трек ·
причалы FLIP'ом в компактных близнецов). Дом — плитка в СЕТКЕ ИГРЫ, перемеренная ПОСЛЕ её `fit()` (цель решена раньше, чем
в неё целятся). Сетка встаёт в позе КВИТАНЦИИ: без курсора, без глаголов, рейл — «Энцелад → Титан · колония построена».
Затем чтение (класс `CARDLAND_READ_MS`) и уход. ⚠ Это сознательная оговорка к закону «завершённый поток не складывается в
browse»: сворачивание здесь — такт РЕЗУЛЬТАТА (объект встаёт на своё место), ввод всё время `none`, фаза — `completing`;
сетка ни на кадр не становится местом решения.

### B2 · Пик состава — три уровня одного flow
`ConsoleColonyPick` получает `roster` (маркер как есть); `colonyPickIntent` (`consoleColoniesModel.ts:239`): `rosterChange` →
**`'roster'`**. Черновик выбора — модульное состояние `colonyRosterDraft {outgoing?: ColonyName}` (переживает парк,
сбрасывается концом потока и abort-батареей). Какая рейка стоит, решает УРОВЕНЬ (один предикат рядом с
`colonyRailIsCatalog`, не второй список): `remove` — всегда игра; `add` — всегда каталог; `replace` — игра, пока уходящая
не выбрана, затем каталог.

```
КАРТЫ В РУКЕ › ОКРАИННАЯ КОЛОНИЯ › РОЗЫГРЫШ           композер: 24, «Плитка колонии — замена в «Колониях»», ПО +1

КАРТЫ В РУКЕ › ОКРАИННАЯ КОЛОНИЯ › ЭНЦЕЛАД · ЗАМЕНА    КАТАЛОГ резерва: на каждом кандидате — «войдёт активной / неактивной»,
```

- **Уровень 1 (СНЯТИЕ)**: кандидаты и причины — из `outgoing`; на кандидате в фокусе рейл: имя · «будет снята · на её место
  — плитка из резерва (N)». Проекция стоит всегда, пока дверь открыта (не «по наведению»).
- **Переход 1 → 2 — это RESEAT**, не `v-if`: плитки игры отпускают содержимое, пластины пересаживаются в раскладку каталога,
  каталог проявляется; имя уходящей уходит в хвост крошки и в ведущий член статус-рейла («СНИМАЕТСЯ ● Энцелад»). B
  играет ту же фразу назад.
- **Уровень 2 (каталог)**: статус плитки — из `incoming[].entersActive`, НИКОГДА из `isActive` каталожной модели (сегодня
  вся рейка врёт «не активна»); причал 1 кандидата — призрак куба в цвете игрока (язык проекции — как `--effective` у
  трека) и глиф награды за постройку; `build.skipped` → ОДНА причина в статусе, куба-призрака нет. Превью торговли не
  запрашивается (каталог: `colonyRailIsCatalog`-запрет остаётся).
- **Уровень 3 (стейдж `roster`)** — композиция режима `build` (`colony-focus-stage.md` §7: причалы первыми, цель пульсирует,
  конфигурации нет) + «исходящее место»: компактный `ConsolePlanetDisc` уходящей с подписью «Снимается» в углу
  геро-колонки (`position: absolute`, ноль лэйаута — дети геро-колонки идентичны во всех фазах). Герой до коммита — в позе
  ПРОЕКЦИИ (пунктирная орбита, диск чуть «не дошёл»). Рейл ИТОГ — три факта, по одному разу: «Снимается: Энцелад» ·
  «Приходит: Титан — войдёт активной» · «Колония: слот 1 · [награда]» (либо причина пропуска). Команды: A «Разыграть
  карту» (staged) / глагол сервера (живая дверь) · X «Осмотреть» (досье приходящей) · L3 «Источник» · B «Назад». Литералов
  кнопок нет.
- Закон двух уровней колоний соблюдён: в сетках A ВЫБИРАЕТ, на стейдже A ПОДТВЕРЖДАЕТ; B — ровно один уровень.
- **Aridor** = уровни 2–3 без уходящей (`kind: 'add'`): каталог → стейдж `roster` (без «исходящего места», без куба) → A
  «Добавить плитку» → ARRIVE → LANDING в НОВЫЙ слот (сетка под припаркованным слоем уже пересчитана на N + 1 — RESEAT
  невидим и бесплатен) → шаг старта продолжается. **Соло-сетап** = уровень 1 + стейдж (`kind: 'remove'`): A «Убрать
  плитку» → DEPART на герое → стейдж отпускает на месте → сетка возвращается с сомкнутыми рядами. Оба — та же секция, тот
  же директор, ноль карточных веток.

## 6. Режим работы
**5 коммитов**, каждый зелёный: (1) сервер — писатель состава + событие + перевод Aridor / сетапа, маркер, четвёртая форма
ответа, `ReplaceColonyTile`, `GENERATION` + спеки; (2) карта + лицо + локаль + лор + арт + спеки; (3) клиент-фреймворк —
модуль `colonyRoster`, слой, свободная орбита, presented-состав, курсор по имени, четыре фразы, посев зрителя, журнал /
нотификация + юниты; (4) клиент-потоки — intent `roster`, три уровня, staged-дверь, гейт своего потока, LANDING, Aridor и
соло на том же пути + юниты; (5) e2e + фикстуры + документы. Перед каждым: `npm run lint`, `npm run build:test` (код выхода
читать ЯВНО), `npm run make:cards`, `npm run make:json`; перед визуальной проверкой `npm run make:css` + `npm run
build:server`. **Не пушить.**
Документы: **`docs/COLONY_ROSTER_CEREMONY.md`** — контракт фреймворка (писатель, событие, маркер, форма ответа, 11 законов
B0, четыре фразы с таймингами, два пути темпа, что получает следующая карта «добавь / убери / замени плитку» даром);
`docs/TURMOIL_REDUX_FRINGE_COLONY.md` — карта, правила 1–10, решения, границы; дополнить `TILE_PLAY_STAGED_COMMIT.md`
(таблица целей: колония × маркер `rosterChange`), `.claude/rules/console-ui.md` (один абзац в законах колоний),
`colony-focus-stage.md` §7 (режим `roster`), чеклист набора §4 (строка «карта меняет состав плиток → `ReplaceColonyTile` /
`seat` / `retire` + `colonyPickStep`»), журнал набора.
