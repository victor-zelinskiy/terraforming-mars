Раз в поколение (причал занят до конца поколения), только владелец карты.

**Серверная часть мала. Главное в задаче — ДВА новых кейса: (1) у торгового действия появляется назначение, которое не
колония, — и оно должно быть выбрано, оплачено и показано тем же языком, что торговля с колонией; (2) премиальная сцена:
игрок входит в назначение-карту → A «Торговать» → флот взлетает со своей площадки, летит и САДИТСЯ на карту → карта
отвечает и отступает → workspace уходит одной поверхностью → поле, размещение океана.** Кейс первый из КЛАССА (три карты
набора) — оценивается тщательность, а не объём.

## 2. Блок A · сервер

### A1 · Причал — контракт класса, co-located в файле карты
`ICard.fleetDock?: FleetDock` (инвариант 8 — хук в файле карты) + общий модуль `src/server/colonies/FleetDock.ts`:
```ts
type FleetDock = {
  /** Блокер НАГРАДЫ (океаны кончились) — одна причина; общие блокеры (занятость) считает модуль. */
  rewardBlockedReason?(player: IPlayer): string | undefined;
  /** Чипы «что даст торговля» — current → resulting, без мутаций. */
  previewEffects(player: IPlayer): ReadonlyArray<ActionPreviewEffect>;
  /** Сама награда: ставит свои deferred-действия (океан). Зовётся ПОСЛЕ посадки флота. */
  receive(player: IPlayer): void;
};
```
Модуль владеет ВСЕМ общим: состояние «флот на карте» (`card.data = {dockedGeneration}`; сериализация уже есть —
`cardSerialization.ts:50–51, 65–66`; занято ⇔ `dockedGeneration === game.generation`, сбрасывать руками не нужно),
`offers(player)` (по карте табло с `fleetDock`: `available` + ОДНА причина в порядке «флот уже на карте в этом
поколении» → `rewardBlockedReason`), `dock(player, card)` (штамп поколения, `usedTradeFleets++`, лог, событие, затем
`receive`). Гейт и причина — ОДНА функция (образец `tradeBlockedReason` рядом с `canTrade`).

### A2 · Назначение торговли — одна абстракция, ни один путь оплаты не узнаёт слова «причал»
Все пути (`TradeWithEnergy :375–481`, `TradeWithTitanium :483–513`, `TradeWithMegacredits :516–570`, `TradeWithUnity`,
`TradeWithAutomatedConvoys`, TFLP и вне-скоуповые) устроены одинаково: взять плату → лог «…to trade with ${colony}» →
`recordTradeDiscountSaving(player, colony, …)` → `colony.trade(player, …)`. Ввести **`ITradeDestination`**
(`src/server/colonies/`): то, что путь называет в логе, чему записывает скидку и у чего зовёт
`trade(player, tradeOptions?, bonusTradeOffset?)`. `IColony` его реализует (поведение побайтно прежнее), рядом —
`FleetDockDestination(card)`: её `trade()` = «торговля состоялась» (A3) + `FleetDock.dock`. `IColonyTrader.trade(destination:
ITradeDestination)` — в каждом пути меняются ТИП и токен лога, больше ничего; `Colony.trade` не трогается.
Спек-страж: каждый путь `tradeHandlers()` торгует с причалом и берёт РОВНО свою плату (таблица по путям, вкл. Delta
Works-микс и отложенную оплату M€).

### A3 · «Торговля состоялась» — одна функция на два назначения
Сегодня у факта торговли два потребителя, и оба зашиты в колонию: `ParliamentHandler.onTrade` (`Colony.ts:156, :169`) и
+3 M€ Venus Trade Hub (`handleTrade :372–374`). Вынести в одну `onTradePerformed(player)` и звать из обоих назначений
(у колонии — в прежних точках, порядок событий не меняется; `colonyTradePreview.flatBonuses` остаётся зеркалом).

### A4 · Вопрос и ответ — маркер на общем пике, поле в ответе `colony`

  `SelectColony` с маркером **`fleetDocks`** = `FleetDock.offers(player)`; `SelectColonyModel.fleetDocks?:

  (инвариант 2). Главная дверь (`tradeWithColony`), TR66 (`AutomatedConvoys.ts:155`), TFLP (`TitanFloatingLaunchPad.ts:118`)
  переходят на него; вне-скоуповые двери (Darkside Smugglers' Union, Collegium Copernicus, Huygens Observatory)
  остаются на `tradeColonyPick` — записать гэпом в документе, не расширять.
- **Ответ**: `SelectColonyResponse` принимает вторую форму `{type: 'colony', fleetDock: CardName}` (`InputResponse.ts:165–172`;
  валидатор сегодня требует РОВНО `['type', 'colonyName']` — образец двух форм `isSelectSpaceResponse`). Ровно одно из
  двух полей. `SelectColony.process`: карта обязана быть `available` в маркере ЭТОГО промпта, иначе `InputError` с её
  причиной — ДО оплаты.
- **Главная дверь** (`tradeWithColony`): пик с НУЛЁМ колоний, но с доступным причалом — законный промпт (правило 5).

- **Гейт**: `tradeBlockedReason()` третьим шагом считает причалы (`FleetDock.offers(...).some(available)`);

  ⚠ `canTrade()` — ещё и `canAct` карт (TFLP `:138`): проверить, что дверь, ставшая доступной «только из-за причала»,

### B1 · Колонка «ПРИЧАЛЫ» в обзоре колоний
- Источник — маркер `fleetDocks` живого пика (контекст торговли получает поле `docks`); вне окна торговли (не ход
  игрока, промпта нет) плитка стоит по публичной модели (`CardModel.fleetDocked` + карта в табло зрителя) с той же
  причиной «окна», что у тайлов колоний (`tileStatus :1285` — одна функция статуса, не вторая).
- **Не слот сетки планет.** Раскладка сетки спроектирована по числу тайлов 1–6 (`colonyGridLayout`), седьмой слот уводит
  её в `catalog`; у класса будет до трёх причалов. Причалы — отдельная узкая КОЛОНКА справа от сетки (под панелью флотов
  — «ваши корабли и куда ещё они ходят»), видна только когда у зрителя есть карта-причал. Фит сетки высотный
  (`ConsoleColoniesSection.vue:60–67`) — колонка берёт ширину, а не высоту; проверить `fit`-пробником на fhd / tv4k /
  Deck при шести колониях и одном причале: тайлы планет не мельчают заметно (порог назвать в отчёте), 0 `[console-overflow]`.
- Плитка причала (`ConsoleFleetDockTile.vue`): арт карты, имя, значок награды (тайл океана), причал
  `[data-fleet-berth="card:<имя>"]` с флотом владельца, когда занят; состояния «свободен» · «флот на карте — до конца
  поколения» · «недоступен + причина». Стоп фокуса в кольце обзора: ▶ из последнего столбца сетки входит в колонку, ◀
  возвращает в тот же ряд (`colonyNavStep` — расширить чистой функцией со спеком, обзор при прогулке не двигается).
  X — «Осмотреть»: штатный осмотр карты. Чужие причалы в обзоре не стоят (правило 9) — они видны на табло соперника.
- Статус-рейл для причала в фокусе: имя · «→ [океан] +1 РТ» · либо ОДНА причина (грамматика `railBlocked`).

### B2 · Стейдж причала — композер торговли с картой
- Сосед фокус-стейджа в том же регионе и на тех же хуках спуска (образец — `ConsoleColonyInspect`): `ConsoleFleetDockStage.vue`,
  состояние — в `colonyFocusState` (новое назначение рядом с `colonyName`; `intent: 'trade'`). Герой — ПОЛНОЕ премиум-лицо
  карты (нужен узел ▲ — не `ConsoleCardFaceLite`); трека, причалов поселений и дохода колонии нет.
- **Пути оплаты — ТА ЖЕ модель и ТА ЖЕ строка**, что у колонии: вынести `payEntries` и ряд оплаты в общий под-компонент /
  чистую модель и подключить в оба стейджа (после коммита соседа; копия разметки = дефект). Запертый путь двери карты,
  отключённые пути с причиной, шаг оплаты M€ и микс Delta Works — работают без отдельного кода. Строка Союза здесь
  говорит «Бесплатно» без фразы про шаг трека (трека нет — модель строки получает признак назначения, текст не режется
  регуляркой).
- РЕЗУЛЬТАТ — только из сервера: чипы `effects` превью (океаны `current → resulting`, РТ), «Флоты ${free} → ${free − 1}»,
  нота следующего шага существующим ключом `'After confirming: place an ocean tile'` (`colonyTradePlan.ts:127`).
- Крошка: `КОЛОНИИ › ПЕРЕВОЗКА ВОДЫ › ТОРГОВЛЯ` — субъект = имя карты, стадия — существующий `'Trading'`
  (`publishStageName`), стейдж себя не титулует. У двери карты: `ДЕЙСТВИЯ КАРТ › <карта-дверь> › ПЕРЕВОЗКА ВОДЫ · ТОРГОВЛЯ`
  по грамматике второй двери.
- Команды: A «Торговать» (существующий глагол) · B «Назад» · X «Осмотреть» (карта). Недоступный причал: A отключён, ОДНА
  причина на стейдже (`blockReason`), не `title`. Литералов кнопок нет (гард `glyphLiteralGuard`).
- Подтверждение — шелл: `onFleetDockConfirm` рядом с `onColonyTradeComposerConfirm` (`ConsoleShell.vue:15986–16071`):
  те же стражи двойного нажатия (`isTradeFleetActive()`), батч — ОДИН строитель (`buildTradeBatch` получает назначение:
  `{colonyName}` | `{fleetDock}`), `holdPresentation`-аналог (квитанция оплаты), `armTradeFleet(…)` с целью-картой,
  `submitBatch`. `armColonyTrade` НЕ армится (манифеста колонии нет); транзакция наград колонии не участвует.

### B3 · Полёт и посадка — тот же директор, цель — карта
- `tradeFleetState` и `armTradeFleet` получают ЦЕЛЬ: `{kind: 'colony', colonyName} | {kind: 'card', card}` (все читатели
  `colonyName` — тайл, орбита стейджа, `dockedColonyName` — переводятся на цель; поведение колонии побайтно прежнее —
  `trade-fleet-probe.spec.ts` зелёный без правок ожиданий).
- Слой: адресат карты — лестница ИЗМЕРЕННЫХ якорей: знак ▲ ряда эффекта на лице-герое
  (`[data-graphic-node]` узла TRADE) → причал плитки в колонке (`[data-fleet-berth="card:…"]`) → нет rect: полёта нет,
  фазы идут, гейт разрешается (как сегодня у колонии). Не `a ?? b`.
- Гейт без изменений: вид с `fleetDocked`, платой и промптом океана применяется ПОСЛЕ посадки; `endTradeFleet` — кроссфейд
  прокси на настоящий знак (B5) и one-shot свечение посадки.

### B4 · Сцена после посадки и уход в размещение
Blocking-холд **`'trade-fleet-dock'`** (поставщик с `diagnose` и `expire` → конечные позы) встаёт в том же блоке, что
apply, и только если стейдж причала стоит; admission `placement` ждёт его — океан не допускается, пока workspace на экране.
1. **ОТВЕТ КАРТЫ** — импульс по печатному ряду ▲ → «:» → [океан], значок океана цветёт один раз (язык коммита действия).
   Океан НЕ изображается севшим — он впереди.
2. **ЧТЕНИЕ** (класс `CARDLAND_READ_MS = 680`): крошка янтарная, строки оплаты — квитанция без стопов, ввод `none`.
3. **УХОД КАРТЫ ТАКТОМ** — «the departure is a beat, not a crossfade»; знак флота уезжает вместе с лицом.
4. **УХОД WORKSPACE ОДНОЙ ПОВЕРХНОСТЬЮ** через ОДНУ охраняемую концовку (не `goBoardHome()` в лоб): фрейм колоний и его
   хост-действие (дверь карты) завершаются ЗДЕСЬ, со своим уходом секции; холд отпускается на КОНЦЕ ухода → размещение
   встаёт над чистым полем. Корень с `yieldsToBoard` (Парламент у двери Союза) ведёт себя по своему закону; фреймы
   торговли к этому моменту сняты, `settleColonyFollowUp` (`:11795–11847`) ничего не «доснимает» — проверить.
Длительности — `motionMs()` / `MOTION_EASE`; холд отпускается сигналом (конец ухода), не `setTimeout`; потолок реестра —
единственная сеть. Бюджет от посадки до чистого поля ≤ 2.2 с базовых. Reduced motion / fx-lite: конечные позы и короткие
фейды. **Прерывания** (размонтирование, abort транспорта, «мир сдвинулся») → конечные позы + отпуск своего холда;
размещение не теряется никогда (оно серверное). Отказ сервера / потерянный ответ — существующая батарея: флот
возвращается на площадку, стейдж цел, выбор оплаты цел.

### B5 · Знак флота на карте — постоянное состояние, не только сцена
`CardModel.fleetDocked` → на премиум-лице знак флота в цвете владельца сидит НА знаке ▲ ряда эффекта: `position:
absolute`, ноль лейаута, реальный ассет (`trade-fleet.png`; `filter` на консоли вырезан). Виден везде, где видна карта:
стейдж, плитка причала, «Разыграно», осмотр, табло соперника. В обозревателе эффектов (`ConsoleEffectsExplorer.vue`) —
строка состояния «Флот на карте · вернётся в следующем поколении»; карта не тускнеет как `isDisabled`. Не использовать
`actionsThisGeneration` (у консоли это список ДЕЙСТВИЙ — появится фантомная «Активирована»).

## 7. Режим работы
**4 коммита**, каждый зелёный по юнитам: (1) сервер — `ITradeDestination`, `FleetDock`, пик назначения и вторая форма
ответа, гейт торговли, `onTradePerformed`, событие, `CardModel`, превью причала, класс A6 + спеки; (2) карта + локаль +
арт + лор + спеки; (3) клиент — колонка причалов, стейдж, общий ряд оплаты, батч, цель полёта, холд и концовка, знак на
лице + юниты; (4) e2e + фикстура + документы. Перед каждым: `npm run lint`, `npm run build:test`, `npm run make:cards`,
`npm run make:json`; перед визуальной проверкой `npm run make:css` + `npm run build:server` (не голый `tsc`). **Не пушить.**
**Документ карты ЗАВОДИТЬ** — `docs/TURMOIL_REDUX_WATER_HAULING.md`: контракт «карта-причал» (чтение правила с тремя
источниками и одним выведенным пунктом — платой; `ITradeDestination` и почему пути оплаты не знают причала; `FleetDock`;
пик назначения и вторая форма ответа; гейт торговли с причалами; колонка и стейдж; полёт на карту; холд и концовка в
размещение), что наследуют TR26 (награда без поверхности: чип РТ летит со значка карты на рельс, flow сворачивается как
обычная торговля) и TR27 (награда С ВОПРОСОМ: цель аэростатов — `cardTarget` в `followUps` превью причала, пре-сбор тем
же шагом, что цель награды колонии), гэп вне-скоуповых дверей. Дополнить: `docs/COLONY_TRADE_FLOW.md` (§ THE FLEET DOCK —
a trade whose destination is a CARD), `.claude/rules/console-ui.md` (один абзац в законах колоний),
`docs/CONSOLE_WORKSPACE_STACK.md` при правке реестра, чеклист набора §4 (строка «карта-причал → `fleetDock`»), журнал
набора. Гочи: `python3` — заглушка Store; юниты последовательно; `eqeqeq` без исключения для null; соло-фикстура УДАЛЯЕТ
колонию (`keepColony`); новая карта меняет сид-сдачи Redux-столов — поехавший чужой спек сперва проверить без карты в
манифесте и чинить классом; диагноз торгового flow — ТОЛЬКО по трейлу (`__conColonyDiag()`), не догадками; MarsBot ×
Venus Redux — известное, отложено.

В отчёте: сигнатуры `ITradeDestination`, `FleetDock`, формы маркера и ответа; таблица «путь оплаты × причал» из спека;
как изменился гейт торговли и что напечатали спеки колоний до / после; замеры фита сетки с колонкой на трёх профилях;
семь кадров + раскадровка; e2e на двух профилях и регрессия соседей до / после; что напечатали гарды; новые ключи i18n;
