**Оцениваются четыре вещи — в этом порядке веса.**
1. **СЕРВЕР НЕ ЛОМАЕТСЯ, ПОТОМУ ЧТО ЛИМИТ — ПРАВИЛО ДВЕРИ, А НЕ СВОЙСТВО МАССИВА.** Число кубов на плитке нигде, кроме
   двери постройки, не сравнивается с константой; каждое чтение «по слоту» — тотальное; у массива кубов ОДИН писатель с
   ОДНИМ инвариантом. Карта не добавляет ни одного сериализуемого поля: «сверх лимита» — это счёт, а не флаг.
2. **МЕСТО СВЕРХ ЛИМИТА.** Четвёртая колония стоит там же, где на настольной плитке — на четвёртой клетке трека; у неё свой
   причал, одна модель мест и три хоста (плитка сетки, стейдж, досье). Обычная плитка после карты — побайтно прежняя.
3. **СЦЕНА «ЛИМИТ ОТКРЫВАЕТСЯ».** Существующая подпись постройки (куб → защёлка → стоп → награда), сдвинутая на клетку, плюс
   ОДИН новый такт перед кубом. Сдержанно: один объект отвечает один раз.
4. **Обратимость.** «Выбрать колонию» ничего не отправляет; A на стейдже — единственный POST; B — ровно один уровень.

### Правила чтения (каждое — закрепить спеком)
1. **Требование** — `{party: PartyName.UNITY}`.
2. **Это обычная ПОСТРОЙКА колонии** — `Colony.addColony`: строка журнала, бонус постройки, «маркер не ниже числа колоний»,
   хуки `onColonyAddedByAnyPlayer`, корпорация бота, задание председателя «построить колонии», метка Науки Leavitt. В
   файле карты ничего из этого не программируется.
3. **Сняты РОВНО ДВА правила** — «у вас уже есть здесь колония» и «на плитке 3 колонии». НЕ сняты: неактивная плитка
   (`'Colony is inactive'`), цена РТ под Красными (океан Европы; Leavitt + Pharmacy Union), «плитка в игре» (резерв — нет).
4. **Лимит снят для ЭТОЙ постройки, а не для плитки.** После неё `isFull()` истинно (4 ≥ 3): больше никто — включая
   владельца, «Научную колонию», стандартный проект, Colony Contest и MarsBot — там не строит. Сыгранная на плитку с 0–2
   колониями, карта даёт обычную постройку (возможно, вторую свою), и лимит плитки остаётся три.
5. **Бонус постройки четвёртой колонии = бонус постройки плитки** (скобки на карте): чтение слота, зажатое на последней
   напечатанной клетке. У однородных плиток это то же число; у Titania — 2 ПО (решение 3).
6. **Трек.** Нижняя граница маркера — число колоний (4): `decreaseTrack` (`Colony.ts:110–112`), сброс после торговли

   предел: кубу нужна клетка, и маркеру должна остаться своя — после постройки `colonies.length ≤ trackTop`. Одной картой
   недостижимо (4 ≤ 6), но правило написано и названо причиной, а не предположено.

## 1. Блок A · сервер — главное

### A1 · ОДНО чтение бонуса постройки — `buildBenefitAt(metadata, slot)`
Рядом с `tradeBenefitAt` (`common/colonies/ColonyMetadata.ts:148–158`) и по его образцу: `{type, quantity, resource}`,
слот зажат в `[0, build.quantity.length − 1]`. Читают ВСЕ: `Colony.addColony` (слот берётся ОДИН раз до push — Vital
Colony платит тот же слот дважды), `colonyTradePreview.buildBonusFollowUps`, клиентские чтения из таблицы выше;
`BenefitGlyph` получает уже разрешённый бонус (`quantity: [q]`, `idx: 0` — приём `fixedBenefit`,
`ConsoleColonyTrackInstrument.vue:275–278`), а не массив с индексом за его краем. Гард-сканер по образцу
`tests/colonies/colonyCardResourceReader.spec.ts`: сырое `build.quantity[` вне читателя, экспорта манифеста и замороженных
десктоп-файлов — провал с файлом и строкой. Гард данных: каждая плитка `ALL_COLONIES_TILES` печатает ровно
`MAX_COLONIES_PER_TILE` клеток постройки и `trackTop > MAX_COLONIES_PER_TILE`.

Там же, в `src/common/colonies/colonyBerths.ts` (общий — сервер и клиент называют «сверх лимита» одной функцией):

(= `max(printed, built, projectedSlot + 1)`).

### A2 · ОДИН писатель кубов и его инвариант
`Colony.placeCube(owner: PlayerId): number` — единственное место, где растёт `colony.colonies`: проверка «свободная
клетка трека есть» (`this.colonies.length < trackTop(this.metadata)`, иначе throw — двери называют это раньше) → push →
«маркер не ниже числа колоний» → возвращает слот. Зовут `addColony` и `AutomaColonies.botBuildColony` (его собственные
push и копия правила маркера `:148–152` уходят; подбор плитки, журнал, хуки и хранилище бота — как были). Source-level
гард по образцу `ColonyRoster.spec.ts:401` / `ColonyCity.spec.ts:344`: в `src/` никто, кроме писателя и
(де)сериализации, не пишет в массив кубов (ростер `game.colonies.push` — другой массив, не путать; тесты присваивают

## 7. Режим работы
**6 коммитов**, каждый зелёный по юнитам: (1) сервер — `buildBenefitAt`, `colonyBerths`, один писатель, опция двери,
близнец и маркер `BuildColony`, превью, бот, прогноз + спеки; (2) карта + локаль + лор + арт + спеки; (3) клиент —
МЕСТА КАК МОДЕЛЬ: чистый рефактор без единого видимого пикселя (зажимы и литералы умирают, A/B кадры идентичны);
(4) клиент — сверхлимитное место в трёх хостах + юниты; (5) клиент — дверь, общий коммит, сцена, продолжения, домой,
зритель + юниты; (6) e2e + фикстура + документы. Перед каждым: `npm run lint`, `npm run build:test`, `npm run
make:cards`, `npm run make:json`; перед визуальной проверкой — `npm run make:css` + `npm run build:server`. **Не пушить.**
Документы: `docs/TURMOIL_REDUX_EXCLUSIVE_COLONY.md` (контракт «колония сверх лимита»: лимит — правило двери, один
писатель, `buildBenefitAt`, маркер `buildSites`, модель мест, сцена; что получит следующая карта, снимающая правило
постройки); `colony-focus-stage.md` §2, §4b, §7; `COLONY_TRADE_FLOW.md` (`buildFollowUps` без гейта);
`TILE_PLAY_STAGED_COMMIT.md` (§ «та же цель — постройка»); `COLONY_ROSTER_CEREMONY.md` §8 (что из продолжений теперь
пройдено); реестр лора — статус; чеклист набора §4 — строка; журнал набора.
Гочи: у `turmoilReduxExpansion` в `testGame` нужен `coloniesExtension: true`; Redux нормализует Кельвинистов в Зелёных;
`Colony.endGeneration` двигает каждый активный трек +1 до заседания (фикстура с маркером на 3 встретит его на 4);
`python3` — заглушка Store; юниты — последовательно; `eqeqeq` без исключения для null; именованный экспорт из `.vue`
невидим для `tsc -p tests`.
В отчёте: сигнатуры (`buildBenefitAt`, `placeCube`, опции двери, `ColonyBuildSite`, `colonyBerthsOf`); список снятых
зажимов и чем доказано, что обычная плитка, обычный стейдж и обычная постройка не изменились; что обобщено (коммит
постройки, квитанция сетки); A/B-тайминги; кадры §6; e2e на двух профилях + регрессия; что напечатали гарды; новые ключи;
подтверждение решений 1–10; **явно — всё, что не получилось сделать, и почему.**
