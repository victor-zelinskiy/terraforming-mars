## 2. ПАССИВ · дополнительные метки науки

### 2.1 Ответ на вопрос «учитывается ли при розыгрыше» — ДА, и шов уже есть

`Tags.count(tag, mode)` — одна точка, через которую проходят и требования карт, и действия. В ней уже
живут оба нужных прецедента (`src/server/player/Tags.ts`):

- `tagCount += this.extraScienceTags;` — **готовое поле «дополнительные метки науки»** (Leavitt Station,
  Underworld);
- `tagCount += ParliamentHandler.wildTags(this.player);` внутри `includeTagSubstitutions` — **уже
  работающий партийный бафф меток** (дикая метка Учёных), с комментарием: «counts when playing cards and
  actions, never for awards».

**Делай по образцу `wildTags`, а не через `extraScienceTags`.** Разница принципиальная:
`extraScienceTags` прибавляется БЕЗУСЛОВНО (в любом режиме, включая `'award'` и `'raw'`), а печатное
правило говорит **«when taking actions»** — значит бафф должен жить внутри `includeTagSubstitutions`
(режимы `default` / `milestone`), ровно там же, где дикая метка.

- Заведи `ParliamentHandler.scienceTags(player)` рядом с `wildTags` — от ПАССИВА принятой резолюции
  (не от партийного эффекта): участник, карта принята, величина = его влияние.
- **Вехи (`milestone`) — граница, которую надо решить и закрепить спеком.** `wildTags` сегодня попадает
  в `milestone`. Для нашего баффа это спорно: веха — не «taking actions». **Решение: НЕ давать бафф в
  `milestone`** (веха фиксирует достижение, а не совершение действия), и обязательно оформить это
  отдельным спеком с комментарием. Если по ходу найдёшь в правилах Redux прямое указание об обратном —
  скажи владельцу, не меняй молча.
- Награды и счётные члены резолюций не затрагиваются по построению:
  `RESOLUTION_TAG_COUNTING_MODE = 'raw'`, награды — `'award'`.

### 2.2 Показ баффа — заказ владельца

`countAllTags()` считает **`'raw'`** (`Tags.ts:68`), а `ServerModel` шлёт клиенту именно его
(`tags: player.tags.countAllTags()`). Значит **зона меток сейчас баффа не увидит вообще** — и это
хорошо: она показывает печатную правду, которую ломать нельзя.

Сделай так, чтобы бафф был **виден, но отличим от печатного**:

- в зоне меток (`ConsoleResourcePanel` → `consoleTagEntries` / `consoleTagMatrix.ts`) метка науки
  получает **надбавку отдельным знаком** — зелёная приписка «+N» рядом с печатным числом, а не
  подменённое число. Игрок должен видеть и «сколько у меня напечатано», и «сколько будет учтено сейчас»;
- надбавка живёт **только пока закон принят**, и при смене закона исчезает;
- **источник надбавки называется** при осмотре (наведение/раскрытие): «+2 от закона «Финансирование
  исследований»» — не безымянный бонус (инвариант 4);
- модель: добавь в модель игрока **отдельное поле надбавок по меткам** (не подмешивай в `tags`), чтобы
  печатный счёт остался печатным. Дикая метка Учёных — тот же класс: если она сегодня тоже невидима,
  **покажи её тем же механизмом** (одна надбавочная модель на оба случая), но это отдельный коммит и
  отдельная строка в отчёте.

**Проверь и закрепи спеком**, что бафф действительно виден там, где игрок принимает решение: в проверке
требований карты при розыгрыше (карта с требованием «3 метки науки» становится играбельной), в
доступности действий, в превью.

## 3. ДЕЙСТВИЕ · повтор действия сыгранной карты = механизм Viron

Владелец прав: это буквально Viron. Смотри `src/server/cards/venusNext/Viron.ts` — приватный
`getActionCards(player)`:

```
tableau → isIActionCard → getCheckLoops() < 2 → actionsThisGeneration.has(card.name) && card.canAct(player)
```

плюс `SelectCard` и **`events.withCopiedAction(player, source, card, run)`** — областью событий, чтобы
результат копируемой карты атрибутировался источнику.

**Этот код уже продублирован:** `src/server/cards/promo/ProjectInspection.ts:40-55` содержит тот же
цикл слово в слово. Наша карта — **третий** потребитель.

- **Вынеси общий хелпер** («карты, чьё действие уже использовано в этом поколении и может быть
  выполнено снова») и переведи на него Viron и Project Inspection. Их юниты — проверка, что вынос
  ничего не сдвинул. Третью копию не писать.
- Действие резолюции объявляется через `ResolutionAction` и идёт по пути, который **уже построила
  RX24**: маркер `resolutionActionPrompt`, источник в «ДЕЙСТВИЯ КАРТ» рядом с партийными, общий
  композер с `resolution`. Ничего нового в этот путь добавлять не надо — только объявить действие.
- **Область событий обязательна**: повтор выполняется под `withCopiedAction` с источником-резолюцией,
  чтобы журнал и статистика связали цепочку «закон → карта → её результат», как у Viron.
- **Доступность и причина** (инвариант 2): нет ни одной карты с уже использованным действием, которое
  можно повторить → недоступно с причиной («Нет использованного действия, которое можно повторить»);
  использование потрачено → своя причина; сменился закон → действия нет.
- **Раз за поколение** (`usesPerGeneration` = 1), учёт — `recordResolutionActionUse`.
- Повторяемая карта выбирается игроком **всегда явно**, даже если кандидат один (инвариант 3).
- `preview` показывает список карт-кандидатов, как это делает `Viron.actionPreview`.

## 5. Бюджет проверки

Ново — бафф меток (и его показ) и общий хелпер повтора.

- **серверные юниты:** влияние 2 → метки науки при розыгрыше +2 (карта с требованием «3 науки»
  играбельна при 1 печатной и влиянии 2); в режиме `'award'` и `'raw'` бафф НЕ виден; **в `milestone`
  не виден** (отдельный спек); при смене закона исчезает; у не-участника нет; бот не тронут; дикая
  метка Учёных по-прежнему считается как раньше;
- **юниты повтора:** хелпер возвращает только карты с уже использованным действием и `canAct`;
  `getCheckLoops() >= 2` исключается; **Viron и Project Inspection дают те же списки, что до выноса**
  (это главная регрессия); повтор выполняется под `withCopiedAction` с источником-резолюцией; учёт
  использования; причины недоступности;
- **клиентские юниты:** надбавка рисуется отдельным знаком и не подменяет печатное число; исчезает без
  закона; источник назван;
- **РОВНО ОДИН новый e2e:** RX26 принята → в зоне меток у науки видна зелёная надбавка «+N» →
  игрок открывает действие резолюции → выбирает карту с уже использованным действием → действие
  выполняется повторно, и его результат виден; плитка действия становится «использовано»;
- **старые сюиты не гоняй**, фикстуру правь точечно (`FIXTURES=… npm run e2e:fixtures`).

Юнитами: Viron, Project Inspection, дикая метка Учёных, RX24 (путь действия резолюции), требования карт

## 7. Режим работы

Экономный. Коммит на блок, каждый зелёный по юнитам, `npm run lint`, `npm run build:test`,
`npm run make:cards`, `npm run make:css` перед визуальной проверкой. **Не пушить.** Документ карты —
`docs/TURMOIL_REDUX_RD_FUNDING.md`; журнал — `docs/claude/parliament-sitting-progress.md`. Чеклист
автора: строка «бафф меток — по образцу `wildTags` (внутри `includeTagSubstitutions`), показывается
надбавкой, печатный счёт не трогается».

**Параллельная работа:** общие файлы (реестр, локали, спек, журнал, `genfiles`) — только своя строка,
генерируемое не править руками. `Tags.ts`, `ParliamentHandler.ts`, `Viron.ts`, `ProjectInspection.ts` —
общие; перед выносом хелпера скажи владельцу, что трогаешь карты апстрима.

Гочи: `python3` здесь — заглушка Store, только `python` (длинные скрипты — файлом, не heredoc);
`cross-env` в bash нет — `NODE_ENV=… npx mochapack`; посевная колода сдвигается с ростом каталога —
сажать карту через `seatResolution`.

В отчёте: где именно прибавляется бафф и почему там; решение по вехам; форма надбавочной модели; что
стало с Viron и Project Inspection после выноса; четыре кадра; новые ключи i18n.

## 8. Нельзя

Прибавлять бафф через `extraScienceTags` (он безусловный — попадёт в награды). Подменять печатное число
меток в зоне меток. Писать третью копию цикла Viron. Выполнять повтор без `withCopiedAction`. Применять
повтор к карте без показа выбора. Скрывать недоступное действие вместо причины. Давать бафф не-участнику
или после смены закона. Гонять старые сюиты. Пуш и красные коммиты.
