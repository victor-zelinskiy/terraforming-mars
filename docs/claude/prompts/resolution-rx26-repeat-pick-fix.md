# Промт-фикс · RX26 R&D Funding: повтор действия идёт через ОБЩИЙ мост, а не через свою строку

Выдан 2026-09-26, поверх сданной RX26. **Регрессия интерфейса, не правил.** Сервер, пассив меток и
учёт использования трогать не нужно — речь только о том, ЧЕМ игрок выбирает повторяемое действие.

---

## 1. Что не так

Сейчас выбор повторяемой карты нарисован **внутри композера резолюции**: `ConsolePartyActionComposer`
получил свою ветку `tableauTargets()` (~637), читающую `entry.model.repeatActionPrompt`, и рисует
локальную строку «ДЕЙСТВИЕ КАРТЫ» с миниатюрой карты. Для игрока это новая, незнакомая поверхность.

**В проекте для этого есть общий механизм, и у него уже три потребителя.**
`src/client/console/consoleRepeatPick.ts`, заголовок модуля:

> «the console twin of the hand-pick / tableau-pick bridges, for the "repeat an already-used card
> action" cards (ProjectInspection [play] and Viron [corp action]). The SOURCE confirm surface shows the
> repeat as a SLOT. Selecting it hands the pick to the **ДЕЙСТВИЯ КАРТ list interface ADAPTED for repeat
> mode** (the SAME `ConsoleCardActions` overlay reused in `repeat` mode) … lets the player choose ONE
> activated action (**A = «Выбрать», never «Выполнить»**) and — if that action has pre-selects — compose
> them right there (reusing the SAME `ConsoleActionComposer`).»

Мост делает `pushWorkspaceFrame`, исходная поверхность остаётся смонтированной под `v-show` (её
состояние переживает пик), а `cancelConsoleRepeatPick` идемпотентен. Потребители:

- **Viron** — `ConsoleActionComposer.vue:3443`;
- **Project Inspection** — `ConsolePlayCardConfirm.vue:3194`;
- **Гидросеть** — `ConsoleShell.vue:14912`, с собственной крошкой через `source: {kicker, card, label}`
  и handoff «исходная поверхность отпускает первой, вложенная открывается на её settle».

То есть мост уже рассчитан на разные источники и разные крошки. Наша карта обязана стать четвёртым
потребителем, а не четвёртым интерфейсом.

## 2. Что сделать

1. **Убрать локальную строку выбора** из `ConsolePartyActionComposer` (`tableauTargets` и всё, что её
   рисует, включая её вклад в `decisionRows`). Композер резолюции показывает повтор **слотом** — ровно
   как `ConsoleActionComposer` показывает его у Viron («Действие для повтора» · пусто → приглашение;
   выбрано → графика действия + имя карты).
2. **Открывать `enterConsoleRepeatPick`** при выборе слота, с `source`, который даёт честную крошку
   резолюции (у Гидросети это `{kicker: 'Mars Hydronetwork', card, label}` — сделай свой аналог:
   кикер «ДЕЙСТВИЯ КАРТ», карта — лицо резолюции). Игрок попадает в привычный список «ДЕЙСТВИЯ КАРТ» в
   режиме repeat.
3. **Реши и объясни последовательность ответа.** У Viron пик происходит ДО отправки: слот заполняется,
   и финальный коммит собирает один батч
   `[<source>, {type:'card', cards:[chosen]}, ...composed]`. У нашей карты сервер присылает `SelectCard`
   как живой промпт. Допустимы оба пути, но **интерфейс для игрока обязан быть тем же**:
   - либо резолюция тоже собирает батч (ближе к Viron, меньше круглых поездок);
   - либо мост обслуживает живой промпт, и результат уходит ответом на него.
   Что бы ты ни выбрал — это должно быть **обобщение моста**, а не ветка «если резолюция». Если
   обобщение получается дороже одного вечера, скажи владельцу до того, как начнёшь.
4. **Маркер `repeatActionPrompt` оставь** — структурное опознание промпта правильно (инвариант 1:
   никогда по заголовку). Меняется только то, куда он ведёт: не в свою строку, а в мост.
5. **Сохрани закон A**: в режиме пика A — «Выбрать», а не «Выполнить». Действие выполняется только
   после финального подтверждения на исходной поверхности.

## 3. Проверка

- **клиентские юниты:** композер резолюции рисует СЛОТ (не список карт); выбор слота открывает мост;
  отмена возвращает в исходную поверхность с сохранённым состоянием; **Viron, Project Inspection и
  Гидросеть ведут себя как раньше** — это главная регрессия, их юниты обязательны;
- **e2e RX26 переписать** (не добавлять новый): вместо проверки локальной строки — переход в «ДЕЙСТВИЯ
  КАРТ» в режиме repeat, выбор карты там, возврат, финальное подтверждение, действие выполнено;
- `npm run lint`, `npm run build:test`, `npm run make:css` перед визуальной проверкой.

Глазами, один профиль, три кадра: слот в композере резолюции (пустой); список «ДЕЙСТВИЯ КАРТ» в режиме
repeat с кандидатами; слот заполнен выбранным действием.

## 4. Режим работы

Один-два коммита, зелёные юниты, **не пушить**. В отчёте: как устроена последовательность ответа
(батч или живой промпт) и почему; подтверждение, что три прежних потребителя моста не тронуты;
три кадра.

## 5. Нельзя

Оставлять второй интерфейс выбора повторяемого действия. Ветвить мост «если резолюция» вместо
обобщения. Менять A с «Выбрать» на «Выполнить» в режиме пика. Трогать серверную часть RX26 (пассив
меток, хелпер повтора, учёт использования) — она принята. Гонять старые сюиты целиком.
