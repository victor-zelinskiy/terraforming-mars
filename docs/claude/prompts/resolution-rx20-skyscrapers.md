# Промт исполнителю · RX20 Skyscrapers (Марс вперёд)

Выдан 2026-09-25. Карта вводит в игру то, чего в движке нет вообще: **на одной клетке может стоять
больше одного города**. Сервер тут простой, а вся цена — в ПОКАЗЕ: игрок обязан видеть на доске «здесь
у меня ДВА города», и момент, когда второй садится на первый, — самый тщательно проработанный кадр этой
карты. Владелец выделил это отдельно.

Процедура автора — `docs/claude/parliament-resolution-checklist.md`, гард —
`tests/parliament/ResolutionContract.spec.ts`. Образцы: **RX03 Biodome Contest** (награда всем + тайл),
**RX09 Colony Contest** (награда, которая не тайл Марса), `docs/claude/console/tile-replacement.md`
(как в прошлый раз расширяли сцену посадки под новый случай).

## 1. Карта

Скан: `C:\Users\zelin\Downloads\TM Turmoil Redux\Resolutions\Skyscrapers.png`.
Арт: `C:\Users\zelin\Downloads\Mars Arts\Skyscrapers_art.png` (владелец кладёт; имя сверь) →
`node scripts/import-card-art.mjs "<путь>" RX20` → `npm run make:cards`. Код RX20 — проверь, что свободен.

- **Партия:** Mars First (в RU — **Марс вперёд**). `compatibility` не объявлять.
- **Печатное правило:** *«The player that won this resolution and players with at least 2 Influence each
  gain a city tile that they MUST place on their existing city on Mars. (Each city in the stack scores VP
  from adjacent greeneries separately; you gain nothing if you have no city on Mars.)»*
- **Задание председателя:** **2 города на Марсе** — `{goal: {kind: 'tile', tile: 'city'}, count: 2}`
  (гекс с силуэтом города + оранжевый уголок «на Марсе»; сверено с таблицей значков §4.1.1).

### Чтения, которые надо зафиксировать

1. **Получатели — победитель И каждый участник с влиянием ≥ 2.** Это первая карта с таким порогом:
   не «всем», не «только победителю». Победитель получает тайл даже при влиянии 0 или 1.
2. **Размещение ОБЯЗАТЕЛЬНО и только на СВОЙ город на Марсе.** Не на чужой, не на космический город
   (вне Марса), не на пустую клетку. Кандидаты — ровно эти клетки; выбор показывается всегда, даже
   когда кандидат один (инвариант 3: «no auto-select»).
3. **Нет города на Марсе — не получаешь ничего**, и это НАЗЫВАЕТ СЕБЯ: «городов на Марсе нет — ярус
   некуда поставить» (инвариант 4). Не тихий ноль и не «нет влияния».
4. **Бонусы клетки НЕ выдаются повторно** — клетка накрыта, путь `coveringExistingTile` в `Game.addTile`
   это уже делает. Проверь и закрепи спеком, что ни печатные бонусы, ни океанское соседство не платятся
   второй раз: город уже стоял у этого берега.
5. **ПО: каждый город в стопке считает соседние озеленения ОТДЕЛЬНО.** Стопка из 2 городов рядом с
   3 озеленениями даёт 6 ПО.
6. **Ярус — НАСТОЯЩИЙ город и считается городом ВЕЗДЕ.** Старый никуда не делся, новый прибавился: у
   игрока стало на один городской тайл больше. Оговорка на карте касается только ПО потому, что там
   игрок иначе посчитал бы соседство один раз на клетку; «город есть город» уточнения не требует.
   Линия раздела проходит не по правилам, а по ВОПРОСУ:
   - **ВЕЛИЧИНА** («сколько у игрока городов», «сколько городов на Марсе», «сколько у игрока тайлов») —
     **суммирует высоты**: стопка из двух даёт 2;
   - **ПРЕДИКАТ** («эта клетка — город», «соседствует ли клетка с городом», «есть ли у игрока хоть один
     город», «можно ли сюда ставить») — **клетка одна**, высота не при чём.
   Затронуты: веха Mayor; награды Metropolist, Constructor, Urbanist и **Landlord** (он считает тайлы
   вообще — `awards/Landlord.ts`); счётчик поведения `Counter` (карты «за каждый ваш город»); Hospitals,
   Vermin, NewHolland; счёт бота. `getCitiesOffMars` НЕ затрагивается: ярус ставится только на Марсе.
7. **Бот** в Парламенте не участвует: тайла не получает, его города не трогаются.

## 2. Блок A · сервер: стопка

`Space.tile` — ОДИН тайл (`src/server/boards/Space.ts`), стопок движок не знает.

- **Заведи высоту стопки на клетке** — счётчик ярусов, а не массив тайлов: все ярусы — города одного
  владельца, второй тайл ничем не отличается от первого. Одно поле, значение по умолчанию = 1;
  **старые сейвы без поля читаются как 1** (инвариант деградации).
- Размещение — обычный `SelectSpace` с фильтром кандидатов; ответ идёт через `Game.addTile`, который и
  так умеет накрытие. Высота растёт на посадке.
- **ПО** (`calculateVictoryPoints.ts` ~244): сейчас обход клеток начисляет за город один раз. Для стопки
  начисляй по разу за каждый ярус, и **`CityVpDetail` должен нести высоту**, чтобы объяснение осталось
  честным: одна строка на ярус либо строка с явным множителем — реши и обоснуй в отчёте, но
  «6 ПО из ниоткуда» в разборе счёта быть не должно.
- **ОДНА функция величины.** `MarsBoard.getCities()` отдаёт список КЛЕТОК, и сегодня каждый счётчик
  берёт у него `.length` — с высотой это перестаёт быть мерой. Оставь `getCities` списком клеток (его
  читают предикаты, соседство, фильтры, `StJosephOfCupertinoMission`, `maybeAdjacentSpaces` в `Counter`)
  и заведи РЯДОМ одну функцию количества — сумму высот. **Переведи на неё всех потребителей-величин**
  (список в §1.6), спеком на каждого: место, что считает, ожидаемое число при стопке. Двух источников
  правды быть не должно — иначе одна панель скажет «2 города», а другая «1».
- Запись исхода резолюции несёт клетку и получившуюся высоту.

## 3. Блок B · ВИД СТОПКИ НА ДОСКЕ — половина ценности карты

Игрок должен понимать состояние клетки **не наводя курсор**. Требования:

- **Стопка читается силуэтом**: под верхним тайлом видны смещённые нижние ярусы (как стопка жетонов),
  с тенью между ними, дающей толщину. Верхний тайл — обычный городской, просто приподнят.
- **Число ярусов названо явно** — компактный счётчик на клетке (в духе существующих меток клетки), а не
  «догадайся по толщине». «Два» и «три» должны различаться мгновенно.
- **Гекс не разрастается**: стопка не залезает на соседние клетки и не ломает сетку; приподнятость —
  внутри клетки, по вертикали.
- **Цвет владельца остаётся читаемым** на верхнем ярусе, как у обычного города.
- Работает на всех профилях, включая **TV** и **перф-режим** (в перф-режиме — без теней, но счётчик и
  смещение остаются: это информация, а не украшение).
- **Осмотр клетки** (`BoardCellInfoPopover`) раскрывает состав: сколько ярусов, чьи, и **сколько ПО даёт
  каждый** по соседним озеленениям.
- **Превью размещения** на клетке-кандидате честно говорит, что получится: «станет 2 яруса» и прирост ПО.

## 4. Блок C · ПОСАДКА ПОВЕРХ — самый важный кадр карты

**Начни с того, что сцена накрытия сегодня НЕ ИГРАЕТ.** Шапка `consoleTilePlacement.ts` прямо это
заявляет: арм проверяется через `verifyPlacement`, и «a refused placement / a hazard / **a covered-tile
case** unwinds with zero trace». То есть без работы карта даст пустую клетку без анимации.

Расширять — **по образцу remove-and-replace**: тот случай уже научил арм нести декларацию промпта
(`hiddenTiles`), и `verifyPlacement` стал читать переход тайл→тайл как настоящее размещение. Сделай
третий законный случай — **надстройку** — тем же способом, не заводя параллельный путь.

**Хореография (это заказ владельца, прорабатывай тщательно):**

1. **Подлёт — не дугой, а стройкой.** Обычная посадка несёт тайл низкой дугой. Ярус приходит СВЕРХУ:
   выходит над клеткой, гасит горизонтальную скорость и **опускается вертикально** — так ставят блок
   краном. Разница с обычной посадкой должна быть видна без объяснений.
2. **Основание принимает нагрузку.** Пока ярус висит, существующий тайл отзывается: контур напрягается,
   лёгкая осадка вниз на 1–2 px. Реагирует ТОЛЬКО эта клетка — соседи неподвижны
   (`parliament-motion-taste-no-blink`).
3. **Контакт.** Короткий плотный удар: пыль по периметру гекса, микро-толчок основания, ярус
   останавливается с вертикальным смещением, показывающим толщину. Без отскока-мультяшности.
4. **Счётчик щёлкает В МОМЕНТ КОНТАКТА** — 1 → 2. Не раньше (ложь), не через 300 мс (потеря связи
   причины и следствия). Это главный информационный кадр: игрок видит, что стало два.
5. **Оседание.** Пыль опадает, тень между ярусами проявляется, клетка успокаивается.
6. **Печатных бонусов НЕТ** — и это сказано вслух (строкой ленты / чипом «ярус надстроен, бонусы клетки
   уже собраны»), а не молчанием там, где в обычной посадке был фейерверк наград.

Общие законы: `motionMs`, холды (завершение — сигнал самой сцены, никаких таймеров), честный откат при
отказе сервера, `prefers-reduced-motion` и перф-режим получают сокращённую, но связную версию (спуск +
щелчок счётчика).

**Несколько игроков получают тайл в одном заседании** — сцены идут по очереди, каждая в свой ход;
зритель видит свою посадку целиком, чужие — как обычные изменения доски со строкой в ленте.

## 6. Бюджет проверки

Ново — стопка на клетке и посадка поверх.

- **серверные юниты:** победитель получает тайл при влиянии 0; участник с влиянием 2 получает, с
  влиянием 1 — нет; без города на Марсе — пропуск с причиной; кандидатами становятся только свои города
  на Марсе (чужой, космический, пустая клетка — нет); высота растёт на 1; бонусы клетки и океанское
  соседство повторно не платятся; ПО = высота × соседние озеленения; `CityVpDetail` объясняет число;
  **величина считает стопку как 2** (Mayor, Metropolist, Constructor, Urbanist, Landlord, `Counter`,
  Hospitals, Vermin, NewHolland, счёт бота — по спеку на каждого), **предикат — как одну клетку**
  (соседство, «есть ли город», допустимость размещения); старый сейв без поля читается как высота 1;
  бот не тронут;
- **клиентские юниты:** стопка рисуется с ярусами и счётчиком; счётчик совпадает с моделью; осмотр
  клетки раскрывает ПО по ярусам; превью обещает то, что даст коммит;
- **РОВНО ОДИН новый e2e:** RX20 принята → у зрителя есть город с соседним озеленением → выбор клетки →
  **сцена надстройки: вертикальный спуск, контакт, счётчик 1→2 в момент контакта** → на доске видна
  стопка → в разборе счёта два городских вклада на одной клетке. Пробник утверждает видимость источника
  и цели и движение между ними (`animation-needs-a-visible-stage`), а о кадрах судит по тикам
  (`probe-sample-carries-its-clock`);
- **старые сюиты не гоняй**, фикстуру правь точечно (`FIXTURES=… npm run e2e:fixtures`).

## 7. Регрессия и кадры

Юнитами: обычная посадка тайла (не поехала), remove-and-replace (второй случай арма жив), счёт ПО за
города без стопок, RX03 (тайл-награда).

Глазами, один профиль, **пять кадров**: клетка со стопкой на доске (обычный зум); она же в TV-профиле;
момент контакта яруса; осмотр клетки с ПО по ярусам; разбор счёта в финале.

## 8. Режим работы

Экономный по проверке, НЕ экономный по сцене надстройки — это заказ владельца. Коммит на блок
(A сервер · B вид стопки · C сцена посадки · D лицо/локаль + юниты и один e2e), каждый зелёный по
юнитам, `npm run lint`, `npm run build:test`, `npm run make:cards`, `npm run make:css` перед визуальной
проверкой. **Не пушить.** Документ карты — `docs/TURMOIL_REDUX_SKYSCRAPERS.md`; журнал —
`docs/claude/parliament-sitting-progress.md`. Чеклист автора: строка «СТОПКА городов — высота на клетке,
ПО за каждый ярус, надстройка = третий законный случай арма посадки».

Гочи: `verifyPlacement` сегодня отменяет накрытие — расширять через декларацию промпта, как
remove-and-replace; посевная колода сдвигается с ростом каталога — сажать карту через `seatResolution`;
heredoc в Bash обрезается около 6 КБ — большие файлы через Write.

В отчёте: как названа высота стопки и как она сериализуется; список мест, считающих города, с
подтверждением «стопка = один город» везде кроме ПО; как расширен арм посадки; тайминги сцены
надстройки; пять кадров; новые ключи i18n.

## 9. Нельзя

Хранить стопку массивом тайлов или дублирующей структурой рядом с клеткой. Позволять ставить ярус на
чужой город, на космический город или на пустую клетку. Применять размещение без показа выбора.
Выдавать бонусы клетки второй раз. Держать ДВА источника правды о количестве городов. Умножать на
высоту то, что спрашивает про клетку (соседство, допустимость размещения, «есть ли город»). Показывать
стопку только толщиной, без числа. Оставлять надстройку на обычной дуговой посадке — это должен быть
вертикальный спуск. Двигать счётчик не в момент контакта. Заводить второй путь анимации вместо третьего
случая существующего арма. Гонять старые сюиты. Пуш и красные коммиты.
