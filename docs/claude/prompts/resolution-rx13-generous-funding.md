# Промт исполнителю · RX13 Generous Funding (Зелёные)

Выдан 2026-09-24. Карта маленькая и без выбора игрока, но приносит **третий вид счётного члена**:
считается не табло и не поле, а **собственный показатель игрока — рейтинг терраформирования, порогами
по 5 сверх 15**. Дальше тем же видом поедут все «за каждые N чего-то твоего» (например, шаги
производства в Бюджетах). Поэтому делается членом семейства, а не веткой для одной карты.

Процедура автора — `docs/claude/parliament-resolution-checklist.md`, гард —
`tests/parliament/ResolutionContract.spec.ts`. Образцы: **RX08 Colonization Funding** (последний, кто
добавлял вид счёта — `{kind:'board'}`, `ResolutionCountModel.spaces`, глиф `{kind:'tile'}`, семейство
стенда `counted-board`; повтори процедуру ровно), RX02 Architecture Award (счёт + влияние + потолок).

## 1. Карта

Скан: `C:\Users\zelin\Downloads\TM Turmoil Redux\Resolutions\Generous Funding.png`.
Арт владелец положит в `C:\Users\zelin\Downloads\Mars Arts\Generous Funding_art.png` (имя сверь: у
части карт суффикс `_art`, у части нет) →
`node scripts/import-card-art.mjs "<путь>" RX13` → `npm run make:cards`. Код RX13 — проверь, что свободен.

- **Партия:** Greens (Зелёные). **Совместимость:** нет.
- **Эффект всем:** *«Gain 2 M€ for each point of Influence and each complete set of 5 TR over 15.»*
  → `unit: {kind:'stock', resource: MEGACREDITS}`, `perInfluence: 2`, `count: {id: <новый>, per: 2}`.
  **Потолка нет** — `cap` не объявляется.
- **Части победителя нет.** Каждый участник считает по своему РТ и своему влиянию.
- **Задание председателя:** +3 РТ — `{goal: {kind: 'tr'}, count: 3}` (`QuestTracker` и `questRender`
  это уже умеют: `b.tr(count)`).

### Правило счёта, как его надо понимать

1. **Считаются полные пятёрки сверх 15:** `⌊max(0, РТ − 15) / 5⌋`. РТ 15 → 0; 19 → 0; 20 → 1; 24 → 1;
   25 → 2; 30 → 3. Остаток не платит ничего.
2. **Число читается в момент выплаты** и замораживается в записи, как любой счёт.
3. **Влияние платит само по себе:** РТ ниже 20 и влияние 3 — это +6 M€. Пропуск только когда итог ноль.
4. **Порог 15** — константа правила карты, не «стартовый РТ»: в соло и при вариантах старта РТ может
   быть иным, порог не двигается.
5. **Бот** в Парламенте не участвует — ничего не получает, его РТ никому не считается.

## 2. Что ново: счётный член по ПОКАЗАТЕЛЮ игрока

Сегодня `ResolutionCountKind` знает три вида: `cards`, `tags`, `board`. Все три отвечают на вопрос
«сколько у тебя ШТУК чего-то» и объясняют число СПИСКОМ (карты или клетки). Здесь объяснять списком
нечего: число выводится из одной величины по формуле с порогом и шагом.

Требуется **четвёртый вид** (имя твоё, например `{kind: 'threshold', metric, over, step}`):

- `metric` — что читается (сейчас `terraformRating`; словарь расширяемый, следующее слово понадобится
  Бюджетам);
- `over` — порог (15), `step` — размер пятёрки (5);
- **число** = `⌊max(0, значение − over) / step⌋`, считается ОДНОЙ функцией, которую читают сервер,
  чтение и стенд. Правило нигде не дублируется (инвариант 7);
- **объяснение** — не список, а **разбор величины**: текущее значение, порог, шаг, сколько полных
  наборов и сколько не хватает до следующего. Расширь `ResolutionCountModel` членом для этого разбора
  (по образцу того, как RX08 добавил `spaces` рядом с `cards`) — ОДНА модель на все виды, второй тип не
  заводить. У `cards`/`spaces` этот член отсутствует, у `threshold` отсутствуют списки.

**Значение берётся у движка** (`player.terraformRating`), не пересчитывается из слагаемых.

## 3. Блоки работы

**A · сервер.** Новый вид и id счёта, функция порога, чтение в `resolutionCount` (ветка рядом с
`board`), `declaredCountIds` подхватит сам. Файл карты по чеклисту: `id`
(`RDX_GREENS_GENEROUS_FUNDING`), `code` RX13, партия, `copies`, `renderData` (2 M€ / влияние + 2 M€ за
набор «5 сверх 15», как на скане), `text`, `scaled`, один `immediateStep` (платит либо отчитывается
`skipped` с причиной и величиной), задание.

**B · чтения.** Запись в `yieldCountPresentation` для нового id: глиф — **значок РТ** (тот же, что
печатает лицо; `CountedObjectGlyph` получает вид «показатель», если сегодняшние виды его не выражают),
`pluralKey` («${0} полных набора по 5 РТ сверх 15»), `ruleKey` (порог, шаг, остаток не платит),
`skipReasonKey` («Нет наборов РТ и нет влияния»). Разбор величины печатается в детальном осмотре вместо
списка карт: «РТ 24 · порог 15 · 1 полный набор · до следующего 1». Формула на лице и в чтении — одна
отрисовка.

**C · стенд, лицо, локаль, арт.** «Полигон»: новое семейство счёта (по образцу `counted-board`) —
синтетические значения РТ (14 / 15 / 20 / 24 / 30), счёт через ту же функцию, не вписанное число. Лицо
«Грамоты», сноска задания (+3 РТ). Ключи i18n — грепни точные строки до добавления.

**D · юниты и один e2e.**

### Чего делать НЕ надо

Ни стадии, ни встроенного шага, ни новой поверхности: у карты нет вопроса игроку. Выплата — штатная
волна M€ в рельсу (RX08/RX12 путь), `parliamentRewardBeat` и адреса не трогать.

## 4. Бюджет проверки

Ново — вид счёта по показателю. Значит:

- **серверные юниты:** таблица РТ → наборов (14, 15, 19, 20, 24, 25, 30); итог = 2×(наборы + влияние);
  РТ 15 и влияние 3 → +6; итог ноль → пропуск с причиной; счёт заморожен в записи; бот не получает;
  разбор величины совпадает с числом;
- **клиентские юниты:** чтение печатает «[РТ] 24 → 1 набор + [влияние] 3 → +8 M€»; разбор величины
  вместо списка карт; существующие виды счёта (карты, метки, поле) читаются как раньше — это и есть
  защита общей модели;
- **РОВНО ОДИН новый e2e:** RX13 принята, у зрителя РТ 24 и влияние 3 → чтение с разбором на панели
  голосования → стадия НАГРАДА → чип +8 M€ стартовал из графики резолюции (видимой), сел в рельсу,
  счётчик тикнул на посадке;
- **старые сюиты не гоняй**, фикстуру правь точечно (`FIXTURES=… npm run e2e:fixtures`).

## 5. Регрессия и кадры

Юнитами: RX02 (карты), RX04/RX06 (метки), RX08 (поле) — общая модель счёта не поехала.

Глазами, один профиль, три кадра: чтение с разбором на панели голосования; стадия НАГРАДА после посадки
чипа; стенд «Полигона» со счётом по показателю.

## 6. Режим работы

Экономный. Коммит на блок, каждый зелёный по юнитам, `npm run lint`, `npm run build:test`. **Не
пушить.** Документ карты — `docs/TURMOIL_REDUX_GENEROUS_FUNDING.md`; журнал —
`docs/claude/parliament-sitting-progress.md`. Чеклист автора: строка «счётный член по ПОКАЗАТЕЛЮ
игрока (порог + шаг) — объяснение разбором величины, не списком».

Гочи из прошлых карт, которые здесь применимы: рельса печатает величину со знаком; ключ потолка тут не
нужен (потолка нет); посевная колода сдвигается с ростом каталога (`quietWinnerIndex` в
`parliamentArrange`); страница НАГРАДА тихой карты стоит только пока летит чип; heredoc в Bash
обрезается около 6 КБ — большие файлы через Write.

В отчёте: форма вида счёта и разбора; таблица РТ → наборов; три кадра; новые ключи i18n; подтверждение
зелёных юнитов RX02/RX04/RX06/RX08.

## 7. Нельзя

Пересчитывать РТ из слагаемых вместо `player.terraformRating`. Прятать формулу порога в карте вместо
общей функции. Объяснять число пустым списком карт. Заводить второй тип модели счёта. Объявлять потолок,
которого на карте нет. Двигать порог 15 под стартовый РТ варианта. Строить стадию или шаг там, где нет
вопроса. Гонять старые сюиты. Пуш и красные коммиты.
