# Промт исполнителю · Парламент Turmoil Redux — «ОБНОВЛЕНИЕ»: такт, которого не было

Выдан 2026-09-22 по ручной проверке заседания (три кадра: НАГРАДА → ИТОГИ → обзор следующего
поколения). Большая итерация. Половина её — строгая механика по правилам, половина — анимационная
подача, в которой тебе дана свобода. Границы между ними проведены ниже явно.

---

## 0. Что сломано, и почему это не баг, а недостроенный такт

**Кадры владельца.** На стадии НАГРАДА у «Марс Вперёд» и «Индустриалистов» есть народная поддержка. На
стадии ИТОГИ её нет ни у партий, ни на их картах: под «Центральной энергосетью» и «Архитектурной премией»
написано «0 делегатов». В обзоре следующего поколения на каждой из них стоит по одному нейтральному
делегату. Игрок видел, как поддержка появилась, и не видел, куда она делась.

**Диагноз снят по коду; перепроверь его сам перед правкой, но не открывай заново.**

1. **Сервер прав.** `stepRefresh` делает ровно то, что спека §1.3 п.5: сбрасывает все карты области,
   раздаёт три заново (`drawDistinct`: пустая колода → перетасованный сброс, карта неподходящей партии →
   в сброс и следующая), при раздаче каждой карты переносит запас её партии на неё голосами
   (`moveSupportToSlot` → `neutralVotes`), потом лобби. Третий кадр — честное состояние.
2. **Обновление не существует как такт.** `SittingStage` = вердикт · принятие · награда · итоги. Бет
   `renewal` играет как прелюдия к раскрытию панели итогов на странице, чья крошка уже говорит «ИТОГИ».
   Лента с ключом «Обновление · народная поддержка становится голосами» в коде есть
   (`parliamentBand.ts:355`), а такта, которому она принадлежит, нет.
3. **Механика симптома.** Колода была пуста, обе проигравшие карты вернулись из перетасованного сброса.
   Сработало исключение P-22 («физически карта стол не покидала», `returningInstances`): ничего не
   улетает, ничего не раздаётся. Из-за этого в `beatResults` не вызывается `releaseTable()`, и область
   до конца заседания рисуется из `heldSlots` — снимка «как проголосовали», где голосов нет. Бет посадки
   кубов ищет гнёзда на этой старой разметке, не находит, `flyCube` без цели сразу зовёт колбэк посадки,
   холды `hiddenCubes` / `support` снимаются без единого полёта. Куб с плитки исчез, на карту ничего не
   прилетело, счётчик под картой считает по снимку, панель итогов читает живую модель. Ровно три кадра.
4. **Такт нечестен и при полной колоде, это просто реже видно.** Кубы поддержки летят из НЕЙТРАЛЬНОГО
   РЕЗЕРВА в шапке (`placeCubeRect(root, '[data-parl-neutral-cube]')`), а не с плитки партии; плитка при
   этом роняет свой куб по посадке — двойник из другого места. Делегаты игроков с проигравших карт не
   летят никуда: спека возвращает их владельцам при сбросе, сервер делает это вычисляемым ledger'ом, но в
   `summary` записи нет (`returned` есть только для принятой карты), и клиент сыграть это не может.
5. **Пробник этого не поймал**, потому что проверял факт события, а не видимость участников.

## 1. Источник истины: правила обновления области

Спека `docs/TURMOIL_REDUX_SPEC.md` §1.3 п.5 (по рулбуку с. 11–12), подтверждено цитатами владельца:

1. Если игра не закончена: **сбросить** две оставшиеся карты области; **делегаты с них возвращаются
   владельцам** (игроков — в резерв, нейтральные — в запас).
2. **Добирать по одной** в слоты от ближайшего к ENACTED. Партия карты не должна совпадать ни с одной
   уже стоящей в области, ни с партией ENACTED — иначе **карта сбрасывается и берётся следующая**.
   **При пустой колоде — перетасовать сброс** и продолжать. Если подходящей карты нет нигде — слот
   остаётся пустым.
3. Затем **все** нейтральные из народной поддержки партий, чьи карты появились, **переходят на эти карты
   как голоса**.
4. Затем каждому, у кого в лобби пусто и есть резерв, — **делегат в лобби**.

**Закон итерации: физика на экране следует этому списку буквально, и исключений для «вырожденных»
случаев нет.** Карта, вернувшаяся из перетасованного сброса, по правилам ушла со стола и была сдана
заново — значит, и на экране она уходит и сдаётся заново. То, что она та же, игрок увидит сам, и
«перетасована» перестанет быть словом в панели. Исключение P-22 удаляется вместе с
`returningInstances` и всем, что на нём стоит.

## 2. Блок A · сервер: обновление как ЖУРНАЛ событий

Клиент не может честно сыграть то, чего сервер не записал. Сегодня `summary` несёт три списка
(`discarded`, `refreshed`, `lobbyRefilled`), и по ним нельзя восстановить ни порядок, ни перетасовку, ни
отвергнутые карты, ни делегатов, ушедших с проигравших. Порядок при этом существенен: перетасовка может
случиться посреди раздачи, и карта, только что ушедшая в сброс, может вернуться второй.

Требуется **упорядоченный журнал обновления** в `summary` (имя и форма — твои, ниже суть). Каждая
запись — одно физическое событие в том порядке, в каком его произвёл сервер:

| Событие | Что несёт |
| --- | --- |
| карта покинула область | instance, слот, **делегаты по владельцам**, которые с неё вернулись (как `returned` у принятой) |
| сброс стал колодой | момент в последовательности; размер |
| карта вскрыта и отвергнута | instance, причина (партия уже в области / партия ENACTED), ушла в сброс |
| карта сдана в слот | instance, слот, откуда (колода как она была / перетасованная) |
| поддержка стала голосами | партия, карта, сколько |
| делегат в лобби | игрок |

Старые три списка можно оставить как производные для совместимости, но директор читает журнал.
Сохранения без журнала (старые сейвы, фаза до обновления) — клиент показывает состояние без такта, как
сейчас делает для полей, которых нет. Идемпотентность шага `refresh:<generation>` не меняется.

Спеки: последовательность записей на четырёх сценариях раздела 5 совпадает с тем, что физически
произошло в `Parliament` (порядок сброса и раздачи, момент перетасовки, отвергнутые, `neutralVotes`).

## 3. Блок B · клиент: ОБНОВЛЕНИЕ — собственный такт ДО итогов

- Новая стадия в `SittingStage` между наградой и итогами. Крошка: `ЗАСЕДАНИЕ › ОБНОВЛЕНИЕ`. Лента — по
  контракту зон v5: «поддержка становится голосами» и что происходит на столе сейчас (уход, перетасовка,
  раздача) — только причина, никакой прозы.
- **Тело — ряд партий всю физику такта.** Кубы поддержки уходят с плиток, значит плитки обязаны быть
  видны. Панель итогов раскрывается только на следующей странице, после посадки последнего объекта
  (закон v4: анимации нужна видимая сцена).
- `heldSlots` освобождается **всегда**, когда такт начинает уход карт, без ветвления по «карта та же».
  После такта область рисуется из живой модели.
- Холды такта сеются в том же синхронном блоке, что применение вида (`parliamentSittingSeed.ts`), и
  снимаются **только посадкой**; полёт без цели — дефект сцены, а не повод снять холд молча. Если
  источник или цель не измеряются, такт обязан это заметить и сообщить (пробник это поймает), а не
  выродиться в присваивание.
- Страница такта — «auto» как принятие и награда; A во время такта — «дожать», не рекламируется.
- Потолок бета (`sittingDirector.ts` ≈ 2.4 с для renewal) поднимается осознанно под новую длину такта и
  остаётся потолком, а не ожидаемой длительностью.

## 4. Блок C · анимация: здесь тебе дана свобода

Владелец просит **главный акцент на физичности и ощущении настольной игры**, на уровне лучших
анимаций проекта или выше. Он не диктует раскадровку — он называет, что должно ЧУВСТВОВАТЬСЯ. Спроектируй
подачу сам, в языке проекта.

### Что должно чувствоваться

- **Уходящая резолюция** — премиальный 3D-переворот рубашкой к игроку перед уходом, как карты уходят в
  драфте между поколениями (`cardExitDirector.ts`: `runHeroPick`, `applyDiscardExit`), и лучше. Карта —
  предмет с двумя сторонами и толщиной, который переворачивают и убирают со стола, а не картинка, которая
  гаснет. Её делегаты **сначала** возвращаются владельцам — с карты, к резерву каждого, по владельцу.
- **Перетасовка при пустой колоде** — отдельное, видимое событие: сброс физически становится колодой, и
  только потом начинается раздача. Это тот самый случай, где правила и экран сегодня расходятся; после
  твоей работы игрок должен понимать «перетасована» без чтения панели.
- **Раздача** — карта покидает верх колоды (живой pile, `data-parl-deck-top`), переворачивается в полёте
  одним движением и **бесшовно** ложится в свой слот: место под ней ждёт, посадка это событие, прокси
  сменяется живой картой без кадра «двух карт». Карта, которая только что ушла в сброс и вернулась,
  проходит ВЕСЬ путь.
- **Отвергнутая карта** — вскрылась, не подошла по партии, ушла в сброс. По правилам это происходит, и
  игрок вправе это видеть; как коротко и внятно это подать — твоё решение.
- **Поддержка становится голосами** — кубы летят **с гнёзд плитки партии** на карту этой партии, по
  одному, каждый в своё гнездо. Плитка отпускает куб в момент его старта, карта принимает в момент
  посадки, счётчик под картой тикает на посадке. Никаких двойников из шапки.
- **Пустой слот** — если подходящей карты нет нигде, слот честно остаётся пустым, и лента называет
  причину (сегодня это уже делает подпись «в колоде нет резолюции другой партии»).
- **Лобби** — как сейчас, по владельцу.

### Образцы, на которые равняться (это язык проекта, не предложение скопировать)

- `src/client/console/cardFlight/card3dInner.ts` — физическое тело карты. Два закона нарушать нельзя:
  **никогда не анимировать `opacity` на inner** (ломает `preserve-3d`, переворот показывает зеркало
  лица), **никогда не делать overshoot на `rotationY`** (вспышка зеркальной рубашки — единственный
  артефакт, который карта показать не может; овершут ездит на scale внешнего элемента).
- `src/client/console/cardDeal/premiumTurn.ts` — ЕДИНСТВЕННЫЙ способ, которым карта открывается в этом
  форке (четыре канала одного движения). Не пиши второй.
- `src/client/console/cardDeal/cardDealDirector.ts` и `cardCarry.ts` — раздача: один носитель
  (позиция, масштаб, поворот на одном ease по низкой дуге, центр истинный), **посадки — это события**
  (раздача каскадом, приземления по одному читаемому такту), дилер может быть настоящей стопкой.
- `src/client/console/cardDeal/cardExitDirector.ts` — уход карт со стола (контракт `onLift`: реальная
  карта исчезает в том же кадре, в котором прокси уже стоит).
- Уже существующий `dealResolutionCard` (`parliamentFlights.ts`) знает, как перевернуть резолюцию в
  полёте — расширяй его, не дублируй.
- Вкус: `docs/CONSOLE_SURFACE_MOTION.md`, `.claude/rules/animations.md`, память проекта о моушене
  Парламента: реагирует только то, чего коснулись; подпись не опережает объект; цвет и состояние едут с
  объектом; никакого мигания.

### Что не обсуждается

Один motion-систем: `motionMs`, `MOTION_EASE`, `prefers-reduced-motion` (позы сразу, холды
регистрируются и снимаются синхронно). Критический бет держит animation hold, снимаемый собственным
завершением, не таймером. Прокси рождаются невидимыми и позиционируются до первого кадра. Всё летает на
фиксированном слое и не создаёт прокручиваемого переполнения. `title` запрещён. Бюджет краски: на Deck
шесть карт и шесть плиток — обычная картина.

## 5. Малая колода: движок обязан работать на ЛЮБОМ составе

Сейчас реальных резолюций мало, и пустая колода — норма, а не край. Позже карт станет больше, и край
станет редким, но движок не имеет права на нём ломаться. Обязательная таблица сценариев, каждый — спек на
сервере и пробник на клиенте:

| # | Сценарий | Что должно произойти |
| --- | --- | --- |
| 1 | колода полная | две уходят, три сдаются из колоды, поддержка садится, лобби |
| 2 | колода пуста, обе вернулись | две уходят в сброс, **сброс становится колодой**, обе сдаются заново, поддержка садится на них |
| 3 | одна из колоды, потом перетасовка посреди раздачи | порядок событий в журнале и на экране совпадает |
| 4 | карта отвергнута по партии | вскрылась, ушла в сброс, сдана следующая |
| 5 | подходящей карты нет нигде | слот остаётся пустым с причиной |
| 6 | на проигравшей карте делегаты игрока | они возвращаются владельцу ДО ухода карты |
| 7 | финальная фаза | обновления нет вовсе — ни такта, ни ленты |

## 6. Пробники

Правило прежнее и без него работа не принимается: **каждый пробник утверждает видимость источника и
цели и движение между ними**; пробник факта считается отсутствующим.

1. **Уход.** Каждая уходящая карта видима в слоте до старта, повёрнута рубашкой в полёте (угол растёт
   монотонно, без овершута), исчезает у колоды/сброса; её делегаты стартовали с карты и сели в резерв
   владельца — при видимом резерве.
2. **Перетасовка.** В сценарии 2 есть кадр, где сброс становится колодой, и он **предшествует** первой
   раздаче.
3. **Раздача.** Каждая сданная карта стартовала с живого верха колоды, лицо открылось в полёте один раз,
   посадка совпала со слотом (дельта ≤ 1 px), ни одного кадра с двумя картами в одном слоте.
4. **Поддержка.** Каждый куб стартовал с гнезда СВОЕЙ плитки (видимой), сел в гнездо на карте (видимой);
   счётчик под картой равен записи сервера после последней посадки; в шапке нейтральный запас не
   менялся.
5. **Тело и лента.** На всём такте тело = ряд партий, панель итогов не видна ни в одном кадре; крошка
   говорит «ОБНОВЛЕНИЕ»; лента не переносится и не срезается предком.
6. **Никаких присваиваний.** Ни один холд такта не снялся без посадки: пробник ловит `flyCube` /
   `dealResolutionCard`, вернувшие `undefined` при живой сцене.
7. **Итоги после.** Панель раскрывается только после последней посадки; «0 делегатов» под картой с
   голосами — провал.

Сценарий 2 — обязательный e2e, он и есть кадры владельца.

## 8. Регрессия

Глазами и кадрами, три профиля, Deck отдельно: заседание целиком на сценариях 1, 2, 4, 6; финальная фаза;
свёрнутое и восстановленное заседание посреди такта (холды переживают секцию, такт доигрывается с
непроигранной страницы); перезагрузка на воротах adjourn (панель стоит, такт не переигрывается).

## 9. Режим работы

Экономный: юниты плюс пробники раздела 6, только они. Коммит на блок (A сервер · B такт · C анимация ·
D пробники и переписанные тесты), каждый зелёный по юнитам, `npm run lint`, `npm run build:test`. **Не
пушить.** Журнал — `docs/claude/parliament-sitting-progress.md`, раздел «Обновление». В отчёте: форма
журнала обновления, раскадровка такта с замерами, таблица сценариев с результатом каждого, список
переписанных тестов и что именно в них изменилось.

## 10. Нельзя

Оставлять ветвление по «карта та же» — исключений для правил нет. Летать из нейтрального резерва тем, что
по правилам уходит с плитки. Снимать холд без посадки. Второй способ открыть карту помимо
`premiumTurn`. `opacity` на inner, овершут на `rotationY`. Панель итогов поверх ряда партий, пока по столу
что-то движется. Крошка «ИТОГИ» на такте, который итогами не является. Молчание о пустом слоте. Пуш и
красные коммиты.
