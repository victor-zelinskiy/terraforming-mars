# Промт исполнителю · RX18 Medical Database (Учёные)

Выдан 2026-09-24. Карта стоит на готовой раскладке RX06 и приносит одно новое свойство: **единицы
выплаты бывают ДВУХ ВИДОВ** — данные или бактерия. Это первая карта семейства, где множество
получателей собирается из двух источников сразу.

Процедура автора — `docs/claude/parliament-resolution-checklist.md`, гард —
`tests/parliament/ResolutionContract.spec.ts`. Образцы: **RX06 Cloud Development** (раскладка: общий
`AddResourcesToCards`, маркер `cardResourceDistributionPrompt`, шаг `distribute` в `ConsoleTaskHost`,
семейство `distributed`, `spread: true`), **RX04 Central Power Grid** (счёт по меткам).

## 1. Карта

Скан: `C:\Users\zelin\Downloads\TM Turmoil Redux\Resolutions\Medical Database.png`.
Арт: `C:\Users\zelin\Downloads\Mars Arts\Medical Database_art.png` (владелец положил; имя сверь) →
`node scripts/import-card-art.mjs "<путь>" RX18` → `npm run make:cards`. Код RX18 — проверь, что свободен.

- **Партия:** Scientists (Учёные). **`compatibility` не объявлять** — оба ресурса базовые для тех
  дополнений, что уже обязательны; карта раздаётся всегда (см. §1.4 про отсутствие держателей).
- **Печатное правило:** *«When enacted: Add 1 data or microbe resource to any card for every Science tag
  you have + Influence. (Each resource can be different, and can go on a different card.)»*
- **Части победителя нет**, потолка нет, мирового шага нет, пассива нет.
- **Задание председателя:** **2 метки науки** — `{goal: {kind: 'tag', tag: Tag.SCIENCE}, count: 2}`
  (круг с атомом = метка; вид задания существует).

### Чтения, которые надо зафиксировать

1. **N = метки науки + влияние**, у каждого своё; счёт — новый id вида `tags` (`scienceTags`),
   `RESOLUTION_TAG_COUNTING_MODE` как у всех (печатные метки, без подстановки диких).
2. **Каждая единица кладётся отдельно и может лечь на свою карту** — это ровно `spread`, механизм RX06.
3. **Вид единицы следует из КАРТЫ, а не из отдельного вопроса.** У карты ровно один `resourceType`
   (`Player.getResourceCards`), поэтому «данные или бактерия» — это не второй вопрос игроку, а то, что
   множество получателей собирается из держателей ОБОИХ видов. Игрок раскладывает по картам; вид каждой
   единицы определён картой, которая её приняла.
   **Единственное исключение** — карта с `CardResource.WARE`: она числится держателем любого вида
   (`getResourceCards` пропускает её всегда). В состоянии хранится только счётчик, а не тип единицы,
   поэтому отдельный вопрос о виде для неё ничего не меняет — журнал называет ресурс карты. Закрепи
   спеком; если найдёшь контрпример (карта, где тип принятой единицы наблюдаем), скажи в отчёте.
4. **Держателей может не быть вовсе** — тогда выплата не происходит и НАЗЫВАЕТ СЕБЯ с величиной:
   «5 ресурсов некуда положить — нет карт, копящих данные или бактерии» (инвариант 4). Это не
   «нет влияния» и не тихий ноль.
5. **Бот** в Парламенте не участвует: ни единиц, ни счёта его меток.

### Факт, который меняет план проверки

**В премиум-скоупе НЕТ НИ ОДНОЙ карты с ресурсом `DATA`** — он живёт только в `moon`, `pathfinders`,
`underworld` (проверено грепом). То есть в обычной игре выбор вырожден: держателями будут только карты
бактерий. Отсюда:

- механика обязана быть честной (в игре с Pathfinders данные появятся), но **e2e берёт бактерии**;
- ветка данных проверяется **юнитом на синтетической карте** (`fakeCard` с `resourceType: DATA`);
- на стенде «Полигона» синтетические табло должны включать обе ветки и смешанный случай.

Это же объясняет, почему `Diverted Research` лежит в `skip`, а эта карта — нет: у неё есть альтернатива.

## 2. Что ново · блок A (сервер)

### 2.1 Раскладка по НЕСКОЛЬКИМ видам

`AddResourcesToCards` сегодня принимает ОДИН `resourceType` и собирает держателей через
`getResourceCards(resourceType)`. Расширь его на **список видов**:

- держатели — объединение по видам, без дублей, в стабильном порядке табло;
- обе формы шага сохраняются как есть: распределение (N ≥ 2 и ≥ 2 держателей, маркер
  `cardResourceDistributionPrompt`) и обычный пик (N = 1 или один держатель, `autoSelect: false` — закон
  «на ЛЮБУЮ карту» форка);
- валидация «сумма = N до применения» (`InputError`, промпт стоит, ничего не изменено) — не трогать;
- запись о посадке несёт **вид, определённый картой**, чтобы журнал и чтение печатали «+1 бактерия на
  «Гетерогенные бактерии»», а не безликую единицу;
- **один вид = список из одного**: старые вызывающие (Cyanobacteria, Communication Boom, RX06) меняются
  только сигнатурой, поведение байт-в-байт. Второй параллельный класс не заводить.

### 2.2 Объявление эффекта

`InfluenceYieldUnit` сегодня — `{kind: 'cardResource', resource, spread?}`. Расширь на **список видов**
тем же приёмом (один вид = список из одного). Карта объявляет `[DATA, MICROBE]`, `spread: true`,
`perInfluence: 1`, `count: {id: 'scienceTags', per: 1}`, без потолка.

### 2.3 Новый id счёта

`scienceTags` → `{kind: 'tags', tags: [Tag.SCIENCE]}`. Вид существует (RX04/RX06), добавляется один id
и одна запись в чтениях.

## 3. Блок B — чтения

- **формула**: «метки науки 3 + влияние 2 = **5**», разбор счёта — список карт с меткой (вид `tags`
  это уже умеет);
- **единица называется двумя видами**: и на лице, и в чтении это «данные ИЛИ бактерия» — одна
  отрисовка, не две строки;
- **раскладка** читается как у RX06: кто сколько принял, с именем карты и видом её ресурса;
- **пропуск без держателей** — своей формулировкой (§1.4), отдельно от «нет влияния».

## 4. Блок C — шаг раскладки

Переиспользуется целиком (`ConsoleTaskHost`, шаг `distribute`, семейство `distributed`). Что проверить
на этой карте:

- сетка получателей содержит карты ОБОИХ видов, и по каждой видно, какой ресурс она примет;
- **подтвердить неполную раскладку нельзя** (правило владельца из RX06): пока сумма < N, «Подтвердить»
  недоступна с названной причиной;
- LB/RB прибавляет и убавляет на карте, как в RX06; статусная рельса показывает остаток;
- вырожденный случай «держатели только одного вида» выглядит как обычная раскладка, без следов второго
  вида и без пустой секции.

## 5. Блок D — лицо, локаль, стенд, арт

Лицо по скану: «[данные] OR [бактерия] / [метка науки] + [влияние]». Сноска задания — две метки науки.
Тексты — языком карт проектов (глоссарий § 8; в RU «микроб» → **бактерия**). Ключи i18n грепнуть по всем
`src/locales/<lang>/*.json` до добавления.

## 6. Бюджет проверки

Ново — раскладка по двум видам. Значит:

- **серверные юниты:** N = метки + влияние; раскладка по держателям обоих видов (синтетическая карта с
  `DATA` через `fakeCard`); сумма ≠ N отвергается и ничего не меняет; один держатель — показанный пик,
  не тихое применение; держателей нет — пропуск с причиной и величиной; запись несёт вид по карте;
  карта `WARE` принимает единицу и журналится своим ресурсом; бот не тронут; старые вызывающие
  (Cyanobacteria, Communication Boom, RX06) ведут себя как раньше;
- **клиентские юниты:** формула с двумя видами; сетка с картами обоих видов; блокировка неполной
  раскладки;
- **РОВНО ОДИН новый e2e:** RX18 принята → шаг раскладки внутри стадии → игрок кладёт N бактерий на две
  карты → подтвердить нельзя, пока не разложены все → после подтверждения счётчики карт выросли ровно на
  разложенное;
- **старые сюиты не гоняй**, фикстуру правь точечно (`FIXTURES=… npm run e2e:fixtures`).

## 7. Регрессия и кадры

Юнитами: RX06 (раскладка не поехала), RX04 (счёт по меткам), карты проектов, использующие
`AddResourcesToCards`.

Глазами, один профиль, три кадра: чтение формулы на панели голосования; шаг раскладки с держателями
обоих видов (на стенде, раз в игре данных нет); попытка подтвердить неполную раскладку с причиной.

## 8. Режим работы

Экономный. Коммит на блок, каждый зелёный по юнитам, `npm run lint`, `npm run build:test`,
`npm run make:cards`. **Не пушить.** Документ карты — `docs/TURMOIL_REDUX_MEDICAL_DATABASE.md`; журнал —
`docs/claude/parliament-sitting-progress.md`. Чеклист автора: строка «раскладка по НЕСКОЛЬКИМ видам —
держатели объединяются, вид следует из карты, список из одного вида = прежнее поведение».

Гочи: `CardResource.DATA` в скоупе отсутствует — не строй сценарии на реальных картах данных; посевная
колода сдвигается с ростом каталога — сажать карту через `seatResolution`; heredoc в Bash обрезается
около 6 КБ — большие файлы через Write.

В отчёте: как расширена сигнатура раскладки и что стало с прежними вызывающими; решение по `WARE`;
три кадра; новые ключи i18n.

## 9. Нельзя

Спрашивать вид ресурса отдельным вопросом там, где его определяет карта. Заводить второй класс
раскладки или второй вид объявления эффекта вместо списка. Применять единицу к единственному держателю
молча. Позволять подтвердить неполную раскладку. Подавать «нет держателей» как «нет влияния» или как
тихий ноль. Строить проверку на несуществующих в скоупе картах данных. Гонять старые сюиты. Пуш и
красные коммиты.
