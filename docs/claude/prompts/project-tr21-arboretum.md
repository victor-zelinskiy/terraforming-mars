**Оценивается одно: выбор клетки читается как выбор ВЫГОДЫ, а выгода приходит физически.** Число data зависит от клетки —
сколько городов вокруг неё. Игрок водит курсор и на каждой клетке ВИДИТ: какие города заплатят (они подсвечены), сколько
data, на какую карту и «было → станет», что ещё сработает. После подтверждения каждый соседний город отдаёт свою data, и
она ложится на выбранную карту на глазах у игрока.

### Ответ на вопрос владельца — кислород
**Подъём кислорода — часть озеленения, не отдельный эффект.** Красный кружок на значке озеленения — печатная пометка «это
озеленение поднимает кислород»: билдер ставит её любому `b.greenery()` по умолчанию (`CardRenderer.ts:283–299`,
`AltSecondaryTag.OXYGEN`). Та же фраза «Place a greenery tile and raise oxygen 1 step» стоит на Plantation, Mangrove, Protected
Valley, Experimental Forest — и все они объявляют только озеленение (`behavior.greenery`), без второго `global.oxygen`.
Движок даёт один шаг сам (`Game.addGreenery` → `increaseOxygenLevel`, `Game.ts:2502–2518`); на максимуме — шага и его РТ нет,
озеленение всё равно ставится. **Отдельно — правило Redux** (свод с. 3, «Greenery revision»): тайл озеленения сам приносит
+1 РТ (`REDUX_GREENERY_TILE_TR`, `ParliamentHandler.onGreeneryPlaced`), в т. ч. при максимальном кислороде. Карта ни то, ни
другое не добавляет — всё делает движок.

5. **«На ЛЮБУЮ карту»** — на ОДНУ свою карту-держатель data, все N разом (как TR01 и Redux-Плутон: `AddResourcesToCard`

6. **Цель выбирается ДО клетки** (решение №4) — порядок форка для «карта + тайл»: выбор цели уходит вперёд тайла на

7. **N = 0** (на выбранной клетке нет соседних городов) — это правило, не потеря: data нет, события пропуска нет; досье и
   журнал говорят «соседних городов нет».
8. **N > 0, держателя data нет** — НАЗВАННЫЙ ПРОПУСК с величиной (`recordSkippedEffect`, `SKIP_REASON.noHolder`,

9. **Реакции** — всё, что отвечает на «ресурс добавлен», отвечает: TR18 «Марсианское оптоволокно» платит +1 M€ за каждую

10. Журнал: одна строка и одно событие на выдачу data с ПРИЧИНОЙ (`за ${0} соседних города`); источник — карта.

### A2 · Выбор цели без числа — общий шаг, не код карты
`src/server/deferredActions/SelectResourceTarget.ts` (имя на усмотрение) — «выбери карту, на которую ЛЯГУТ ресурсы, число
— потом»: `constructor(player, kind: CardResource, cause, {per: 'adjacent-city'})`, `Priority.PLAY_CARD_RESOURCE_CHOICE`,
`autoSelect` нет (всегда спрашивает), кандидаты — те же, что у `AddResourcesToCard` (одна функция кандидатов, не копия),
`previewSelectCard()` — read-only близнец, ответ сохраняется в шаге (`chosen`) и читается `andThen` размещения. Маркер —
`resourceGainPrompt` без `amount`, с `amountBasis: {per: 'adjacent-city'}` (новый член `ResourceGainPromptModel`,
сериализация в `SelectCard.toModel` — вложение-безопасно): клиент не придумывает число. Шаг превью — `addToCardStep` с тем
же маркером. Перезагрузка между выбором и размещением теряет очередь — как у любого отложенного шага (известное поведение
движка), спек фиксирует, что цель не «прилипает» к следующему розыгрышу.

### A3 · Хук досье карты подсвечивает клетки
- `FactOptions` (`placementPreviews.ts:52–60`) получает `spaces?: ReadonlyArray<SpaceId>` — первый хук карты, который
  называет участвующие клетки (relation-слой зажигает их сам — `placementRelations.ts`).
- `Arboretum.placementPreview`: N = `adjacentCityTiers` ПОД ГИПОТЕЗОЙ тайла на клетке (соседей это не меняет, но держать
  форму общего движка); факт «+N data · за N соседних городов» (`delta {icon: 'data', amount: N}`, `spaces` = клетки соседних
  городов, `params` — N); N = 0 → факт-правило «Соседних городов нет — data не будет» (`noEffectHere`-форма, секция правил);
  N > 0 и нет держателя → предупреждение пропуска с величиной.
- **Реакции на эту data в досье**: «Сработает» TR18 (+N M€) на каждой клетке — через ту же функцию прогноза выдач, что у
  композера (`effectForecast` grant-проход по чипу `{data, N}`), не таблицей; если пройти её read-only с синтетическим чипом
  нельзя без переделки — записать гэпом с причиной, не дублировать правило.
- **Найдено при подготовке — чинить классом (досье поставит их рядом с data)**: факт ПО Commercial District в досье считает
  КЛЕТКИ (`BoardInformationEngine.ts:1046–1054`, `cities.length`), а реальный подсчёт — ярусы; факт «соседний город получит ПО
  в конце игры» у озеленения пишет `0 → 1` на клетку (`:1191–1206`), а стопка из двух ярусов получит 2. Оба — через
  `adjacentCityTiers` / `tiersOf`; спеки «досье == подсчёт» на стопке.

### A4 · Причина в журнале
`EventImpact.cardResources[]` получает необязательный `basis?: {count: number, unitKey: string}` (ключ i18n единицы —
«adjacent city(-ies)»), `EventRecorder.recordCardResourceDelta` принимает его из `addResourceTo(…, {basis})`; журнальная строка
события рисует «· за 3 соседних города». Общий член — им воспользуется любая следующая выдача «за каждый X». Строка лога —
одна (`'${0} added ${1} ${2} to ${3} for ${4} adjacent city(-ies)'`), под источником карты.

### A5 · Запись подачи — что видит сцена

amount, resource: 'data'}` — только своему игроку; у соперника — та же запись в публичной модели или журнальное событие с
`basis` (выбрать одно, без дублирования). Клиент не пересчитывает соседей.

### B2 · Досье клетки (`placementDossier.ts`, `ConsoleContextPanel`)
«ВЫ ПОЛУЧИТЕ»: факт карты — «+3 data · за 3 соседних города → [мини-лицо цели] Векторные вычисления 2 → 5» (было/станет — из
`amount` сервера и счётчика карты в модели: клиент складывает два серверных числа, правило он не считает); рядом —
кислород / РТ / бонус клетки / сталь партии — как у любого озеленения; «Сработает»: TR18 +3 M€ (A3). N = 0 — строка правил;
пропуск — колодец предупреждения. Законы досье в силе: ноль подсказок контроллера, ничего не анимируется при смене клетки,
текст не клэмпится, стандартное размещение не скроллится (`expectFits`), кэш превью — с `card` и `staged`.

### B3 · Поле — relation-слой
Платящие города зажигаются из `spaces` факта, тоном `reward`. Сегодня их перекрывает `score` озеленения (соседний СВОЙ город
получает ПО в конце — ранг 2 бьёт ранг 3, `placementRelations.ts:43–49`). Решение №5: **«платит сейчас» старше «ПО в
конце»** — `reward` встаёт перед `score` (`penalty < ocean < reward < score < event`); спек тонов + регрессия
`console-placement-relations`; посмотреть кадры Ares-соседства (там `reward` уже был), где это меняет картину. Нейтральный
соло-город (у него нет факта ПО) — тот же `reward`.

## 3. Блок C · сцена «ГОРОДА ПЛАТЯТ»

### C0 · Грамматика
- По закону §8-bis: тайл и кислород — ПОЛЕ (существующая посадка, бонус клетки из-под тайла, РТ); data — КАРТА, но её
  ПРИЧИНА — соседние города, поэтому каждая data РОЖДАЕТСЯ У СВОЕГО ГОРОДА (как монета у своего океана), а ПРИНИМАЕТ её
  карта-получатель — data принадлежит карте, не рельсе.
- Одна data — один физический жетон; стопка ×2 отдаёт два жетона (два коротких импульса одного города).
- Реагирует только тронутое: город — один импульс на свой жетон; соседи не мигают.

## 5. Тесты клиента и e2e
**Юниты**: шаг цели без числа (строка кандидата, `ConsolePlayedTargetStep`), досье (факт карты, было/станет, N = 0, пропуск),

**e2e — ОДИН спек** `tests/e2e/console-arboretum.spec.ts`, фикстура `arboretum` (образец доступа «Марс вперёд» —
`martian-census`): Redux, двое; синий — карта в руке, ≥ 12 M€, держатель data (TR05) и TR18 в табло; на поле — клетка
озеленения у ТРЁХ городов (свой, чужой и стопка ×2 — итого 4 data; если фикстура не даёт стопку — два города, а стопка

## 7. Режим работы
**4 коммита**, каждый зелёный: (1) сервер — карта, шаг цели, хук досье со `spaces`, `adjacentCityTiers`, две починки «по
ярусам», `basis` журнала, запись подачи + спеки; (2) лицо + локаль + лор + арт; (3) клиент — шаг цели без числа, досье,
старшинство тонов, сцена «города платят» + юниты; (4) e2e + фикстура + документы. Перед каждым: `npm run lint`,
`npm run build:test`, `npm run make:cards`, `npm run make:json`; перед визуальной проверкой `npm run make:css` +
`npm run build:server`. **Не пушить.** Документ карты `docs/TURMOIL_REDUX_ARBORETUM.md` — контракт «награда карты зависит от
клетки» (хук со `spaces`, шаг цели без числа, `basis`, запись подачи, сцена), что получает следующая карта «за каждый X рядом
с тайлом» даром. Дополнить `board-placement-flow.md` (старшинство тонов), `TILE_PLAY_STAGED_COMMIT.md` §8-bis (первая
выдача карты, рождённая у соседей), чеклист набора §4 (строка), журнал набора.
В отчёте: сигнатуры; что обобщено и чем доказано, что озеленение, Forestry, TR01 и TR14 не изменились; A/B-тайминги сцены;
кадры §6; e2e на двух профилях + регрессия; что напечатали гарды; новые ключи; подтверждение решений 1–6; **явно — всё, что
не получилось сделать, и почему.**

`shardPlan.json`. Пуш и красные коммиты.
