## 4. План работ

**Ф0 — замер.** Перед правками: полный прогон бокса (`npm run e2e:remote -- <task> --workers=4`, оба прохода) —
функциональная база; затем список истории флаков (§ 2) в CI-профиле `TM_E2E_CI_LIKE=2 … --repeat-each=5` — частота
каждого ДО. Запиши таблицу «спек → частота до → класс» в `docs/claude/e2e-flake-zero.md` (рабочий журнал итерации).

**Ф1 — примитивы, которых не хватает** (в `tests/e2e/`, с юнит-спеком там, где логика чистая):
- `readSettled(page, reader, {equal: 2, timeoutMs})` — ОДНО «устоявшееся чтение» (после `settle`, два равных
  замера подряд по значениям, которые будут утверждаться; при таймауте печатает ряд замеров);
- обёртка свидетеля поверх рекордера: `armWitness(page, key, reader)` → `{ever(pred), last(), sequence(), firstWhere(pred)}` —
  чтобы спеку не приходилось разбирать сэмплы руками;
- перенос восьми страничных свидетелей (§ 2) на рекордер с сохранением их API;
- если находишь в спеках повторяющийся локальный приём (как было с открытием листа розыгрыша) — подними в примитив
  и замени все копии (страж ② потом не даст завести копию заново).

**Ф2 — стражи** (`tests/console/e2eDriverGuard.spec.ts`, новые правила с allow-list'ом «строка + причина»):
⑧ `setInterval(` / `requestAnimationFrame(` в `*.spec.ts` — 0 (храповик уже считает; правило делает ноль законом);
⑨ расширение ⑦: разовое `expect(await <locator>.count() | .isVisible() | .textContent() | .getAttribute(…))`;
⑩ `waitForTimeout(` в `*.spec.ts` — 0 (только именованные примитивы);
⑪ функциональный спек (не из `TIMING_SPECS`) не передаёт в `expect` значение, вычисленное из `Date.now()`;
⑫ чтение геометрии в `page.evaluate` вне `readSettled` / ридера рекордера — храповик (сразу ноль не получится:
   начать со счёта и опускать);
⑬ известные пары «исчезновение ⇒ готово» (`.con-context__task-kicker`, `.con-composer--play`, `.con-hand`…) в
   роли условия завершения цикла без серверной проверки рядом — по согласованному списку.
Каждый страж — с отрицательным контролем (фикстура-строка, на которой он краснеет).

**Ф3 — миграция спеков.** Порядок: история флаков (§ 2) → вес по храповику → остальные. Для каждого спека:
меняется КАК он наблюдает, НЕ ЧТО он утверждает; спек, который флакал, после правки доказывается частотой в
CI-профиле (`TM_E2E_CI_LIKE=2 --repeat-each=5`, ноль красных). Механические замены (сэмплер →
`recordTransient`) можно делать кодмодом, но каждый спек после кодмода прогоняется. Волна = ~20–40 спеков →
коммит → пуш → CI владельца.

**Ф4 — аудит продукта (класс N).** Найди в `src/client` бюджеты по стенным часам, которые РЕШАЮТ видимый исход
(деградация «поглотить на месте», «показать без анимации», «отпустить заявку»): константы `*_MS`, используемые как
`deadline` / `budget` / потолок ожидания в презентационном коде. Для каждого: привязано ли ожидание к событию?
Если нет — привязать (как `9c1d1a78e1`), потолок оставить только на «никогда не случилось»; закон —
`.claude/rules/animations.md` § A MOTION IS RIGHT ON A SLOW FRAME BY CONSTRUCTION. Продуктовая правка — с юнит- или
гард-спеком и с доказательством на боксе.

**Ф5 — доказательство.** Полный прогон бокса (оба прохода) зелёный; CI-профиль по истории флаков — ноль; затем
три CI владельца подряд 0/0. Только после этого итерация закрыта.

## 6. Законы работы

- **e2e — только на Steam Machine**, рецепт: `npm run build` (если менялся продукт) → `npm run e2e:snapshot <task>`
  → `npm run e2e:remote -- <task> <spec…>`. Ноутбук не запускает Playwright. **Перед каждым запуском**:
  `ssh steam-machine 'pgrep -afi enshrouded | grep -v pgrep'` — играет владелец → на бокс не идём (обёртка сама
  выйдет с 4); тогда работаем над статикой/примитивами и просим CI. Exit 2/3/4 = прогон не состоялся.
- **CI-профиль прибит к ядрам 0…N-1** — два CI-подобных прогона одновременно делят ядра и врут; запускай их по
  одному (отвязанный скрипт-очередь). Не запускай побочный прогон под ИМЕНЕМ идущей задачи (стирает её
  `test-results`). Фоновый Bash живёт 30 мин — длинные очереди в `nohup bash <script> &`.
- **Запрещено**: ослаблять утверждение (менять ЧТО проверяется), поднимать таймаут как «исправление», добавлять
  ретраи / `test.retry` / `if (CI)`, `test.skip`, `waitForTimeout` в спеках. Если красный — гонка продукта, это
  баг продукта: чинить продукт (с юнит-спеком), а не тест.
- **Каждый CI-красный сначала воспроизводится** в CI-профиле, потом чинится, потом доказывается частотой.
- **Общие файлы**: `tests/e2e/consoleTest.ts`, `causeHarvest.ts`, `console-monkey.spec.ts` ведёт сессия
  freeze-zero (worktree `C:\Projects\Mods\tm-fz`) — правки там согласуй сообщением; основной клон делят несколько
  сессий: коммит только с явным pathspec (`git commit -F <msg> -- <пути>`), перед коммитом
  `git diff HEAD -- package.json package-lock.json` пуст, после коммита хук версии оставляет package-файлы в
  индексе — `git reset -q -- package.json package-lock.json`. Пуш — `npm run push`.
- **Окружение**: в Bash-инструменте Node 22 — перед npm `export PATH="$APPDATA/fnm/node-versions/v24.20.0/installation:$PATH"`
  (и `export LC_ALL=C.UTF-8` для `e2e:remote`); многострочные правки — Edit/Write или `.py`-скрипт, не heredoc с `\`.
- **Мандатные проверки перед каждым коммитом**: `npm run lint`, `npm run build:test`, `npm run test:server`,
  `npm run test:client` (затронутые стражи — отдельно), `npx mocha … tests/console/e2eDriverGuard.spec.ts
  tests/console/e2eLiveness.spec.ts`, `npm run e2e:baseline` при падении счётчиков.
