## 2. ЧТЕНИЕ ПРАВИЛА — что перехватывается, что нет (каждый пункт — спеком `tests/parliament/UnmiVeto.spec.ts`)

Это **ВТОРОЙ ЗАМЕНЯЮЩИЙ** пассив (род RX35), но **на другую единицу и БЕЗ ВОПРОСА**: RX35 забирал саму единицу
терраформирования (параметр не двигался, тайл не ложился) и ставил вместо неё data; RX42 забирает **только РЕЙТИНГ** —
параметр ДВИГАЕТСЯ, тайл ЛОЖИТСЯ, бонусы шкалы и клетки приходят, а шаг РТ **не засчитывается** и ничем не заменяется.
Правила Redux важнее словесного описания (`redux-rules-outrank-owner-description`) — читаем по букве.

1. **Кто под вето — ЖИВО, в момент каждого получения** (решение Р2): «игрок(и) с наибольшим РТ» = все места, чей
   `terraformRating` равен максимуму среди **ВСЕХ** игроков партии (`game.getPlayers()`, бот включён в сравнение — Р3;
   зрители нет). Ничья наверху → под вето КАЖДЫЙ из равных. Статус не фиксируется при принятии и не сериализуется —
   он вычисляется на каждом получении и на каждой сборке модели (одна функция `ratingLeaders(game): Set<PlayerId>`
   для перехвата, превью, модели и чтений — **один источник правды**).
2. **Единица — ОДНО СОБЫТИЕ ПОЛУЧЕНИЯ = один вызов воронки** (решение Р2, по умолчанию): `increaseTerraformRating(steps)`
   оценивается ЦЕЛИКОМ в момент вызова — либо весь `steps` засчитан, либо весь проигнорирован. Догоняющий на 1 ниже с
   «+3 РТ» получает все 3 и становится первым по РТ (следующее его получение — под вето). Внутри ОДНОГО действия события
   независимы и идут ПО ПОРЯДКУ движка: «+2 температуры» = одно событие (`Game.increaseTemperature` → один вызов на 2 шага);
   «+2 температуры» с бонусным океаном на 0 °C = два события; озеленение = два события (РТ кислорода `global: true` + РТ
   тайла Redux `ParliamentHandler.ts:469`); Giant Ice Asteroid (температура + 2 океана) = три. Превью обязано промоделировать
   ту же последовательность (§A5) — «порядок обещания = порядок исполнения» (CLAUDE.md § Effects and choices).
3. **Что перехватывается — ВСЁ, что идёт через воронку как рост:** `behavior.tr` и бэспоук `increaseTerraformRating` карт
   (`Executor.ts:574`, 22 файла), шаги кислорода/температуры/Венеры/океанов (`Game.ts:1833/1953/2043/2965`), бонус трека
   Венеры (`:1913`), РТ озеленения Redux (`:469`), шаг `tr` трека Повестки (`ChairmanSeat.ts:145` — в том числе шаг
   победителя на этапе 1 СЛЕДУЮЩЕГО заседания, пока закон ещё стоит — RX35 п.11), часть победителя RX23 (шаг параметра
   НАГРАЖДАЕМЫЙ) — но только если RX23 принимается ПОСЛЕ RX42 и сам RX42 ещё в слоте — а это невозможно: принятие ставит новую
   карту ДО её шагов (`ParliamentPhase.stepEnact`, RX35 п.10) → **спек: RX23 после RX42 — победитель получает РТ**; колонии с
   выплатой РТ (`Colony.ts:853`); Ares (`AresHandler.ts:480`); корпорация UNMI (ирония по букве: «3 M€ → +1 РТ» у первого
   по РТ — под вето); финальное озеленение последнего поколения (`onGreeneryPlaced` + кислород — по букве, как RX35 Р2).
4. **Что НЕ перехватывается:** ПОНИЖЕНИЯ (`decreaseTerraformRating` — отдельная функция, закон говорит «gain»); ход
   Мирового правительства (РТ там не даётся — спек: ничего не перехвачено, строки нет); места вне Парламента; РТ при
   `steps === 0`.
5. **Следствия перехвата — движковые, ничего не дописывать:** внутри воронки возврат ДО `raiseRating` → не растут
   `terraformRating`, `terraformRatingFromCards`, `terraformRatingSources`; **не ставится `hasIncreasedTerraformRatingThisGeneration`
   и не растёт `trThisGeneration`** (корпорация UNMI остаётся закрытой — `UnitedNationsMarsInitiative.ts:41–47` «Your terraform
   rating was not raised this generation» — верно по букве; Pristar получает свои 6 M€ как «не повышал» — по букве, спеком);
   не пишется `tr-changed`; Зелёные не платят; реакторы `onIncreaseTerraformRatingByAnyPlayer` не зовутся; ПО конца игры не
   растут. **Параметр, тайл, бонусы шкалы и клетки, `global-parameter-changed`, `tile-placed` — КАК БЫЛИ.** Гейт стоит
   ПЕРВЫМ в воронке — до `trThisGeneration`, до Preservation Program (`:561`), до мёртвого под Redux налога Красных
   (`:613` — классический Turmoil и Redux взаимоисключены, `Game.ts:388`; ветка недостижима, не трогать).
6. **Потеря НАЗВАНА, с величиной — всегда** (инвариант 4): каждое перехваченное событие пишет строку журнала с числом и
   законом и структурную запись под областью закона (§A6). Тихий `return` в воронке — дефект.
7. **Статус ДВИЖЕТСЯ — и движение названо:** после КАЖДОГО изменения РТ любого игрока (рост в `raiseRating`, падение в
   `decreaseTerraformRating`) воронка сравнивает множество «первых по РТ» ДО и ПОСЛЕ; вход/выход места — событие
   `rating-veto-changed` (кто вошёл, кто вышел, с чьим РТ), из которого нотификация говорит «Вето UNMI теперь действует на
   вас (32)» / «…больше не действует на вас — первый по РТ теперь Синий (33)». Пока закон не принят — ничего.
8. **Бот** (решение Р3, по умолчанию): **бот ПОД ВЕТО и В СРАВНЕНИИ** — это ограничение, не выплата (D3 о выплатах молчит;
   D11 — «деяние закона — боту да»); если бот первый по РТ, его рост РТ игнорируется той же воронкой (`AutomaResolver.ts:200`
   и др. — ни одной своей ветки), ход бота идёт как шёл, строка журнала — о боте, разбор хода бота — вне полировки
   (память `bot-turn-review-out-of-polish-scope`). Механизм: аспект `enactment` у бота выключен (`BotParliamentPolicy`) →
   **новый аспект `restriction`** («ограничение стоящего закона действует на место») с `бот = true`; диспетчер вето гейтит
   `participates(player, 'restriction')`, не `enactment`. Альтернатива для владельца — §3.
9. **Задание «2 метки Марса»:** объект и ключ RX38 (`{kind: 'tag', tag: Tag.MARS}, count: 2`, текст `'Play 2 Mars tags'`);
   считаются только свои разыгранные карты (`QuestTracker` как есть); бот — как решено в RX38 (`botQuestReachable('tag')` →
   `true`, путь бота — его бонус-карты). Спек: своя карта с меткой Марса +1; карты принятия (добор) — 0.
10. **Однажды за принятие:** добор ровно раз; перезагрузка внутри взятия — RX40 `:94`. Пассив состояния не имеет — после
    перезагрузки действует с первого же получения.
11. **Пограничные случаи (по букве, спеком, без особых веток):** одиночная партия без бота — единственное место всегда
    первое по РТ → всегда под вето (чтение панели голосования говорит это прямо); два игрока с равным РТ — оба под вето,
    пока один не упадёт (TR70 Backroom Deal «−1 РТ» снимает вето с упавшего — п.7); игрок под вето играет карту «+1 РТ и

## 10. Режим работы

Экономный, 4 коммита (A сервер + гарды + свип · B проход превью + чипы + бейджи + модель · C статусные поверхности +
заседание + показ + e2e · D доки/локаль/лор), каждый зелёный по юнитам; `npm run lint`, `npm run build:test`
(обязателен — тесты тронуты), `npm run make:cards`, `npm run make:json`, `npm run make:css` перед визуальной проверкой.
**Не пушить.** Гочи прошлых прогонов (`turmoil-redux-diverted-research`, `turmoil-redux-sponsored-projects`,
`turmoil-redux-reds-budget`): `build:client` — с `SKIP_TS_CHECK=1`, типизация — `npm run lint:client`; «Build Finished»
при ошибках чекера = бандл НЕ переписан; новые RU-ключи в e2e — только после `make:json` + пересборки + нового снапшота;
ворота заседания в e2e — только `answerGateOnScreen`; `sittingStep` истинен уже на странице ПРИНЯТИЯ — ждать по
`sittingStage`; раскадровка 4K — только `TM_E2E_GPU=1`; свечение через `filter: drop-shadow` в консоли мертво — только
`box-shadow`/transform; размеры мелких символов в чтениях — в `em`; новая карта в колоде сдвигает сидированную раздачу
`ParliamentPhase.spec` — сажать через `seatResolution`; RTK-хук ест `\\` и `\\'` в heredoc — патчи через Write/Edit;
heredoc > ~6 КБ обрезается — большие файлы через Write; `git commit -- <пути>` оставляет индекс `package.json` —
`git reset -q -- package.json package-lock.json`; стат коммита — `git show --stat HEAD`; `python3` — заглушка Store,
только `python`.

## 11. В отчёте

Подтверждение, что перехват — ОДНА строка в ОДНОЙ воронке (ни одного изменённого вызывающего места) и ОДИН проход превью
