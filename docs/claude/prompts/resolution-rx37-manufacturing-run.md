## 2. ЧТЕНИЕ ПРАВИЛА (каждый пункт — спеком `tests/parliament/ManufacturingRun.spec.ts`)

1. **Три взаимоисключающих исхода на ОДНУ карту:** 2 аэростата, или 1 истребитель, или 1 мех. Карта — СВОЯ (как у
   Учёных: «to any card» = одна из своих карт; RX01/RX18 читают так же). Не раскладка (`spread` не объявлять).
2. **Вид — ВЕТКА, а не карта** (решение Р2): форма Учёных — `OrOptions` по видам, в каждой ветке `SelectCard` над
   держателями этого вида, `resourceGainPrompt.amount` = 2 / 1 / 1. Ветка вида без держателей не предлагается; одна ветка
   — сворачивается движком (`OrOptions.reduce`, исключение инварианта 3), но выбор КАРТЫ показывается всегда, даже при
   одном держателе (`autoSelect` не применять). Альтернатива («вид следует из карты», RX18) отвергнута: величины у видов
   разные, и печать «OR» — вариантный выбор.
3. **Сколько раз:** **2 за поколение; 3 — если влияние места ≥ 2.** Влияние читается **В МОМЕНТ ИСПОЛЬЗОВАНИЯ** (это уже
   так: `resolutionActionUsesLeft` зовёт `usesPerGeneration(player)` живьём): место с влиянием 1 потратило 2, стало
   председателем (Повестка +1 → влияние 2) — у него появляется третье в том же поколении; спек. Влияние в течение
   поколения только растёт — обратного случая нет (закрепить комментарием, не веткой).
4. **Каждое использование — отдельное действие хода** (как любое действие карты): оба действия одного хода могут быть
   этим законом; учёт — при ответе (`runResolutionAction`), сброс — на границе поколения. Закон сменился — счётчик не
   переносится (сменить закон можно только в солнечной фазе — поколение и так закончилось).
5. **Доступность с причиной:** нет ни одного держателя трёх видов → «No card of yours can hold floaters, fighters or
   mechs» (ключ — по образцу Учёных); исчерпано → семейная причина использованного действия (с числом «2 из 2» / «3 из 3»);
   бот — семейная.
6. **Журнал:** «used the action of …» (семейная строка) + строка добавления ресурса с источником-законом
   (`addResourceTo(card, {qty, log: true, from: {resolution: ID}})`); событие `cardResource` под областью закона.
7. **Задание:** зелёные карты обычных розыгрышей; само действие ничего не разыгрывает (Q5 тут и не нужен). Ресурсы от
   закона в задания не идут (источник на стеке — `QuestTracker.eligible`), и это не важно ни одному заданию каталога с
   флоатерами/мехами — закрепить одной строкой спека, что прогресс «2 зелёные карты» действием не двигается.
8. **Реакции стола:** держатели этих видов в скоупе не реагируют на добавленный ресурс (`onResourceAdded` у них нет —
   проверено при подготовке), ПО по ресурсу (Mech Sports, Formula Zero, Aurora Station, Security Fleet, Jovian Lanterns
   и т. п.) — через `vpBox`, как у Учёных. Если найдётся реактор — общий прогноз (`grantFacts`) его называет; своего
   кода нет.

## 4. Блок A · сервер — сборка + одна декларация

### A1 · Объявление

```ts
export const MANUFACTURING_RUN_USES: ResolutionActionUses = {base: 2, atInfluence: {influence: 2, uses: 3}};
export const MANUFACTURING_RUN_YIELD = [
  {resource: CardResource.FLOATER, amount: 2},
  {resource: CardResource.FIGHTER, amount: 1},
  {resource: CardResource.MECH, amount: 1},
] as const;

action: {
  usesPerGeneration: (player) => actionUsesFor(MANUFACTURING_RUN_USES, player.game.parliament?.influence(player) ?? 0),
  canAct(player): какой-либо вид имеет держателя → {available: true}; иначе названная причина,
  execute(player, parliament, meta): OrOptions по видам с держателями (порядок печатный: аэростаты → истребитель → мех),
    ветка = SelectCard(..., {min: 1, max: 1}).markResourceGainPrompt({amount, cardResource, vpBox}).markResolutionActionPrompt(meta)
      .andThen(([card]) => { runResolutionAction(player, parliament, ID, () => player.addResourceTo(card, {qty: amount, log: true, from: {resolution: ID}})); return undefined; });
    OrOptions: .markChoiceContext({source: {kind: 'resolution', resolution: ID}, trigger: 'Resolution action', mode: 'effect-choice'}).markResolutionActionPrompt(meta);
  preview(player?): по чипу на вид (иконка, amount, нота 'to a card'); с местом — только виды с держателями,
},
actionUses: MANUFACTURING_RUN_USES,
```

- **Новая декларация `actionUses`** (`src/common/parliament/actionUses.ts`, по образцу `actionBill.ts`): `{base: number,
  atInfluence?: {influence: number, uses: number}}` + ОДНА функция `actionUsesFor(uses, influence): number`. Её читают
  сервер (`usesPerGeneration`) и клиент (манифест: `IClientResolution.actionUses`, экспорт в `export_card_rendering.ts:246`
  рядом с `actionBill`). Объявлено рядом с `action`, никогда вместо: гард `ResolutionContract` — «`actionUses` без
  `action`» и «`usesPerGeneration` ≠ `actionUsesFor(actionUses, …)` на трёх влияниях 0 / 1 / 2» (одна правда, а не две).
  Карты без декларации — `1` (как сегодня); гарду всё равно, есть ли декларация у старых карт.
- **Общая форма «ресурс на свою карту, вид — веткой»** — решить честно: Учёные (партия) и закон строят ОДИН И ТОТ ЖЕ
  промпт с разными видами/числами/источником/маркером. Вынести общий построитель `resourceToOwnCardChoice(player, yields,
  {source, from, meta-маркер, run})` (в `parliament/` рядом с `ResolutionAction.ts`) и перевести на него Учёных —
  **байт-в-байт тот же промпт** (спек партийного действия зелёный без правок). Если перевод Учёных тянет за собой
  непропорционально много — оставить Учёных как есть, написать закон по образцу, сказать в отчёте.
- **Бот** — аспект `enactment` выключен, действия нет (семейство).

## 4.1 Блок B · клиент — одна дыра и одна форма

### B1 · Дыра: «один раз за поколение» вшит у закона

`parliamentEffectsStepModel.ts:119` пишет закону `usesPerGeneration: 1` — «Ваши эффекты» напечатали бы «раз за поколение»
у закона, который даёт 2–3. Читать **живое число места** (`viewer.resolutionAction.usesPerGeneration` — сервер уже
кладёт) или, без места, `actionUsesFor(manifest.actionUses, …)`; `cadenceOf` (`ConsoleParliamentEffectsStep.vue:111`)
уже умеет «N раз за поколение». Пройти ВСЕ потребители `usesLeft`/`usesPerGeneration` из списка контрактов и закрепить
юнитом, что ни один не подставляет `1` для закона: плитка «Действия карт» (`sourceUsesText` «1 из 2»), плашка Парламента
(`consoleParliamentModel` состояние `used` только при `usesLeft <= 0`), композер (`usesText`), «Ваши эффекты»
(`ready/used/locked`), осмотр закона, стенд.

### B2 · Чтения порога (статические, без места — манифест)

- **Панель голосования / осмотр / «Полигон»:** кикер «Действие, пока принята» (`quietRewardPose`) + строка
  «2 раза за поколение · 3 при влиянии 2+» одной функцией из `actionUses`; у места — «для вас: 3 раза» / «для вас: 2 раза
  · ещё 1 влияние до третьего» (язык порога RX20 `tileGrantModel` — «на линии / ниже линии», не новый словарь); прогноз
  «если победите» (Повестка +1 до влияния 2) — честно меняет 2 → 3.
- **Плитка закона в «Действиях карт»:** печатный бокс `→` (`actionRowsOf`), под ним «осталось N из M»; после последнего
  использования — уходит из обычного вида в «Активирована» (RT), как у всех.

### B3 · Форма решения — форма Учёных, обобщённая по ФОРМЕ ПРОМПТА, не по партии

Ветка `kind === 'scientists'` композера читает ровно то, что строит закон: верхний `or` с `card`-ветками, у каждой
`resourceGainPrompt`. Обобщить чтение на ФОРМУ (`resourceBranchesOf(entry)` — `or` из `SelectCard` с
`resourceGainPrompt`), чтобы `kind === 'resolution'` с этой формой рисовал **те же два ряда** («РЕСУРС» → «КАРТА-ЦЕЛЬ»)
и коммитил тем же `scientistsResponse` (переименовать в нейтральный `resourceToCardResponse`). Без второго компонента и без
копии разметки (RX24-закон: «второго композера не бывает»). Три варианта в `ConsoleVariantChoice` с «ИЛИ» между —
проверить на 4K, что ряд не тесен; ряд «КАРТА-ЦЕЛЬ» — лица держателей с `current → resulting` и ПО.
Крошка: `ДЕЙСТВИЯ КАРТ › СЕРИЙНЫЙ ВЫПУСК › НАСТРОЙКА` (дверь из Парламента — `ПАРЛАМЕНТ › …`, как у партий).

## 9. Режим работы

Экономный, 3 коммита (A сервер + `actionUses` + гарды · B клиент + PL-427 + e2e · C доки/локаль), каждый зелёный;
`npm run lint`, `npm run build:test`, `make:cards`, `make:json`, `make:css`. **Не пушить.** Гочи прошлых прогонов:
`python3` — заглушка Store, только `python`; `cross-env` в bash нет; heredoc > ~6 КБ обрезается — большие файлы через
Write; RTK-хук ест `\\` в heredoc-патчах; `npx vue-tsc --noEmit` напрямую падает по heap — только `npm run lint:client`;
`FixtureName` в `consoleStart.ts` — объединение, новую фикстуру добавлять руками; `parliamentFixture` оставляет корпорации
ожидающее первое действие — спек, которому нужны ДВА действия хода, чистит `p2.pendingInitialActions = []` в `arrange`
(PL-715); фикстура `done` открывается на p2; потраченное действие резолюции видно только под RT (`--activated`);
`testAutomaGame` под Redux требует `coloniesExtension: true`; полный `test:client` под нагрузкой даёт случайные таймауты —
проверять изоляцией; стат коммита — `git show --stat HEAD`.

## 11. Нельзя

Константа «1» или «2/3» в клиенте вместо `actionUsesFor`. Порог третьего использования, замороженный на начало поколения
(Р3 — живой). Раскладывать порцию по картам (`spread`). `autoSelect` при одном держателе. Второй композер или копия
разметки рядов Учёных. Полёт жетона на спутник вместо карты-цели. Отдельный путь посадки для закона, минуя директор TR53.
