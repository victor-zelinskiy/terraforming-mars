# Промт исполнителю · Парламент Turmoil Redux — ФИНАЛЬНАЯ ПОЛИРОВКА и доведение до законченного состояния

Выдан 2026-09-20 после сдачи финального прогона (`cb9f260936`, `docs/TURMOIL_REDUX_PARLIAMENT_FINISH.md`,
журнал `docs/claude/parliament-sitting-progress.md`). Это ПОСЛЕДНЯЯ итерация по Парламенту перед расширением
каталога резолюций: все хвосты закрываются здесь, «отложено» больше не бывает.

---

Ты — исполнитель финальной полировки Парламента Turmoil Redux в приватном форке `terraforming-mars`
(vize1215). Функционал построен и сдан (ворота фазы, заседание одним flow, награда как физическое событие,
галерея, гарды). Твоя задача — **довести всё до идеального, полностью законченного состояния**: закрыть каждый
хвост предыдущих прогонов, пройти весь Парламент вторым, свежим взглядом, дожать всё, что мешает назвать его
премиальным, и подготовить базу так, чтобы следующая резолюция любого семейства ложилась без сюрпризов.
Работаешь автономно, несколько дней, без вопросов пользователю; отвечаешь и пишешь по-русски.

**Планка.** Turmoil Redux нигде онлайн не реализован, мы первые, Парламент — сердце продукта. Пользователь
скрупулёзен к «мелочам»: одна прыгающая подпись, один двусмысленный термин, один пустой блок — и экран не
премиальный. Мерило: рядом со Steam-версией и Ark Nova не стыдно, новичок понимает всё без обучения, в каждой
позе на каждом профиле. «Отложено», «minor», «вне скоупа, потому что чужой файл» в этой итерации не принимаются:
либо сделано, либо в документе доказано скриншотом и замером, почему делать нельзя (правила игры или ломается
другая подсистема — с пробником, который это показывает).

## 0. Режим работы

- Порядок блоков: **A (доказанные хвосты) → B (второй аудит и полировка) → C (пересмотр «вне скоупа») →
  D (готовность к семействам резолюций) → E (финальная приёмка)**. Блок не начинается, пока предыдущий не принят.
- Коммиты: локальный коммит на блок (внутри — сколько нужно, каждый зелёный: `npm run test:server`,
  `npm run test:client`, `npm run build:test`, `npm run lint:client`, eslint по изменённым файлам). Сообщение:
  `Parliament polish · <A|B|C|D|E>: <суть>`. **Не пушить.**
- e2e: парламентские сюиты теперь адаптированы, поэтому **в конце КАЖДОГО блока** зелёными должны быть
  `tests/e2e/console-parliament*.spec.ts`, `console-external-draw.spec.ts`, `console-resolutions-playground.spec.ts`
  (`--workers=1`); полный `tests/e2e` — один раз в блоке E. Никакой пересборки `build/` во время идущего прогона.
- Журнал прогресса — тот же `docs/claude/parliament-sitting-progress.md`: раздел «Финальная полировка» с
  реестром второго прохода (нумерация `P-…`), пользователь читает его во время работы.
- Застрял (три подхода без прогресса): гипотезы и замеры в журнал, самое честное из работающих решений, дальше.
- Субагенты — только чтение/разведка; продуктовые правки — один поток.

## 3. Блок B — второй аудит свежим взглядом и полировка

Первый реестр (R-01…R-36) составлял тот же агент, что строил заседание. Ты — свежие глаза. Метод тот же, что в

fx-lite}: обзор (все состояния правительства/слотов/мест/поддержки/кресла/задания), голосование (лобби / резерв /
блок с причиной / оплата / посадка / приписка «если победите» / кэп), кресло, анонс-плита, все стадии заседания и
все варианты НАГРАДЫ (волна / пик / добор / big-draw / тайл с уходом на поле и возвратом / пропуск / чужое место /

резолюции из четырёх дверей, осмотр партии с LB/RB, композер каждого из четырёх действий партий, стенд, группа в
журнале, полоса Информации, свёрнутое заседание и карточка возврата на board home.

Классы дефектов — из §6.1 того промта, плюс обязательные проверки этой итерации:
- **Стадии заседания под лупой** — их пользователь ещё не принимал: кикеры, плиты, строка ожидания с чипами,
  карточка ЗАКРЫТИЯ (только объекты), поза «получено», поза «Без награды», иерархия числа/подписи/суффикса.
- **Моушен покадрово** через кадры трейса (`--trace=on`, `e2e-trace-screencast-perceptual-frames`): два полных
  заседания (Climate с добором, Biodome с тайлом) на 1080 и TV; каждый объект появился из реального места, ни одного
  двойника, ни одного блика, easing и длительности в бюджете §6 плана; посадка чипов и тик счётчика в одном кадре.
- **Пустые и повторные состояния**: «0 делегатов · Лидера пока нет · Ваши ▢▢ 0» ×3, «Делегатов пока нет» ×3 — тише и
  короче; бейдж/глиф принимаемой резолюции (звезда на Deck) с `data-hint`.
- **Проза на игровых экранах** — только там, где реестр её оправдал; правительство, слоты, плитки — объекты.
- **Команды бара** — единые глаголы на всех поверхностях Парламента («ОСМОТРЕТЬ», «НА ПОЛЕ», «СВЕРНУТЬ»,
  «К НАГРАДЕ», «ЗАКРЫТЬ ЗАСЕДАНИЕ»); каждый заблокированный — с причиной и `data-hint`; ни одной мёртвой команды.
- **Фокус/hover/disabled** на каждом интерактивном элементе; фокус-ринг не заезжает на соседа; perf/fx-lite —
  состояния без `filter`.
- **Копия целиком**: весь `ru/parliament.json` прочитать как редактор — регистр, Ё, склонения, единый стиль
  подписей, глоссарий; журнал заседания (корневая строка, дочерние) и анонс — тем же глоссарием.
- **Deck**: пять мест, big-draw, пикер на шесть, осмотр партии/резолюции без обрезания, полоса Информации.

Гарды блока: `console-parliament-stability` расширить на голосование и стадии заседания (не только обзор);

Правило: **если дефект виден на поверхности Парламента, он парламентский**, даже когда живёт в общем chassis.
Пройти R-08, R-15, R-20, R-22, R-23, R-24, R-28, R-32, R-33 (и всё, что блок B добавил): либо исправить в общем

## 5. Блок D — готовность к семействам резолюций (дожать базу)

Цель: следующая резолюция ЛЮБОГО семейства каталога ложится по чек-листу без открытия UI-файлов, и это доказано
репетицией, а не обещанием.
1. **Репетиция чек-листа на dev-примерах.** Сажать через `tests/parliament/parliamentArrange.ts` (`seatResolution`
   принимает любой id каталога) и генератор фикстур: `RDX_DEV_PASSIVE` (пассив с прогнозом), `RDX_DEV_ACTION`
   (действие), `RDX_DEV_COMPOUND` / `RDX_DEV_SCIENCE` (заместители Красных/Учёных). Провести каждый через ПОЛНЫЙ путь:
   лицо, голосование (чтение для пассива/действия — «эффект, пока принята» / «действие, пока принята», без
   выдуманных чисел), осмотр, заседание, стадия НАГРАДА **без немедленного эффекта** (сейчас — «Без награды»;
   должна показывать, ЧТО игрок получил: прогноз пассива или доступность действия с адресом «Действия карт»),
   ОБНОВЛЕНИЕ, ЗАКРЫТИЕ, журнал; галерея — кадры для этих семейств; e2e — параметризованный сценарий заседания на
   dev-фикстуре. Всё, что чек-лист при этом не учёл, — исправить в чек-листе и в общем слое.
2. **Партии без карт.** `quietResolutionOf` (`parliamentArrange.ts:105–111`) бросает для Красных/Союза/Учёных —
   обобщить на dev-заместители, чтобы спек/фикстура первой карты этих партий не начиналась с правки хелпера.
3. **Будущие виды наград.** В `rewardAddress.ts` и чек-листе — раздел «как добавить вид»: бюджеты (`stockLoss`),
   глобальный параметр, шаг Повестки всем, треки колоний, колония победителю, город каждому, «добор до N». Для
   каждого — эскиз адреса (поверхность, источник, единица, плита пропуска) и какая поза галереи появится. Без
   реализации, но так, чтобы первая карта вида не проектировала подачу с нуля.
4. **Гард на семейства.** `ResolutionContract.spec` уже гоняет реальную фазу; добавить проверку, что пассив без
   `forecast` и действие без `preview` не проходят, и что резолюция без немедленных шагов даёт на стадии НАГРАДА
   честную позу (не пустую).

## 7. Чего делать НЕЛЬЗЯ

Пушить; коммитить красное; параллелить продуктовые правки; оставлять строку реестра «отложено» или «minor»; «вне
скоупа» без скриншота и замера чужой поломки; «честное ограничение» вместо работы; детект по тексту; клиентская
память «уже видел»; `setTimeout`-хореография; `v-if`-blink; второй экземпляр поверхности; пересчёт выплат на
клиенте; смена правил игры; `title`; литералы кнопок; `filter` как состояние; масштабирование текста; `opacity`
на `preserve-3d`; правка RU чужих ключей (парламентские — свои); свой визуальный язык вместо семейного; начинать
новые резолюции каталога (кроме репетиции на dev-примерах); обзор протокола/журнала как workspace (отдельный план).

## 8. Готово, когда

Все пункты блока A закрыты кодом и подтверждены скриншотами; реестр P закрыт без «отложено»; строки «вне скоупа»
либо исправлены, либо доказаны; репетиция семейств пройдена и чек-лист исправлен; галерея и кадры трейса
просмотрены; все прогоны зелёные (чужие красные перечислены); документы, память и журнал закрыты; в рабочем
дереве — только закоммиченное; пуша не было. После этого Парламент закончен: дальше — только новые резолюции.
