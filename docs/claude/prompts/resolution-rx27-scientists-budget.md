### Порядок и чтения

1. **Печатный порядок — исполняемый:** плата 10 M€ → выплата (метки науки + влияние) → добор 2 карты.
   Семейство это уже фиксирует: `levy` идёт ПЕРВЫМ шагом (`resolutionLevy.ts`, `LEVY_STEP_KEY`).
2. **Плата — объявлением, не кодом.** `levy: {resource: MEGACREDITS, amount: 10}`; всё остальное делает
   общий шаг: частичная уплата при нехватке (`levyPaid` / `levyShort`, запись со знаком и «было
   должно»), `from: {resolution}`, причины. **Если для этой карты понадобилось трогать `levyStep` —
   значит RX15 сделал его недостаточно общим; скажи об этом в отчёте.**
3. **Выплата** — `unit: {kind:'stock', resource: MEGACREDITS}`, `perInfluence: 1`,
   `count: {id: 'scienceTags', per: 1}`, без потолка. **Id счёта уже есть** (завёл RX18), новый не
   заводить.
4. **Добор — всем участникам по 2 карты**, фиксированно, через `ExternalDrawIntake` (заседание, не свой
   ход): карты уходят из колоды на принятии, удерживаются до взятия, перезагрузка внутри взятия ничего
   не теряет, пустая колода → честный недобор (`delivered`). Влияние на добор не влияет.
5. **Нетто-чтение** — как у RX15: «−10 → +7 = −3» одной линией, и добор отдельной строкой (он ни от
   чего не зависит и не складывается с деньгами).
6. **Бот** в Парламенте не участвует: ни платы, ни выплаты, ни добора.

## 2. ЛОВУШКА · метки науки теперь считаются в двух режимах

Вчера сдана **RX26 R&D Funding** — закон, который даёт **надбавку к меткам науки** (хук `tagBonus`
внутри `includeTagSubstitutions` в `Tags.count`). А счётные члены резолюций читают метки в режиме
**`'raw'`** (`RESOLUTION_TAG_COUNTING_MODE = 'raw'`, `ResolutionCounts.ts:155`
`player.tags.count(tag, RESOLUTION_TAG_COUNTING_MODE)`).

Значит **надбавка R&D Funding в этот счёт НЕ попадает** — и это правильно: её правило говорит «when
taking actions», а выплата резолюции действием не является. Но со стороны это выглядит как
рассогласование: в зоне меток у игрока «2 +2», а Бюджет платит по 2.

**Что требуется:**

- ничего не менять в счёте — `'raw'` остаётся;
- **закрепить спеком**: при действующем R&D Funding выплата Scientists Budget считает ПЕЧАТНЫЕ метки,
  надбавка не участвует. Спек должен называть обе карты, чтобы следующий читатель не «починил» это;
- **в чтении не соврать**: разбор счёта показывает печатное число меток; если рядом действует надбавка,
  не подмешивай её в это число молча. Реши, нужна ли здесь оговорка в осмотре («учитываются печатные
  метки»), и обоснуй решение в отчёте — лишний текст на панели тоже цена.

## 3. Блоки

**A · сервер.** Файл карты по чеклисту: `id` (`RDX_SCIENTISTS_SCIENTISTS_BUDGET` — сверь стиль с
`IndustrialistBudget`), `code` RX27, партия, `copies`, `renderData` (как на скане: 2 карты сверху,
`−10 M€` и `1 M€ / [метка науки] + [влияние]`), `text`, `levy`, `scaled`, `immediateSteps` (выплата,
добор), задание. Кода механики писать не должно быть почти нечего — если пишется много, ты строишь
копию вместо объявления.

**B · чтения.** Нетто-линия (RX15) + строка добора; разбор счёта по меткам (RX18).

**C · показ.** Отток платы (RX15) → волна M€ в рельсу → добор с раскрытием (RX16). Всё существует;
проверь, что три такта идут по очереди и не наслаиваются, и что лента даёт по строке.

**D · лицо, локаль, стенд.** Стенд «Полигон»: 0 меток науки · 3 метки · нехватка M€ на плату · пустая
колода.

## 4. Бюджет проверки

**Новых механик нет → НОВЫЙ e2e НЕ ДОБАВЛЯТЬ.** Юнитов достаточно.

- **серверные юниты:** плата 10 при 12 M€ → осталось 2; при 4 M€ → частичная с «было должно», выплата
  всё равно идёт; выплата = метки науки + влияние (0 меток и влияние 2 → +2); добор 2 каждому
  участнику независимо от влияния; пустая колода → недобор назван; порядок шагов = печатный (по
  записям); **при действующем R&D Funding надбавка в счёт не входит** (§2); бот не тронут;
  **RX15 не поехал** — Industrialist Budget даёт те же числа;
- **клиентские юниты:** нетто-линия; строка добора отдельно; разбор счёта по печатным меткам;
- `npm run lint`, `npm run build:test`, `npm run make:cards`;
- **старые сюиты не гоняй.**

Глазами, один профиль, два кадра: панель голосования с нетто и добором; исход после трёх тактов.
