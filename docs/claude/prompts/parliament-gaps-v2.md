# Промт исполнителю · Парламент Turmoil Redux — «Заседание v2»: закрытие гэпов реализации

Выдан 2026-09-20 после ручного тестирования пользователем сданной полировки (`567cd53298`). Найдено семь
проблем, которых часы e2e-прогонов не поймали. Итерация — большая: два реворка (порядок фазы на сервере,
правительство/оппозиция на обзоре) и пять исправлений подачи. Режим работы — экономный: юниты + точечные
новые e2e на свои изменения, без перегонов всего скоупа; проверять будет пользователь руками.

---

Ты — исполнитель итерации «Заседание v2» по Парламенту Turmoil Redux в приватном форке `terraforming-mars`
(vize1215). Парламент построен и отполирован (см. §1), но живая игра показала гэпы, которые надо закрыть
реворком, а не заплатками. Работаешь автономно, по-русски, без вопросов пользователю.

**Планка прежняя:** премиальная подача уровня Steam-версии / Ark Nova, новичок понимает всё без обучения,
ничего не скачет, ничего не пустует, каждое движение отвечает «откуда, почему, куда». Пользователь проверит
результат сам, руками, на живой партии — поэтому важен РЕЗУЛЬТАТ на экране, а не количество прогонов.

## 0. Режим работы (изменён — экономный)

- **Не гоняй существующие e2e-сюиты и галерею.** Часы прогонов не нашли ни одной из семи проблем. Вместо
  этого: (а) юнит-спеки на каждую чистую модель, которую трогаешь; (б) **точечные новые e2e-пробники только на
  свои изменения** (§8), запуск `--workers=1` только этих файлов; (в) свои скриншоты/кадры трейса — смотреть
  как ревьюер. Старые e2e, которые твоя правка ожидаемо ломает, — переписать по новой грамматике (селекторы,
  стадии), но не гонять всем списком; перечисли их в отчёте.
- Порядок блоков: **Б1 → Б2 → Б3 → Б4 → Б5** (§4–§8). Локальный коммит на блок (`Parliament v2 · Б<n>: <суть>`),
  каждый зелёный по юнитам (`npm run test:server`, `npm run test:client`, `npm run build:test`,
  `npm run lint:client`, eslint по изменённым файлам). **Не пушить.**
- Сборка перед своими пробниками: `npm run make:json` → `npm run make:css` → `npm run build`; никакой
  пересборки во время идущего playwright. Юнит-сюиты — не параллельно с e2e (таймауты).
- Журнал прогресса — `docs/claude/parliament-sitting-progress.md`, раздел «Заседание v2»: решения, замеры,
  отклонения; в конце — **ручной сценарий проверки для пользователя** (§9).
- Застрял — три подхода, замеры в журнал, самое честное решение, дальше. Субагенты — только чтение.

## 3. Целевой flow заседания (после итерации)

```
СЕРВЕР:  winner → ▶ ASSEMBLY ◀ → agenda → support → enact → effects → refresh → lobby → ▶ ADJOURN ◀ → done
         (final:  winner → ▶ ASSEMBLY ◀ → agenda → support → enact → effects → ▶ ADJOURN ◀ → done)

ИГРОК:   ВЕРДИКТ ──A──▶ [авто: ПОВЕСТКА → ПОДДЕРЖКА → ПРИНЯТИЕ] → НАГРАДА ──(волна авто | ВЫБОР | ПОЛУЧЕНИЕ | A «К полю» → РАЗМЕЩЕНИЕ)──▶
         [ждём чужие ходы, если есть] → ИТОГИ [авто: сброс проигравших → раздача с переворотом → поддержка садится → лобби → карточка итогов] ──A «Закрыть заседание»──▶ доска
```

- **Два нажатия A на поколение** (плюс собственные выборы). Между ВЕРДИКТОМ и НАГРАДОЙ — ни одного нажатия:
  беты идут одной выверенной последовательностью, каждый после посадки предыдущего (пауза ≥ 250 мс),
  бюджет ≈ 5–6 с до волны.
- **Всё, что игрок видит на ВЕРДИКТЕ, ещё не случилось**: маркер на старом шаге, поддержка не роздана, карта в
  слоте, правительство и задание — прошлого поколения. После A сервер применяет шаги, ответ (свой сабмит или
  WS/опрос) несёт диффы, клиент ЗАСЕИВАЕТ удержания в том же синхронном блоке, что применение вида (образец —
  `seedParliamentRewardHold` в `gameTransport.seedRewardHolds` / `App.update()`), и играет беты от старого к
  новому. Reload посреди последовательности — серверный шаг, конечные позы, без реплея.
- Крошка: `ПАРЛАМЕНТ › ЗАСЕДАНИЕ › ВЕРДИКТ | ПРИНЯТИЕ | НАГРАДА | ВЫБОР | ПОЛУЧЕНИЕ | РАЗМЕЩЕНИЕ | ИТОГИ`.
  B до ИТОГОВ — свернуть (committed); на ИТОГАХ — none (verdict-фаза).

## 4. Б1 — сервер: ворота ДО изменений (проблемы 5, 6-причина, 4-порядок)

- Модель: `ParliamentPhaseModel.summary` в процессе (есть), `awaiting` (есть). `parliamentPhasePrompt.stage`

## 5. Б2 — клиент: последовательность после A, правительство и оппозиция (проблемы 5, 6)

**Позиция и страницы** (`consoleSittingFlow.ts`): `assembly` → страница ВЕРДИКТ (A = ответ на ворота);
после ответа — стадии ПРИНЯТИЕ и НАГРАДА без страниц-остановок (автобеты), реальная остановка только на
шаге награды `choice | intake | placement | waiting`; `adjourn` → одна страница ИТОГИ (§6).

**Удержания перехода** (`parliamentDisplayHolds.ts`, расширить): при ответе с диффами засеять
`agendaAwaits` (маркер на `from`, чтение влияния старое), `supportAwaits` (гнёзда поддержки без новых кубов),
`govAwaits` (карта в слоте, правительство ПРОШЛОЕ: старая карта или заглушка, старая правящая партия, старое
задание с исходом — «Председатель: <игрок> / никто»), `returnsAwait` (кубы на карте). Снимаются посадками
бетов. Засев — в том же синхронном блоке, что применение вида, для ОБОИХ путей (свой сабмит и WS/опрос):
пробник обязан показать ноль кадров, где новое состояние видно раньше своего бета.

**Беты** (`sittingBeats.ts`/`sittingDirector.ts`), порядок и вкус:
1. **ПОВЕСТКА** — заметно и премиально: сегмент рейки от `from` до `to` подсвечивается, маркер едет
   (`agendaGlide`), достигнутый шаг пульсирует один раз, чтение влияния в строке Повестки тикает; бонус
   шага (РТ-чип в HUD / карта) — как в Э5. ≈ 0.9–1.1 с.
2. **ПОДДЕРЖКА** — ПОСЛЕДОВАТЕЛЬНО: партия за партией в порядке сводки, плакетка партии подсвечивается,
   когда принимает; куб за кубом ≥ 90 мс, между партиями ≥ 180 мс; ярус оппозиции виден целиком на это время
   (не peek с opacity .08). ≈ 1.0–1.4 с.
3. **ПРИНЯТИЕ** — одна связная фраза: старая резолюция уходит в сброс → карта-победитель FLIP-ом из слота в
   правительство → кубы домой по владельцу (подпись у резерва) → **смена правительства** (§ ниже) →
   задание: старый блок RELEASE (с исходом прошлого поколения) → UNFOLD → REVEAL нового. ≈ 1.8–2.2 с.
4. **НАГРАДА** — волна с графики карты (Б3), либо стадия выбора/получения/размещения.
Каждый бет — под своим hold-ом, старт следующего — по посадке предыдущего; A во время бета = дожать. Общий
бюджет до волны ≈ 5–6 с; reduced-motion — позы ≤ 2 с.

**Правительство и оппозиция (решение пользователя):**
- Внизу — ТОЛЬКО оппозиция: пять плиток партий, у которых нет власти (народная поддержка по правилам идёт им).
- Правящая партия — только в правительстве, плиткой ТОГО ЖЕ шасси и размера, что плитки оппозиции
  (`ConsolePartyPlaque tile`), фокусируемой: X = осмотр партии, дверь действия партии — как с плитки внизу.
  Стартовое правило: Зелёные наверху, внизу пять остальных.
- Смена правительства — одна DOM-инстанция на партию: плитка новой правящей партии FLIP-ом поднимается из
  ряда в правительство, плитка старой опускается на освободившееся место ряда (ряд переукладывается FLIP-ом
  после посадки; размеры не меняются); если партия не сменилась — только карта и задание.
- Размеры блоков правительства и плиток ряда — общие токены; пробник стабильности проверяет, что ряд не
  скачет при смене состава.
- Обновить: `ConsoleParliamentGovernment.vue`, `ConsoleParliamentParties.vue`, `parliamentNavigation.ts`
  (фокус/двери), `console_parliament.less`/`console_party_plaque.less`, e2e-свидетели (`data-parl-ruler`,
  `.con-parl__party[data-party]`), `console-parliament-stability` (д-пад по ряду из пяти + правитель).

## 6. Б3 — награда: волна всегда, тайл по нажатию (проблемы 3, 4)

- **Дверь запуска не зависит от транзиентной стадии.** Запуск бета награды не может читать
  `parliamentFlow.stage === 'sitting'` в pre-flush watcher-е: свой сабмит (`submitting` → `sitting` только в
  post-flush `onAnswerKey`) и чужой ответ по опросу должны сходиться в ОДНУ точку — ledger публикует
  «есть должное» и директор потребляет его по позиции сервера (`sittingPositionOf`), а не по флагу секции;
  `submitting` — не состояние, в котором что-либо может потеряться. Юнит на оба пути (собственный ответ /
  опрос) обязателен — именно этот случай не ловили API-driven e2e.
- **Удержание без wall-clock.** Убрать `REWARD_HOLD_SAFETY_MS` как условие тика: удержание отпускается
  (а) посадкой чипа, (б) явным завершением стадии (уход на поле, закрытие, свёртывание, размонтирование
  секции — через `expire` supplier-а animation-hold), (в) сторожем аномалии (35-секундный ceiling реестра с
  `diagnose`). Пауза игрока на любой странице НЕ отпускает удержание. То же для бонуса Повестки.
- **Волна робастна к монтажу:** origin меряется в момент бета; если hero-карта ещё не нарисована — ждать
  кадр (`probeTick`/`nextTick` + `img.decode`), не деградировать в «без полёта»; деградация — только при
  отсутствии карты на экране, и тогда чип летит с плиты чтения (реальное место), никогда «из ниоткуда».
- **Воспроизведение до правки** (обязательно, в журнал): живая соло-партия (dev-door + UI-нажатия), фикстура
  Biodome/Aquifer/Climate, `parliamentRewardDiag()` до и после A — почему не полетело; после правки — тот же
  сценарий + сценарий с двумя местами, где исход зрителя приходит по WS/опросу (второе место отвечает по API
  ПОСЛЕ зрителя) — волна летит в обоих.
- **Тайл: явный CTA.** Шаг награды `placement` → поза с чтением тайла (`ConsoleWinnerReward`) и глаголом
  **A «К полю»** (глоссарий; X осмотреть; B свернуть). Только нажатие уводит стек на поле (`yieldStackToBoard`
  по нажатию, не по `placementActive`); подсветка клеток на поле ждёт нажатия (`setConsolePlacementHeld`
  до двери), после посадки тайла стек возвращается в НАГРАДУ в позе «получено» (как сейчас). Сервер не
  меняется: промпт `SelectSpace` стоит, клиент держит дверь. Никаких автоматических уходов на поле из
  Парламента.
- Юниты: ledger (`parliamentRewardBeat.spec`) — отпускание по стадии, не по времени; e2e-пробник §8.

## 7. Б4 — ИТОГИ: одна стадия вместо двух (проблема 7)

- `adjourn` → одна страница **ИТОГИ**: беты ОБНОВЛЕНИЯ играют сами (проигравшие → сброс, раздача с
  переворотом, поддержка садится, лобби), после них в той же панели REVEAL-ом — карточка «Итоги поколения N»
  (только объекты: принята · победитель голосования · ваша награда · новые резолюции с партиями · в лобби);
  A «Закрыть заседание» — единственное нажатие; до посадки бетов A = дожать.
- Крошка `ИТОГИ`, фаза `verdict` (B none). Удалить стадии `renewal`/`closing` как отдельные страницы (тип
  `SittingStage`, `sittingPagesOf`, беты `renewal`/`lobby`/`closing` → под стадией `results`).

## 8. Б5 — геометрия голосования и уход одним движением (проблемы 1, 2)

- **Голосование:** от нажатия A до конца flow ничего, кроме текста, состояния кнопки и полёта, не меняется:
  панель — фиксированная высота с зарезервированными тремя рядами фактов (третий ряд — пустой резерв, пока
  ребра нет), CTA-плита той же высоты во всех состояниях, `billGeometry` только когда РЕАЛЬНО стоит панель
  оплаты (серверный `votePayment`), и даже тогда — оплата хостится внутри зафиксированной панели без смены
  строки сетки карт (`--con-parl-bill-h` не должен трогать `grid-template-rows` карт — только колонки панели);
  `fitParliamentCards`/ResizeObserver/`view`-watcher заморожены от сабмита до ухода (`fitFrozen` в
  `parliamentCardFit.ts` — одна точка), `playParliamentVoteRefit` не вызывается в потоке голоса.
- **Уход:** конец любого flow Парламента (голос, кресло, заседание, действие партии из Парламента) — ОДНО
  движение всей поверхности: убрать отдельный класс-фейд `con-parl__vote--concluded`; `flow-complete` — на
  посадке; уход — director-ом (`data-motion-surface`/`data-motion-panel` на корне и раме, все слои включая
  припаркованное тело внутри панели ухода); ни одного кадра «рамка без тела»; доска видна сразу под
  растворяющейся поверхностью. Проверь B «свернуть» (v-show) и конец заседания (`closeWorkspaceRoot`).
- Пробники §9.
