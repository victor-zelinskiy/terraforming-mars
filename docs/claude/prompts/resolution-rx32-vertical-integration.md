## 2. Единственная новая деталь · счёт по ТИПУ карты

```
MEGACREDITS: {unit: {kind: 'stock', resource: MEGACREDITS}, perInfluence: 1,
              count: {id: <новый>, per: 1}, recipient: 'each'}
```

Формула байт-в-байт RX27 — отличается только id счёта. Новый id заводится в
`src/common/parliament/resolutionCounts.ts` как счёт **вида CARDS** (единица — КАРТА), по образцу
`buildingCardsWithNonNegativeVp`, с предикатом в `cardCountVerdict` и причиной отказа английским ключом
(«Not a blue card»).

### Что именно считается — закрепить спеком каждую строку

- **Синяя карта = `CardType.ACTIVE`**, и больше ничего. Это ЕДИНСТВЕННЫЙ вопрос предиката: ни меток,
  ни VP-значка, ни стоимости.
- **«В игре» = табло**, и определение уже написано в шапке `ResolutionCounts.ts`: корпорации,
  прелюдии, CEO, сыгранные проекты и события, минус отключённая Pharmacy Union; рука, сброс и карты,
  размещённые под чужой картой (Self-Replicating Robots), в табло не входят. Своего определения не
  изобретай — ходи общим обходом.
- **Тип отсекает всё лишнее сам**: корпорация (`CORPORATION`), прелюдия, CEO, событие (`EVENT`) и
  зелёная карта (`AUTOMATED`) синими не являются. Спеком — по случаю на каждый.
- **Не бери движковые счётчики «синих» — их там нет.** `Tycoon` (веха) и `Celebrity` (награда) считают
  `ACTIVE || AUTOMATED`, то есть синие И зелёные: формула, похожая на нашу ровно настолько, чтобы
  сломать счёт молча. Мимо них.
- **Проверка «лицом вниз» здесь ни при чём.** `cardTagsInPlay` — про МЕТКИ разыгранного события; тип
  карты виден всегда, и событие всё равно отсеивается типом. Не копируй эту ветку из соседнего
  предиката «на всякий случай».
- **Разбор счёта — список самих карт** (`ResolutionCountModel.cards`, единица = карта, без
  `units`-разбивки: у карты нет «двух синестей»), чтобы «4» всегда объяснялось четырьмя названиями.

## 3. Блоки

**A · сервер.** Файл карты по чеклисту: `id` (`RDX_INDUSTRIALISTS_VERTICAL_INTEGRATION` — сверь стиль
с `IndustrialistBudget` / `MetalResearch`), `code` RX32, партия, `copies`, `renderData` (как на скане:
`1 [M€] / [синяя карта] + [влияние]`), `text`, `scaled`, один `immediateSteps` шаг по образцу
`ScientistsBudget.MEGACREDITS_STEP` (`resolutionCount` → `scaledAmount` → `stock.add(..., {log: false,
from: {resolution}})` → одна журнальная строка с полным расчётом → `report`), задание. **Ноль называет
себя**: ни одной синей карты и влияние 0 → «нет синих карт и нет влияния — M€ нет» (одна запись
`skipped`, как у RX27). Бот в Парламенте не участвует.

Если при сборке пришлось тронуть `resolutionCounts.ts` глубже трёх аддитивных строк (список,
`resolutionCountKind`, ветка предиката) — **скажи в отчёте**: значит вид CARDS оказался менее общим,
чем его объявил RX02.

**B · чтения.** Рейт «1 M€ за синюю карту + влияние» на панели голосования и в осмотре; разбор счёта
списком карт; исход как у RX27. **Чужая колонка считает ЧУЖИЕ синие карты** (чужие исходы сданы
2026-09-25) — спеком: подстановка своего счёта в соседнюю колонку не упадёт, а тихо соврёт.

**C · показ.** Один такт: волна M€ в рельсу (RX15/RX27). Ничего нового.

**D · лицо, локаль, стенд.** Лицо по скану. Тексты — языком карт проектов (глоссарий § 8). Ключи i18n
грепнуть по всем `src/locales/<lang>/*.json` перед добавлением; ключ задания уже есть (§1). Стенд
«Полигон»: 0 синих карт · 2 синие · табло из синих + зелёных + событий вперемешку (проверка, что
считаются только синие), влияние 0 / 3.

## 4. Бюджет проверки

Новых механик нет → **НОВЫЙ e2e НЕ ДОБАВЛЯТЬ.**

- **серверные юниты:** 0 синих и влияние 2 → +2 M€; 3 синих и влияние 1 → +4 M€; корпорация, прелюдия,
  CEO, событие и зелёная карта **не** считаются (по случаю на каждый); карта в руке и карта под
  Self-Replicating Robots не считаются; отключённая Pharmacy Union не считается; ноль-ноль → названный
  пропуск; бот не тронут; **RX27 и RX02 не поехали** (счётное семейство даёт те же числа);
- **клиентские юниты:** рейт на панели; разбор счёта списком карт; чужая колонка;
- `npm run lint`, `npm run build:test`, `npm run make:cards`, `npm run make:css` перед визуальной
  проверкой; **старые сюиты не гоняй.**

Глазами, один профиль, **два кадра**: панель голосования с рейтом и разбором счёта; исход после такта.

## 5. Режим работы

Экономный, **1–2 коммита** — это самая маленькая карта пачки. **Не пушить.** Документ карты —
`docs/TURMOIL_REDUX_VERTICAL_INTEGRATION.md` (короткий: сборка из готового + новый вид счёта);
журнал — `docs/claude/parliament-sitting-progress.md`; спек — строка каталога (задание уже сверено
аудитом, не откати). Чеклист автора: строка «счёт по ТИПУ карты — единица есть карта, движковые
счётчики синих+зелёных не подходят».

Гочи: `python3` здесь — заглушка Store, только `python` (длинные скрипты файлом, не heredoc);
`cross-env` в bash нет — `NODE_ENV=… npx mochapack`; посевная колода сдвигается с ростом каталога —
сажать карту через `seatResolution`.

В отчёте: подтверждение, что формула и задание взяты объявлением (и что общие модули потребовали
ровно три строки); как разошлись с `Tycoon` / `Celebrity`; два кадра; новые ключи i18n (ожидается
только имя и текст эффекта).

## 6. Нельзя

Считать зелёные карты вместе с синими. Переиспользовать `Tycoon` / `Celebrity`. Считать карты в руке,
в сбросе или под Self-Replicating Robots. Заводить новый ключ задания вместо ключа RX26. Писать свою
формулу вместо `InfluenceScaledEffect` и свой обход табло вместо общего. Переписывать чужую строку в
`resolutionCounts.ts` (§0). Добавлять e2e. Гонять старые сюиты. Пуш и красные коммиты.
