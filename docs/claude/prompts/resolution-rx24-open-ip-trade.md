### Чтения действия

1. **Раз за поколение**, как всякое действие Парламента (`PARTY_ACTION_USES_PER_GENERATION`; для
   резолюций — `usesPerGeneration(player)`, верни 1 и закрепи спеком). Сброс на границе поколения уже
   есть.
2. **Держат его только участники, и только пока карта принята**: сменился закон — действие исчезло из
   меню. `Parliament.participates`, `enactedDefinition().action`.
3. **Недоступно с причиной, не скрыто**, когда: в руке нет карт («В руке нет карт»); использование
   потрачено («Уже использовано в этом поколении»); ход не свой. Инвариант 2: кнопка отражает
   ПРИСУТСТВИЕ опции в `waitingFor`, причина — серверная.
4. **«Любое число» — не ноль.** Ноль карт — не действие; минимум 1, максимум — вся рука (как у продажи
   патентов). Ответ с пустым списком отвергается `InputError`.
5. **Порядок внутри**: сброс → M€ (`stock.add`, 3 × N, под источником резолюции) → добор N (обычный
   добор в СВОЙ ход: `drawCard`, карты идут в руку; это НЕ внешний интейк — внешний нужен, когда
   добор случился не в твоём ходу). Колода не может выдать всё → честно, сколько выдала.
6. **Задание**: зелёная = `CardType.AUTOMATED`; синие, события, прелюдии, корпорации — нет. Сброс карт
   этим действием — НЕ розыгрыш и заданию не помогает. Розыгрыш под источником-резолюцией по правилу
   Q5 тоже не считается — здесь его и не бывает (действие ничего не разыгрывает).
7. **Бот** в Парламенте не участвует: ни добора при принятии, ни действия.

## 2. Блок A · сервер: действие резолюции — полноправный источник

Построить зеркально партийному, **одним семейством**, а не второй копией:

- **`ResolutionActionPromptMeta`** (по образцу `PartyActionPromptMeta`): резолюция (`ResolutionId`),
  `stage`, `usesLeft`, `usesPerGeneration`; маркер **`resolutionActionPrompt`** в `PlayerInputModel`,
  сериализуется на `toModel` самого промпта (nesting-safe, как партийный). Консоль находит промпт ПО
  МАРКЕРУ, никогда по заголовку (инвариант 1).
- **`ParliamentHandler.resolutionActionOptions(player)`** рядом с `partyActionOptions`: принятая
  резолюция с `action` · участник · `usesLeft > 0` · `canAct` → `execute(player)` даёт промпт с meta.
  **Подключить в `Player.ts` там же, где партийные** (`~2814`), одной строкой рядом.
- **Модель для клиента**: `ParliamentModel.viewer` получает `resolutionAction` того же вида, что
  `PartyActionModel` (`hasAccess` · `available` · `reason` · `usesLeft` · `usesPerGeneration` · `preview`).
  Не дублируй тип — обобщи или наследуй.
- **Учёт** — `recordResolutionActionUse` в коммите ответа, не при выдаче промпта.
- **Действие карты**: `SelectCard` из `cardsInHand`, `min: 1, max: hand.length`, `played: false`;
  `andThen`: `discardCardFromHand` каждой, `stock.add(MEGACREDITS, 3 × N, {from: {resolution}})`,
  `drawCard(N)`; журнал одной строкой с обеими величинами. **Не** вызывай продажу патентов напрямую —
  это своё действие с другим источником и другой выплатой; переиспользуется ФОРМА промпта и сцена.
- `preview(player)` честный: «N карт → +3N M€ и N карт» — читается статусной рельсой ДО коммита.
- Файл карты по чеклисту: `id` (`RDX_SCIENTISTS_OPEN_IP_TRADE`), `code` RX24, партия, `copies`,
  `renderData` (как на скане: `[карта] / [влияние]`; действие `X [карта] → X [карта] + 3X M€`), `text`
  (включая `action`), `scaled`, `immediateSteps`, `action`, задание.

## 3. Блок B · клиент: ОДИН ПОТОК через workspace — главный заказ владельца

Действие живёт в **«ДЕЙСТВИЯ КАРТ»** как источник того же ряда, что карты и партийные действия, и
открывается **двумя дверьми** — из меню действий и из Парламента — одним и тем же компонентом, одним
промптом, байт-идентичным ответом (закон партийного композера).

### 3.1 Источник в списке

`ResolutionActionSource` рядом с `PartyActionSource` (`ConsoleCardActions.partyActionSources`):
плитка с **лицом резолюции** (не партийной плитой), печатной графикой действия, `usesLeft`,
доступностью и серверной причиной. Не заводи третий список — обобщи «источники Парламента».

### 3.2 Поток — крошка непрерывна, стадии идут по очереди

```
⚡ ДЕЙСТВИЯ КАРТ › ОТКРЫТАЯ ТОРГОВЛЯ ПАТЕНТАМИ › ВЫБОР
                                               › ПРОДАЖА      (сцена)
                                               › ДОБОР КАРТ   (раскрытие)
```

1. **ВЫБОР — шаг на РЕАЛЬНОЙ руке** (`card-actions ⊃ hand`, слот `action-hand`, как сброс у
   Красных). Многовыбор с живой суммой — **переиспользуй режим выбора продажи патентов**
   (`handSelectState` / `sellPatentsState`: там уже есть «отметь любое число, внизу итог»), но
   суммирующая строка говорит про ЭТО действие: «3 карты → **+9 M€ · +3 карты**». Ноль отмеченных —
   A недоступна с причиной. Лицо резолюции — герой слева, крошка называет стадию.
2. **A Подтвердить → ACTION COMMIT → ПРОДАЖА — сцена патентной продажи** (`consolePatentSale`):
   отмеченные карты снимаются с руки, летят в терминал, терминал работает, **чип +3N M€** выходит и
   садится в рельсу, счётчик тикает на посадке. Арм — до POST, детект — по ответу (карты реально ушли
   из руки), холд — до посадки чипа. Если сцена зашита под стандартный проект (источник, подпись,
   величина «1 за карту») — **обобщи**: ставка и источник приходят от вызывающего.
3. **ДОБОР — раскрытие в зоне исхода** (как «Reds' draw claims its batch into the OUTCOME zone»):
   N карт снимаются с HUD-стопки колоды, раскрываются в зоне исхода того же композера, затем уходят в
   руку интейком. Дверь стадии открывается по `followUp` — **после того, как чип продажи сел**, не
   раньше: один ответ сервера несёт и списание, и добор, и поверхности идут ПО ОЧЕРЕДИ (закон «один
   пресс, несколько эффектов»). Пока добор не взят — поток `owed-step`, свернуть можно, закрыть нельзя.
4. **Завершение** — guarded conclusion, как у любого workspace: закончилось — уходим, не
   сворачиваемся к списку.

**Композер.** У `ConsolePartyActionComposer` уже есть всё нужное: колонка ГЕРОЯ, колонка РЕШЕНИЯ, ряд
коммита с кольцом готовности, шаг руки, зона исхода с раскрытием. **Не копируй его в
`ConsoleResolutionActionComposer`.** Обобщи источник: герой — плита партии ИЛИ лицо резолюции;
решение — от промпта; всё остальное общее. Если обобщение ломает партийные действия — это регрессия,
её ловят их юниты и e2e; копия в 900 строк — не выход.

### 3.3 Из Парламента

Та же дверь, что у партийных действий из сцены Парламента: `⚖ ПАРЛАМЕНТ › ОТКРЫТАЯ ТОРГОВЛЯ ПАТЕНТАМИ ›
ВЫБОР …` — тот же композер, вложенный как шаг. Ничего второго.

## 6. Бюджет проверки

Ново: путь действия резолюции, задание `automated`, сцена продажа → добор.

- **серверные юниты:** промпт действия появляется у участника в свой ход с маркером
  `resolutionActionPrompt`; не появляется у не-участника, при потраченном использовании, при пустой
  руке (с причиной), после смены закона; ответ на 0 карт отвергнут; 3 карты → −3 в руке, +9 M€, +3 в
  руке, журнал; `usesLeft` 1 → 0 и обратно на границе поколения; колода пуста → честно; **задание**:
  розыгрыш automated считается, active / event / prelude — нет, сброс этим действием — нет; добор при
  принятии = влияние через интейк; бот не тронут; **партийные действия ведут себя как раньше**;
- **клиентские юниты:** источник в списке действий; сумма на шаге выбора; блок «0 отмечено» с причиной;
  дверь добора не открывается до посадки чипа;
- **РОВНО ОДИН новый e2e:** RX24 принята → меню действий → плитка резолюции → шаг выбора на руке,
  отмечены 2 карты, рельса «+6 M€ · +2 карты» → A → **сцена продажи** (карты ушли в терминал, чип сел,
  счётчик тикнул) → **добор** (2 карты раскрылись в зоне исхода и ушли в руку) → рука −2 +2, M€ +6,
  плитка действия — «использовано». Пробник утверждает ВИДИМОСТЬ источника и цели на каждом такте и
  порядок тактов (`animation-needs-a-visible-stage`, `probe-sample-carries-its-clock`);
- **старые сюиты не гоняй**, фикстуру правь точечно (`FIXTURES=… npm run e2e:fixtures`).

Юнитами: партийные действия (Красные — сброс + добор; Индустриалисты; Учёные; Союз-торговля),

## 8. Режим работы

Экономный по проверке, **не экономный по потоку** — владелец назвал это главным. Коммит на блок
(A сервер · B источник + композер · C сцена продажа → добор · D лицо/локаль + юниты и один e2e), каждый
зелёный по юнитам, `npm run lint`, `npm run build:test`, `npm run make:cards`, `npm run make:css` перед
визуальной проверкой. **Не пушить.** Документ карты — `docs/TURMOIL_REDUX_OPEN_IP_TRADE.md` с разделом
«действие резолюции: путь, который повторит следующая карта с действием»; журнал —
`docs/claude/parliament-sitting-progress.md`. Чеклист автора: строка «действие резолюции — маркер
`resolutionActionPrompt`, источник рядом с партийным, композер общий».

**Параллельная работа:** в дереве могут работать другие агенты; общие файлы (реестр, локали, спек,
журнал, `genfiles`) — только своя строка, генерируемое не править руками, мелкие коммиты. Обобщение
композера и `ParliamentHandler` — твоя зона, но перед правкой `Player.ts` и `PlayerInputModel.ts`
скажи владельцу, что трогаешь их.

Гочи: `python3` здесь — заглушка Store, использовать `python`; `cross-env` в bash нет —
`NODE_ENV=… npx mochapack`; посевная колода сдвигается с ростом каталога — сажать карту через
`seatResolution`; heredoc в Bash обрезается около 6 КБ.

В отчёте: форма маркера и модели действия; как обобщён композер и что стало с партийными действиями;
что обобщалось в сцене продажи; тайминги тактов; пять кадров; новые ключи i18n.

## 9. Нельзя

сюиты. Пуш и красные коммиты.
