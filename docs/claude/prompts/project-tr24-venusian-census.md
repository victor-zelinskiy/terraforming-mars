**Оценивается одно: шаг Венеры читается как ПРИЧИНА, data — как его СЛЕДСТВИЕ.** До нажатия игрок видит, что сработает
перепись — своя или чужая — и сколько она получит. После: маркер шкалы Венеры доезжает до нового деления, и только ПОТОМ из
него выходят жетоны data и садятся туда, где их ждут; счётчик не меняется раньше своего жетона. Так же — когда Венеру поднял
соперник, бот или мировой ход резолюции.

Действие карты — общее с TR15 и уже готово (`censusAction.ts`: «+1 data» ИЛИ «3 data → делегат на резолюцию», staged action
vote в «Действиях карт»). **Его не трогать и не переписывать** — только вызвать.

1. **Требование** — `requirements: {party: PartyName.UNITY}` (класс TR15; плашка «Союза» есть — TR22 / TR23). Проверяется

2. **Триггер** — каждый ПОДЪЁМ шкалы Венеры: кем угодно и чем угодно — владелец, соперник, MarsBot, торговля с Redux-Венерой

9. Журнал: одна строка-эффект владельца под подъёмом («Венерианская перепись: +2 data · Венера +1 шаг»), у чужого подъёма —

### A3 · Прогноз реакции на шаг шкалы (класс, не код карты)
- `grantOfEffect` (`effectForecast.ts:212–240`): для шкалы `steps` = **сделанные шаги** — `(resulting − current) /
  шаг шкалы` (шаг шкалы — тот же `GLOBAL_META`, вынести в общий экспорт, не копировать); `current === resulting` — гранта нет
  (уже так).
- `FORECAST_HOOK_PAIRS` (`:916–922`) += `{live: 'onGlobalParameterRaised', forecast: 'grantForecast'}` и `{live:
  'onGlobalParameterIncrease', forecast: 'grantForecast'}` — двойник называется так же, как у прочих грантов (грант `global` уже
  член `EffectForecastGrant`, `EffectForecastContext.ts:79`).
- Проход реакций на `global`-грант: реакторы `onGlobalParameterRaised` — у КАЖДОГО места, по `tableau` (корпорации
  включены); реакторы `onGlobalParameterIncrease` — только у действующего места. Получатель факта — владелец реактора
  (`forecast.recipientOf`), порядок — порядок живого диспетчера. Реактор без двойника — честный `unknown`, как везде.
- Гард `effectForecastCoverage` после расширения пар перечислит в скоупе: VenusianCensus, Aphrodite (решение №4), **Homeostasis
  Bureau** (promo — +3 M€ за шаг температуры: ворклист закрыть двойником, не строкой `ALLOWED`). Venus Contract (`prelude2`)
  вне скоупа — не трогать.

  реакция на шаг шкалы «не достигнута» (урок TR18).

## 3. Блок C · ПОСЛЕ — «ШАГ ШКАЛЫ ПЛАТИТ»

### C0 · Грамматика
- Причина раньше следствия: жетон рождается у маркера шкалы ПОСЛЕ того, как маркер доехал до деления, которое заплатило
  (`after` записи). Маркер — текущий курсор шкалы на поле (`AnimatedScaleMarker`, `.scale-marker--venus`; дать ему
  структурный хук `data-scale-marker="venus"`, если его нет).
- Одна data — один жетон; Aphrodite — монеты M€ тем же языком. Реагирует только тронутое: маркер не мигает лишний раз, соседние
  ячейки спутника стоят.
- Числа — Resource Transfer Framework (`runResourceTransfers`, `transferWaveDelayMs`); новой хореографии нет.

### C1 · Последовательность
| Такт | Что происходит |
| --- | --- |
| **ШКАЛА** | существующий глайд маркера до нового деления (если доска закрыта — park и слив, как сегодня) |
| **ЖЕТОНЫ** | с края маркера по одной записи за раз (порядок кольца), N жетонов data — в ячейку data спутника «ДОП. РЕСУРСЫ» (`auxDataCellRect`, `cityDataPayoutBeat.ts:166–168`) для своей карты; в чип владельца строки статуса (`remoteOriginPoint`, `consoleRemotePlacement.ts:1008`) для чужой; монеты Aphrodite — в строку M€ рельсы / чип владельца |
| **КАСАНИЕ** | счётчик ячейки тикает НА КАСАНИИ своего жетона, никогда раньше |
| **ДАЛЬШЕ** | только после последнего касания — разпаркованная партия шкалы (крышка карты 8 % с того же маркера) и следующие такты |
- **Холды**: при применении ответа (свой — `gameTransport.seedRewardHolds`; опрос / WS — `App.update`, ТОТ ЖЕ синхронный блок)
  запись кольца заявляется один раз по `seq` (образец `tileMoveRecords`) и сеет держатель панели (`beginPanelRewardHold` —
  величина из записи, не пересчёт); сцена отпускает только СВОИ холды (`releasePanelRewardHold`), посадкой или честным
  деградом. Именованный холд `'scale-step-reward'` (реактивный, `expire` + `diagnose`) — только для ленты уведомлений:
  вопросы игрока он не держит (решение №7).
- **Сопряжение с park** (`boardBeatPark.ts`): доска закрыта (подъём из «Карт в руке», из стандартного проекта, торговлей) —
  жетоны становятся членом слива: settle → значения отпущены, маркер доехал → **жетоны** → партия 8 % распаркована. Окно
  такта шкалы растягивается ожиданием посадки волны (её собственный сигнал), не числом. Доска видна — жетоны ждут прибытия
  маркера: его WAAPI-анимация (`AnimatedScaleMarker.vue:707–733`) публикует «доехал» в модуль; таймер вместо сигнала —
  запрещён. Ожидания между тактами — на часах GSAP (`gsap.delayedCall`).
- **Заседание** (Gas Export, шаг победителя Венерой): мировой такт планеты (`parliamentWorldBeat`) играет маркер; волна
  жетонов — его «дело на доске» (такт не возобновляет стек, пока волна в воздухе). Если проводка выходит за рамки — счётчик
  тикает честно в конце такта, гэп назван.
- **Бот** (подъём MarsBot): сцена играет, когда доска видима, в темпе хода бота; обзор хода бота и уведомление называют
  реакцию.
- **Reduced motion / fx-lite**: полётов нет, счётчик тикает с отпусканием значений шкалы. Нечего мерить (нет маркера / ячейки) —
  `data-scale-reward-degraded` на корне слоя (e2e требует отсутствия), холды отпускаются сразу.
- Слой — шелл-уровня (рядом с прочими полётными слоями), никогда внутри телепортируемой поверхности.

**4 коммита**, каждый зелёный: (1) сервер — хук `onGlobalParameterRaised` + диспетчер, Aphrodite на нём, класс прогноза (шаги,

`npm run build:test`, `npm run make:cards`, `npm run make:json`; перед визуальной проверкой `npm run make:css` +
`npm run build:server`. **Не пушить.** Документ карты `docs/TURMOIL_REDUX_VENUSIAN_CENSUS.md` — контракт «шаг шкалы платит
карте» (хук, диспетчер в позиции Aphrodite, прогноз, кольцо, сцена, сопряжение с park) и что следующая карта с триггером «шаг
