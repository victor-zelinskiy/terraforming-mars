**Код — RX22.** RX21 уже занят: второй агент прямо сейчас делает Migration Funding. Перед стартом

- **Партия:** Industrialists (в RU — **Индустриалисты**). `compatibility` не объявлять.
- **Печатное правило:** *«Each player increases their titanium production 1 step. Also increase your
  steel production 1 step for each point of influence you have.»*
- **Части победителя нет**, потолка нет, мирового шага нет, пассива нет, счётного члена нет.
- **Задание председателя:** **+1 производства стали** —
  `{goal: {kind: 'production', resource: Resource.STEEL}, count: 1}`. Ровно то же объявление, что у
  RX15 Industrialist Budget (значок — коричневый квадрат с инструментами в рамке производства = СТАЛЬ,
  не метка строительства; см. таблицу значков §4.1.1).

### Чтения

1. **Две части, обе каждому участнику**, в печатном порядке: сначала титан, потом сталь.
   - титан: плоская часть — `{unit: {kind:'production', resource: TITANIUM}, base: 1, perInfluence: 0,
     recipient: 'each'}`;
   - сталь: `{unit: {kind:'production', resource: STEEL}, perInfluence: 1, recipient: 'each'}`.
2. **ВЛИЯНИЕ 0 НЕ ОБНУЛЯЕТ КАРТУ** — это прямая ловушка, на которой уже спотыкались (закон записан в
   шапке `ClimateResearch.ts`): при нулевом влиянии стальная часть НАЗЫВАЕТ СЕБЯ пропущенной, а
   **титановая всё равно выдаётся**. Читать «влияние 0 → ничего» здесь нельзя.
3. **Это ПРОИЗВОДСТВО**, не запас: через `production.add`, со всеми его событиями, записью рекордера и
   **реакциями правящей партии** — если партия печатает ответ на рост производства, он срабатывает сам
   через штатный хук, и второй раз в карте его писать не надо (закон из RX05).
4. **Горизонт:** заседание идёт ПОСЛЕ фазы производства, значит оба шага впервые заплатят в СЛЕДУЮЩЕМ
   поколении. Чтение обязано назвать горизонт формулировкой RX15 — не изобретай вторую.
5. **Бот** в Парламенте не участвует: производство не растёт, влияние не считается.

## 2. Блок A · сервер

Файл карты по чеклисту: `id` (`RDX_INDUSTRIALISTS_MINING_INCENTIVES`), `code` RX22, партия, `copies`,
`renderData` (как на скане: `[сталь произв.] / [влияние]` и `[титан произв.]`), `text`, `scaled` с двумя
эффектами, два `immediateStep` в печатном порядке, задание. Записи исхода — штатные `production`.

**Ничего нового в общие модули не добавляется.** Если по ходу кажется, что нужен новый вид счёта, новый
член `InfluenceYieldUnit` или правка `resolutionCounts.ts` — **остановись**: этой карте они не нужны, а
эти файлы прямо сейчас правит второй агент.

## 3. Блок B · чтения и показ

- формула: «титан +1 · сталь +1 × влияние 3 = +3» — две строки, каждая со своим ресурсом;
- пропуск стальной части при влиянии 0 — своей формулировкой, рядом с честно выданным титаном;
- горизонт производства назван (§1.4);
- показ — штатные шаги производства (путь RX05/RX15), дельта-чипы по ресурсам. Ничего нового не строить.

## 4. Бюджет проверки

**Новых механик нет → НОВЫЙ e2e НЕ ДОБАВЛЯТЬ.** Это правило владельца: тратить прогон только на новую
механику. Достаточно юнитов.

- **серверные юниты:** титан +1 каждому участнику; сталь = влияние (0 / 1 / 3); при влиянии 0 титан
  выдан, сталь пропущена с причиной; порядок шагов = печатный (проверяется по записям); реакция правящей
  партии на рост производства срабатывает один раз через штатный хук; бот не тронут; **паритет
  горизонта**: производство впервые платит в следующем поколении (спек на два поколения);
- **клиентские юниты:** две строки формулы; пропуск стали читается штатно; горизонт назван;
- `npm run lint`, `npm run build:test`, `npm run make:cards`;
- **старые сюиты не гоняй.**

Глазами — один кадр: панель голосования с обеими строками.

## 5. ПАРАЛЛЕЛЬНАЯ РАБОТА — читать до первого коммита

Второй агент делает **RX21 Migration Funding** (Марс вперёд) в том же дереве. Его зона — счётные члены
по полю и всё вокруг стопок городов. Твоя карта туда не лезет, и это хорошо: пересечение сводится к
нескольким общим файлам.

**Общие файлы — трогай минимально и коммить сразу:**

- `ResolutionCatalog.ts` — обе карты добавляют свою строку. Добавь **только свою**, не переставляй
  соседние, не «причёсывай» форматирование рядом.
- `src/locales/<lang>/parliament.json` — **грепни ключ перед добавлением** (сборка падает на дубликате)
  и добавляй только свои строки.
- `docs/TURMOIL_REDUX_SPEC.md` — правь **только строку своей карты**.
- `docs/claude/parliament-sitting-progress.md` — допиши свой абзац в конец, чужие не редактируй.
- `src/genfiles/parliament.json` — **генерируемый**: не правь руками, перегенерируй `make:cards` и
  коммить как есть; при конфликте — перегенерируй заново, а не разрешай построчно.

**Не трогай вообще:** `src/common/parliament/resolutionCounts.ts`,
`src/server/parliament/resolutions/ResolutionCounts.ts`, `MarsBoard`/`cityStack`/`Space` и всё про
стопки, `influenceYieldModel.ts` в части счётных членов, файлы карт чужой партии.

**Если понадобилось изменить общий модуль** — сначала скажи владельцу, не правь молча: параллельная
правка одного модуля двумя агентами даёт конфликт, который потом чинится вслепую.

Коммить **мелко и часто** (A сервер · B чтения · C лицо/локаль + юниты), зелёными по юнитам. **Не пушить.**
