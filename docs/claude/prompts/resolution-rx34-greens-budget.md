## 2. ЛОВУШКА · «to any card» — это ОДНА карта, а не раскладка

Соблазн взять образцом RX06 Cloud Development велик (там тоже «ресурсы на карты»), и он приведёт к
неверной механике. **`spread` НЕ объявлять.**

- **RX06** — «each resource can go on a different card»: раскладка по нескольким держателям, общий
  `AddResourcesToCards`, маркер `cardResourceDistributionPrompt`, шаг `distribute`. **Не наш случай.**
- **Наш случай — RX01 Aquifer Contest**: «add N animals to any card» — весь объём ложится на ОДНУ
  карту, выбранную игроком, через `AddResourcesToCard` (единственное число). Формулировка на нашей
  карте та же, дважды: 2 животных на одну карту, 3 микроба на одну карту.
- Две порции — **два независимых выбора**: карта-получатель животных и карта-получатель микробов
  выбираются отдельно (это разные виды ресурса, держатели у них почти всегда разные).

## 3. Блок A · сервер: четыре объявления и ни одной новой механики

```
LEVY:        {resource: MEGACREDITS, amount: 10, recipient: 'each'}
MEGACREDITS: {unit: {kind:'stock', resource: MEGACREDITS}, perInfluence: 1,
              count: {id: <новый>, per: 1}, recipient: 'each'}
ANIMALS:     {unit: {kind:'cardResource', resources: [ANIMAL]},  base: 2, perInfluence: 0, recipient: 'each'}
MICROBES:    {unit: {kind:'cardResource', resources: [MICROBE]}, base: 3, perInfluence: 0, recipient: 'each'}
```

- **Плата — объявлением**: `levy` + общий `levyStep(...)` ПЕРВЫМ в `immediateSteps`. Частичная уплата
  при нехватке, `levyPaid` / `levyShort`, `from: {resolution}` — всё делает семейный шаг. **Если
  пришлось тронуть `resolutionLevy.ts` — значит RX15 сделал его недостаточно общим; скажи в отчёте.**
- **Новый счёт `plantMicrobeAnimalTags`** — вид TAGS над тремя метками, по образцу
  `earthVenusJovianTags` (три аддитивные строки: список, `resolutionCountKind`, ветка предиката).
  Карта, печатающая две из трёх меток, стоит 2 — как у образца, с разбивкой по меткам.
  Режим счёта берётся семейством: `RESOLUTION_TAG_COUNTING_MODE = 'raw'` (печатные метки; дикая метка
  не считается; метки разыгранного события лицом вниз не считаются).
- **Раздачи — фиксированные**: влияние в них НЕ участвует (`base`, `perInfluence: 0` — приём RX27).
  Шаг пишется по образцу `AquiferContest.ANIMALS_STEP` целиком: `ctx.state` запоминает причитающееся,
  `getResourceCards(<вид>)` проверяет держателей, `AddResourcesToCard(..., {count, autoSelect: false,
  title, cause: SOURCE, from: {resolution}})`, отчёт в `.andThen`. **`autoSelect: false` обязателен**
  — единственный кандидат всё равно ПОКАЗЫВАЕТСЯ (инвариант 3).
- **ЧЕТЫРЕ РАЗНЫХ НУЛЯ, и каждый называет СЕБЯ** (инвариант 4, «один шаг — одна запись»):
  не хватило на плату → частичная с «было должно»; нет живых меток и влияния 0 → «M€ нет»;
  **нет карты, принимающей животных** → «2 животных пропадают» (именно с величиной, как у RX01);
  нет карты, принимающей микробов → то же про 3 микроба. Общего «ничего не досталось» быть не должно.
- Бот в Парламенте не участвует ни в одной из четырёх частей.

### Что здесь действительно ново — ДВА ПРОМПТА ПОДРЯД у одного места

До сих пор место отвечало на один вопрос за принятие. Здесь их два (животные, затем микробы).
Проверь и закрепи спеком: второй промпт приходит ПОСЛЕ ответа на первый; **перезагрузка между ними**
не теряет второй и не повторяет первый (ключи шагов + `ctx.state`); заседание не идёт к следующему
месту, пока оба не закрыты; порядок ровно печатный.

## 4. Блок B · чтения

- **Нетто-линия платы** (RX15): «−10 → +N = …» одной строкой.
- **Разбор счёта по трём меткам** — с разбивкой по каждой (образец RX29): «растения 2 · микробы 1 ·
  животные 1 = 4», списком карт.
- **Раздачи — отдельными строками**, не складываются ни с деньгами, ни друг с другом: «2 животных на
  карту», «3 микроба на карту». Влияние в них не участвует, и читание не должно намекать, что
  участвует.
- **Чужие исходы**: соседняя колонка считает свои метки и свои карты-получатели.
- Стенд «Полигон»: 0 живых меток · карта с двумя из трёх меток · нет держателя животных · нет
  держателя микробов · нехватка M€ на плату · влияние 0 / 3.

## 5. Блок C · показ

Всё существует, ничего не строить: отток платы (RX15) → волна M€ в рельсу → прилёт животных на
выбранную карту → прилёт микробов на выбранную карту. **Четыре такта подряд — главный риск карты:**

## 6. Блок D · лицо, локаль

Лицо по скану: верхний ряд `−10 [M€]`, `2 [животное]`, `3 [микроб]`; ниже
`1 [M€] / [метка растения] + [метка микроба] + [метка животного] + [влияние]`. Значки уже разобраны
аудитом (спек §4.1.1: зелёный КВАДРАТ с лапой = животное-ресурс на карту, круг с листом = метка).
Сноска задания — круг с листом ×2. Тексты языком карт проектов (глоссарий § 8; **микроб → бактерия**
по глоссарию — сверь, как это слово пишут соседние карты). Ключи i18n грепнуть по всем
`src/locales/<lang>/*.json`.

## 7. Бюджет проверки

Новых механик нет, но ново сочетание «два вопроса одному месту».

- **серверные юниты:** плата 10 при 12 M€ → осталось 2, при 4 M€ → частичная с «было должно», выплата
  всё равно идёт; выплата = (растения + микробы + животные) + влияние, карта с двумя метками даёт 2;
  дикая метка и метка разыгранного события не считаются; 2 животных ложатся на ВЫБРАННУЮ карту,
  3 микроба — на другую выбранную; нет держателя → названный пропуск с величиной (по одному на вид);
  влияние на раздачи не влияет (влияние 0 → всё равно 2 и 3); порядок шагов = печатный;
  **перезагрузка между двумя выборами** не теряет и не дублирует; бот не тронут; **RX15, RX27 и RX29
  не поехали**;
- **клиентские юниты:** нетто-линия; разбор счёта с разбивкой по трём меткам; раздачи отдельными
  строками; чужая колонка;
- **РОВНО ОДИН новый e2e:** RX34 принята → плата и выплата → игроку приходит выбор карты для 2
  животных → выбирает → **следом** выбор карты для 3 микробов → выбирает → на обеих картах видны
  ресурсы, лента дала четыре строки;
- **старые сюиты не гоняй**, фикстуру правь точечно (`FIXTURES=… npm run e2e:fixtures`).

Глазами, один профиль, **три кадра**: панель голосования (нетто + разбор счёта + две строки раздач);
второй выбор карты (микробы) сразу после первого; исход после четырёх тактов.
