## 2. ЧТЕНИЕ ПРАВИЛА (каждый пункт — спеком `tests/parliament/SponsoredProjects.spec.ts`)

1. **Печатный порядок = исполняемый:** добор → ресурсы, для каждого места по очереди (драйвер ходит по местам). Добор не
   меняет набора карт с ресурсами (карты приходят в руку, не на стол) — порядок не меняет числа, но записи и показ идут
   печатно.
2. **Добор = влияние** — интейком, как RX24: 0 влияния → названный пропуск «нет влияния»; колода пуста → «колода пуста»;
   короткая колода — сколько было, сказано; перезагрузка внутри «взять» ничего не тянет второй раз.
3. **«Each of your cards that already has a resource»** = карты табло места с `resourceType` и `resourceCount ≥ 1` в
   момент шага (`getCardsWithResources()` — одна функция и для счёта, и для выплаты, и для всех чтений). Корпорация с
   ресурсами — тоже карта места (Arklight, Celestic, StormCraft, Recyclon…). Карта-держатель с 0 ресурсов — НЕТ («already
   has»). Чужие карты — нет.
4. **Каждой ровно 1 ресурс СВОЕГО вида** (вид единицы следует из карты — приём RX18): 1 животное на Fish, 1 аэростат на
   Dirigibles, 1 data на Supercomputer. Никакого выбора — ни вида, ни карты: «each» — каждая; вопроса нет, и промпта нет
   (инвариант 3 не применим: нет цели, которую выбирают).
5. **Через `addResourceTo` — со всеми следствиями движка:** строка журнала с источником-законом (`from: {resolution: ID}`),
   событие `cardResource` под областью закона, ПО карт по их правилам (Birds 1 → 2, Search for Life «уже 3 ПО» и т. п.),
   реакторы стола на добавленный ресурс (`onResourceAdded` — если в скоупе есть карта, отвечающая на ресурс на ЛЮБОЙ своей
   карте, — она отвечает, закреплено спеком на реальной).
6. **Ноль — назван своей причиной:** нет ни одной карты с ресурсом → «No card of yours has a resource yet» (`skipped`),
   отдельно от нуля добора. Два шага — две записи, две причины.
7. **Задание «4 data»:** data от закона НЕ засчитывается (корень `political-phase` — `QuestTracker.eligible`; RX35
   закрепил это для data принятия); засчитывается data своих действий (Supercomputer, Pluto Redux, …). Бот ведёт задание
   областью хранения data (`botQuestPath`, путь `table`).
8. **Бот — нет** (Р3, рекомендация): добор и ресурсы — ВЫПЛАТЫ закона, а не деяние на поле или треке; у бота нет руки и нет
   карт табло (его «ресурс карты» — область хранения), перевод был бы выдуманным — ровно то, что D3 исключает, и D11 это
   не меняет («тайл или шаг Карьеры — да; выплата — нет»). Спек: бот ничего не тянет и ничего не получает в области хранения.
9. **Однажды за принятие:** ключи идемпотентности; перезагрузка между добором и ресурсами — ресурсы ровно раз; набор
   «карт с ресурсом» фиксируется в `ctx.state` в первый проход шага (список имён) — повторный проход не пересчитывает.

## 4. Блок A · сервер

### 4.1 Объявление

```ts
scaled: [
  {id: 'draw', unit: {kind: 'cards'}, perInfluence: 1, recipient: 'each'},                                   // RX24 один в один
  {id: 'resources', unit: {kind: 'cardResource', resources: 'own-kind', onto: 'each-counted'},               // НОВАЯ форма единицы
   base: 0, perInfluence: 0, count: {id: 'cardsWithResources', per: 1}, recipient: 'each'},
],
immediateSteps: [DRAW_STEP, eachCountedCardStep(ID, RESOURCES)],
quest: {goal: {kind: 'cardResource', resource: CardResource.DATA}, count: 4},
```

- **Счёт `cardsWithResources`** — вид CARDS над табло (форма `blueCards`): одна карта = одна единица, предикат —
  `getCardsWithResources()` (никогда своя копия: при расхождении счёт пообещает одно, а шаг заплатит другое). Модель счёта
  несёт список карт с ВИДОМ и ЧИСЛОМ ресурса каждой (`countedUnits` / новое поле `byCard: [{card, resource, count}]` —
  выбрать по форме модели), чтобы чтения печатали «Fish 2 → 3».
- **Новая форма единицы `onto: 'each-counted'`** в `InfluenceYieldUnit.cardResource` (`influenceScaling.ts`): «по `per`
  на КАЖДУЮ посчитанную карту, вида этой карты» — рядом с «на одну карту» (без флага) и «раскладкой» (`spread`). `resources:
  'own-kind'` — вид не объявлен, его даёт карта (если тип `resources` — список видов, ввести честное значение «любой»,
  не перечислять все виды игры). Все читатели формы единицы (лицо, панель голосования, «Полигон», итоги, адрес) получают
  исчерпывающую ветку — гард `ResolutionContract` назовёт пропущенные.
- **Общий шаг `eachCountedCardStep(id, effect)`** (`resolutions/ResolutionEachCard.ts`): мутирует, никогда не спрашивает;
  фиксирует список в `ctx.state` первым проходом; на каждую карту `addResourceTo(card, {qty: per, log: false, from:
  {resolution}})` + ОДНА строка журнала «${0} adds 1 resource to each of ${1} card(s) with ${2}» (журнал по карте — от
  `addResourceTo` с `log: true`, если он даёт по строке на карту лучше — выбрать то, что читается в ленте, и закрепить);
  запись `{kind: 'cardResource', effect, amount, cards: [{card, amount, resource}], resource?}` (одна `resource` — только при
  едином виде, как RX18); ноль — `skipped` с причиной §2.6.
- **Адрес** (`rewardAddress.ts`): у `cardResource` сегодня стадия `choice` (выплата спрашивает); для `onto: 'each-counted'`
  стадия — `reward` (вопроса нет) — либо вид адреса читает форму единицы, либо новый вид `cardResourceEach` со своей
  строкой. Выбрать то, что не плодит ветки у читателей; спек адреса.
- **Бот** — ни шага, ни аспекта (Р3); спек.

## 5. Блок B · показ — «КВИТАНЦИЯ СТОЛА»: выплата без вопроса садится на настоящие карты

### 5.1 Что нужно и почему общим механизмом

Сегодня выплата закона на карту видна только через ВОПРОС (капсулы кандидатов пикера). Выплата без вопроса —
новый класс, и он вернётся (у классического события — тот же; у будущих законов «каждой карте …» — тоже). Построить
ОДИН хост «квитанция стола» и посадить на него показ — **пятый хост директора приёма TR53** (`cardReceiveDirector`), не
свой полёт:

- **Где:** в стадии НАГРАДА заседания, в зоне тела (встроенный шаг-ПОКАЗ, как экран колоний у RX29 — «шаг без вопроса»),
  строкой ЛИЦ карт-получателей места зрителя (плотность альбома — TR65 / `console-hand-album`; при 6+ картах — та же строка
  тесней, без прокрутки — цель 1; проверить на фикстуре с 8 картами).
- **Фраза:** импульс по печатной графике лица закона к иконке «?» → из неё рождается жетон на КАЖДУЮ карту по очереди
  (общая лесенка волны `runResourceTransfers`) → жетон носит вид СВОЕЙ карты (животное, аэростат, data — RX18: «chip lands
  wearing its own card's kind») → касание: капсула ресурса карты тикает «2 → 3», ПО карты, если изменились, — «1 → 2» →
  короткое чтение → квитанция уходит, заседание идёт дальше. Обе стороны полёта видимы (память
  `polish-quality-no-regressions`); жетон рождается в rect иконки, садится в rect капсулы.
- **Детектор:** по записи ФАЗЫ (`cardResource` с `cards[]` и формой `each-counted` у места зрителя), никогда по
  стоявшему промпту — у этой выплаты его нет; перезагрузка (нет «до» с меньшим числом записей) ничего не повторяет.
- **Чужие места:** у зрителя — строка ожидания и итог их колонки («+5 ресурсов на 5 карт»); их карты не показываются
  (ресурс на чужих картах виден в «Разыграно»).
- **Холды:** капсулы и ПО карт держатся до касания; рельс не трогается (ресурс карты не на рельсе). Бит регистрирует
  holds, отпуск — собственный сигнал завершения (инвариант 6), не таймер.

### 5.2 Чтения

- **Панель голосования / осмотр:** две строки, не складываются: «[карта] +N — по влиянию» (добор) и «+1 [ресурс своего
  вида] на каждую карту с ресурсом: 4 карты» со списком «Fish 2 → 3 · Dirigibles 1 → 2 · Supercomputer 3 → 4 · Arklight 4 →
  5» и честным итогом ПО («ПО +2», `targetVictoryPoints` — та же функция, что у пикеров); 0 карт — «ни на одной карте ещё
  нет ресурса» (честный ноль, не «без награды»).
- **Чужие исходы:** соседняя колонка считает свои карты.
- **Итоги заседания:** добор · ресурсы (число и число карт).

## 10. Режим работы

Экономный, 3 коммита (A сервер: счёт + форма единицы + шаг + адрес + гарды · B клиент: квитанция стола + чтения + e2e ·
C доки/локаль), каждый зелёный; `npm run lint`, `npm run build:test`, `make:cards`, `make:json` (дубль ключа с событием
бросит — это проверка, не помеха), `make:css`. **Не пушить.** Гочи прошлых прогонов: сборка клиента под мусорными
`tmp/**/*.spec.ts` — `SKIP_TS_CHECK=1` (память `build-client-finished-but-not-emitted`); ворота заседания в e2e — только
`answerGateOnScreen`; `sittingStep` истинен уже на странице ПРИНЯТИЯ — ждать по `sittingStage`; раскадровка 4K — только
`TM_E2E_GPU=1`; `python3` — заглушка Store; heredoc > ~6 КБ обрезается, RTK ест `\\` — патчи через Write; `npx vue-tsc
--noEmit` напрямую падает по heap — `npm run lint:client`; `FixtureName` в `consoleStart.ts` — объединение; `parliamentFixture`
оставляет корпорациям ожидающее первое действие — чистить `pendingInitialActions` (PL-715); фикстура `done` открывается на
p2; e2e против своего HEAD при чужом WIP — worktree + junction `node_modules`; полный `test:client` под нагрузкой —
случайные таймауты, изоляцией; стат коммита — `git show --stat HEAD`.

## 11. В отчёте

Подтверждение, что добор взят интейком без правок; как легла форма единицы `each-counted` (и сколько читателей получили
ветку); как квитанция стола встала пятым хостом директора приёма (и закрыла ли PL-426); как показ определяет выплату без
промпта; Р2–Р4 — что принято, что изменено; ключ имени — переиспользован из событий; шесть кадров 4K с вердиктами; находки полировки
сверх §9.

## 12. Нельзя

Спрашивать игрока, куда класть (вопроса нет). Своя копия «карт с ресурсом» рядом с `getCardsWithResources`. Ресурс не
того вида, что у карты. Держателю с 0 ресурсов — ресурс. Писать полёт квитанции мимо директора приёма TR53. Детектировать
квитанцию по стоящему промпту или по тексту. Давать боту добор или ресурсы. Дублировать ключ имени события. Гонять старые
сюиты целиком. Пуш и красные коммиты.
