## 2. ЛОВУШКА · «метка города» — это МЕТКА, а не город на доске

В каталоге счётов уже есть **ТРИ городских счёта, и все три по ДОСКЕ**: `spaceCities` (города вне
Марса, RX08), `marsCities` (клетки-назначения, RX20), `marsCityTiers` (ярусы стопок, RX21). **Ни один
из них не годится**, и схватить не тот — самая дешёвая ошибка в этой карте: она не упадёт, она просто
выдаст неверное число.

Карта считает **метки города в ТАБЛО** — близнец `scienceTags` (RX18) и `powerTags` (RX04).

- **Новый id `cityTags`**, вид `{kind: 'tags', tags: [Tag.CITY]}` — три аддитивных строки в
  `src/common/parliament/resolutionCounts.ts` по образцу `scienceTags`, и ни строчкой больше.
- Правила счёта берёт семейство, своих не изобретай: `RESOLUTION_TAG_COUNTING_MODE = 'raw'` —
  **печатные** метки; **дикая метка не считается**; **метки разыгранных событий лежат лицом вниз** и
  не считаются (`Tags.eventTagsInPlay`, кроме Odyssey); карта с двумя метками города даёт 2.
- **Тайлы не считаются вообще.** Закрепи спеком отдельным случаем: у игрока пять городов на Марсе и
  ни одной карты с меткой города → **ноль карт**. Этот спек существует не ради арифметики, а чтобы
  следующий читатель не «починил» счёт на городскую доску.
- Корпорация с меткой города (Tharsis Republic) — обычный носитель метки, считается как любая карта
  в табло.

## 3. Блок A · сервер: две объявленные половины

Кода механики почти нет — если пишется много, ты строишь копию вместо объявления.

```
DRAW:        {unit: {kind: 'cards'}, perInfluence: 0, count: {id: 'cityTags', per: 1}, recipient: 'each'}
MEGACREDITS: {unit: {kind: 'stock', resource: MEGACREDITS}, perInfluence: 2, recipient: 'each'}
```

- **Счётный добор — новое сочетание.** `scaledAmount` про unit ничего не знает, так что арифметика
  работает даром; цена этого сочетания не на сервере, а в ЧТЕНИЯХ (§4) — проверь их, не поверив, что
  «раз считается, то и показывается».
- **Шаг добора — по образцу `ScientistsBudget.DRAW_STEP` целиком**: `ExternalDrawIntake.open(...)` с
  источником `{kind:'resolution', resolution, effect}`, `ctx.state[INTAKE_KEY]` и **повторный вход
  после перезагрузки внутри взятия** (карты уже ушли из колоды — второй раз не добирать),
  `takePromptFor`, пустая колода → названный недобор, `report({kind:'cards', amount, drawn, intake})`.
  Обычный `drawCard` здесь **запрещён**: это заседание, не свой ход.
- **Шаг M€ — по образцу `MEGACREDITS_STEP`**: `stock.add(..., {log: false, from: {resolution}})` и одна
  журнальная строка с полным расчётом.
- **ДВА РАЗНЫХ НУЛЯ, и каждый называет СЕБЯ** (инвариант 4, контракт «один шаг — одна запись»):
  нет меток города → «нет меток города — карт нет»; влияние 0 → «нет влияния — M€ нет». Общего
  «ничего не досталось» быть не должно: половины независимы, и игрок с влиянием 0 и тремя метками
  города обязан получить три карты.
- **Порядок = печатный: сначала ДОБОР, потом M€** (правило напечатано именно так; лицо рисует иначе —
  лицо это пиктограмма, а не порядок). Шаг с промптом не обязан быть последним (RX24/RX28 нести
  промпт в середине умеют). Если драйвер всё же упрётся — **не переставляй молча**, обоснуй в отчёте.
- Бот в Парламенте не участвует: ни карт, ни M€.

## 4. Блок B · чтения — вся новизна карты здесь

Сочетания «`cards` + счёт» в чтениях ещё не было: `cards` встречался плоским (RX27), уровневым (RX16)
и последовательным (RX05). Пройди по всем поверхностям и убедись, что рейт читается **как рейт**:

- **Панель голосования и осмотр**: «1 карта за каждую метку города» + «2 M€ за влияние» — две строки,
  не одна сумма (величины разной природы, складывать их нечем).
- **Разбор счёта** — как у `scienceTags`: список карт с вкладом каждой (`ResolutionCountModel.units`),
  чтобы «3» всегда объяснялось картами, а не висело числом.
- **Исход**: доставленное честно — сколько причиталось и сколько реально пришло (`drawn`), в духе
  «+2 / 3» при исчерпанной колоде. У RX27 ровно это место один раз уже теряло `drawn` — проверь.
- **Чужие исходы** (сданы 2026-09-25): колонка соседа считает ЕГО метки и ЕГО влияние. Прогони это
  спеком — счётный член у каждого места свой, и подстановка своего счёта в чужую колонку не упадёт,
  а тихо соврёт.
- **Стенд «Полигон»**: своя строка, синтетические табло с 0 / 1 / 3 метками города (в том числе карта
  с двумя метками) и влиянием 0 / 3.

## 5. Блок C · показ

Ничего нового не строить. Добор с раскрытием (RX16/RX27) → волна M€ в рельсу (RX15/RX27). Два такта
**по очереди**, не внахлёст; лента даёт по строке на каждый. Проверь глазами, что при нуле карт
(ни одной метки города) такт добора не играет пустоту, а пропуск назван.

## 6. Блок D · лицо, локаль

Лицо **как на скане**: слева `2 [M€] / [влияние]`, справа `[карта] / [метка города]` — рисуй
порядком скана, а не порядком шагов. Сноска задания — тот же серый круг с силуэтом города.
Тексты — языком карт проектов (глоссарий § 8): `effect` называет обе половины в печатном порядке.
Ключи i18n грепнуть по всем `src/locales/<lang>/*.json` перед добавлением (ключ задания «Play 1 city
tag» — проверь, не завёл ли его уже кто-то из соседних карт).

## 7. Бюджет проверки

Своих механик нет → **НОВЫЙ e2e НЕ ДОБАВЛЯТЬ.** Юнитов и кадров достаточно.

- **серверные юниты:** 0 меток → карт нет, причина названа, M€ при этом выплачены; 3 метки → 3 карты
  (в том числе карта с двумя метками = 2); **пять городов на доске и ноль меток → ноль карт** (§2);
  дикая метка не считается; метка разыгранного события не считается; M€ = 2 × влияние (влияние 0 →
  названный пропуск, карты при этом выданы); пустая колода → недобор назван; перезагрузка внутри
  взятия не добирает второй раз; порядок шагов = печатный; бот не тронут; **RX27 не поехал**
  (добор и счёт дают те же числа);
- **клиентские юниты:** рейт «1 карта / метка города» на панели и в осмотре; разбор счёта списком
  карт; исход печатает `drawn`; чужая колонка считает чужие метки; стенд;
- `npm run lint`, `npm run build:test`, `npm run make:cards`, `npm run make:css` перед визуальной
  проверкой; **старые сюиты не гоняй.**

Глазами, один профиль, **три кадра**: панель голосования с двумя строками и разбором счёта; исход
после двух тактов; стенд со строкой карты.

## 8. Режим работы

Экономный, 2–3 коммита, каждый зелёный по юнитам. **Не пушить.** Документ карты —
`docs/TURMOIL_REDUX_URBAN_RESEARCH.md` (короткий: сборка из готового + новый счёт + ловушка «метка ≠
тайл»); журнал — `docs/claude/parliament-sitting-progress.md`; спек — строка каталога (задание уже
сверено аудитом, не откати) + случай «города на доске не считаются». Чеклист автора: строка «счётный
добор — проверка, что чтения умеют рейт, а не только плоское число».

Гочи: `python3` здесь — заглушка Store, только `python` (длинные скрипты файлом, не heredoc);
`cross-env` в bash нет — `NODE_ENV=… npx mochapack`; посевная колода сдвигается с ростом каталога —
сажать карту через `seatResolution`.

В отчёте: подтверждение, что обе половины взяты объявлением (и что общие модули менять не пришлось,
кроме трёх строк счёта); что показали чтения при сочетании «карты + счёт» и что пришлось починить;
порядок шагов и почему; три кадра; новые ключи i18n.
