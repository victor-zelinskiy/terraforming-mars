## 2. ЧТЕНИЕ ПРАВИЛА (каждый пункт — спеком `tests/parliament/TaxBreaks.spec.ts`)

1. **N = разные виды ресурса на своих картах + влияние, потолок 5 на ВСЮ величину** (как RX04: потолок режет прибавку, не

   чужие карты — нет.
3. **Счёт фиксируется в первый проход шага** (`ctx.state` — приём RX18): виды и карты каждого вида; перезагрузка не
   пересчитывает.

   разбором («${0} raised M€ production ${1} from ${2}: ${3} resource type(s) + ${4} influence, max 5»); реакторы стола на рост
   производства (Manutech и т. п.) — движковые.
5. **Ноль — назван:** 0 видов и 0 влияния → «No resources on your cards and no influence» (`skipped`). Потолок — не пропуск:
   запись несёт `uncapped` рядом с `amount` (как RX04/RX08), чтение говорит «6 → 5 (макс.)».
6. **Бот — нет** (D3: производства у бота нет — положительное изменение бросает; это выплата, и D11 её не касается).
7. **Задание «2 [мех]»:** мехи своих действий (карты мехов, их действия); мехи от действия закона RX37 не считаются (Q5 —

## 4. Блок A · сервер (≈ 15 % сил)

```ts
scaled: [{id: 'megacredits', unit: {kind: 'production', resource: Resource.MEGACREDITS}, perInfluence: 1,
          count: {id: 'cardResourceTypes', per: 1}, cap: 5, recipient: 'each'}],
immediateSteps: [MEGACREDITS_STEP],
quest: {goal: {kind: 'cardResource', resource: CardResource.MECH}, count: 2},
```

- **Счёт `cardResourceTypes`** — вид `holders` с МЕРОЙ: `resolutionCountKind('cardResourceTypes')` → `{kind: 'holders',
  measure: 'types'}` (а `cardsWithResources` RX40 → `measure: 'cards'`, поведение без изменений) — прецедент RX21: одна
  выборка, две меры, объявление вида говорит, какая. Модель счёта несёт разбивку ПО ВИДАМ: `byType: [{resource, cards:
  [{card, count}]}]` (или расширение `byCard` с группировкой — выбрать по форме модели), чтобы чтение печатало виды с
  картами под каждым. Ветка предиката стенда — по той же мере. Никакой своей выборки «карт с ресурсом» — только
  `getCardsWithResources()`.
- **Шаг** — по образцу шага RX04 целиком (счёт → `ctx.state` → `scaledAmount` с потолком → `production.add` → запись
  `production` с `count`, `counted`, `countedByType`, `uncapped`). Если у RX04/RX17 шаг уже общий — взять общий; если нет и
  тело повторяется третий раз — вынести общий `productionCountStep(id, effect)` и перевести на него соседей байт-в-байт (их
  спеки зелёные без правок) — сказать в отчёте.
- **Спеки:** каждый пункт §2; 3 вида на 4 картах (Fish 2, Birds 1, Dirigibles 1, Supercomputer 3) → 3; держатель с 0 — не
  вид; корпорация с ресурсами — вид; влияние 0 / 2; потолок: 4 вида + влияние 3 → 5 (`uncapped` 7); 0 и 0 — пропуск;
  производство 10 → 15 при N 5; перезагрузка; бот — ничего; задание мехов: свой мех +1, мех от RX37 — 0; бот — задание

## 10. Режим работы

Экономный: A сервер + гарды · B чтения + e2e · C доки/локаль · по коммиту на каждую строку полировки; каждый зелёный;
`npm run lint`, `npm run build:test`, `make:cards`, `make:json`, `make:css`. **Не пушить.** Гочи прошлых прогонов (память
`turmoil-redux-sponsored-projects`, `turmoil-redux-reds-budget`): `build:client` — с `SKIP_TS_CHECK=1`, типизация —
`npm run lint:client`; новые RU-ключи в e2e — только после `make:json` + пересборки + нового снапшота; ворота заседания в
e2e — только `answerGateOnScreen`; `sittingStep` истинен уже на странице ПРИНЯТИЯ — ждать по `sittingStage`; раскадровка 4K
— только `TM_E2E_GPU=1`; свечение через `filter: drop-shadow` в консоли мертво — только `box-shadow`/transform; размеры
мелких символов в чтениях — в `em` (стрелка «6.7» RX39); новая карта в колоде сдвигает сидированную раздачу
`ParliamentPhase.spec` — сажать через `seatResolution`; RTK-хук ест `\\` и `\\'` в heredoc — патчи через Write/Edit;
`git commit -- <пути>` оставляет индекс `package.json` — `git reset -q -- package.json package-lock.json`; e2e против
своего HEAD при чужом WIP — worktree + junction `node_modules`; стат коммита — `git show --stat HEAD`.

## 11. В отчёте

Подтверждение, что выплата и потолок взяты формой RX04, а счёт — выборкой RX40 (мера `types`, сколько строк в общих
модулях); вынесен ли общий шаг производства; Р1/Р2 — что принято; **таблица полировки**: строка реестра или своя находка ·
кадр ДО · что сделано · кадр ПОСЛЕ · гард · A/B соседей; что отправлено владельцу батчем и с какой рекомендацией; новые
ключи.

## 12. Нельзя

Своя выборка «карт с ресурсом» рядом с `getCardsWithResources`. Отдельный вид счёта вместо меры у `holders`. Считать
держатель с 0 ресурсов видом (без решения владельца Р2). Потолок на итоговое производство вместо прибавки. Давать боту
производство. Дублировать ключ «max 5». Правка общего `ConsoleInfluenceYield` без A/B соседей. Полировка «на половину» —
концепция или откат (`polish-quality-no-regressions`). Гонять старые сюиты целиком. Пуш и красные коммиты.
