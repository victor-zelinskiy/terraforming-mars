### Правила чтения (каждое — закрепить спеком карты; правила КЛАССА не дублировать)
1. **Требование** — Союз; условие РОЗЫГРЫША. Причал работает и без Союза.
2. **Розыгрыш:** тайл города на СВОЕЙ клетке у трека Венеры. Это город вне Марса: без бонуса размещения и соседства; считается
   везде, где считаются космические города (`getCitiesOffMars`, Нова-Сити — 2 ПО, RX08), и не считается там, где читают
   Марс (TR15, Mayor). Триггеры «размещён город» срабатывают по своим предикатам (Immigrant City, Rover Construction, Pets).
3. **Флота карта не даёт.** С одним флотом игрок каждое поколение выбирает: колония или причал.
4. **Причал — по классу**: назначение во всех дверях торговли, плата выбранного пути, раз в поколение на карту, только
   владелец, это торговля (задание, Venus Trade Hub), торговля возможна без открытых колоний.
5. **Награда в печатном порядке:** 2 аэростата на ОДНУ карту Венеры (карта с меткой Венеры, которая держит аэростаты; оба —
   на одну: один `AddResourcesToCard` с `count: 2`, как у Стратополиса), ЗАТЕМ +1 производство M€. Порядок событий = порядок
   значков.
6. **Сама карта — всегда кандидат** (метка Венеры, держит аэростаты) → награда не может потеряться, блокера нет,
   `rewardBlockedReason` не объявляется. При ≥ 2 держателях выбирает игрок; при одном — получатель назван на стейдже с
   «n → n + 2» до нажатия. Вопроса после посадки нет ни в одном из случаев.
7. **Цель выбрана до подтверждения и едет в том же POST.** Если хвост батча запаркован (раньше спросил кто-то другой) или
   страница перезагружена посреди — живой вопрос остаётся вопросом ЭТОЙ карты (источник — карта) и отвечается внутри
   workspace колоний, не отдельной полосой.
8. **ПО — 1 за 2 аэростата НА ЭТОЙ карте** (вниз), кто бы их ни положил (Титан, Floater Technology, действие Стратополиса).
9. **Карта — держатель аэростатов для всех читателей**: Титан, позиции 3–5 Redux-Венеры («a card that can accept floater
   resources» — Аврора делает такую торговлю возможной). Траты аэростатов с неё нет.
10. **Бесплатная дверь → бесплатная награда** (действие Союза, мех TR66).
11. **Три причала** (TR06 + TR26 + TR27): три штампа, `potentialTradeCount` = min(колонии + свободные причалы, свободные флоты).
12. **Карта не действие.**
13. **Save / load:** штамп, аэростаты, тайл; клетка догружается в сохранение, сделанное до карты.
14. **MarsBot** карту не играет; человек за столом бота играет как обычно.
15. **Журнал:** корень «${0} sent a trade fleet to ${1}»; под ним плата, «[флот] −1», «+2 [аэростат] → <карта>»,
    «+1 прод. M€», реакции — их эффектами. Ни одной строки дважды.
16. **Без Venus Next** карты нет в колоде и её клетки нет на поле.

## 1. Блок A · сервер

### A1 · Награда с целью — ОДНА конструкция на обещание и выплату (класс)
Сегодня цель-карта торговли описана дважды: `cardTargetFollowUp` (превью) и ветка `Colony.giveBonusImpl` (жизнь). Причалу
третья копия запрещена.
- Класс получает способ объявить награду-вопрос так, чтобы карта назвала ЧТО положено, а модуль сам вывел и follow-up
  превью, и живой шаг — закон «a hook that answers is not a hook that acts» (`game-logic.md`). Рекомендуемая форма: карта
  отдаёт построенный, не поставленный в очередь `AddResourcesToCard` (тип импортируется как тип — `FleetDock.ts` обязан
  остаться без рантайм-импортов); модуль зовёт его дважды — для превью (0 / 1 / ≥ 2 кандидата → `lost` / `auto` / `pick`,
  тем же чтением, что `cardTargetFollowUp`) и для `game.defer` после посадки флота. Другая форма допустима, если условие
  «одно чтение на оба конца» выполнено и закреплено спеком «превью == живой промпт» (кандидаты, порядок, авто-выбор).
- `cardTargetFollowUp` становится общим (принимает готовый шаг и роль); путь колоний — побайтно прежний
  (`colonyTradePreview.spec`, `Colony.spec` зелёные без правки ожиданий).
- **Авто-выбор согласован с превью:** при одном держателе живой шаг не спрашивает (иначе в батче нет ответа и вопрос
  встанет ПОСЛЕ посадки), при двух — спрашивает, и ответ уже едет в хвосте.
- **Живой вопрос несёт структурный источник** — `choiceContext` с картой-причалом (не `colonyBonus`, не заголовок): по нему
  клиент узнаёт перезаданный или запаркованный вопрос (правило 7).

### B1 · ЦЕЛЬ ДО НАЖАТИЯ — шаг стейджа причала, общий со стейджем колонии
- Стейдж причала получает строку шага «КУДА» и подстадию выбора — ТЕ ЖЕ, что у стейджа колонии: общий селектор

- Отличие причала одно и структурное: герой — карта и она кандидат → селектору передаётся `sourceCardName`, свой причал
  стоит в нём как «ЭТА КАРТА» (существующий режим композеров), а не вторым лицом той же карты.
- **Выбор — нажатие** (закон «A CHOICE IS A PRESS»): при ≥ 2 кандидатах ничего не предвыбрано, «Торговать» отказывает с
  причиной «выберите карту», пока цель не названа; при одном — получатель стоит строкой без остановки курсора.
- Каждый кандидат читается как решение: сколько аэростатов сейчас → станет, и что это значит для ЭТОЙ карты (ПО за
  аэростаты — по данным, которые селектор уже показывает у синих действий; клиентской арифметики правил не добавлять).
- B — один уровень: выбор цели → стейдж → обзор; выбранная цель переживает возврат к оплате и обратно.
- Крошка: «КОЛОНИИ › СТАНЦИЯ «АВРОРА» › ТОРГОВЛЯ», на выборе хвост — то же слово, что у этого шага на стейдже колонии.

### B2 · ОДИН POST и три честных исхода

### B3 · СЦЕНА «КАРТА ПЛАТИТ КАРТЕ» — слот REWARD третьей категории
Фраза прежняя: `ANSWER → REWARD → READ → LEAVE → CONCLUDE`; план — из превью, прибитого на границе коммита, плюс выбранная
цель (захват шага либо `auto`).
- **ANSWER:** импульс проходит печатный ряд и садится на ПЕРВЫЙ значок аэростата.
- **REWARD, по порядку значков:** жетон из значка 1 → карта-получатель, жетон из значка 2 → она же (два значка — два
  жетона, каждый из СВОЕГО измеренного узла, с шагом между касаниями); затем жетон производства из своего значка → ряд
  производства M€ на рельсе (`railReward` — без изменений); затем ответ стола тактом после последнего касания.
- **Удержание:** счётчик аэростатов получателя стоит на старом числе с применения вида до касаний (n → n + 1 → n + 2 — по
  жетону) — тем же механизмом удержания, каким карта принимает ресурс у торговли с колонией и у синего действия
  (`console-blue-action-receive`); обещание сверено с диффом двух видов, несошедшееся — не удерживается и названо. Всё
  ПРОИЗВОДНОЕ от этого числа держится с ним: ячейка ПО рельса (2 аэростата на карте «1 / 2» = +1 ПО — класс PL-014), чип
  спутника ДОП. РЕСУРСЫ, бейдж ПО на лице.
- **Получатель:** ≠ причал — принимающая карта ПОДАНА на стейдж подачей стейджа колонии (место раньше объекта: она стоит до
  вылета первого жетона, принимает, читается); = причал — жетоны садятся на счётчик героя, короткой дугой внутри лица.
  Принимающую карту нельзя размонтировать под летящим жетоном (корень дефекта Redux-Венеры — `run:no-dest`).
- **LEAVE:** награда доставлена, впереди ничего нет → герой и принимающая карта уходят ВМЕСТЕ с workspace (как у `rail`).
- Деградация названа (`data-fleet-dock-degraded` + dev-warn) по каждому адресу; холды ограничены и отпускаются на любом
  конце сцены; reduced motion — итоговые позы сразу. Ни одного `setTimeout` в тактах (гард `fleetDockSceneClock.spec`).
- **Сцены TR06 (`placement`) и TR26 (`rail`) — побайтно прежние**: A/B раскадровок и отметок времени против `tr27-before`.

## 7. Режим работы
**Коммиты карты**, каждый зелёный по юнитам: (1) сервер — награда с целью как одна конструкция (класс), клетка, карта,
гарды, локаль, лор, арт, спеки; (2) клиент — вынос шага цели и подачи принимающей карты в общее БЕЗ видимых изменений
стейджа колонии (A/B) + юниты; (3) клиент — шаг цели на стейдже причала, слот REWARD третьей категории, удержания,
три причала + юниты; (4) клиент — клетка города на фланге + юниты; (5) e2e + фикстура + документы. **Коммиты полировки** —
отдельно, по одному на находку. Перед каждым: `npm run lint`, `npm run build:test`, `npm run make:cards`,
`npm run make:json`; перед визуальной проверкой — `npm run make:css` + `npm run build:server`; юниты — последовательно,
на тихой машине. **Не пушить.**
Документы: `docs/TURMOIL_REDUX_WATER_HAULING.md` — контракт класса: §9.1 (третья категория построена — имя, признак, слот,
уход), новый раздел «награда с целью: одна конструкция, пре-сбор, три исхода», §9.5 переписать фактом; `COLONY_TRADE_FLOW.md`
(шаг цели и подача — общие для двух стейджей); `TURMOIL_REDUX_NOVA_CITY.md` §9 и комментарий `hostedSpaces.ts` (решение 4);
`.claude/rules/console-ui.md` § A CARD CAN BE THE TRADE'S DESTINATION — третья категория одной фразой; `board.md` — пятая
клетка дуги, если правило дуги меняется; чеклист §4 — строка «причал с наградой на карту»; журнал § TR27; реестр.
Гочи: у `turmoilReduxExpansion` в `testGame` нужен `coloniesExtension: true`; стартовые Зелёные платят +2 M€ за шаг РТ —

`receive` в обход класса; вопрос о цели ПОСЛЕ посадки флота; авто-выбор цели при двух кандидатах; предвыбранная цель.

цель / клетка» на клиенте. Копия селектора цели или подачи принимающей карты в стейдже причала; изменение кадров и таймингов
стейджа колонии, сцен TR06 и TR26, торговли с Титаном и Redux-Венерой — кроме правок §6 с A/B и строкой реестра. Тик

поля; строка в `HOSTED_SPACES`; свой компонент места и своя сцена посадки; клетка на поле в партии без Venus Next.
