## 4. ГЛАВНОЕ — «ПАНЕЛЬ ГОЛОСОВАНИЯ — ОДИН ВЗГЛЯД: ЧИСЛО, ПОТОМ ПОСЛЕДСТВИЯ» (решение 3) — композиция
**Цель:** панель слева от трёх резолюций отвечает на два вопроса в этом порядке — «что я получу, если ЭТА резолюция примется» (ОДНО число — закон модели) и «что изменит МОЙ голос» (лидер, победа, эффект
партии) — одним взглядом, без таблицы и без второго громкого числа; CTA — плита. Грамматика P73 (DC) переносится на лист Парламента: три зоны по высоте колонки карт, значение громче кикера, лист не
озаглавливает себя сверх имени резолюции, коммит — плита. Модель `voteInfoModel` остаётся ЧИСТОЙ и той же по содержанию (бюджет — гард); меняется ПОДАЧА. Свет — только курсор и одноразовое событие.
1. **ТРИ ЗОНЫ ПО ВЫСОТЕ КОЛОНКИ КАРТ (V1).** Верх панели = верх ряда карт, низ = низ полосы голосов под картами (общие линии с правой колонкой — панель и ряд читаются как один стол). ВЕРХ — имя резолюции
   с эмблемой (как есть). СЕРЕДИНА — ЧТЕНИЕ (одно число, семьи чтений — их боксы как есть, только иерархия §4.2). НИЗ — ГОЛОС (источник, факты, CTA), прижат к нижней линии. Колонки `__info` (чтение | голос
   22rem) → одна колонка из трёх зон (голос — под чтением, а не рядом), ЕСЛИ ширина панели на fhd / deck не держит две; на tv4k решить по свидетелю (а): без пустоты > 15 % высоты. Бокс панели — ПОСТОЯННЫЙ от A
   до ухода (`vote-geometry` — закон); смена субъекта LB/RB и смена карты — кроссфейд тел на месте (как есть, `__info-body` absolute).
2. **ЧИСЛО — ГЛАВНЫЙ ГОЛОС (V3).** Формула чтения (`ConsoleInfluenceYield`): результат «+N [ед.]» — самый тяжёлый и крупный элемент панели (≥ 1.6 × кикера), слагаемые тише, стрелка — форма; подложка —
   нейтральное стекло (лиловый тон — долой; тон ресурса допустим только как кант ≤ 10 %). «ЕСЛИ ПОБЕДИТЕ» — СУФФИКС того же числа одной тихой строкой под ним: «+1 если победите · шаг ③» (`suffixWinKey` — как
   модель и обещает), без звёзд-капсов и без второй плашки; при равенстве (победа ничего не добавляет) — суффикса нет. Нулевая формула (грант на карте без выплаты: «0 → +0») не печатается — вместо неё тихая строка
   кикера семьи «quiet reward» (`quietRewardPose` — уже есть для карт без выплаты: проверить, почему на P70 / P72 кадрах напечатаны нули — вероятно, дверь гранта читает чтение резолюции ПОД курсором; это
   правильно — но нули должны сворачиваться в «ничего при принятии» словом, не в «0 + 0 → +0»).
3. **СУБЪЕКТЫ — ТАБЫ, НЕ ПИЛЮЛИ (V2).** `ConsoleVoteLedger` уходит со строки кикера на СВОЮ строку над чтением — ряд табов мест (кубик + имя при одном-двух местах / кубик + число при шести; активный — inset-кант
   и вес), глифы LB/RB — на краях ряда; строка ЗАРЕЗЕРВИРОВАНА постоянной высоты (при одном месте — таб «ВЫ» один, без глифов). Комментарий «41 px» (`:55–65`) — пересмотреть под новую высоту зон (§4.1): если
   на 4K строка не помещается — бюджет берётся у пустоты, не у чтения.
4. **ФАКТЫ — ОБЪЕКТЫ (V4).** `ConsoleVoteFactRow` — ряд из трёх ПЛИТОК равной высоты вместо трёх строк: ЛИДЕР — кубик лидера (до → после: кубик → кубик; «—» заменяется пустым гнездом), ПОБЕДА — корона (форма
   «принимается» / «не принимается»: заполненная / пустая корона, слово — кикер плитки), ЭФФЕКТ ПАРТИИ — два гнезда «n / 2» в языке плашки партии (заполненные / пустые гнёзда + слово «эффект ваш» при переходе
   через 2); `ally` (TR62) — четвёртая плитка, когда есть. Факт без изменений — ОДНО значение (закон модели), изменение — «до → после» внутри плитки; тон `gain` — кант, не свет. Инспектор X печатает те же факты
   тем же компонентом (один рендер, два хоста — закон R-10) — проверить, что новый ряд умещается в футере инспектора, иначе `variant="row" | "list"` одного компонента.
5. **ИСТОЧНИК И CTA — ПЛИТА (V5, V6).** Источник делегата — одна тихая строка над CTA: кубик игрока + «из резерва» / «из лобби» + цена (число + значок) или «бесплатно» — без кикера «ВАШИ ДЕЛЕГАТЫ» (крошка и
   бар уже говорят «ГОЛОСОВАНИЕ»; при гранте — «×2» на кубике). CTA — плита по содержимому у нижней линии (глиф A · глагол · тихая цена), `--ready` — кант и вес, не заливка во всю ширину; `--blocked` — причина
   одной строкой на плите (как есть); `--busy / --done` — слово и форма. Классы `__cta--*` и `data-parl-cta` — те же (фокус-цель пада).
6. **СВИДЕТЕЛЬ ПАНЕЛИ** — НОВЫЙ `tests/e2e/console-parliament-vote-panel.spec.ts` (FUNCTIONAL, ×3 профиля, корпус §3): (а) верх / низ панели = верх ряда карт / низ полосы голосов ±2 px; пустота (сумма вертикальных
   промежутков без содержимого) ≤ 15 % высоты панели; (б) бокс панели и CTA не меняются при LB/RB и ◀▶ (±1 px) и от A до ухода (`vote-geometry` — зелёный); (в) кегль результата формулы ≥ 1.6 × кегля кикера;
   нет второй плашки «если победите» (суффикс — одна строка под числом, `data-parl-vote-suffix`); нет нулевой формулы («0 → +0» не рендерится); (г) табы субъектов — отдельная строка, кегль ≥ пола ТВ; (д) три
   факта — плитки равной высоты, лидер — кубик, не текст; (е) ширина CTA ≤ 60 % ширины панели; у плиты в `--ready` нет `box-shadow` с размытием светлого; (ж) нет лилового фона у формулы (computed background
   без фиолетового оттенка — проверка по hue); (з) `expectParliamentFits`, `expectRailHonest` где применимо. ПЕРВЫМ ДЕЛОМ — прогнать «ДО»: (а), (в), (д), (е), (ж) ДОЛЖНЫ быть красными (иначе переписать
   свидетель, не правку).
7. **ЧЕГО НЕ ДЕЛАТЬ.** Не менять СОДЕРЖАНИЕ модели (`voteInfoBudget` — тот же бюджет: одно чтение, суффикс, два-три факта); не повторять печатную формулу карты (она справа); не переносить фразы из инспектора;
   не трогать полёты кубиков / цены, ряд карт, серию, дверь TR03 сверх подачи блока `__info-party--support` (его геометрия — цель посадки нейтральных кубиков: бокс не менять); не переименовывать классы / `data-*`
   (18 спеков); «ОДНА РАМА» — плита панели остаётся опакой нейтральной.
