## Premium card renderer (`.pcard` — the from-scratch card face)

**Project cards (automated / active / event) + preludes + CORPORATIONS render through a NEW, fully isolated premium face** — `src/client/components/premiumCard/PremiumCard.vue` — designed to the physical-set concept (dark metal corpus themed by card type, 9-patch gold frame echoing the card back, gold cost/VP badges, tag medallions, copper «от/до» requirements band, a large art viewport, an icons-only mechanics plate). CEOs / standard projects stay on the legacy renderer until their own premium pass. **The ONE scope gate is `premiumCardTheme.isPremiumFaceType`** — every routing point consults it; widening the scope later is a one-line change there.

- **Routing:** hosts import `card/CardFace.vue` (a zero-visual-logic facade registered locally as `Card`, so templates/props are unchanged) → premium for in-scope types, legacy `Card.vue` otherwise. The zoom modal routes inside `CardZoomCard.vue` (premium branch renders the GLOBALLY-registered `premium-card-face` — a static import would close the `PremiumCard → CardZoomModal → CardZoomCard` type cycle and collapse vue-tsc to `{}`, same trick as `modal-input-host`). Console proxies route inside `ConsoleCardFaceLite.vue` (PremiumCard `name`-only static mode — printed face, inert). **Never import legacy `Card.vue` directly in a new host — import `CardFace.vue`.**
- **Data flow:** `CardModel + ClientCard → premiumCardViewModel.buildPremiumCardViewModel → PremiumCard` — the VM layer (`premiumCardViewModel.ts` / `mechanicsModel.ts` / `premiumCardTheme.ts` / `tagLayout.ts` / `titleFit.ts`) is PURE (no Vue/DOM/i18n; unit-tested under the server runner). Mechanics = a walk of the SAME render DSL via the common type guards; plain-string description rows are DROPPED (the face is icons-only — prose lives in overlays / the future fullscreen text panel); nodes are kept as REFERENCES (no copies, no drift). The VM throws for out-of-scope types — the facade gates first.
- **Geometry:** design space **320×460 px @ zoom 1** (matches the card-back ratio 0.697; the legacy face was 300×400). Hosts scale via `zoom` exactly like the legacy card. Internal layout is a 4-row grid (header shell / requirements rail / art `minmax(96px,1fr)` / lower section): the ART absorbs free height, and the **density tier** (`mechanicsModel.densityOf` → `pcard--mech-sparse|normal|dense|veryDense`) scales the mechanics icon size — 4 CSS presets, no JS measuring, no reflow.
- **Header = NAMEPLATE + OVERLAYS (the flagship zone).** `.pcard__header` is a FIXED-height positioned shell; `.pcard-nameplate` (NOT `.pcard-plate` — that's the mechanics gold TEXT plate!) is the full-width faceted title plate (clip-path gold kant → dark metal body → engraving → theme inner contour) whose **silhouette never changes**; the cost badge (**the REAL `assets/resources/megacredit.png` tile** — instant M€ semantics; printed cost overlaid + a horizontal «−N» delta chip docked lower-right) and the tag medallions are **overlay layers at z4 (above the gold frame)** pinned over the plate ends. Only the title TEXT insets react — `--pcard-title-safe-l/-r` set inline from the DETERMINISTIC `tagClusterPlan(count)` geometry (`tagLayout.ts`: row 1–2 / overlap 3–6 / stack 7+) + cost/modifier presence (`PremiumCard.headerVars`; never DOM-measured). No requirements → the rail collapses to the thin `.pcard__divider` hairline.
- **Lower section = mechanics + corner ANCHORS, no footer row.** `.pcard__lower` hosts the mechanics panel (**always FULL width**) plus corner elements that yield content LOCALLY and SYMMETRICALLY: the LAST `.pcard-mech-group` gets an EQUAL left+right inset `~"max(var(--pcard-vp-safe), var(--pcard-res-safe))"` (LESS-escaped CSS `max()`; vp-safe 40/44/64 via `pcard--vp-<variant>` from `vpVariantOf()`, res-safe 60 via `pcard--has-res`) — a short centered row is visually UNTOUCHED, a wide row WRAPS and stays centered, never a one-sided shove. The VP badge (38px premium gold plate, sizes to content, `max-width 75` — the widest formula the corpus prints, Vermin's «−1 / [city] *») sits over the panel's bottom-right corner. **The reserve is a GUARANTEE, not a measurement of the plate**: since the badge started printing its relation operator the plate exceeds its own reserve (a `wide` is 57–62px against 44), and raising the reserves to match cost three cards a second wrapped line for room nobody was using — measured across all 163 in-scope faces, the tightest gap between a row's last INK and the plate's first INK is 17.9px, so the plate's own 9px padding is what keeps them apart. Re-measure before widening the plate again; the expansion stamp (13px) is ENGRAVED into the panel surface bottom-left at **z0 UNDER the content rows (z1)** — a seal, not an overlay, never touching the frame; the resource slot is a sunken capsule CARVED INTO the panel (inset shadows + lip light) beside the stamp. **No VP/counter → no reserve.**
- **THE VP BADGE PRINTS A RELATION, never two symbols side by side.** «1 [jovian]» reads as «one jovian tag» just as easily as «1 VP per jovian tag», so `premiumCardViewModel.vpRelationOf` classifies the printed `CardRenderDynamicVictoryPoints` ONCE and the badge renders that verdict (it never re-derives one): **`per`** → «N / [icon]» (per each) · «N / K [icon]» (per every K) — **`conditional`** (one-or-more) → «[icon] : N», TM's own «trigger : effect» colon, because Search for Life scores a FLAT 3 and «3 [science]» read as a rate — **`variable`** (`questionmark()`) → «?», never the gold «0» the premium face used to print for Agricola Inc / Red City — **`plain`** (Law Suit's «−1 from ANY player») → a bare numeral, `compact` like a fixed amount. ⚠️ `target` is a RENDER field, not a semantic one: the per-one builders (`moonMiningTile`, `any`) copy `points` into it, so a denominator is only a `target` that is BOTH `> 1` AND `!== points` — the same collapse the legacy face did (`target === points || target === 1`). The operator (`.pcard__vp-op`) is INK, not a divider: heavier than the numerals it separates and carrying their engraved highlight, so the plate's specular sweep cannot wash it out. An operator NEVER dangles — a per-one relation earns it only once an icon resolves, which is what keeps the unmapped moon/underworld VP subjects (Luna Mining Hub, Luna Train Station, Luna Hyperloop, The Grand Luna Capital Group, Underground Shelters) printing an honest bare amount. Guards: the relation table + the corpus worklist sweep in `premiumCardViewModel.spec.ts`, the per-shape render cases + the no-dangling-operator sweep in `PremiumCard.spec.ts`.
- **CANONICAL MECHANICS ORDER — «при розыгрыше» is ALWAYS at the BOTTOM (unified across every card type).** `mechanicsModel.buildMechanics` reorders every card's mech GROUPS into `orderMechGroups` — top→bottom = **actions → passive effects → the on-play zone (плашка «при розыгрыше», opened by the `.pcard-play-rail`) LAST**. It is a STABLE sort by kind-rank (`action`/`corp-action`=0, `effect`/`corp-effect`=1, `plain`/`production`=2), so same-rank OR-choice runs stay contiguous + keep their «ИЛИ» divider (orJoin is recomputed on the FINAL adjacency; a stale cross-rank orJoin is cleared). This flipped the old per-type split: a CORPORATION's starting-resources run (authored at the TOP of the DSL) now moves to the bottom exactly like a project card's trailing immediate mechanics — `playZoneStart` finds the trailing run on ALL cards, so `PremiumMechanicsPanel` has ONE rail path (the old `playZoneStartLeading` + `corporation` prop are gone). **The structured card-info TEXT is ordered the SAME way** — `buildCardInformation`'s `orderInfoGroups` (requirements → action → effect → immediate → VP) + the annotation `KIND_ORDER` + the console rules `PHYSICAL_KIND_ORDER` all match, so the face and the rule text read 1:1. Intra-group block order (within «при розыгрыше») is STILL render-reading-order via `orderBehaviorBlocks` — the group reorder is a separate, outer layer. Guards: `premiumCardViewModel.spec` (Helion `['effect','plain']`, Kuiper trailing plain), `cardInformation.spec` (group-order), `annotationModel.spec` (play-zone invariant). **When adding a new group kind, give it a rank in BOTH `orderMechGroups` and `orderInfoGroups` — never hardcode order at a call site, and never move on-play back above effects/actions.**
- **A variable amount rides `innerText`, NOT `text`.** The DSL's item option `{text: 'x'}` is stored on `CardRenderItem.innerText` (`text` is set ONLY by `.plate()` / `.text()`, which never build an M€ item), so `PremiumMechNode.insideText` reads `item.innerText ?? item.text` — the legacy `CardRenderItemComponent` has always preferred `innerText` here. Reading only `text` printed the placeholder `amount` instead: Energy Market's «2x M€ per energy» face read a flat «1» (the WRONG price on the card), Playwrights lost its «?» and Nirgal Enterprises its «0». Guard: `PremiumCard.spec` «a variable M€ face shows its override text».
- **Icons:** `premiumCardIcons.ts` is the ONE mapping (item type / tag / card-resource / tile / expansion → raw asset URL; components inline-style `background-image`). The legacy icon classes are CSS-scoped under `.card-container` and MUST NOT be reused. An unmapped type renders a labelled fallback chip + one-shot dev warn.
- **Art:** `cardArt.ts` — `assets/card-images/<metadata.cardNumber>.webp`, availability baked at build time into `src/genfiles/cardArtManifest.json` (generator `src/tools/make_card_art_manifest.ts`, chained into `make:cards` — no 404 storm). `premiumCardArt()` ALWAYS resolves (fallback `-1.webp`); `cardArtUrl()` keeps the legacy contract (undefined without real art). The `<img>` failure chain is one-shot: art → `-1.webp` → procedural theme body (never loops).
- **Host CSS/JS hooks:** every host rule/query that sized or state-styled the legacy face was widened to **`:is(.card-container, .pcard)`** (hand/played/selection/draft/console LESS zoom vars, SFC `:deep()` zoom hooks, console deal/exit/zoom directors, focus-engine, `CardZoomModal`'s measure selectors, focus-frame selectors). `CARD_NATURAL_W` (console cinematics) is now **320**. Rules keyed on legacy INTERNALS (`.filterDiv`, `.card-hover-tall`, `.card-content`) stay legacy-only by design. When adding a new host: use gap-based spacing + a `zoom` hook on `:is(.card-container, .pcard)`; legacy-glue `.cardbox` rows and `.cards-stack` peek piles get their premium margins in `premium_card.less`.
- **`justify-content` GOVERNS EVERY WRAPPED LINE — a rule written for ONE box left-aligns the whole remainder.** The last mechanics row gets an ASYMMETRIC corner reserve when it carries a plate (`padding-left: --pcard-res-safe` / `padding-right: --pcard-vp-safe`, so a wide plate-label row like «ГЛОБАЛЬНЫЕ ПАРАМЕТРЫ : ±2» spreads into the free left space and still fits one line) — and it also took `justify-content: flex-start`. But the fit is bought by the PADDING; the alignment does nothing for it and applies to every line the row wraps onto. A row holding SEVERAL boxes (a plate-bearing action beside its effect — Tycho Magnetics C46, Robinson C15, UNMI C12, Factorum C20, and 3 human faces in premium scope) then hangs its short second box off the LEFT edge under the wide first one, reading as a misplaced fragment (measured: 71px off the row's centre). Such a row stays CENTRED (`:has(> * + *)`); the corner reserve is untouched, and because wrapping depends on available width, alignment alone can never change what fits. Guard: the per-line centre-drift assertion in `tests/e2e/console-bot-corp-no-tags.spec.ts`.
- **Styles:** `src/styles/premium_card.less` (namespace `.pcard`, imported in common.less) — geometry/material tokens live in the `.pcard` root block, themes = `pcard--theme-emerald|azure|crimson|prelude|corporation` variable sets, quality tiers `pcard--tier-thumb|normal|full` (`lightweight` prop → thumb: no texture/glow/hover for dense boards). Frame/badge assets: `assets/premium-card/*.svg` (the gold frame is a border-image 9-patch, slice 60 — one decode app-wide). No `backdrop-filter`, no runtime SVG filters, no infinite animations; `prefers-reduced-motion` honoured.
- **Corporation face (2026-07):** theme `corporation` (graphite + gold), routes by TYPE — **every corporation of every module** renders premium (the draft can deal any corp; guarded by a full-manifest build test). NO art by design: the art slot hosts **`PremiumCorpIdentity.vue`** — the EXISTING wordmark logo system (`CardCorporationLogo.vue`, bespoke SVGs / css / image wordmarks / caps-text fallback) inside `.pcard-corp-stage`, a ~300×88 stage replaying the legacy title geometry the logo coordinates are calibrated to, scaled via `--pcard-corp-logo-scale`. **The identity plate is LIGHT (warm parchment) on purpose** — the wordmarks were designed against the legacy WHITE card face and several are dark-inked (Interplanetary Cinematics / Teractor / Morning Star / Polyphemos); a dark plate makes them unreadable (verified by screenshot audit of all 39 in-scope corps — don't re-darken it). The logo styles in `cards_v2.less` are scoped **`:is(.card-container, .pcard-corp-stage)`** — deliberately NOT a literal `card-container` class inside the pcard (hosts zoom `:is(.card-container, .pcard)` descendants → a nested `.card-container` would be zoomed twice). No cost badge (starting M€ lives in the mechanics, as printed); the on-play rail is hidden for the corp theme (the trailing plain run is the STARTING resources, not «при розыгрыше»). **Corp-box flattening** (`mechanicsModel.flattenCorpBoxRows`): the legacy `corpBox(...)` chrome is dissolved — its content becomes ordinary root groups, each effect/action frame SPLIT into its own group (the corp builders chain several frames into ONE row — StormCraft), spacer-only rows (`vSpace`) skipped, and the Viral-Enhancers trigger splice is DISABLED for corp-box rows (`startEffect`/`startAction` there is a genuinely empty cause — the splice was eating the starting-resources row). Corp rows carry no `graphicId` (corps are outside the card-information scope).
- **Showcase:** `?premiumCardsPlayground` — reference strip (back ↔ green/blue/red/prelude), curated edge cases (discount chip, dynamic/vermin VP, missing art, VP-only), auto density buckets, longest translated titles, tag extremes, tiers/states, full in-scope catalog. This is the visual acceptance surface.
- **Guards:** `tests/client/components/premiumCard/premiumCardViewModel.spec.ts` (VM + a coverage guard: every in-scope premium card builds; the no-graphics list is PINNED — 8 genuinely mechanics-less VP-only cards; a new card landing there fails with its name) + `PremiumCard.spec.ts` (mochapack; face render, discount chip, art fallback chain).
