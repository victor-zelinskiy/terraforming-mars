# Чужие исходы при голосовании + политическая зона в Информации — исследование и план

Ответ на промт `docs/claude/prompts/parliament-rival-outcomes-research.md` (выдан 2026-09-25). Только чтение кода;
продукт не тронут. Все ссылки — на состояние `main` от 2026-09-25 (после RX25).

## 0. Главное первым

1. **Проблема подтверждена, но решается проще, чем в промте: серверной работы для задачи A нет вовсе.**
   `voteYieldsOf` / `voteLevyOf` / `colonyLedgerOf` / `tileGrantReadingOf` / `noRecipientCompactNoteOf` уже
   принимают цвет места и табло, а `ParliamentModel.players` уже несёт входы формул для КАЖДОГО участвующего
   места — причём гейт входов идёт **по каталогу**, а не по столу (§2). Вся работа — в чистой модели чтения и в
   двух поверхностях.
2. **Y в зоне голосования НЕ свободна**: шелл перехватывает её до диспетчера секции как «Информация» на любой
   поверхности (`ConsoleShell.vue:12227`, правило P27b). Свободны и доходят до режима голосования **LB/RB, LT/RT,
   L3, ▲/▼** (§4.1). Семантически подходит только пара **LB/RB** — «Игроки» во всей Информации и в «Разыграно».
3. **Рекомендация (задача A): двухъярусный «леджер исходов» на панели голосования.** Ярус 1 — строка чипов
   «[куб] +N» по каждому участвующему месту под чтением (0 нажатий до ответа «кому выгоднее»). Ярус 2 — LB/RB
   переводят СУБЪЕКТ большого блока чтения на выбранное место (тот же честный разбор, что у себя), кикер называет
   субъекта кубом и именем, столбец «ВАШ ГОЛОС» и A не меняются никогда (§4.4).
4. **Задача B: зона «ПАРЛАМЕНТ» в Информации** (кольцо, колонка 3, только для людей; бот — честная строка
   «не участвует» без фокуса) с маршрутом-деталью: влияние из чего складывается · Повестка · делегаты ·
   председательство · **исходы резолюций на столе для этого игрока**. A и B **сходятся в одной модели**:
   `seatParliamentReadingOf(model, seat, tableau)` (§5).
5. **Что можно сделать раньше и отдельно:** ярус 1 (строка чипов) — самостоятельный блок без новых ключей
   второго лица и без состояния; он один уже закрывает стратегическую ошибку. Ярус 2 и зона Информации — следом,
   на той же модели (§6).

## 1. Подтверждение проблемы (своими словами, со ссылками)

**Что видит игрок сейчас.** Панель голосования печатает ОДНО число — исход выбранной резолюции для зрителя:
`ConsoleParliamentVoteMode.vue:282–300` строит `voteInfoOf({... viewer: this.viewerColor, tableau:
this.playerView.thisPlayer.tableau ...})`; внутри `voteReadingOf` (`voteInfoModel.ts:149–199`) читает
`voteYieldsOf(resolution, model, viewer)`, `voteLevyOf`, `colonyLedgerOf`, `tileGrantReadingOf` — все по цвету
зрителя. Кикер — «Для вас при принятии» (`READING_KICKER_SEATED`). Ни одна поверхность голосования не печатает
чужое число: ни панель, ни лента, ни осмотр по X (`ConsoleShell.vue:8722–8752`: `zoomResolutionYields` /
`zoomResolutionLevy` / `zoomResolutionLedger` — всё по `this.thisPlayer.color`).

**Где зашит зритель в модели.** `influenceYieldModel.ts:573` — `seatOf(model, viewer)`; его вызывают
`voteYieldsOf` (589), `resolvingYieldOf` (746), `voteLevyOf` (799); `enactedYieldsOf` (679) фильтрует записи по
`o.player === viewer`. Но «зашит» — неточно: **параметр `viewer` — просто цвет**, функции не знают, что это
«я». То же у `colonyLedgerOf(resolution, model, viewer)` (`colonyLedgerModel.ts:61`),
`tileGrantReadingOf(resolution, model, viewer)` (`tileGrantModel.ts:108`), `partyReactionsOf(resolution,
yields)` (вообще без цвета — только чтения), `noRecipientCompactNoteOf(effect, tableau)` (любое табло).
Единственное место, где «зритель» — это именно зритель: `viewerHasSeat(model, viewer)` в `voteReadingOf:156`
(отсекает зрителя без места) и презентационные ключи второго лица (§4.5).

**Что уже подтверждает наш собственный код.** `LEVEL_LOSS_NOTE_KEY` («Всё сверх нормы отнимается»,
`influenceYieldModel.ts:430`) — с комментарием «the vote is the only defence against this law». Предупреждение
— только про своё место. Панель итогов (`parliamentResultsModel.ts` §① ВЫПЛАТЫ) показывает **строку на каждое
место** — но уже ПОСЛЕ принятия («a seat saw its OWN reward … and has never been shown anybody else's»). То есть
язык «строка на место» в Парламенте уже есть, а разрыв — ровно ДО голоса.

**Последствие — то, что описано в промте, без преувеличения.** На `Plant Ban` (RX25) норма = 2 + влияние у
каждого своя (`docs/TURMOIL_REDUX_PLANT_BAN.md` §3.1): игрок с 3 растениями видит «терять нечего» и голосует
«за», не видя, что лидер с 12 растениями теряет 7 — или наоборот. На `Central Power Grid` / `Cloud Development`
чужой счётный член (метки, колонии) может дать сопернику вдвое больше при том же влиянии.

**Где промт неточен (важно для плана):**

- `ConsoleMenuZoomHost.vue (~258)` — не потребитель `voteYieldsOf`. Потребители: `voteInfoModel.ts`,
  `colonyLedgerModel.ts`, `ConsoleParliamentBand.vue:251–266` (resolving/enacted), `ConsoleShell.vue:8730/8741`
  (осмотр), `ConsoleResolutionsPlayground.vue` (стенд — там, кстати, `voteYieldsOf(r, this.model, color)`
  уже вызывается по ЛЮБОМУ цвету тестовых игроков: строки 2327–2329, 2518).
- «Y — свободна» — нет (§4.1). «X — осмотр, A — голос, B — назад» — верно (`parliamentCommands.ts:100`).
- «N мест × M эффектов на каждой перерисовке» — считается не на перерисовке, а в `computed`, который
  пересчитывается при смене объекта `model` (каждый апдейт транспорта); N ≤ 5, M ≤ 3 — микросекунды (§7).

## 2. Сервер: нужна ли работа

**Для задачи A — нет.** Доказательство по `src/server/parliament/ParliamentModel.ts:179–259` (`playerModel`):

| Поле `ParliamentPlayerModel` | Кому строится | Гейт |
| --- | --- | --- |
| `influence`, `agenda`, `lobby`, `reserve`, `onResolutions`, `chairman`, `access`, `partyActionUses`, `resolutionActionUses` | каждому игроку (`game.playersInGenerationOrder.map`, строка 78) | нет |
| `counts` (число + карты/клетки/колонии/метрика) | каждому **участвующему** | `declaredCountIds(parliament.catalog)` — **по каталогу**, не по столу |
| `production` (делители sequel-членов) | участвующему | `declaredSequelProductions(catalog)` |
| `stock` (что берёт плата, от чего считается уровень) | участвующему | `declaredStockReads(catalog)` |
| `colonyBonuses` (леджер колоний) | участвующему | `declaresColonyBonuses(catalog)` |
| `hand` (размер руки для уровневого члена) | участвующему | `declaresHandLevel(catalog)` |

Гейт по каталогу означает: у каждого места всегда есть ВСЕ входы всех формул, какие только может выложить
колода, — не только тех трёх карт, что на столе. Значит клиент может посчитать чужой исход любой резолюции в
области голосования без единого нового байта на проводе. Единственная зрительская часть модели — `viewer`
(проекции голоса и действия партий, строки 166–175), и она чужим исходам не нужна.

**Для задачи B — одно поле, и оно инфраструктурное.** Влияние на сервере = уровень Повестки +
`influenceBonus` + `card.getInfluenceBonus?.(player)` по табло (`Parliament.ts:450–459`). Модель несёт только
ИТОГ; разбор «Повестка N + бонусы M» клиент выводит сам (`influence − influenceAtAgenda(agenda)`), а вот
**назвать источники** не может: `influenceBonus` хранит сумму без имён.

> **Уточнение 2026-09-25 (найдено при написании промта исполнителю).** Сегодня в Redux-игре оба бонусных
> слагаемых МЕРТВЫ, то есть влияние всегда равно уровню Повестки: `getInfluenceBonus` не реализует ни одна
> карта (`ICard.ts:221` — только объявление и два читателя), а все четыре вызова `addInfluenceBonus` идут в
> ЛЕГАСИ-`Turmoil` (`Executor.ts:696`, `ceos/Oscar.ts:28`, `community/ByElection.ts:30`, `colonies/Colony.ts:558`),
> которого в Redux-игре нет (`Game.ts:187` и `:195` — разные поля); карточные источники в Redux-пул не попадают
> вовсе, потому что ни одна карта не помечена `politics: 'redux' | 'both'` (`CardFactorySpec.ts:27,47`).
> **Попутная находка:** колония **Pallas** (`cards/community/Pallas.ts:11` → `Colony.ts:556`) в Redux-игре тихо
> не даёт влияния (`Turmoil.ifTurmoil` пишет в консоль и выходит) — живая «тихая потеря» и единственный
> источник, который сделал бы список непустым. Это правила, а не показ: отдельное решение владельца.

Форма поля: `ParliamentPlayerModel.influenceSources?: ReadonlyArray<{source: string, amount: number}>`; хранилище
— зеркало уже существующего `grantedEffects` (`Parliament.ts:117`, `{party, source}`), новое сохранение обязано
деградировать со старого (`Record<PlayerId, number>` → одна безымянная запись; CLAUDE.md § Database).
**Решение владельца: делаем поимённо** (в инфо-панели место есть) — как инфраструктура вперёд контента: зона
печатает источники, когда они есть, и молчит, когда их нет (строки «бонусы 0» не существует).

| Поле | Статус | Основание |

| `colonyBonuses` | публично | кубы колоний на тайлах |
| `hand` | **публично как ЧИСЛО** | `PublicPlayerModel.cardsInHandNbr` (`PlayerModel.ts:53`, сервер `ServerModel.ts:615`); док-рука показывает «закрытый веер + точный счёт» другого человека (`dockInspection.ts:33–57`: «The fan NEVER consumes the private card list»); `hand` = `player.cardsInHand.length` из того же источника. Список карт в модель Парламента не попадает вовсе |

Мест, где чужой размер руки **намеренно скрыт**, в консоли нет — он штатно виден в доке. С оговоркой: `hand`
не включает карты, удержанные в незавершённом интейке (комментарий `ParliamentModel.ts:123–129`) — это то же
число, что прочтёт шаг, и оно не больше публичного.

**Вывод:** ничего приватного; все поля УЖЕ уходят каждому клиенту для каждого места (модель не гейтится по
зрителю), так что показ ничего нового не раскрывает — он лишь рендерит то, что на проводе.

## 4. Задача A — чужие исходы на панели голосования

### 4.1 Какие кнопки действительно свободны в режиме голосования

Цепочка ввода: `ConsoleShell.handleIntent` → (Информация, если открыта) → **Y = «Информация» на ЛЮБОЙ
поверхности** (`ConsoleShell.vue:12227`, до всех секций) → … → `handleSectionIntent` →
`ConsoleParliamentSection.handleIntent` (диспетчер в `ConsoleShell.vue:13389`; секция — `:1022–1133`) → в стадии
`vote`: `handleStageIntent` → B закрывает режим,
остальное — `ConsoleParliamentVoteMode.handleIntent` (`:550–569`), который обрабатывает ТОЛЬКО `nav left/right`,
`inspect` (X) и `primary` (A). Всё прочее молча падает.

| Контрол (семантика `glyphSets.ts`) | В режиме голосования | Занят где-то рядом |
| --- | --- | --- |
| `confirm` (A) | «Отправить делегата» | — |
| `back` (B) | «Назад» (сворачивает режим) | — |
| `secondary` (X) | «Осмотреть» (три карты, LB/RB листают) | — |
| `inspect` (Y) | **занята шеллом: «Информация»** | везде |
| `bumperL/R` (LB/RB) | **свободны** (доходят, игнорируются) | в осмотре — листание карт; в обзоре Парламента — нет; в Информации — «Игроки» |
| `triggerL/R` (LT/RT) | свободны | колёса на доске; «Сценарий» на Полигоне; ±5 в оплате |
| `stickL` (L3) | свободна | «Источник» в мастерских; на Полигоне — «Победитель» |
| `stickR` (R3) | свободна в режиме | в обзоре Парламента — «Осмотреть принятую» |
| d-pad ▲/▼ | свободны | ◀/▶ — выбор карты |
| `view` | свободна | «Сброс» фильтров в журнале |

**Выбор по семантике: LB/RB.** Концепт (`docs/CONSOLE_MODE_CONCEPT.md` §11): бамперы — «движение между
соседними панелями одного контейнера»; в этом форке это КОНКРЕТНО «Игроки»: Информация
(`ConsoleInfoMode.footCommands`: `{control: 'bumperL', control2: 'bumperR', label: 'Players'}`), «Разыграно»,
обзор хода бота (`cycleInspectedPlayer`). Переключение МЕСТА, чей исход читается, — ровно этот жест. Конфликт с
осмотром (там LB/RB листают карты) — тот же, что уже отгружен в Информации (LB/RB игроки → X осмотр → LB/RB
карты): вложенная поверхность переопределяет бамперы. ▲/▼ свободны, но d-pad — навигация по объектам, а
полоса чипов горизонтальна и ◀/▶ уже выбирают карту. LT/RT — «тот же ось, быстрее», не «другой субъект».

### 4.2 Сколько места есть на самом деле (это исходное условие)

Режим голосования = ряд карт + панель фиксированной высоты (`console_parliament_vote.less:53`); карты упёрлись
в `MAX_VOTE_ZOOM` на всех профилях, вертикального запаса нет (`docs/TURMOIL_REDUX_PARLIAMENT_VOTE_ONE_NUMBER.md`
§4). Панель — две колонки: чтение · голос.

| | 1080 (`console_parliament.less:149`) | Deck (`:1283`) | TV 4K (`:1393`, логич. px) |
| --- | --- | --- | --- |
| `--con-parl-info-h` | 9.9rem = 198 px | 8rem = 160 px | 10.6rem = 212 px |
| Колонка голоса | 22rem | 17rem | 24.5rem |
| Бокс партии в колонке чтения | 13rem | 9rem | 17.5rem |
| Блок чтения / графика / чтения (max, замер «одна цифра») | 155 / 133 / 70 | 128 / 88 / 94 | 171 / 112 / 38 |

Следствия: (а) **пять полных блоков чтения** (по одному на место) на панель не встают ни на одном профиле;
(б) под ОДНОЙ строкой чтений на 1080 и TV есть запас высоты до высоты графики (133 − 70 и 112 − 38 px), на Deck —
нет (чтения 94 > графика 88); (в) третья колонка шириной с бокс партии сжала бы чтения ниже измеренного минимума
(на Deck чтения Climate с двумя суффиксами уже переносятся на 2–3 строки; на TV им нужно до ~700 логических px).
Значит любое решение либо занимает **одну строку под чтением** (1080/TV), либо на Deck **занимает место
графики** — прецедент есть: «the formula graphic steps aside (the selected card right above prints the very same
graphic)» (`console_parliament_vote.less`, комментарий HANDHELD).

### 4.3 Варианты

| Критерий | В1 · субъект на той же панели (LB/RB) | В2 · сводка по всем местам + разбор по требованию | В3 · зона в осмотре по X | В4 · мини-сводка под КАЖДОЙ из трёх карт |
| --- | --- | --- | --- | --- |
| Место | 0 (тот же блок) | 1 строка чипов под чтением (1080/TV); место графики на Deck | правая колонка правил на TV/Deck «не вмещает ни строки» (§6 док «одна цифра»); подвал занят статусом · фактами · чтением · леджером · реакциями · победителем | +1.4rem к хрому каждого слота → карты уменьшаются ~6 % на всех профилях |
| Нажатий до «кому выгоднее» | N−1 + сравнение в уме — **проигрывает** | **0** (для выбранной карты); ◀/▶ — для остальных двух | 1 (X), но осмотр — про КАРТУ, а не про стол | 0 для всех трёх карт сразу |
| Полный разбор чужого | да, тот же блок | по требованию (ярус 2 = В1) | да, если влезет | нет |
| TV | ок | ок (строка под чтением) | нет места | карты меньше |
| 720p / Deck | ок | строка вместо графики | нет места | нет запаса вообще |
| Бот | не в кольце (`participates=false`) | не в строке | — | — |
| Законы | риск «чужое выглядит как моё» — кикер и рамка обязаны сменить голос; «одна панель — одно чтение» соблюдается | соблюдается: одно ЧТЕНИЕ, а сводка — числа, не чтение | X = «осмотреть текущий объект»; исходы стола — не свойство карты | стабильность стола: ряд карт перефитится |
| Стоимость | ключи 3-го лица (§4.5) + состояние субъекта + бюджет | чистая функция чипов + LESS; без слов | новые блоки аннотаций + перепланировка подвала | фит карт, все e2e геометрии |

**В3 отклоняю**: осмотр уже на пределе плотности (блок «Ваш голос» пришлось перенести из правой колонки в колонку
партии), и он отвечает на вопрос «что это за карта», а не «что получит стол». **В4 откладываю**: это самый быстрый
ответ на сравнение ТРЁХ карт разом, но он платит размером карт на всех профилях, и его можно добавить потом, если
ярус 1 окажется недостаточным (замер решит). **В1 один — проигрывает по критерию скорости**, но как ЯРУС 2 внутри В2
он нужен: владелец требует «тот же честный разбор, что у себя».

### 4.4 Рекомендация — «леджер исходов», два яруса

**Ярус 1 (всегда, 0 нажатий).** Под чтениями выбранной карты, внутри `.con-parl__info-own` — одна строка
чипов, по чипу на каждое **участвующее** место в порядке `ParliamentModel.players` (тот же, что зона делегатов
и панель итогов; никогда не сортировать по выгоде — стол не переставляется под курсором): `[куб] +12 [иконка]`.
Первый чип — зритель, «[куб] вы +6». Число = **оценка при текущем влиянии** места, по эффекту — то же
`oneNumberYieldsOf(voteYieldsOf(resolution, model, color))`, что и большое чтение, через одну чистую
`ledgerChipOf(yield)`:

- плата (бюджеты): нетто «−3 M€» по `voteLevyOf(…, color)` (закон «−10 → +7 = −3»), плюс «+4 [произв.]»
  второй частью; горизонт производства чип НЕ печатает (это слова осмотра);
- уровневый срез (Plant Ban): «−7 [растение]»; у нормы — «0» тихим тоном;
- множитель (Colonial Affairs): «×2 [колония]»;
- пропущенная выплата (нет карты-держателя у этого места — `noRecipientCompactNoteOf(effect, playerView.players[i].tableau)`):
  «✕ 3 [иконка]» в тоне потери, как чип пропуска ленты (`con-iyield__out--lost`), — закон «ничего молча»;
- часть «победителю голосования» (`recipient: 'winner'`): число с существующим акцентом
  `con-iyield__who--winner`; чипа для тайла по порогу (Skyscrapers) — иконка тайла у мест, проходящих по
  влиянию (`tileGrantEligibility`).

Суффикс «если победит» на чипах не печатается — строка отвечает на «кому выгоднее СЕЙЧАС», а выигрыш — вопрос
яруса 2. Имена на чипах не печатаются: куб — язык Парламента (лента, лидер, зона делегатов с именами в шапке),
имя появляется в кикере при переключении. Бот (`participates === false`) в строку не попадает никогда.

**Геометрия.** 1080/TV: строка `flex-basis: 100%` в конце `.con-parl__info-readings` — высота блока =
max(графика, чтения + строка) = графика, панель не растёт (70 + ~22 < 133; 38 + ~26 < 112). Deck: строка
занимает **место графики** (`info-mech` уходит, карта над панелью печатает ту же графику крупнее) — иначе
Climate с двумя суффиксами перестаёт помещаться (94 + 18 > 116). Пять мест × два числа переносятся на вторую
строку — на 1080/TV помещается (70 + 44 < 133), на Deck ширина колонки графики (~245 px) даёт 3–4 чипа в ряд.
Арбитр — `tests/e2e/console-parliament-vote-fit.spec.ts` на трёх профилях по всем `*-vote` фикстурам
(`parliament-aquifer-assembly-six.json` подсказывает, что шестиместная фикстура уже есть — её `-vote` близнец
нужен для худшего случая).

**Ярус 2 (LB/RB).** Субъект большого блока чтения = `parliamentFlow.voteSubject: Color | undefined`
(undefined = зритель). LB/RB ходят по чипам строки (чип субъекта подсвечен), блок кроссфейдится
(`con-parl-xfade`, ключ `instance + subject`), и:

- кикер: «ДЛЯ [куб] ИМЯ ПРИ ПРИНЯТИИ» (новый ключ `For ${0} when enacted`, имя — display string; ключу нужен
  собственный `overflow: hidden; text-overflow: ellipsis; min-width: 0` — закон честной рейки);
- рамка блока: **не циан** (циан = «моё до коммита»); тихая белая рамка `rgba(255,255,255,.06)` + куб в кикере;
- суффикс победы для чужого: «+1 если победит · шаг ③» (новый ключ `if they win`, 3-е лицо; субъект уже назван
  кикером); `winnerForecastYield` уже считает по `seat.agenda` любого места;
- реакция партии, леджер колоний, тайл по порогу, заметки — те же функции по цвету субъекта и его публичному
  табло; ключи второго лица получают близнецов (§4.5);
- **столбец «ВАШ ГОЛОС», плата и A не меняются ни при каком субъекте** — A всегда отправляет МОЕГО делегата на
  ВЫБРАННУЮ карту (`submitVote` субъекта не читает). Это главный инвариант яруса 2, и его держит e2e.

Субъект **переживает ◀/▶** (сравнить, что получит Анна на каждой из трёх карт — идиома Информации «маршрут
переживает смену места»), и **сбрасывается на зрителя** при открытии режима, на границе коммита (`submitVote`:
посадка куба, счётчики и «Делегат поставлен» — про меня) и при закрытии. B не трогает субъект (боковой ход, не
уровень) — как в Информации.

**Осмотр (X) при чужом субъекте.** Подвал осмотра сегодня читает по `thisPlayer.color`
(`zoomResolutionYields/Levy/Ledger`, `ConsoleShell.vue:8722–8752`). Если панель показывает Анну, а X показывает
меня — это рассинхрон одной сцены. Рекомендую: запрос осмотра из режима голосования несёт `subject`, и подвал
читает чтение/плату/леджер по нему (кикер подвала — тот же «Для [куб] Анна»); **факты «Ваш голос» и глагол A в
осмотре остаются зрительскими** (голос — всегда мой). Развилка для владельца (§8.3).

**Командная панель.** Стадия `vote` в `parliamentCommands.ts:100` получает четвёртый чип
`{control: 'bumperL', control2: 'bumperR', label: 'Players'}` (существующий ключ, «Игроки»); ширину на Deck
проверяет `console-parliament-chassis-parity`.

**TV / 720p, итог.** TV: строка под чтением при .8rem-полу, чипы с кубами 11 px × `conUiScale` — читается с
дивана, потому что это числа, а не слова. Deck: строка вместо графики, чипы .7rem-числа; при 5 местах × 2 числа
— две строки в колонке графики. Ни один профиль не растит панель и не двигает карты (закон
`console-parliament-vote-geometry`).

### 4.5 Строки второго лица, которым нужны близнецы (цена яруса 2)

`For you when enacted` → `For ${0} when enacted`; `if you win` / `SUFFIX_HINT` → `if they win`;
`${0} of yours` (`LEVEL_IN_SUPPLY_KEY`) → `${0} theirs`; `You have no colonies` (`COLONY_LEDGER_EMPTY`) →
`No colonies`; подписи тайла по порогу `Yours at influence ${0} — win or not` / `Only if you win — …`
(`tileGrantCaptionOf`) → 3-е лицо. Безличные и переиспользуемые как есть: `Not enough M€ for the levy`,
`No card can hold animals`, `Everything above the limit is taken`, `${0} in hand`, `nothing to lose`. Всё —
НОВЫЕ ключи (инвариант 9), канон RU — в глоссарий §2 («если победит») и `parliamentGlossary.spec` CANON; плюс
запрет: строка чужого субъекта не содержит «вы/ваш» (BANNED-паттерн на ключах семейства `theirs`).

## 5. Задача B — политическая зона в Информации

**Место в ряду.** `INFO_SUMMARY_COLUMNS` (`infoRoute.ts:215`): колонка 3 = `['actions', 'effects', 'campaign',
'botdoor']` → `['actions', 'effects', 'parliament', 'campaign', 'botdoor']`. Существование зоны — факт ИГРЫ
(`playerView.game.parliament !== undefined`, через `InfoZoneContext.parliament`, как `campaign`), маршрут
`parliament` применим только к `human` (`infoRouteApplies`). Бот: зона **присутствует** (геометрия общих зон не
сдвигается — она и так в человеческой колонке) и печатает одну спокойную строку — существующий ключ `MarsBot
takes no part in the parliament`; не фокусируется (нет маршрута → нет A — закон честности командной панели).
Имя зоны — **«ПАРЛАМЕНТ»** (существующий ключ `Parliament`): зона называется по мастерской, которую сводит,
как «Кампания». «Политика» в глоссарии не определена — не вводить.

**Сводка (на зоне, 3–4 строки как у соседей):**

```
ПАРЛАМЕНТ
Влияние                 3      ← ярко (mint), как «Доступно сейчас»
Повестка              шаг 5/12 · далее [РТ]
Делегаты              ● лобби · резерв ×4 · на резолюциях 2
Председатель                  ← только когда chairman
```

**Деталь (A → маршрут `parliament`, крошка «ИНФОРМАЦИЯ › Анна › ПАРЛАМЕНТ»), четыре секции без скролла:**

1. **ВЛИЯНИЕ** — «Повестка 2 + бонусы 1 = 3» (клиент: `influenceAtAgenda(agenda)` и остаток); v2 — источники
   поимённо (единственная серверная работа, §2). Иконка влияния — тот же бейдж, что на лицах резолюций.
2. **ПОВЕСТКА** — позиция маркера, уровень влияния трека, награда следующего шага («ДАЛЕЕ» + значок, канон §5
   глоссария) — маленькая графическая копия трека без чужих маркеров (все маркеры — на самом треке в
   Парламенте; дублировать весь трек не нужно).
3. **ДЕЛЕГАТЫ** — лобби ●/○, резерв ×n, на резолюциях: по каждому слоту стола «[эмблема] резолюция · ▢▢ n ·
   лидер?» (из `slots[].votes` по владельцу и `slots[].leader`).
4. **НА СТОЛЕ** — для каждой резолюции в области голосования: чтение этого игрока в грамматике панели
   («[влияние] 3 → +6 [иконка] · +1 если победит»), реакция партии, заметки; для принятой — что
   **получено** этим игроком в последнем заседании (`enactedYieldsOf(…, color)` по `lastPhase.outcomes`).
   Это та же функция, что ярус 2 панели — **сходимость A и B**.

**Что НЕ дублировать:** эффекты партий и действие принятого закона — уже в зоне «Эффекты»
(`ConsolePartyEffectsStrip`); зона печатает только «доступ: k партий · действий использовано m»; задание
председателя с прогрессом всех — в правительстве Парламента; полный трек Повестки — в Парламенте.

**Одна модель.** `src/client/console/parliament/seatParliamentReading.ts` (чистая):
`seatParliamentReadingOf(model, color, tableau, {slots}) → {influence: {total, track, bonus}, agenda: {position,
next}, delegates: {lobby, reserve, onSlots: [...]}, chairman, access: {held: k, actionsUsed: m}, table:
[{instance, reading: VoteReadingVm}], enacted?: {…}}`. Панель голосования берёт `table[selected].reading` для
яруса 2 и проекцию `ledgerChipOf` для яруса 1; Информация — всё. Одна функция чтения — две поверхности;
`voteReadingOf` становится её частью с параметром субъекта (сигнатура уже такая).

**Вывод:** да, A и B лучше делать на одной модели, чем двумя решениями. Но зона Информации — НЕ механизм
задачи A: Y открывает оверлей поверх голосования (это контракт Информации, а не «модалка переключения»), два
нажатия до чужого разбора, и он не в зоне голосования. Она — второе окно той же модели для тех, кто сравнивает
вне голоса.

## 7. Риски и что может пойти не так

- **Этого может оказаться слишком много для одного экрана** — честно: панель уже на пределе (§4.2). Поэтому
  ярус 1 — только числа, без единого слова, кроме «вы»; на Deck он занимает место графики. Если и это не встанет
  (шесть мест × три числа), запасной ход — на handheld печатать по одному числу на чип (сумма частей одной
  валюты) и говорить об этом в осмотре, а не молчать.
- **Бюджет слов** (`VOTE_INFO_LIMITS.words = 28`, по RU-словарю): имена в кикере — display strings, но
  `countWords` считает и их. Гард должен исключать raw-параметры, иначе двусложное имя валит каталог.
- **«Чужое выглядит как моё»** (ярус 2) — главный UX-риск: кикер с кубом и именем, некиановая рамка, чип субъекта
  подсвечен, «ВАШ ГОЛОС»/A неизменны, сброс на границе коммита; e2e утверждает, что при чужом субъекте кикер
  никогда не читается «Для вас».
- **Строки второго лица разбросаны** по пяти модулям (§4.5) — пропущенный ключ прочитается «У вас нет колоний»
  про Анну. Гард BANNED на ключах семейства субъекта закрывает это статически.
- **Осмотр по субъекту** тянет состояние в `consoleCardZoom` (запрос несёт цвет); если владелец откажется —
  X при чужом субъекте покажет моё чтение, и это надо прямо сказать в кикере подвала.
- **Перф — не риск:** `voteInfo` уже пересчитывается при каждом объекте модели; добавка — N ≤ 5 мест × M ≤ 3
  эффектов чистой арифметики + ≤ 5 `holdsAnyOf` по публичным табло (`getCard` — мапа). DOM — ≤ 6 чипов. Ярус
  2 рендерит ОДНО чтение, как сегодня. Кэшировать нечего; в перф-режиме ничего не меняется.
- **Форкаст «если победит» для чужого** — это сценарий «он выигрывает», а строка показывает «сейчас»: два
  вопроса, и их нельзя смешать в одном чипе. Оставляем форкаст ярусу 2 и осмотру.
- **Фикстуры**: `*-vote` фикстуры в основном на два места; худший случай (шесть мест, Climate/Budget) нужен
  как своя фикстура, иначе гард обрезания не увидит переноса на вторую строку.
- **Глоссарий**: «Игроки» как подпись LB/RB в Парламенте — общеконсольное слово, не парламентский термин;
  если владелец захочет «места» — это новый ключ и строка глоссария.
