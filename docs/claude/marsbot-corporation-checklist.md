# Добавление новой корпорации MarsBot — чеклист

Пошаговая процедура. Контракт подсистемы: `docs/claude/marsbot-corporations.md`. Официальные данные и трактовки: `docs/AUTOMA_DATA_AUDIT.md` §10. Реализованные образцы: **C01 Credicor** (эффект + драфт-приоритет), **C02 Ecoline** (своя бонус-карта B23 + ресурс на карте), **C03 Helion** (кубы на треках), **C04 Interplanetary Cinematics** (эффект на каждое продвижение трека + белые маркеры-напоминания), **C05 Inventrix** (уничтожение карты бонусной колоды на сетапе + своя recurring-карта B25, чья лестница общая с B06), **C06 Mining Guild** (банк M€ на карте, перехват дохода бота в `Stock.add`), **C07 PhoboLog** (посев проектных карт в бонусную колоду + кубы, тянущие из неё), **C08 Saturn Systems** (триггер по обеим сторонам стола + tag-chain приоритет), **C09 Teractor** (целиком из готовых примитивов + общая выплата за продвижение), **C10 Tharsis Republic** (триггер на размещение города с обеих сторон), **C11 ThorGate** (кубы + карта по первой метке), **C12 UNMI** (+B31 в бонусной колоде, размен бонусных карт), **C13 Cheung Shing Mars** (серебряные кубы по всему треку), **C14 Point Luna** (кубы одного трека двигают другие), **C45 Spire** (стартовая метка + ресурс + Before-Action-Phase).

Правило `.claude/rules/marsbot-corps.md` загружается само, когда трогаешь `src/server/automa/corps/**` — этот файл его полная версия.

## 2. Поведение (`src/server/automa/corps/MarsBot<Name>.ts`)

Co-located файл, реализующий ТОЛЬКО те хуки, что печатает карта:

- [ ] `setup?` — бокс SETUP (кубы объявляются данными, здесь только то, что данные выразить не могут).
- [ ] `beforeActionPhase?` / (Round Start — при появлении первой такой карты добавить хук в `MarsBotCorp`).
- [ ] `onProjectCardResolving?` — «When resolving a card …»: срабатывает ДО обработки меток, Failed Action его не гасит.
- [ ] `onTrackCubeTrigger?` — эффект куба; вернуть `'replaces-action'` ТОЛЬКО если карта явно говорит «instead of».
- [ ] `onTrackAdvance?` — «когда бот продвигает такой-то трек»: срабатывает на КАЖДЫЙ успешный шаг (каскад платит по шагам, maxed = Failed Action и не платит).
- [ ] `onMegacreditsGained?` — «когда бот получает M€»: диспатчится из `Stock.add`, срабатывает на ЛЮБОЙ доход (клетка, покрытые иконки, Failed Action, чужой корп-эффект); хук реентерабелен — то, что он делает, может дать боту ещё M€.
- [ ] `resolveBonusCard?` — своя B-карта (см. §3).
- [ ] Подача: эффект внутри хода — `game.events.beginEffect(bot, {kind:'corporation', card: this.info.original, owner: bot.color}, 'automa-corporation')` + `AutomaTurnLog.setCause(game, {kind:'corporation'})` с восстановлением прежней причины (`getCause`); действие ВНЕ хода — `beginAction(..., {category: 'corporation-action'})`.
- [ ] Каждый значимый шаг — `bumpCorpStat(game, '<key>', n)`.
- [ ] Физику брать из общих примитивов (`AutomaTilePlacer`, `AutomaTerraformer`, `drawAndResolveProjectCard` из `AutomaCardDraw.ts`, `AutomaResolver.advanceTrack`) — они уже несут TR, бонусы клеток, триггеры человека, Failed Action и журнал. Никогда не мутировать поля напрямую (`stock.add` / `production.add`).
- [ ] **Боту нельзя показывать промпт.** Любая «развилка» решается детерминированно или seeded-rng (`game.rng` / `pickVictim`).

## 4. Примитивы — использовать существующие, расширять только по факту

| Механика карты | Что уже есть | Что делать |
| --- | --- | --- |
| Draft Priority | `mostExpensive` · `mostTags` · `tags` (цепочка) · `leastAdvancedTrack` | взять готовый тип; НОВЫЙ тип = case в `MarsBotDraftResolver.scorerOf` + `savedFromDiscard` |
| Кубы на треках | `trackCubes` (адрес трека = ТЕГ) + `corpCubesTriggered` + `onTrackAdvanced` | объявить кубы + `cubeLegend`; UI и spent-once работают сами. Много кубов подряд — генерировать `Array.from` прямо в данных (образец C13: #4…конец трека). **Легенда куба рендерится БЕЗ параметров** — число вписывать в текст |
| Эффект на каждое продвижение трека | `MarsBotCorp.onTrackAdvance` + `MarsBotTrackPayout` (образцы C04, C09) | объявить `TrackPayout` (треки ТЕГАМИ, сумма, шаблон журнала, счётчики) — физика общая; триггер по ТРЕКУ ловит и «чужие» метки того же трека (город на треке Земли) |
| Маркер-напоминание на треке (SETUP «replace the tracker…») | `whiteMarkerTracks` + `markerLegend` → `MarsBotTracks` | объявить ПАРУ (гард в `MarsBotCorpData.spec.ts`); игрового эффекта нет, но на планшете это видно |
| Своя бонус-карта (B22–B32) | `corpBonusCards` + `resolveBonusCard` + `BonusCardData` | добавить текст/`buildBonusCardView`-ветку; **recurring** — через `recurringBonusCards` (образец B23/B25); **разовая в общей ротации** — просто замешать в `bonusDeck` (образец B31), тогда она живёт как обычная бонусная карта |
| Карта бонус-колоды уничтожается на сетапе | **`corps/MarsBotBonusDeckOps.destroyBonusCard`** (C05, C21) | вызвать его — трёхместная чистка и отдача бонусного слота колоды 1-го поколения уже внутри; карта пишет только свою строку журнала |
| Печатная ветка, повторяющая другую карту | общий модуль (образец `AutomaNearBonusPush` для B06/B15/B25) | физику вынести в ОДИН модуль, карте оставить её судьбу и её fallback — иначе две копии правила разойдутся То же для ДВУХ КОРПОРАЦИЙ с одним эффектом (C14+C19 → `MarsBotCubeTrackPush`): общие также i18n-ключи текста, НО НЕ факт инсайта — у каждой свой голос. Прогнать спек СТАРОЙ карты СРАЗУ после выноса. Позже модуль можно ОБОБЩИТЬ, а не копировать (C23: белый куб → трек растений вместо wild-правила) — цель/ключ/счётчики становятся ДАННЫМИ (`pushes`), а карта со СВОЕЙ фразой обязана иметь СВОИ i18n-ключи |
| Ресурс на карте корпорации | `resource` + `corpResources` + капсула `.pcard__res` | объявить `resource`; НОВЫЙ вид хранимого — это член `MarsBotCorpResource` + свой case в `corpResourceSocket` (резолвер ИСЧЕРПЫВАЮЩИЙ с `never`-гардом — без case не соберётся, а не нарисует молча серый куб). Для НЕ-card-resource (растения, M€) в этом же case даётся `iconUrl`; корпусный гард — «EVERY printed storage kind paints a real icon» в `MarsBotCorpFace.spec.ts` |
| Карта НАКАПЛИВАЕТ M€ (касса) | `corpResources` + `resource: 'megacredits'` + хук `onTrackAdvance` (образец C20) | это ОБРАТНАЯ сторона банка C06: карта начинает ПУСТОЙ и наполняется, бот до съёма НЕ получает ничего. Триггер общий, но `MarsBotTrackPayout` НЕ брать — его контракт «бот ПОЛУЧАЕТ». Формулировка съёма: «N, or as much as possible» = ЧАСТИЧНО (третья после «up to X» и «X, if able») |
| Перехват ДОХОДА бота (M€) | `mcBank` + `onMegacreditsGained` (образец C06) | точка одна — `Stock.add`; слив писать циклом (доход может опустошить карту несколько раз) и помнить о реентерабельности: продвижение само может заплатить боту |
| Посев проектных карт в бонусную колоду | **`corps/MarsBotBonusDeckOps.seedBonusDeckFromProjectDeck`** + `bonusDeckSeed` (C07, C21) | раскрытие общее; различается только ДИСПОЗИЦИЯ, и она объявляется ДАННЫМИ (`bonusDeckSeed.shuffle`: `'all-revealed'` — «shuffle THESE cards», `'matching-only'` — «shuffle IT»). Колода типизирована союзом `AutomaActionCard`; новая точка розыгрыша ОБЯЗАНА ветвиться по `entry.kind` |
| Реакция на МЕТКУ бота | `onTagResolved` (образец C08) | диспатч из `AutomaResolver.resolveTag`, ПОСЛЕ работы метки; стартовые метки идут тем же путём («including this» бесплатно) |
| Реакция на карту ЧЕЛОВЕКА | `onHumanCardPlayed` (образец C08) | диспатч из `Player.onCardPlayed`; гранулярность у сторон может быть РАЗНОЙ — читать печатный текст буквально (карта против метки) |
| Реакция на РАЗМЕЩЕНИЕ тайла | `onTilePlaced` (образец C10) | диспатч из `Game.addTile` — через него идут ОБЕ стороны; тип тайла проверять движковым предикатом (`Board.isCitySpace`), а не списком `TileType` |
| Карта разыгрывается ЧАСТИЧНО | `resolveProjectCard(..., {tagLimit})` (образец C11) | ограничивать ТОЛЬКО продвижение треков; карта всё равно играется целиком (журнал, played pile, оба диспатча), иначе сломаешь human-реакторы RB-B |
| Корпорация делает ЧУЖУЮ бонусную карту постоянной | чистка трёх мест (C05) + `recurringBonusCards` (образец C17/B04) | `corpBonusCards` НЕ трогать (карта базовая, её резолв остаётся в `AutomaBonusCards`); если карта может УНИЧТОЖАТЬСЯ — проверить, что `routeBonusCard` выкидывает её из recurring-пула, и перепроверить `destroyedBonusCards` в самом боксе |
| Корпорация ставит МАРКЕР (бронь) на карту | `AutomaMarkerPlacer` + `AutomaTilePlacer.breakTie(…, beforeFlip)` (образец C18/B22) | запрет для чужих уже бесплатен (`space.player`); выплата за стройку на своём — через `onBuildOnOwnMarker` (та же строка `Game.addTile`, никакой второй выплаты); ОБЯЗАТЕЛЬНО положить клейм в `MarsBotTurnVisual.markers` и красить его в `applyTurnVisual` ПОСЛЕ `armPlacementAnimations()` — иначе куб всплывёт без премиального `pc-place` |
| Эффект на НОВУЮ ГРАНИЦУ между застройками | `onTilePlaced` + подсчёт соседств НОВОГО тайла (образец C22) | нов только один тайл — значит новы ровно его границы, пересчёт доски не нужен. Бесхозный тайл (океан) — ничей: так читает ту же фразу человеческая карта. Маркер (C18) — не тайл. Каскад (продвижение → тайл → граница) законен, но счётчик глубины — В МОДУЛЕ, не в `corpStats` |

| Бот ставит ОСОБЫЙ ТАЙЛ из своей стопки | `marsLandTileFor` в `MarsBotPhilares.ts` (образец B27) | классификация ВЫВОДИТСЯ (`isSpecialTile` + `tileTypeToString` + `OCEAN_TILES`), таблицы бот-правил нет; собственные требования карты не проверяются (RB-B), гарант — спек-ворклист |

Сумма, условия выбора, `choiceContext` и атрибуция — бесплатно и без дрейфа. ⚠️ промпт игрока ОСТАНАВЛИВАЕТ очередь — спек обязан ответить и слить её снова |
| Микробное продвижение без метки (клетка 9 Венеры) | `onMicrobeAdvancement` (образец C24) | RB-B FAQ: «as if a card with a microbe was played». Диспатч ТОЛЬКО с той клетки; стартовая метка идёт через `onTagResolved` и туда НЕ должна попадать — иначе двойная оплата |
| Корпорация набирает ПО в конце игры | `endgameVictoryPoints` + терм `corpVp` (образец C25) | хук ЧИСТЫЙ: считается из состояния в момент подсчёта, никакого параллельного талли. | Условие модуля через «ИЛИ» | `requiresAnyModule` (образец C25) | отдельное поле от `requiresModules` («И»). Гард в `MarsBotCorpData.spec` обязан проверять ОБЕ формы — забытая форма равна непроверенному условию |

| Коробка ROUND START | `roundStart` + маркер `corpRoundStartGeneration` (образец C26) | диспатч из `Game.gotoResearchPhase` ДО фазы, РАЗ ЗА ПОКОЛЕНИЕ (форма `corpBapGeneration`) — коробка, платящая ресурс, не смеет сработать дважды после релоада/отмены. Поколение 1 её НЕ видит. Тестить НАСТОЯЩИЙ переход (`forceGenerationEnd`), а не только диспетчер |
| Печатный ПРОБЕГ клеток с пропуском | выписать позиции ПОШТУЧНО в `trackCubes` (образец C27: #5–#9, #11, #12 — #10 пуста) | никаких генераций диапазоном — она тихо выдумает лишний куб. Гард в спеке фиксирует именно ПРОПУСК, а не только количество |

Печатная норма может зависеть от ПОКОЛЕНИЯ (`game.generation`) — граница печатная, не угаданная, и на неё нужен тест по обе стороны. Карту НЕ называть в журнале — только счёт |

Спрашивать ДО проверки «а можно ли» — заменённое действие не Failed Action. Гарантия покрытия — сквозной тест по каждому пути, не grep |

Тест утверждает ИНВАРИАНТ чередования, а не «каждый второй по счёту»: оплаченный шаг может сам выложить тайл-триггер |

| Коробка УБИРАЕТ карту из колоды действий | `beforeActionPhase` + `printedTagCount` + `projectDeck.discard` (образец C32) | ценность карты для бота = число печатных меток; БОНУСНАЯ карта в выборе НЕ участвует (у неё нет ряда меток, а не «мало»). Гард: `cubeLegend.black === cubeLegend.white` |
| Клетка УЖЕ разрешена («after resolving the effect…») | `onTrackSpaceResolved` (образец C29) | «after»-близнец `onTrackAdvance`: тот ДО печатной иконки, этот ПОСЛЕ неё и всего каскада — формулировка карты выбирает хук. Триггер — ПРИЗЕМЛЕНИЕ (`landed` снят ДО иконки, которая могла унести маркер), толчок — обычный `advanceTrack` ОТ ТЕКУЩЕЙ позиции. `depth + 1` ПЕРЕДАВАТЬ обязательно — иначе общий гард каскада начнёт счёт заново |
| Напоминание на КОЛОНКЕ (SETUP ºbove the #N columns») | `reminderColumns` + `columnLegend` → `MarsBotTracks` (образец C29) | примитив C04/C20, повёрнутый на 90°: колонка пересекает все треки, поэтому разрешение по доске НЕ нужно и нового поля в `MarsBotCorpModel` не появляется — клиент читает данные напрямую. Объявлять ПАРОЙ (гард в `MarsBotCorpData.spec.ts`); легенда — без параметров |
| Триггер на ГЛОБАЛЬНЫЙ ПАРАМЕТР | `onVenusIncreased` (образец C28) | диспатч из единственной точки входа и РЯДОМ с выплатой человеческого близнеца: ПОЗИЦИЯ в функции есть правило (вне solar-гарда = печатная скобка про Government Intervention). Гранулярность — у близнеца |
| Карта требует МОДУЛЬ («only when playing with …») | `requiresModules` + `AutomaCorporations.hasRequiredModules` (образец C16) | объявить модуль ДАННЫМИ — корпорация выпадает из пула сама (и dev-форс её не посадит); НИКОГДА не проверять модуль внутри хуков. Гард в `MarsBotCorpData.spec.ts` ловит условие на модуль вне играбельного набора |

## 6. Статистика и endgame-инсайт

- [ ] Ключи статистики бампятся в поведении и описаны в `MarsBotCorpStats`.
- [ ] Ветка в `analyzeBotCorporation` (`src/client/components/endgame/insightEngine.ts`) с ПОРОГОМ значимости (инсайт молчит, если корпорация ничего не решила) + RU-ключ текста. **Историй может быть НЕСКОЛЬКО**: если печатные боксы меряют независимые вещи (образец C05 — налог на требования и толчки от B25), пушить отдельную story на каждую со своим порогом и своей фразой — склеивать их в одно предложение через `||` нельзя (предложение начнёт с половины, которая ничего не сделала). Селектор (`selectStoryInsights`) дедупит по КЛАСТЕРУ на банду, так что вторая история уходит в secondary/«показать ещё», а не теснит остальные.

Число в заголовке = то, что игрок видел (у C07 — внеплановые розыгрыши, не «попадания в кубы»). Начинать каждую фразу одним шаблоном «Корпорация X у Y…» тоже нельзя — это витрина финала, у каждой корпорации свой голос (примеры: C01 «мегапроекты кормили…», C04 «камеры не выключались…», C06 «прибыль не залёживалась…»).

## 10. Красные линии

- **Никогда** не наследовать правила human-корпорации (стартовые M€, first action, human-теги, скидки) — оригинал даёт только идентичность/арт/лор/коллизию.
- **Никогда** не добавлять `switch (corporation)` вне `AutomaCorporations`.
- **Никогда** не выдумывать правило при неоднозначности: сверить с картой → RB-B → зафиксировать вывод комментарием + тестом; иначе спросить владельца.
- Новое сериализуемое поле — опциональное, старые сейвы деградируют молча (`?? default`).
- Легаси-сейв без корпорации остаётся corpless навсегда (гард `generation === 1`).

### Типовые ловушки (оплачены отладкой)

1. **Данные не могут импортировать серверные константы** — трек в `trackCubes` адресуется ТЕГОМ, не индексом `THARSIS_TRACK`.
2. **Статический импорт `PremiumCard.vue`** в потребителя цепочки `CardZoomModal → CardZoomCard` замыкает type-cycle и обрушивает `vue-tsc` в `{}` — использовать глобальный `premium-card-face` (в юнит-тесте регистрировать локально).
3. **Куб/эффект помечается сработавшим ДО выполнения** — эффект может каскадом вернуться на тот же трек.
4. **e2e-текст `.pcard` и кикеров — регистронезависимо** (`text-transform: uppercase` попадает в `innerText`).
5. **Счёт визуальных элементов в e2e скоупить** (легенда кубов рисует свои свотчи тем же классом, что и мат).
6. **Деталь «Планшет бота» открывается R3** (`KeyV`), не LT.
7. Тёмный элемент на тёмном мате нуждается в тёмном ТЕЛЕ и холодном ободе — светлый обод превращает чёрный куб в белый.
8. **Легенда куба и текст секции — РАЗНЫЕ i18n-ключи** («onto it» против «onto a white cube»): переводить оба; гард покрытия в `MarsBotCorpData.spec.ts`.
9. **`preludeExtension: true` обязателен в фикстуре корпорации с `requiresModules`** — иначе боту тихо выдадут ДРУГУЮ корпорацию; а e2e такой игры не пройдёт визардом — прелюдии выбирает только API-драйвер (`bootSeededGame`), а не `bootToBoard`.
