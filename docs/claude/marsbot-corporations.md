# MarsBot corporations — the production framework (RB-B «Adding Corporations»)

**Status: production (2026-08-19).** Реализованы **C01–C36 + C38 + C39 + C40 + C45 + C46**; ЖИВОЙ список — `MARS_BOT_CORP_IDS` в `AutomaTypes.ts` (он же порядок карт), а что именно печатает каждая — таблица `docs/AUTOMA_DATA_AUDIT.md` §10. Здесь перечисляются только ПРИМИТИВЫ, а не карты: каждая секция ниже названа механикой и помечена корпорацией, которая её ввела. Официальные данные и трактовки: `docs/AUTOMA_DATA_AUDIT.md` §10 (RB-B транскрибирован полностью). Дизайн-референс upstream-типов: `docs/AUTOMA_CORP_FRAMEWORK_REFERENCE.md` (историческая записка — реализация НЕ по его фасаду).

## Модель

Корпорация бота — **отдельная игровая сущность**, никогда не human-карта с изменёнными числами. Оригинальная human-корпорация даёт ровно четыре официальные связи: имя/логотип, арт, лор, ключ коллизии при выборе (`original: CardName`). Ни одно human-правило (стартовые M€, first action, human-теги, скидки) через эту ссылку не протекает.

| --- | --- | --- |

**Добавление корпорации N+1**: строка в enum → запись данных в `MarsBotCorpData` → файл поведения → строка в `REGISTRY` → RU-ключи → спек. Ни один switch за пределами registry не растёт; UI/сериализация/статистика подхватывают автоматически.

## Тайминг (ONE gate)

`Game.playerIsFinishedWithResearchPhase` — единственный research→action переход (все поколения). Там `AutomaCorporations.onActionPhaseStart`:
- **gen 1**: выбор корпорации (случайный seeded из eligible; dev-override если eligible) — строго ПОСЛЕ розыгрыша корпораций всех людей (RB-B Setup 1) и ДО прелюдий (фаза PRELUDES вложена в первый ход) → Setup box → starting tags «как у вскрытой карты» (`AutomaResolver.resolveTag`; трек двигается, действия клеток срабатывают — Earth[1]='city' у Spire реально ставит город; позиция трека = перманентный «tag count» бота);
- **каждое поколение** (включая 1-е): Before-Action-Phase box, гард `corpBapGeneration`.

Пустой eligible-пул — invariant error (Spire всегда eligible: её human-двойник требует Prelude 2, конфликтующий с ботом). Легаси-сейв без корпорации, ушедший дальше 1-го поколения, живёт corpless (гард `generation === 1`); все его пути (random-драфт, discard shuffle-first) байт-идентичны прежним.

## Драфт (RB-B)

Pick: приоритет корпорации; равные → случайно (seeded), нет совпадений → случайно. Дискард: shuffle → первый НЕзащищённый уходит; защищено всё → сброса нет → **колода действий из 5 карт** (никаких `length === 4` assumptions). «Most tags» = печатный ряд `AutomaResolver.printedTags` (event-метка и wild считаются; исключение wild в RB-B скоуплено на tag-chain приоритеты). Corpless / без приоритета: официальный random + discard-first (rng-идентично старому коду).

## События / подача

- Эффект корпорации в ходе: `events.beginEffect(bot, {kind:'corporation', card: original, owner}, 'automa-corporation')` → journal + `corporationFacts` (passive-метрики) бесплатно; турн-скрипт получает cause `{kind:'corporation'}` → «Разбор хода» строит цепочку «Эффект корпорации» (`botTurnReviewModel`, id из архива).
- Вне хода (выбор, Spire-город): `beginAction(..., {category:'corporation-action'})` → нотификация «Corporation action» + журнальная группа.
- B23 — recurring-механизм B16-семейства (`recurringBonusCards`); gen-1 вставка seeded-random позицией в готовую колоду (идемпотентно, ровно одна копия навсегда).


## Кубы на треках (RB-B «Special Cubes on the MarsBot Player Mat»)

Primitive, введённый вместе с **C03 Helion** (первая корпорация с кубами):

- **Данные**: `MarsBotCorpInfo.trackCubes` — `{tag, position, cubeType}`. Трек назван ТЕГОМ (печатные карты говорят «the building track», «the Earth track»), сервер резолвит его через `board.getTrackIndexForTag` — куб переносим на любой планшет, где такой трек есть, и молча отпадает там, где его нет.
- **Состояние**: `AutomaState.corpCubesTriggered` (ключи `trackIndex:position`, сериализуются). Куб срабатывает РОВНО ОДИН раз за партию; регресс трека НЕ перевзводит сработавший куб (дословное правило RB-B).
- **Диспатч**: `AutomaCorporations.onTrackAdvanced(game, trackIndex, position, printedAction)` вызывается из `AutomaResolver.advanceTrack` после шага и ДО печатного действия; помечает куб сработавшим ДО эффекта (эффект может каскадом вернуться на тот же трек) и возвращает `true`, если корпорация ЗАМЕСТИЛА печатное действие. Хук корпорации: `MarsBotCorp.onTrackCubeTrigger(...) → 'replaces-action' | void`.
- **Порядок RB-B**: эффект куба — ДО и В ДОПОЛНЕНИЕ к печатной иконке, если карта явно не сказала «вместо». Helion: белый куб = `'replaces-action'` (все шесть стоят на печатной temperature — закреплено тестом), чёрный = +1 температура плюс печатная иконка.
- **Серебряный куб** (`'credit'`, введён в дело с C13): это печатный РЕСУРСНЫЙ куб, а не абстрактный жетон — бот забирает его «как M€» по номиналу компонента (кубы TM: 1 бронза / 5 серебро / 10 золото → `MARSBOT_SILVER_CUBE_MC = 5`, константа лежит в common рядом с типом). На мате он серебряный и подписан «Серебряный куб ресурса».
- **Модель + UI**: `MarsBotCorpModel.cubes` (`{trackIndex, position, cubeType, spent}`) → `MarsBotTracks` рисует куб в углу клетки (белый — светлое тело/тёмный обод, чёрный — тёмное тело/холодный обод, spent — гравированный контур) плюс **легенду** из `cubeLegend` (печатный смысл каждого цвета) и `data-hint` на клетке. Кубы — открытая информация: их видно и в console-детали «Планшет бота», и в desktop-оверлее.

## Эффект НА КАЖДОЕ продвижение трека + белые маркеры-напоминания

Primitive, введённый вместе с **C04 Interplanetary Cinematics**:

- **Физика выплаты — ОБЩАЯ**: `MarsBotTrackPayout.payForTrackAdvance` (вынесена при добавлении C09 Teractor). Карта объявляет `TrackPayout` — какие треки платят (ТЕГАМИ), сколько, как это называется в журнале и какие счётчики бампает; хук остаётся однострочным. Вопрос «мой ли это трек» — у корпорации, ответ (scope, M€, журнал, счётчики) — у общего модуля, поэтому одинаковое печатное предложение C04 и C09 не может разойтись.
- **Хук**: `MarsBotCorp.onTrackAdvance(game, trackIndex, position)` — вызывается из того же места, что и кубы (`AutomaCorporations.onTrackAdvanced`, из `AutomaResolver.advanceTrack`) после КАЖДОГО успешного шага и ДО печатной иконки. Соседство с кубами не случайно: оба говорят «бот только что встал на клетку», и оба обязаны отработать до того, как клетка сделает своё.
- **Что считается продвижением**: ровно один шаг. Каскад `advance` платит за каждый свой шаг; трек в максимуме (официальный Failed Action) не платит вовсе — диспатч туда не доходит; регресс ничего не «тратит» (это не куб). Всё закреплено тестами.
- **«Including the starting tags»** не требует спец-кода: `selectCorporation` сажает корпорацию (`automa.corporation = id`) ДО резолва Setup-бокса и стартовых меток, поэтому печатные метки идут через тот же хук.
- **Белые маркеры**: `MarsBotCorpInfo.whiteMarkerTracks` (список ТЕГОВ) + `markerLegend`. Это ЧИСТОЕ напоминание (карта так и говорит: «as a reminder»), у него нет игрового эффекта — но игрок, который смотрит планшет бота, должен видеть то же, что видит игрок за столом: `MarsBotCorpModel.whiteMarkerTracks` (индексы) → `MarsBotTracks` красит маркер текущей позиции этих треков белым кубом и добавляет строку легенды. Пара `whiteMarkerTracks`/`markerLegend` обязательна целиком — маркер без объяснения был бы украшением (гард в `MarsBotCorpData.spec.ts`).
- ⚠️ **ОДНА И ТА ЖЕ ПОМЕТКА НЕ ОЗНАЧАЕТ ОДИН И ТОТ ЖЕ ТРИГГЕР** (введено с **C31 Arklight**). C09 Teractor красит маркер и платит за ПРОДВИЖЕНИЕ трека — поэтому метка города, идущая по треку Земли, тоже платит, дословно как напечатано. C31 ставит то же напоминание на трек растений и платит за МЕТКУ, а по этому треку идут ТРИ метки, из которых платят две: печатное «(not microbe!)» существует ровно потому, что одно напоминание читалось бы как правило Teractor. Формулировка выбирает хук: «advances the track» → `onTrackAdvance` + `MarsBotTrackPayout`; «resolving a … tag» → `onTagResolved`. Взять здесь модуль выплаты за трек значит тихо оплатить микробов — гард: тест «продвижение трека само по себе не платит». И `markerLegend` обязана назвать исключение вслух, иначе на мате белый маркер обещает больше, чем платит.

## Уничтожение карты бонусной колоды на сетапе + общая «лестница ближайшего бонуса»

Primitive, введённый вместе с **C05 Inventrix**:

- **Destroy-at-setup**: `setup` находит нужную бонусную карту и убирает её ИЗ ИГРЫ (`destroyedBonusCards`), вычищая из `bonusDeck` и `bonusDiscard`. Гоча порядка: наш движок строит колоду действий 1-го поколения ПРИ СОЗДАНИИ игры, до появления корпорации, поэтому уничтожаемая карта может уже занимать единственный бонусный слот этой колоды — тогда слот отдаётся следующей карте бонусной колоды (за столом сетап-бокс отработал бы раньше и слот достался бы именно ей), и размер колоды не меняется. Печать выбирается по составу игры: «Лоббисты» это B06 без Венеры и B15 с ней.
- **Общая лестница** `AutomaNearBonusPush.pushNearestBonus(game, 'ocean' | 'venus')` — печатные варианты a/b/c карт **B06/B15 Lobbyists** и **B25 Do It Right** совпадают дословно, поэтому физика (и ключ ветки для обзора хода) живёт в ОДНОМ модуле; каждая карта владеет только своей судьбой и своим (d). Одна реализация = один ответ на правило «1–2 шага до бонуса» для обеих карт.
- **«No effect» — печатный исход, а не Failed Action.** Компенсацию 5 M€ бот получает, когда попытался и не смог; карта, которая печатает «d. No effect», просто ничего не делает (закреплено тестом).

## Банк M€ на карте корпорации (перехват дохода бота)

Primitive, введённый вместе с **C06 Mining Guild**:

- **Данные**: `MarsBotCorpInfo.mcBank = {size, trackTag}` — сколько кладётся на карту и какой трек двигается при опустошении (трек назван ТЕГОМ, как и кубы).
- **Точка перехвата ОДНА**: `Stock.add` (`delta > 0 && resource === MEGACREDITS && player.isMarsBot`) → `AutomaCorporations.onBotGainedMegacredits` → хук корпорации `onMegacreditsGained`. Доходы бота приходят отовсюду (клетки треков, покрытые иконки, компенсация Failed Action, эффекты других корпораций) — перехватывать их по местам было бы решетом. Прецедент слоя: `Production.add` уже держит automa-ветку.
- **Семантика «take it from this card instead»**: карта — РЕЗЕРВУАР, а не пошлина. Бот получает M€ как обычно (его баланс растёт), просто кубики берутся с карты; то, что карта реально конвертирует — доход в ТЕМП: каждые полные `size` M€ = одно бесплатное продвижение трека.
- **Слив — цикл, а не вычитание**: доход больше остатка опустошает карту, перезаправляет её, двигает трек и продолжает брать из свежей стопки (25 M€ при полной карте = 2 продвижения и 5 M€ на карте).
- **«#18» = КОНЕЦ трека** (`track.maxPosition`), а не литерал: продвижение никогда не становится Failed Action, а на конце эффект честно выключается — остаток дохода идёт из общего запаса.
- **Реентерабельность**: продвижение само может заплатить боту (покрытые иконки океана, компенсация Failed Action) и снова войти в слив. Перезаправка выполняется ДО продвижения, поэтому вложенный доход уже видит полную карту; есть счётчик глубины (`MAX_DRAIN_DEPTH`) как runaway-гард. Инвариант, закреплённый тестом: `banked === refills * size + (size − остаток)`.
- **Подача**: `resource: 'megacredits'` → штатная капсула `.pcard__res` с `iconUrl`-override на стандартную иконку M€ (M€ не `CardResource`, как и растения Ecoline).

## Смешанная бонус-колода (проектные карты внутри)

Primitive, введённый вместе с **C07 PhoboLog**:

- **Тип колоды**: `AutomaState.bonusDeck` стал `Array<AutomaActionCard>` — тем же союзом, что и колода действий (`{kind:'bonus', id}` | `{kind:'project', name}`). Старые сейвы хранили голые `BonusCardId`, десериализатор поднимает их до `{kind:'bonus'}` (закреплено тестом).
- **Посев**: данные `MarsBotCorpInfo.bonusDeckSeed = {tag, count}` — «вскрывать карты проектов, пока `count` из них не окажутся с меткой `tag`». **«Shuffle these cards» трактуется как ВСЕ вскрытые карты**: карта не называет иного места для остальных, а физическое вскрытие обязано куда-то их деть. Вскрытые карты названы в журнале — они ушли из колоды проектов, и человек имеет право знать какие.
- **Каждая точка розыгрыша решает по виду записи**: бонусный слот колоды действий поколения (`finishActionDeck`), прореживание B18 (проектная карта уходит в сброс ПРОЕКТОВ, не в бонусный), fallback B08 и белый куб C07 — все через `drawAndResolveBonusDeckCard` / собственную ветку. Проектная карта из бонусной колоды играется штатным путём (`resolveProjectCardForBot`) и попадает в played pile, а значит из бонусной ротации выходит навсегда.
- **Где живёт розыгрыш**: `AutomaCardDraw.ts` — тот самый модуль, что уже разрывает цикл для `drawAndResolveProjectCard`. Экспорты-функции TS присваивает в `exports` ДО своих `require`, поэтому взаимный импорт с `AutomaBonusCards` безопасен (использование только в вызовах).

## Триггер по ОБЕИМ сторонам стола (метка у человека и у бота)

**Третья точка — размещение тайла** (`MarsBotCorp.onTilePlaced`, диспатч из `Game.addTile` после фан-аута карточных `onTilePlaced`): через неё проходит ЛЮБОЕ размещение на Марсе, чьё бы оно ни было, поэтому C10 читает обе стороны одним хуком, а сторона игрока решает, какая половина эффекта срабатывает. «Город» — движковый предикат `Board.isCitySpace` (столица считается), никогда не рукописный список типов. «These effects also apply to setup» бесплатно: корпорация сажается до своего setup-бокса.

Primitive, введённый вместе с **C08 Saturn Systems**:

- **Две точки, потому что стороны разные**: `MarsBotCorp.onTagResolved` диспатчится из `AutomaResolver.resolveTag` (единственное место, где бот резолвит печатную метку — метки карт И стартовые метки корпорации), `MarsBotCorp.onHumanCardPlayed` — из `Player.onCardPlayed` (флипы бота туда не попадают by construction; в диспетчере всё равно стоит `isMarsBot`-гард).
- **Гранулярность у сторон РАЗНАЯ и ровно печатная**: «you play a CARD containing a Jovian tag» → одно срабатывание на карту (сколько бы меток на ней ни было), «MarsBot resolves a Jovian TAG» → на каждую метку (бот и обрабатывает карту по меткам, слева направо). Обе половины закреплены тестами, включая карту с двумя юпитерианскими метками.
- **Порядок**: хук бота вызывается ПОСЛЕ того, как метка отработала (её трек продвинулся, иконка клетки сработала) — триггер реагирует на завершившееся событие. Метка без трека на этом планшете (например венерианская без Venus Next) всё равно СЧИТАЕТСЯ разыгранной.
- **Рекурсии нет** по конструкции: награда ПРОДВИГАЕТ трек, а продвижение трека метку не резолвит (клетка `tag_N` двигает другой трек напрямую).
- Побочный эффект по правилам: трек бота может продвинуться посреди ХОДА ЧЕЛОВЕКА (и поставить тайл, взять РТ, объявить достижение). Это ровно то, что печатает карта; атрибуция идёт обычным corporation-scope.

## Ограниченный резолв карты (только первая метка)

Primitive, введённый вместе с **C11 ThorGate**: `AutomaResolver.resolveProjectCard(game, card, {tagLimit})` (прокинут через `drawAndResolveProjectCard` / `resolveProjectCardForBot`). Карта разыгрывается ПОЛНОСТЬЮ как событие — журнал «Бот сыграл …», played pile, корп-диспатч `onProjectCardResolving`, RB-B human-реакторы видят ВСЮ карту; ограничивается только то, СКОЛЬКО печатных меток двигают треки. Так читается «ignoring all except its first tag»: это про треки бота, а не про то, какая карта вошла в игру. Карта вообще без меток — по-прежнему Failed Action.

## Своя бонус-карта В КОЛОДЕ (а не в recurring-холдинге)

Введено с **C12 UNMI**: `corpBonusCards` объявляет владение (диспатч `resolveCorpBonusCard` + `corpOwningBonusCard`), но B31 не попадает в `recurringBonusCards` — сетап просто ЗАМЕШИВАЕТ её в `bonusDeck`, и дальше она живёт в обычной ротации (вскрытие → сброс → перетасовка). Это третий вид жизни корп-карты после recurring (B23/B25) и разового розыгрыша.

Там же — обратная операция к «раздаче»: «do not add a bonus card during setup» ОТМЕНЯЕТ уже розданную карту (движок строит колоду 1-го поколения при создании игры, до корпорации): карта возвращается в `bonusDeck`, колода действий становится на одну короче.

## СЕТАП-ОПЕРАЦИИ НАД КОЛОДАМИ — один модуль на всех

Вынесено при **C21 Pharmacy Union** (`corps/MarsBotBonusDeckOps.ts`). Две операции, каждая напечатана на ДВУХ картах:

- **`destroyBonusCard`** — «destroy the card X from the bonus deck» (C05 Lobbyists, C21 Meteor Shower). Три места, и третье тонкое: колода действий 1-го поколения строится ДО корпорации, поэтому обречённая карта может уже занимать её единственный бонусный слот — слот отдаётся следующей карте, размер колоды не меняется.
- **`seedBonusDeckFromProjectDeck`** — «reveal … until N cards carry TAG» (C07, C21). Раскрытие ИДЕНТИЧНО, различается только ДИСПОЗИЦИЯ, и именно она вынесена в ДАННЫЕ (`bonusDeckSeed.shuffle`): `'all-revealed'` (C07: «shuffle THESE cards») или `'matching-only'` (C21: «shuffle IT» — остальные уходят в сброс проектов — вскрытую карту надо куда-то положить).
- ЛОГИРУЕТ КАРТА, не модуль: какие карты ушли из колоды проектов — публичная информация, и каждая карта формулирует это по-своему.

## КОГДА ПРАВИЛО УЖЕ ЕСТЬ У ЧЕЛОВЕЧЕСКОЙ КАРТЫ — берём её трактовку

Закреплено на **C21**. Её эффект «when you play a microbe tag, lose 4 MC, or as much as it is able to lose» — это ДОСЛОВНО то же, что печатает человеческая Pharmacy Union, а движок уже её реализует.

- **Гранулярность берём у движка, а не из буквы бот-карты.** `PharmacyUnion.onCardPlayedByAnyPlayer` читает ту же фразу как РАЗ НА КАРТУ (`card.tags.includes(MICROBE)` — булево), и бот делает так же. Две сущности с одним правилом не должны расходиться — это то же правило, что заставило C18 ехать на выплате человеческой Arcadian.
- **А вот гранулярность ВТОРОЙ половины — из её СОБСТВЕННЫХ слов**: «a card WITH a science tag» → раз на карту (`onProjectCardResolving`), а не потеговый хук. Каждая половина читается ОТДЕЛЬНО.
- **«Including this»** = собственная стартовая метка: RB-B Setup 4 резолвит её «as if shown on a card revealed during play», то есть карта корпорации сама есть «карта с меткой науки». Поднимается РАЗ, в setup-боксе — там, где это нельзя спутать с метками проектной карты.

## ГРАНИЦА как триггер — корпорация, читающая ФОРМУ карты

Введено с **C22 Philares**. Все остальные корпорации смотрят на трек, метку или карту; эта — на ГРАНИЦЫ между двумя застройками, и симметрично — человек кормит её точно так же, как она кормит себя сама.

- **Считаем СОСЕДСТВА НОВОГО ТАЙЛА, а не пересчитываем доску.** Нов только один тайл — значит все новые границы проходят через него, и ни одна другая измениться не могла. Это и дешевле, и единственное чтение, совпадающее с печатным «each NEW adjacency … regardless of who just placed THE TILE».
- **БЕСХОЗНЫЙ тайл — ничей**, и это трактовка ДВИЖКА, а не наша: человеческая `Philares.onTilePlaced` выходит при `space.player === undefined`, поэтому океан (а также Martian Nature Wonders и Rey Skywalker) не создаёт границы ни в одну сторону. Тот же закон, что у C21 и C18.
- **Маркер (C18) — НЕ тайл.** Печатное «between your TILES» требует тайла, поэтому бронь на пустой клетке ничего не платит.
- **«Then, if able» — ОДНА попытка на триггер, не дренаж**: предложение входит в ТОТ ЖЕ эффект, поэтому 9 науки тратят 4 один раз. Но купленное продвижение может ПОСТАВИТЬ ТАЙЛ и войти в тот же хук снова — это законный каскад (наука конечна), но счётчик глубины обязателен и ЖИВЁТ В МОДУЛЕ, а не в `corpStats` (те сериализуются и читаются insight'ом).
- **Цель «most-advanced non-maxed»** — `board.getMostAdvancedNonMaxedTrackIndex`, ничья разрешается в верхний трек, как у давно живущего брата `getLeastAdvancedTrackIndex` (RB-B нигде не решает ничью по трекам вскрытием карты).

## ПЕЧАТНЫЙ ИСХОД «обратно в бонусную колоду» (`return-to-deck`)

Введён с **B27**. До него бонусная карта умела только уйти в сброс, быть уничтоженной или остаться в recurring-холдинге. Новый исход кладёт карту ОБРАТНО В КОЛОДУ с перемешиванием — карта остаётся в ротации ПРЯМО СЕЙЧАС, а не после следующей перетасовки сброса. В разборе хода это судьба `reshuffled` (`MarsBotBonusFate`), у неё своя подпись.

## ОСОБЫЙ ТАЙЛ ИЗ СТОПКИ БОТА — выводим, а не таблица

B27 ветка (b) ставит «a special tile matching a card in its played pile». Какая именно карта — ПЕРВАЯ в упорядоченной стопке, чей тайл вообще может лечь на сушу Марса (карта другого критерия не называет), а МЕСТО — по общим тайбрейкам.

Сама классификация ВЫВОДИТСЯ из источников движка: `isSpecialTile` говорит, какие типы вообще особые, `tileTypeToString` — какой карте каждый принадлежит, `OCEAN_TILES` — какие сидят на океане. Явно перечислены только тайлы лунной доски, которые `isSpecialTile` не отсеивает (LUNA_*/LUNAR_*). Спек `MarsBotPhilares.spec` проверяет, что разбиение ИСЧЕРПЫВАЮЩЕЕ, и падает СО СПИСКОМ ИМЁН, если upstream добавит тип тайла.

Собственные требования карты к клетке (вулкан, соседство, бонус) НЕ проверяются: RB-B — бот требований карт не читает, а карта B27 называет РОВНО ОДИН критерий места — «adjacent to one of your city tiles».

## БОТ-КАРТА МОЖЕТ ПРОСТО ЗАПУСТИТЬ СТРОКУ ЧЕЛОВЕЧЕСКОЙ

Введено с **C24 Splice**, и это сильнейшая форма закона C18/C21. Первая ветка её эффекта — ДОСЛОВНО эффект человеческого Splice, только владелец — бот. Поэтому файл корпорации НЕ переписывает правило, а ВЫЗЫВАЕТ чужой хук:

```ts
const splice = newCorporationCard(CardName.SPLICE);
game.events.withEffect(bot, splice, 'card-played-by-any',
  () => splice.onCardPlayedByAnyPlayer?.(bot, card, human));
```

Зеркало того, что `AutomaHumanTagReactions.onBotCardResolved` делает в ОБРАТНУЮ сторону (человек владеет картой, бот разыгрывает) — та же атрибуция, тот же хук. Задаром получаем всё, что могло бы разойтись: сумму, условие «выбор есть только если карта держит микробов», `choiceContext` промпта (он сам назовёт Splice) и порядок очереди.

⚠️ **ПОРЯДОК ОЧЕРЕДИ — ЧАСТЬ КОНТРАКТА, и он ловит тесты.** Выбор игрока имеет БОЛЕЕ ВЫСОКИЙ приоритет, чем `GainResourcesDeferred` владельца, а `DeferredActionsQueue.run` ОСТАНАВЛИВАЕТ очередь на любом `PlayerInput` — значит выплата боту ждёт ОТВЕТА человека. Спек обязан ответить на промпт и снова слить очередь — это не баг, а то, как эта карта работает и у человека.

⚠️ **ГРАНУЛЯРНОСТЬ БЕРЁТСЯ У СВОЕГО БЛИЗНЕЦА, А НЕ У СОСЕДНЕЙ БОТ-КАРТЫ.** C21 и C24 печатают ОДНУ английскую фразу «when you play a microbe tag», но их человеческие карты читают её ПО-РАЗНОМУ: `PharmacyUnion.onCardPlayedByAnyPlayer` — булево `card.tags.includes(MICROBE)` (раз на карту), `Splice.onCardPlayedByAnyPlayer` — `cardTagCount * 2` (на каждую метку). Оба правильны; выбор своего близнеца — единственный честный критерий.

## МИКРОБНОЕ ПРОДВИЖЕНИЕ — ТОЖЕ МИКРОБ (`onMicrobeAdvancement`)

Клетка 9 трека Венеры двигает Bio-трек МИКРОБОМ, не резолвя метку. RB-B FAQ уже заставляет санкционированные ЧЕЛОВЕЧЕСКИЕ карты решать её «as if a card with a microbe was played»; бот-корпорация, чьё собственное правило смотрит на микробов, не должна быть глуше той же карты в табло человека.

Хук диспатчится РОВНО ИЗ ОДНОГО места — из той самой клетки в `AutomaResolver.advanceTrack`, рядом с `AutomaHumanTagReactions.onBotMicrobeAdvancement`. **Стартовая МЕТКА туда НЕ идёт**: она — настоящий `resolveTag` и приходит через `onTagResolved`; если бы хук висел также на `onBotNonCardTag`, микробная стартовая метка оплатилась бы ДВАЖДЫ.

## КОРПОРАЦИЯ, КОТОРАЯ НАБИРАЕТ ПО В КОНЦЕ (`endgameVictoryPoints`)

Введено с **C25 Viron**. До неё всё, что делали корпорации, конвертировалось в темп; эта пишет очки напрямую.

- **Хук ЧИСТЫЙ**: вызывается из подсчёта очков, поэтому НИЧЕГО не меняет и пересчитывается из состояния (стопка разыгранных), а не копится в счётчике — второй источник правды разошёлся бы. Закреплено тестом на чистоту.
- **Новый терм в `AutomaVictoryPoints` — это СЕМЬ точек**, и пропуск любой ломает инвариант «сумма сегментов ≡ total»: `VictoryPointsBreakdownBuilder.updateTotal`, `AutomaScoring.automaVictoryPoints`, `endgameModel.automaCardsTotal`, `finalScoringRevealModel` (строка церемонии), `victoryPointsModel` (шкала отчёта) и `consoleOverviewModel` (своя ветка `OvBotCardSource` + формула в `ConsoleOvTabCards`) и **`consoleEndgameModel.AUTOMA_SEGMENT_FAMILY`**. ⚠️ Союз `OvBotCardSource` исчерпывающий — компилятор сам спросит ветку; а вот `AUTOMA_SEGMENT_FAMILY` — ОБЫЧНАЯ ТАБЛИЦА, несопоставленный сегмент даёт `undefined` и МОЛЧА выбрасывается: терм остаётся в `finalTotal` и не попадает ни в одну категорию. ⚠️ И ФИКСТУРЫ НОВОГО ТЕРМА ОБЯЗАНЫ БЫТЬ НЕНУЛЕВЫМИ: с `corpVp: 0` везде инвариантный тест зелён и при потерянном терме — именно так баг и прошёл.
- **Строка обзора называет КОРПОРАЦИЮ и очки, и на этом останавливается** — какое именно правило их принесло, знает текст самой карты; общая модель не пересказывает то, чего не видит.

## УСЛОВИЕ МОДУЛЯ БЫВАЕТ «И» И «ИЛИ»

`requiresModules` — ВСЕ перечисленные (C16: «only when playing with Prelude»), `requiresAnyModule` — ЛЮБОЙ из них (C25: «Venus Next or Colonies»). Два ПОЛЯ, а не флаг на одном: карты говорят две разные вещи, читатель данных не должен угадывать, а будущее «X и (Y или Z)» выразимо без правки предиката. Отсутствующий список — НЕ условие (пустой `some` вернул бы false и выкинул бы корпорацию из любой игры). Гард в `MarsBotCorpData.spec` проверяет ОБЕ формы.

## КОРОБКА ROUND START и РЕАКЦИЯ НА FAILED ACTION

Введены с **C26 Celestic** — два хука, каждый с одной точкой диспатча.

- **`onFailedAction`** — из `AutomaFailedAction.failedAction`, единственного места, через которое проходят ВСЕ провалы (максимум трека, завершённый параметр, нет места под тайл, занятые вехи/награды). Вызывается **ПОСЛЕ** выплаты M€ и записи в журнал: печатное «in ADDITION to the usual MC» добавляет к ЗАВЕРШЁННОМУ событию, а не заменяет его.
- **`roundStart`** — из `Game.gotoResearchPhase`, ДО смены фазы. **РАЗ ЗА ПОКОЛЕНИЕ**, маркер `corpRoundStartGeneration` — точно та же форма, что у `corpBapGeneration`. Коробка, которая ПЛАТИТ ресурс, не имеет права сработать дважды после релоада или отмены; маркер сериализуется и деградирует в 0 на старых сейвах.
- **Поколение 1 коробку ROUND START не видит** — и это НЕ баг: корпорация выбирается на воротах research → action того же поколения, то есть ПОСЛЕ его фазы исследований. Первый раунд покрывает SETUP-коробка.
- **Тест обязан проверить ПРОВОДКУ, а не только диспетчер**: отдельный кейс гонит НАСТОЯЩИЙ переход поколения (`forceGenerationEnd`) и считает КОРОБКОЙ (`celesticRounds`), а не пулом — собственные ходы бота в том же поколении тоже могли дать плавателей через Failed Action.

## ГЛОБАЛЬНЫЙ ПАРАМЕТР КАК ТРИГГЕР (`onVenusIncreased`) — и ПОЗИЦИЯ ДИСПАТЧА ЕСТЬ ПРАВИЛО

Введено с **C28 Aphrodite**. До неё корпорации смотрели на треки, метки, карты, тайлы и провалы; эта смотрит на ГЛОБАЛЬНЫЙ ПАРАМЕТР.

- **Одна точка входа**: `Game.increaseVenusScaleLevel` — единственный способ, которым Венера вообще двигается. Поэтому «человеком, Ботом или картой» не требует трёх веток — все три источника проходят там.
- **Диспатч стоит РЯДОМ С БЛИЗНЕЦОМ**, и это не косметика. Выплата человеческой Aphrodite живёт там же и ВНЕ гарда `phase !== SOLAR`. B16 Government Intervention поднимает Венеру, временно выставив `phase = SOLAR`, чтобы подавить РТ и бонусы — а печатная скобка «or the card Government Intervention» говорит игроку, что до ЭТОГО эффекта подавление не дотягивается. Значит честная реализация — **НАСЛЕДОВАТЬ ПОЗИЦИЮ**, а не переписывать исключение в своём файле.
- **Бот-корпорация — НЕ карта в табло**, поэтому её нельзя найти тем же `players.find(p => p.tableau.has(...))`, что и человеческую — нужен свой диспатч через `AutomaCorporations`.
- **Гранулярность — ПОШАГОВАЯ**, потому что так читает близнец (`2 * steps`). Подъём на 2 шага платит 4 M€; подъём, обрезанный потолком, платит только за состоявшиеся шаги (оба случая в тестах).

## КЛЕТКА УЖЕ РАЗРЕШЕНА (`onTrackSpaceResolved`) — «after»-близнец `onTrackAdvance`

Введено с **C29 Manutech** — единственной корпорацией набора, которая платит не ресурсом, а ТЕМПОМ.

- **Два хука на одно движение, и порядок в них весь смысл.** `onTrackAdvance` (и диспатч кубов рядом с ним) срабатывает ДО печатной иконки клетки — так читаются «each time MarsBot advances …» и «advancing ONTO a cube». `onTrackSpaceResolved` срабатывает ПОСЛЕ иконки и после всего каскада, который она открыла — так читается «after resolving the effect, …». Формулировка карты выбирает хук; гадать не нужно.
- **Триггер — ПРИЗЕМЛЕНИЕ, а не конец цепочки.** Резолвер запоминает `landed` сразу после `advance()` — печатная иконка может быть «advance» и унести маркер дальше (трек событий: #5 именно такая). Хук получает клетку, на которую маркер ВСТАЛ; вопрос «какой клетки он достиг?» всегда о ней.
- **…а толчок идёт от ТЕКУЩЕЙ позиции**, обычным `advanceTrack`. Физически игрок доигрывает клетку, смотрит на напоминание и двигает маркер ещё на одну — с того места, где тот оказался. Из-за этого одно приземление на #5 трека событий даёт цепочку #5 → #6 → #7 → #8, и тест на неё есть.
- **`depth` ОБЯЗАН передаваться дальше** (`depth + 1`). Хук может двинуть тот же трек снова, поэтому общий гард от убегающих каскадов (`MAX_CASCADE_DEPTH`) продолжает считать только если глубину протащить. Тест читает `depth` и `cause` прямо из записи хода — это и есть доказательство, что она протащена.
- **Ничего общего не переписывать.** «Advance it another space, and resolve that one as well» ЕСТЬ `advanceTrack`: иконка новой клетки, её каскад, чужие кубы и Failed Action на законченном треке приходят бесплатно. Трек Венеры короче остальных (12 клеток), поэтому его #12 — последняя, и толчок там ВСЕГДА Failed Action; это не исключение карты, а общее правило, встретившее короткий трек.
- **Счётчик «шагов» считается по факту.** `manutechSteps` бампится только если позиция реально выросла: провалившийся толчок — это Failed Action, а не шаг.

## РАСХОД РЕСУРСА КАК ТРИГГЕР (`onFloatersSpent`)

Введено с **C34 Stormcraft Incorporated**. До неё все триггеры смотрели на ПРИХОД или на действие; эта — на РАСХОД.

- **У бота есть РОВНО ОДИН расход аэростатов** — `AutomaResearch.trySpendFloaters` (5 штук в конце фазы исследований, когда веха Hoverlord уже недостижима). Поэтому «when MarsBot spends floaters to keep an additional card» не требует веток — диспатч в той единственной точке, ПОСЛЕ списания и записи в журнал: печатная фраза добавляется к ЗАВЕРШЁННОМУ событию (то же чтение, что у `onFailedAction`).
- **Тестить НАСТОЯЩУЮ ПРОВОДКУ**: отдельный кейс гонит `AutomaResearch.buildActionDeck`, а не только хук — тот же закон, что у ROUND START в C26.
- **Армировать расход в спеке** — это ДВА условия, а не одно: ≥ 5 аэростатов И недоступная Hoverlord. Без «Венеры» вехи в игре нет вовсе (это и есть случай «no longer available»), а с ней — занять три вехи.

## ХУК, КОТОРЫЙ ОТМЕНЯЕТ ДЕЙСТВИЕ

Введено с **C36 Pristar** — первой корпорацией, эффект которой не ДОБАВЛЯЕТ к событию, а ЗАМЕНЯЕТ его.

- **`onWouldRaiseParameter` спрашивается ДО действия** и возвращает `'replaces-action'`; диспетчер — `AutomaCorporations.replacesParameterRaise(game, GlobalParameter)`. Все прочие хуки узнают о случившемся; этот решает, случится ли оно.
- **ГЕЙТ СТОИТ НА ТОЧКАХ ДЕЙСТВИЯ БОТА, А НЕ В ДВИЖКЕ.** Триггер — печатное ДЕЙСТВИЕ («raise the temperature / raise oxygen / place an ocean / raise Venus»), а не движение параметра: зелень поднимает кислород как следствие ТАЙЛА, и такой фразы карта не печатает. Гейт внутри `Game.increaseOxygenLevel` съел бы кислород уже положенной зелени — это не «skip increasing the global parameter», а порча чужого действия.
- **МЕСТА, КОТОРЫЕ ОБЯЗАНЫ СПРАШИВАТЬ** (все пути бота, а их больше одного на параметр): общий `AutomaTerraformer.raiseTemperature` · общий `AutomaTilePlacer.placeOcean` · `AutomaResolver.raiseVenus` · лестница бонус-карт «самый отстающий параметр» (`AutomaBonusCards`) · лестница «около бонусной клетки» (`AutomaNearBonusPush` — все четыре ветви, включая ту, что сама выбирает клетку океана). Гарантия — не грep, а СКВОЗНОЙ тест: спек гонит каждый путь и проверяет замену.
- **ДЕЙСТВИЕ ОДНО, СКОЛЬКО БЫ ШАГОВ ОНО НИ ПЕЧАТАЛО.** Ветка «+2 шага» заменяется целиком: «skip increasing the global parameter» — про действие, а не про шаг.
- **ЗАМЕНЁННОЕ ДЕЙСТВИЕ НЕ СТАНОВИТСЯ FAILED ACTION**: гейт спрашивается ПЕРЕД проверкой «а можно ли ещё поднять», потому что «WOULD raise» описывает инструкцию, а не её выполнимость. Обратное чтение («нечего пропускать → Failed Action») зафиксировано в комментарии как отвергнутое и закреплено тестом.
- **КОРОБКА BEFORE ACTION PHASE ЗАМЕНЯЕТ SETUP.** Общий гейт резолвит её и сразу после сетапа, поэтому карте, которой нужен ресурс с 1-го поколения, бокс SETUP не нужен — и печатная карта его не печатает. В тестах это значит: игра ПРИХОДИТ уже заряженной, счётчики читать как ДЕЛЬТЫ (закон C32).

## СОСТОЯНИЕ В ОДИН БИТ + ЧУЖОЕ ПОЛЕ КАК ПРАВИЛО

Введено с **C35 Lakefront Resorts** — первой корпорацией, которая на одно и то же событие реагирует ПО-РАЗНОМУ в зависимости от предыдущего раза.

- **КУБ НА КАРТЕ — ЭТО ФЛАГ, А НЕ СКЛАД**, и живёт он в том же слоте, что растение Ecoline и наука Philares (`AutomaState.corpResources`, сериализуется, публичен): на столе это физически одна и та же вещь — куб, лежащий на карте корпорации. Новых полей не нужно, нужен только новый вид ресурса (`MarsBotCorpResource` += `'cube-white'`; лицо уже рисует всё, что не наука, обычным кубом `CardResource.RESOURCE_CUBE`).
- **ЧЕРЕДОВАНИЕ — ЭТО И ЕСТЬ ПРАВИЛО, а не «каждый второй»**: сетап кладёт куб именно затем, чтобы ПЕРВЫЙ океан был платящим. Тест обязан утверждать ИНВАРИАНТ (после N переключений куб на месте ⟺ N чётное; оплат = ⌈N/2⌉), а не «третий океан платит»: между ними может встрять океан, который выложила сама доска.
- ⚠️ **ОПЛАЧЕННЫЙ ШАГ МОЖЕТ САМ ПОРОДИТЬ СОБЫТИЕ-ТРИГГЕР.** Клетка #2 трека строительства выкладывает океан, поэтому переключение → продвижение → океан → переключение. Это ПЕЧАТНОЕ правило, а не особый случай: цепочка конечна (каждая оплата стоит шага трека), но глубина живёт в МОДУЛЕ и протаскивается в `advanceTrack` (законы C22 и C29 вместе).
- **ПЕЧАТНАЯ СТАВКА, КОТОРУЮ ДВИЖОК УЖЕ УМЕЕТ, — ЭТО ОДНО ПОЛЕ**: «bonus for placing adjacent to an ocean is 3 MC» = `player.oceanBonus`, ровно то поле, которое ставит ЧЕЛОВЕЧЕСКИЙ близнец. Одна строка на сетапе наследует все пути сразу (свои тайлы, тайлы с клетки трека, тайлы бонусной карты) и переживает перезагрузку — поле сериализуется у игрока. Корпорация НЕ переписывает выплату и ничего не платит сама; она только ИЗМЕРЯЕТ надбавку, пересчитывая соседей той же `board.oceanAdjacencyBonus`, которой платил движок.
- **«WHEN AN OCEAN TILE IS PLACED» — ЧТЕНИЕ ДВИЖКА, а не своё**: человеческая карта печатает тот же триггер, значит предикат берётся у неё (`Board.isUncoveredOceanSpace` — НОВЫЙ океан, не Ocean City поверх лежащего). Закон C21, применённый к тайлу.

## КАРТА НА ДНЕ КОЛОДЫ + ЦЕПОЧКА ПРИОРИТЕТОВ ВНЕ ДРАФТА

Введено с **C46 Tycho Magnetics / B30 Interface Hyperlink** — корпорацией, у которой вообще нет ни бокса эффекта, ни стартовых меток.

- **ДНО — четвёртая диспозиция корп-карты.** Было: recurring (`recurringBonusCards`), замешать в ротацию (`push` + `inplaceShuffle`), сделать постоянной чужую. Стало: ПОЛОЖИТЬ без перемешивания — розыгрыш бонусной карты берёт `shift()` с начала, значит `push()` есть дно и карта выйдет последней. Гард в спеке: она ПОСЛЕДНЯЯ в `bonusDeck` и НЕ в `recurringBonusCards`.
- **ПЕЧАТНЫЙ СПИСОК ПРИОРИТЕТОВ — ТО ЖЕ СРАВНЕНИЕ, ЧТО У ДРАФТА**, и работает на той же машинерии: `MarsBotDraftResolver.pickByScore` (метод открыт ради этого). Лексикографическое сравнение массивов очков + seeded-развязка уже жили там; «Random» в конце печатного списка И ЕСТЬ эта развязка, а не четвёртая оценка.
- ⚠️ **НОВЫЙ ТИП В `MarsBotDraftPriority` ДОБАВЛЯТЬ НЕЛЬЗЯ.** Этот union — множество приоритетов, печатаемых на плашке DRAFT PRIORITY. Правило выбора бонусной карты в нём не место: общая МАШИНЕРИЯ, разные ПРАВИЛА.
- **Считать, а не проверять булево**: «1. Science tag» читается как КОЛИЧЕСТВО меток науки (RB-B: «карта с первой меткой дважды — ещё лучше»). При отсутствии карт с двумя науками оба чтения совпадают — поэтому карта и пишет это одним словом.
- **«Select 2» — ВЫБРАТЬ ДВАЖДЫ, не сортировать**: лучшая, затем лучшая из оставшихся. Только так случайная развязка остаётся честной при тройном равенстве.
- **Сбрасывать ОТВЕРГНУТЫЕ ДО розыгрыша оставленных** — иначе эффект, запущенный самим розыгрышем, может вытянуть только что отвергнутую карту.
- ⚠️ **Тест судьбы карты гнать ЧЕРЕЗ НАСТОЯЩИЙ ПУТЬ** (`drawAndResolveBonusDeckCard`): резолв карты, всё ещё лежащей в колоде, проверяет состояние, которого в игре не бывает (в игре её сначала снимают с колоды).

## СОБЫТИЕ С ДВУМЯ ТОЧКАМИ ВХОДА (`onColonyBuilt`)

Введено с **C33 Poseidon**. До неё каждый триггер имел ОДНУ точку входа (`Game.addTile`, `Stock.add`, `increaseVenusScaleLevel`, `failedAction`).

- **Колонию можно основать в ДВУХ местах**, и это не дублирование, а правда правил: `Colony.addColony` (человек) и `AutomaColonies.botBuildColony` (бот, который НАМЕРЕННО не идёт через первое — он игнорирует печатную награду и берёт 2 ресурса на транспортную доску).
- **Диспатч ставить РЯДОМ С ДВИЖКОВЫМ ЦИКЛОМ** «any player built a colony», который уже крутится в обоих местах ради `onColonyAddedByAnyPlayer` ЧЕЛОВЕЧЕСКОЙ Poseidon. Это тот же закон C28: позиция наследуется, а не переписывается — «you or MarsBot» тогда не требует ни одной ветки.
- **Двойного срабатывания нет по конструкции**: пути не вложены друг в друга (у `addColony` три вызывающих, все человеческие). Перед добавлением второй точки это обязательно проверить грепом.
- **«INCLUDING DURING SETUP OF THIS CARD» бесплатно**: `selectCorporation` сажает корпорацию ДО резолва Setup-бокса, поэтому то, что бокс делает, доходит до собственного эффекта карты. Тот же принцип, что у «including the starting tag» — и так же закрепляется тестом.

## КОРОБКА, КОТОРАЯ УБИРАЕТ КАРТУ ИЗ КОЛОДЫ ДЕЙСТВИЙ

Введено с **C32 Polyphemos** — первая корпорация, которая не ДАЁТ боту ничего, а УБИРАЕТ.

- **Ценность карты для бота = число меток.** Ход бота — вскрыть карту и продвинуть трек за каждую напечатанную метку; карта без меток — официальный Failed Action. Поэтому сброс самой слабой карты — это поднятый пол каждого оставшегося хода, а не косметика.
- **Мера — ПЕЧАТНЫЙ ряд меток** (`MarsBotDraftResolver.printedTagCount`), тот же счёт, что у приоритета «most tags». Сравнивать можно только то, у чего этот ряд есть: **бонусная карта НЕ участвует** — у неё не «мало меток», а нет их вовсе, и это спец-ход поколения. Гарды: колода, где единственная «бестеговая» запись — бонусная, сбрасывает проектную; колода из одних бонусных не сбрасывает ничего.
- **Куда уходит**: в ОТКРЫТЫЙ сброс проектов (`game.projectDeck.discard`) — туда же, куда уходит пост-драфтный сброс. Поэтому строка журнала НАЗЫВАЕТ карту: колода действий закрыта, но то, что из неё вышло, человек и так видит.
- ⚠️ **ПЕРВОЕ ПОКОЛЕНИЕ НЕ ИСКЛЮЧЕНИЕ.** RB-B резолвит Before-Action-Phase «также после сетапа, до фазы действий 1-го поколения», и общий гейт это уже делает — значит, к моменту, когда спек начинает что-то мерить, коробка УЖЕ отработала один раз. Счётчики проверять ДЕЛЬТОЙ, а сам факт закрепить отдельным тестом.

## КОРПОРАЦИЯ МЕНЯЕТ ОБЩИЙ СТОЛ (`ColoniesHandler.seatColonyTile`)

Введено с **C30 Aridor** — первый бот-сетап, который трогает не материал бота, а ОБЩУЮ игру: «Add an additional Colony tile to play» открывает колонию и человеку тоже.

- **Отличие от человеческой карты — только ВЫБОР.** Человеческий Aridor печатает ту же фразу и спрашивает владельца (`addColonyTile` → `SelectColony`); бот промптов не получает и берёт тайл `game.rng`. Всё, что ПОСЛЕ выбора — сортировка колоний, проверка «войдёт ли активной» (`colonyTileWillEnterActive`), изъятие из `discardedColonies`, строка журнала — вынесено в общий `seatColonyTile`. Это тот же закон, что дал `MarsBotSilverCubePayout`: совпадает ПРАВИЛО ⇒ один модуль; расходится только то, чем карты действительно отличаются.
- **Прогнать спеки ВСЕХ вызывающих сразу после выноса** — у `addColonyTile` их три (человеческий Aridor, CEO Maria, Prospecting). Это и есть доказательство, что ничего не разъехалось.
- **Пустой пул — не ошибка.** В бот-партии он недостижим (валидатор запрещает `customColoniesList`, в игре все 11 базовых тайлов), но гард есть у обеих карт и покрывается прямым вызовом сетапа, а не нелегальным конфигом.
- **Тайминг совпадает с RB-B:** корпорация бота выбирается на воротах research → action 1-го поколения, то есть ПОСЛЕ розыгрыша корпорации человека — ровно там, где рулбук велит резолвить Setup box.

## ЦВЕТ КУБА КАК КОМПОНЕНТ, А НЕ ПРАВИЛО

Тот же C30. До него цвет куба всегда что-то значил (C03 белый ≠ чёрный, C14/C19 белый ≠ чёрный, C23 только белый).

- **«A black OR white cube» — одно предложение с одним исходом.** Два цвета взяты потому, что девяти одноцветных кубов в коробке нет. Поэтому оба цвета получают один `target`, один `logKey` и один счётчик; вычитать различие — значит выдумать правило.
- **Легенда группируется по СМЫСЛУ, а не по цвету** (`legendRows`): цвета с одинаковым текстом дают ОДНУ строку со ВСЕМИ своими образцами. Две одинаковые строки на мате утверждали бы разницу, которой карта не печатает.
- **Гард в спеке карты**: `cubeLegend.black === cubeLegend.white` — если кто-то однажды разведёт тексты, он сделает это осознанно.

## НАПОМИНАНИЕ НА КОЛОНКЕ (`reminderColumns` + `columnLegend`)

Тот же C29. Примитив C04/C20 («заменить маркер трека белым кубом»), повёрнутый на 90°.

- **Колонка — не трек.** Печатная фраза «above the #5 and #12 columns» адресует ВЕРТИКАЛЬ: на физическом мате треки лежат строками одной сетки, и колонка пересекает их все сразу.
- **Поэтому разрешение по доске не нужно.** `whiteMarkerTracks` хранит ТЕГИ и сервер резолвит их в индексы треков (`AutomaCorporations.whiteMarkerTrackIndexes`); номер колонки одинаков на любом треке, который до неё дотягивается, так что клиент читает `reminderColumns` прямо из `marsBotCorpInfo` — нового поля в `MarsBotCorpModel` не появилось.
- **Объявляется ПАРОЙ** с `columnLegend` (гард в `MarsBotCorpData.spec.ts` — тот же, что у пары маркеров), и легенда, как все легенды, рендерится БЕЗ параметров: числа вписаны в текст.
- **На мате** колонка — полоса через все треки, а сам чёрный куб рисуется ОДИН раз, над верхней строкой: это и есть «над колонкой».
- **Регресс её не гасит.** Правило регресса глушит СОБСТВЕННОЕ действие клетки, а не корпоративную клаузу, триггер которой — движение (так же уже читает C04). Физическая примета совпадает: потраченный ресурсный куб уходит с мата, напоминающий не уходит никогда.

## КАССА на карте (накопление), в отличие от банка (расход)

Введено с **C20 Factorum / B24**. На карте корпорации уже было хранилище M€ (C06 Mining Guild), но там оно работает В ОБРАТНУЮ сторону.

| | C06 Mining Guild (банк) | C20 Factorum (касса) |
| --- | --- | --- |
| Начало | ПОЛНАЯ (10 M€ на сетапе) | ПУСТАЯ |
| Кто двигает | ДОХОД бота (`onMegacreditsGained` через `Stock.add`) — опустошает | ПРОДВИЖЕНИЕ трека (`onTrackAdvance`) — наполняет |
| Куда идёт M€ | бот получает их всё равно (источник другой) | бот НЕ получает ничего, пока не снимет своей картой |
| Что конвертируется | доход → темп | темп → доход (с задержкой) |

- **Триггер общий, АДРЕСАТ — НЕТ.** Хук `onTrackAdvance` тот же, что у C04/C09, но `MarsBotTrackPayout` НЕ переиспользуется: его контракт — буквально «MarsBot ПОЛУЧАЕТ N MC». Общий модуль выносится только когда совпадает ПРАВИЛО, а не когда совпадает точка входа — иначе контракт модуля перестаёт быть правдой.
- **«OR AS MUCH AS POSSIBLE» ≠ «IF ABLE».** Третья формулировка оплаты в наборе после «up to X» (частично) и «X, if able» (всё-или-ничего): «N, or as much as possible» — ЧАСТИЧНО. Здесь это подтверждено самой картой: её else-ветка «if it gained 0 MC» имела бы смысл только при возможности частичного съёма. Граница проверяется тестами на 2 и на 1 M€ (съём → fallback закрыт).

## ДВЕ корпорации с ОДНИМ печатным эффектом

Закреплено на **C14 Point Luna + C19 Astro Drill** (третий случай после `MarsBotTrackPayout` для C04/C09 и `AutomaNearBonusPush` для B06/B15/B25).

**Третий случай того же закона — C13 + C27** («When MarsBot advances onto a silver resource cube, MarsBot gains it as MC», слово в слово): общий `corps/MarsBotSilverCubePayout.takeSilverCube`, общие легенда куба и текст эффекта (гард в спеке C27 ассертит РАВЕНСТВО с C13), разные счётчики и разные инсайт-факты. Сумма (5 M€) живёт в `common` (`MARSBOT_SILVER_CUBE_MC`), потому что это номинал КОМПОНЕНТА, а не выбор карты.

Обе карты печатают ДОСЛОВНО одно: белый куб → самый отстающий трек (при равенстве — верхний), чёрный → трек космоса. Поэтому реализация ОДНА (`corps/MarsBotCubeTrackPush.pushCubeTrack`), а карта владеет только тем, что у неё действительно своё: где стоят кубы (данные), её идентичность и её счётчики.

**С C23 Recyclon модуль ОБОБЩЁН, а не скопирован.** Её белый куб толкает ИМЕНОВАННЫЙ трек (растения), а не wild-правило, поэтому «что толкает каждый ЦВЕТ» стало ДАННЫМИ (`pushes: {white|black: {target, logKey, stat}}`), а общим осталось то, что расходиться не должно никогда: scope и атрибуция события, ОБЩЕЕ продвижение (`advanceTrack` — и значит иконка клетки, каскады и Failed Action на завершённом треке), и отсутствие «instead of». Правило формулировок при этом НЕ ослабляется: C14 и C19 делят i18n-ключи, потому что печатают ОДНУ фразу; C23 печатает СВОЮ — и обязана иметь собственные ключи легенды, текста эффекта и журнала (гард в её спеке). Доказательство отсутствия дрейфа — спеки СТАРЫХ карт, прогнанные ПЕРВЫМИ (22 теста C14+C19, зелёные без правок).

- **ТЕКСТ ТОЖЕ ОДИН.** Легенда кубов и строки эффекта — ТЕ ЖЕ i18n-ключи, не вторая формулировка того же правила (гард в `MarsBotAstroDrill.spec.ts` сравнивает оба набора на равенство). А вот **ФАКТ ИНСАЙТА — СВОЙ У КАЖДОЙ**: правило общее, голос нет (C14 — «земной офис подталкивал отстающее», C19 — «космическая программа как маховик»).
- **КУБ МОЖЕТ ТОЛКАТЬ СВОЙ ЖЕ ТРЕК.** У C19 чёрные кубы стоят на треке космоса и его же двигают. Никакого спецкода это не требует: `corpCubesTriggered` гасит каждый куб навсегда, поэтому саморазгон конечен по построению — но это именно то, что обязан закреплять тест.
- При переводе старой карты на общий модуль прогонять ЕЁ СОБСТВЕННЫЙ спек ПЕРВЫМ — это и есть доказательство, что поведение не сдвинулось.

## МАРКЕР на карте (бронь) — и его анимация

Введено с **C18 Arcadian Communities / B22 Settlers**. Маркер — это КУБ БЕЗ ТАЙЛА (`space.player` на пустой клетке), точный близнец «общины» человеческой Arcadian.

- **Запрет для чужих — бесплатно**: `Board.getAvailableSpacesOnLand` уже отказывает в клетке с чужим `space.player`. Ничего писать не надо и нечему расходиться с человеческой картой.
- **Выплата за стройку на своём — ТА ЖЕ СТРОКА**: `Game.addTile` считает флаг ДО `simpleAddTile` (потом `space.player` уже не отличить от владения тайлом), и корпорация отвечает хуком `onBuildOnOwnMarker → 'pays'`. НИКОГДА не делать боту параллельную выплату — она разойдётся с человеческой по скоупу, порядку и исключениям.
- **АНИМАЦИЯ — ОБЩАЯ, НЕ СВОЯ** (требование владельца): куб бота обязан падать тем же премиальным `pc-place`, что и куб человеческой Arcadian. Тот фреймворк (`cubeDropState.observeCube`) завязан на ЦВЕТ-ОНЛИ дифф по тайл-лесс клетке, поэтому:
  1. сервер кладёт клейм в `MarsBotTurnVisual.markers` — ОТДЕЛЬНО от `tiles` (все tile-фреймворки ждут ПОЯВЛЕНИЯ тайла и маркер либо проигнорируют, либо подделают тайл);
  2. клиент (`applyTurnVisual`) вызывает `armPlacementAnimations()` ДО мутации цвета — вотчер `BoardSpace` срабатывает синхронно, без взвода куб отрисуется сразу «в покое» и просто всплывёт;
  3. больше ничего — `observeCube` видит свежий цвет без тайла и запускает дроп НЕМЕДЛЕННО (ждать нечего — тайла нет).
  Гард: `marsBotStagedCommits.spec.ts` « a CLAIM » — ассертит именно `shouldHoldForOwnerCubePlacement`, то есть тот же предикат, которым App.vue взводит дроп для человеческой общины.
- Маркер сетапа ставится ВНЕ хода бота — он приезжает обычным поллом, где `App.vue` уже взводит анимацию по `shouldHoldForOwnerCubePlacement`. Два пути, один дроп.

## ЧУЖАЯ бонусная карта как постоянная (и как она умирает)

Введено с **C17 Vitor**. Четвёртый вид жизни бонусной карты после recurring (B23/B25/B28), разовой в ротации (B31) и уничтожения на сетапе (C05): корпорация берёт ЧУЖУЮ, БАЗОВУЮ карту и делает её постоянной.

- **Владения НЕТ**: `corpBonusCards` остаётся пустым, `resolveBonusCard` не реализуется — карта продолжает резолвиться своим штатным кодом в `AutomaBonusCards`. Корпорация только вынимает её из ротации и возвращает в колоду.
- **Сетап = чистка ТРЁХ мест** (тот же код, что у C05): `bonusDeck` · `bonusDiscard` · бонусный слот колоды 1-го поколения (слот отдаётся следующей бонусной карте, размер колоды не меняется). Без этого карта существовала бы ДВАЖДЫ — в ротации и как постоянная.
- **УНИЧТОЖЕННАЯ КАРТА НЕ ВОЗВРАЩАЕТСЯ**: `routeBonusCard` на исходе `'destroy'` теперь убирает id из `recurringBonusCards`. До C17 ни одна recurring-карта не могла туда попасть (все всегда возвращают `'discard'`), и без этого пересборка колоды воскресила бы её в следующем поколении. Сам бокс BAP всё равно перепроверяет `destroyedBonusCards` — «unless it has been destroyed» напечатано на карте, и бокс должен читаться так же, как карта.
- **Предикат эффекта — чужой и готовый**: «non-negative VP icon» = `AutomaScoring.hasNonNegativeVpIcon` (тот же, что считает ПО стопки бота на Hard/Brutal). Переиспользовать, а не писать второй — счётный скорер («-1 за город») должен читаться отрицательным по ОБЕ стороны.
- **Эффект может СОВПАСТЬ с человеческим дословно** — и это НЕ утечка, если так напечатано на карте бота (Vitor: 3 M€ за карту с значком ПО). Негативные ассерты гардов целятся в то, чего НА КАРТЕ БОТА НЕТ (стартовые M€, первое действие), а не в общие фразы.

## Условие МОДУЛЯ на карте + добавка в СТАРТОВУЮ колоду

Введено с **C16 Valley Trust**.

**«Use this corporation only when playing with Prelude» — это ДАННЫЕ, а не рантайм-проверка.** `MarsBotCorpInfo.requiresModules: ReadonlyArray<Expansion>` читается вторым ЧИСТЫМ предикатом `AutomaCorporations.hasRequiredModules(info, gameOptions.expansions)` рядом с коллизионным — два отдельных вопроса, у каждого один ответ и ни у одного нет разрешающего дефолта, который можно забыть передать. Следствие: корпорация просто НЕ попадает в пул, и dev-форс (`AutomaOptions.corporation`) тоже её не посадит — та же ветка «честно только пока eligible», что у коллизии. Гард в `MarsBotCorpData.spec.ts`: условие не смеет называть модуль, который automa-валидатор вообще запрещает (иначе корпорация мёртвая навсегда) — играбельный набор POC = corpera / prelude / venus / colonies.

**«Give MarsBot 1 extra card … for its starting hand»: у бота нет руки — его «рука» это колода действий 1-го поколения** (3 проекта, +3 с Прелюдией, +1 на Brutal, плюс бонусная карта). Колода строится при создании игры, до корпорации, поэтому карта не раздаётся вместе со всеми, а ЗАМЕШИВАЕТСЯ в готовую на seeded-random позицию — тот же приём, что у gen-1 вставки B23/B25/B28. В журнале НЕ называется, КАКАЯ это карта: колода рубашкой вверх, и имя выдало бы будущий ход бота.

## Печатные формулировки оплаты: «up to X» ≠ «X, if able»

Закреплено на **C15 / B28**. Этот набор карт различает две формулировки и пишет их НАМЕРЕННО:

- **«loses up to X»** (B01 Meteor Shower) — ЧАСТИЧНО: сколько есть, столько и снимается;
- **«loses X, if able»** (B28 Diversification; FAQ «spends 2 MC if able» у St. Joseph of Cupertino Mission) — **ВСЁ ИЛИ НИЧЕГО**: не хватает на полную сумму — не платит вообще.

Ни та, ни другая НЕ Failed Action: это печатная ветка самой карты, компенсации 5 M€ за неё нет. И если карта печатает ДВА предложения (действие + оплата), они НЕЗАВИСИМЫ и идут в печатном порядке: действие выполняется всегда (и само может принести деньги — на заполненных треках это Failed Action с компенсацией), оплата идёт после него.

Цена для бота реальная: остаток M€ конвертируется в ПО на финальном подсчёте (`AutomaScoring.mcPerVp`) — именно поэтому факт корпорации говорит о цене в очках, а не в механике.

## FAQ: human-корпорации, реагирующие на бота (RB-B)

`AutomaHumanTagReactions.ts` — санкционированный **allowlist** (прецедент AutomaBans): ровно {Saturn Systems, Pharmacy Union, Splice}, как перечисляет RB-B. Диспатч из трёх точек резолва карты бота (`onBotCardResolved` — собственные `onCardPlayedByAnyPlayer` карт, атрибуция `withEffect` как у человеческого пути; возврат промпта для бота = громкий throw), из стартовых меток (`onBotNonCardTag` → `onNonCardTagAddedByAnyPlayer`, microbe → дальше) и из «microbe advancement» без карты (`onBotMicrobeAdvancement` → co-located `ICard.onMarsBotMicrobeAdvancement`; Venus-клетка 9 помечена `TrackDefinition.microbeTagCells`). Splice для бота берёт детерминированную M€-половину (микроб физически некуда класть). Исключение tracker-advance у Saturn — структурное: каскады через эти точки не проходят. Расширение санкции = новая строка в `SANCTIONED_REACTORS` + co-located хук в файле карты.
