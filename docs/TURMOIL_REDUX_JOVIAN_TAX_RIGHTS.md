# RX17 · Jovian Tax Rights (Союз) — счётный член по КОЛОНИЯМ

**Статус: СДАНА 2026-09-24.** Карта собирает две готовые половины — титан по влиянию (RX09 Colony Contest дословно) и
капнутое производство M€ (по образцу RX02 Architecture Award) — и приносит **шестой вид счётного члена: счёт по
КОЛОНИЯМ игрока**. Это первый счёт, который не ходит ни по табло, ни по доске Марса, ни по показателю: он считает
КУБИКИ игрока на тайлах колоний, и число ему даёт движок.

Печатный текст: *When enacted: Gain titanium equal to your Influence. Increase your M€ production 1 step for each
colony you have. (Max. 5)* Задание председателя: 2 метки Юпитера. Колонии в Redux обязательны — `compatibility` не
объявляется (формулировка RX09; значок колонии в поле скана — маркер исходной совместимости, не наш гейт).

Промт: `docs/claude/prompts/resolution-rx17-jovian-tax-rights.md`. Файл карты:

## 2. Правило, как оно понято

1. **Титан = влияние**, каждому участнику, в запас (`stock.add`), без потолка; влияние 0 → названный пропуск
   «No influence». Шаг — RX09 дословно (та же журнальная строка, та же запись).
2. **Производство M€ = 1 шаг за каждую колонию, не более 5.** Потолок — на ПРОИЗВОДСТВЕННОЙ части (`cap: 5` объявлен у
   неё), титан не ограничен: на лице «(Max. 5)» стоит под производственной формулой, каталог спека читает «+1 пр. M€ за
   колонию (max 5)». Семь кубиков → +5, запись хранит `uncapped: 7`.
3. **Влияние в производственную часть НЕ входит** (`perInfluence: 0`) — на карте его рядом с колонией нет. Это
   отличие от RX02/RX04, где влияние складывалось со счётом, и новый случай для блока чтения (§ 5).
4. **«Колония» = КУБИК игрока на тайле колонии**, не тайл: две колонии на разных тайлах — 2; два кубика на одном тайле
   (если правила позволили) — тоже 2; чужой кубик на том же тайле — 0. Тайл, с которым игрок только торгует (гость),
   неактивный тайл — не его колония; кубик на неактивном тайле — колония.
5. **Ноль колоний — штатный исход**: титан приходит, производство не растёт, запись называет «No colonies» — пропуск
   ОТДЕЛЬНЫЙ от «No influence»: карта может выдать одну часть и пропустить другую (влияние 0 и три колонии — титана нет,
   производство +3).
6. **Бот** в Парламенте не участвует: ни титана, ни производства; его кубики никому не считаются.

## 3. Очерёдность поколения

`Game.gotoProductionPhase` → `postProductionPhase` → `endGenerationForColonies` (треки колоний растут, флоты
возвращаются, гость уходит — решение Q9) → `ParliamentPhase.start`. Следствия, закреплённые спеком
(`tests/parliament/JovianTaxRights.spec.ts` § «the order of the generation»):

1. **Титан в запасе сразу** — им можно платить в следующем поколении.
2. **Производство впервые платит в СЛЕДУЮЩЕМ поколении**: в поколении принятия ни одного M€ из +N; следующая фаза
   производства платит `РТ + N`. Чтения называют горизонт («платит со следующего поколения») и не складывают его с
   сегодняшним титаном.
3. **Шаг колоний фазы кубиков не двигает**: трек Луны 2 → 3, гость ушёл, флот вернулся — а `colony.colonies` тот же, и
   запись читает пред-фазовый счёт с тем же списком. Если когда-нибудь шаг колоний начнёт строить колонии, этот спек
   покраснеет.

## 4. Блок A — сервер: число путём `Counter`, список тайлов в записи

| Слой | Что заведено |
| --- | --- |
| Общий хелпер | `ColoniesHandler.coloniesOf(game, player): Array<IColony>` — один элемент на КУБИК игрока, порядок стола; гейт `coloniesExtension` внутри. На него переведены `Counter` (countable «colonies», ветка игрока) и `Player.getColoniesCount` (награда Constructor, Microgravity Nutrition…) — три читателя, одно правило (инвариант 7: правило не переписано, вынесено) |
| Вид счёта | `RESOLUTION_COUNT_IDS` += `'colonies'`; `ResolutionCountKind` += `{kind: 'colonies'}`; `resolutionCountKind('colonies')` |
| Общий читатель | `countColoniesToward(id, colonies: ColonyName[])` — число = длина списка, список едет в модели; сервер (`resolutionCount`) отдаёт ему `coloniesOf(...).map(c => c.name)`, стенд — синтетический список |
| Модель | `ResolutionCountModel.colonies?: ColonyName[]` (имя на кубик) — второй модели счёта нет; `cardCountVerdict` / `spaceCountVerdict` называют, почему карта и клетка не считаются |
| Запись | `SerializedEnactOutcome.countedColonies` / `ParliamentEnactOutcomeModel.countedColonies` — заморожено при принятии, не перечитывается по позднему столу |
| Чтение | `InfluenceYield.countedColonies`, `YieldCount.colonies`, `withCount` / `fixedYield` несут |
| Модель места | `ParliamentPlayerModel.counts` несёт `{id: 'colonies', count, cards: [], colonies}` (через `declaredCountIds`) |
| Глиф | `CountedObjectGlyph {kind: 'colony'}` → `PremiumCountGlyph` рисует тайл колонии лица (`tiles/colony.png`, тот же ассет, что `b.colonies()`), без искры и числа |
| Семейство стенда | `familyOf` → `counted-colonies` |

**Реестр RX07 (`ParliamentPlayerModel.colonyBonuses` + `ConsoleColonyLedger`) НЕ переиспользован.** Он отвечает на
другой вопрос — «какие тайлы платят мне бонус и сколько» — и строится по ТАЙЛАМ (`includes(player.id)`: один ряд на
тайл, два кубика на Луне — один ряд), а его присутствие в модели зависит от того, что RX07 есть в каталоге
(`declaresColonyBonuses`). Счёт RX17 — по кубикам и должен читаться из собственной записи резолюции, поэтому список
живёт в модели счёта. Общее у них — источник (`game.colonies`) и имена тайлов (`$t(colonyName)`).

Шаги карты: `TITANIUM_STEP` (RX09 дословно) → `PRODUCTION_STEP` (`resolutionCount(player, 'colonies')`,
`scaledAmount` / `uncappedAmount`, запись с `count`, `countedColonies`, `uncapped`; журнальные строки «1 per colony,
N colony(-ies) [= S, limited to the maximum of M]»; ноль — «has no colonies — no M€ production from»).

## 5. Блок B — чтения

- **Счётная часть без члена влияния** — `yieldInfluenceEnters(effect)` (`perInfluence !== 0`): формула блока печатает
  «1 [пр. M€] / [колония] · макс. 5» без «+ 0 [пр. M€] / [влияние]» (`data-yield-influence-term="false"`), чтение — «[колония]
  4 → +4» без «+ [влияние] 3» и без висящего «+». Запись влияние несёт (гард контракта сверяет), формула его не
  использует. Плоская часть (`yieldIsFlat`) — другой случай ставки 0: без счёта, с базой.
- **Два горизонта без платы** — `productionHorizonOn(effects, effect, levy)`: производственная часть рядом с частью,
  выплачиваемой СЕГОДНЯ (плата ИЛИ часть в запас той же карты), несёт «платит со следующего поколения». ОДИН предикат
  для блока (`horizonOn`), бюджета слов панели (`voteInfoBudget`) и осмотра. RX02 (только производство) горизонта не
  несёт — ему нечего различать; лента заседания его не печатает (решение RX15).
- **Панель голосования**: две строки, каждая со своим объектом — «[влияние] 3 → +3 [титан]» · «[колония] 4 → +4 [пр. M€]»,
  горизонт под второй; суффикса «если победите» у титана при Повестке 5 нет (шаг 6 сохраняет влияние 3 — прогноз,
  равный оценке, отбрасывается). Потолок — «Макс.» у результата и `uncapped` в атрибутах, когда бьёт.
- **Осмотр «Для вас»** — «Учтены сейчас: Луна ×2 · Титан · Миранда» (`countedColonyNames`: имя на кубик, соседние
  одинаковые сливаются в ×n; имена — ключи колоний, как в реестре RX07); ноль — «Сейчас колоний нет — считать нечего» /
  «При принятии колоний не было — считать было нечего», никогда «ни одна карта». Правило счёта — «Считается каждая ваша
  колония: две колонии на одном тайле дают 2. Тайл без вашей колонии не считается.»
- **Запись** читается как записана: список, `uncapped`, «Max.»; пропуски — каждый со своей причиной.

## 6. Блок C — показ и стенд

Показ — ничего нового: титан — штатная волна чипа в рельсу (RX09), производство — штатный шаг производства (RX04);
директор играет записи места по очереди: «+3» рождается в графике закона и садится на ячейку титана с тиком на касании,
только затем «+4» летит в производственную зону M€; чтение ленты несёт «Max.» при потолке.

**Стенд «Полигон»** — семейство `counted-colonies`: место несёт `colonies` (имя на кубик), панель «Колонии» рисует чип на
КУБИК (диск планеты спрайтом `<Colony>-background`, кубик места, имя тайла); кубик сверх потолка остаётся на месте и
зачёркнут — учтён, ничего не платит. Число считает та же `countColoniesToward`. Сценарии: четыре колонии (эталон),
ноль (только титан), одна, ровно пять (максимум достигнут), семь (две сверх), влияние 0 при трёх колониях (только
производство), каждому своё, запись, зритель, задание 0/2 и выполнено, живой `parliament-jovian-vote`.

## 7. Блок D — лицо, фикстуры, e2e

- **Лицо** по скану: одна строка «[титан] / [влияние]  [1 пр. M€] / [колония]», ниже «max 5»; сноска задания — метка
  Юпитера ×2.
- **Фикстуры** (`tests/e2e/fixtures/generate.ts`, `jovianTable`): `parliament-jovian-vote` (синий — Луна ×2 · Титан ·
  Миранда, Повестка 5 = влияние 3, его делегат на карте; красный — Луна, Повестка 1) и `parliament-jovian-assembly` (то
  же, побеждает КРАСНЫЙ — синему платятся ровно числа голосования: +3 титана, +4 производства; ворота сборки стоят).
- **РОВНО ОДИН e2e** `tests/e2e/console-parliament-jovian.spec.ts` (standard-1080): панель — две строки с своими входами,
  без входа влияния у производства, горизонт, без нетто и суффикса; осмотр — правило, список тайлов, никогда «ни одна
  карта»; заседание — чип «+3» рождается в видимой графике закона, садится на видимую ячейку титана, счётчик тикает на
  касании (окно −34…+260 мс), «+4» стартует только после посадки титана и садится в производственную зону, readout +4;
  запись `['titanium', 'production']` с `countedColonies`; итоги «+3 · +4», без пропуска и нетто. Пробник —
  `MutationObserver` + `setInterval`, каждый кадр несёт видимость источника и цели.

### Находки

- Имя карты «Jovian Tax Rights» уже переведено в `turmoil_events.json` — дубликат в `parliament.json` сломал бы `make:json`.
- Глоссарий запрещает форму «у вас нет …» — «Для вас» при нуле формулируется без неё.
- Fullscreen-осмотр монтирует блок чтения с `formula: false` (формулу печатает карта) — утверждения о формуле без члена
  влияния живут в юните компонента; первый прогон e2e упал ровно на этом.
- `isICardRenderText` нет — «max 5» на лице есть `CardRenderItem` типа `TEXT`.
- Повестка 5 → 6 сохраняет влияние 3: суффикса «если победите» на панели нет по построению.
