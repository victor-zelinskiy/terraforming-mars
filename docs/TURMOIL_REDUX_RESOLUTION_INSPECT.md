# Turmoil Redux — fullscreen-осмотр резолюции: одна сцена (партия · карта · правила · footer)

Дата: 2026-09-16, две итерации поверх `TURMOIL_REDUX_PARLIAMENT_V5.md`.
- **Итерация 1** — сцена: партия слева (ячейка лора), карта в центре, собственные правила справа, footer со статусом и
  личным доступом к эффекту партии.
- **Итерация 2** — композиция и язык блоков как у проектной карты (центр по карте, в блоках только слова), редактура
  текстов партий/заданий/осмотра, листание трёх предложений LB/RB и голос прямо из осмотра.

Обзор Парламента, информационная зона режима голосования и зона делегатов — отдельные итерации (сюда попали только
две точечные правки, без которых новые тексты ломали зону: часть «для победителя» и мера чтения строки партии, §2.7).
Правила Redux не менялись; dev-примеры каталога (`copies: 0`) не раздаются и нужны только для проверки компоновки.

## 2. Контракты

### 2.1 Язык блоков: графика на карте, в блоках — слова
- `CardAnnotation.graphic` **удалён** (и отрисовка `PremiumMechanicsPanel` в `ConsoleCardRulesPanel`): блок никогда
  не рисует формулу повторно — ни четырёх делегатов задания, ни будущие формулы собственного эффекта. Исключение —
  плашка партии слева (карта резолюции формулу партии не печатает). Служебные иконки (тип блока, состояние, глифы)
  остаются.
- Правая колонка (`resolutionAnnotations`): `text.effect` → «При принятии» (immediate) · `text.winner` →
  «Победителю голосования» · `text.passive` → «Эффект резолюции» · `text.action` → «Действие резолюции» · затем
  «Задание председателя» (только условие; награда одинакова для всех и живёт в блоке правительства). Заглушка — один
  спокойный блок «Эффект резолюции: Собственного эффекта нет» на месте главного, не пониженный.
- Левая колонка (`resolutionPartyAnnotations(party)`): «Эффект» / «Действие» — по одному печатному предложению, без
  состояния, без «раз за поколение», без технических примечаний. Осмотр самой партии (X на плашке,
  `partyAnnotations`) сохраняет полное чтение: «Эффект/Действие партии» + «Для вас» (живые основания доступа и
  состояние действия: «Действие использовано в этом поколении» · «Действие недоступно: …» · «Действие доступно в ваш
  ход» · «Действие доступно в этом поколении») + одна справочная строка «Доступ».
- Обе колонки читают ОДИН tier плотности (`denserRulesTier(rulesLengthTier(правые), rulesLengthTier(левые))`,
  проп `tier` у панели) — соседние колонки не расходятся кеглем.

### 2.2 Центр по карте — как у проектной карты
- Рамка итерации 1 (`calc(460px × fit)`, top-anchored) снята: `.con-zoom-asidecol` / `.con-zoom-sidecol` — та же
  механика, что у эталона (`height: 100%` полосы midrow + `justify-content: center`). Карта сама центрирована в той
  же полосе, поэтому центр стека = центр карты; длинное чтение заполняет полосу и прокручивает только тело.
- Плашка стоит в текстовой колонке: её поля = паддинги тела правил (1080/Deck 1.1rem, TV 1.3rem), тело открывается
  отступом блока, а не второй шапкой. Измерено: левый/правый край плашки = край текста (TV 236/1192, Deck 52/428).

### 2.3 Листание трёх предложений (только из режима голосования)
- `ConsoleParliamentSection.inspect()` в стадии `vote`: `ids` = три слота в физическом порядке, `index = slotIndex`,
  `origin(index)` = лицо карты в слоте, `onBrowse(i)` → `selectVoteSlot(i)` (выбор режима следует за осмотром, hold
  слота переезжает через `retargetZoomHold`, B приземляет карту в слот последней просмотренной). LB/RB и d-pad ←/→.
- Любая другая стадия (счёт, отправка, посадка) и принятая карта Правительства — одна карта, без листания и без глагола.
- `CardZoomModal navCounter=false` — верхняя плашка счётчика не рисуется и не резервируется (размер карты прежний);
  позиция `2/3` — в подсказке листания footer'а. `flankMotion` — содержимое колонок поднимается (opacity + 0.6rem) в
  том же кадре, что стартует поворот карты: новая карта никогда не стоит рядом со старыми колонками.

### 2.4 Голос из осмотра — одна операция, две двери
- Мост `ConsoleZoomVote {verbAt(index), execute(index)}` (модуль `consoleCardZoom`) отдаёт секция.
- `voteVerbOf` (чистая, spec'd) читает ТОТ ЖЕ тайл голоса, что и подтверждение режима (серверный `VoteOptionModel`:
  `available/reason/source/cost`), присутствие опции в меню (`bridge.vote`), `canActNow`, список партий живого
  prompt'а и общий `offTurnReason`. Ворота: `rule` (серверная причина, старше хода) · `turn` (источник и цена видны +
  текст хода) · доступно. Цена — только серверная (`cost` для резерва, лобби бесплатно).
- A: заблокировано → «толчок» причины (transform-only), осмотр не закрывается и ничего не отправляет; доступно →
  `closeZoomViewer()` (карта летит в свой слот) → `execute(index)` = `selectVoteSlot(index)` + собственный
  `submitVote()` режима (тот же snapshot, счёт внутри режима, полёт куба). Голос уходит за карту, показанную в момент A.
- Двойная отправка невозможна: во время полёта `zoomClosing` глотает ввод; `submitVote` отказывает вне стадии
  `vote`; повтор клавиши никогда не повторяет кнопку. Измерено: `10 open → 343 closed → 467 submitting → 651 landed
  → 658 cube → 2303 flow left` (TV), двойное A — один делегат.
- ⚠️ Драйвер e2e `openZoomViewer` больше не жмёт X, пока открытие уже летит (`body.con-zoom-open`): второй X по
  контракту отменяет открытие, и на нагруженном 4K ретраи шли «открыть → отменить → открыть».

### 2.5 Footer: смысл и устойчивость
- Два якоря: информация слева (`margin-right: auto`), глаголы справа; ширина плиты = ширина сцены
  (`2 × (--con-rules-w + 1.1rem) + 320px × --card-zoom-fit`).
- Чип статуса — два факта **строками**: где стоит карта (`На голосовании · Побеждает` / `Принята`) над доступом к
  эффекту партии (`▢▢ 1/2 недоступен` · `доступен · партия правит` · `доступен всем`). В строку пара уходила за левый
  край бара рядом с причиной отказа (Deck: чип 614 + причина 307 px в 1192) — `scrollWidth` этого не видит, потому
  что правый якорь выталкивает переполнение влево.
- Глагол: строка деталей фиксированной высоты (иконка М€ = высота строки причины), цифра позиции — один advance
  (`min-width: 1ch`; у консольного шрифта нет табличных цифр). Измерено: высота плиты постоянна на всех состояниях
  (1080 — 81, TV — 183, Deck — 74 px), глаголы не сдвигаются при листании, худший случай (цена резерва + «Сначала
  завершите текущее действие» рядом с самым широким чипом) помещается на всех трёх профилях.
- 2/2 — только доступ к эффекту партии; «доступен» не дублируется в колонке партии (там правило, в footer — состояние).
  Информационные элементы — не остановки фокуса.

### 2.6 Тексты — один источник
- `PartyEffects.ts` `text.passive/action` и `ResolutionCatalog.ts` `text.effect/winner/passive/action/quest`
  (`IClientResolution.text.winner` — новое поле). Потребители: осмотр, информационная зона режима (`ownText` +
  `ownWinner`), строка правящей партии, плитка действия партии в «Действиях карт». `text.rule` не менялся.
- Удалены мёртвые RU-ключи прежних формулировок; сохранены `Place 4 delegates` (строка лога уже сыгранных партий) и
  `Add 2 data or 2 microbes … holds that resource.` (описание в render DSL).

### 2.7 Две правки информационной зоны (вынужденные текстами)
- Часть «для победителя» больше не зашита в предложение эффекта — зона добавляет её явно (`ownWinner`).
- Строка партии получила меру чтения (`flex: 1 1 10.5rem`, перенос под широкую формулу; на Deck строки уже стоят
  столбиком, там мера снята) — новое действие Красных не помещалось узкой колонкой рядом с формулой (220 > 188 px).

## 6. Ограничения (честно)

- «Сначала завершите текущее действие» вместе с ценой резерва проверено подстановкой текста в DOM (реальное
  состояние «свой ход, но висит другой prompt, а режим голосования открыт» фикстурой не собиралось).
- В информационной зоне режима хвост «· раз за поколение» у действия партии остался (зона — отдельная итерация).
- Разрыв «10 / М€» на узкой колонке Deck возможен: неразрывных пробелов в локалях проекта нет, конвенцию не вводили.
