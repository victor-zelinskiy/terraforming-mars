# Turmoil Redux — fullscreen-осмотр резолюции: одна сцена (партия · карта · правила · footer)

Дата: 2026-09-16. Отдельная итерация поверх `TURMOIL_REDUX_PARLIAMENT_V5.md`: только fullscreen-осмотр резолюции
(X на выбранной карте режима голосования, X на принятой карте Правительства) и общие компоненты, которые он
использует. Обзор Парламента, нижняя панель голосования, зона делегатов и стоимость на кнопке голоса не трогались.
Правила Redux и заглушки не менялись; два новых **не раздаваемых** (`copies: 0`) примера в каталоге существуют только
для проверки компоновки.

---

## 1. Композиция

```
┌─ ◈ ПАРТИЯ РЕЗОЛЮЦИИ ─┐   ┌────── карта ──────┐   ┌─ § ПРАВИЛА ──────────────┐
│ [печать] ИМЯ    [⚡]  │   │                   │   │ ЭФФЕКТ РЕЗОЛЮЦИИ         │
│ контекст партии       │   │   крупная         │   │ [графика] предложение    │
│ [печатная формула]    │   │   резолюция       │   │ уточнения framework      │
│ ЭФФЕКТ ПАРТИИ  текст  │   │   (размер прежний)│   │ ЗАДАНИЕ ПРЕДСЕДАТЕЛЯ     │
│ ДЕЙСТВИЕ ПАРТИИ текст │   │                   │   │ [графика] условие        │
│ раз за поколение · …  │   └───────────────────┘   └──────────────────────────┘
└───────────────────────┘
      [● НА ГОЛОСОВАНИИ · сейчас побеждает │ ЭФФЕКТ ПАРТИИ ▢▢ 1/2 НЕДОСТУПЕН]   [B ЗАКРЫТЬ]
```

| Область | Что | Откуда |
| --- | --- | --- |
| Слева (ячейка лора) | `ConsoleResolutionAside`: плашка партии `ConsolePartyPlaque size="aside"` (печать · имя · бейдж действия · одна строка контекста · печатная формула через `ConsolePartyFormula`) + текстовый блок механик — тот же `ConsoleCardRulesPanel` (`embedded keepOrder`) | `resolutionPartyAnnotations(party, model, viewer, canActNow)` |
| Центр | карта без изменений (тот же `.pcard` face, тот же fit) | — |
| Справа | `ConsoleCardRulesPanel keepOrder` с **графикой блоков** (`CardAnnotation.graphic` → `PremiumMechanicsPanel`): «Эффект резолюции» (графика + предложение + факты framework), «Задание председателя» (графика + условие, без награды) | `resolutionAnnotations(id)` |
| Footer | `ConsoleResolutionStatus`: жизненное состояние (`На голосовании` / `Принята`, хвост «сейчас побеждает») + чип «Эффект партии» с индикатором своих делегатов | `resolutionStatusOf(id, model, viewer)` |

Блоков «Эффект партии» и «Статус» справа больше нет; правил ничьих и общих политических правил в осмотре нет
(они остались в режиме голосования и в осмотре партии).

## 2. Контракты

- **`CardAnnotation.graphic?: ICardRenderRoot`** (annotationModel) — печатная графика блока; `ConsoleCardRulesPanel`
  строит `buildMechanics` один раз на набор (`graphics` computed), текст-only корень не рисует пустую плиту.
- **`ConsoleCardRulesPanel keepOrder`** — читать блоки в порядке `order` (без сортировки по типу и без измерения
  якорей): для партии эффект стоит ПЕРЕД действием, как рисует формула; для резолюции эффект перед заданием.
- **`CardZoomModal #aside`** — opt-in слот левой ячейки (там, где у проектной карты лор); `hasAside` входит в
  `hasFlank`; резерв fit-движка — тот же `--con-rules-w + 1.6rem` симметрично, поэтому вторая колонка **не меняет
  размер карты** (1080: 632×908; TV 4K: 1263×1816 — как и при одной панели правил).
- **`dialog.con-zoom--parliament`** (класс шелла, когда на сцене резолюция): обе колонки стоят в рамке высотой
  ровно с карту (`calc(460px * var(--card-zoom-fit))`, top-anchored) — заголовки колонок на линии верхнего края
  карты для любой резолюции, короткое чтение обнимает содержимое, длинное не уходит ниже подошвы карты. На
  handheld рамка снята (карта на минимальном zoom, полоса выше карты — колонки берут всю полосу, центр по карте),
  и ширина колонок сцены = базовые 21rem (Deck-овые 24rem одной панели не помещаются парой рядом с 320-px картой;
  21rem — то, что и резервирует fit-движок, читающий html-токен).
- **Модель статуса (`resolutionInspectModel.ts`, чистая, spec'd)**: `lifecycle` `vote|enacted`; `access`:
  `everyone` (принята — у всех, индикатор не рисуется), `held` (+`basis` `delegates|ruling|granted`, места
  показываются только для `delegates`), `progress` (`mine` из `slot.votes.filter(owner === viewer)` — нейтральные
  и чужие никогда не заполняют, ≥3 своих рисуются как полная пара; счёт показан как `min(mine, 2)/2`). Источник
  доступа — серверный `PartyAccessModel.hasEffect`, не пересчёт делегатов. Нет модели / карта не на столе →
  `undefined` → footer молчит.
- **Состояние действия партии** (общая деривация `partyMechanicBlocks` для осмотра партии и колонки): «использовано
  в этом поколении» · «доступно» · «доступно в ваш ход» (`canActNow` = `myTurn && awaitingInput` — гейт
  исполнения, не причина) · серверная причина · без доступа — только «Раз за поколение».
- **Движение**: карта летит как раньше (прокси → `showModal` на посадке); ячейки колонок `.card-zoom-side/-aside`
  в `--flight` стоят с `opacity: 0` и `translateX(∓1.2rem)` и раскрываются наружу от карты после посадки
  (opacity 220 / transform 300 мс, `@con-ease-enter`) — вместе с footer'ом; на закрытии складываются к карте под
  её обратным полётом (160/220 мс). Внутри сцены быстрый `--closing` fade хостов снят, чтобы складывание было видно.
- **Dev-примеры** (`ResolutionCatalog.ts`, `copies: 0`): `RDX_DEV_COMPOUND` (Красные; длинное имя, две строки
  графики, часть для победителя через `winnerSteps`) и `RDX_DEV_SCIENCE` (Учёные; одна строка с условием).
  Фикстура для проверки — `parliament.json` со слотами `RDX_DEV_COMPOUND#0 / RDX_DEV_SCIENCE#0 / RDX_DEV_PASSIVE#0`
  и `partyActionUses[p1][Scientists] = 1` (в репозиторий не входит; собирается одной командой node — см. §4).

## 5. Ограничения (честно)

- LB/RB между резолюциями внутри сцены недостижимы из текущих дверей (v5 убрала X с области голосования; режим
  открывает одну карту) — синхронность обновления колонок проверена сменой выбранной карты между открытиями и
  кодом (все три колонки и footer — computed от `consoleCardZoom.card`, один flush).
- Осмотр партии (X на плашке) не менялся кроме строки состояния действия («доступно в ваш ход» не в свой ход).
- Заглушки: справа спокойная строка «Собственного эффекта нет» без графики; блок сохраняет место главного.
