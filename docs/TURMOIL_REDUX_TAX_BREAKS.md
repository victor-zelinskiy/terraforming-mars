# RX41 · «Налоговые льготы» (Tax Breaks)

Сдана 2026-10-21 (не запушено). Печатное правило: *«When enacted: Each player increases their M€ production 1 step for
each different type of card resource they have + Influence. (Max. 5)»* Партия — Индустриалисты; задание председателя —
2 меха на свои карты. Базовая карта, дополнений не требует (держателей мехов в скоупе девять — RX37).

Процедура автора — `docs/claude/parliament-resolution-checklist.md` (§1; § RX04 — счётный член; § RX21 — две меры одного
счёта; § RX40 — `holders` и новый абзац «У `holders` ДВЕ МЕРЫ»); гард — `tests/parliament/ResolutionContract.spec.ts`.
Промт владельца — `docs/claude/prompts/resolution-rx41-tax-breaks.md`.

**Решения владельца** (батч не задавался — приняты рекомендации промта, как у RX40): **Р1** имя RU «Налоговые льготы»;
**Р2** «вид, который у вас есть» = вид с хотя бы одним ресурсом на карте (мера движка Tradesman / Collector), держатель
с 0 вида не даёт.

## 2. Мера `types` у счёта `holders`

`resolutionCountKind` теперь `{kind: 'holders', measure: 'cards' | 'types'}` — прецедент RX21 (`board` с `cells | tiers`):
одна выборка, две меры, объявление вида говорит какая. `cardsWithResources` → `cards` (RX40, поведение без изменений);
`cardResourceTypes` → `types`. Число — через ОДНУ функцию `holdersMeasured(measure, byCard)` над ОДНОЙ группировкой
`holderKindsOf(byCard)` (виды в порядке первого держателя в игре, карты вида — в порядке игры). Модель / запись несут тот
же `byCard` (карта · её вид · число) — вид-группировка выводится, вторым полем не хранится. ПО «одной ещё» мера `types` не
считает (у выплаты по видам нет адресатов-карт). Стенд — `countHoldersToward` с той же мерой, прибит к движку корпусом
(и к выражению движка `new Set(getCardsWithResources().map(resourceType)).size`). Шаг `eachCountedCardStep` и гард
`checkEachCounted` принимают только меру `cards`.

## 3. Общий шаг производства по счёту

`productionCountStep(id, effect, words)` (`resolutions/ResolutionProductionCount.ts`) — тело «счёт → `uncappedAmount` /
`scaledAmount` → `production.add(…, {log: false, from: {resolution}})` → одна строка журнала (с потолком или без; влияние —
только если оно член части) → запись `production` со счётом и ВСЕМ его разбором» было написано четыре раза: RX02, RX04,
RX08, RX17 переведены на него байт в байт (их спеки — без правок, зелёные). Отказ на неподходящей декларации (не
производство / без счёта) — при построении.

## 5. Бот — ничего

D3: производства у бота нет; это выплата, D11 её не касается. Задание «2 меха» для бота НЕДОСТИЖИМО — ни одна область
бота не хранит мехи (`botQuestTableOf`: виды тайлов колоний + аэростаты); блок задания говорит это (`botReachable`).

## 6. Чтения

- **Лицо**: «1 [пр. M€] / [держатель с «?»] + [влияние]», «макс. 5». Держатель — глиф RX40 (`PremiumResourceCardGlyph`) с
  проп `wild`: вместо трёх кубов — ОДИН существующий `wild.png` (Tradesman печатает тот же «?» за «разные виды»). Два
  закона различимы на взгляд: три куба = каждая карта с ресурсом, один «?» = каждый вид.
- **Глиф счёта** в чтениях — `{kind: 'resource-card', wild: true}` (`yieldCountPresentation('cardResourceTypes')`).
- **Панель голосования**: «[держатель ?] 3 + [влияние] 3 = 6 → +5 МАКС.» (сумма до потолка — общий класс, PL-799) и
  строка видов (`kindsReadingOf` → `[data-parl-vote-kinds]`): «3 вида ресурсов · [животное] Рыба · Птицы · [аэростат]
  Аэростаты · [данные] Суперкомпьютер» — число ведёт, каждый вид — неразрывная группа; держатель с 0 не в списке.
- **Осмотр (X)**: «Учтены сейчас: Животное — Рыба, Птицы · Аэростат — Аэростаты · Данные — Суперкомпьютер»; после
  принятия — «…при принятии».
- **Чужие колонки** — свои виды (леджер и LB / RB). **Итоги** — «+5 [пр. M€]», пропуск — названная причина целиком.
- **«Полигон»** — семейство `counted-holders`, 14 сценариев (три вида, голосование с потолком, ноль и ноль, держатель с 0,
  один вид на трёх картах, корпорация, ровно 5, потолок счётом, потолок влиянием, места, запись, зритель, задание 0/2 и ✓).
  Строка «КАРТЫ В ИГРЕ» у счёта `holders` (RX40 и RX41) читает `holdings` сценария: каждая карта — вердикт общего
  `holderCountVerdict` («✓ Животное 2» / «✕ На карте ещё нет ресурса»), число строки — мера общего `countHoldersToward`
  (PL-803: строка читала `cards`, которых у таких сценариев нет, и печатала «0» под чтением «3»).
