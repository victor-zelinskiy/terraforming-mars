# Turmoil Redux — Development Craze (RX10): первый живой ПАССИВ

Дата: 2026-09-23. Промт: `docs/claude/prompts/resolution-rx10-development-craze.md`. Продолжение
`TURMOIL_REDUX_COLONIZATION_FUNDING.md` (RX08) и `TURMOIL_REDUX_COLONY_CONTEST.md` (RX09); шов пассива —
`DEV_PASSIVE` («Urban Charter») в `ResolutionCatalog.ts`.

Development Craze — десятая настоящая резолюция и **первая с настоящим пассивом**. До неё семейство пассивов было
отрепетировано только dev-примером (`copies: 0`). Карта делает пассив живым и — по требованию владельца — ВИДИМЫМ:
своя графика чипа, своя строка в списке эффектов, явный показ срабатывания при размещении с осмотром резолюции.

## 2. Правило

Печатный текст: *When enacted: Gain steel equal to your Influence. Effect: Double all placement and adjacency
bonuses you get for placing tiles on Mars.*

- **Немедленно всем**: `1 × влияние` стали в запас, без потолка (семейный шаг Biodome Contest; влияние 0 — пропуск
  с именем). Запись `kind: 'stock'`, чип в рельсу штатной волной.
- **Пассив, пока принята**: бонусы клетки платятся движком ДО парламентского хука (`Game.grantPlacementBonuses`:
  печатные бонусы → океанское соседство → Ares-соседство → `ParliamentHandler.onTilePlaced`). Поэтому «удвоить»
  технически и по смыслу = **выдать те же бонусы второй раз** теми же входами движка, под источником резолюции:
  `grantSpaceBonuses` · `grantOceanAdjacencyBonus` (выделен из `grantPlacementBonuses`, один путь для обеих выдач) ·
  `AresHandler.earnAdjacencyBonuses` под Ares. Хук получает контекст `{coveringExistingTile}` — при покрытии тайла
  (океанский кавер Ares) движок печатные бонусы не платил, значит и второй раз не платит.
- **Только Марс** (`SpaceType.COLONY` — ничего), **только свои размещения** (хук пер-игрок), **бот не участвует**
  (`BotParliamentPolicy.participates`), **ровно пока принята** (`enactedDefinition()` читается в момент хука).
- Ход Mars Nomads (камп) тайл не размещает и хука не запускает — не удваивается (карта говорит «for placing tiles»).

### 2.1 Виды бонусов — что удваивается и как

| Вид бонуса (`SpaceBonus`) | Удваивается | Как |
| --- | --- | --- |
| сталь, титан, растения, тепло, энергия | да | второй `stock.add` под источником резолюции; в сцене — вторая волна тех же иконок |
| карта (`DRAW_CARD`) | да | второй `drawCard` (в руку) |
| микроб / животное / данные / наука / астероид | да | второй `AddResourcesToCard` — тот же вопрос холдеру (одиночный холдер — авто-применение движка, как и в первый раз) |
| производство энергии | да | второй `production.add` (партийные хуки видят второй шаг) |
| **океан (Hellas)** — платный | да, ОБЕ раза | второе предложение «заплати 6 → океан»; неоплатимый счёт **пропускается по имени** (см. 2.2) |
| **температура / температура 4 M€ (Vastitas)** — платный | да | второе предложение «заплати 3/4 → шаг» (проверка максимума — в момент выдачи) |
| **колония (Terra Cimmeria)** — платный | да | второе предложение «заплати → колония» |
| делегат (`DELEGATE`) | формально да | под Turmoil Redux `Turmoil.ifTurmoil` пуст — ничего |
| океанское соседство (2 M€/океан, 3 у Lakefront) | да | тот же `grantOceanAdjacencyBonus`; эхо несёт тот же `oceanSpaceIds` |
| Ares-соседство | да | второй `earnAdjacencyBonuses` — второй манифест; клиентская сцена летит по НОВЕЙШЕМУ гранту клетки (первый Ares-полёт не проигрывается — см. §7) |

### 2.2 Особые случаи — трактовка и решение (для владельца)

**Платные бонусы** (океан Hellas, температура Vastitas, колония Terra Cimmeria). Буквальное прочтение «получаете
дважды» = **второе предложение той же сделки**; оно ограничено (одна дополнительная сделка) и не зациклится (второй
океан на полюсе Hellas невозможен — полюс занят городом). Реализовано буквально. Но оба счёта ставятся в очередь ДО
оплаты первого, а обязательный счёт `SelectPaymentDeferred` бросал исключение у игрока без денег — крах посреди
хода. Решение общее, не только для RX10: `SelectPaymentDeferred.skipIfUnaffordable` — проверка **в момент исполнения
счёта** (образец `atMost`): неоплатимая сделка пропускается с журнальной строкой «Бонус клетки «океан» пропущен —
${игрок} не может заплатить ${N} M€». Тот же шов защищает Frontier Town и Jansson (они тоже выдают бонусы клетки
повторно через `grantSpaceBonuses`). Первую выдачу это не меняет: её сделку уже проверил валидатор размещения.

**Температура у максимума.** Проверка `getTemperature() < MAX` идёт в момент выдачи (оба предложения ставятся
при одной температуре); второй оплаченный шаг при достигнутом максимуме — no-op движка (`increaseTemperature`).
Крайний угол Vastitas; не трогал — описываю.

**Ares-соседство.** Сервер платит дважды честно; манифест `aresAdjacencyGrants` получает две записи; клиентская
сцена (`latestAresGrantFor`) летит по новейшей и «съедает» её один раз — первая Ares-волна на экране не играется.
Ares + Redux — край; оставлено с пометкой (§7).

## 3. Видимость — что сделано

### 3.1 Графика чипа
`b.effect(undefined, eb => eb.emptyTile('normal', {size: SMALL}).asterix().startEffect.adjacencyBonus().text('x2'))` —
композиция скана «[тайл с бонусом] : БОНУСЫ × 2 *» словарём игры: пустой гекс со звёздочкой (тайл на Марсе) →
глиф «тайл с бонусом» (тот же ассет, что печатают правила Ares-соседства) × 2. Одна отрисовка: лицо «Грамоты»,
строка списка эффектов, осмотр.

### 3.2 Строка в списке эффектов (Информация → ЭФФЕКТЫ)
`ConsolePartyEffectsStrip`: строка принятой резолюции идёт **первой** (закон раньше привилегий), над названием —
кикер «ПРИНЯТАЯ РЕЗОЛЮЦИЯ» (`.con-pfx__law`, золото), плитка носит золотой шов правительства
(`.con-pfx__item--resolution` — тот же знак, что `.con-parl__gov--enacted`). Графика — тот же `renderData`.
Второго компонента нет. Юнит: `ConsolePartyEffectsStrip.spec.ts` (4).

Попутно: у эффектных строк render-DSL пустой хвостовой слот приходит из JSON как `null`, и `PremiumMechNode`
получал `null`-узел (prop-warning). `isRenderableNode` теперь отбрасывает `null`.

### 3.3 Срабатывание при размещении

**Физика.** Пассив публикует эхо `lastPlacementBonusEcho` (self-only, транзиент, образец `lastOceanBonus`):
`{spaceId, resolution, printed, ocean?}`. Сцена размещения (`consoleTilePlacement.ts`) принимает эхо только для
армированной клетки, держит в холде ОБЕ доли (счётчик тикает на посадке каждой волны — дважды, а не одним числом)
и после первой волны (печатные → вода → Ares) играет **вторую волну** тех же иконок с тех же точек и той же воды
(`runEchoWave`, пауза `ECHO_WAVE_BREATH_MS` 320 мс, свидетель `data-echo="1"` на `.con-tileplace`). Пробник e2e
подтвердил: эхо объявлено на отрисованных кадрах, счётчик прошёл через промежуточное значение (2 → 5 → 7), первая
волна закончилась ДО эха. По кадрам две волны читаются как две: между ними пауза и второй тик счётчика; отдельной
подписи «×2» на поле нет — подпись не опережает объект, а источник называет карточка закона.

**Нотификация — «карточка закона».** Дыра `effectSourceCard` закрыта честно: поле `effectCard: CardName` заменено
одним объединением `effectSource: {kind:'card', card} | {kind:'resolution', resolution}`. Но главное открытие:
собственное действие зрителя в консоли ПОДАВЛЯЕТСЯ (закон «no self-spam»), а пассив всегда срабатывает внутри
действия (размещение = стандартный проект / розыгрыш) — маркер `effect-triggered` никогда не корень. Значит
«явный показ срабатывания» для того, кто размещал, требовал нового правила: **ответ ЗАКОНА на собственное действие
не подавляется** (`lawAnswerNotification`): маркер резолюции с непустой выплатой становится ОДНОЙ карточкой
`passive-effect` — заголовок «Сработал эффект», источник «Принятая резолюция · Строительная лихорадка», строка
самого эффекта («получает бонусы размещённого тайла второй раз»), чипы ТОЛЬКО выплаты закона (+2 стали, не +5
всего действия), hold X «Осмотреть» → **существующий осмотр резолюции** (`inspectParliament`, CTA
`inspect-resolution` через `notificationBus`). Пустой маркер (голая клетка) карточки не даёт. Для корня-пассива
(`passive-effect` как корень цепочки) источник-резолюция тоже доходит и CTA — осмотр.

**Досье клетки.** Партийные факты досье были, а факт резолюции — нет: досье обещало +2 стали, а платилось +4.
Добавлен шов `ResolutionPassive.placementFacts` (двойник хука для досье; гард контракта требует его у тайлового
пассива): RX10 повторяет факты `printed-placement-bonus` / `ocean-adjacency-bonus` под именем резолюции.
`placementReduxPreview.spec` § Development Craze: preview == commit.

## 4. Прогноз (`forecast`)
На каждую операцию, кладущую тайл на Марс, — один `deferred`-факт без числа («Development Craze pays the placement
and adjacency bonuses of a tile you place on Mars a second time»): клетка выбирается после прогноза, число было бы
догадкой. Спек: `DevelopmentCraze.spec` § forecast.

## 7. Открытое / замечено по пути

- Ares + Redux: клиентская Ares-волна играет только новейший грант клетки (первая из двух не летит); сервер честен.
- Подвал осмотра резолюции печатает «ЭФФЕКТ ПАРТИИ · ДОСТУПЕН ВСЕМ» для принятой РЕЗОЛЮЦИИ — существующая подача
  `ConsoleResolutionStatus`, по глоссарию просится «эффект резолюции»; не трогал.
- Плита источника ревила карты Марс вперёд говорит «Действие партии» о ПАССИВЕ партии — существующее.
- Карточка закона для города ждёт закрытия цепочки (задание председателя / добор) — закон атомарной подачи; так и
  задумано, но стоит знать.
