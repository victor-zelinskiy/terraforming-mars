## 1. Что изменилось — коротко

| Область | Было (v2) | Стало (v3) |
| --- | --- | --- |
| Голос | стадия в средней полосе + рейка прогноза под картами + большая нижняя форма | **шаг голосования** — фазовый спуск кадра `parliament`: обзор отступает в точку нажатия, карта переезжает в колонку-герой слева, справа раскрывается поверхность решения; B сворачивает ту же фразу |
| Физика карты | X открывал копию поверх источника (`origin: textual`); стадия рисовала карту второй раз | **один физический объект**: X поднимает карту из её слота (`origin: physical`, слот пуст через `.con-zoom-hold`), A из вьюера передаёт её в герой шага (zoom handoff), B возвращает FLIP'ом в слот |
| Делегаты | белые квадраты (нейтральные) vs кубы игроков, точки-микроиндикаторы | **одна система**: `PlayerCube` для игроков, тот же куб в стали (`steel`) для нейтральных; **гнёзда** (`__socket`, `__place`, `__support-place`) — заполнено/пусто читается сразу: лобби 0/1, порог эффекта 1 из 2, народная поддержка 0–3 |
| Источники движения | куб летел «из шапки» | **реестр мест** `[data-parl-seats]`: у каждого игрока гнездо лобби · резерв · кресло; полёт голоса стартует из гнезда лобби или резерва зрителя и садится в **место на ленте карты** (пустое гнездо `[data-parl-vote-place]`) |
| Правительство | огромная печать рядом с крошечной принятой картой | принятая карта — **главный объект** (крупнее), партия — компактный **бейдж правителя** (эмблема · «правящая партия» · имя · формула); до первой политической фазы — честное **пустое место** «Резолюция ещё не принята» |
| Голосование | V1/V2/V3, сортировки не было, но ярлыки мешали | общий заголовок **«Голосование · ближайшая к правительству — первая»**, слот подписан эмблемой + именем партии, бейдж «ПОБЕЖДАЕТ»; порядок = порядок ничьей |
| Печать партии | имя терялось (Союз/Учёные почти чёрные), точки доступа/поддержки/использования были одинаковыми | **анатомия** печать · имя (яркий тракт) · **бейдж действия** (доступно — залит мятой, использовано — штамп ✓, не сейчас — янтарный контур) · чип состояния с **кубами зрителя в двух местах порога** · формула · **три места поддержки** со стальными кубами |
| Эмблемы | Союз и Учёные — два «кольца» | новые SVG: **Союз** — триада сплошных полумесяцев вокруг ядра; **Учёные** — гексагональная молекула с ядром; различимы на 48 px |
| Лицо резолюции | предложение задания на лице, dummy — крупная надпись в центре | зона задания = кикер + **графика условия** + метки награды «КРЕСЛО + ▸1»; dummy — тихая строка «Собственного эффекта нет» на месте механики; три **dev-примера** реальных механизмов (мгновенный / пассивный / действие) в каталоге с `copies: 0` |
| Повестка | шаг подсвечивался | **маркер едет** по треку директором Гидросети (`runHydroMarkerGlide`): заряд → скольжение → прибытие → фиксация; реальный куб проявляется под прокси; награда «карта» — **обложка поднимается со ступени** (сцена `board-card-bonus`, источник `agenda-step`) и дальше стандартный добор в руку |
| Эффекты резолюций | seam `passive?: undefined` — пассивный эффект резолюции негде было подключить | `ResolutionPassive` (`IResolution.ts`): те же хуки, что у партий (`onTilePlaced` / `onTerraformRatingGained` / `onProductionChanged`, для всех участников, источник события `{kind: 'resolution'}`) + **обязательный прогнозный двойник** `forecast(ctx)`; факт прогноза с источником `resolution` (R3 / композер), в проводнике эффектов — печать партии и печатное имя резолюции; InfoPanel «Эффекты партий» показывает строку принятой резолюции с её графикой; dev-пример «Городская хартия» (2 М€ за город на Марсе) доказывает seam |
| Тексты | «У вас есть…/У вас нет», дубли у Союза и принятой резолюции, «1 делегатов» | описания механик исправлены на сервере (`PartyEffects`), нота Союза не дублируется, «принята» сказано один раз, множественное число через `{делегат|делегата|делегатов}` |

## 2. Архитектура шага голосования

```
ПАРЛАМЕНТ › <резолюция> › ГОЛОС                       (descendWorkspaceFrame('parliament', name, 'Vote'))
┌ герой ───────────┐ ┌ поверхность решения ───────────────────────────────────────────┐
│ [карта]          │ │ ДЕЛЕГАТ   [гнездо] Свободный делегат из лобби | Из резерва  −5 M€ │
│ эмблема · партия │ │ НА КАРТЕ  ● ● [ ]          ← лента + место нового делегата        │
│ · ПОБЕЖДАЕТ      │ │ ПРОГНОЗ   делегатов 1→2 · ваши 0→1 · лидер ●→вы · эффект партии  │
│                  │ │           (только то, что МЕНЯЕТСЯ; «→» пунктир = прогноз)        │
│                  │ │ [зона счёта — при оплаченном голосе]                              │
│                  │ │ (A) Отправить делегата                        ПОЛНОЕ ДЕЙСТВИЕ    │
└──────────────────┘ └───────────────────────────────────────────────────────────────────┘
```

- **Один слой, одна композиция.** `ConsoleParliamentSection.vue`: `.con-parl__field` держит тело обзора и поверх него
  `.con-parl__vote` (`v-if` + `<transition :css="false">`, хуки `consoleParliamentVoteMotion.ts`). Вход: тело
  отступает в точку нажатия (`descendRecede`), поверхность раскрывается из ректа слота (`descendUnfold`), карта делает
  FLIP из ректа своей копии в слоте (`descendFlipFrom`), строки решения всплывают каскадом. Слот носит `--carried`
  (его карта `visibility: hidden`, место сохраняется) до тех пор, пока герой не вернётся. B: каскад уходит, поверхность
  складывается в слот, тело возвращается, герой FLIP'ом садится в слот, и только в `done` слот показывает карту.
- **Из вьюера — тот же шаг.** `inspectParliament` передаёт зуму `ConsoleZoomAction {labelFor: 'Vote', reasonsFor,
  execute: openVoteFromViewer, handoffTarget: '.con-parl__vote [data-zoom-handoff="parliament-vote"]'}`; слой
  вооружается `armParliamentVote({instant: true})` — карта летит из вьюера в герой (`playZoomHandoff`), тело стоит
  отступившим. X внутри шага — физический зум из героя, возврат ничего не сбрасывает.
- **Стадии**: `browse → vote → submitting → (paying) → landed → уход`. `answerKey` = `gameAge | promptIdentityKey(wf)`:
  ответ сервера — изменение состояния ИЛИ новый промпт (счёт оплаченного голоса поднимается до оплаты — возраст не
  меняется). `submitVote` требует `stage === 'vote'` — второе A в том же ударе ничего не шлёт. После ответа
  `landVote()` находит новейшего делегата зрителя на карте, куб летит из гнезда-источника (`[data-parl-lobby-cube]` /
  `[data-parl-reserve-cube]`) в его место на ленте шага, счётчики тикают на посадке, затем `flow-complete` → одно
  охраняемое завершение шелла (workspace уходит).
- **Прогноз** — `voteForecastOf` (проекция сервера): строки только для изменений (всего · ваши · лидер · победитель ·
  доступ к эффекту · одно предупреждение); текущие значения слева, прогноз справа с пунктиром; после посадки —
  `--done` без пунктира. Нигде больше прогноз не повторяется (рейка удалена).
- **Оплаченный голос.** Сервер помечает счёт: `SelectPaymentModel.votePayment = {party, cost}` (маркер, никогда не
  заголовок; `SelectPaymentDeferred.Options.votePayment` → `SelectPayment.markVotePayment`). Клиент:
  `ConsoleShell.taskEmbedTarget` телепортирует `ConsoleTaskHost` в `[data-embed-slot="parliament-vote"]` при
  `consoleParliamentUi.voteStanding` (публикуется секцией `flush: 'post'`); секция переходит в `paying`; B на счёте =
  свернуть весь workspace (карточка на поле — путь назад); **после перезагрузки** `ConsoleShell.parliamentBillStanding`
  открывает Парламент вокруг счёта, `votePayment`-watcher секции пересобирает шаг (карта несётся, числа до голоса,
  источник — резерв, стадия `paying`).

## 3. Удалённые дублирующие сценарии

- Стадия `vote` в средней полосе + `[data-parl-consequences]` + чипы прогноза в нижней форме — удалены.
- Рейка прогноза `[data-parl-rail]` (`railForecast`, `railRows`, `voteForecastRows(compact)`) — удалена с обзора.
- Ярлыки `V1/V2/V3` и `tiePriority` как подпись слота — удалены (порядок слотов и есть порядок ничьей).
- Текстовый источник зума для Парламента (`origin: {kind: 'textual'}`) — заменён физическим для карт, печатей и героя.
- Отдельный пульс шага Повестки по `agendaPosition` — заменён общим `playAgendaGlide` (живой `lastAdvance` и бит
  итогов).

## 6. Честные ограничения

1. **Итоги поколения** физичны частично: маркер Повестки едет; возврат делегатов в реестр, переезд принятой карты,
   раздача новых карт и наполнение поддержки по-прежнему — текстовые биты с подсветкой объектов.
2. **Награда-карта со ступени Повестки** проверена на уровне модели/сцены (сопоставление источника, ожидание маркера);
   e2e-сценарий, доходящий до карточной ступени трека, не построен.
3. Награда «РТ» на ступени — тик счётчика HUD и пульс ступени, без отдельного полёта чипа.
4. R3-слой «Эффекты» в композере партийного действия отсутствует (как в v2).
7. Пассивный эффект принятой резолюции проверен на уровне сервера/модели и структурно на клиенте (проводник, InfoPanel);
   в игре его не увидеть, пока в колоде нет резолюции с пассивным эффектом (dev-пример не раздаётся).
5. Арты резолюций — по-прежнему печати партий в окне арта; dev-резолюции только для осмотра (`copies: 0`).
6. Записи движения сняты Playwright'ом при `PARL_VIDEO=1` (1920×1080, из окна теста) — ориентир для ритма, не
   продуктовое видео.
