## 1. Сервер — что работает

### 1.1 Модуль `src/server/parliament/**`

| Файл | Ответственность |
| --- | --- |
| `Parliament.ts` | Состояние парламента: три слота области голосования, принятая резолюция, задание председателя, председатель, лобби, `voteSeq`, Popular Support, Повестка, бонусы влияния, гранты эффектов, использования действий, колода/сброс резолюций, прогресс фазы, отложенные политические действия. **Один леджер делегатов** — резерв/нейтральный запас *выводятся* из голосов, лобби и кресла (`reserve()`, `neutralSupply()`, `assertLedger()`). Победитель/лидер/ничьи (`leaderOf`, `winner()` — приоритет слота V1 при ничьей, самый ранний первый делегат при ничьей игроков). Доступ к партийному эффекту (`access()` → правящая ∨ ≥2 своих делегата ∨ грант карты; грант **не** удовлетворяет требование карты). Сериализация v1 с `IncompatibleParliamentSaveError`. |
| `SerializedParliament.ts` | Формат сохранения, включая `phase` (шаг фазы, применённые ключи, состояние эффекта per player, ожидающий выбор) и `pendingActions` (незавершённый сброс Красных, невыбранное кресло). |
| `BotParliamentPolicy.ts` | `BotParliamentMode = 'none'`: бот не участвует (нет делегатов, голосов, промптов, партийных бонусов, заданий). |
| `ParliamentPhase.ts` | Политическая фаза как **собственная `Phase.PARLIAMENT`**: победитель → Повестка → Popular Support → принятие → эффекты резолюции (шаги `EnactStep`, ASK-шаги через `setWaitingFor` + `game.save()`) → (финал? стоп : обновление области → лобби). Идемпотентность по ключам шагов; `resume()` после загрузки продолжает с того же шага без повторных наград. |
| `ParliamentHandler.ts` | Ход игрока: опция голосования (`SelectParty` с маркером `votePrompt`, оплата резерва через `SelectPaymentDeferred` **до** размещения), опции партийных действий, пассивные хуки движка (тайл, РТ, производство, карта, ресурс карты, колония, wild-метки), +1 РТ за озеленение через источник `parliament`, восстановление отложенных промптов после загрузки. Все точки входа — no-op без парламента и терпят `player.game === undefined` (unit-тесты карт). |
| `parties/PartyEffects.ts` | Шесть партий: Союз (бесплатная торговля через `TradeWithUnity`), Зелёные (+2 М€ за шаг РТ; производство М€ вместе с растениями/теплом), Учёные (wild-метка; действие: 2 данных или микроба), «Марс вперед» (сталь за тайл, карта за город), Индустриалисты (перестройка производства, `AndOptions`), Красные (подтверждение → добор 2 → **обязательный** сброс 2 с выплатой; незавершённый сброс переживает перезагрузку). Точка коммита каждого действия — само меню (вложенный `OrOptions`/`AndOptions`), использование записывается в момент мутации. |
| `quests/QuestTracker.ts`, `quests/ChairmanSeat.ts` | Задания председателя: стартовое (поколение 1: +3 производства тепла) и из определений резолюций; засчитываются только действия самого игрока в фазе действий и не из политических/планетарных/солнечных/ботовых корней (event-scope, не журнал). Кресло: делегат из резерва → из лобби → иначе выбор резолюции (`SelectParty`, маркер `chairman-seat`), предыдущий председатель теряет кресло. Повестка: 12 шагов, бонусы РТ/карта с атрибуцией `Agenda track`. |
| `resolutions/*` | `ResolutionDefinition`/`EnactStep`; каталог из 12 dummy-резолюций (по две на партию, у каждой своё задание) + тестовая `RDX_TEST_CHOICE` (мутация → выбор → мутация → выбор) для проверки восстановления посреди фазы. |
| `TradeWithUnity.ts` | `IColonyTrader`: бесплатная торговля раз в поколение, флот тратится, причина недоступности — «уже использовано». |
| `ParliamentModel.ts` | Проекция для клиента (`GameModel.parliament`): слоты с лидером/победой/приоритетом/голосами зрителя, игроки, задание, фаза и её итог, для зрителя — доступность голоса и партийных действий с причинами и превью. |

### 1.2 Интеграция с движком
- `GameOptions.turmoilReduxExpansion`, ключ модуля `turmoilRedux` (требует Colonies, исключает классический Turmoil).
- `Game`: создание парламента, сериализация/десериализация, ветка `deserialize` для `Phase.PARLIAMENT`, порядок конца поколения
  «колонии → парламент → WGT», финальное поколение — шаги 1–3, затем финальные озеленения; `gotoEndGeneration` без повторного
  роста колоний.
- `Player`: голосование и партийные действия в меню действий; хуки РТ/карт/ресурсов. `Production`, `Tags` (wild-метки Учёных
  вне наград), `Colonies`/`Colony` (Союз, задания), требования `PartyRequirement`/`ChairmanRequirement`/`PartyLeadersRequirement`
  через фасад `game.politics` (`PoliticalOps`: Redux ↔ классический Turmoil), `calculateVictoryPoints` (без ПО озеленений),
  `CardFactorySpec.politics` (карты с политикой включаются в Redux **только** с явной готовностью `'redux'|'both'`).
- Effects framework: источники `party`/`resolution`/`parliament` в `EventSource`, категории журнала `parliament`/`political-phase`,
  токен `RESOLUTION` в логах, прогноз эффектов (`effectForecast.partyFacts`: Зелёные — РТ/производство, «Марс вперед» — тайлы) с
  источником `{kind:'party'}`.

### 1.3 Как проверено (сервер)

## 2. Клиент — что работает

> **Обновлено той же датой:** композиция workspace «Парламент» и двери партийных действий переработаны — см.
> `TURMOIL_REDUX_PARLIAMENT_UI_REWORK.md`. Колонка плиток действий, компактная полоса итогов и посадка «на месте» ниже
> описаны как было в нулевой итерации; актуальное: партийные действия — в «Действиях карт» (+ контекстная дверь из детали
> партии), талли и рейка фокуса у карт, партии 3×2 с одной зоной детали, полёт куба делегата из чипа шапки.

- **Создание партии**: строка «Turmoil Redux» в премиум-создателе, требование Colonies (`EXPANSION_REQUIRES`), MarsBot допущен.
- **Семейство резолюций на премиум-грани** (`CardType.RESOLUTION`, тема `resolution`, фиолетовая): эмблема партии в шапке, задание
  председателя в нижнем углу, dummy честно подписаны «эффекта пока нет»; баннер партийного эффекта (`partyEffectPremiumVm`,
  класс `pcard--party-banner` — эмблема как значок в окне арта, не растянутая картинка).
- **Эмблемы партий** — собственный набор форка `assets/parties/redux/*.png` (512 px, один язык: тёмный значок, тонкий золотой
  обод, светящийся символ партии); чёткие от плитки 40 px до полноэкранного баннера. Старые 154-px PNG Turmoil остаются
  классическим поверхностям.
- **Workspace «Парламент»** (слот колеса «Парламент», строка `parliament` в `WORKSPACE_KINDS`): шапка с крошкой `ПАРЛАМЕНТ › <субъект> › <ЭТАП>`
  и чипами (правящая партия, лобби/резерв, влияние, колода); верхний ярус — принятая резолюция + правящая партия + задание +
  председатель, область голосования из трёх слотов (приоритет V1, «Побеждает», лента делегатов, лидер, ваши голоса); нижний ярус —
  шесть партий (Popular Support, статус доступа, правило эффекта), Повестка (старт + 12 шагов, маркеры игроков, легенда), плитки
  действий (голос, четыре партийных действия) с причинами недоступности сервера. Стадии в зоне справа: **ГОЛОС** (источник
  делегата, стоимость, резерв, делегаты на карте, последствия), **кресло председателя**, **Индустриалисты** (две строки выбора),
  **Учёные** (ветка + карта), **Красные** (подтверждение с тоном опасности), отправка с таймаутом безопасности. Союз открывает
  колонии как вложенный кадр (`colonies` внутри `parliament`). Фит карт — измеряемый (`fitCards()`): зумы слотов и зоны принятой
  решаются из рамки за вычетом измеренной обвязки, на handheld зона принятой складывается в стек.
- **Осмотр**: X над резолюцией/партией — полноэкранный инспектор с блоками правил (эффект резолюции · партийный эффект · задание ·
  статус · «у кого есть и почему»). Вкладка «Эффекты» InfoPanel — полоса партийных эффектов зрителя. R3 в композерах — прогноз
  фактов партий (источник без карты, `forecastSourceIsCardless`; в слое R3 и в досье партийный факт несёт эмблему партии там,
  где карточный источник рисует свой печатный блок).
- **Маршрутизация**: `TaskKind 'party'` (маркер `votePrompt`, стадия кресла) — секционная задача Парламента, сворачиваемая;
  копирайт в `consoleTaskSummary`; журнал/уведомления — токен резолюции и подписи источников `resolution`/`parliament`/`party.owner`.
- **Сцена итогов политической фазы** — стадия `recap` workspace: при первом открытии Парламента в новом поколении итоги
  прошлой фазы (`lastPhase` сервера, никогда не журнал) проигрываются битами по объектам, которые они изменили: победитель →
  зона «Принята» вспыхивает, шаг Повестки, принятие, народная поддержка (плитки партий), обновлённые слоты, возврат делегата в
  лобби; крошка `ПАРЛАМЕНТ › ИТОГИ ПОКОЛЕНИЯ N`, A/B — продолжить; играет один раз на поколение (`consoleParliamentUi.recapSeen`),
  после — компактная полоса recap над телом workspace.
- **Посадка делегата** — после ответа сервера на голос стадия `landed`: новый куб зрителя падает на ленту (анимация transform /
  opacity), слот вспыхивает, бит держится `beginAnimationHold('parliament-vote-landing')`, и только затем flow покидает workspace.
- **Добор и сброс партийным действием** — источник reveal `{type: 'party'}` (Красные): экран «Получены карты» называет
  «Действие партии «Красные»»; обязательный сброс в режиме сброса руки называет партию (`discardIntent.partyName`) и считает
  выплату честно — по МЕТКАМ выбранных карт (`exchange.perTag`, 2 М€ за метку растений/микробов/животных), а не по картам.

## 3. Честные ограничения нулевой итерации

1. **Сцена политической фазы** проигрывается из итога сервера (`lastPhase`) при открытии Парламента, а не в момент самой
   фазы: между поколениями игрок видит исследование карт, а итоги — при первом входе в workspace (плюс линии фазы в журнале
   и уведомлениях). Шаги ASK резолюций (тестовая `RDX_TEST_CHOICE`) отвечаются через обычный effect-choice промпт с
   `choiceContext.source = resolution`; зона встраивания в стадии Парламента (`data-embed-slot="parliament"`) готова, но
   маршрут телепорта решения в неё в нулевой итерации не подключён (dummy-резолюции шагов не задают).
2. ~~**Посадка делегата** — бит на месте (падение куба на ленту), не полёт из чипа лобби/резерва через экран.~~ Закрыто
   переработкой UI: куб летит из чипа лобби/резерва в свою позицию ленты (`TURMOIL_REDUX_PARLIAMENT_UI_REWORK.md`).
3. **Прогноз партий** покрывает Зелёных (РТ, производство) и «Марс вперед» (тайлы); wild-метка Учёных и торговля Союза не
   являются реакциями на розыгрыш, поэтому прогнозу не нужны.
4. **Полоса InfoPanel** только читает (нет перехода к действию из неё).
5. **Торговля Союза** в e2e доведена до предложения бесплатного пути внутри Парламента и возврата; сам коммит торговли —
   существующий flow колоний (покрыт своими спеками), на сервере — `TradeWithUnity` unit-спек.
6. Dummy-резолюции без арта (плейсхолдер грани) и без эффектов — по плану.
