# Turmoil Redux — переработка UI «Парламента» (итерация UI-1)

Дата: 2026-09-14. Опирается на `TURMOIL_REDUX_ITERATION0_STATUS.md` (что работало до переработки) и `TURMOIL_REDUX_SPEC.md`.
Этот документ фиксирует **композицию**, **маршруты игрока**, **контракты**, которые держат её целой, **как это проверено** и
**честные ограничения**. Механика и правила не менялись; новых house rules, эффектов резолюций и контента нет.

---

## 1. Композиция workspace (один экран, один flow)

```
┌ ПРАВИТЕЛЬСТВО ──────────────┐ ┌ ОБЛАСТЬ ГОЛОСОВАНИЯ ─────────────────────────────────────────┐
│ [принятая карта | эмблема]   │ │ V1 ★ ПОБЕЖДАЕТ          V2                      V3            │
│ Правящая партия · основание  │ │ [карта] │ТАЛЛИ│         [карта] │ТАЛЛИ│          [карта] │ТАЛЛИ│ │
│ формула эффекта (графика)    │ │ лента делегатов (порядок = правило ничьей)                     │
│ «эффект есть у всех…»        │ │ РЕЙКА ФОКУСА: откуда делегат · N→N+1 · что изменится          │
│ ┌ ЗАДАНИЕ ПРЕДСЕДАТЕЛЯ ─────┐│ └───────────────────────────────────────────────────────────────┘
│ │ цель (графика) · гонка   ││ ┌ ПАРТИИ 3×2 ─────────────────────┐ ┌ ДЕТАЛЬ ПАРТИИ ───────────────┐
│ │ награда → «вам: …»        ││ │ эмблема · имя · поддержка · статус│ │ формула · почему у вас есть   │
│ │ председатель              ││ └──────────────────────────────────┘ │ действие · короткие слова     │
│ └───────────────────────────┘│                                       └──────────────────────────────┘
└──────────────────────────────┘ ┌ ПОВЕСТКА: влияние · следующий шаг ·   СТАРТ ① [РТ] ② [РТ] ③ …  ┐
```

- **Правительство** отвечает «кто правит и что это даёт»: основание одним словом («Стартовое правило» / «Принятая резолюция»),
  объект-источник (эмблема Зелёных до первой резолюции, иначе грань принятой резолюции), печатная формула правящей партии
  (`ConsolePartyFormula` — те же узлы render-DSL, что на грани и в инспекторе) и одна строка «эффект есть у всех игроков».
  Задание председателя стоит у подножия колонки: цель графикой, гонка — чипы по одному на игрока (5 игроков = одна строка),
  награда «Кресло председателя и шаг Повестки → вам: уровень влияния N», текущий председатель. Выполненное задание —
  «✓ Выполнено · выполнил ■ имя».
- **Область голосования** — центр экрана. Карта резолюции сохраняет семейство грани и окно арта (печать партии вместо пустого
  плейсхолдера: эмблема на поле акцента партии). **Талли** рядом с картой: всего делегатов, ЛИДЕР (кто лично выиграет
  резолюцию — никогда не «побеждающая карта» и не председатель) с причиной при ничьей игроков («ничья · лидер поставил
  раньше»), ВАШИ и близость к эффекту («0 из 2 до эффекта» / «эффект ваш»), у побеждающей карты — причина при ничьей резолюций
  («★ ничья · ближе к правительству»). Лента делегатов — часть композиции карты: кубы в порядке постановки, после 12 — стопки
  по владельцам в порядке первого прихода.
- **Рейка фокуса** (одна строка фиксированной высоты): источник делегата (лобби · бесплатно / резерв + стоимость),
  `N → N+1`, компактные последствия проекции сервера («станет побеждающей», «победит по ничьей», «лидер — вы», «эффект
  партии — ваш», «требование партии — выполнено»). Или честная причина, почему голосовать нельзя. Прогноз **никогда не обещает
  итоговую победу** — стадия голоса прямо пишет «прогноз при текущем распределении».
- **Партии 3×2**: эмблема, имя, народная поддержка (три места нейтральных кубов — заполненные/пустые, форма, а не цвет),
  статус доступа фразой («Правит по стартовому правилу», «Ваш эффект · 2 делегата», «Ваш эффект · выдан картой»,
  «1 из 2 делегатов», «На голосовании», «Не на голосовании»), знак действия (◈ доступно · ◇ нет/не сейчас · ⟳ использовано).
  **Деталь** — одна зона для партии под курсором (или партии объекта под курсором в области голосования/правительстве):
  формула, причины по ТЕКУЩЕМУ состоянию (`accessReasonRows`: стартовое правило в поколении 1, принятая резолюция, два
  делегата, грант — все основания без удвоения, сноска «требование на картах: выполнено / грант не считается»), состояние
  действия, короткие слова эффекта/действия — только пока живых причин не больше двух (зона фиксированной высоты не режет
  причину ради фразы; полный текст — в инспекторе, X).
- **Повестка**: компактная графическая дорожка — уровни влияния золотыми кругами с цифрой (не «+2»), значки РТ/карты,
  маркеры игроков, «здесь» — белая рамка, «следующий шаг» — золотая рамка и шеврон; в шапке — влияние зрителя и результат
  следующего шага; легенда в той же строке.
- **Стадии** (голос, кресло председателя, действие партии, итоги фазы, отправка) разворачиваются на месте яруса партий:
  рамка, карты и рейка не двигаются; ярус — пол стадии, а не потолок: стадия может вырасти поверх Повестки, но не дальше её
  нижнего края (командная полоса всегда видна). Крошка растит хвост: `ПАРЛАМЕНТ › <резолюция/партия> › ГОЛОС/ДЕЙСТВИЕ/…`.

### 1.1 Три профиля — разные компоновки, не масштабирование
- **1080 / TV 4K** — слот «карта | талли» бок о бок, талли — токен ширины (`--con-parl-tally-w`, фит карты вычитает
  измеренную коробку, никогда не читает свой вывод). TV — «диванная» типографика (всё ≥ .8rem), формулы крупнее.
- **Steam Deck 1280×800** — слот в стек (карта · талли строкой · лента), правительство уже, награда задания короткой формой
  («Кресло + шаг Повестки», «теперь председатель»), без легенды Повестки, деталь партии без слов; ряды композитора действия в
  Парламенте — рядом, а не друг под другом.

## 2. Маршруты игрока

| Задача | Маршрут |
| --- | --- |
| Понять состояние | Колесо → «Парламент». Правительство слева, карты с талли в центре, партии и Повестка ниже. |
| Проголосовать | ←/→ по картам (рейка показывает последствия) → A → стадия ГОЛОС (источник, стоимость, резерв, делегаты на карте N→N+1, ваши, лидер до→после, последствия) → A → куб летит из чипа лобби/резерва в шапке в свою позицию ленты → посадка → flow уходит на поле. B на стадии — назад в просмотр. |
| Действие партии (канон) | «Действия карт» (RT ↑) → группа «ДЕЙСТВИЕ ПАРТИИ · <партия> · N из M в этом поколении» среди карт → A → `ДЕЙСТВИЯ КАРТ › <ПАРТИЯ> › НАСТРОЙКА` → выборы → A на строке подтверждения. |
| Действие партии (контекст) | Парламент → партии → A на партии → стадия `ПАРЛАМЕНТ › <ПАРТИЯ> › ДЕЙСТВИЕ` — тот же композитор, тот же серверный промпт. |
| Союз | A на Союзе (из меню или из Парламента) → колонии ВНУТРИ текущего workspace, путь оплаты залочен на «бесплатно (Союз)» с выбором продвижения трека → подтверждение торговли колоний = единственный коммит. B выходит без траты. |
| Красные | A → «Взять 2 карты» (тон опасности; действие списывается в момент добора — выйти/вернуться ради второго бесплатного добора нельзя) → «Получены карты · действие партии «Красные»» → обязательный сброс 2 в режиме сброса руки с живой выплатой по меткам. |
| Кресло председателя | Обязательный выбор на своём ходу открывает стадию сам; B СВОРАЧИВАЕТ (выбор остаётся должным), карточка на поле / A возвращает ту же стадию. |
| Итоги фазы | Первое открытие Парламента в новом поколении: биты итогов подсвечивают объекты; A — дальше. Один раз на поколение, **перезагрузка не проигрывает историю** (метка на устройстве, ограниченный список). |
| Осмотр | X: резолюция / правящая партия / партия под курсором — полноэкранная грань с блоками правил (эффект · действие · у кого есть · для вас · статус). Выборы композитора переживают осмотр. |

## 3. Контракты, которые держат это целым

- **Партийные действия — это действия.** Колонка действий удалена из Парламента. Источник — `ParliamentModel.viewer.partyActions`
  (вердикт сервера: доступ, доступность + причина, использования), ворота исполнения — ПРИСУТСТВИЕ опции в меню действий
  (`partyActionPrompt` / для Союза — путь оплаты с `OptionMetadata.party`). Плитки строит `buildConsoleActionsModel` в тех же
  полосах, что карты (доступна / не сейчас / правила / активирована); партии без доступа в меню не попадают. Счётчик меню
  `potentialActions.partyActions` входит в бейдж «Действия карт».
- **Одна дверь торговли на двоих.** `colonyTradeEntry` помнит `{card, party}`; `lockedTradePaymentIndex(options, card, party)`
  залочивает оплату на путь партии структурно (метаданные, никогда не подпись). Лок снимается, когда шаг колоний закончился.
  Композитор партии в фокус-стадии «Действий карт» стоит `position: absolute; inset: 0`, как композитор карты: в потоке его
  зона колоний (`flex: 1`) схлопывалась в 0 px и стадия торговли раскладывалась «ни в чём» (e2e проверяет высоту стадии).
- **Прогноз честный**: строки — из проекции сервера (`VoteProjectionModel`), полный и компактный словари — один и тот же набор
  фактов в одном порядке (`voteForecastRows(forecast, compact)`, спек).
- **Фит без чтения собственного вывода**: карты слотов — из высоты слота минус измеренная обвязка самого высокого слота;
  грань принятой резолюции — из СВОБОДНОЙ высоты колонки правительства (минус все остальные блоки), не из высоты своей строки.
- **Формулы**: зум — токен хоста (`--con-pformula-zoom`), у блока только fallback внутри `zoom:` (объявление по умолчанию на
  `.con-pformula` перебивало хосты, стоящие раньше в каскаде).
- **Производство М€ может уйти в минус**: `productionChange` зажимает уменьшение у пола производства ровно как запись
  (`productionFloor`), и чип читает незажатый `resulting` как законный ход «0 → −1», а не «0 / 1» дефицита.
- **Тексты действий без лимита** («Бесплатная торговля; перед ней можно продвинуть трек…», «Добавьте 2 данных или 2 микроба на
  любую карту») — лимит «раз за поколение» структурный и печатается рядом с живыми использованиями.

## 5. Честные ограничения

1. **Добор и сброс Красных** — не встроены в «Действия карт»: после подтверждения workspace уходит, карты приходят стандартным
   экраном «Получены карты» (источник `{type: 'party'}`), затем обязательный сброс в режиме сброса руки. Работает и объясняет
   себя, но это не «один flow» уровня карточных действий (нужна claim-поддержка партийного источника и шаг сброса внутри
   `card-actions`).
2. **R3-прогноз реакций стола** есть в композерах карт; в композиторе партийного действия слоя «Эффекты» нет.
3. **Сцена политической фазы** по-прежнему итог при первом открытии Парламента (не покадрово в момент фазы).
4. Резолюции — dummy без собственного арта (печать партии в окне арта — намеренная замена плейсхолдера).
