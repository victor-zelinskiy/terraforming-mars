# MarsBot corporation rules

**ADDING A CORPORATION IS A CHECKLIST, and it is `docs/claude/marsbot-corporation-checklist.md`** — read it before writing anything here. The subsystem contract is `docs/claude/marsbot-corporations.md`; official rule data is `docs/AUTOMA_DATA_AUDIT.md` §10.

## The five invariants

1. **A MarsBot corporation is its OWN entity.** The `original: CardName` link gives exactly four things — name/logo, art, lore, the selection-collision key (RB-B Setup 1). No human rule (starting M€, first action, human tags, discounts) ever leaks through it, and the guard specs assert that.
2. **The printed card is the source of rules** — the scan of `Automa - C## - <Name>.png`, then RB-B (draft-priority special cases, special cubes, FAQ). An ambiguity is resolved by the sources and pinned by a comment + a test, never invented.
3. **Adding corporation N+1 is FOUR touch points**: the id (`MarsBotCorpId` in `AutomaTypes.ts`, value = the printed card number) · the data entry (`CORP_INFO`) · the co-located behavior file (`MarsBotCorp` hooks) · one line in `AutomaCorporations.REGISTRY`. Plus `renderDataOf` in `marsBotCorpPremiumVm.ts` — its switch is exhaustive, so the compiler asks for it. **A `switch` on the corporation anywhere else is the defect this framework exists to prevent.**
4. **Only the boxes the card prints exist.** No fake Setup/Effect/Draft-Priority sections for symmetry (RB-B: "Not all corporations use all fields").
5. **The bot never receives a prompt.** Every fork resolves deterministically or through the seeded `game.rng`; physics goes through the shared primitives (`AutomaTilePlacer`, `AutomaTerraformer`, `AutomaCardDraw.drawAndResolveProjectCard`, `AutomaResolver.advanceTrack`) so TR, placement bonuses, human triggers, Failed Actions and the journal all behave identically.

## Presentation + state

- Effect INSIDE a bot turn: `events.beginEffect(bot, {kind:'corporation', card: info.original, owner}, 'automa-corporation')` + `AutomaTurnLog.setCause({kind:'corporation'})` with the previous cause restored (`getCause`). Action OUTSIDE a turn (selection, a Before-Action-Phase move): `beginAction(..., {category: 'corporation-action'})`.
- Every meaningful step bumps a counter (`bumpCorpStat`) whose key is documented in `MarsBotCorpStats`; the endgame insight reads STRUCTURED stats, never display text.
- New serialized state is optional and degrades on old saves; a legacy corpless save stays corpless forever (`generation === 1` guard).

the WORDING is the rule — «up to X» is partial, «X, if able» is all-or-nothing, «N, or as much as possible» is partial again (C20/B24 — and its own «if it gained 0» else-branch is the proof), and none of them is a Failed Action; two printed sentences are INDEPENDENT and resolve in printed order, so the action may fund its own price — C15/B28) · **a printed MODULE condition** (`requiresModules` + the pure `hasRequiredModules` — the corporation drops out of the selection pool, so even a dev-force cannot seat it; never check a module inside a hook — C16) · **a card added to the STARTING deck** (MarsBot has no hand: its «starting hand» IS the generation-1 `actionDeck`, built before the corporation exists, so shuffle into it at a seeded-random index and never name the card in the journal — C16) · **a BORDER as the trigger** (`onTilePlaced` counting the adjacencies of the NEW tile — only one tile is new, so every border it forms is new and no board-wide recount exists; an UNOWNED tile (ocean) is nobody's, because that is how the human Philares reads the identical sentence, and a C18 MARKER is not a tile at all. «Then, if able» is ONE attempt per trigger, and the cascade it can open (advance → tile → border) needs a depth counter that lives in the MODULE, never in the serialized `corpStats` — C22) · **a printed fate that returns a card to the BONUS DECK** (`BonusCardOutcome` `'return-to-deck'` + `MarsBotBonusFate` `'reshuffled'` — not the discard: the card is back in the rotation immediately, B27) · **planting a SPECIAL TILE from the bot's played pile** (`marsLandTileFor` — derived from `isSpecialTile` + `tileTypeToString` + `OCEAN_TILES`, never a fork table; and a new term's FIXTURES must carry a NON-ZERO value, or every guard is vacuous — a zero cannot be lost; the overview row names the CORPORATION and its points and restates no rule it cannot see — C25) · **a printed module condition in the OR form** (`requiresAnyModule` beside `requiresModules`, two fields because the cards say two different things; an ABSENT list is no condition, and the data guard checks BOTH forms — C25) · **a predicate over a CARD's shape** («a blue card with a red arrow» = `CardType.ACTIVE` + `isIActionCard`, the very pair the human Viron uses — take the engine's, never a fresh one, and pick the spec's example cards by PROBING the corpus: Search for Life has an arrow — C25) · **reacting to the bot's own FAILED ACTION** (`onFailedAction`, dispatched from the ONE `failedAction` AFTER the M€ is paid and logged — «in ADDITION to the usual MC» adds to a FINISHED event; every route reaches it, so the spec drives several distinct reasons — C26) · **a ROUND START box** (`roundStart` + the `corpRoundStartGeneration` marker, dispatched from `Game.gotoResearchPhase` BEFORE the phase; ONCE PER GENERATION in exactly the `corpBapGeneration` shape — a box that PAYS a resource may never fire twice across a reload or an undo, and generation 1 never sees it because the corporation is selected at that generation's research → action gate. Test the real transition (`forceGenerationEnd`), not only the dispatcher — C26) · **a GLOBAL PARAMETER as the trigger** (`onVenusIncreased`, dispatched from `Game.increaseVenusScaleLevel` — the ONE way Venus ever moves, so «by you, MarsBot, or the card» needs no branches — and placed literally BESIDE the human twin's own payout, OUTSIDE the `phase !== SOLAR` guard: B16 forces SOLAR to suppress TR/bonuses, and the printed parenthetical «or the card Government Intervention» is telling the player that suppression does not reach this effect. INHERIT the position, never re-state the exception; a bot corporation is not a card in a tableau, so it needs its own dispatch beside the twin's `tableau.has` lookup — C28) · **a MARKER on the map** (`AutomaMarkerPlacer` — a cube on a TILE-LESS cell; the reservation against other players is free (`space.player`), the build-on-own-claim payout rides the HUMAN card's own line via `onBuildOnOwnMarker`, and the claim MUST travel as `MarsBotTurnVisual.markers` so the client drops it with the shared premium `pc-place` — C18/B22) · **a space that is already RESOLVED** (`onTrackSpaceResolved` — the AFTER twin of `onTrackAdvance`: that one fires BEFORE the space's printed icon («each time MarsBot advances…», «advancing ONTO a cube»), this one after it and after the cascade it opened («after resolving the effect, …»). The printed wording picks the hook. The trigger is the LANDING (`landed` is captured before the icon, which may be «advance» and carry the marker on), while the push is an ordinary `advanceTrack` from the CURRENT position — so one landing on the event track's #5 chains #5→#6→#7→#8. `depth + 1` MUST be passed on or the shared runaway guard restarts from zero; the spec proves it by reading `depth` and `cause` out of the turn recording. Nothing shared gets restated: the new space's icon, its cascade, cubes and the Failed Action on a finished track all come free — and the Venus track's #12 is its LAST space, so the push there is always that Failed Action — C29) · **a reminder on a COLUMN** (`reminderColumns` + `columnLegend` — the C04/C20 marker primitive through 90°: the mat lays the tracks out as rows of ONE grid, so a column crosses every track, needs no board resolution and no new `MarsBotCorpModel` field (the client reads the data directly); declared as a PAIR with its legend, which like every legend renders WITHOUT params. A regressed re-advance still fires it: the regression rule silences the SPACE's own action, never a corporation clause whose trigger is the move — and the physical tell agrees, a spent cube leaves the mat, a reminder never does — C29) · **a setup that changes the SHARED table** (`ColoniesHandler.seatColonyTile` — C30's «Add an additional Colony tile to play» opens a colony for the HUMAN too. Its human twin prints the same sentence and differs ONLY in the choice (it asks its owner, the bot takes one at seeded random because it receives no prompts), so everything AFTER the choice — sort, the will-it-enter-active check, removal from `discardedColonies`, the journal line — is one shared function; run every caller's spec right after such an extraction (`addColonyTile` has three). An empty pool is unreachable in a MarsBot game (the validator refuses `customColoniesList`) but the guard exists on both paths and is covered by calling the setup directly, never by an illegal config) · **a cube COLOUR that carries no rule** (C30: «a black OR white cube» is ONE sentence with ONE outcome — two colours only because nine of one colour are not in the box. Both get the same `target`, `logKey` and counter, and `legendRows` groups colours by TEXT so the mat draws ONE row with BOTH swatches; two identical rows would assert a difference the card does not print. Guard: `cubeLegend.black === cubeLegend.white` in the card's own spec) · **the same MAT MARKING with the opposite trigger** (C31 Arklight vs C09 Teractor: both paint a white tracker on a track, but Teractor pays for ADVANCING it — so a city riding the Earth track pays too — while Arklight pays for a TAG, and its track carries THREE of them. The printed «(not microbe!)» exists precisely because the marking alone would read as Teractor's rule. **The WORDING picks the hook**: «advances the track» → `onTrackAdvance` + `MarsBotTrackPayout`; «resolving a … tag» → `onTagResolved`. Taking the track-payout module here would silently pay for microbes — guard it with «advancing the track on its own pays nothing». A WILD tag is not one of the named tags (`resolveTag` passes the tag as PRINTED), a microbe ADVANCEMENT (Venus cell 9) is not either — being deaf to that cell is the reading when the card excludes microbes, not an omission — and `markerLegend` must state the exclusion out loud or the mat promises more than the card pays) · **a box that REMOVES a card from the action deck** (C32 Polyphemos — the first corporation that gives the bot nothing and takes instead. A card's value to the bot IS its printed tag count (one flip, one track advance per tag; NO tags is the official Failed Action), so shedding the fewest-tagged card raises the floor of every remaining turn. Measure with `MarsBotDraftResolver.printedTagCount` — the same count the «most tags» priority uses — and compare only entries that HAVE a tag row: a BONUS card is not «few tags», it has none and is the generation's special move. Ties → `game.rng`; the card goes to the OPEN `projectDeck.discard`, which is why the journal line may name it. ⚠️ The box has ALREADY run once by the first action phase (RB-B resolves Before-Action-Phase boxes after setup too, and the shared gate does it) — measure counters as DELTAS and pin that fact with its own test) · **an event with TWO entry points** (`onColonyBuilt` — C33 Poseidon's «when you or MarsBot build a colony». Every earlier trigger had ONE choke point; a colony has two, and that is the truth of the rules rather than duplication: `Colony.addColony` (a human) and `AutomaColonies.botBuildColony` (the bot, which deliberately does NOT go through the former — it ignores the printed reward for 2 shipping-board resources). Dispatch beside the engine's own «any player built a colony» loop in BOTH, the same C28 law of inheriting the position, and «you or MarsBot» needs no branch. Before adding the second site, GREP that the two paths are not nested — otherwise one build pays twice. «Including during setup of this card» is free because `selectCorporation` seats the corporation BEFORE running its Setup box; pin it with a test) · **a resource SPEND as the trigger** (`onFloatersSpent` — C34 Stormcraft Incorporated. Every earlier trigger watched an INCOME or an action; this one watches an expense, and the bot has exactly ONE: `AutomaResearch.trySpendFloaters` (5 floaters at the end of the Research Phase once Hoverlord is out of reach). Dispatch there, AFTER the pool is charged and logged — the printed sentence adds to a FINISHED event, the `onFailedAction` reading. Test the REAL wiring (`buildActionDeck`), not just the hook, and remember that arming the spend is TWO conditions, not one: ≥5 floaters AND an unavailable Hoverlord. Its setup and round-start boxes are C26 Celestic's WORD FOR WORD, so both run `corps/MarsBotFloaterPayout` and share those i18n keys — with a guard asserting the shared sections are EQUAL and the effect section is NOT). · **a corporation that is nothing but a DEFERRED EVENT** (C46 Tycho Magnetics / B30 Interface Hyperlink — no effect box, no starting tags: its whole rule is a bonus card put on the BOTTOM of the bonus deck. The bottom is the FOURTH disposition of a corp card, after recurring / shuffled into the rotation / making a BASE card permanent — and it needs no new field, because a bonus draw `shift()`s from the front, so `bonusDeck.push` without a shuffle IS the bottom; guard it as «last in `bonusDeck` and NOT in `recurringBonusCards`». Its printed priority chain is the SAME comparison the draft makes, so it runs on the draft's own machinery — `MarsBotDraftResolver.pickByScore` (made public for exactly this), lexicographic over an array of scores with the seeded tie-break that «Random» at the end of the printed list literally IS. ⚠️ Do NOT add a case to `MarsBotDraftPriority`: that union is the set of priorities printed on a DRAFT PRIORITY plate — shared MACHINERY, different RULES. A tag in such a chain is COUNTED, never tested as a boolean («a card with the first tag twice is even better», RB-B), «Select 2» is PICK TWICE rather than sort (only that keeps the tie-break honest at a three-way tie), and the REJECTS are discarded BEFORE the keepers resolve or an effect the resolution starts could draw the card just rejected. Drive the fate test through the real `drawAndResolveBonusDeckCard` — resolving a card that still sits in the deck tests a state that never occurs in play). · **a STATE FLAG on the card + a printed rate the engine already owns** (C35 Lakefront Resorts — the first corporation that answers the same event DIFFERENTLY depending on the last time. Its white cube is a one-bit memory, not a store, and it lives in the very slot Ecoline's plant and Philares' science do (`corpResources`) — on the table it is the same physical thing, so no new field, only a new `MarsBotCorpResource` (`'cube-white'`, which the face already draws as the generic `RESOURCE_CUBE`). The setup places it precisely so the FIRST ocean is a paying one; the SPEC must therefore assert the ALTERNATION INVARIANT (cube present ⟺ an even number of flips; spends = ⌈flips/2⌉), never «the third ocean pays» — the paid step can itself lay an ocean (building space #2 prints one), which flips the card again. That cascade is the printed rule, not a special case: it terminates because each spend costs a track step, but its depth lives in the MODULE and is passed on to `advanceTrack` (C22 + C29 together). And «MarsBot's bonus for placing adjacent to an ocean is 3 MC» is ONE FIELD — `player.oceanBonus`, the very field the human twin sets: one line at setup inherits every placement path at once and survives a reload, the corporation re-implements no payout and only MEASURES the surcharge through the same `board.oceanAdjacencyBonus` the engine paid from. The trigger predicate is the twin's too (`Board.isUncoveredOceanSpace` — a genuinely NEW ocean, never an Ocean City over one already there), the C21 law applied to a tile). · **a hook that CANCELS an action** (`onWouldRaiseParameter` + `AutomaCorporations.replacesParameterRaise` — C36 Pristar, whose effect does not add to an event but REPLACES it: the mat says «raise the temperature», the card answers «no — a TR and 6 M€, and Mars is left alone». The gate is asked at MARSBOT'S OWN ACTION SITES, never inside `Game.increaseOxygenLevel` & co, because the trigger is the printed ACTION: a greenery raises oxygen as a consequence of a TILE and «place a greenery tile» is on none of the four sentences — a gate in the engine would eat the oxygen of a greenery already placed. Every path of every parameter must ask (there is more than one per parameter: the shared `raiseTemperature`, the shared `placeOcean`, the resolver's Venus, and BOTH bonus-card ladders including the branch that picks its own ocean space), and the guarantee is a SWEEP TEST that drives each path — not a grep. One ACTION is replaced whole however many steps it prints, and the gate is asked BEFORE each site's own maxed check, so a replaced action never becomes a Failed Action («WOULD raise» names the instruction, not its feasibility — the other reading is recorded as rejected and pinned by a test). Its BEFORE ACTION PHASE box also replaces a SETUP box: the shared gate resolves that box right after setup too, so a card needing its resource from generation 1 prints no setup line — and specs must read every counter as a DELTA, the C32 law). · **a PROJECT card dealt into the action deck every generation** (C38 TerraLabs — the human card buys cards cheap and pays in TR; the bot has no hand and no prices, so the same bargain is struck in the only currency it spends, its ACTION DECK: 8 TR at setup, then one extra project card per generation and TWO from generation 9. A thicker deck is more TURNS, not better ones — each card is one flip and one track advance per printed tag — so nothing here SELECTS: draw off the top of `projectDeck` and `splice` at a seeded-random index, which is what «shuffle into» means (C02/C16/C12's idiom, and the card is never named in the journal — it went in face down). A printed rate that depends on the GENERATION is read from `game.generation` and its boundary is tested on BOTH sides; an exhausted project deck simply adds nothing. And the box has already run once by the first action phase, so its counters are DELTAS.) · **a GENERATION-PARITY effect that reads TWO tracks at once** (C39 Utopia Invest / B32 Investors — the human card trades a production step for four resources of that kind, moving value from where it sits to where it is wanted; B32 does that to the only board the bot has: on EVEN generations it takes a step off the bot's strongest track and gives it to its weakest, on ODD ones it cashes the weakest track's space number out as M€. ⚠️ When one printed sentence names BOTH targets, read BOTH BEFORE anything moves — picking the leader AFTER the push lets the push create the leader it then cancels (a flat mat pushes track 0 to 1 and slides it straight back), i.e. the card does nothing exactly when it should do the most. Both clauses saying «topmost if tied» means a flat mat legitimately resolves onto ONE track, and that is honest: the space icon fires on the way up and the regression marker stops it firing twice. Three shared readings come free and none is re-implemented: `getLeastAdvancedTrackIndex` (the wild tag's / C33's / B28's own helper), `getMostAdvancedTrackIndex`, and the ordinary `advanceTrack`; the pull-back is the engine's own `MarsBotTrack.regress` (the Ares hazard consequence uses it). A track at the start cannot regress and space number 0 pays 0 — both are honest outcomes, NOT Failed Actions.) · **a STORE that fills from tags and empties at a THRESHOLD** (C40 Ecotec — the human twin's own «bio tag» family (plant, microbe, animal) feeds the ordinary on-card socket (`resource: 'plant'` + `corpResources`), and a Before-Action-Phase box cashes five of them for one push of the very track those tags ride; so the corporation makes the bot's bio tags count TWICE rather than making it faster. The threshold box is NOT a loop — one conversion per generation, and «remove 5» is spent even when the push turned into a Failed Action (C45's shape). ⚠️ A card that feeds on MICROBE tags must also implement `onMicrobeAdvancement`: the Venus board's cell 9 advances the bio track BY a microbe without resolving a tag, and the RB-B FAQ reads it as one (the C24 Splice precedent) — that cell is the hook's ONLY dispatch site, so a starting tag arriving through `onTagResolved` is never counted twice. And a printed sentence that is WORD FOR WORD another implemented card's (its setup marker is C31 Arklight's) takes the SAME i18n key while `markerLegend` stays its own — one rule, one phrasing; different effects, different legends.)

## Tests + verification

A corporation is done when: its own `tests/automa/MarsBot<Name>.spec.ts` covers every printed effect (positive AND negative), the interaction with the shared rules (maxed → Failed Action, regression markers), serialization + an OLD save without the new field, and the identity/no-human-leak assertions; the client face spec has its branch; RU keys exist (grep for duplicates first, then `make:json`); and `build:server`, `build:test`, `lint:client`, `eslint`, `test:server`, `test:client` are all green. A new VISIBLE element additionally needs an e2e probe whose config forces `customCorporationsList` without that corporation's original (`seed` is ignored, so the collision rule can legitimately hand the bot a different corp).
