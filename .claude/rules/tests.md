# Testing rules

## Helpers
- **`testGame(n, options?)`** (`tests/TestGame.ts`) → `[game, ...players]`; skips initial card selection and disables Ares hazards by default.
- **`TestPlayer`** extends `Player` with `popWaitingFor()` etc.
- **`tests/TestingUtils.ts`**: `runAllActions(game)` (drain the deferred queue — call it after anything that defers), `cast(value, Class)`, `setOxygenLevel()`, `setTemperature()`, `addOcean()`, `addGreenery()`, `addCity()`, `fakeCard()`.
- Server card specs: instantiate the card → `canPlay()` / `play()` / `action()` → assert state.
- Client specs: `@vue/test-utils` with `tests/client/components/setup.ts`.
- Framework: Mocha + Chai (`expect` style); the client suite is ONE Vite bundle run under mocha in jsdom (`scripts/client-tests.mts`, since 2026-11-15 — it replaced the webpack runner, which had replaced `mochapack`; «mochapack» or «the webpack bundle» in an older comment means that bundle).

## Runners
```bash
npm run test:server          # mocha, ~22 800 specs, ~4 min
npm run test:client          # scripts/client-tests.mts, ~9 950 specs, ~6 min (the bundle ~40 s of it)
npm run build:test           # tsc -p tests/tsconfig.json --noEmit  +  the e2e tree

# one server spec
npx mocha --import=tsx --require tests/testing/setup.ts "tests/cards/base/Algae.spec.ts"

# one client spec (or a glob) — no flags: the runner always builds ONE bundle with the product's own Vue options
# and always puts tests/client/components/bundleSetup.ts first in it (`TM_KEEP_TEST_BUNDLE=1` keeps the bundle to look at)
npm run test:client:one -- "<spec>"

# THE CONSOLE IN A BOTTLE (tests/client/bottle/*.bottle.ts — NOT in the unit glob: a minute, and it loads the game
# server into the runner's process): the real App + ConsoleShell against the real server in one process, one manual clock
npm run test:bottle
# …and THE MONKEY IN THE BOTTLE (opt-in — every table, ~40 min on the laptop in two shards, no box): the box monkey's
# own walk (same seed → same presses), classes filed in the box monkey's format
TM_BOTTLE_MONKEY=1 TM_BOTTLE_MONKEY_SHARD=1/2 npm run test:client:one -- tests/client/bottle/monkey.bottle.ts
node scripts/monkey-report.mjs .e2e-remote/bottle-monkey --against .e2e-remote/<the box run>/monkey-report.json
# THE FREEZE GATE — the three in one command, with NO BOX (≈ 35 min of a laptop): the replays of every closed class,
# the monkey in the bottle over every table, the report against the committed baseline — red on a NEW defect class
npm run gate:freeze                      # --shards 4 · --only <regex> · --report-only · --write-baseline
# THE SHRINK — a walk that names a class, cut down to the steps that make it (each candidate on a fresh bottle)
TM_BOTTLE_MONKEY=1 TM_BOTTLE_MONKEY_ONLY='^<table>$' TM_BOTTLE_MONKEY_SHRINK='<class regex>' npm run test:client:one -- tests/client/bottle/monkey.bottle.ts
```
**THE FREEZE GATE'S BASELINE SAYS WHY** (`tests/client/bottle/monkeyBaseline.json`, guard
`tests/console/freezeGateBaseline.spec.ts`): the classes the bottle is KNOWN to name, each with the reason it may
stand. A class the gate calls NEW is a finding — close it (a law, a guard, a replay) or, when a real browser says
«not there», add it with its `why`; a row without one is red in the unit run. Never add a row to make the gate green.

**A CLASS FOUND IS A CLASS REPLAYED** (`tests/client/bottle/classReplays.bottle.ts`): every cause class closed gets a
test there — the fixture, the presses that produced it, the property its fix established — and that test is RED with
the fix switched off, under the class key the monkey filed (prove it once, by hand, before the commit). The bottle has
no layout: a class that needs a rect or a paint is replayed on the box instead, and said so in its row of the plan.

**The client runner is `scripts/client-tests.mts`** (2026-11-15, `docs/claude/stack.md` S2 · S3): Vite builds the
specs into ONE ES module with the PRODUCT's `@vitejs/plugin-vue` options — **a template is compiled INLINE, as it
ships** (guard `tests/client/vapor/sfcCompileParity.spec.ts`) — and mocha runs it in this process inside the jsdom of
`tests/client/components/setup.ts`. The runtime stays Vue's DEVELOPMENT build. An inline template keeps the setup
bindings to itself, so the unit bundle (only it) records them at the end of every `<script setup>`
(`tests/client/testing/scriptSetupState.ts`): `wrapper.vm.<binding>` and a stub by its local name keep working. The
specs run in ONE fixed order (by path, `localeCompare`); a spec that passes only in the suite is a LEAK in an earlier
spec — run it alone to tell. A bottle's PAGE is a second bundle, compiled once and run per page
(`tests/client/bottle/consoleBottle.ts` § a pristine page): a replay reaches the page's modules through
`bottle.pageModules`, never by importing them itself.

**A VAPOR component in a unit spec** (`<script setup vapor>` — the road to `createVaporApp`, `docs/claude/vapor/ROADMAP.md`
§ 4b): **the spec is written as for any component** — `mount(TheComponent, {props, slots, global: {stubs}})`,
`shallowMount`, `setProps`, `findComponent`, `wrapper.vm`. `@vue/test-utils` itself is a virtual-DOM tool (a Vapor
root throws, `stubs` never reach a Vapor parent's children, `findComponent` cannot enter one); inside the unit bundle
the names `@vue/test-utils` and `vue` resolve to the suite's LAYER (`tests/client/testing/` — aliased by
`scripts/client-tests.mts`), which closes all three for every spec and is pinned row by row by
`tests/client/testing/vaporTestLayer.spec.ts`. The unit bundle compiles every component AS WRITTEN and as it ships
(the virtual-DOM valve and its `TM_UNIT_VAPOR` modes are gone with the move to Vite). What a spec must NOT do: assert how a runtime
SERIALISES — the order of classes after an update, of attributes in `html()`, the anchor comment of an absent root
(`<!--v-if-->`) — assert the set, the attribute by name, «no element»; read `$el` off a parent's ref on a child (a
Vapor child's ref is its `defineExpose` object); expect an Options-API surface on `wrapper.vm` (`$data`, `$options`).
A REAL Vapor `<Transition>` (`stubs: {transition: false}`) needs a frame source — `tests/client/vapor/lendFrames.ts`.
What Vapor takes at all is `tests/client/vapor/vaporCapability.spec.ts`.

**Both `npm run test:*` scripts go through `scripts/run-tests.mjs`**, which fails the run when fewer tests are COLLECTED than the declared floor (`--min`). Raise a floor when a batch of specs lands; never lower one to make a run pass.

**…and on a FAILING run it re-prints mocha's failure block at the very END**, after the `[test-count]` line. A full suite prints thousands of ✓ after that block, so a reader of the TAIL (CI's summary, `| tail`, a captured background job) otherwise sees the count and not one spec name — which is exactly what made two intermittent `test:client` failures undiagnosable. It re-prints, never rescues: the run's own exit code and output are untouched.

## КАК ПИСАТЬ E2E-ПРОВЕРКУ — the law of every e2e check (FLAKE ZERO, the owner 2026-11-15)
A check observes FACTS OF THE PRODUCT, never the speed of the machine (CI = 2 cores, software raster, a frame of
300 ms). Every line below is a flake class that went red on CI; the static guard counts each one
(`tests/console/e2eDriverGuard.spec.ts` ④ — a new spec starts at ZERO in every class; journal and recipe:
`docs/claude/e2e-flake-zero.md`). Laws 11–20 are the lessons of FLAKE ZERO's seven waves; the stories behind the
traps below are `docs/claude/e2e-flake-history.md`.
1. **Wait for STATE, never a duration** — `settle(page)` at a chain's boundary, a locator assertion with its timeout,
   `expect.poll`, `pressUntil*`. No `waitForTimeout` in a spec; the one honest mid-cinematic pause is
   `cinematicBeat(page, ms, why)`.
2. **Act → verify ITS effect → retry only without one** — `pressUntil` / `walkFocusUntil` / a surface's signature
   before and after (`playCardFromHand`); never «press A five times», never a press inside `expect.poll`. The witness
   is FALSE before the press: `pressUntilVisible` presses nothing when it already holds (the bot hub's door carries a
   MINIATURE `.mb-tracks` — a press verified by `.mb-tracks` never left the hub; the detail is `.con-botboard .mb-tracks`).
3. **A transient is RECORDED from before the action** — `armWitness(page, key, reader)` (`tests/e2e/witness.ts`, on the
   replace-proof recorder) armed above the press, asked after (`ever` · `firstWhere` · `sequence` ·
   `happenedInOrder`); a coexistence / order claim arms `{settled: true}`. No `setInterval` / `requestAnimationFrame`
   in a spec; the reader returns an OBSERVATION, never a tick count.
4. **A live state is asserted by a POLL** — `toHaveCount` / `toBeVisible` / `toHaveText` / `toHaveAttribute` or
   `expect.poll`; never `expect(await x.count())` (and never its two-step form).
5. **Geometry is measured at REST** — `readSettled(page, () => read(page))` (`tests/e2e/settledRead.ts`: two equal
   reads a frame apart, after `settle`); two compared measurements BOTH through it; a pose mid-motion is a witness's.
6. **«Done» is the SERVER moving on** — `promptId`, `wireOf` / `fetchPlayerModel`, `syncClient`, `placementState`;
   never «the kicker / the sheet left the screen».
7. **A surface is read after its READINESS marker** — `composerLoaded`; a new surface that loads gets its own
   `data-*-loading` marker and a line in `settle`.
8. **A duration is a TIMING spec's, on the PAGE's clock** — a witness's `t`, the product's `data-*-at`; a functional
   spec never asserts a value of the driver's `Date.now()`.
9. **A judge never calls «lost» what the product still OWES** — read its announcement («Возвращаемся…», `data-*-owed`).
10. **A CI-only red is REPRODUCED before it is fixed — ON CI, by THE HUNT** (the box's CI-like profile passed every
    one of the late CI flakes, 2026-11-16…21): `gh workflow run "Playwright E2E" --repo victor-zelinskiy/terraforming-mars
    -f grep="<the test titles>" -f repeat_each=<N> -f retries=0 -f burnin_depth=0 -f shards=<K>` — every failed
    attempt is a FAILED test with its own diagnostics on the run's brief; a hunt files nothing and touches no ledger.
    The fix is proven by RATE there (the same hunt, green). The box (`TM_E2E_CI_LIKE=2 npm run e2e:remote -- …`) is the
    quick first look. A race of the product is fixed in the product (with a unit spec); a wait of the product is bound
    to its EVENT, never to the wall clock; a red that does not name its cause gets the diagnostics FIRST (the product's
    trail — `__conReady().transfer.trail` — in the assertion's message).
11. **A record keeps the state it was ARMED in** — a claim about a window starts at the window's first state (the new
    surface standing, a `pageNow` mark at the press), never at the arm.
12. **`settled` is the end of a CALLBACK, not of a frame** — a state between two frame callbacks of one rendering step
    (GSAP's tick, a probe tick — each ends with a microtask checkpoint) is recorded though never painted: a «never two at
    once» claim that can meet such a hand-off reads the product's DECLARED state (e.g. `data-parl-flight-landed`),
    never a bare count (`tests/e2e/transientRecorder.ts` note).
13. **`readSettled` settles first by default** — inside a scene that STANDS for the player (a reveal waiting for its
    take, a decision, a chain between two presses) read with `{settle: false}`.
14. **A bound on samples is a POSITIONAL claim** — «vanished for at most one sample» says where the tolerated moment
    stands in the sequence; never «one contiguous run» (any length), never a ms bound (a 300 ms frame). Nor a claim
    that a frame landed INSIDE a motion shorter than a frame (a «mid-turn sample» of a 231 ms flip — CI 43998786293):
    the e2e reads the motion's STANDING ends, and «it is a tween through every angle» is a unit spec on the animation
    clock (`cardDealTurn.spec` — `gsap.globalTimeline.time(…)`). Nor an ORDER between two motions on two CLOCKS (a CSS
    `animationend` against a GSAP timeline's end — CI's 300 ms frames delayed the first by a second, hunt 44905308724):
    the order the product guarantees is its STRUCTURE (what awaits what — a source guard, `deckPickFoldGuard.spec`),
    the e2e reads the journey. And an order of two states of ONE record is the record's INDEX (`samples.indexOf`, a
    witness's ids), never `a.t > b.t`: two callbacks of one 300 ms frame share a whole-millisecond `t` (the hunt
    44905320939: «#1 +9 t=10661 · #2 ПО+2 t=10661»).
15. **A transient that comes and goes is never waited for AFTER a server poll** (a `waitFor(visible)` of a 340 ms
    receipt) — it is read from a recording armed before the press.
16. **`toContainText` reads `textContent`** — a read of what the player SEES under `text-transform` is
    `toContainText(…, {useInnerText: true})`.
17. **An END STATE a spec waits for is read off the product's template** (the selector and its `v-if`), never guessed
    from a class name; a function that arms a witness and folds it after a loop leaves the loop by `break`, never `return`.
18. **A spec's zero is a LAW** — a `*.spec.ts` has no row in `tests/console/e2eRatchetBaseline.json` (guard ④
    «a SPEC has no row at all»: the baseline cannot freeze new debt in one).
19. **Product side: state written imperatively onto an element whose classes are BOUND is an ATTRIBUTE, never a class**
    — on a NON-ROOT element (a `v-for` row, an inner node) a Vapor class binding that changes writes `className`
    whole (`runtime-vapor` `setClass`; a component ROOT is patched incrementally and keeps it) — `data-sweep`, and the
    support places / card-exit rejects of 2026-11-16; `data-peek` keeps the same law for the board cell.
20. **Product side: a «never happened» ceiling over a motion is `motionCeilingMs`** (scales UP with a slower motion, never
    down — the functional e2e runs at `?motion=0.5`); a duration is `motionMs` (`.claude/rules/animations.md`).
Never: weaken an assertion, raise a timeout as a fix, add a retry / `test.retry` / `if (CI)` / `test.skip`.

## Traps that have bitten before
Each trap is its LAW. The story behind a long one — the measurements, the runs, the specs — is in
`docs/claude/e2e-flake-history.md`, under the heading its `→ history` names.
- **A CLIENT TIMER IS AN OWNED WAIT OF THE FLOW KERNEL — a unit spec drives the KERNEL'S clock, never a stub of `window.setTimeout`**: `const clock = createManualClock(0); setFlowClock(clock); … clock.advance(ms); … setFlowClock(undefined)` (`@/client/console/kernel/flowClock`; `clock.pending()` says what still stands). A source-reading spec looks for the owned form (`.after(` / `.guarantee(` / `motionAfter(`) — re-point it in the diff that converts a site; `tests/console/kernelCoverage.spec.ts` fails on any raw primitive in the client. → history: `docs/claude/e2e-flake-history.md` § Kernel clock in unit specs
- **`npm run build:test` is mandatory when you touch `tests/`** — the only typecheck of the test tree (mocha + tsx do not), and what catches case-sensitive import paths that break CI on Linux. It is TWO full-program gates: `tsc -p tests/tsconfig.json --noEmit` and the e2e tree (`tests/e2e/tsconfig.json`, noEmit — Playwright transpiles without ever type-checking). **Never make a mandatory gate incremental**: a gate that can pass without looking is worse than a slow one. → history: `docs/claude/e2e-flake-history.md` § The incremental build:test
- **THE HARNESS SCANS EVERY PAGE FOR A RAW TEMPLATE AFTER EVERY TEST** (`consoleTest.ts` `rawTemplateGuard`, PL-160): a `${n}` / `${name}` in rendered text, `aria-label` or `data-hint` on any page of the test's context fails the test; a second client on its own context scans itself with `rawTemplatesOn(page)`. → history: `docs/claude/e2e-flake-history.md` § Raw templates and flight ends
- **A flight's ends are WITNESSED, never assumed** (`tests/e2e/transferWitness.ts`): `armTransferWitness(page)` before the press, `transferWitness(page)` after the scene; `endsOverGlass` must be empty; `effectiveVisibility(page, sel)` is the ONE «can the player see it» reader. ⚠ `elementsFromPoint` never returns a `pointer-events: none` element. → history: `docs/claude/e2e-flake-history.md` § Raw templates and flight ends
- **AND EVERY TEST FAILS ON A RE-ASKED PRE-SELECT** (`consoleTest.ts` `preselectGuard`, the pre-select law): the console warns `RE-ASKED PRE-SELECT` when a question the last batch already answered stands again (`console/preselectWitness.ts`), and the harness collects it from every page of the test's context and fails the test with the report. A spec never needs to arm it; a route that asks the player twice is red wherever it is walked.
- **…AND ON A COVERED PROMPT** (`consoleTest.ts` `coveredPromptGuard`, 2026-10-18): the leak detector warns `COVERED PROMPT` when a live question's surface is mounted UNDER a full-bleed scene (the «Корпоративные архивы» pick after B → A — pickable, owning the pad, invisible, and «served» by the stranded check). Read off stacking order, debounced past a hand-off frame; every spec is red on it. A probe that asks «is the surface there» must also ask «is it ON TOP» (`document.elementFromPoint` on its content — `console-deck-pick-collapse` § `onTop`).
- **An e2e payment object is DERIVED, never a literal** — `{...NO_PAYMENT}` from `consoleStart.ts` (itself built from `SPENDABLE_RESOURCES`). A hand-written key map is invisible to the compiler (`Wire = any`) and rots the day the game grows a spendable: 24 files did, all at once, answering 400 «payment is not a valid type» at spec SETUP.
- ⚠️ **The client suite ran ZERO tests, green, from 2026-07-02 to 2026-08-14** (a webpack split chunk the runner never loaded) — which is why `scripts/run-tests.mjs` fails a run that collects fewer tests than its floor (§ Runners). → history: `docs/claude/e2e-flake-history.md` § The client suite that ran zero tests
- **A mount that is never unmounted is a live subscriber.** Specs share one process and one module-state graph, so stale components re-render on every later spec's writes: measured 432 failures + 6 min together vs 19 failures + 55 s apart. `bundleSetup.ts` auto-unmounts after each test — so **mount in `beforeEach`, never in `before`** (a wrapper does not survive into the next `it`).
- `tests/client/components/setup.ts` exposes **every jsdom CONSTRUCTOR** (not a hand-picked list) — Vue's own `v-model` needs `Document`/`ShadowRoot`. Imperative APIs (`requestAnimationFrame`, `matchMedia`, …) are deliberately NOT added: feature detection must keep seeing this environment.
- `npm run lint:server` with `--cache` can mask errors; run `eslint --no-cache` when in doubt.
- ⚠️ **A LAYOUT GUARD CALIBRATED ON WINDOWS HAS NO MARGIN ON THE LINUX RUNNER — simulate the rounding, never budget for it.** CI rounds HUD-sized glyph advances UP to whole pixels: rebuild the worst case (∑⌈advance⌉ + tracking, `canvas.measureText` on the PAINTED string — mind `text-transform`), clamp it to the laid-out ink, and assert the COLUMN (a clone of the real element at the real width) clears it; `getComputedStyle` is LIVE — read it BEFORE detaching the clone. Reference: `tests/e2e/console-strategy-rail.spec.ts` § `headFits`. → history: `docs/claude/e2e-flake-history.md` § Glyph rounding on the Linux runner
- ⚠️⚠️ **A PROBE HOLDS FOR ANY BOARD ITS CONFIG CAN DEAL.** Only the EXPLICIT lists force a deal — `customPreludes`, `includedCards`, `bannedCards`, `customCorporationsList`; the seed (§ EVERY E2E GAME IS SEEDED, below) replays one deal at one commit, never across card-pool changes. Sweep rather than remember a cell, assert the CLASS of thing rather than a specific one, and name what it was looking at when it failed. A filler returns what the PRODUCT allowed, not what it was asked for (`fillPicks(page, 3)` on a lean campaign start — unseeded — buys ONE card: the budget gate refuses the rest): compute a claim from what the page HOLDS, read at rest (CI 43919360711, `console-tenders-storyboard`). → history: `docs/claude/e2e-flake-history.md` § The ignored seed
- ⚠️ **A STUBBED SERVER MUST STAY CONSISTENT WITH ITS OWN ANSWERS.** A spec that fakes one endpoint usually fakes two (the model route and the submit route), and they must not contradict each other: a stub needs MEMORY (what has already been answered), not just a response. → history: `docs/claude/e2e-flake-history.md` § A stub without memory
- ⚠️ **A SCENE THAT WAS ALREADY STANDING IS NOT EVIDENCE OF YOUR PRESS — and «is the modal up?» is not a claim about ORDER.** A driver's success test is specific to ITS press (a reveal left by an earlier card owns A and satisfies «some scene is up»); a live `.con-deckdraw` is the queue still WORKING; a drain inside a retry loop is repeated after it; an ORDER claim is recorded from before the press (`armWitness`, law 3), both sides read in the SAME sample. → history: `docs/claude/e2e-flake-history.md` § A scene already standing
- ⚠️ **A COMPARISON IS ONLY AS SETTLED AS ITS LEAST SETTLED SIDE — and a `waitForTimeout` is a DURATION standing in for a state.** Two measurements of the same thing BOTH go through the same settle read (`readSettled`, law 5); a poll on one side only moves the flake. → history: `docs/claude/e2e-flake-history.md` § A comparison settled on one side
- ⚠️ **THE SHAPE OF A PROMPT CAN ITSELF DEPEND ON THE DEAL — drive the surface's OWN markup, never a guessed key sequence.** A step list is data-dependent (a sole target renders no step rows, a second one makes it a CHOICE); the stage marks its unanswered steps (`--missing`), and a driver walks THOSE to zero before confirming. → history: `docs/claude/e2e-flake-history.md` § A prompt whose shape is dealt
- ⚠️ **A PROBE'S OWN LIVENESS FLOOR IS A FLAKE TOO — it may only catch a sampler that never ran.** Set the floor where only a DEAD sampler fails it — never a sample count, a coverage ratio or a max-gap bound (each scales with the machine) — and carry the real numbers in the message. **A SCREENCAST FRAME IS EVIDENCE, NEVER THE CLAIM**: a storyboard's `writeFrameAt` near a moment the probe named writes the frame or says in the log that none came — never an `expect` (CI 44062996994: 16 frames a minute on the software raster, none inside a 380 ms lift); the event itself is the probe's. → history: `docs/claude/e2e-flake-history.md` § A probe's liveness floor
- ⚠️⚠️ **EVERY RING THESE DRIVERS WALK CLAMPS SOMEWHERE — ONE primitive walks it, `walkFocusUntil`. Never hand-roll a focus walk in a spec.** It yields to the purchase («ОПЛАТИТЬ» can own the ring), turns around only after TWO consecutive no-moves (a wall and a swallowed arrow read alike for one lap), retries a failed pick IN PLACE (up to 3 presses), budgets ≥ 2.5 passes of the LARGEST ring, and PRINTS ITS TRAIL on shortfall. → history: `docs/claude/e2e-flake-history.md` § Focus walks against a clamped ring
- ⚠️⚠️ **A BARE `page.reload()` SWALLOWS KEYS — use `reloadConsole(page)`.** The GPU warm-up paints the console UNDER `.boot-loader`, and every key pressed in that window is lost; `reloadConsole` waits in `openConsole`'s order: shell → `.con-load` → `.boot-loader`. Guard ① in `e2eDriverGuard.spec.ts`. → history: `docs/claude/e2e-flake-history.md` § A bare reload
- ⚠️ **A BOARD PLACEMENT IS TWO PRESSES, and a d-pad step UNLOCKS.** `A` on a legal cell LOCKS it; a second, separately-released press past the 280 ms dwell commits; **B** between attempts CANCELS the placement (and rolls a pay-on-commit play all the way back). Drive it with **`placeTile`** (anywhere legal), **`walkToSpace` + `commitFocusedSpace`** (a specific cell), or opt into `forceSwiftPlacement` when the confirm flow is not the subject (guard ③). → history: `docs/claude/e2e-flake-history.md` § One-press placements
- ⚠️ **EVERY PRESS IS act → verify → retry — `pressUntil` / `pressUntilVisible` / `pressUntilGone`.** This console has three DELIBERATE ways to swallow one: a visible toast overrides B everywhere, a decision surface re-arms its submit on every response, and a cinematic hold absorbs input for its whole length. A blind press plus a 45 s `waitForSelector` reports the timeout, never the swallow. The witness must be POSITIVE and SPECIFIC — «the draft workspace is on screen», not «something changed».
- ⚠️ **…AND A RETRY IS A SECOND PRESS ON WHATEVER THE FIRST ONE OPENED.** A Parliament gate (verdict / results) is answered through **`answerGateOnScreen(page, request, viewer, 'assembly' | 'adjourn')`** (`closeSitting` = the adjourn one): the gate must STAND before the press, and a retry happens only while it provably still stands 10 s later. Guard ⑥ in `e2eDriverGuard.spec.ts` freezes the hand-rolled sites that predate it — counts may only fall. → history: `docs/claude/e2e-flake-history.md` § A retry into what the first press opened
- ⚠️ **A DOCK COUNTER IS A VIEW, NOT A WITNESS.** The play cinematic freezes the view it animates, so `data-hand-total` still read «1/1» with the card gone and its tile prompt live. `playCardFromHand` asks the SERVER's own `cardsInHand` — and treats a standing placement as «the play was made», because that is what it is.
- ⚠️ **A ONE-SHOT READ OF A LIVE STRING IS A RACE** — the command bar, the crumb and the bar's hot verb republish a frame (on a starved runner, several) AFTER the press. ## Guard specs are worklists, not decoration
Coverage specs enumerate the in-scope card set and FAIL with the exact list of cards needing attention (`cardPlayPreviewCoverage`, `actionReasonCoverage`, `cardInformation`, `effectSummaryCoverage`, `premiumCardViewModel`, `trackerCoverageGuard`, …). When widening expansion scope, widen their `SCOPE` sets first and let them tell you the work.

Prefer a cheap unit/integration spec over e2e; e2e (`tests/e2e/`) only when the bug cannot be reproduced otherwise — and after `npm run make:css`, since `build:client` does not compile LESS.

⚠️ **VERIFY THE BUILD BEFORE BLAMING THE PRODUCT.** e2e serves the BUILT client, and `make:css` refreshes only the stylesheet — a JS bundle from an earlier commit looks exactly like «this feature is broken», because the feature simply is not in it. Every test's `build` annotation (and the first line of `<served root>/test-results/worker-servers/worker-N.log`) names the build's commit, its time and its root, and says STALE — per side: server · client · styles, each against its OWN sources — when the sources on disk are newer: read it before calling anything a regression. This cost two false product bugs in one session — and ~40 on 2026-09-30, when a neighbour rebuilt the shared build mid-run.
