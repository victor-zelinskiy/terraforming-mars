# Testing rules

## Helpers
- **`testGame(n, options?)`** (`tests/TestGame.ts`) → `[game, ...players]`; skips initial card selection and disables Ares hazards by default.
- **`TestPlayer`** extends `Player` with `popWaitingFor()` etc.
- **`tests/TestingUtils.ts`**: `runAllActions(game)` (drain the deferred queue — call it after anything that defers), `cast(value, Class)`, `setOxygenLevel()`, `setTemperature()`, `addOcean()`, `addGreenery()`, `addCity()`, `fakeCard()`.
- Server card specs: instantiate the card → `canPlay()` / `play()` / `action()` → assert state.
- Client specs: `@vue/test-utils` with `tests/client/components/setup.ts`.
- Framework: Mocha + Chai (`expect` style); client via mochapack.

## Runners
```bash
npm run test:server          # mocha, ~8740 specs, ~50s
npm run test:client          # mochapack, ~4140 specs, ~85s
npm run build:test           # tsc --build tests/tsconfig.json

# one server spec
npx mocha --import=tsx --require tests/testing/setup.ts "tests/cards/base/Algae.spec.ts"

# one client spec — BOTH flags are required when invoking mochapack directly:
#   --webpack-config webpack.test.config.js   (single-chunk build; see below)
#   --include ./tests/client/components/bundleSetup.ts   (auto-unmount)
cross-env NODE_ENV=development npx mochapack \
  --webpack-config webpack.test.config.js \
  --require tests/client/components/setup.ts \
  --include ./tests/client/components/bundleSetup.ts "<spec>"
```

**Both `npm run test:*` scripts go through `scripts/run-tests.mjs`**, which fails the run when fewer tests are COLLECTED than the declared floor (`--min`). Raise a floor when a batch of specs lands; never lower one to make a run pass.

**…and on a FAILING run it re-prints mocha's failure block at the very END**, after the `[test-count]` line. A full suite prints thousands of ✓ after that block, so a reader of the TAIL (CI's summary, `| tail`, a captured background job) otherwise sees the count and not one spec name — which is exactly what made two intermittent `test:client` failures undiagnosable. It re-prints, never rescues: the run's own exit code and output are untouched.

## Traps that have bitten before
- **`npm run build:test` is mandatory when you touch `tests/`** — it is the only thing that typechecks the test tree (mocha + tsx do not), and it is what catches case-sensitive import paths that break CI on Linux. Since 2026-09-03 it is TWO gates: the Mocha tree (`tests/tsconfig.json`) **and the e2e tree** (`tests/e2e/tsconfig.json`, noEmit — Playwright transpiles without ever type-checking, which is how the whole e2e payment-literal rot shipped silently when `floodgateSteel` widened `SPENDABLE_RESOURCES`).
- **An e2e payment object is DERIVED, never a literal** — `{...NO_PAYMENT}` from `consoleStart.ts` (itself built from `SPENDABLE_RESOURCES`). A hand-written key map is invisible to the compiler (`Wire = any`) and rots the day the game grows a spendable: 24 files did, all at once, answering 400 «payment is not a valid type» at spec SETUP.
- ⚠️ **The client suite ran ZERO tests, green, from 2026-07-02 to 2026-08-14.** A fixed-name `vendors` split chunk that also collects lazily-imported deps makes `chunk.isOnlyInitial()` false for it, mochapack then never loads it, and `main.js` waits forever on a deferred startup — so the entry module (which runs the specs) never executes: «0 passing», exit 0, and every spec in the batch silenced. Fixed by `webpack.test.config.js` (no split chunks, no async chunks). **Never point the unit runner at `webpack.config.js`.** Full write-up in that file's header.
- **A mount that is never unmounted is a live subscriber.** Specs share one process and one module-state graph, so stale components re-render on every later spec's writes: measured 432 failures + 6 min together vs 19 failures + 55 s apart. `bundleSetup.ts` auto-unmounts after each test — so **mount in `beforeEach`, never in `before`** (a wrapper does not survive into the next `it`).
- `tests/client/components/setup.ts` exposes **every jsdom CONSTRUCTOR** (not a hand-picked list) — Vue's own `v-model` needs `Document`/`ShadowRoot`. Imperative APIs (`requestAnimationFrame`, `matchMedia`, …) are deliberately NOT added: feature detection must keep seeing this environment.
- `npm run lint:server` with `--cache` can mask errors; run `eslint --no-cache` when in doubt.
- ⚠️ **A LAYOUT GUARD CALIBRATED ON WINDOWS HAS NO MARGIN ON THE LINUX RUNNER — and a flat allowance cannot fix it.** Chromium lays HUD-sized text out with SUBPIXEL glyph advances on a dev box and with advances ROUNDED UP TO WHOLE PIXELS on CI (FreeType, below the size at which subpixel positioning turns on): «ДОСТИЖЕНИЯ» inks 95.41 px at 13.2 px locally and 100.41 px on the runner (+0.5 px per glyph), while the SAME string at 34 px costs nothing extra — which is why the strategy rail shipped an ellipsis only the FHD shard ever saw, at every retry, reproducible nowhere. **Simulate the rounding, never budget for it**: «keep N px per glyph spare» is right on the dev box and DOUBLE-COUNTS on the runner, where that margin has already been spent — the first fix failed a layout its own ellipsis check called whole. Reconstruct the worst case from the platform's own advances (∑⌈advance⌉ + tracking, via `canvas.measureText` on the PAINTED string — mind `text-transform`), clamp it to the laid-out ink so the measuring API's convention cannot change the budget, and assert the COLUMN clears it. The column is measured too: a `flex: 0 1 auto` title that fits reports its own ink and says nothing about the room it has — clone the real element at the real width and give it a string no line can hold. ⚠️ `getComputedStyle` is LIVE: read every property BEFORE detaching the clone, or the face silently reads «». Reference: `tests/e2e/console-strategy-rail.spec.ts` § `headFits`.
- ⚠️⚠️ **`seed` IN A CREATE-GAME CONFIG IS IGNORED — no e2e game is reproducible.** `ApiCreateGame.ts` calls `Math.random()` for every game it builds and never reads `gameReq.seed`, so «a deterministic solo game, seed 0.42» is a comment, not a fact (measured: three creations with one config produced three disjoint Ares hazard layouts). Only the EXPLICIT lists are forced — `customPreludes`, `includedCards`, `bannedCards`, `customCorporationsList`. Anything else a spec depends on (the rest of a deal, hazard positions, which cells are taxed, what the opponent holds) varies every run, so a probe must hold for ANY board the config can deal: sweep rather than remember a cell, assert the CLASS of thing rather than a specific one, and name what it was looking at when it failed. This is the single largest source of «green here, red on CI» in this suite.
- ⚠️ **A STUBBED SERVER MUST STAY CONSISTENT WITH ITS OWN ANSWERS.** An e2e that fakes one endpoint usually fakes two — the model route and the submit route — and they can contradict each other: `console-card-discard` had the submit answer «the discarded card is gone» while the model route re-injected the whole probe hand on EVERY refresh. Whether a run saw it came down to whether a model poll landed inside the cinematic: green on a dev box, red on all three CI attempts, with the product doing the right thing in both. A stub needs MEMORY (what has already been answered), not just a response.
- ⚠️ **A SCENE THAT WAS ALREADY STANDING IS NOT EVIDENCE OF YOUR PRESS — and «is the modal up?» is not a claim about ORDER.** `playQueueCard` accepted `gone || sceneUp`, where `sceneUp` is «some scene is on screen»: a reveal left by an EARLIER card owns A (so it swallows the press) *and* satisfies that test, so the driver reported a play that never happened and the spec then measured somebody else's scene — measured, with the target card still sitting in the queue. The source is ordinary: a corporation with a triggered draw (Point Luna, on its own Earth tag) fires one every time it is dealt, and the deal is not reproducible, which is what made it «red on CI, green on the retry». Three fixes, all general: a live `.con-deckdraw` is the queue still WORKING (the scene arms a beat after the response, so an idle test that watches only the start scene's own proxies returns too early); a drain that lives inside a retry loop is skipped whenever the press SUCCEEDS, so it has to be repeated after it; and an ORDER claim («the modal does not exist while the cards come off the deck») cannot be sampled three round-trips late — the scene is legitimately past `assemble` by then, with the reveal staged and painted. Arm a `MutationObserver` + `setInterval` probe BEFORE the press and read the modal's state in the SAME sample as the first proxy.
- ⚠️ **A COMPARISON IS ONLY AS SETTLED AS ITS LEAST SETTLED SIDE — and a `waitForTimeout` is a DURATION standing in for a state.** `hand-album-probe` polled the page-2 read until it settled and compared it against a REFERENCE taken one-shot right after a fixed 1200 ms open episode: on a loaded 4K runner the focused card was still growing at that moment, so «card width identical across pages» failed by 25 px with the product right on both sides. Whenever two measurements of the same thing are compared, BOTH go through the same settle read (two consecutive equal samples of the values you will assert on) — putting the poll on one side only moves the flake, it does not remove it.
- ⚠️ **THE SHAPE OF A PROMPT CAN ITSELF DEPEND ON THE UNREPRODUCIBLE DEAL — drive the surface's OWN markup, never a guessed key sequence.** Miranda's trade income is «add 1 animal to a card»: with a single animal holder in play the target is unambiguous and the focus stage renders NO step rows at all, while a second holder — a random corporation — makes it a CHOICE, and a choice is never seeded. `canConfirm` then stays false, X is inert, and the cursor does not start on the unanswered row, so the probe pressed X six times into «ЦЕЛЬ ТОРГОВОЙ НАГРАДЫ · Выберите себе карту…» and never moved. The stage marks its own unanswered steps (`--missing`), so a driver walks THOSE to zero before confirming; the same holds for any surface whose step list is data-dependent. Measured 1/8 → 32/32.
- ⚠️ **A PROBE'S OWN LIVENESS FLOOR IS A FLAKE TOO — it may only catch a sampler that never ran.** `hand-album-probe` demanded «more than 20 samples» from its `setInterval` sampler; that tally is scaled by how many pages happen to be mounted AND by machine speed, and it read exactly 20 on a loaded runner, failing a sampler that had worked perfectly. Neither replacement anyone reaches for first survives either: a coverage RATIO compares a Node-timed act (protocol round-trips included) against page-side samples, and a max-GAP bound fails because a loaded 4K runner genuinely starves the main thread for seconds (measured: 3.1 s gaps, 57-117 samples) — during which the animation being sampled is starved too, so there is nothing to miss. Set the floor where only a DEAD sampler fails it and carry the real numbers in the message.
- ⚠️⚠️ **EVERY RING THESE DRIVERS WALK CLAMPS SOMEWHERE, so «press ArrowRight N times and hope» fails SILENTLY — and a spec that keeps its OWN copy of the walk can only ever re-learn half the lesson.** The deployment queue does not wrap by design and the hand album clamps at a page edge, so a one-way walk parks against the wall: the caller then presses A on whatever it was already sitting on. Three call sites had three different halves of this — `focusCard` knew neither, `console-prelude-burn-gate`'s private `focusQueue` knew about the wall but not that «ОПЛАТИТЬ» can own the ring (CI: «focused the waiting prelude» false with the prelude in plain sight), and `waitForBoardHome`'s hand branch knew to look for a PLAYABLE card but walked one way, so it hammered A into «✕ Нельзя разыграть» for the whole 420 s budget while «Можно разыграть: 2» sat one hop to the left. ONE primitive now (`walkFocusUntil`): yield to the purchase, and turn around whenever a hop moves nothing. Never hand-roll a focus walk in a spec. **And the 2026-09-09 refinement, measured by rate (3/8 → 1/8 → 0/8 under worker-load):** ① a WALL and a SWALLOWED ARROW read identically for one lap, so the flip needs TWO consecutive no-moves — a one-strike bounce turns every swallowed press into a false wall and ping-pongs mid-ring; ② a failed pick RETRIES IN PLACE (up to 3 presses) — the likeliest swallow window is the pick FLIGHT of the card taken one lap earlier, and the return pass costs half the ring plus a second exposure; ③ the budget covers ≥2.5 passes of the LARGEST ring (the prelude step deals up to TEN — 20 moves died at 1.8 passes); ④ on shortfall the walk PRINTS ITS TRAIL — the trail is what turned this from a theory contest into a 10-minute read.
- ⚠️⚠️ **A BARE `page.reload()` SWALLOWS KEYS — use `reloadConsole(page)`.** The session-wide GPU warm-up paints the real console UNDERNEATH `.boot-loader`, so the surface a spec waits for is fully visible, its own verbs are on the command bar, the root classes read «ready» — and every key pressed in that window is lost. 32 of the suite's 35 reload sites had it; `console-composite-surfaces` reported «the shared picker never opened» about a picker whose door it had pressed twice. Same order as `openConsole`: shell → `.con-load` → `.boot-loader`.
- ⚠️ **A BOARD PLACEMENT IS TWO PRESSES, and a d-pad step UNLOCKS.** `A` on a legal cell LOCKS it; a second, separately-released press past the 280 ms dwell commits. Three specs spelled the commit themselves, all as one press, and all reported the CONSEQUENCE («the Hydronetwork's bonus layer never appeared», «the workspace never came back after the placement chain», «the focus never detached»); one of them additionally pressed **B between the attempts**, which CANCELS a placement and rolls a pay-on-commit play all the way back. Drive it with **`placeTile`** (anywhere legal), **`walkToSpace` + `commitFocusedSpace`** (a specific cell), or opt into `forceSwiftPlacement` when the confirm flow is not the subject.
- ⚠️ **EVERY PRESS IS act → verify → retry — `pressUntil` / `pressUntilVisible` / `pressUntilGone`.** This console has three DELIBERATE ways to swallow one: a visible toast overrides B everywhere, a decision surface re-arms its submit on every response, and a cinematic hold absorbs input for its whole length. A blind press plus a 45 s `waitForSelector` reports the timeout, never the swallow. The witness must be POSITIVE and SPECIFIC — «the draft workspace is on screen», not «something changed».
- ⚠️ **A DOCK COUNTER IS A VIEW, NOT A WITNESS.** The play cinematic freezes the view it animates, so `data-hand-total` still read «1/1» with the card gone and its tile prompt live. `playCardFromHand` asks the SERVER's own `cardsInHand` — and treats a standing placement as «the play was made», because that is what it is.
- ⚠️ **ON A QUICK WHEEL THE DIRECTION PRESS *IS* THE ACTIVATION — and a slot can be DISABLED with a reason.** Measured on the live wheel: LT opens it with five slots and ONE ArrowDown closes it; there is no "walk then A" in that mode, so the wheel's own disappearance is the witness that the press landed. And the arms are DATA — which verbs, in which arm, depends on the state, the profile and the expansion set, and each carries `.con-quick__slot--disabled` + `.con-quick__slot-reason` when it is refused. Two specs drove it by memorised direction into tiles that were dead for two different honest reasons — «В этой партии нет колоний» (the config has no colonies expansion at all) and «Сначала завершите текущее действие» (the one-reason law while a decision is owed) — so their «detour» proved nothing and their pass was silently lost. Read the slot before pressing it; a refusal is the product speaking, not a missed key.
- **Guard: `tests/console/e2eDriverGuard.spec.ts`** (server runner) enforces the three above statically — no bare `page.reload()`, no spec-local helper SHADOWING a `consoleStart.ts` export, and a cursor-aiming spec must commit through a primitive. Each rule carries an allow-list where an exception is real, with the reason written down. It also turns **the RATCHET**: `tests/console/e2eRatchetBaseline.json` freezes per-file counts of `waitForTimeout(` and `requestAnimationFrame` — growth fails (new debt), and a FALL fails too until locked in with `npm run e2e:baseline` in the same diff, so an improvement cannot erode.
- ⚠️ **`settle` WAITS FOR QUIET — and INSIDE a mandatory chain quiet is the wrong predicate.** Wave 1 measured both failure modes in one file: between two presses of ONE mandatory sequence (Pluto's draw→discard) a `[blocking]` hold legitimately STANDS until the next answer — `settle` times out naming it (`holds=[card-discard[blocking]]`); and right after a press whose beat arms >250 ms later with no transport trip, the quiet window passes BEFORE the animation starts — `settle` returns early and the next press hits the wrong phase. The law: **`settle` at chain BOUNDARIES** (post-boot, after the resolution's final answer, before a settled screenshot), **named `cinematicBeat` INSIDE a chain** (pacing between its presses). A settle timeout that names a `[blocking]` hold while `waitingFor` stands is this law talking.
- ⚠️ **A FIXED SLEEP IS A GUESS — wait on STATE.** New waiting is `settle(page)` (the product's own facts: named animation holds, the transport's in-flight request + cinematic gates, optionally the notification feed — on timeout it PRINTS THE OPEN HOLD NAMES), `pressUntil*`, or a poll loop; the one honest mid-cinematic pause is `cinematicBeat(page, ms, why)` with its reason written at the call site. The ratchet counts everything else.
- **EVERY DRIVER PRESS IS ECHOED.** The console key bridge counts every recognized key event with its outcome (`inputEcho.ts` → `window.__conInputEcho`; consumed / unconsumed / system / update-gate), and `press()` waits for the bridge to SEE the key before starting its settle — a press can no longer race the bridge's install or a busy main thread. `window.__conReady` (`e2eReadiness.ts`, installed by ConsoleShell) is the in-game aggregate: input echo + hold names + transport facts + workspace depth + `notificationsSettled` — read it in error messages so a timeout names the state it timed out IN.
- **EVERY E2E GAME IS SEEDED, and a red run NAMES its seed.** `ApiCreateGame` honours `seed` (float `[0,1)`); `soloGameConfig()` defaults it to `specSeed()` — a stable hash of the running test's title path, so every spec gets a reproducible deal without authoring anything and no two specs share one by accident. `createGameWithCards` annotates `seed=… player=…` into the report; to replay a failure locally, pass that seed via `opts.seed` / `config.seed`. A seed makes REPLAY exact at the same commit — it does not make a scenario stable against card-pool evolution (that is fixture boot, phase 4).
- **EVERY WORKER IS ITS OWN SERVER + THROWAWAY DB** (`tests/e2e/consoleTest.ts`, phase 3): specs import `test`/`expect` from `./consoleTest`, NEVER from '@playwright/test' (guard ⑤) — the extended `test` boots `node build/src/server/server.js` on `8100+workerIndex` with `TM_DB_FOLDER` in a temp dir and points `baseURL` (page AND `request`) at it. Contamination between runs/workers is structurally impossible; `workers: 4` locally is real (measured: 16 tests incl. two 4K profiles, 3.2 min). Absolute URLs are banned in specs — helpers read `process.env.TM_E2E_BASE_URL` (per-worker by process isolation). Debug escape hatch: `TM_E2E_SHARED_SERVER=1`. The server must be BUILT first.
- **STATE IS DECLARED, NOT CLICKED** (phase 4): a spec whose subject lives past the opening boots a FIXTURE — `bootFixture(page, request, name)` posts `tests/e2e/fixtures/<name>.json` to the loopback-gated `/api/dev/load-game`, which remaps ids and rides `Game.deserialize` (the real save path; the resume block re-primes the prompt). Fixtures are GENERATED by the engine (`npm run e2e:fixtures` — `tests/e2e/fixtures/generate.ts` answers the real start flow, then arranges with the unit suite's own setters) and guarded by `tests/console/e2eFixturesLoad.spec.ts`: schema drift fails in seconds with the deserializer's message, never as a mystery e2e 400. Measured: the endgame journey 26.9 s from fixture vs minutes of API-driving. The UI walk stays ONLY where the walk IS the subject.
- **WITNESSES LIVE IN THE DRIVER, and the canary breaks first** (phase 5): `workspaceOpen` / `crumbText` / `placementState` (+ the existing server-truth readers) are the shared readers of «where does the player stand» — a UI rework updates them once. `aaa-driver-canary.spec.ts` (~20 s, sorts first) exercises every load-bearing primitive against a fixture game, so a grammar change goes red THERE, naming the driver, before forty specs fail three screens from the cause.
- **THE LAYER CHECKLIST for a new e2e spec** (phase 5): ① could this red have been a mocha red? A pure decision gets a unit guard, and the e2e then asserts the JOURNEY, not the decision's exact value (the bot-turn card asserts «the gain is in the card», not the whole turn's sign). ② Is the arrangement a fixture, a seeded API drive, or genuinely the UI? ③ Are all waits state-waits (`settle`/`pressUntil*`/poll)? ④ Does every witness read server truth or a driver witness, not a private selector? A spec that fails the checklist is the ratchet's next customer.
- **PROVE A FLAKE FIX BY RATE, never by one green run.** `npx playwright test <spec> --workers=1 --retries=0 --repeat-each=8` turns «flaky» into a number: the Miranda owner-bonus probe measured 1/8 locally, which is what made it debuggable at all — a single pass says nothing about a 12 % failure. Measure before and after, and keep the failure DIAGNOSTIC enough that the next occurrence names the bug rather than the symptom (that probe now prints the SERVER's own queued reveal batches, so «the client never presented it» and «the trade never committed» stop looking identical).
- ⚠️ **A DRIVER THAT ANSWERS A SURFACE MUST FIRST LET IT RESOLVE ITSELF.** `waitForBoardHome` gained a branch for the generic task host, and the eager version — press A/RT the moment one is seen — answered prompts the shell was already driving. Wait the first rounds out (the old no-op behaviour), then self-heal; the product's own stalled-foreground watchdog uses the same three-pass shape for the same reason.
- **Module state is BUNDLE-SHARED in mochapack.** A spec that overrides an injected supplier or leaves module reactive state set (an open flow, a live animation hold, a foreground lease) corrupts every later spec — restore it in `after()`.
- A PURE helper spec with no Vue dependency also runs under the faster server runner.
- `eqeqeq` has no null exception here — `== null` fails lint.

## Guard specs are worklists, not decoration
Coverage specs enumerate the in-scope card set and FAIL with the exact list of cards needing attention (`cardPlayPreviewCoverage`, `actionReasonCoverage`, `cardInformation`, `effectSummaryCoverage`, `premiumCardViewModel`, `trackerCoverageGuard`, …). When widening expansion scope, widen their `SCOPE` sets first and let them tell you the work.

Prefer a cheap unit/integration spec over e2e; e2e (`tests/e2e/`) only when the bug cannot be reproduced otherwise — and after `npm run make:css`, since `build:client` does not compile LESS.

⚠️ **VERIFY THE BUILD BEFORE BLAMING THE PRODUCT.** e2e serves the BUILT client, and `make:css` refreshes only the stylesheet — a JS bundle from an earlier commit looks exactly like «this feature is broken», because the feature simply is not in it. The server prints `Starting <commit>, built at <date>` as its first log line: check it against `git log --oneline -1` before calling anything a regression. This cost two false product bugs in one session.
