# Board rules

The Mars board **explains itself** on three surfaces — hover, active placement, and the confirm modal. It is not a separate "analysis mode".

- **Vocabulary:** `src/common/boards/BoardInformationFacts.ts` — a `BoardFact` is ONE explainable statement with `category` / `timing` / `severity` / **`recipient`** (`current-player` / `player` / `tile-owner` / `neutral` / `nobody` — the load-bearing field) / title+description (English i18n keys) / an optional `delta` chip. `groupFactsByRecipient` is the ONE place the "who gets what" ordering lives.
- **Engine:** `src/server/boards/BoardInformationEngine.ts` — `boardCellInfo` (hover) + `boardCellPreview` (placement). It **never mutates state and never re-implements rules** — it reuses `MarsBoard.oceanAdjacencyBonus` (the same method `Game.grantPlacementBonuses` calls), the printed `space.bonus`, the `calculateVictoryPoints` adjacency predicates, `MarsBoard.placementCostInfo`, `MarsBoard.illegalReasonFor`. Purity is test-guarded.
- **Delivery:** the bounded read-only `GET /api/game/board-cell-preview` — facts are fetched lazily per cell, never attached to `SelectSpaceModel` (which rides every poll).
- **Location ≠ identity ≠ `countsAs` ≠ scoring.** On-grid is derived from the REAL adjacency graph (`getAdjacentSpaces(space).length > 0`); an off-Mars slot gets a neutral `external-area` fact instead of false 0-VP scoring. `countsAs` is shown but is NOT scoring. A special/composite tile never degrades to a bare "ОСОБЫЙ ТАЙЛ".
- **Cancellable placement** rides the server `placementContext` marker (`cancellablePlacement` / `committedPlacement`); `createMarsSelectSpace` DEFAULTS to committed (honest "the action is already underway"). The client never hardcodes cancellability — it reads the marker. Pay-on-commit standard projects apply cost/effects only in the commit callback, so a cancel emits nothing. Classification of what may/may not be cancelled: `docs/PENDING_ACTION_CANCEL_AUDIT.md`.
- **Preview ↔ commit can't diverge** — both go through the same grant logic (guarded by `placementPreviewConsistency.spec.ts`). Future/endgame VP is PREVIEW-ONLY; the journal is a commit log of what happened, never speculation.
- **The cell can't explain the CARD.** Two co-located read-only hooks close that gap (builders: `src/server/cards/placementPreviews.ts`, context: `boards/PlacementPreviewContext.ts`):
  `ICard.placementPreview?()` — what the card DRIVING the placement does about this cell (Solar Farm's energy production per plant bonus, Mining Area's steel-or-titanium, a `.andThen` production cost); `ICard.tilePlacedPreview?()` — the mirror of `onTilePlaced`, walked over EVERY player's tableau so an opponent's Arctic Algae / Tharsis Republic gain shows up under "Other players receive".
  Reached via `SelectSpace.sourceCard` → `SelectSpaceModel.sourceCard` → `?card=` on the preview endpoint. `PlaceTile` threads it from `tile.card`; the declarative city/greenery/ocean branches pass `card.name`; a bespoke `createMarsSelectSpace` passes `sourceCard` explicitly — **a bespoke placement that forgets it silently loses its own preview**.
  **The tile is not on the board yet**: a hook must never call `Board.isCitySpace(space)` — read `ctx.countsAsCity/countsAsOcean/countsAsGreenery/covering/cleared`.
  **A trigger the CELL decides answers EVERY cell**: where it pays, the grant (and the table's reply under it — `forecastReaction(fact, answers)`); where the cell stops it, a NAMED no with the kind and the count of what stops it (`noEffectHere` — TR30 Red Museum «Beside 1 ocean — no data»), never silence; «on Mars» is `Board.onMarsGrid`, the one reading for the hook and the dossier.
- **Not every "pick a cell" places a tile.** `SelectSpace.placementEffect` (`'tile'` default / `'bonus-only'` / `'marker'`) is the server's declaration, and `ctx.placesTile` / `ctx.grantsPlacementBonus` / `ctx.firesTileTriggers` / `ctx.bonusesCovered` are what hooks and the engine read. **The COSTS obey it too**: every Ares placement cost (hazard cleanup, the hazard-adjacency production penalty, adjacency M€, the deficit warning) is charged by `Game.addTile` ONLY — `placementCostFacts` prices a non-tile pick via `placementCostInfo({placesTile:false})` (the map's pay-to-use bonus price survives; affordability = `canAffordPlacementBonuses`), and a marker prices nothing. `bonusesCovered` (`space.tile !== undefined` — a HAZARD counts, mirroring `addTile`'s `coveringExistingTile` and Mars Nomads' own hazard branch) suppresses the printed-bonus promise; it is distinct from `ctx.covering` (the placed tile's `covers` — a removed hazard never sets it), which is what the survey-family hooks mirror. `firesTileTriggers` (`effect !== 'marker'`) gates the whole `tilePlacedPreview` walk — Land Claim runs no fan-out, a nomads move runs it with `space.tile === undefined`. Guard: `tests/boards/placementEffectConsistency.spec.ts` (preview and REAL commit over the same geometry). Full matrix: `docs/PLACEMENT_PREVIEW_AUDIT.md` § E-bis. **The CLIENT must forward it** (`fetchBoardCellPreview(…, placementEffect)` → `?effect=`, and it is part of the cache key) from BOTH `SelectSpace.vue` call sites and `ConsoleShell.loadCellPreview` — a declaration the engine is never told defaults to `'tile'`, and the panel promises the cell bonus / Ares adjacency / VP / milestone progress that the commit grants to nobody. Mars Nomads MOVES a camp — cell bonus yes, tile no, so no Ares adjacency, VP, milestone count or tile trigger (the card's own ruling: *"Mining Guild and Philares cannot take advantage of it"*); Land Claim / an Arcadian marker grant nothing at all. **A trigger that means "when a tile is placed" must gate on `ctx.placesTile`, never on live board state** — `game.nomadSpace` still points at the OLD cell during a preview. A new marker-style prompt that forgets to declare itself promises effects the commit suppresses.
- **The panel is finite.** It is the whole right rail on a TV, so a fact must earn its line: the engine drops the card-attribution tag on the card the prompt already names (`stripRedundantSource`), a description that restates its own title or block heading is omitted, and the confirm CTA is not repeated at the bottom. Overflow announces itself (edge fade + a `stickR` glyph line) — a silent scroll is the same bug as hidden information.
- **The placer's own table answers the tile** (T15 · CD): `tileTriggerFacts` marks a fact of one of the PLACER's own cards `tableAnswer: true` — the dossier reads it as «Сработает» (a no-op note too), never mixed into what the CELL gives; another seat's card answering stays that seat's recipient fact. Guard: `tests/boards/placementTableAnswers.spec.ts`.
- **Milestone / award progress** (`progressFacts`) is read from the REAL `getScore` via `withHypotheticalTile`, which installs the prospective tile, reads, and restores the exact three fields `simpleAddTile` writes. Never hand-compute "a greenery advances Gardener" — that would duplicate a rule that lives elsewhere.
- **An off-Mars cell the board draws is placed by CONSTRUCTION, never by eye** (`console.less` § P20/P29c — `keep-px` board px-space): every row of `expansionSpaceColonies` is drawn by `Board.vue` by name unless it is HOSTED (`hostedSpaces.ts` — its place is another object), and no two console cells stand closer than the flank's arm. The right flank's fifth cell (TR27 Aurora Station, '80') mirrors Maxwell about Dawn City's column — the arc's next even step was measured and refused: it lands on the temperature scale's 0 °C ocean-bonus marker. Guard: `tests/console/offMarsCellPlacement.spec.ts`.
- **To extend:** a new reason/bonus → add the `BoardFact` reusing the real rule source; a card-specific consequence → the co-located hook, never a central table; Ares facts → populate `aresAdjacencyFacts` from `space.adjacency` GENERICALLY (never hardcode "special tile = source"). i18n keys in `ru/board_info.json` (grep first).

Deep reference: `docs/claude/board-information.md`, `docs/SPECIAL_TILE_AUDIT.md`.

## ДВА ТАЙЛА НА КЛЕТКЕ — ПЬЕСЫ (TR44 Aquatic Research Station, 2026-10-14)
Клетка может нести ДВЕ фишки, и обе остаются собой: обычный ГОРОД поверх обычного ОКЕАНА (`tile.covers`; писатель — ТОЛЬКО `simpleAddTile`, через `Game.addTile(…, {overOcean: true})`). **Одно чтение** — `src/common/boards/cellPieces.ts` (`piecesOf` читает форму ОБЕИХ сторон: сервер `tile.covers`, клиент `SpaceModel.under`), и единственное правило составного тайла — `buriedOceanUnder(top, covers)`: накрытый океан — отдельная фишка только когда верхняя САМА не из `OCEAN_TILES`; Ares Ocean City остаётся ОДНИМ тайлом, считающимся обоими. `Board.isOceanSpace` стоит на `countsAsOcean` — счёт до девяти, M€ соседства, ПО Столицы и каждое «рядом с океаном» видят океан под городом; перепись TR45 считает «город 1 · океан 1». **Три писателя**: `addTile({overOcean})`; `liftTopCity` (последний ярус над водой уходит — океан остаётся стоять, ничей, едущий город без фантомного `covers` — TR14); `liftOcean` (`server/boards/cellPieces.ts` — с верха пустой клетки ИЛИ из-под города, город / владелец / ярусы остаются; бросает на составном) — `moveOceanTile` (TR39), `removeTile` (RX33 / Красные) и превью `withOceanLifted` идут только через него, и `removeTile` НИКОГДА не сносит город вместе с океаном. **Гард** `tests/boards/cellPiecesGuard.spec.ts`: ни один модуль не спрашивает `OCEAN_TILES` о клетке напрямую и не читает `.covers` мимо пьес (список разрешённых читателей может только сокращаться). Вид размещения `'city-over-ocean'` — верхушки простых океанов, чьи угодно (составной / накрытый — `occupied`, суша / пустой резерв — `requires-ocean-tile`; без единого простого океана карта не играбельна с причиной своего вида — `PLACEMENT_BY_KIND`). Досье: накрытие — «Без бонуса размещения» С ПРИЧИНОЙ («Бонус клетки уже получил океан.») + «Океан остаётся под городом»; снятие / переезд ГОВОРЯТ, ЧТО ОСТАЁТСЯ (`remove-ocean-under-city` / `move-ocean-under-city` «Город остаётся», `move-city-off-water` «Океан остаётся»); инспектор — «Два тайла: город стоит на тайле океана…» против «Один особый тайл: считается и городом, и океаном» у составного. Копия досье — ОДНА строка на факт: две прозаические заметки заставили панель 4K скроллить. Контракт: `docs/TURMOIL_REDUX_AQUATIC_RESEARCH_STATION.md`.

## ЧТО ОТКРОЕТСЯ — one function for what a lifted piece uncovers (TR47, 2026-10-14)
Every picker that LIFTS a piece — an ocean removal (RX33, the Reds, Dry Deserts, TR47), a move's SOURCE level (TR39's ocean, TR14's city), a remove-and-replace (Kaguya Tech's `cleared`) — and the hover of an occupied lone tile say what lies under it through ONE engine function, `BoardInformationEngine.uncoverFacts(space, lifted, mode)` (+ `coveredBonusFacts` for the hover): the cell's printed bonus as NEUTRAL chips («Бонус клетки снова доступен», recipient `nobody`, timing `future`), «Резерв океана снова примет океан» / «Клетка суши снова свободна» / «Бонуса нет — …», and the piece that STAYS by name («Ничего не откроется — на клетке остаётся город / океан / стопка»); Kaguya's own line is «Откроется — и сразу будет получено» (a bare cell — «Бонуса нет — открывать нечего»: a bonus the commit cannot pay is never promised). Category `uncovered-bonus` → the dossier's own section «ОТКРОЕТСЯ», never a field rule. Read through `piecesOf` only (the TR44 pair rule). Guard: `tests/boards/uncoverFacts.spec.ts`.
