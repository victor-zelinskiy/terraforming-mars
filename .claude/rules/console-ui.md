# Console-native rules

Console native (`?console=1` → `ConsoleShell.vue`) is **the default shell and THE product**. A UI feature is done when it works here; a desktop counterpart is never required. Concept doc: `docs/CONSOLE_MODE_CONCEPT.md`.

## Settings placement — the SYSTEM SURFACE
Both surfaces the player meets outside the game's flow share ONE chassis, `.con-sys` (`console_settings.less`): `.con-sys--settings` = `ConsoleOptionsPanel` (the settings console), `.con-sys--menu` = `ConsoleSystemMenu` (the in-game Menu overlay). Same card, crumb head, foot bar and focus language — so the settings console looks identical from either host (main menu, and in-game System → «Настройки»).

A new SETTING is a row in **`consoleSettingsModel.ts`**, in one category, never a hand-written row at a call site: the model owns the grouping, the option RING (`index`/`count`/`step(dir)` — `‹ ›` and d-pad left/right step BOTH ways and wrap) and the description. The categories are a HORIZONTAL strip with the LB/RB chips at its ends (the control moves sideways, so the list does too) — never a vertical rail, and the foot bar therefore spends no line on «Категория». Mark a technical/dev-ish category `minor: true` and it renders past a hairline seam, small and dim. A category has **either `rows` or a read-only `readout`, never both**. Context decides existence: the shell switch is main-menu-only, ПАРТИЯ (private score) is in-game-only.

**Layout-shift contract (load-bearing).** Rows are ONE line tall with the description in the always-mounted detail strip; the stepper cell is fixed-width and its arrows only change *opacity*; the detail strip reserves both text lines; **`.con-set` has a fixed `height`, not `min-height`** — LB/RB must not resize the card either.

The in-game `ConsoleSystemMenu` is still a **FIXED-SHAPE list of ACTIONS** — plates carry a subtitle, but every label is static, so nothing relabels under the d-pad cursor. **Never add a setting there**; «Диагностика» is a deep link (`initialCategory`) into the settings console's minor readout category, which is that readout's only home.

The overlay is owned by `GamepadLayer` (off the console router), so the keyboard reaches it through **`consoleSystemMenuBridge.ts`** — and the registered handler must own input for as long as the overlay is open, or the arrows drive the board behind it. Full contract + the traps (the nested-`&` selector that compiles to nothing, the lazy-`import()` spec zeroing, RAW_STRING): `docs/claude/console/system-surface.md`.

## Leak detector (breaks silently if skipped)
A new console surface that renders its OWN root class is invisible to `consoleLeakDetector.ts` and gets masked by the amber stranded guard even though it renders underneath. **Register its root selector**: general surface → `SERVING_SURFACES`; kind-specific section → `KIND_SURFACES[<kind>]`. The root must have layout. No spec enumerates the list — a miss fails only at runtime.

**Check 3 ACTS — the stalled-foreground self-heal.** `runForegroundWatchdog` shares the detector's DOM pass and runs BEFORE the stranded early-returns (the freeze lives exactly where the guard is disarmed by contract). Claimed foreground + nothing rendered + something waiting, 3 passes, only on `boardHomeIdle` → the stale claims are expired, the queue drains, the recovery names itself. See `docs/claude/presentation-flow.md` § the foreground watchdog.

**A hand-off to an ALWAYS-MOUNTED surface (board placement, hand carousel) has no registrable selector** — it needs a module-level MIRROR + early-return instead (`setConsoleTaskSpacePlacement`, `setConsoleTaskDeferred`, `isConsoleHandPickActive`, …) plus a spec row. This is how the final-greenery placement stranded (a nested `SelectSpace` branch keeps `waitingFor` classified as `choice` while every task surface unmounts). Full table: `docs/claude/console/leak-detector-contract.md`.

## Input — semantic, never raw
Physical input → `GamepadIntent` → `ConsoleAction` (`consoleActionModel.ts`). The ONE keyboard map lives there; the global `consoleKeyBridge` feeds the same dispatch. **Never add a component-local `keydown` listener or a new physical binding at a call site** — new screens use `useConsoleInput({onAction, onNav, overrides})`. `useGamepad`/`useMagicKeys` from VueUse are deliberately not used.

## Controller glyphs — never a literal button name
The player picks a glyph set («Настройки» → УПРАВЛЕНИЕ → «Контроллер»: Auto / Xbox / PlayStation / Steam) and an A↔B layout; `activeGlyphSet()` resolves both. Three sanctioned ways to show a button, in order of preference:
1. **`<GamepadGlyph control="triggerL"/>`** — the badge. Default for all markup.
2. **Interpolate the label** when the string is plain text with no glyph slot: `translateTextWithParams('Press ${0} …', [activeGlyphSet().stickL.label])`, and keep the English key parameterized.
3. **`content: var(--gp-label-<control>)`** (+ `var(--gp-tone-<control>)`) — ONLY for a badge on DOM we don't own (the `simple-keyboard` virtual keys). Published onto `<html>` by `glyphCssBridge.ts`, republished by `GamepadLayer`.

A literal `LT` / `RB` / `L3` / `Y` is a bug — including inside a **RU translation value**, where the English key looks clean («колесе LT/RT» shipped that way). Comments may name buttons freely. `tests/gamepad/glyphLiteralGuard.spec.ts` fails on any non-comment literal in `console/**`, `gamepad/**`, `console*.less` and `console.json`.

**Auto-detect cannot see through Steam Input** — it virtualizes every pad as an Xbox 360 controller, so `detectGlyphSet` returns `xbox` and the player must pick Steam/PlayStation manually. When a glyph "looks wrong", check «Настройки» → УПРАВЛЕНИЕ → «Контроллер» (Auto shows what it resolved to) BEFORE hunting for a hardcode.

## The WORKSPACE BAND — every decision surface docks right of the rail
A decision surface stands between the two bars **and right of the always-visible player rail** (resources stay context, and they are the landing zone of resource flights). Two things, always **both**: `.con-ws-band()` in LESS (the modal band + `left: var(--con-ws-left)`) and the **`con-ws` marker class** on the surface root — `.con-root:has(.con-ws)` drops `.con-main`'s stacking trap, lifts the rail to z11520 and rings it, holding automatically through leave transitions (no JS "closing" flag). **The lift sits on `.con-res`, never on `.con-res-host`** — a z-index on the host makes it a stacking context and drags the absolute ДОП.РЕСУРСЫ satellite up with the rail; the satellite is never hidden — it takes the one gap in the ladder (**z11470**: above the shade 11460, below every band surface 11480+ and the wheel 11500), so it is COVERED where a panel reaches it but never dimmed and never blanked (and it stays measurable as a resource-flight landing anchor). Leaving it at its board-level z lets the shade darken it while the rail it belongs to stays lit — the same information loss as hiding it, just softer. Mixin without marker → the rail stays under the shade; marker without mixin → the rail sits over a full-width panel. Panel widths inside the band are `min(Xrem, 100%)` — a `vw` cap overruns the narrowed band on the Deck. Seam tokens (`--con-pad-x`, `--con-rail-w`, `--con-main-gap`, `--con-ws-left`) live on `.con-root`; profiles override the TOKENS there. Cinematics (reveal / ceremony / mandatory announce / fullscreen zoom / system menu / start scene / endgame) deliberately stay full-bleed. Full contract + family list: `docs/claude/console/workspace-band.md`.

**…AND THE BAND IS THE CENTRAL OPENING — a modal never covers a bar, and its DIM never greys one.** The frame is four hull members (status strip · command bar · player rail · strategy rail) and the box they enclose; `.con-modal-band()` IS that box (`.con-ws-band()` = it + the `con-ws` marker contract), the shared `.con-shade` is bounded by the same four insets, and a surface with its own `__backdrop` uses `position: absolute; inset: 0` — a `fixed; inset: 0` dim greys all four members and only *looked* right because two of them out-stacked it (the side rails never did). **Geometry is MEASURED, replacement is POLICY**, deliberately in two places: `useWorkspaceBandGeometry` publishes `--con-stage-t/-b/-l/-r` from `.con-main` + BOTH rails' rects (it must observe the rails — a rail flip changes no box inside `.con-main`, so the column's own observer misses the one event that moves the edge most; the tokens stay the pre-mount fallback), while `.con-root--rail-replaced` (`ConsoleShell.conRootClasses`, derived from the WORKSPACE STACK + the two workspace-shaped overlays + the two drawers — never a second list of names) zeroes `--con-stage-r-eff` and hides `.con-strat`. A **WORKSPACE SCREEN and the right-edge DRAWERS («Журнал», the board dossier) TAKE the strategy rail's zone** and the rail stops being *drawn*; a compact DIALOG stands inside the opening beside a LIT rail. **A screen declares that itself** (`.con-ws-stage-band()` / `.con-ws-stage-sides()` → `right: 0`) and never spends the policy token: `right: 0` cannot disagree with «am I on screen», whereas the token flips the instant the stack empties — which is the frame the surface STARTS FADING, so a 4K screen would re-fit its grid inside a 468px-narrower box while dissolving. The token is for the two consumers that genuinely ask «is the rail visible right now»: the shared dim and the dialogs. **`visibility`, never `display`** — the rail's box must survive or `.con-main` re-lays out and the board rescales for a mode change. One definition, because the defect was never per-surface: «РАЗЫГРАНО»'s category view inherited `left: 0` from the old full-width band and reached across the player rail. Cinematics, flight layers and the two system failure surfaces (`.con-stranded`, `.con-alert`) are outside this family. Guards: `console-workspace-band` (both families, split by the policy class) + `console-right-drawer`. Contract: `docs/claude/console/hud-frame.md` § THE CENTRAL OPENING.

**TWO-LEVEL SAFE AREA + STABLE FOOT (tokens on `.con-root`).** `--con-stage-x` is the VISUAL-STAGE inset — how close large visual objects (card galleries, grids, hero plates) may come to the physical edge; `--con-hud-pad-x` stays the CONTENT-SAFE inset for text/controls/prices. One boundary is protected by exactly ONE of them: a panel whose body rides `--con-stage-x` gives its TEXT rows the difference back via `--con-stage-gain` (an `--embedded` surface zeroes the gain — no viewport boundary inside a host zone). **Every workspace foot/status rail is `height: var(--con-ws-foot-h)`** — fixed, border-box, overflow hidden, one ellipsizing line; a `min-height` there re-fits the body on focus navigation (the stdp jumping-grid bug). ⚠ A profile ladder re-stating a compensated `padding` as a bare shorthand strips the safe inset — repeat the compensation in the override. Contract: `docs/claude/console/hud-frame.md`.

## A workspace is ONE FLOW (the four conditions)
A stage reached from inside a workspace is done only when ALL FOUR hold: (1) **embedded**, not a new surface; (2) the breadcrumb is **continuous** — `ДЕЙСТВИЯ КАРТ › <карта> › <ЭТАП>` (stable context before the mutable stage; only the tail advances), workspace name and card name never restart, and the embedded surface **hands its stage name up** (`setWorkspaceOutcomePhase`) instead of drawing its own kicker; (3) the transition is the **same phrase one level deeper** — RELEASE in place → UNFOLD from the old surface's rect → REVEAL from inside (`consoleActionOutcomeMotion.ts`); a `v-if` swap is a blink and is never acceptable; (4) **B = one logical level**, carried card survives. Reference: the blue-action flow.

**…and a FINISHED flow LEAVES — it never folds back to browse.** One workspace had four endings, one per result flavour, each closing itself: a plain reward and a taken batch went home, a deck-check «ОК» and an answered purchase folded to the ДЕЙСТВИЯ КАРТ grid — so «Поиск жизни» ended by putting the player back in the list, staring at the action they had just performed, greyed «Активирована». Past the commit boundary the workspace is not a place to return to; it is the thing that is over. Every ending now routes through ONE guarded conclusion (`workspaceConclusionFor` → `ConsoleShell.concludeWorkspaceFlow`, synchronous — the callers that need a tick already defer, and the result-flight sites must fold in the SAME frame the card detaches). It dismisses only when nothing inside is still owed, and every hold is a NAMED reason: `nested-step` · `owed-step` (a second effect of the same press whose door is still waiting) · `live-outcome` · `owned-prompt` (pick-then-pay is ONE decision) · `parked` (concluding a set-aside flow turns «свернуть» into «закрыть»). **On dismiss the stage is NOT folded first** — it departs WITH the workspace in one motion; **on hold it is not folded either** — what holds a finished activation is a step teleported into that stage's own zone.

**…and a TERMINAL stage does not collapse either.** `committed` means «a decision about the result is still live», which is what makes «свернуть» a round trip worth offering. A VERDICT (the deck-check «Результат вскрытия») keeps no decision: nothing is chosen, owed or continued after it. Its phase is `verdict` — `isCommitted` yes, `acceptsInput` yes (A/X/L3 must land), `backVerbFor` **`none`** — because parking it unmounts the very stage that was suppressing the standalone presenter, while `lastReveal` lives on as server state until the player's next input: B on the verdict summoned the LEGACY full-bleed modal carrying the verdict just minimized. Three rules fall out. ① **The witness of «a workspace owns this artifact» is the CLAIM, never a mounted surface** — `workspaceClaimsDeckCheck` survives the park; `consoleActionComposerUi.revealClaim` is a component-lifetime mirror and is only a second witness (the decision is pure in `consoleRevealPresentation.resultRevealPresentation`). ② **An embedded stage may never say LESS than the legacy surface it replaces** — the verdict panel is ONE component (`foundation/ConsoleRevealVerdict.vue`, `.con-verdict`) mounted by both, so «✕ Условие не выполнено» can no longer be the workspace's whole reading while the modal states the check, the found/not-found and «награда не получена». A shared CLASS is not enough: every past divergence in this family was a markup divergence. ③ **EVERY door to a verdict is a workspace, so the verdict is inside all of them** — a direct activation and Viron draw their own stage (`hostDrawsItself`), while a repeated action played from the hand («Проверка проекта») and the Hydronetwork's stage-7 copy take the SAME shell-mounted overlay teleported into their zone (`embedded` + `mode: 'result'`, no head of its own — it hands its stage name UP). Their claims are `scope: 'chain'` / preview-derived, because the server attributes a copied action's verdict to the card that RAN, not to the card the player pressed; the reconciler needs the server's own unconsumed verdict as positive evidence (the play's hero scene stands between the answer and the re-home), and «ОК» must route through `foldWorkspaceAfterResult`, or the claim stands until its 20 s backstop. The standalone band is left with what it is FOR: a result with no parent surface.

Header hierarchy is TYPOGRAPHIC, never positional: the parent title keeps one style in browse and in flow (never re-scaled / re-animated on entry), the card name is the brightest+heaviest voice, the stage is a compact accent marker (cyan → amber past the commit). Console-wide inspection grammar: **X = the current object, L3 = the source that produced it** — every post-commit stage offers `L3 Источник` (from the claim's `sourceCard`), and the embedded status line under a result card is STATUS (name/economics/blocked reason), never a second command bar.

## DEPTH IS ONE STACK (`consoleWorkspaceStack.ts`)
«Where am I, and inside what» has ONE answer: an ordered stack of frames. `consoleState.section` / `.sheet` are read-only PROJECTIONS of it (the DEEPEST projecting frame wins — «the player drives the surface they SEE» by construction, which is why `shellTaskOnSurface` needs no `…Embedded` flags), and an assignment to either is a compile error. Two invariants carry everything else:
1. **PRESENCE IS DERIVED FROM THE STACK.** A surface mounts because a frame of its kind is in the stack — `v-if="workspaceFrameRenders(kind)"` and nothing else. «Own a zone whose host is unmounted» stops being expressible, which is the soft-lock (play `TradingColony`, press B) removed by construction rather than by a guard.
2. **A FRAME LIVES ONLY WHILE ITS ANCHOR HOLDS.** The anchor is STRUCTURAL and serializable (never a title — cross-cutting invariant 1, and deliberately not `promptIdentityKey`, which interpolates the translated title).

**ADDING A WORKSPACE IS ONE ROW** in `WORKSPACE_KINDS`: crumb root, DOM root (the leak detector's probe is derived from it — never a second list), the `section`/`sheet` projection, the default `serves`, and whether it `hosts` a step (`'always'` / `'inFlow'`). Not a shell latch, not a `handleSectionBack` arm, not a `KIND_SURFACES` entry, not an «is my host alive» computed.

**Navigation is VERBS, never an assignment.** `section = 'board'` meant «park this», «this flow is finished» and «take me there» at once, so every reader re-guessed — and B guessed differently from the branch beside it. `enterWorkspace` (lateral — resets the stack, and NEVER nests: a lateral move stands OVER a surviving phase root) · `pushWorkspaceFrame` (a flow hosts a step) · `descendWorkspaceFrame` (picking an object up INSIDE a screen is a **PHASE**, not a frame — the browse layer is parked, so selection/filter/scroll survive for free) · `foldWorkspaceFrame` · `leaveWorkspace` · `goBoardHome` (finished; a PHASE-anchored root survives — the start workspace yields to a placement and comes back) · `collapseWorkspaceStack` + `restoreWorkspaceStack` (park the WHOLE stack at full depth; both axes clear together, so the documented «half-collapse» is unexpressible).

⚠️ **The PARK is a SEPARATE stack, not a flag.** The player parks precisely in order to go and open other screens, so a park that shares `frames` is destroyed by the first lateral move — «свернуть» silently becomes «закрыть» (the minimized sponsor step was lost by walking to the colonies and back, and A returned the player to the deployment instead of their own unfinished card play). `goBoardHome` / `enterWorkspace` / `leaveWorkspace` never touch it; only `restoreWorkspaceStack` (the player came back) and `discardWorkspacePark` (the SERVER moved on to a different prompt) empty it. A parked chain still `stackServes` and still owns its workspace — check `workspaceFrameKnown`, not `workspaceFrameIndex`, before standing a second one up beside it.

⚠️ **RESUME and FRESH-OPEN are different intents — never one code path.** RESUME (the exact suspended instance, full depth) has exactly two doors: the board-home restore card (A/B) and the notification CTA — both `restoreDeferredTask`; plus the PROMPT-routed doors (`restoreParkedWorkspace` in `openHandWorkspace` / `openColoniesForPrompt`), because a server demand's home is the parked chain. A WHEEL/hand open (`openSheet`) is always a FRESH instance beside the park: clean browse, read-only via `actionBlockedReason`, adopting nothing — and it never un-defers (`parked non-empty ⇒ deferred`). What the frames cannot carry across a park, a workspace keeps in a module-level SUSPENDED-INSTANCE record and re-seats on mount from a pure, HOST-SCOPED plan (`actionWorkspaceRestorePlan`: the descent draft `consoleCardActionsUi.draft` + only a claim whose `host` is its own — adopting a foreign claim is how «ДЕЙСТВИЯ КАРТ › ПЛУТОН › ПЛУТОН · СБРОС КАРТЫ» stood over a browse body); a host whose step was already hosted BEFORE its mount must republish the step's zone from `mounted()` (a change-watcher cannot fire true→true). A descent that cannot be rebuilt FOLDS the whole workspace honestly — the mandatory gate re-announces; a mixed surface (one workspace's crumb over another's body) is the forbidden outcome.

**One form of «the chain is not over yet»**: `workspaceFrameHasNested(kind)`. The shell carried five hand-written copies of that question and the missing sixth was the bug — a host may not fold, release its claim or drop its zone while a step is standing inside it.

**Nesting = the teleport chain.** `workspaceFrameTarget(kind)` is the zone published by the frame BELOW; the host publishes it `flush: 'post'` (a `pre` watcher names a node the child has not rendered, the parent resolves the teleport first, and Vue leaves the surface in place — the composer once rendered *under* the command bar) and retracts it in its own `beforeUnmount`, never from the flow side. **Ownership ≠ readiness**: a nested frame renders NOWHERE for the gap frame, never in its own band first. An **OVERLAY** frame (`overlay: true`) is the exception that proves it — the client pick bridge, where the hand takes the screen and the asking composer waits underneath with its captures intact; it has no zone to wait for, so it must not be held off screen.

**Where a follow-up belongs** is `workspaceHostForStep()`: the NEAREST live unfinished step, never the outermost root (inside the start's play-from-hand prelude a played card's SelectColony belongs to the CARD-PLAY step — `start ⊃ hand ⊃ colonies`). A prompt-pushed frame carries a `prompt` anchor, which is what later says «hand the screen back when the demand is met»; a visit the player made carries `always` and stays.

Step surfaces stay **host-agnostic** (one `embedded` prop strips frame / `ConsoleWsHead` / `con-ws`; logic, module state, input path and captures untouched), **one instance teleported** (never a copy), and the crumb is the HOST'S — stages hand their name UP (`setWorkspaceFrameStage`), browse-layer chrome hides past the descent, and the tail is the DEEPEST frame's (a crumb that stopped at the hand kept naming a stage the player had left two screens ago). B on a nested step = MINIMIZE the hosting workspace; a bare close soft-locks. A server refusal must roll the frame's phase back to `configure` beside `resetSubmitting()`, or B stays dead. Header: **`ConsoleWsHead.vue`** is the ONE workspace header (metrics in `.con-wshead`; profiles override THAT, never per-surface classes). Full write-up + the migration record: `docs/CONSOLE_WORKSPACE_STACK.md`.

## A LANDING WAITS FOR A BOARD THE PLAYER CAN SEE
A tile a card places ITSELF (a reserved slot — Ganymede, Phobos, Stratopolis: `city: {space}`, no `SelectSpace`) arrives in the response while the player is still inside the workspace they played it from — and the board section behind it is `display: none`. Two consequences, one bug: `measureBoardHexRect` reads a zero rect, the flight degrades to an instant reveal, and by the time the workspace folds the city is simply THERE. So `flyRemote` first awaits a WATCHABLE board (`boardCovered()` = a workspace frame ∨ the played-card scene ∨ the deck dealing ∨ a live reveal batch), then lets the leaving surface settle (`BOARD_SETTLE_MS`), and only then measures and flies. **Waiting is free and hiding is not**: the tile stays behind its reveal hold (the cell keeps reading as untouched) but the wait is BOUNDED (`BOARD_WAIT_MAX_MS`) — a hidden tile is a worse lie than a missed animation — and the stage safety is re-armed while waiting, because a deliberate hold is not a stall. Guard: `tests/e2e/console-auto-tile-landing.spec.ts` (workspace up → the cell is EMPTY → workspace gone → a proxy flies → the tile appears).

## The HAND is an ALBUM — strict pages, never a scroll
«Карты в руке» renders STRICT PAGES (profile-fixed: 5×2 everywhere, 4×1 handheld — `consoleHandAlbum.ts`, pure + spec'd), one page in the viewport, the rest parked as face-down PACKETS beyond the stage edges. Card size solves from the BOX + the profile grid only — never from the hand size (one card and ten are the same geometry). **The active page is DERIVED from `consoleState.handIndex`** — no second page state exists to restore or desync; d-pad across the page edge IS the page turn, **LB/RB jump a page in EVERY album mode** (the tag filter rides the TRIGGERS: LT/RT cycle in browse, LT stays «only suitable» in select, RT stays the sale/multi confirm; R3 resets), the right-stick flick / wheel / spine-chip click do the same unadvertised, and focus is anchored to CARD IDENTITY (a re-sort follows the card; the `modeKey` watcher must stay declared BEFORE the entries watcher). The page position renders in ONE place — the ALBUM SPINE in the footer bay (`ConsoleHandDock` `album` prop: «LB 1–10 из 15 · 1/2 RB», swapping the «КАРТЫ n/m» counter for the album's lifetime, yielding back past the descent); a header pager is a regression, and the pages hint never appears in the command bar (one action — one hint). The page turn is ONE retargetable transform transition on the strip — armed only after mount settles (`--live`) and pinned during reveal/filter episodes (`--transit`); every page is positioned by TRANSFORM, and since even transformed bounds are scrollable overflow by spec, the album pins its own programmatic scroll to 0 (`pinScroll`) — the clip keeps the root guard quiet. **The WHOLE hand leaves the dock while the album is open** (`dockLiftedNames` reads `handAlbumUniverse`, never the filtered entries): a filtered-out card rides the far-right packets (`packetExtras`), a packet-bound proxy wipes behind the stage edge on a SIDE clip (`RevealClip.left/right`) instead of crossing the HUD whole, and a filter change is a RE-PAGINATION (leavers/enterers fly to/from `packetHomeRects`, never to the dock). Full contract: `docs/claude/console/hand-album.md`.

## HAND DOCK presence — never hidden, always on top, compact under load
Once the dock appears after setup it stays to the END of the game: no screen may hide it (the old per-surface hide list is gone), and the whole unit — chassis z11703/11705 AND the pack z11704 — rides the top of the section/band ladder always (the pack's z0-under-scenes dive is gone). A busy screen is answered by the **COMPACT pose** (`handDockCompact` — Planet Focus, or `!handDockInteractive`), never by hiding/re-layering; while cards are physically ARRIVING the dock is **FULL whatever is open** (the accent of receiving — and those episodes measure dock rects). Full-bleed cinematics (reveal/zoom/endgame) may COVER it; nothing may unmount it.

⚠️ **The intake accent is a BOUNDED LEASE (`consoleDockAccent.ts`), never a predicate over foreign flags.** `beginDockIntakeAccent(label)` / `holdDockIntakeAccent(label, promise)`; leases nest and every one expires on `ACCENT_MAX_MS`. Reading other directors' booleans shipped a game-long dead compact pose: one of them (`handRevealState.holdSlots`, latched by a section change inside the reveal's pre-install window) stuck true and pinned the accent ON forever. A pose that silently stops working is worse than one briefly wrong. Contract: `docs/claude/console/hand-dock-presence.md`.

## A CARD PLAY'S RESULT BELONGS TO THE WORKSPACE THE PLAY WAS MADE IN
A card can be played from three doors and each of them used to answer «who owns what this produced» differently: the hand composer answered NOTHING (a card that drew cards folded its workspace on the landing beat and the batch arrived as a full-bleed reveal over the board), the start queue answered «only if the preview PROMISED cards» (Point Luna draws from a TRIGGERED effect — `onCardPlayed` on its own Earth tag — which no `behavior` preview advertises, so its opening draw went to the fullscreen viewer as though it had come off the board), and the standalone `playFromHand` band correctly answered «nobody». **One resolver** (`played/consolePlayOutcomeClaim.ts`): `playOutcomeHost()` is a table of the workspaces a play can be made inside + the zone each publishes, DEEPEST first (`start ⊃ hand` — the same «nearest live unfinished step» law as `workspaceHostForStep`). Two properties are load-bearing: the claim is **OPTIMISTIC** (`expectedCards` sizes the arrival, it never gates the claim) — so `reconcileWorkspaceOutcome` must run on EVERY response for a play host, and for a play claim «ours» reads the RAW prompt (`deckSelect`/`cardSelect`/`payment`), never «the gate is holding something» (the play's own cinematic holds the task host for its whole length, so *everything* looks held); and its scope is **`'chain'`** — the server attributes a draw to the card whose EFFECT ran, so one press's whole causal chain is claimed, not one name. Ending: `endPlayCardFlow` → the shared `concludeWorkspaceFlow`, which holds on `live-outcome` until every card is taken — with `servedPromptHolds: false` (the hand frame's `serves` are registry DEFAULTS, and a forced discard would hold the workspace around a PARKED browse layer) and a **PHASE-anchored root ends with `goBoardHome`, never `closeWorkspaceRoot`** (a flow inside the start cannot end the opening). Two things must STAND while the claim stands, both «a host does not fold under what it carries»: the `pendingPlayCard` watcher does not fold the descent (`!handOutcomeLive` beside `!workspaceFrameHasNested('hand')` — else the hand shelf lights up UNDER the embedded reveal), and the landing scene stays (`playLandingHolding`) because the deck deals the drawn cards only AFTER the hero scene ends — freezing its own view (`latchedIncoming`/`latchedRevealed`), since the transaction has already cleared its state by then. **…AND A TRIGGERED EFFECT IS A STAGE OF THAT PLAY, NOT A WINDOW OVER IT.** «Марсианский университет» answers the science tag the player just played (including its own), and that question used to LEAVE the workspace the press was made in: the hand folded on the landing beat, the decision rose as a full-bleed band, its discard opened a FRESH hand and the drawn card arrived in a fullscreen reveal — one press, four unrelated-looking screens. The claim now admits a fourth kind, **`'effect'`**, claimed for every play for exactly the reason `draw` and `pick` are (a triggered effect is invisible to every preview, so «claim, then release what is not ours» is the only way to catch it), and the reconciler keeps it for a `choice` that is STRUCTURALLY one of these on both sides — the server's `choiceContext` marker AND a shape `buildEffectDecision` can present honestly, so an ordinary `OrOptions` branch still releases it. Three consequences, each a separate bug paid for: ① **an answer given INSIDE a flow never ends the flow** — `workspaceOutcomeEmbedded` legitimately falls while the decision hands the screen to the workspace's own shelf (the surface unmounts by design; the discard cinematic then holds every task surface closed), so `embed-fell` must ask the RAW prompt, and `leaveHandAfterAnswer` + the close episode's `setSection` hook — TWO sites, ONE law, each already broken once on its own — now share `handExitVerb` (hosted → pop one level · own flow still owed → do not leave · alone → home). ② **The crumb only moves FORWARD**: a published stage name stands for as long as the claim does (else the tail fell back to «РОЗЫГРЫШ» for the whole discard), the embed target needs the ADMITTED vm (the raw one made the zone «occupied» through the landing beat and the tail read «ДОБОР КАРТ» one stage early), and the pick HANDS THE TAIL ON at its answer rather than retracting it. ③ **The landing tableau lets go when the outcome TAKES the stage** (`deckDrawDealing() ∨ stage === 'presenting'`), not only when a deal starts — a decision brings no cards, so keyed on the deal alone the tableau never let go; and the composer unmounts on the TABLEAU's schedule (`playComposerReleasable`, `flush: 'post'` — a child's watcher runs after its parent's in the same flush), so the handoff is a dissolve and not a cut. An embedded decision keeps its own FILL (its content-sized panel does not cover the zone a card row does) and its trigger line (an embedded stage may never say less than the band it replaces), and drops the kicker — the crumb is where it names itself. Guard: `tests/e2e/console-effect-decision-embed.spec.ts`.

**THE SHIFT CHANGE IS THE DEAL, and it is a DISSOLVE**: the tableau lets go on `deckDrawState.dealing` (published once, where the scene stops waiting — the layer reads that same fact, never a second flag), not when the reveal arrives, or the previous beat stands over the one arriving; «showing» and «holding» are therefore two questions (`playLandingShowing` = holding ∨ releasing keeps the layer mounted and frozen for the fade), and the fall is told apart from a server REFUSAL by the positive `playLandingYieldedToDeal` — the same watcher rolls the setup back, and it must not do that over a live deal. **A CONDITIONAL SEARCH'S «СБРОШЕНО» PILE TRAVELS** to the berth the reveal keeps for it (`runDeckDrawTraySeat`, on the cards' own leg): the scene's tray and the reveal's pile are one stack of cards, and painting both — one vanishing with the layer, one fading in with the frame — is the teleport the flight removes; the berth is held (`.con-reveal--bonus-held .con-reveal__discard`) until the tray lands on it. ⚠️ The tray enters on a CSS animation with `fill-mode: both`, and a FILLING animation overrides inline styles — without `animation: none` before the tween the tray does not move at all. Full contract: `docs/claude/console/workspace-band.md` § РОЗЫГРЫШ КАРТЫ.

## EMBEDDED outcomes — a self-opened workspace owns its own follow-ups
When the player ENTERED a workspace themselves, the stages that follow (reveal, drawn cards, the buy/keep pick, the result) present INSIDE it; a standalone band is for what the player did NOT open. Mechanism: a **claim** (`consoleWorkspaceOutcome.ts` — keyed on the SERVER's own `CardDrawRevealSource {type:'card',cardName}` / `lastReveal.action`, `kinds` derived structurally from the branch preview) + a **`<Teleport>` of the SAME shell-mounted instance** into the workspace's `[data-embed-slot]` zone. **Never a second nested copy** — one mount point, one command contract, one input path; and a static import of a `Card.vue` consumer into a unit-tested component silently zeroes its whole spec file (`CardHelp.vue` loads a webpack chunk that mochapack cannot). The slot is published REACTIVELY (`workspaceOutcomeState.embedSlot`) and rendered from SUBMIT time — a teleport whose target does not exist yet drops its content. An orphaned claim is worse than a leak (it suppresses the standalone presenter, so the artifact shows NOWHERE): release on unmount, and `reconcileWorkspaceOutcome` drops it a tick after the response when nothing turned out to be embeddable. Full contract: `docs/claude/console/workspace-band.md` § EMBEDDED OUTCOMES.

## Card results in a workspace — BATCH ARRIVAL + one stage chassis
A result of N cards is **N physical objects from the first frame**. The count is known before anything moves (the answer, else the claim's `expectedCards` — the preview's server-computed `cards` amount), the workspace renders a PREPARED stage with N empty slots in the shared chassis, and `runBatchArrival` flies N proxies from `.con-deckstack__pile` into those exact rects. The opening motion is `addPremiumTurn` (`cardDeal/premiumTurn.ts`) — the SAME function the deck-draw cinematic plays, never a copy. Modes are SEMANTIC, never timing (`consoleCardArrival.ts`): `in-flight-reveal` lands face-up (a post-landing flip there is a bug), `awaiting-data` flies backs and opens per-card by whichever route is still continuous, `conditional-reveal` (a `deck-check` claim) keeps the deliberate Search-For-Life beat. **`arrivalDone` ≠ `beatDone`**: the first releases the SURFACE, the second the PLAYER — focus ring, selected name and every bar verb stay suppressed while the real cards are held invisible under their proxies (`workspaceOutcomeArrivalPending()`), and the gate can never stick (handoff, unmount and a 5 s backstop all open it).

**⚠️ Never put `opacity` (or animate it) on an element that declares `transform-style: preserve-3d`.** Any value below 1 is a grouping property: it forces that element back to `flat`, backface culling stops, and a 180° turn shows a MIRROR of the face instead of the card's back. Dim the flat child (`__flip-back`) instead. This shipped once as "the take flip mirrors the card".

Geometry is ONE engine for both embedded stages (`consoleWsStageLayout.ts` — size, focus-safe GAP and row shape solved together; the gap is an output, so a focus ring can never grow over its neighbour) and ONE header component (`ConsoleWsStageHead.vue` — title + badges on a single reserved row). **The height budget is MEASURED, not enumerated**: the stage is a strict flex column whose row is the only flexing part, so the fit reads `row.clientHeight`. Two traps that shipped: a host `min-height` beats the shared `height` on the status line, and each host's own full-bleed width (`.con-task--wide`, `.con-reveal__card`) overflows the zone — inside a workspace the ZONE is the room. Baseline + probe: `tests/e2e/wsStageParity.ts`.

## A FLYING CARD — `Card3DInner`, batch ownership, exact handoff
The physical card body is `cardFlight/card3dInner.ts` (+ `console_card3d.less`): **CardMotionOuter** (`.con-card3d-outer`) owns position/scale/shadow **and the `perspective`**; **Card3DInner** (`.con-card3d`) owns `rotationY` / a small `rotationX` / `z` and nothing else; both faces plus a real paper `__edge` exist from birth. It formalizes the chassis the fork already had (the faces keep their `.con-deal-proxy__face/__back` names, so every shared rule still applies) and the turn is LAYERED onto the caller's flight timeline — «fly» and «turn over» are one gesture. **A rotateY with no `perspective` on the parent is ORTHOGRAPHIC and reads as one picture replacing another** — that, not a missing flip, is what made the start flow look like a face swap (`.con-startdock-proxy` had no perspective).

**A flight owns ITS OWN proxies** (`ProxyBatch`) and disposes only those. Clearing the whole layer at the end of a convoy is how a combined transition lost cards: the shorter convoy wiped the longer one's still-airborne bodies while its timeline kept revealing destinations — the visible «the last cards teleport in one by one». There is no card cap and no instant-placement path: a missing source/destination is a dev warn, never a silent «just appear».

**Destinations are MEASURED, never assumed** (`measureTargets` + the host's prewarm: mount the target layout invisible at its final box, `visibility: hidden` so it still measures, solve the fit there, and freeze both fit engines for the flight). **Handoff = reveal the destination, then remove the proxy on the NEXT frame** — never a crossfade (the copies are identical, so a fade can only expose what differs) and never hide-then-reveal (a blank frame).

⚠️ **«THE COPIES ARE IDENTICAL» IS A CONTRACT THE PROXY HAS TO MEET, and `ConsoleCardFaceLite` meets it only if you pass it BOTH halves.** LITE is a cost budget — no interactivity, no zoom teleport, render-once — and it is never licence to fly a different picture. (1) Pass the **live `CardModel`** whenever the host has it: the discount chip and the stored-resource capsule exist only with it, and — because the cost chip widens `--pcard-title-safe-l` from 50 to 84px — dropping it also re-sizes and re-wraps the card's NAME. (2) Pass **`lightweight`** when the destination is a console GRID (they all draw `<Card … lightweight>`): `pcard--tier-thumb` is not a quieter `normal`, it swaps the title's engraved gold gradient for solid warm ink. The hand-open flight shipped without either and the whole shelf visibly re-drew at the handoff. (3) **Warm the art with `preloadPremiumCardArt` at ARM time, and know that fetching ≠ decoding** — `img.src` only guarantees the bytes, so it now `decode()`s too; a proxy standing over a slot that already paints the same webp must additionally skip the face's own load-fade (`opacity: 1; transition: none`, scoped to the flight layer — the `.con-discard-proxy` precedent). Guards: `consoleHandRevealParity.spec.ts` (props) + `console-hand-open-parity.spec.ts` (the two faces' `.pcard` class signatures must match mid-flight; screenshots are the art's evidence, since no cheap DOM read distinguishes «decoded» from «downloaded»).

Stage ORDER for the start workspace: `startStageDirector.ts` splits ACTIVE (`stepIdx`) from PENDING (`startTransition.to`) — the commit is a phase, and forward it sits after the docking. Forward and backward are deliberately different orders. Full contract + every trap: `docs/claude/console/start-flow-motion.md`.

## Viewport / reduced motion

## Scale model (TV profile) — rem discipline
All `console*.less` is authored in **rem (1rem = 20px logical, a 1920×1080 logical layout)**; `--con-ui-scale` maps it onto the viewport, JS mirror `conUiScale()`. New console styles must be rem. Two traps that shipped as bugs:
- A JS reader of a length-valued custom property MUST use `cssUnits.cssLengthPx()` — `getComputedStyle().getPropertyValue('--x')` returns the unresolved `"18.3rem"` string.
- Anything positioned inside the planet's `transform: scale(var(--board-scale))` px-space (off-Mars `.board-space-XX` margins, cell spotlight inset, arc-marker ring) stays **px + a `keep-px` marker**.
- A new px constant in console JS (fit engines, director offsets, scroll steps) must multiply by `conUiScale()` or content stops growing on 4K.
- Embedded px content integrates via `zoom:` multiplied by `var(--con-ui-scale, 1)`.

## Performance mode (`con-perf-lite`) — every new overlay/animation must support it
The profile cuts `filter` and `text-shadow` globally; `box-shadow` is deliberately KEPT. Therefore:
1. Motion lives in `transform` / `opacity` only.
2. **Functional state indicators — focus, selection, cursor, availability — use `box-shadow`/`outline`, NEVER `filter`/`drop-shadow`/`text-shadow`** (they vanish in perf mode and the player loses navigation cues; the colour carries state).
3. Decorative-only glow via `filter` is fine.
4. Verify by toggling «Производительность» ON: every cue still visible and correctly coloured, motion identical.

## Surface motion (band surfaces)
Orchestrated by `src/client/console/surfaceMotion/` behind `<transition :css="false">`. Markup contract: `data-motion-surface="<id>"` on the root (absent → hooks pass through, the gradual-migration path), `data-motion-panel` on the animated panel, `data-motion-anchor="card:<name>"` for phase FLIPs. ONE shared `.con-shade` dims behind every migrated surface — a migrated surface renders no own backdrop div. **Before deleting a now-dead backdrop CSS rule, grep the `.vue`s — chassis classes are SHARED** (two dim-less regressions came from this). FLIP transforms inside a CSS `zoom:` context need `effZoom` compensation. **Never re-close a composer at submit time** — use the awaiting handoff (`beginAwaitingHandoff`), else the "confirm → bare board → reveal" gap returns.

⚠ **`v-show` FIRES the enter/leave pair**, so "is this a real dismissal or a client PICK BRIDGE hiding its composer?" is a fork the director must get right — and the answer is the ONE fact the shell publishes (`pickBridgeActive` → `setPickSuppressed`), never a re-derivation naming the bridges one by one. ## «МОГ БЫ» ≠ «МОГУ ПРЯМО СЕЙЧАС» — the turn is an EXECUTION GATE, never a reason
Every green count in the console means ONE thing: how many of these the player COULD do in the current game state. It must not move because the turn moved — the wheel is a planning instrument and an opponent's turn is exactly when it is read. So «Сейчас не ваш ход» **blocks the commit, paints the calm `warning` register («НЕ СЕЙЧАС»), and stays IN the count**; a real rule (cost, tag, target, per-generation usage, no free fleet, no payment path) does the opposite and OUTRANKS it, so the turn gate can never mask «Нужна метка». Semantics are STRUCTURAL and per-code (`src/common/availability/AvailabilityBlocker.ts`: `blocksExecutionNow` / `affectsPotentialCount` / `tone` — never derived from «is it temporary» and never from a colour; `turn`/`phase` are the only two `UnplayableReasonType`s the CLIENT adds, everything the server produces is about the card).

The numbers come from ONE turn-independent SERVER projection (`potentialActions` on the self model — `getPlayableCards` / `getPlayableActionCards` / `DeltaProjectExpansion.maxSteps` / `Colonies.potentialTradeCount`), which owns no rule of its own and must never grow one; `canAdvanceDelta` and `availableBlueCardActionCount` are DERIVED from it. Trade is `min(tradeable colonies, free fleets)`, 0 with no usable payment path — composed from `tradeBlockedReason()` + the SAME `tradeHandlers()` list the live trade action offers (⚠️ never folded INTO `tradeBlockedReason()`: it backs `canTrade()`, which three cards use as their own `canAct`, so widening it changes game rules). The client re-derives nothing (`potentialAvailability.ts` only applies the intake clamp and «not in this game»). ⚠️ **`playable ⊆ potential` is ENFORCED, not assumed** — a prompt can carry its own discount (Eccentric Sponsor's play-from-hand prelude), which `unplayableReasons` knows nothing about, and the card would be dimmed while its own РАЗЫГРАТЬ was live. Execution off-turn stays impossible everywhere; nothing here submits anything. Full contract: `docs/claude/console/potential-availability.md`.

## «Почему нельзя» — ONE answer while something is owed
There is only ever one real reason a board-home action cannot be started: a decision is already owed — a live board PLACEMENT, or a mandatory prompt the player MINIMIZED to go and look around. The shell states it once (`actionBlockedReason`) and it **OUTRANKS every surface's own arithmetic**: the basic-actions wheel, the Standard-Projects rows (patent sale included), the Milestones/Awards items, the action centre's activations, the hand's play press and the colony trade all read that one string. Shipped bug: with a play-from-hand minimized, the LT wheel read «Сейчас недоступно» · «Недостаточно растений» · «Недостаточно тепла» · «Доступно после первого действия в этом ходу» — each line individually true, together a lie about why the game would not move, and the player was told five wrong things instead of the one right one. **Never let a surface compute a turn-flavoured reason of its own**: `offTurnReason(awaitingInput)` is the fallback (`Finish your current action first` vs `Not your turn…`), and `myTurn` alone is not a discriminator — a top-level play-from-hand prompt makes `hasTurn` TRUE, so the off-turn reason never gets a chance to speak.

## The COLONY RESOLUTION — one interaction owner (Pluto)
⚠️ **THE ONE TERM OF THE GATE THE CLIENT WRITES IS THE ONE THAT CAN LATCH — AND IT DID.** `clearColonyBonusEntry()` runs on exactly ONE edge (the falling edge of `colonyResolutionLive`), so while the armed remote ENTRY was itself a term of that predicate the edge was unreachable by construction: the flag kept the resolution true and the resolution kept the flag. For the rest of the session the claim was never released, the workspace never concluded (board: «Вернуться к решению» → A: a colony screen with nothing to do → B: an empty frame), the «СБРОШЕНО» receipt counted across resolutions, and the stage named a trader from a payout two generations old over the player's OWN trade. The gate is now split: `colonyResolutionEvidenceFor` is the AUTHORITATIVE half (markers · batch · discard flight · own transaction) and the entry contributes only `awaiting` — ended the instant evidence exists (read at the entry site AND on the evidence watcher's rising edge) and, for the one case with no signal at all, on a bounded named net (`COLONY_BONUS_ENTRY_WAIT_MS`). **A client latch may EXTEND a resolution to the end of a beat; it may never BE one.** After that the entry is CONTEXT (which colony, whose trade) and the viewer's own live transaction outranks it.

⚠️ **A ONE-SHOT ARMED BY A WATCHER NEEDS BOTH ITS EDGES AND ITS MOUNT.** The payout pose (`--handing` — what takes the track out from under the reveal) missed two entrances that never fire a rising edge: a stage MOUNTING mid-resolution (post-discard restore, remote entry, reload) and the NEXT cycle's zone re-opening while the cue is already true (`payoutLiftOff` is resolution-scoped — true→true fires nothing). Both drew the reveal ON TOP of a fully lit track. `immediate` + a re-arm on the zone's own rising edge, one writer (`armOutcomeHandoff`); no `$el` yet = pose without animation, which is exactly right.

**A BONUS THE PLAYER DID NOT TRADE FOR IS ITS OWN COMPOSITION** (`ColonyFocusIntent 'bonus'`): the stage drops its whole working half — track, guard rail, berths, configuration, reward package, availability verdict — because none of it is a decision in front of the player. What remains is the paying colony, WHOSE trade set it off (leading, on its own plate), how many settlements of theirs are paying, and the choice. All three shapes land there: Pluto's card + mandatory discard, Miranda's collect, and a card TARGET pick («куда положить ресурс») — the last routed by the ANNOUNCE press with the claim admitting `pick`, so `ConsoleTaskHost` teleports into the stage's own zone instead of raising a band over the colony that is paying. Detection is the server's own `choiceContext.source = {kind:'colony', name}`, never a title.

⚠️ **A ZONE IS NOT A SLOT.** `wsStageLayout` solves `n` boxes of `slotW × slotH`; a «Бонус колонии» zone is a slot PLUS furniture (a lateral margin, a caption floating above the row, a taller box). All three are real layout, so all three ride into `fitEmbeddedStrip` MEASURED FROM THE DOM — margins off `availW` and into `padXPx` (the wrap cap must hold the line that will be laid out), the extra height off `availH` (a flex line is as tall as its tallest item), the caption's overhang into `rowGapPx`. **Subtract, never FLOOR** (`Math.max(slotH, avail − cost)` is a budget raised to a whole card — the engine's one forbidden move, and it crops the row at 1080 while looking like a safety rail), and **watch the box you measure**: the observer on the reveal ROOT misses a row that loses height inside a root that keeps its size. The row states its own solve in `data-fit` — read that before theorising.

⚠️⚠️ **AND THE GAP THE ENGINE SOLVES MUST BE THE GAP THAT RENDERS — a profile that re-states a solved value silently unsolves it.** `html.con-profile-tv .con-reveal__strip { gap: … }` (0,2,1) out-specified the stage row's `column-gap: var(--con-ws-stage-gap)` (0,2,0), so at 4K the engine planned a line ~200 px narrower than the browser laid out: `flex-wrap` broke a card onto a row the stage had no height for and the payout rendered cropped top and bottom — while the same batch fitted at 1080 (measured `cg=96px → 29.96px`, 3 lines → 1, overflow `513px → 0`). Any profile ladder touching a row the fit owns must be scoped away from it (`:not(.con-ws-stage-row)`). **A fit claim asserted at ONE resolution is a claim about one resolution** — the e2e default viewport is 720p, where this composition fits by accident; geometry guards must `test.use({viewport: 3840×2160})` and assert against the box that actually clips (the padding is deliberate focus headroom, not overflow).

An owner bonus has TWO shapes and both must work: Pluto's «draw 1, then discard 1» (a per-colony sequence, rendered in the «Бонус колонии» ZONES) and Miranda's plain «возьмите карту» (no discard, no zone). A bonus card leaves the reveal's strip ONLY when a zone will draw it (`revealWaveForIndex`) — splitting it out unconditionally rendered Miranda's card in neither place, so the covers had no landing slot and the take no origin. And a plain draw paid by SOMEBODY ELSE's trade is DELIVERED, not posted: the server marks a `colonyBonusPrompt` collect (`TaskKind 'colonyBonus'`, always interruptive, drawn inside the answer) queued at `BACK_OF_THE_LINE` on the RECIPIENT — returning it to `GiveColonyBonus` freezes the trader's own income behind an opponent's click.

**A TRADE HAS TWO DOORS AND ONE BODY.** «Колонии» and a card's «потратьте X, чтобы бесплатно поторговать» are two entry points into the same action: one server command (the card's own `IColonyTrader`, never a second `colony.trade` in the card file), one payment model, one workspace, one resolution. The card door **submits nothing** — `playActionCard` marks a card action used at the BRANCH PICK, so submitting first spends the cost before the colony is asked for and leaves B nothing to undo. It declares itself (`ActionPreviewStep {kind:'colonyTrade', card}`), relabels its CTA to «Выбрать колонию», pushes the colonies as a STEP of the card-actions frame, pins the fee to `OptionMetadata.card` (never a label) with every other path dimmed and out of the ring, and lets the trade's own confirm be the single atomic commit. The header is the ONLY trace of the origin — «ДЕЙСТВИЯ КАРТ › ЛЕТАЮЩАЯ ПЛАТФОРМА › ГАНИМЕД · ТОРГОВЛЯ» — so the hero column recedes and nothing below repeats the card. ⚠️ **Two projection axes can be set at once** (`sheet: cardActions` + `section: colonies`); input routing and the command bar must break the tie by DEPTH (`workspaceStackTopAxis()`), not by asking one axis first. Full contract: `docs/COLONY_TRADE_FLOW.md` § THE SECOND DOOR.

⚠️ **A prompt served by a SHELL SECTION must suppress the desktop fallback modal too.** Its screen opens on the player's press (usually after a mandatory announce), so there is a window where none of its DOM is mounted — judging «is this served?» by what is on screen lets the legacy `MandatoryInputModal` rise into it, and answering THERE bypasses the console's own door (the Miranda colony-bonus collect flew its card to a full-bleed reveal instead of into the colony that paid it). The set is `SECTION_SERVED_KINDS`, read by `promptServedNatively` — deliberately NOT `hostServesPrompt`, which answers a different question (may the TASK HOST take it) for the outcome reconciler. `projectCard` is excluded: its degenerate shape has no console screen, so the legacy modal stays its honest fallback.

**A PAYOUT'S CARDS ARE PHYSICAL, WHEREVER THE PAYOUT CAME FROM.** Trade and BUILD are one language: covers separate from the reward's own printed glyph and fly into the reveal's real slots. Three rules the family paid for: ① a claim whose payout is flown by a scene marks the **execution beat done at claim time** — leaving it pending keeps the reveal unmounted for the 2.6 s backstop, the scene finds no slots to measure, degrades, and the cards then appear out of nothing (the build path's whole bug); ② **every card turns IN THE AIR** — a destination that opens a card delivered face-down draws its own back while the cover is still carrying it (two objects for one card) and then plays a second, differently-shaped turn, so `bonus-held` holds every BACK too, and the flip chassis belongs to the take-in-place turn alone; ③ the scene under the flight **evaporates WITH the cards** — one shared cue (`colonyResolutionUi.payoutLiftOff`, raised by whichever scene flies) read by the stage, with a long dissolve and a SHORT return (the closing beat waits on the return, so the two directions are different durations declared on the state each transitions into).

A colony card payout (trade income → owner-bonus cycles → the MANDATORY discard → the track reset) is ONE resolution with ONE root owner: the colony workspace. Its close gate is `colonyResolutionLive` (`colonyResolution.ts`) — **never «the reveal is empty»**: an emptied batch between two legs is a mid-resolution state. The mandatory discard is an EMBEDDED hand step (`colonies ⊃ hand`, `hosts: 'inFlow'`, serves earned at runtime), never a second workspace root; a foreign trade's owner bonus is HELD behind the mandatory announce (`remoteColonyBonusHold` — keyed on the discard MARKER only; a markerless bonus batch is the auto-discard edge and must flow) and enters straight onto the colony's focus stage. ## STANDARD PROJECTS — the workspace owns the whole action

## Mandatory prompt gating — notifications and mandatory actions NEVER share a queue
A mandatory ACTION is ANNOUNCED, not auto-opened: surface stays closed, `ConsoleMandatoryAnnounce` names it, **A opens it** (`consoleMandatoryGate.ts`). Two beat sources, one deterministic order: an interruptive TASK beat (`corpFirstAction` **mid-game only** — inside the start flow (`corpFirstActionInStartFlow`) the Game Start Workspace's own «ПЕРВОЕ ДЕЙСТВИЕ» stage serves it with no beat at all, like every startSequence prompt (`docs/claude/console/start-first-action.md`); plus forced `handSelect` + `colonyBonus` always; host sub-prompts only on an off-turn forced reaction) outranks the pending FLOW beats (a must-open workspace flow — the between-generations draft, key `draft:gen<N>` stable across every round; its open route is `openMandatoryAnnounce`'s `enterWorkspace`, and the frame-lifecycle watcher only CLOSES on the falling edge — never auto-enters). The viewer's own turn is never gated. **Never gate a cinematic ENDPOINT** (a drawn-cards reveal is the continuation of a draw animation — gating splits one cinematic). New interruptive kind → the gate's scope set + a fixture row; new must-open flow → a `MandatoryFlowKind` + a derivation in `mandatoryFlowBeats` + an open-route branch.

**ORDINARY NOTIFICATIONS AND MANDATORY ACTIONS ARE DIFFERENT TRAFFIC — the feed keeps flowing inside a workspace.** Only what OWNS THE SCREEN silences it (`SILENCING_REASONS` in `presentationPolicy.ts`: a live animation, a full-bleed reveal, the turn review, a ceremony). A `'mandatory-choice'` lease is NOT among them: it means the player is WORKING (start flow, draft, payment), and silencing for it piled the game's events up as «СОБЫТИЯ В ОЧЕРЕДИ +N» for most of a turn. Two consequences that must move together: (1) the silencing test walks EVERY raised reason, never `foregroundBlockReason`'s winner (a ceremony sits below a mandatory lease and would be missed), and the freed/blocked broadcast rides that same predicate — keyed off the raw block reason, opening a workspace would yank the visible card back into the queue; (2) a flow-holding card may hold the NEXT prompt but may never RETRACT a surface already up (`mandatoryPromptsHeld` ignores it while `mandatoryLeases > 0`) — that used to be free, because the lease kept such a card from ever being delivered. **A visible toast OVERRIDES B, everywhere** — the press closes the card and is consumed; the screen's own back/minimize is the NEXT B. The opposite assignment (toast yields B inside a workspace) shipped and was reverted within a day: the player taps B to clear a toast and their workspace steps back under them — an unasked navigation is strictly worse than one extra B. The toast branch sits below every screen-owning moment (alert / awaiting-handoff / heroes / review), so a cinematic's own swallow still wins, and A / X-tap / navigation always pass through.

**The chip BEACON needs a second fact the plate does not.** «A decision is owed» ≠ «it can be answered NOW»: a prompt stands while the table is still busy elsewhere (the corp first action during another player's preludes, a minimized start workspace), and the player is then free to walk the interface. So `ConsoleStatusStrip.attention` = the debounced `attentionPending` **AND** `viewerAwaited` (`myCategory === 'active'` — the SAME presentation its own pill renders, so a chip reading «ОЖИДАЕТ» can never flash for attention), lighting the instant the status turns active (the debounce is already spent). The plate and its A-route are deliberately NOT gated on it — a calm «here is where to go» is right whenever the player looks. Never duplicate that predicate in the shell.

**The lifecycle is asymmetric** (pending → presented → acknowledged → gone): the FIRST presentation (plate on board home / chip beacon elsewhere — one moment, the location only picks the form) waits for the ordinary-notification feed to finish COMPLETELY (`notificationsSettled()` — nothing visible, empty queue, exit animations done via the layer's leave hooks) plus every presentation/animation hold. Once presented, the action is a STANDING state: later notifications show beside it and must never hide the plate, re-queue it or replay its entrance (the plate yields only to the player's own location and the viewer's own full-bleed cinematics). Latches die with their beat (`noteMandatoryBeatIdentity`) — a completed/invalidated action leaves nothing stale, and the same key re-arising later is a fresh cycle.

A DEFERRED (minimized) task is reachable **only from the board home** — its `.con-mandatory` card renders nowhere else, and `handleSectionBack`'s restore branch sits AFTER the section-close branches on purpose. Putting it first (it once was, as a "global fallback") makes B inside the hand/colonies/hydro yank the prompt back instead of closing that screen, so B stops meaning "one calm step back" the moment anything is deferred.

⚠️ **«СВЕРНУТЬ» IS A ROUND TRIP, and the way back is ONE predicate that must cover EVERY family offering the verb.** A minimizable surface carries `!consoleState.task.deferred` in its own `v-if`, so B unmounts it and that card is the only door — and a family the predicate forgets is a soft-lock nothing shouts about (a deferred task is deliberately invisible to the leak detector, so only a reload recovers). The whole DEDICATED COMPOSITE family shipped that way: `mandatoryDeferredActive` listed host / section / start scene, and the Venus alt-track bonus, spend-heat, the planetary thresholds and «оставь K из N» are **none of the three** — one B and the bonus was gone for the session. These four held none, and `mandatoryPromptsHeld` only spares a live surface while `mandatoryLeases > 0`, so a bot-turn card arriving over them unmounted them for its TTL. Pure + spec'd in `consoleRevealPresentation.ts` (the overlay itself cannot be unit-mounted — its static `Card` import zeroes the spec file).

**…and the ARRIVAL is decided once per batch too — the same seam, the other reader.** The deck-draw cinematic's entry test is a list of «somebody else owns this» questions, and one of them (`workspaceClaimOwnsArrival` — the card-actions composer's beat already pulled these cards off the pile) is a CLAIM, which dies at the take. Assert the probe's own `samples`, or a dead probe passes.

**A SOLVED NUMBER IS ONLY REAL ONCE IT IS A STRING.** `wsStageLayoutStyle` serializes with `toFixed`, which ROUNDS UP — so the solver checked its budgets against `zoom 1.136957 / gap 26.186` while the browser laid out `1.137 / 26.19`, a line 0.06 px wider than the cap computed beside it. `flex-wrap` obeys 0.06 px: the 4 + 3 the engine chose rendered as 3 + 3 + 1, cropped top and bottom, inside a 4K screen with a third of its height unused. So `wsStageLayout` **snaps onto the published grid itself** before deriving anything — DOWN for the zoom (a budget: smaller only fits better), UP for the gaps (a CLEARANCE the focus ring may never lose) — and back-solves against the snapped values. ⚠️ And the wrap cap sits at the **MIDPOINT**, not on the line it caps: its only job is to separate «perRow fits» from «perRow + 1 fits», and those are a WHOLE CARD apart, so pinning it to the first spends the whole tolerance on the wrong side. Half a card of slack is invisible (the group is centred inside the cap) and is below the next break by construction, so it stays correct even when it exceeds the band. Height keeps a sub-pixel guard for the same reason width keeps 2 %. **A wrapping stage row is also never a SCROLL CONTAINER** — `.con-cards__strip` inherits `overflow-x: auto` from the single-line carousel, and on a wrapped row that is a loop the fit cannot win (overflow → scrollbar → `clientWidth` drops → narrower fit → fits → scrollbar goes). **And a geometry claim asserted at ONE resolution is a claim about one resolution**: this shipped because `console-deck-pick.spec.ts` only ran at 1920. It is parameterised over `fhd` + `tv4k` and asserts the SHAPE (`[4, 3]`) — «more than one row» is satisfied by the bug — plus «does anything stick out of the ROW», because every earlier check asked the viewport and the viewport was never what clipped.

**The LANDINGS are the events, so the landings are what gets scheduled.** Launch and landing shared one schedule (every card flew the same duration), so the launch decay was also the landing decay and a seven-card draw landed its last four cards 58, 50 and 43 ms apart — under the threshold at which the eye separates events, which is why seven placements read as one flash. `planCardArrival` now owes a landing CADENCE (`minLandGapMs` ≈ 6 frames): a card that would arrive too early stays LONGER IN THE AIR (`travelStretchMax`) rather than launching later — the quick cascade off the pile is what reads as dealing, and later cards are aimed at farther slots anyway. Everything the turn is measured against is that card's OWN travel, or a stretched flight opens early and coasts face-up. Supporting: the launch decay gets a floor (`stepMinMs`, bounded on both sides — below ~3 frames it is a flutter, above ~60 ms the batch stops being airborne before the first landing), the birth fan is bounded AS A WHOLE (a fixed per-card step is a stack at three cards and a spread hand at seven), and the flight's scale grows over the whole approach (a card already at its landed size reads as already there).

**A fit engine may never solve a shape that does not fit.** `wsStageLayout` clamped candidates with a FLOOR and then compared the clamped values — but `shapeZoom` already returns the largest zoom a shape can afford, so raising to a floor is by definition asking for a card that does not fit: at 4K a seven-card reveal solved three rows, got clamped up, out-scored the feasible two-row shape and rendered cut off top AND bottom with nothing to scroll to. Ceiling only; compare on the value that will render; a starved band gets small honest cards. ⚠️ The GAP hides a second overflow — it is solved from the zoom (focus headroom) but also has a floor, and on a tight band that floor wins, so the row exceeds the budget its zoom was solved for. Back-solve the zoom against the gap actually used (one pass is exact). Swept in `consoleWsStageLayout.spec.ts`, not sampled.

**A LANDING IS MEASURED AGAINST THE PLACE, NEVER AGAINST WHAT IS DRAWN IN IT.** The played shelf's `.con-splayed__top` is a *prepared card place* — card-shaped by construction and already the anchor the outbound hero flight uses (`data-start-front`). The RETURN flight measured the painted `.con-splayed__face` inside it instead, and that face exists only when there is something to paint: while the source card is out on loan its family may have nothing else (`topFace === undefined` exactly when the away card was its category's only card — the ordinary case for a player's first prelude). The query returned null, the flight branch was skipped, and the card went from the source seat to «РАЗЫГРАНО» in ONE FRAME. ⚠️ And the probe that should have caught it asserted the card was ON the shelf — true for the whole bug, since the slot carries the away card's identity the entire time. A teleport and a flight have the same end state; watch the MIDDLE (`.con-start__embedsource--departing`, set on entry and cleared at touchdown — the broken path cleared everything in one synchronous block, so Vue never rendered it). `.con-startdock-proxy` alone is not a discriminator: every start flight spawns those.

**A slot's IDENTITY and its FACE are different questions.** While an embedded step runs, the card that opened it leaves «РАЗЫГРАНО» for the step's source seat; when it was the family's TOP the slot rendered `con-deal-hold` and the only thing painted was the 31 px depth strip — indistinguishable from a clipped card. The pile shows the card UNDERNEATH (promoted), while the away card keeps `topKey` so its return flight still has a destination.

**`workspaceSourceZoomOrigin` is the ONE resolver — keep every host in it.** It knew only the card-actions composer, so `L3 Источник` inside the start workspace degraded to the TEXTUAL entrance: the viewer rose out of nowhere while the seat kept its card and the player saw two of the same card. A physical origin exists precisely so there is only ever one.

The source seat's reserve did exactly that AND rode a `padding` longhand the profile ladders overwrite with their shorthand: the seat then sat on top of the first revealed card, and the ~300 px of phantom width also kept a seven-card reveal in one small-card strip. Reserve it on BOTH sides of a centred group and overlap stops being expressible — no z-index, no phase where it comes back. ⚠️ The wrap cap (`--con-ws-stage-rowmax`) is a `max-width` on the row, so it carries the row's OWN padding only; folding a virtual margin into `padXPx` makes the cap wider than the shape it caps (4+3 broke as 5+2). ## A CHOICE IS A PRESS — never the cursor, never a seeded default
Where a screen asks the player to pick one of several results (the play-card «ИЛИ», and any surface that grows one), **focus, selection and commit are three different things**: moving the cursor selects NOTHING, A on an option SELECTS it (idempotent, and it does not travel to the commit rail), and the commit is a second deliberate press. A selection is seeded ONLY where there is no decision — one branch, or exactly one the RULES allow (`initialVariantSelection`); a card that opens already «ready» lets one A play a result nobody chose, which is precisely the defect. The protection is STRUCTURAL, not a guard: the unmade choice is a **commit requirement**, so `computeCommitGate` refuses the commit AND `commitAcceptsCursor` withholds the rail — a repeat, a held button or a double click has nowhere to land. Paint says the same three things: cyan ring = cursor (no ✓), mint plate + ✓ = the answer (it survives the cursor leaving), both = mint plate + an OUTER cyan ring.

Composition rule for the options and for the result units beside them: **content-sized intrinsic layout, never a grid of equal columns** — `flex: 1 1 <reading measure>` for comparable option cards (a `flex-basis: auto` lets one long sentence claim the line and strands the «или»), `flex: 0 1 auto` for the fact chips. Full contract + the traps: `docs/claude/console/play-card-result.md`.

**…and THE INSTRUMENT FOLLOWS THE BUDGET — a one-unit distribution is a CHOICE, not a number.** The `.con-lanes` chassis (Venus track bonus + Stormcraft's spend-heat, one engine in `budgetLanes.ts`) drove every prompt with −1 / +1 / MAX, so the common case — one resource to place, one heat to cover — made the player count a dial to 1 past four verbs and then hunt for the confirm. `budgetSingleStep` asks the pure engine whether **every usable lane is a whole answer by itself and nothing more may be added once taken** (a property of the budget, never `target === 1`, so `cover` with weighted lanes answers honestly too); the surfaces then drop the steppers, the counter cells and — for a GIFT, not a bill — the meter, and become a radio: A places / takes back, X commits, and the mark rides beside the cursor per the rule above. Placing MOVES the unit (rebuilt from empty), because under a full budget a plain `+1` elsewhere is refused and «A on another lane» would be the mode's one gesture, dead. The unadvertised LB/RB/MAX still land on that gesture — muscle memory must never meet a dead button. Pinned in `compositePrompts.spec.ts` + e2e `console-composite-surfaces.spec.ts`.
